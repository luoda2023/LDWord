## 1. 使用规则

- `已实现`：代码和针对性测试已经存在，但仍需进入最终发布回归。
- `本轮完成`：本轮已修改并完成针对性验证。
- `待验证`：实现证据存在，但尚未完成对应发布用例或门禁验证。
- `待实施`：缺少足以满足 PRD 的实现或用户闭环。
- 每项必须同时具备代码入口、自动化测试和端到端验收证据，才能标记为发布通过。
- 本表只记录 P0；P1/P2 不得挤占未完成的 P0 发布阻断项。

## 4. 当前产品决策

| 决策 | 当前口径 | 变更条件 |
| --- | --- | --- |
| 正式品牌 | Alavette Form V1.0 | 只有产品负责人明确改名时才调整 |
| 内部包名 | lark-formatter | 单独的兼容迁移版本，不在 V1.0 P0 中重命名 |
| 平台 | Windows 本地桌面 | 跨平台作为后续版本评估 |
| 核心输入 | DOCX | 其他输入按模式能力声明 |
| CLI 输入 | 仅 DOCX | 在共享执行契约与测试完善后扩展 |
| 数据处理 | 默认仅本机，不自动上传 | 未来联网插件必须独立授权和披露 |
| 标准口径 | 提供规则化模板与检查，不承诺自动绝对合规 | 有明确规则版本、审核人与持续更新机制后再提升承诺 |

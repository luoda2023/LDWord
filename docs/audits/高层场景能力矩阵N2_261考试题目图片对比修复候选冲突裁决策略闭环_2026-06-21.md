# 高层场景能力矩阵 N2.261 考试题目图片对比修复候选冲突裁决策略闭环

## 1. 本轮定位

N2.260 已经把同一 `repair_target_type + repair_target_key` 下的多个 ready 修复候选统一拦截为 `confirmation_status=conflict`，避免 Workbench 或后续批量链路把多候选目标误当作单候选直接应用。

N2.261 关闭的是“冲突裁决策略首片”：当人工已经在冲突组中明确选择一个候选时，队列需要能表达这个选择结果，并让被选候选重新接入既有的单候选确认替换链路；未选候选必须保持不可应用，且说明它是因冲突裁决被拒绝。

## 2. 已实现能力

- 新增 `_resolve_question_figure_repair_queue_conflict()`：
  - 输入 `question_figure_repair_queue`、`selected_queue_id`；
  - 要求 `confirmed=True` 才执行裁决；
  - 不修改原始队列，而是返回裁决后的队列副本；
  - 仅允许 `confirmation_status=conflict` 且带 `conflict_group_id` 的候选被裁决；
  - 同一 `conflict_group_id` 下少于 2 个 conflict 候选时拒绝裁决；
  - 被选候选恢复为 `confirmation_status=ready`、`confirmation_action=confirm_question_figure_replacement`、`confirmation_apply_supported=True`；
  - 未选候选转为 `status=rejected`、`confirmation_status=rejected`、`confirmation_apply_supported=False`；
  - 未选候选写入 `candidate_rejected_by_conflict_resolution` blocker；
  - 队列写入 `resolution_records[]`，记录 `selected_queue_id`、候选集合、被拒绝候选、裁决人和裁决说明。
- 新增 `_refresh_question_figure_repair_queue_status()`：
  - 裁决后重新计算 `queue_count`、`conflict_group_count`、`conflict_count`；
  - 如果没有剩余 conflict 候选，队列状态从 `conflict` 回到 `queued`。
- Workbench issue 详情新增冲突组、裁决状态和裁决说明展示。
- Workbench action 路由保持原契约：
  - 裁决后被选候选重新输出 `profile_question_figure_repair_candidate`；
  - 被拒绝候选继续只输出 `profile_question_figure_item` 行级定位，不允许直接替换。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue conflict resolution bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`question_figure_repair_queue.entries[]` -> 同目标多 ready 候选被 N2.260 标记为 conflict -> 人工选择一个 `selected_queue_id` -> `_resolve_question_figure_repair_queue_conflict(..., confirmed=True)` -> 被选候选恢复 ready -> Workbench 输出 `profile_question_figure_repair_candidate` -> AssetsPanel 继续走既有单候选人工确认替换与审计链路；未选候选转 rejected 并保持行级定位。

这让“冲突发现”与“人工选择后继续替换”之间不再断链。

## 4. 明确不宣称完成

- 不做完整人工冲突裁决 UI；
- 不做自动候选优先级排序；
- 不做图片内容质量判断；
- 不做批量确认执行；
- 不做批量/事务回滚；
- 不写回 Word 或远端素材库；
- 不改变 N2.257-N2.259 已有的单候选应用、审计和回滚边界。

当前能力只承诺：已经被人工明确选中的冲突候选，可以在数据层解除冲突并重新接入单候选替换链路。真正的可视化冲突选择器、自动推荐和批量确认仍是后续产品化边界。

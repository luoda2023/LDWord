# 模板内页脚与页码对象草案（2026-04-11）

## 1. 这份草案回答什么问题

这份草案只回答一个很具体的问题：

**“特殊页码到底应不应该放在场景里，还是模板里只保留常规页脚？”**

结论是：

1. 特殊页码不应该放在场景里。
2. 模板也不应该“只定义常规页脚”。
3. 正确边界是：**模板同时拥有 footer 外观载体和 page number 语义计划**。

也就是说，模板内应该同时有两层：

1. `footer`：页脚怎么呈现
2. `page_number_plan`：页码怎么编号

场景只负责：

1. 是否启用 `header_footer` 模块
2. 哪些 section 参与格式化

---

## 2. 设计原则

### 2.1 footer 与 page number 是同一条链路，不要拆所有权

在 Word 里，页码并不是一个纯“业务开关”，它实际依赖：

1. footer 是否存在
2. footer 里是否插入 PAGE field
3. 当前 section 的 `w:pgNumType`
4. section break 是否正确插入

所以如果把：

- “常规页脚”放模板
- “特殊页码策略”放场景

后面几乎一定会重新出现双重所有权，导致：

1. 页脚样式在模板里
2. 页码阶段在场景里
3. 执行时必须再做一层拼装
4. UI 和持久化边界再次变脏

### 2.2 这块应当是“模板拥有完整页脚语义”

因此更合理的分法不是：

- 模板 = 常规页脚
- 场景 = 特殊页码

而是：

- 模板 = 完整页脚语义
- 场景 = 是否启用、处理范围

---

## 3. 推荐最终对象结构

## 3.1 顶层目标

推荐把页眉页脚配置收敛为：

```python
@dataclass
class HeaderFooterConfig:
    typography: HeaderFooterTypographyConfig = field(
        default_factory=HeaderFooterTypographyConfig
    )
    header: HeaderConfig = field(default_factory=HeaderConfig)
    footer: FooterConfig = field(default_factory=FooterConfig)
    page_number_plan: PageNumberPlanConfig = field(
        default_factory=PageNumberPlanConfig
    )
```

这个结构的核心思想是：

1. `header` 管页眉内容与显示规则
2. `footer` 管页脚载体与显示规则
3. `page_number_plan` 管页码编号语义
4. `typography` 管页眉页脚共同字体

这样比把所有字段继续平铺在 `HeaderFooterConfig` 顶层更稳，也比“把特殊页码扔给场景”更干净。

---

## 3.2 typography

```python
@dataclass
class HeaderFooterTypographyConfig:
    font_cn: str | None = None
    font_en: str | None = None
    size_pt: float | None = None
```

职责：

1. 定义页眉页脚共同字体
2. 不参与编号语义
3. 不参与 section 切换

保留原因：

1. 现有实现已经把 `font_cn/font_en/size_pt` 作为页眉页脚公共字体
2. 这部分属于稳定的外观参数，不值得和 phase 编号策略绑在一起

---

## 3.3 header

```python
@dataclass
class HeaderConfig:
    mode: str = "styleref"          # "styleref" | "fixed" | "none"
    fixed_text: str = ""
    styleref_level: int = 1
    border: bool = True
    hide_on_cover: bool = True
```

职责：

1. 定义页眉内容来源
2. 定义页眉横线
3. 定义封面是否隐藏页眉

说明：

1. `mode=styleref` 对应当前 STYLEREF 跟随模式
2. `mode=fixed` 对应当前固定页眉文本
3. `mode=none` 对应彻底不显示页眉
4. `hide_on_cover` 是现有 `hide_cover_header_footer` 的一部分语义拆分

---

## 3.4 footer

```python
@dataclass
class FooterConfig:
    content_mode: str = "page_number"   # "page_number" | "none"
    hide_on_cover: bool = True
```

职责：

1. 定义 footer 这个载体是否启用
2. 定义 footer 在封面是否隐藏
3. 决定 page number plan 是否实际渲染到文档

这里故意**不急着**把 footer 做成“大而全富文本模型”，原因是：

1. 当前系统真实支持的 footer 内容本质上只有页码
2. 如果现在就把 footer 扩成固定文本、前后缀、左右三栏、混合字段，会显著扩大改造面
3. 本轮目标是把页码策略边界做干净，不是一次性发明一个新的页脚排版引擎

所以推荐先把 `footer` 收敛为非常小的载体对象，只表达：

1. 有无 footer 内容
2. 当前 footer 内容是不是页码

如果未来要扩展，可以在不破坏 `page_number_plan` 的前提下增加：

- `fixed_text`
- `content_layout`
- `prefix/suffix`
- `mixed_content`

---

## 3.5 page_number_plan

```python
@dataclass
class PageNumberPhaseConfig:
    phase_id: str = ""
    selectors: list[str] = field(default_factory=list)
    visible: bool = True
    number_format: str = "decimal"      # decimal | upperRoman | lowerRoman
    start_mode: str = "continue"        # continue | restart
    start_value: int = 1


@dataclass
class PageNumberPlanConfig:
    phases: list[PageNumberPhaseConfig] = field(default_factory=list)
    on_missing_doc_tree: str = "warn_and_fallback"
    validation_mode: str = "strict"     # strict | warn
```

职责：

1. 定义页码阶段
2. 定义每个阶段命中哪些 section
3. 定义格式、起号方式、起始值
4. 定义 `doc_tree` 缺失时如何退化

注意：

1. 这里不再保留 `enabled` 字段
2. 是否渲染页码由 `footer.content_mode` 决定
3. 这样可以避免 `page_number_enabled` 和 `page_number_plan.enabled` 两个布尔值互相打架

这是个很重要的收敛点：

- `footer` 决定“要不要显示页码”
- `page_number_plan` 决定“如果显示，怎么编号”

---

## 4. 为什么不要把页码开关放回 plan 里

如果同时存在：

1. `footer.content_mode`
2. `page_number_plan.enabled`

就会出现新的歧义：

1. `content_mode=page_number` 但 `enabled=false`
2. `content_mode=none` 但 `enabled=true`

这类状态本身没有业务价值，只会制造额外判断分支。

因此建议：

1. `footer` 决定显示与否
2. `page_number_plan` 只保存规则
3. 即使当前不显示页码，也允许保留原有编号计划，方便用户重新打开时不丢策略

---

## 5. 推荐 selector 集

为了让模板可读、UI 可配、执行稳定，建议内置 selector 为：

```python
PAGE_NUMBER_SELECTORS = (
    "cover",
    "front_matter",
    "abstracts",
    "toc",
    "body",
    "back_matter",
    "references",
    "errata",
    "appendix",
    "acknowledgment",
    "resume",
    "all_numbered_content",
)
```

默认展开语义：

1. `front_matter` = `abstract_cn + abstract_en + toc`
2. `back_matter` = `references + errata + appendix + acknowledgment + resume`
3. `all_numbered_content` = 除 `cover` 外所有可编号内容区
4. `abstracts` = `abstract_cn + abstract_en`

## 6. 当前旧字段如何映射到新对象

推荐映射如下：

| 当前字段 | 新对象字段 |
|------|-----------|
| `header_mode` | `header.mode` |
| `header_text` | `header.fixed_text` |
| `styleref_level` | `header.styleref_level` |
| `header_border` | `header.border` |
| `font_cn` | `typography.font_cn` |
| `font_en` | `typography.font_en` |
| `size_pt` | `typography.size_pt` |
| `page_number_enabled` | `footer.content_mode = "page_number" / "none"` |
| `hide_cover_header_footer` | `header.hide_on_cover` + `footer.hide_on_cover` |
| `front_matter_page_number_format` | `page_number_plan.phases[front].number_format` |
| `front_matter_page_number_start` | `page_number_plan.phases[front].start_value` |
| `body_page_number_format` | `page_number_plan.phases[body].number_format` |
| `restart_body_page_number` | `page_number_plan.phases[body].start_mode` |
| `body_page_number_start` | `page_number_plan.phases[body].start_value` |

其中旧 front/body 二段式建议迁移为：

```python
page_number_plan = PageNumberPlanConfig(
    phases=[
        PageNumberPhaseConfig(
            phase_id="front",
            selectors=["front_matter"],
            visible=True,
            number_format=front_matter_page_number_format,
            start_mode="restart",
            start_value=front_matter_page_number_start,
        ),
        PageNumberPhaseConfig(
            phase_id="body",
            selectors=["body", "back_matter"],
            visible=True,
            number_format=body_page_number_format,
            start_mode=("restart" if restart_body_page_number else "continue"),
            start_value=body_page_number_start,
        ),
    ]
)
```

## 7. 推荐模板保存形态

模板最终推荐保存成类似：

```yaml
header_footer:
  typography:
    font_cn: 宋体
    font_en: Times New Roman
    size_pt: 10.5

  header:
    mode: styleref
    fixed_text: ""
    styleref_level: 1
    border: true
    hide_on_cover: true

  footer:
    content_mode: page_number
    hide_on_cover: true

  page_number_plan:
    validation_mode: strict
    on_missing_doc_tree: warn_and_fallback
    phases:
      - phase_id: front
        selectors: [front_matter]
        visible: true
        number_format: upperRoman
        start_mode: restart
        start_value: 1
      - phase_id: body
        selectors: [body, back_matter]
        visible: true
        number_format: decimal
        start_mode: restart
        start_value: 1
```

这个结构有几个优点：

1. 一眼就能看出“页脚载体”和“页码编号”是两个不同层次
2. 仍然都属于 `header_footer`，不会拆散所有权
3. 比现在平铺字段更容易扩展
4. 未来 UI 可以直接按对象分组渲染

---

## 8. scene 应该保留什么，不该保留什么

## 8.1 scene 保留

scene 只保留：

1. `module_switches["header_footer"]`
2. `format_scope`
3. 场景级行为开关

## 8.2 scene 不再保留

scene 不应继续持有：

1. `front_matter_page_number_format`
2. `body_page_number_format`
3. `restart_body_page_number`
4. `body_page_number_start`
5. 任何 `header_footer.xxx` 的隐式 `template_overrides`

如果未来真的需要“场景覆盖模板页码策略”，也不应退回 dotted-key，而应单独引入：

```python
scene.template_appearance_overrides.header_footer.page_number_plan
```

但这属于后续扩展，不是当前必要项。

## 9. 对当前代码结构的建议

当前 `feature_configs.py` 文件头写的是：

1. 这些配置属于 feature-specific config
2. 它们由 scene module switches 控制
3. 它们之所以不放 `template.py`，是因为 scene 也要引用

如果页码策略正式迁到模板侧，这段语义就不再完全成立。

所以建议分两步走：

### 9.1 第一阶段

先只改“语义所有权”，不急着大搬文件：

1. `TemplateConfig` 继续持有 `header_footer`
2. `SceneWorkspace` 不再承载页码策略
3. loader / resolver / UI 先完成边界收口

这样可以减少第一轮改动面。

### 9.2 第二阶段

再考虑把 header/footer 模型从 `feature_configs.py` 中抽出来，例如：

1. `src/config/header_footer_config.py`
2. 或直接并回 `template.py`

我更推荐单独拆文件，而不是直接塞回 `template.py`，因为：

1. `template.py` 已经比较大
2. header/footer 自身就是一组独立模型
3. 单独文件更利于 UI、migration、resolver 共用

---

## 10. 最终建议

这块的最稳做法不是：

- 模板只管常规 footer
- 场景再补一层特殊页码

而是：

1. 模板内统一拥有 `header`
2. 模板内统一拥有 `footer`
3. 模板内统一拥有 `page_number_plan`
4. 场景只决定启用与处理范围

换句话说：

**特殊页码不是场景能力，它是模板版式的一部分。**

所以后面实现时，建议我们按这个对象结构直接推进：

1. 先把 `HeaderFooterConfig` 拆成 `typography/header/footer/page_number_plan`
2. 再把旧平铺字段迁移进去
3. 最后再改 loader / resolver / UI / execution

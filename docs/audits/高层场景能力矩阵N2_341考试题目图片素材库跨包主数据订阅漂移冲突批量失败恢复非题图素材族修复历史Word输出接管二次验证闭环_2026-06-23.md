# 高层场景能力矩阵 N2.341 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出接管二次验证闭环

## 1. 本轮定位

N2.340 已经能生成 `.header-footer-rewrite.docx`，并证明页眉/页脚 relationship 指向了恢复后的非题图素材。但修复副本如果只停留在 manifest 里，还不能算“历史输出已接管”。本轮 N2.341 补上 adoption second-pass verification：在 rewrite 完成后显示 `Adopt`，对 repaired DOCX 做二次 Word XML/media 扫描与素材内容命中验证，生成 adoption manifest，并把 adopted path 回写为新的历史 DOCX 目标。

## 2. 新增能力

- 新增 adoption action：`asset_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_non_question_asset_family_repaired_historical_word_output_adoption_second_pass_verification`。
- adoption 消费 N2.340 的 header/footer rewrite record 与 N2.338 的 execution record。
- 对 repaired DOCX 路径进行二次扫描：确认 `xml_media_consistent`、header/footer part 状态、media 状态和恢复素材 hash 命中。
- 生成 JSON/Markdown manifest，记录 adopted docx count、second-pass verified count、asset media verified count 和 adoption rows。
- metadata 回写 adoption status、adoption id、manifest paths、adopted docx count、second-pass verified count、asset-media verified count。
- adoption 会保存 `original_historical_docx_path(s)`，同时把 `historical_docx_path(s)` 指向 adopted repaired DOCX，供后续 verification 和写回链路消费。
- UI 链路推进为：`Record -> Execute -> Verify -> Rewrite -> Adopt -> Manifest`。

## 3. 当前边界

本轮完成的是本地 repaired DOCX 的接管与二次验证，不声明完成正式远端写回：

- 未把 adopted DOCX 上传到远端资料库或主数据仓。
- 未处理远端覆盖、保留原件、冲突合并、审批和幂等重试。
- 未做跨输出版本的正式对账。
- 未把 adopted DOCX 发布为最终交付包的唯一正式产物。

下一缺口推进为：

- pack：`advanced question asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote writeback handoff execution UI`
- family：`advanced asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote writeback handoff execution UI`

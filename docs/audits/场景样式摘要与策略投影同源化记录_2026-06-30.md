# 场景样式摘要与策略投影同源化记录

日期：2026-06-30

后续进展：`StylePolicyToggleList` 已完成泛化，旧 `StyleOverrideToggleList` 保留为兼容包装，详见 `docs/refactor-records/StylePolicyToggleList泛化与旧Override兼容记录_2026-06-30.md`。

后续进展：样式策略主链路已迁移到 `policy_*` API，详见 `docs/audits/样式策略PolicyAPI主链路迁移记录_2026-06-30.md`。

## 1. 本轮目标

上一轮已经完成：

```text
StyleObjectProjection.policy
-> StyleManagementBlock
-> StyleRuleControlDeck.apply_projection(...)
```

但场景分区样式仍有一个明显不一致点：摘要区还由 `scene_panel._refresh_style_override_summary()` 手动维护。

旧链路是：

```text
_refresh_style_override_summary()
  -> set_summary_items(...)
  -> set_restore_all_enabled(...)
  -> set_undo_restore_all_enabled(...)
```

这和模板管理的对象投影链路不一致。模板管理是先构建 `StyleObjectProjection`，再由 `StyleManagementBlock` 统一下发。

本轮目标是让场景样式的摘要、策略、差异和预览来自同一份 projection。

## 2. 新链路

现在场景分区样式刷新路径收束为：

```text
scene state changed
-> build_scene_section_style_projection(...)
-> StyleObjectProjection.summary_items
-> StyleObjectProjection.policy
-> StyleObjectProjection.difference
-> StyleObjectProjection.preview_projection
-> StyleManagementBlock.apply_style_object_projection(...)
```

`scene_panel._refresh_style_override_summary()` 不再直接操作摘要和按钮，而是触发：

```text
_sync_style_editor()
```

也就是重新应用当前样式对象 projection。

## 4. 和模板管理的一致性提升

模板管理：

```text
build_template_body_style_projection(...)
-> summary_items / owner_state
-> StyleManagementBlock
```

场景分区样式：

```text
build_scene_section_style_projection(...)
-> summary_items / owner_state / policy / difference / preview
-> StyleManagementBlock
```

现在两者差异主要来自业务能力，而不是 UI 组织方式。

场景多出的能力被放在结构化字段里：

- `policy`：分区开关、可见性、批量恢复动作
- `difference`：当前分区和模板基线差异
- `preview_projection`：当前分区样式预览
- `summary_items`：摘要区状态

## 5. 对“说人话”的影响

这轮没有直接重写大量界面文案，但它让文案减法有了结构基础。

后续可见文本应该优先来自这些结构化状态：

```text
override_status：整体是否全部跟随模板
current_variant_status：当前分区状态
owner_boundary：全局样式去模板管理修改
policy.restore_all：全部跟随模板是否可点
policy.undo_restore_all：撤销恢复是否可点
```

不再需要在卡片中解释“策略、分区数量、功能数量、内部 key”等技术信息。

## 6. 当前仍保留的兼容层

以下 API 仍保留：

```text
SceneStyleRulesBlock.set_summary_items(...)
SceneStyleRulesBlock.set_restore_all_enabled(...)
SceneStyleRulesBlock.set_undo_restore_all_enabled(...)
SceneStyleOverrideSection.set_summary_items(...)
SceneStyleOverrideSection.set_restore_all_enabled(...)
SceneStyleOverrideSection.set_undo_restore_all_enabled(...)
```

保留原因：

1. 现有测试仍覆盖这些公开 wrapper。
2. 外部跳转和面板间调用可能仍依赖这些方法。
3. 本轮目标是移除场景面板的直接状态维护，而不是一次性删除所有兼容 API。

这些方法应逐步退化为兼容入口，不再成为主链路。

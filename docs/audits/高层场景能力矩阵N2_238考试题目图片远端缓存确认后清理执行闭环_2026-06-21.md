# 高层场景能力矩阵 N2.238 考试题目图片远端缓存确认后清理执行闭环

## 1. 背景

N2.237 已经在 AssetsPanel 前台把清理 dry-run 结果推进到可确认：用户确认后会写入 `<shared_cache_dir>/cleanup_confirmation.json`，并把下一次执行清理所需参数写回当前资料档。

但仅写回参数仍不足以构成执行闭环。Workbench 执行侧如果不消费 `cleanup_confirmation.json`，就无法证明真实清理范围和前台确认范围一致。本轮闭合确认后清理执行首片：当 entity_data 携带 cleanup confirmation 字段时，执行侧必须验证目录级 confirmation 记录；只对验证通过的目录执行清理，未验证目录写入跳过状态。

## 2. 闭合范围

本轮闭合：
- Workbench 执行侧读取 `remote_asset_cache_cleanup_confirmation_id` 与 `remote_asset_cache_cleanup_confirmed_task_id`；
- 支持 `remoteAssetCacheCleanupConfirmationId`、`question_figure_cache_cleanup_confirmation_id`、`question_asset_cache_cleanup_confirmation_id`、`cache_cleanup_confirmation_id` 等别名；
- 执行真实清理且携带 confirmation 字段时，逐目录读取 `<cache_dir>/cleanup_confirmation.json`；
- 只有 `confirmation_id`、`source_task_id` 和 `status=confirmed` 匹配的目录会执行清理；
- 未匹配 confirmation 的目录不删除文件、不改写 index，记录 `status=confirmation_missing`；
- cleanup payload 写入 `confirmation_status`、`confirmation_id`、`confirmation_source_task_id`、验证目录数、缺失目录数和 confirmation paths；
- 每个目录 payload 和 cleanup history record 写入目录级 confirmation 状态；
- manifest 摘要暴露 `cache_cleanup_confirmation_*` 字段；
- 资料包报告新增 `Cleanup confirmation` 行；
- 成熟度矩阵增加 `question asset remote cache cleanup confirmed execution bridge` evidence。

本轮不做：
- 跨 profile 后台定时清理；
- 全局任务列表、任务取消、任务重试；
- 后台队列、并发调度和断点续传；
- 自动生成或续签素材库 API 凭证；
- 清理策略编辑器和批量任务审阅面板。

## 3. 数据链路

前台确认记录：
```text
<shared_cache_dir>/cleanup_confirmation.json
```

执行输入参数：
```text
remote_asset_cache_cleanup=true
remote_asset_cache_cleanup_dirs=<shared_cache_dir>
remote_asset_cache_cleanup_dry_run=false
remote_asset_cache_cleanup_confirmed_task_id=<source_task_id>
remote_asset_cache_cleanup_confirmation_id=<confirmation_id>
```

执行侧验证：
```text
for each cleanup_dir:
  read <cleanup_dir>/cleanup_confirmation.json
  match confirmation_id + source_task_id + status=confirmed
  verified -> execute cleanup
  missing  -> status=confirmation_missing, no mutation
```

manifest 摘要字段：
```text
cache_cleanup_confirmation_requested
cache_cleanup_confirmation_status
cache_cleanup_confirmation_id
cache_cleanup_confirmation_source_task_id
cache_cleanup_confirmation_verified_dir_count
cache_cleanup_confirmation_missing_dir_count
cache_cleanup_confirmation_paths
```

## 4. 边界说明

无 confirmation 字段的旧式显式清理行为保持兼容；这是为了不破坏已有自动化和测试。只有从 N2.237 前台确认入口进入的清理参数，才会启用确认守卫。

当 confirmation 守卫启用时，执行侧不会因为当前运行缓存目录也在 observed dirs 中而顺手清理未确认目录。未确认目录会保留在 cleanup payload 和报告里，状态为 `confirmation_missing`，用于提示后续任务系统或前台 UI 继续处理。

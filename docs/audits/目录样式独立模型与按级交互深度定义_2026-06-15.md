# 目录样式独立模型与按级交互深度定义（2026-06-15）

## 1. 结论

目录页的原始模型是正确的：目录应该保留自己的样式角色，而不是直接复用标题编号页的标题样式。

正确调整方向是：

- 目录内容来源于标题识别、标题编号和 `include_in_toc`；
- 目录样式归属于目录自己的可见结果角色；
- UI 复用“按级编辑”的交互形态；
- 数据仍写入 `toc_title / toc_level1...toc_level6`；
- 不把目录条目样式改成 `heading1 / heading2...`。

这次需要修正的不是“目录独立样式是否存在”，而是目录样式编辑器的交互组织方式。

## 2. 关键边界

标题编号页负责标题本身：

- 标题编号如何组成；
- 标题编号如何计数；
- 标题正文如何显示；
- 某级标题是否加入目录。

目录页负责目录输出对象：

- 是否生成目录；
- Word 自动目录或普通目录；
- 目录深度；
- 插入位置；
- 目录标题样式；
- 各级目录条目样式。

标题编号可以决定目录条目的文本内容，例如“第一章 绪论”是否进入目录；但不能因此接管目录条目的排版样式。目录条目是 Word 的 TOC 输出对象，应该由 `TOC 1...TOC 6` 和对应的 `toc_level1...toc_level6` 控制。

## 3. 当前问题重新定义

之前误判的问题是把“复用交互控件”理解成“复用标题编号数据源”。这会造成几个严重偏差：

- 目录页变成了标题编号页的入口；
- 摘要卡显示“跟随标题编号”，误导用户；
- `TOC 1...TOC 6` 从 `heading1...heading6` 派生，覆盖了目录自己的设置；
- `toc_title / toc_levelN` 变成旧字段，破坏了旧模板和用户心智。

正确的问题定义应该是：

- 原有 `toc_title / toc_level1 / toc_level2 / toc_level3` 是合理的；
- “目录共享样式”不适合作为 UI 角色，只应该作为内部 fallback；
- 旧的目录样式表单堆叠太重，和“按级编辑”的交互语言不一致；
- 静态目录预览不是实时预览，容易误导；
- “目录联动”是解释文本，不是当前任务的操作控件。

## 4. 正确 UI 形态

目录页保留两个区域：

```text
目录结构
目录样式
```

目录结构只保留：

- 启用目录；
- 目录模式；
- 目录深度；
- 插入位置。

目录样式采用按级编辑式交互：

- 左侧列表：目录标题、1 级目录、2 级目录、3 级目录，随目录深度扩展到 6 级；
- 右侧 Inspector：当前角色样式预览、字体、字号、字形、对齐、特殊缩进、左右缩进、行距、段前段后；
- 不显示目录共享样式；
- 不显示静态整目录预览；
- 不显示目录联动说明；
- 不嵌入标题编号面板。

## 5. 执行层规则

Word 原生目录：

- `TOC Heading` 使用 `toc_title`；
- `TOC 1` 使用 `toc_level1`；
- `TOC 2` 使用 `toc_level2`；
- 依此类推到 `TOC 6`；
- 若角色样式不存在，则 fallback 到 `styles.toc`，再 fallback 到正文或 normal。

普通目录：

- 收集标题时仍使用标题识别和 `include_in_toc`；
- 4 级标题进入目录时保留为 `TOC 4`；
- 不再把 3 级以上压成 `TOC 3`；
- 格式化时仍使用 `toc_levelN`，不是 `headingN`。

## 7. 后续判断标准

后续目录页改动需要遵守：

- 目录内容可来自标题体系，目录样式不能被标题样式接管；
- 复用控件形态可以，不能复用错误的数据源；
- fallback 可以存在于代码，不作为用户可编辑角色暴露；
- 没有真实文档上下文时，不放静态整目录预览；样式页只允许预览当前选中 TOC 角色；
- 跨模块关系进入诊断或跳转，不常驻为说明卡。

# 高层场景能力矩阵 N2.256 考试题目图片对比修复候选队列确认替换计划闭环

## 1. 本轮定位

N2.255 已经把 `question_figure_repair_queue.entries[]` 接入 Workbench issue queue，并能通过 `profile_question_figure_item` action 回到对应 profile 的 AssetsPanel 题图行。但候选项仍只停留在“可定位”，没有告诉前台或后续执行层：这个候选是否具备可替换来源、为什么不能替换、确认后应该调用什么受控动作。

N2.256 关闭的是“候选队列确认替换计划”的首片：在 batch repair queue entry 中写入确认动作、ready/blocked 状态、本地替换来源和阻断原因，并在 AssetsPanel 提供 `apply_question_figure_repair_candidate(..., confirmed=True)` 的受控应用入口。它仍不是完整一键替换 UI，也不是批量自动应用；它只把“人工确认后可替换”的最小安全合同落下来。

## 2. 已实现能力

- `_batch_question_figure_repair_queue()` 为每个候选项追加确认计划字段：
  - `confirmation_action=confirm_question_figure_replacement`
  - `confirmation_apply_supported`
  - `confirmation_status=ready|blocked`
  - `replacement_source_path`
  - `replacement_source_kind=local_file`
  - `apply_blockers`
- `_question_figure_repair_apply_plan()` 只允许本地真实文件作为替换来源：
  - 缺少 `question_figure_item` 修复目标时阻断；
  - 缺少 `repair_target_key` 时阻断；
  - 缺少 comparison reference 时阻断；
  - reference 不是本地文件时阻断；
  - http/https、asset、lark 等远端或抽象引用不会被误判为可直接替换。
- Markdown batch report 的 `Question Figure Repair Queue` 行追加 `confirm=ready|blocked`，让人工审阅时能看到确认状态。
- `WorkbenchExecutionAdapter.question_figure_repair_queue_issue_items()` 在问题详情中展示：
  - 确认替换可用/不可用；
  - 替换来源路径；
  - 阻断原因；
  - 确认状态。
- `AssetsPanel.apply_question_figure_repair_candidate()` 提供受控应用入口：
  - 必须显式传入 `confirmed=True`；
  - 候选必须 `confirmation_status=ready`；
  - 候选必须 `confirmation_apply_supported=True`；
  - 替换来源必须仍然是本地存在文件；
  - 目标必须能解析到当前题图行；
  - 最终复用现有 `_replace_question_figure_item_path()`，保证 archive、material context、题图表和预览状态继续一致。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue confirmation plan bridge` evidence。

## 3. 链路闭合

当前链路为：

`comparison_issue_* metadata` -> `batch_issue_items[].comparison_issue_items[]` -> `question_figure_repair_queue.entries[]` -> `confirmation_* / replacement_source_* / apply_blockers` -> `WorkbenchIssueItem.details` -> `profile_question_figure_item` 行级定位 -> `AssetsPanel.apply_question_figure_repair_candidate(candidate, confirmed=True)` -> `_replace_question_figure_item_path()` -> `EntityArchive` / `MaterialExecutionContext` / 题图表 / 预览同步。

这让 N2.255 的“可点击定位”继续推进为“可判断是否能安全替换，并可在人工确认后执行单候选替换”。后续如果要做真实一键按钮，可以复用同一组 confirmation 字段和 AssetsPanel 入口，而不是重新发明替换目标 schema。

## 4. 明确不宣称完成

- 不做完整前台一键确认按钮；
- 不做批量确认应用；
- 不做自动替换；
- 不处理多个候选同时指向同一题图的冲突裁决；
- 不做撤销、回滚、审计日志或替换前快照；
- 不写回 Word、资料包或远端素材库；
- 不下载远端 comparison reference 再替换；
- 不做内容级错图识别、视觉 diff 或 AI 判图。

当前能力只承诺：候选项能形成可审计确认计划；本地文件来源的 ready 候选能在显式人工确认后替换当前 AssetsPanel 的题图行。其他都仍属于高级素材库后续产品化边界。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.255 的“候选队列问题动作路由”推进到 N2.256 的“候选队列确认替换计划”。已闭合能力新增：候选项能区分 ready/blocked，能说明阻断原因，能把本地替换来源交给 AssetsPanel 的人工确认入口执行。

仍保留的高级素材库边界是：真实素材库 API 登录/续期/签名与授权续期、跨资料包/后台定时清理、后台全局任务中心、断点续传/后台队列/并发下载调度、跨资料包长期命中率趋势中心、真实素材库预览服务/签名预览 URL 续期、自由框选/多区域标注/标注图层编辑、完整一键确认 UI、批量确认执行、替换审计/回滚、内容级错图识别、复杂学科图或 AI 质量判断。

# 高层场景能力矩阵 N2.178 固定版式 Profile 产品化能力矩阵

日期：2026-06-19

## 1. 定位

N2.178 承接 V39 的 P0 缺口：把固定行高、内容控件、文本框、套打/证书/登记表/答题卡等固定版式能力，从“Word/OOXML first slice 已有实现”推进到“可审计、可浏览、可报告、可走 release gate”的产品化闭环。

它不是通用表格模板功能，也不是新的顶层 pack。它是一个横跨场景矩阵、Word 风险、控件契约、执行模块、报告证据和修复路由的 profile 层。

## 2. 覆盖的高频场景

| 高频场景 | 承载层 | 固定版式对象 | 当前闭环 |
| --- | --- | --- | --- |
| 批量登记表、申请表、HR 表单 | `batch_forms` / `form_batch_documents` | `w:trHeight`、内容控件、文本框、占位符残留 | 11/11 profile channel ready |

| 标书/合同/政策材料里的嵌入式内容块 | `bidding_materials`、`contract_delivery`、`official_policy` | content control、textbox shape | fixed-layout text runtime 和 entity fill 已覆盖 |

## 4. 边界裁决

- `TableConfig.row_height_pt` 不回到普通表格模板。固定行高只在 fixed-layout profile 中承接，并明确对应 Word `w:trHeight`。
- N2.178 不做所见即所得表单设计器，不承诺拖拽控件排版、不承诺复杂版面自动重建。
- N2.178 不验证证书、奖状、合同或表单资料真实性。资料事实仍归 MaterialSchema/InputSourceProfile/人工确认链路。
- 答题卡和试卷固定区域可进入 ObjectPreflight 与 fixed-layout profile，但出题质量、复杂图生成、AI 内容生成仍属于 plugin/manual boundary。
- 内容控件和文本框替换只承诺可识别、可映射、可报告；对不可结构化嵌套对象继续走风险报告和人工确认。

## 6. 当前仍非 Green/L5 的原因

N2.178 现在是“审计与可见性闭环”，不是完整产品化终点。仍需后续补深：

- 前台 fixed-layout profile 浏览器还需要从“summary/card/drilldown 可见”推进到“可筛选、可预览、可解释每个 Word 对象风险”。
- 固定版式预览需要更接近真实用户 journey：批量登记表、证书、答题卡、套打表单至少覆盖成功、降级、失败、人工确认四类路径。
- 报告 artifact drilldown 仍应进一步支持从控制契约跳回具体输出、compare、manifest、intermediate 和 issue repair。
- 控件样式需要继续遵守模板管理控件契约：同一语义同组件、同单位、同禁用态、同 tooltip/status 语言；固定行高入口不能在普通表格控件里复活。

## 8. 结论

N2.178 已经把“固定行高是不是残留参数”的问题正式裁决为：固定行高不是普通表格配置，也不应从模型里退场；它属于 fixed-layout profile，并通过 Word `w:trHeight`、运行时策略、UI/报告证据、repair route、dashboard/drilldown/summary 和 release gate 形成闭环。

这一步让高层场景能力矩阵在固定版式域不再只有边界声明，而有可回归的产品化证据。下一步应继续推进 N2.180 report/artifact drilldown 和真实业务 fixture 深度，而不是继续扩张顶层 pack。

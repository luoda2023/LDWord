# 试卷母版定义深度分析

日期：2026-07-01

## 1. 当前问题

现在的实现仍然不对，根因不是某几个占位符难看，而是对象定义错了。

目前 `打开母版` 的行为是：

```text
点击按钮 -> 用代码临时生成一个 Word -> 打开这个 Word
```

这会导致三个问题：

- 用户看到的不是“母版源文件”，而是一次性生成物。
- Word 里出现的文字很容易变成调试占位，例如试卷标题、题目内容区域、下划线。
- 后续正式生成不一定真正基于用户看到的那个文件，用户无法信任它。

所以继续美化这个临时 Word，不是最正确的方向。

## 2. 正确定义

试卷母版应该是一个真实存在、可追踪、可复制、可校验的 `.docx` 文件。

它不是：

- 不是样张。
- 不是正式试卷。
- 不是代码临时拼出来的预览文件。
- 不是通用模板管理里的论文/报告模板。

它应该是：

```text
试卷场景专用的 Word 母版文件。
```

它负责定义：

- 标题区的位置和样式。
- 考试信息栏的位置和样式。
- 考生信息栏是否存在。
- 注意事项区是否存在。
- 题目正文从哪里开始。
- 题目区、答题区、页眉页脚、页码的基本版式。
- 学生卷和答案版共享哪些页面结构。

它不负责定义：

- 本次考试标题。
- 本次科目、年级、考试时间、满分。
- 真实题目内容。
- AI 出题。
- 题图素材管理。

## 3. 最合理的对象分层

建议把试卷场景拆成四个对象：

| 对象 | 用户理解 | 程序责任 |
| --- | --- | --- |
| 试卷场景 | 我要做哪类试卷 | 选择题稿识别、答案处理、工作台字段 |
| 试卷母版 | 这张卷子的外框长什么样 | 提供真实 `.docx` 母版文件和装配槽位 |
| 试卷样张 | 套入示例题后效果如何 | 用同一母版和固定示例题生成校验文件 |
| 工作台任务 | 本次要生成哪份卷子 | 填写本次信息、导入题稿、生成正式产物 |

其中 `试卷母版` 是长期配置，`工作台任务` 是每次执行。

## 4. 文件归属

最合理的文件结构应当是：

```text
exam_masters/
  builtin/
    default_exam.docx
    compact_exam.docx
  user/
    default_exam_copy.docx
```

内置母版：

- 随程序提供。
- 不允许直接覆盖。
- `打开母版` 可以打开只读副本，或打开原文件但提示不可直接修改。

用户母版：

- 通过 `复制后修改` 从内置母版复制出来。
- 当前场景切换到这个副本。
- 用户可以打开编辑。
- 样张和正式生成都基于这个副本。

这样用户一眼能理解：

```text
默认试卷是系统自带的。
我要改，就先复制一份。
改完之后，样张和正式生成都会用我的副本。
```

## 5. 母版文件应当怎么做

真正的 Word 母版不应该靠可见的 `【字段】` 来表达规则。

更合适的做法是：

- 页面上保持自然的人类可读外观。
- 程序使用 Word 内容控件、书签、样式名或段落标记识别装配位置。
- 用户打开时看到的是正常卷面，而不是开发调试符号。

推荐母版结构：

```text
试卷标题
科目：        年级：        考试时间：        满分：
姓名：        班级：        考号：

注意事项
1. 请在规定区域内作答。
2. 保持卷面整洁。

一、题目区
题目内容由系统在这里装入。

页脚：第 X 页 / 共 Y 页
```

但其中“题目区”不应只是普通文本。

程序层需要给它一个稳定标识，例如：

```text
content_control tag="exam.questions"
```

或：

```text
bookmark name="exam_questions_start"
```

这样母版既能被人看懂，也能被程序稳定装配。

## 6. UI 应该怎么改

`试卷装配` 卡片只做规则：

```text
空白试卷样式  默认试卷
题目装配      按 Markdown 标题识别
答案处理      学生卷 + 答案版
```

`试卷母版` 卡片应该这样：

```text
试卷母版

默认试卷                       内置
标准 A4 卷面；含标题区、考试信息栏、考生信息栏、注意事项、题目区和页脚。

[查看母版] [生成样张] [复制后修改]
```

按钮定义：

| 按钮 | 正确行为 |
| --- | --- |
| 查看母版 | 打开真实内置母版文件，或打开只读副本 |
| 生成样张 | 用当前母版 + 固定示例题生成样张 |
| 复制后修改 | 从当前母版复制出用户母版，切换当前场景，并打开编辑 |

当当前母版是用户副本时：

```text
默认试卷 副本                  可修改
基于：默认试卷

[打开编辑] [生成样张] [恢复内置]
```

## 7. 为什么现在的“打开母版”仍然不对

即使当前生成的 Word 看起来更干净，它仍然不是真正母版。

因为它还是：

```text
运行时生成的展示文件
```

而不是：

```text
正式装配会使用的母版源文件
```

用户关心的不是“系统能不能生成一个空白 Word”，而是：

```text
我以后正式生成试卷时，就是用这个外框吗？
我改了这个外框，生成结果真的会变吗？
```

所以最正确的修复不是继续调整临时 Word，而是把母版变成一等文件资源。

## 8. 后续实现方案

第一阶段只做必要闭环：

1. 新增内置母版文件目录。
2. 提供真实 `default_exam.docx`。
3. `打开母版` 改为打开这个真实文件。
4. `复制后修改` 改为复制这个真实文件到用户目录。
5. `ExamPaperConfig` 保存当前母版文件引用。
6. `生成样张` 使用当前母版文件生成。
7. 测试确认样张确实使用当前母版。

暂时不做：

- 不做题图。
- 不做 AI 出题。
- 不做复杂母版设计器。
- 不做通用模板面板混入。

## 9. 验证标准

真正完成后，必须能回答这些问题：

| 问题 | 验证方式 |
| --- | --- |
| 用户打开的是不是母版源文件 | 文件路径来自 `exam_masters/builtin` 或 `exam_masters/user` |
| 内置母版会不会被误改 | 内置只读，编辑必须复制 |
| 用户副本能不能被保存 | 场景配置保存用户母版引用 |
| 样张是否用当前母版 | 修改副本后生成样张，样张反映副本变化 |
| 正式生成是否用当前母版 | 工作台执行读取同一个母版引用 |

## 10. 最终结论

最合适的设计是：

```text
试卷母版 = 试卷场景专用的真实 Word 母版文件。
打开母版 = 打开这个真实文件。
生成样张 = 用这个真实文件跑示例题。
复制后修改 = 复制真实文件，切换场景到副本。
```

现在继续优化代码生成的空白 Word，方向仍然会偏。下一步应该把 `default_exam` 从“代码里的样式定义”升级成“真实内置母版文件”。

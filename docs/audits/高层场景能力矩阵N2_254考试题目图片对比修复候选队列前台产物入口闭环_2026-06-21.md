# 高层场景能力矩阵 N2.254 考试题目图片对比修复候选队列前台产物入口闭环

## 1. 本轮定位

N2.253 已经生成 `question_figure_repair_queue`，但它主要停留在 batch payload 与 JSON/Markdown report 中。若真实线程执行或前台 adapter 不保留该字段，用户仍只能打开报告后自行查找，不能在最近运行产物清单里直接看到“题图修复候选队列”。

N2.254 关闭的是“候选队列前台产物入口”的首片：把 `question_figure_repair_queue` 从 runtime 透传到 `ExecutionWorker`、`WorkbenchExecutionAdapter`、`ExecutionResultState`、`RecentRunState` 与 `RecentRunPanel.artifact_items`。它仍不做自动替换，不做一键写回，只让候选队列成为可见、可打开、可验收的前台产物。

## 2. 已实现能力

- `ExecutionWorker._normalize_result()` 保留：
  - `batch_issue_items`
  - `question_figure_comparison_matrix`
  - `question_figure_repair_queue`
- `WorkbenchExecutionController.apply_execution_result()` 与 legacy `WorkbenchPanel.apply_execution_result()` 将 `question_figure_repair_queue` 传入 adapter。
- `ExecutionResultState` 与 `RecentRunState` 新增 `question_figure_repair_queue`。
- `WorkbenchExecutionAdapter._build_artifact_items()` 在队列非空时新增 artifact：
  - `kind=question_figure_repair_queue`
  - `label=candidates`
  - `group_id=reports`
  - `status=warning`
  - `path` 优先指向 `_batch_report.md`，没有 Markdown 时退到 JSON report
  - `fragment=question-figure-repair-queue`
  - `detail=题图修复候选 N 项，需要人工确认，自动应用关闭`
- `RecentRunPanel` 新增 artifact kind 标签“题图修复候选”。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue artifact bridge` evidence。

## 3. 链路闭合

当前链路为：

runtime `question_figure_repair_queue` -> `ExecutionWorker` normalized payload -> `WorkbenchExecutionController` / `WorkbenchPanel` -> `WorkbenchExecutionAdapter.build_result_state()` -> `ExecutionResultState.question_figure_repair_queue` -> `ArtifactItemState(kind=question_figure_repair_queue)` -> `RecentRunState.artifact_items` -> `RecentRunPanel` 产物清单。

这补上了 N2.253 的真实前台消费断点：队列不再只是报告内部字段，而是最近运行结果里可见的产物入口。

## 4. 明确不宣称完成

- 不自动替换题图；
- 不批量应用候选项；
- 不提供应用前后 diff 预览；
- 不写回资料包或 Word；
- 不做撤销、回滚、审计日志；
- 不做内容级错图识别或 AI 判图。

当前能力只承诺“候选队列可见、可打开、可验收”。下一步若继续推进，应进入“一键确认执行/自动替换”层，并同时设计确认、回滚、冲突和审计边界。

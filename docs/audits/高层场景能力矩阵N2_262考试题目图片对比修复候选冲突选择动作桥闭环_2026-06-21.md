# 高层场景能力矩阵 N2.262 考试题目图片对比修复候选冲突选择动作桥闭环

## 1. 本轮定位

N2.261 已经补上冲突裁决的数据层策略：当人工明确选中一个冲突候选时，队列可以把该候选恢复为 ready，并把未选候选转为 rejected。

N2.262 关闭的是“前台选择动作桥首片”：当 Workbench 问题队列里展示某个本地可替换的 conflict 候选时，用户点击该候选的处理动作，系统可以把“选择当前候选”表达成专用 action，继续走现有单候选确认替换链路，并在 AssetsPanel 替换审计中保留冲突裁决上下文。

## 2. 已实现能力

- `_apply_question_figure_repair_queue_conflict_guard()` 为本地可替换的 conflict 候选写入：
  - `conflict_resolution_select_supported=True`；
  - `conflict_resolution_action=select_question_figure_replacement_conflict_candidate`。
- `question_figure_repair_queue_issue_items()` 在 Workbench issue 详情中展示：
  - 冲突组；
  - 冲突动作；
  - “冲突裁决：可选择此候选”；
  - 同组候选 queue id。
- `workbench_issue_action_target()` 对可选择的 conflict 候选输出：
  - `profile_question_figure_repair_conflict_selection`；
  - payload 中的候选会被转为 `confirmation_status=ready`；
  - payload 保留 `conflict_resolution_status=selected`；
  - payload 保留 `conflict_selected_queue_id`；
  - payload 保留 `conflict_resolution_candidate_queue_ids` 和 `conflict_resolution_rejected_queue_ids`；
  - `candidate_conflict_same_repair_target` blocker 会在被选候选上移除。
- `WorkbenchPanel._open_issue_repair_target()` 支持新 action，并复用现有 `PanelBridge.material_profile_repair_candidate_requested` 将候选交给 AssetsPanel。
- `AssetsPanel` 替换审计记录新增冲突裁决字段：
  - `conflict_group_id`；
  - `conflict_resolution_status`；
  - `conflict_resolution_action`；
  - `conflict_selected_queue_id`；
  - `conflict_resolution_group_id`；
  - `conflict_resolution_candidate_queue_ids`；
  - `conflict_resolution_rejected_queue_ids`；
  - `conflict_resolution_by`；
  - `conflict_resolution_note`。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue conflict selection action bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`question_figure_repair_queue.entries[]` -> 同目标多 ready 候选被标记为 conflict -> 本地可替换 conflict 候选写入 `conflict_resolution_select_supported` -> Workbench issue 显示可选择此候选 -> QuickExecutionDetail 处理按钮发出 `profile_question_figure_repair_conflict_selection` -> WorkbenchPanel 解码并通过 bridge 交给 AssetsPanel -> AssetsPanel 按 ready 候选执行替换 -> 审计记录保留 selected/rejected 冲突上下文。

这让 N2.261 的数据层裁决策略真正有了前台动作入口。

## 4. 明确不宣称完成

- 不做多候选并排比较弹窗；
- 不做自动候选优先级排序；
- 不做图片内容质量判断；
- 不做批量确认执行；
- 不做批量/事务回滚；
- 不写回 Word 或远端素材库；
- 不改变普通 blocked/conflict 候选的保护：没有 `conflict_resolution_select_supported=True` 的 conflict 候选仍只定位，不会被当作可应用候选。

当前能力只承诺：用户在 Workbench 问题队列中点击某一个“可选择此候选”的 conflict 候选时，该候选会被视为人工选择结果并接入现有确认替换链路。完整候选对比选择器、自动推荐和批量裁决仍是后续产品化边界。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.261 的“候选冲突裁决策略首片”推进到 N2.262 的“候选冲突选择动作桥首片”。已闭合能力新增：前台不再只能定位 conflict 候选；对本地可替换且被标记为可选择的 conflict 候选，可以通过 Workbench 问题处理动作表达“选择此候选”。

仍保留的高级素材库边界是：真实素材库 API 登录/续期/签名与授权续期、跨资料包/后台定时清理、后台全局任务中心、断点续传/后台队列/并发下载调度、跨资料包长期命中率趋势中心、真实素材库预览服务/签名预览 URL 续期、自由框选/多区域标注/标注图层编辑、完整候选对比选择器、自动候选优先级策略、批量确认执行、批量/事务回滚、内容级错图识别、复杂学科图或 AI 质量判断。

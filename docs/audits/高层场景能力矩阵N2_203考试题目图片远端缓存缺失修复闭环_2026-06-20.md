# 高层场景能力矩阵 N2.203 考试题目图片远端缓存缺失修复闭环

## 1. 本轮定位

N2.203 继续执行 V43 的 P0 高级考试素材库路线，补齐 N2.202 后留下的一个窄断点：

```text
远端 question_figure 已有 asset_id/source/cache_path，
但 cache_path 指向的本地缓存文件不存在或失效时，
诊断、问题队列和前台修复入口必须能定位到同一条题图资产。
```

本轮不实现真实远端下载、鉴权、缓存刷新器或无缓存远端预览；这些仍属于高级题图素材库的后续边界。

## 2. 断点分析

N2.202 已经让缓存路径参与前台预览和运行时渲染：

- AssetsPanel 能显示缓存文件名；
- Workbench 渲染时可用 `metadata.cache_path` 作为本地图片路径；
- manifest 保留 `path="" + asset_id/source/cache_path`；
- 缓存文件存在时可正常插入 Word。

但缓存文件缺失时仍有一个不够稳的地方：`repair_target_key` 里的 `path` 更偏向原始 `AssetItem.path`。远端缓存资产常常没有原始本地 path，只把本地缓存落在 `metadata.cache_path`。这会导致问题队列虽然能报告缺图，但前台回链在缺少 `item_id` 或跨批量记录定位时，不能把“该修哪一条缓存题图”表达得足够明确。

## 3. 本轮实现

### 3.1 执行侧 repair target 增强

`_question_figure_item_repair_target_key()` 现在会把缓存路径提升为一等修复目标字段：

```json
{
  "role": "question_figure",
  "item_id": "question_figure_2",
  "question_index": "2",
  "path": ".../missing_cached_question_2.png",
  "cache_path": ".../missing_cached_question_2.png",
  "asset_id": "remote-question-2",
  "metadata": {
    "asset_id": "remote-question-2",
    "source": "lark_asset_library",
    "cache_path": ".../missing_cached_question_2.png"
  }
}
```

其中：

- `path` 使用 `_asset_render_path()`，即普通本地 path 优先，远端/空 path 时落到 cache path；
- `cache_path` 单独写入，避免调用方必须解析 metadata；
- `asset_id` 单独写入，继续保留远端资产身份；
- `metadata` 保留完整上下文，方便后续真实下载/刷新器接管。

### 3.2 前台修复定位增强

AssetsPanel 的题图修复目标匹配现在支持：

- `item_id`;
- `question_index` / `questionId` / `question_no` / `number`;
- 原始 `path`;
- 预览路径 `_asset_item_preview_path()`;
- `cache_path` / `cachePath` / `cached_path` / `local_path` / `resolved_path` / `download_path` / `asset_path`;
- `asset_id` / `assetId`。

这意味着即使 repair target 不携带 `item_id`，只携带缺失缓存文件路径，也可以回到题图明细表的对应行，并显示“缓存缺失”状态。

### 3.3 替换链路同步

`_question_figure_payload_matches_item()` 同步纳入缓存路径匹配。这样用户在“缓存缺失”行点击替换后，更新的是当前结构化 `asset_items` payload，而不是落到模糊的普通图片槽位。

## 4. 闭环链路

```text
CSV/XLSX 或 JSON asset_items
-> metadata.asset_id/source/cache_path
-> AssetsPanel 题图明细表显示缓存文件名 + 缓存缺失
-> Workbench 预检发现 cache_path 文件不存在
-> material_diagnostics: preflight_missing_question_figure_file
-> batch_issue_items: repair_target_type=question_figure_item
-> repair_target_key 带 path/cache_path/asset_id/metadata
-> Workbench issue queue
-> AssetsPanel.focus_material_repair_target()
-> 定位到缺失缓存题图行
-> 用户替换本地文件后刷新 material context
```

## 5. 成熟度证据

`scene_product_readiness` 新增 evidence：

```text
question asset remote cache miss repair bridge
```

覆盖对象：

- `pack:exam_education`
- `family:exam_teaching`

这使高级考试素材库从“缓存路径可被渲染”推进到“缓存路径失效也可被报告并修复”。N2.204 已继续追补远端无缓存引用的报告与修复回链；它仍不等于完整远端素材库，因为真实下载、鉴权、缓存刷新策略和远端内容预览还没有实现。

## 6. 仍未闭合的边界

N2.204 后，`advanced question asset library UI` / `advanced asset library UI` 的剩余边界收窄为：

- 远端素材真实下载、鉴权、缓存刷新策略和远端内容预览；
- 内容级错图识别：图片内容、OCR、题干语义或图像相似度比对；
- 复杂学科图、几何图、公式图的生成或插件接管；
- AI 出题质量、素材质量、版权或真实性判断；
- 更完整的素材库批量审阅、历史版本、学科/题型标签和复用治理。

# 高层场景能力矩阵 N2.267 考试题目图片对比修复批量应用 Word 媒体写入闭环

日期：2026-06-21

## 1. 本轮目标

N2.267 承接 N2.266 的 `batch_apply_execution_plan`。N2.266 已经能生成“如果进入批量执行，会处理哪些 frozen queue 和 repair target”的任务草案，但仍明确不写 Word。

本轮关闭第一段真实 Word 写入能力：在显式确认、计划 ID 和计划指纹均匹配时，根据执行计划草案，把源 docx 复制为一个新的修复 docx，并替换其中唯一匹配原题图字节哈希的 `word/media/*` 文件。

## 2. 已实现结构

运行时新增 `_apply_question_figure_repair_batch_execution_to_docx()`。

- `question_figure_repair_queue`

## 3. Word 写入策略

本轮不尝试解析任意视觉语义，也不尝试自动判断图片内容是否正确。写入策略是可审计、可阻断的：

- 从 planned entry 的 `repair_target_key` 解析原题图路径；
- 读取原题图文件的 SHA-1；
- 扫描输入 docx 的 `word/media/*`；
- 只有当某个媒体文件字节哈希与原题图唯一匹配时，才允许替换；
- 替换源必须存在；
- 替换源扩展名必须与 docx 内媒体文件扩展名一致；
- 输出写到新的 docx，不覆盖输入 docx。

因此，本轮能真实产出一个图片已替换的 Word 副本，同时避免在匹配不唯一或无法验证时误写。

## 4. 阻断边界

以下情况会阻断：

- 缺少 `batch_apply_execution_plan`；
- 执行计划不是 `planned`；
- 执行计划未 ready；
- 未显式确认；
- 缺少或不匹配 `expected_plan_id`；
- 缺少或不匹配 `expected_execution_plan_fingerprint`；
- 执行计划指纹被篡改或失配；
- 输入 docx 缺失或不是有效 zip/docx；
- 输出路径缺失或等于输入路径；
- 输入 docx 没有 `word/media/*`；
- 原题图文件缺失；
- 替换源文件缺失；
- 原题图哈希在 docx media 中找不到；
- 原题图哈希在 docx media 中匹配多个媒体文件；
- 多个计划 entry 指向同一 docx media；
- 替换源扩展名与原媒体扩展名不一致。

## 6. 不宣称完成

本轮仍不宣称：

- 完整批量事务中心；
- 跨多 docx 的后台任务调度；
- 批量事务回滚；
- 复杂重复图片的智能 disambiguation；
- 图像内容质量判断；
- 自动候选优先级排序；
- 完整候选对比选择器。

N2.267 是 Word 媒体写入首片：能对一个计划内 docx 输出修复副本，但还不是完整批量执行产品中心。

# 高层场景能力矩阵 N2.393f Warning 来源级治理读数归因补充

## 背景

N2.381 已将残留 warning 统一治理为 `managed_warnings=10/10`，N2.393d 又把 dashboard 投影 warning 补成 `dashboard_warning_projection=3/3 governed`。扫描 release gate 后仍可看到两个来源级裸读数：

- `scene_input_source_warning_count=5`
- `scene_count_profile_warning_count=2`

本轮补充的发布读数是：`input_warnings=5/5 managed` 与 `count_profile_warnings=2/2 managed`。

## 闭环定义

`input_warnings=5/5 managed` 表示 5 个输入源 warning 全部由插件/人工输入边界承接：

- IP/patent documents 的专业输入边界；
- exam education 的复杂图示插件/人工边界；
- professional disclosure 的专业输入质量边界；
- import AI boundary 的导入轴边界与插件/人工边界。

`count_profile_warnings=2/2 managed` 表示 2 个 CountProfile warning 全部由参考 profile 治理承接：

- `basic`
- `word_xml_full`

这两个 profile 作为 reusable fallback/reference profile 存在，不是场景 family 的 ready promise，因此不能被当成缺失的场景计数能力。

## 链路

```text
scene_input_source_audit.warning_count
  -> scene_residual_warning_governance_audit.input_source_managed_warning_count
  -> verify_scene_matrix_release_gate.py: input_warnings=5/5 managed

scene_count_profile_audit.warning_count
  -> scene_residual_warning_governance_audit.count_profile_managed_warning_count
  -> verify_scene_matrix_release_gate.py: count_profile_warnings=2/2 managed
```

## 发布要求

- release gate 最终摘要必须展示 `input_warnings=5/5 managed`；
- release gate 最终摘要必须展示 `count_profile_warnings=2/2 managed`；
- dashboard 的 Managed warnings 卡片必须展示 input/count profile 的成对治理读数；
- summary projection 的 Boundary、Evidence、Readiness 视角必须展示来源级 warning 治理读数；
- `scene_residual_warning_governance_audit` 的 source evidence 必须检查 release gate 中的 `input_warnings=` 和 `count_profile_warnings=` marker。

## 非目标

本轮不消除这些 warning，也不把插件/人工输入边界或参考 CountProfile 改写为 Green/L5 能力。它只关闭“warning 来源是否已经被治理归因”的读数缺口。

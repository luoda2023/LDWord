# 高层场景能力矩阵 N2.304 考试题目图片素材库远端写回批量回滚补偿清单与 Drilldown 闭环

## 1. 背景

N2.303 已经把远端当前快照冲突推进到字段级合并回滚：当远端被第三方改动时，用户可以按字段选择回滚值或远端当前值，并以 batch rollback execution 审计记录沉淀。

本轮闭合 N2.303 后明确保留的缺口：批量回滚/补偿完成后，缺少一份可导出的 manifest 清单，也缺少事务报告表里的独立 drilldown 入口。它不启动后台任务，也不承诺 OAuth/SSO 或组织权限主数据，只承诺把已发生的事务报告、回滚、二次补偿和待回滚余量整理成可追踪产物。

## 2. 已闭合能力

- 事务报告表新增 manifest 行为：当批量事务已生成报告、至少执行过一次回滚/补偿、且待回滚余量为 0 时，显示“生成清单”。
- 清单生成后，同一操作位切换为“定位清单”，用于打开 Markdown/JSON 清单或提示清单已记录在历史中。
- 新增历史记录 `question_figure_library_remote_writeback_batch_rollback_manifest`。
- manifest 历史记录保存 `transaction_report_changed_at`、`transaction_execution_changed_at`、`transaction_plan_signature`、`manifest_status`、`manifest_item_count`、`manifest_pending_rollback_count`、`manifest_drilldown_anchor`、`manifest_payload` 和产物路径。
- manifest payload 汇总以下视角：
  - 事务报告元数据与事务报告项；
  - 原批量执行结果项；
  - 所有 batch rollback execution 及其 result items；
  - 所有 second compensation execution 及其 result items；
  - 当前仍待回滚的 pending items；
  - report/rollback/second compensation/pending 的计数摘要。
- manifest 文件导出为 JSON 与 Markdown；默认写入 `artifacts/remote_writeback_manifests`，如果当前素材项有本地文件路径，则写到素材所在目录。
- Markdown 清单提供事务报告、执行记录、计划签名、清单项数、待回滚余量、事务报告项、回滚执行和二次补偿执行摘要。
- 回滚冲突字段合并成功后，manifest payload 能追溯 `question_figure_library_remote_writeback_batch_rollback_field_merge` connector 和合并后的 result item。
- 清单生成不会改变原回滚/补偿结果，只作为审计产物和 drilldown 入口叠加在现有链路之上。

## 3. UI 链路

- 未生成事务报告：仍显示“生成报告 / 定位失败”。
- 已生成事务报告且仍有待回滚项：仍显示“执行回滚”，不提前生成 manifest。
- 回滚失败仍未处理：保留“定位回滚失败 / 定位失败”，manifest 不会伪装闭合。
- 回滚或补偿已闭合且待回滚为 0：显示“生成清单 / 定位失败”或“生成清单 / 定位批次”。
- 生成清单后：显示“定位清单 / 定位失败”或“定位清单 / 定位批次”。

## 5. 仍不宣称完成

- 后台任务化、进度持久化、取消、重试队列和断点恢复；
- 并发控制、限流、指数退避、失败重放和幂等任务锁；
- OAuth/SSO 登录、token 自动续期、签名 URL 自动续签；
- 组织、角色、题库权限申请或审批；
- 跨资料包素材主数据版本系统；
- 更完整的后台任务 drilldown，例如任务时间线、重试历史和多批次比较。

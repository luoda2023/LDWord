# 高层场景能力矩阵 N2.346 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决回滚执行闭环

## 1. 定位

N2.345 已经把失败的 remote conflict decision 归档到 rollback queue governance。本轮 N2.346 继续向前推进一格：让 queued 状态不再停留在可审计计划，而是可以执行队列项，记录远端状态确认、重试/重放交接和人工复核分流结果。

这里的“执行”不是简单再次写回。对于权限不足、远端仍冲突、输入阻断等失败裁决，通常可以证明远端没有发生本次裁决副作用；这类队列项应记录 `no_remote_change_confirmed`，并交给对应 resolution action 后续重试或重放。只有无法确认无副作用的普通执行失败，才进入 `manual_remote_state_review_required`。

## 2. 本轮闭环

- `queued` 状态下表格提供 `Execute`、`Manifest`。
- `Execute` 消费 rollback queue governance record 中的 `queue_items`，生成 rollback execution record。
- execution record 写入独立 JSON/Markdown manifest，目录为 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_queue_executions`。
- 对 `rollback_required=no_remote_change_confirmed` 的队列项，执行结果记录为 `rollback_execution_confirmed_no_remote_change`，并标记 `retry_or_replay_handoff_ready`。
- 对需要人工远端状态复核的队列项，执行结果记录为 `rollback_execution_manual_remote_review_required`，并标记 `blocked_until_remote_state_review`。
- execution metadata 回写到相关 profile 的 asset item，表格状态推进为 `executed` 或 `review`。
- `Manifest` 优先级调整为 execution > queue > decision > connector > 前序治理，避免执行后打开旧阶段报告。

## 3. 链路变化

失败裁决链路现在变为：

```text
... -> Govern -> Decide -> Queue -> Execute -> Manifest
```

其中 `Execute` 的职责是把队列项从“待治理计划”推进到“已确认远端状态/已分流重试或人工复核”的执行归档。

# 高层场景能力矩阵 N2.184 场景旅程运行时报告闭环

日期：2026-06-20

## 1. 目标

本文承接 V40 在 N2.183 之后的 P0 路线：把 project / product / professional / import 这些已经具备 user journey fixture 的证据，推进到一次真实执行可见的 runtime/report/artifact/repair 桥接层。

本轮不把任何 subject 升为 Green/L5。它闭合的是“fixture 和 business capability 证明有规划，但用户执行报告里看不到这条旅程”的断链。

## 2. 落地内容

新增 `src/shared/engine/scene_journey_runtime.py`：

- `build_scene_journey_runtime_evidence(config)`：从当前 config 推导 coverage pack / planned family，再读取 `scene_user_journey_fixture_audit` 和 `scene_business_capability_matrix_audit`；
- 输出命中的 journey path、request-cell、fixture、manual gate、expected report、artifact channel、repair target 和 boundary note；
- `SceneJourneyRuntimeResult` / `SceneJourneyRuntimePath` 提供 report-ready payload。

接入执行链：

- `PipelineContext` 新增 `scene_journey_runtime`；
- `Pipeline` 在加载文档后写入 `scene_journey_runtime` tracker 记录；
- `report_writer` 的 JSON 报告新增 `scene_journey_runtime`；
- Markdown 报告新增“场景旅程运行时证据”段。

## 3. 本轮覆盖的高频路径

project / product：

- `project_application` 可在运行时报告看到 missing-items、budget attachment、rule-source、material repair、artifact drilldown bridge；
- `product_sales_documents` 可在运行时报告看到 asset report、customer/internal version report、delivery preset repair 和 material repair。

professional / import：

- `professional_disclosure` 继续保持 Blue/Boundary，但运行时报告会显式暴露 `professional_disclosure_review_gate`、professional source quality report 和 boundary confirmation；

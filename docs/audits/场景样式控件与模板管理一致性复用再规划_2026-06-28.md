# 场景样式控件与模板管理一致性复用再规划（2026-06-28）

## 1. 本轮结论

这轮复查后的核心判断是：场景页现在最大的问题不是“少解释”，而是控件归属仍然不够清晰。用户看到的是一组状态卡和内部词汇，但真正要操作的是三件事：

1. 选择一个模板基线。
2. 决定这个场景相对模板要覆盖什么。
3. 处理运行时资料、风险保护和输出交付。

因此场景页不能继续按内部审计维度堆卡片。它应该复用模板管理的字段编辑器、摘要、预览和字段定位模型，只把“场景特有的运行时契约”放在场景页里。工作台只做问题分诊和跳转，不拥有任何样式控件。

## 2. 与模板管理的对比

模板管理当前较清晰的地方：

- 有稳定的编辑对象：页面、正文排版、标题编号、表格、页眉页脚、目录、参考文献、题注。
- 每个对象有自己的详情页和参数行，用户知道自己正在改哪一类 Word 样式。
- 样式预览直接呈现页面比例、页边距、标题层级、正文排版效果。
- 字段定位已经形成链路：问题目标 -> 模板面板 -> 卡片 -> 具体控件高亮。

场景页当前的不足：

- “场景概览”把规划状态、运行时证据、输入资料、输出能力和内部成熟度混在同一层。
- “样式覆盖”与模板正文/页面/表格控件还没有形成同一套视觉和字段契约。
- `schema` 曾被误认为资料面板目标，实际它属于场景输入契约；资料面板只应处理具体资料值和文件。
- 卡片内容里仍出现 `custom_basic`、`quick_formatting`、`Green/L5`、`template 13 / scene 37` 这类内部表达，用户很难知道下一步做什么。

## 3. 重新划分功能边界

### 模板管理

模板管理负责“文档格式事实源”。凡是能直接落到 Word 样式、页面设置、标题编号、表格样式、目录、题注、参考文献、页眉页脚的控件，都应优先由模板管理承载，并提供可复用编辑器。

场景页需要改这些字段时，不应重新造一套控件，而应通过共享编辑器或适配器暴露为“场景覆盖”。

### 场景管理

场景管理负责“运行时使用契约”。它应该聚焦：

- 使用范围：这个场景处理哪些章节、对象和风险面。
- 资料要求：输入格式、资料 Schema、必填字段、图片/附件角色。
- 样式覆盖：仅展示相对模板基线发生变化的字段。
- 风险保护：对象预检、固定版式、内容控件、文本框、宏等保护策略。
- 输出交付：交付 preset、命名、目录、版本和可见性规则。
- 证据样本：样本、报告、审计结果，只用于证明链路是否打通，不直接混入主编辑流程。

### 资料面板

资料面板负责“具体资料值”。它处理 `asset`、`field`、`question_figure_item`、profile 资料项和文件缺失修复。它不负责 `schema` 契约本身。

本轮已经把 `schema` / `material_schema` 收敛到场景内容卡 `scn_content`，避免用户从一个 Schema 问题被带到资料值编辑界面。

### 工作台

工作台负责“问题分诊和行动入口”。它不应该解释所有内部细节，也不应该拥有业务控件。它只需要：

- 展示用户能理解的问题标题、影响、证据。
- 给出一个主要动作。
- 通过注册表跳到正确面板、卡片、字段控件。

## 4. 信息架构建议

场景页建议从当前“状态卡矩阵”重排为六个结果导向板块：

1. 当前用途
   - 场景名称、关联模板、处理范围、是否可直接使用。
   - 不展示内部成熟度编号，把 `Green/L5` 归到开发/审计详情。

2. 资料要求
   - 输入格式、资料 Schema、必填字段、图片/附件角色。
   - 复用模板管理的表单行、选择器、摘要行和导航高亮。

3. 样式覆盖
   - 只列出相对模板基线改变的字段。
   - 字体、字号、行距、段前段后、缩进、对齐、固定行高等控件与模板管理共用。
   - 未覆盖时显示“跟随模板”，不再用大段文字解释继承关系。

4. 风险保护
   - 对象预检、宏、内容控件、文本框、固定版式、行高契约。
   - 状态表达使用“已保护 / 需确认 / 阻断”，不要直接暴露 `object_preflight`、`content_controls` 等内部 key。

5. 输出交付
   - 输出 preset、命名、目录、版本和可见性。
   - 与模板输出设置共享按钮样式、选择器和摘要控件。

6. 证据与样本
   - 样本、fixture、审计报告、链路完整性。
   - 只作为“为什么系统认为可用”的证据，不抢占主编辑区。

## 5. 需要删除或下沉的冗余文本

应从主界面删除或下沉到详情/tooltip：

- `custom_basic`、`manual / 提示`、`quick_formatting` 等内部策略 ID。
- `template 13 / scene 37 / material 6 / output 17` 这类开发计数。
- 英文审计句子，例如 “General formatting must preserve...”。
- `Green/L5` 这类成熟度标签。
- 已由控件状态表达的信息，例如“点击编辑可跳转”。

主界面建议保留：

- 可直接使用
- 需要补资料
- 需要人工确认
- 已保护
- 已跟随模板
- 已覆盖模板
- 点击修复

## 6. 控件复用准则

后续实现应按以下准则收敛：

- 字段控件优先复用模板管理控件，不在场景页复制一个“看起来类似”的版本。
- 字段命名、单位、placeholder、禁用态和错误态由共享目录提供。
- 场景覆盖只保存 override，不复制模板完整样式。
- 预览使用同一套版面投影：模板预览显示基线，场景预览显示“基线 + 覆盖”。
- 所有问题修复目标必须经过 `workbench_issue_navigation_for_target` 注册表。
- 所有可跳转字段必须能通过 focus projection 审计到具体控件。
- 工作台证据区继续复用 `EvidenceLineList` / `EvidenceActionBar`，不再散落自定义行动作。

## 7. 本轮已经落地的链路修正

本轮完成了三处关键收敛：

- `schema` 从资料面板目标中移出，改为进入场景内容卡 `scn_content`。
- 新增场景内容卡的 Schema 字段聚焦：主 Schema、Schema 列表、必填字段、图片角色均可被导航高亮。
- 固定版式批量证据审计改为追踪真正拥有路由映射的 `workbench_issue_navigation` 注册表，恢复 `0 issue / 12 of 12 ready`。

## 8. 还不够优秀的剩余缺口

下一轮不应继续堆说明文本，而应推进真正的控件级复用：

1. 抽出模板管理与场景覆盖共用的样式字段编辑器。
2. 建立字段显示名目录，把内部 key 统一映射为用户语言。
3. 让场景样式预览与模板预览使用同一渲染投影。
4. 将状态卡矩阵改为六个结果导向板块。
5. 把 `profile_schema` 这类 profile 级资料契约单独审计，明确它何时属于资料 profile，何时属于场景输入契约。
6. 增加截图级视觉回归，验证文字不溢出、卡片不堆叠、状态语义不靠长文解释。

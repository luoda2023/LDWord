# 高层场景能力矩阵 N2.393e 保留 Gap 封套读数归因补充

## 背景

N2.392 已建立 `scene_boundary_maturity_release_envelope_audit`，把 6 个 Blue/Boundary 成熟度保留项逐一打包为发布证据封套。N2.393b 又把 `maturity_l5_blocked=6/27` 补成 `maturity_l5_enveloped=6/6`。当前仍保留一个容易被误读的裸读数：`scene_product_maturity_upgrade_gap_count=6`。

本轮补充的发布读数是：`retained_gaps=6/6 enveloped`。

## 闭环定义

`retained_gaps=6/6 enveloped` 表示：

- 分母 6 来自 `scene_product_maturity_upgrade_audit.gap_count`；
- 分子 6 来自 `scene_boundary_maturity_release_envelope_audit.retained_gap_count`；
- 每个 gap 都必须进入同一条 release envelope，并关联外部 handoff、boundary guarded completion、readiness reconciliation、terminal release trace、boundary subject dossier 和 subject continuity；
- 这些 gap 被保留是边界事实，不是发布失败，但不能作为无归因缺口裸露在 release gate、dashboard 或 summary 中。

## 链路

```text
scene_product_maturity_upgrade_audit.gap_count
  -> scene_boundary_maturity_release_envelope_audit.retained_gap_count
  -> verify_scene_matrix_release_gate.py: retained_gaps=6/6 enveloped
  -> boundary_release_envelopes / maturity_upgrade dashboard cards
  -> scene_summary_projection
```

## 发布要求

- release gate 最终摘要必须展示 `retained_gaps=6/6 enveloped`；
- `boundary_release_envelopes` 卡片必须展示 `6/6 retained gaps enveloped`；
- `maturity_upgrade` 卡片必须同时展示 L5 blocker envelope 和 retained gap envelope；
- summary projection 的 Boundary、Evidence、Readiness 视角必须展示 `6/6 retained gaps enveloped`；
- `scene_boundary_maturity_release_envelope_audit` 的 source evidence 必须检查 release gate 中的 `retained_gaps=` marker。

## 非目标

本轮不消除 6 个 retained gaps，也不把对应主体升为 Green/L5。它只关闭“gap 是否已经被发布封套承接”的读数缺口。

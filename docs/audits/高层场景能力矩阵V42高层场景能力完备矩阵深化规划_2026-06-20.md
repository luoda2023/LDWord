# 高层场景能力矩阵 V42 高层场景能力完备矩阵深化规划

日期：2026-06-20

## 1. 文档定位

V41 已经回答“不要遗漏高频适用场景、不要让边界模糊”的总纲问题，但它仍偏规划说明。V42 继续把这个问题提升到能力矩阵本体：

```text
不是再列更多场景入口，
而是定义任一高频请求必须穿过的能力坐标、裁决字段和闭环证据。
```

V42 的目标是让后续每个功能补齐都能回答：

```text
用户怎么说
-> 应由哪个 pack/family/profile/schema/preset/manual gate/plugin 承载
-> 输入事实源是什么
-> 模板控件是否继承同一 control contract
-> Word/OpenXML 风险在哪
-> runtime consumer 是否存在
-> report/artifact/repair 是否能回链
-> 成功/降级/失败/人工/歧义/负例是否有 journey
-> 是否进入 fixture/test/release gate。
```

不能回答这些问题的功能，只能算 planning、boundary 或 future slice，不能算完整场景能力。

## 3. 当前基线判断

当前矩阵已经不再是“场景名列表”：

| 层级 | 当前判断 | 风险 |
| --- | --- | --- |
| 顶层覆盖 | 12 个 coverage pack 已覆盖主要高频心智 | 再扩 pack 会让导航和边界失控 |
| Family/profile | 15 个 planned family 已提供承载层 | thin profile 仍不足，尤其个人文档、培训资料、Excel/data-to-Word |
| 请求样本 | 52 request-cell 覆盖 matched/ambiguous/negative | 用户自然说法仍需要持续补样本 |
| Journey | 90 条 success/degraded/failure/manual/ambiguous/handoff/negative path | 产品 UI 和报告链路仍不等于 L5 |
| 业务能力 | 17/17 ready | 只是业务语义闭合，不代表普通用户可稳定完成 |
| 产品成熟 | 27/27 subject L5-blocked，49 个 product gap | 主战场是 UI、runtime、report、artifact、repair、rule、boundary |

因此 V42 的核心判断是：

```text
高频场景遗漏风险已经从“入口没有”转为“能力槽位没有定义清楚”；
边界模糊风险已经从“场景名相邻”转为“专业责任、导入质量、AI 质量和 Word 对象风险没有前台化”。
```

## 4. V42 能力矩阵坐标

任一场景单元必须由三类坐标定义。

### 4.1 场景承载坐标

| 坐标 | 可选值 | 说明 |
| --- | --- | --- |
| Pack | 12 个 coverage pack | 顶层入口，不轻易扩张 |
| Family | 15 个 planned family 或后续薄 family | 高频差异承载层 |
| Profile | 学校、期刊、个人、课程、产品、客户、表单、固定版式等 | 规则和资料的具体配置 |
| Schema | MaterialSchema、question schema、personnel schema、attachment schema | 机器事实源 |
| Preset | DeliveryPreset、BatchPreset、OutputPreset、VisibilityPreset | 交付版本和执行策略 |
| Manual gate | 法律、财务、医疗、专利、翻译质量、AI 质量、OCR/LaTeX 低置信 | 人工确认边界 |
| Plugin gate | OCR、LaTeX、复杂图、专业审查、翻译、财务/法律插件 | 核心不承诺的扩展能力 |
| Negative | 非 Word 交付或超出产品责任 | 明确拒绝或 handoff |

## 5. 高频场景不遗漏地图

V42 不新增顶层 pack，但把高频任务分成 10 个任务群。每个任务群必须落到既有 pack/family/profile 或 manual/plugin gate。

| 任务群 | 高频说法 | 承载层 | 当前必须补的深度 |
| --- | --- | --- | --- |
| 通用规范化 | 修格式、修目录、修页码、统一缩进、清理样式 | `quick_formatting` | 字段级修复、真实模板 fixture、对象风险前台化 |
| 轻量个人文档 | 简历、求职信、个人陈述、证明材料 | `quick_formatting` thin profile | request-cell、轻量 MaterialSchema、隐私提示、导出 preset |
| 学术/投稿 | 中文论文、英文 manuscript、cover letter、response letter | `chinese_academic`、`english_journal` | CountProfile/RuleSource UI、section scope、Bib/CSL、投稿包 artifact |
| 教育/培训 | 试卷、答案版、解析版、答题卡、讲义、练习册 | `exam_education` + education thin profile | 结构化题源、多版本显隐、题图素材库、复杂图/AI 质量边界 |
| 企业材料/标书 | 商务标、技术标、资质包、附件归档 | `bidding_materials` | 多主体 schema、证照附件 manifest、盖章/正副本边界 |
| 公文/制度/会议 | 通知、函、纪要、制度汇编、正式/内部/归档稿 | `official_policy` | 文号元数据、水印状态、归档报告、编号保留 |
| 长文档/出版 | SOP、接口文档、技术手册、验收报告、书稿 | `technical_long_docs` | 章节 inventory、索引/附录、多文件边界、对象预检 |
| 申报/售前 | 项目申报、基金、产品手册、白皮书、客户方案 | `application_reports` | 规则来源、附件清单、产品素材一致性、报价/手册歧义 |
| 合同/批量/表单 | 合同、NDA、offer、证明、证书、登记表、套打 | `contract_delivery`、`batch_forms` | 字段证据 UI、批量失败隔离、fixed-layout profile browser |
| 专业/导入/AI 边界 | 财务报价、ESG、专利、法律、医疗、翻译、OCR、LaTeX、AI | `professional_disclosure`、`import_ai_boundary` | manual/plugin gate、置信度 artifact、handoff、非承诺前台化 |

薄弱但高频的补强结论：

| 缺口 | 不新增 pack 的原因 | 正确补法 |
| --- | --- | --- |
| 个人轻量文档 | 本质是通用模板 + 少量资料字段 | `quick_formatting` thin profile |
| 培训课程资料 | 复用教育显隐和素材逻辑 | education thin profile + `exam_teaching` capability |
| Excel/data-to-Word | 横切输入方式，不是独立业务 | MaterialSchema + BatchPreset + target pack |
| 法律/医疗专业文书 | 专业责任强，不能混入合同/申报 | professional manual gate + negative/manual samples |
| 复杂学科图 | 不是 Word 排版核心能力 | image asset placeholder + plugin gate |
| AI 内容质量 | 核心只能结构化和渲染 | JSON schema + preview + manual quality gate |

## 6. 边界裁决树

新增需求进入矩阵前先走裁决：

1. 是否要求 Word 原生交付。不是则 negative 或 external plugin。
2. 是否只是普通外观样式。是则归模板管理，不新建场景功能。
3. 是否是场景侧复用样式控件。是则必须继承模板 control contract。
4. 是否是事实资料、人员、项目、产品、签章、图片、附件。是则归 MaterialSchema / AssetsPanel。
5. 是否是字数、词数、图表、公式、参考文献、规则来源。是则归 CountProfile / RuleSourceGovernance。
6. 是否是输出版本、命名、目录、PDF/ZIP/report/manifest/intermediate。是则归 DeliveryPreset / OutputConfig。
7. 是否是多记录、多人员、多公司、多项目、多模板。是则归 BatchPreset。
8. 是否是固定版位、证书、答题卡、套打、固定行高。是则归 fixed-layout profile。
9. 是否触碰字段、批注、修订、内容控件、文本框、OLE、宏、嵌入包。是则必须走 ObjectPreflight。
10. 是否涉及法律、财务、审计、专利、医学、翻译质量、AI 内容质量、OCR/LaTeX 无损转换。是则进入 PluginManualGate。
11. 是否能从导入边界 handoff 到目标 pack/family。能则必须有 handoff、置信度和回退策略。

新增顶层 pack 必须同时满足：

| 条件 | 标准 |
| --- | --- |
| 稳定用户心智 | 用户长期以该大类表达，而不是行业别名 |
| 独立事实源 | schema/profile/rule 与现有 pack 明显不同 |
| 独立交付 | 输出版本、目录、失败策略明显不同 |
| 独立 Word 风险 | OOXML 风险组合现有 pack 无法承载 |
| 独立证据链 | request-cell、fixture、report、repair、release gate 都有计划 |

## 7. 控件一致性准入

场景配置中的控件样式控制必须与模板管理保持同一语言。

| 控件/参数 | 归属 | 场景侧要求 |
| --- | --- | --- |
| 左缩进/右缩进 | TemplateConfig / paragraph controls | 同名、同单位、同步进；可同一行展示 |
| 段前/段后 | TemplateConfig / paragraph controls | 保持“段前/段后”和磅值语义 |
| 特殊缩进 | TemplateConfig / paragraph controls | 必须可切换无/首行/悬挂；无时禁用并归零 |
| 行距类型/行距值 | TemplateConfig / paragraph controls | 类型和值联动，runtime 未消费时只能 planned/boundary |
| 普通表格 | TableConfig | 只处理通用表格外观 |
| 固定行高 | fixed-layout profile | 对应 Word `w:trHeight`，不作为普通 `TableConfig.row_height_pt` 残留 |
| 水印 | DeliveryPreset / scene output semantics | 复用同名控件和报告字段 |
| 输出 | DeliveryPreset / OutputConfig | 命名、目录、PDF/ZIP/report/manifest 进入 artifact |
| 公式 | FormulaPolicy / plugin gate | OMML-first、fallback 和低置信报告 |
| 素材 | MaterialSchema / AssetsPanel | 缺项进入 repair target，不停留在 warning |

统一链路：

```text
Template control contract
-> ScenePanel / Workbench control
-> resolver / pipeline consumer
-> report field
-> issue queue / repair target
-> fixture / test / release gate
```

任一段缺失时，UI 不得表现为已执行能力。

## 9. N2.193 关联裁决

V42 之后执行的 N2.193 不新增 exam 的 Green/L5，也不移除 `advanced question asset library UI` 缺口。它只把高级考试素材库中一个高频可见性缺口闭合：

```text
CSV/Excel 题目图片1/2
-> EntityProfile.asset_items
-> AssetsPanel current asset items
-> question_figure frontstage detail table
-> 用户可核对每张图对应哪道题、说明是否存在、文件是否可用。
```

仍保留的高级素材库缺口：

- 前台逐题编辑；
- 单题缩略图预览/替换；
- 缺项修复入口；
- 远端 asset id/source；
- 一题多图/图组排序；
- 复杂学科图插件；
- AI/素材质量 manual boundary。

# 高层场景能力矩阵 N2.177 资料录入与修复能力矩阵

日期：2026-06-19

## 1. 结论

N2.177 将 MaterialSchema 从“资料 schema 已注册”推进到“资料缺口可发现、可报告、可路由、可聚焦、可确认”的产品链路。它不替代 N2.166 的横向 MaterialSchema 覆盖审计；N2.166 负责证明哪些 family/pack 需要哪些字段、图片、签章和附件，N2.177 负责证明这些资料缺失或 schema 冲突时，用户是否能从工作台和报告一路回到修复入口。

## 2. 外部参考边界

用户提供的 ChatGPT share 链接在当前环境只能看到标题方向“Word文档自动生成技术栈”，正文需要登录后才可见。因此，本轮只吸收其可见主题：Word 自动生成不能只规划模板样式，还必须把资料、结构化输入、执行产物、报告和修复链路放进同一技术栈视角。不可见正文不作为实现证据，也不作为 release gate 依据。

用户提供的 `count_engine_tech_record.md` 和 `exam_generator_tech_stack_record.md` 前序分析继续保留两条原则：

- CountProfile 只承接计数口径、范围和规则来源，不被 MaterialSchema 吞掉。
- 试卷/教育生成属于场景能力矩阵中的专业内容/结构化输出/内容显隐/插件边界，不应把 AI 出题质量伪装成普通资料字段修复。

## 3. N2.177 的 11 条能力通道

| 通道 | 产品问题 | 已锁定链路 |
| --- | --- | --- |
| `schema_requirements_to_assets_panel` | schema 中字段/资产是否真正投影到资料录入控件 | `MaterialSchema -> build_material_requirements -> AssetsPanel fields/assets/attachments` |
| `assets_panel_preview_missing_detection` | 用户录入后是否知道还缺什么 | `_current_preview_state -> missing_required_fields/missing_asset_roles -> next missing target` |
| `workbench_material_readiness_groups` | 运行前是否能按 schema/field/asset/source 分组 | `material_readiness_issue_groups -> evaluate_material_requirements -> source notes` |
| `material_issue_items_repair_targets` | warning 是否带可执行目标 | `WorkbenchIssueItem -> field/asset/schema repair_target_type` |
| `issue_queue_actionability` | 问题队列是否可筛选、可动作、可确认 | `summarize_workbench_issue_queue -> QuickExecutionDetail action/resolve/ignore` |
| `quick_material_repair_button` | 缺资料是否有直接入口 | `QuickExecutionDetail 补资料按钮 -> field/asset 优先路由 -> content_fill fallback` |
| `panel_bridge_material_routing` | Workbench 是否能打通资料修复面板 | `QuickExecutionDetail -> WorkbenchPanel -> PanelBridge -> AssetsPanel/content_fill` |
| `assets_panel_target_focus` | 修复入口是否能聚焦具体字段/资产/profile | `consume_material_repair_target -> focus_material_repair_target/profile target` |
| `schema_replacement_recommendation_flow` | unknown schema 是否能推荐替换并进入修复 | `recommend_material_schema_replacement -> tooltip/issue item/schema target` |
| `batch_profile_material_repair_targets` | 批量记录失败是否能定位到具体 profile | `batch_issue_items -> profile_field/profile_asset/profile_schema -> AssetsPanel profile focus` |
| `material_manifest_feedback` | 资料结果是否进入报告和资料包 | `_material_manifest_payload -> fields/asset_roles/missing/diagnostics/delivery` |

## 4. 高频场景覆盖矩阵

| 高频场景 | 资料能力要求 | N2.177 覆盖方式 | 明确边界 |
| --- | --- | --- | --- |
| 标书/资质包 | 公司、项目、法人、logo、公章、证照附件、正副本资料包 | 字段/资产/附件 schema 投影，缺项进入 issue queue，manifest/package 输出 | 不验证证照真实性，不做投标策略判断 |
| 合同/协议签章 | 合同主体、金额日期、签章/签名资产、schema 版本替换 | unknown schema 推荐替换，schema issue target 回 content_fill，签章资产走 AssetsPanel | 不提供法律意见，不验证签名真实性 |
| HR 批量文书 | 一人一记录字段、头像/签名、失败记录隔离 | batch issue items 进入 profile_field/profile_asset 路由 | 不做人事背景核验，不把失败记录混入成功输出 |
| 表单批量 | 表单字段、缺失值、逐记录报告 | profile-scoped repair target + batch isolation | 不审计业务数据真假 |
| 技术长文/产品手册 | 产品名、型号、技术图、附件说明 | schema 资产位、图片占位符预览、material package | 不承诺 AI 内容质量，不替代专业审稿 |
| 项目/售前/商务材料 | 客户、项目、案例、产品图、报价附件 | MaterialSchema + DeliveryPreset manifest 反馈 | 报价真实性和商业判断属于外部业务流程 |
| 专业披露/申报 | 机构、项目、引用附件、证据包 | schema/report/package 证据链，plugin/manual gate 保留 | 金融/法律/医学判断仍是人工或插件边界 |
| 教育/试卷 | 结构化题目、答案、显隐版本、素材 | 主要走 DeliveryPreset/ContentVisibility/structured intermediate；资料修复只覆盖素材事实 | 不把出题质量、答案正确性并入 MaterialSchema |
| 导入/改写类任务 | PDF/Markdown/Excel 来源、字段映射、缺失提示 | InputSourceProfile 与 MaterialSchema 分层，缺资料回修复入口 | 导入质量、OCR/AI 解析质量仍归导入/插件边界 |

## 5. 控件样式一致性要求

场景配置中的资料控件必须与模板管理已规定的控件语言保持一致：

- 字段、资产、schema 下拉和状态提示不能自造另一套样式，应复用现有 `StyledComboBox`、按钮 variant、tooltip、状态 badge 和 SummaryGrid 语义。
- 数值/单位类控件继续沿用模板管理的单位、禁用态和同组展示规则；资料模块不得把模板外观单位改写成资料事实单位。
- issue queue 的动作按钮、筛选、resolve/ignore 状态必须继续沿用 Workbench 的问题队列语义，不在资料面板中平行发明另一种“待处理/已处理”模型。
- schema 修复是资料事实源修复；普通字段/资产应精准进入 AssetsPanel，unknown schema 当前以 content_fill/schema 替换入口承接，后续如新增 schema selector，也必须服从同一控件契约。

## 6. 与高层能力矩阵的关系

N2.177 新增的 `material_repair_flow` 被纳入：

- release gate：`scene_material_repair_flow_audit`；
- dashboard：`fact_source`、`evidence_chain`、`product_readiness` lens，以及 `Material repair` card；
- drilldown：`material_repair_flow` 明细；
- summary projection：Evidence chain 增加 `11/11 material repair flows`；
- CI：`tests/test_scene_material_repair_flow_audit.py`。

这意味着高频场景不再只看“有没有 MaterialSchema”，而要同时看：

```text
MaterialSchema registry
-> AssetsPanel input controls
-> preview/missing detection
-> Workbench issue queue
-> repair route
-> target focus
-> manifest/report feedback
-> dashboard/drilldown/release gate
```

## 7. 仍保留的边界

- N2.177 不证明资料真实性，只证明资料缺口、schema 冲突和资料包反馈链路可见且可修复。
- N2.177 不等于完整 artifact browser；资料包路径和日志已进入执行结果，但更完整的报告 drilldown 与产物浏览仍归 N2.180。
- N2.177 不替代 N2.178 fixed-layout profile；行高、固定版位、content control 和复杂表格版式仍走 fixed-layout/Word OOXML 风险链。
- N2.177 不替代 N2.175 控件一致性；它依赖 N2.175 定义的控件语言，新增资料入口也必须服从同一控件契约。

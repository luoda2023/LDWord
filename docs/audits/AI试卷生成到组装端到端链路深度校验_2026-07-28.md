# AI 试卷生成到组装端到端链路深度校验

> 校验日期：2026-07-28  
> 校验对象：Alavette Form 的 AI 文档助手试卷生成链路  
> 校验方式：源码状态机审阅、正向真实组装、反向破坏性样例、恢复场景和回归测试  
> 结论边界：本文只对当前支持的“自然语言或已授权 DOCX 材料 → Markdown 题稿 → 学生卷/答案卷 DOCX”负责，不把模型内容质量、教学合理性或所有文件格式夸大为已自动解决。

## 1. 最终结论

当前支持范围内，AI 试卷生成主链已经从“能生成两个文件”收敛为“需求、内容、执行资源和交付产物都能被本地证据约束”的闭环：

```text
用户需求/授权材料
  → AI 对话或问题续答
  → 类型化试卷计划
  → AI 生成 Markdown 题稿
  → 本地严格内容门禁
  → 题稿摘要与哈希绑定到计划
  → 冻结输入、卷面、模板和输出目录
  → 本地预检
  → 用户批准
  → 试卷终端组装器
  → 学生卷/答案卷按合同分流
  → DOCX 包真实性与交付完整性校验
  → 回执、引用与中断恢复
```

可以判定为通过的范围：

1. 直接描述需求生成试卷；
2. 使用经用户授权披露的 DOCX 材料生成试卷；
3. AI 先追问“学生卷、答案卷或两者”，用户续答后回到原任务；
4. 默认生成学生卷和答案卷；
5. 明确只要学生卷时只生成学生卷；
6. 明确只要答案卷时只生成答案卷；
7. 答案与解析能够进入答案版 Word，而不是只停留在解析结果中；
8. 分值、答案、题号、题型、选项、总分、题量和用户显式要求不完整时阻止组装；
9. 输入、题稿、方案、模板、卷面或输出目录在批准后漂移时阻止执行；
10. 组装器声称成功但文件缺失、为空、扩展名错误或不是有效 DOCX 包时改判失败；
11. 生成、预检或执行被异常中断时，不把半成品误报为成功，并提供与当前阶段对应的恢复动作；
12. 组装完成后才观察到取消信号时，已经发布的学生卷和答案卷证据不会被丢失。

不能判定为“完全自动解决”的范围：

1. 题目事实是否绝对正确；
2. 难度、区分度和课程标准适配是否达到教师要求；
3. 生成内容是否充分覆盖材料中的隐含知识点；
4. 图片题、复杂公式、OCR、PDF 或扫描件是否都能稳定转成结构化题目；
5. 教师卷、答题卡、评分细则等尚未列入当前 Assistant 交付合同的扩展版本；
6. 用户使用非常自由、隐晦的自然语言表达时，所有约束是否都能被规则解析。

因此当前准确状态是：

> 当前支持边界内的工程链路完整；教学语义与扩展试卷版本仍需另设产品合同，不能用文件生成成功替代。

## 2. 顶层场景矩阵

| 场景 | 输入 | 计划与内容门禁 | 实际交付 | 结果 |
|---|---|---|---|---|
| 默认试卷 | 自然语言 | 类型化试卷计划；严格题稿校验 | 学生卷 + 答案卷 | 通过 |
| 仅学生卷 | 自然语言明确“只要学生卷” | 计划要求 `student` | 只有学生卷 | 通过 |
| 仅答案卷 | 自然语言明确“只要答案卷” | 计划要求 `answer_key` | 只有答案卷 | 通过 |
| 双版本 | 明确“学生卷和答案卷” | 计划要求两个产物 | 两个 DOCX | 通过 |
| 授权材料生成 | DOCX 材料 + 授权 | 材料正文进入模型上下文；本机路径不进入模型 | 双版本 | 通过 |
| 问题续答 | AI 询问版本，用户回答 | 原始请求与补充答案合并后建计划 | 按补充答案交付 | 通过 |
| 用户取消续答 | 用户回答“取消/不要了” | 清除待续任务，不创建计划 | 无产物 | 通过 |
| 需要逐题解析 | 用户明确要求详细解析 | 解析覆盖必须等于题量 | 答案版含解析 | 通过 |

| AI 漏分值/答案 | 任一题缺分值或答案 | 本地门禁阻止 | 不进入组装 | 通过 |
| 选择题漏选项 | 选择题少于两个选项 | 本地门禁阻止 | 不进入组装 | 通过 |

| 答案分组错位 | 答案题型/顺序与大题不一致 | 解析器阻止 | 不进入组装 | 通过 |
| 占位符残留 | 题稿包含 `{{...}}` | 本地门禁阻止 | 不进入组装 | 通过 |
| 输出伪成功 | 路径存在但为空、TXT 或伪 DOCX | 交付校验改判失败 | 不产生成功回执 | 通过 |
| 组装后取消 | 两个版本已写入后收到取消 | 保留已发布路径和运行证据 | 返回取消并携带产物 | 通过 |

## 3. 需求合同是否真正进入生成链

### 3.1 当前可确定解析的要求

试卷领域合同集中在：

`src/assistant/domain/exam_authoring_contract.py`

它负责解析和校验：

- 学科；
- 年级；
- 考试时间；
- 满分；
- 总题量；
- 选择、判断、填空、计算/解答、阅读、写作、简答等题型；
- 指定题型数量；
- 是否明确要求逐题解析；
- 学生卷、答案卷或双版本交付。

这些要求同时进入两处：

1. 作为 AI 系统提示词的本次运行硬约束；
2. 作为生成完成后的本地确定性验收规则。

这意味着模型不再既负责写题又负责宣布自己合格。

### 3.2 当前仍需承认的解析边界

自然语言解析是确定性规则，不是第二次模型猜测。它对“七年级数学、90 分钟、满分 100 分、10 道选择题、逐题解析”这类表达可靠；对隐喻、省略、表格化复杂蓝图、多个章节配额和难度曲线尚未形成完整合同。

合理后续不是继续向正则中堆零散例外，而是新增独立的 `ExamBlueprint`：

```text
ExamBlueprint
├─ curriculum_scope
├─ knowledge_point_weights
├─ difficulty_distribution
├─ section_specs[]
│  ├─ family
│  ├─ question_count
│  ├─ score_per_question
│  └─ analysis_policy
└─ delivery_versions[]
```

在用户真正需要复杂组卷时，应先让用户确认蓝图，再允许 AI 起草。

## 4. 生成题稿完整性门禁

### 4.1 必须阻止的内容问题

当前 Assistant 生成的试卷题稿必须满足：

- 具有标题、学科、年级、考试时间和满分；
- 至少有一道题；
- 每题都有答案；
- 每题都有分值；
- 满分与逐题分值总和一致；
- 每个大题内题号从 1 开始连续；
- 大题标题声明的题量与实际题量一致；
- 大题声明的总分或每题分值与实际一致；
- 选择题至少有两个选项；
- 答案分组能够按题型和顺序匹配大题；
- 用户明确要求的学科、年级、时间、总分、题量和题型均被满足；
- 用户明确要求逐题解析时，解析覆盖全部题目；
- 不含未替换的模板占位符。

### 4.2 两道防线不是重复补丁

同一个领域规则由两个阶段复用：

1. AI 输出落盘前校验，阻止无效题稿成为计划输入；
2. 预检时对 Assistant 生成源再次校验，阻止题稿落盘后被修改或旧计划绕过新规则。

规则所有权仍只有 `exam_authoring_contract.py` 一处。两阶段调用属于同一不变量的防御性复核，不是复制两套判断。

## 5. 授权材料链路

本轮真实模拟覆盖：

1. 创建 DOCX 材料；
2. 生成材料指纹；
3. 以当前会话、Provider、模型、引用和指纹生成披露授权；
4. 提取 DOCX 正文并发送给内容生成 Provider；
5. 验证材料事实进入 Provider 请求；
6. 验证本机绝对路径没有进入 Provider 请求；
7. 生成并编译 Markdown 题稿；
8. 绑定题稿哈希；
9. 预检；
10. 执行试卷组装；
11. 验证源 DOCX 字节未改变；
12. 验证学生卷和答案卷均生成。

这里证明的是“授权和工程传递闭环”，不是“模型一定完整利用材料中的每一个知识点”。

## 6. 计划、冻结资源、批准与组装

### 6.1 计划不是提示文本

试卷任务在计划中明确携带：

- `artifact_kind=exam_paper_markdown`；
- `parser_id=exam_items_v1`；
- `terminal_assembler=exam`；
- 可接受输入后缀；
- 交付版本和必需产物键；
- 生成题稿的文件引用和摘要；
- 输出策略。

### 6.2 执行资源必须冻结

实际执行前必须建立执行会话并冻结：

- 输入题稿；
- 当前试卷卷面；
- 当前模板；
- 材料上下文；
- 输出命名空间；
- 预检证据。

本轮在底层取消测试中发现旧测试仍绕过该边界。处理方式不是放宽生产代码，而是让测试经过与产品相同的冻结执行会话。这验证了当前资源边界确实生效。

### 6.3 批准后漂移必须失败

批准对象绑定预检摘要。输入文件、题稿、方案、模板、卷面或输出目录在批准后变化时，执行不得沿用旧批准继续写文件。

## 7. 学生卷、答案卷和解析内容

此前存在两个实质缺口：

1. 计划即使选择单版本，底层仍可能固定生成双版本；
2. 解析已经从 Markdown 解析出来，但答案 Word 中没有写入。

当前行为：

| 计划要求 | 运行时策略 | 必需产物 |
|---|---|---|
| 仅学生卷 | `student_only` | `student` |
| 仅答案卷 | `answer_only` | `answer_key` |
| 双版本/默认 | `student_plus_answer` | `student` + `answer_key` |

答案版现在写入“答案”和可用的“解析”；运行时证据分别报告可见答案数和可见解析数。学生卷与答案卷不是同一个文件路径，也不是同一份字节内容。

## 8. 交付真实性

“路径存在”不能证明 Word 产物有效。当前对试卷和其他 Word 产物的最低交付校验为：

1. 文件存在；
2. 文件大小大于 0；
3. 对应 Word 产物键必须使用 `.docx` 后缀；
4. 文件必须是可打开的 ZIP 包；
5. 包内必须至少含 `[Content_Types].xml` 和 `word/document.xml`；
6. 计划要求的每个产物键都必须存在。

该校验能够阻止空文件、TXT 冒充、普通文本改后缀和只生成一个版本却回报双版本成功。

它仍不等于 Word 视觉质量验收。分页、孤行、复杂公式、图片裁切和打印效果应继续由卷面视觉测试或 Office/PDF 渲染检查负责。

## 9. 中断与恢复

| 中断阶段 | 恢复后的状态 | 可用动作 |
|---|---|---|
| Provider 普通回复 | 当前 Turn 失败 | 重新发送请求 |
| 内容生成 | 不接受未完成题稿 | 重新生成内容草稿 |
| 预检 | 不进入执行 | 重新检查 |
| 执行且无终态日志 | 失败，不报告成功 | 重新预检 |
| 执行且日志已有终态 | 从日志恢复结果 | 打开全部已恢复产物 |
| 组装后才收到取消 | 取消，但保留已发布证据 | 查看已生成产物 |

恢复结果现在投影所有输出引用，不再只保留一个主文件。

## 10. 避免“补丁堆叠”的职责划分

| 层 | 唯一职责 |
|---|---|
| `domain/exam_authoring_contract.py` | 试卷需求解释、题稿阻断规则、版本交付解释 |
| `application/content_generation_service.py` | 组织 Provider 请求和授权材料，不判定 UI 状态 |
| `adapters/content_generation_adapter.py` | 将模型文本编译为受管题稿 |
| `application/plan_builder.py` | 建立类型化计划，不直接组装 Word |
| `adapters/production_adapter.py` | 预检、批准、执行、交付合同和文件真实性 |
| `shared/engine/exam_question_schema.py` | Markdown 题目/答案结构解析与结构问题 |
| `shared/engine/exam_paper_style.py` | 学生版/答案版 Word 渲染 |
| `application/session_recovery.py` | 持久任务与执行日志恢复 |
| `ui/assistant_panel.py` | 展示和续答编排，不拥有试卷业务校验 |

本轮没有把分值、选项、版本和文件真实性判断继续塞入按钮回调或页面组件。

## 11. 初始缺口与根因归纳

| 初始缺口 | 根因 | 当前处理 |
|---|---|---|
| 测试只断言生成成功 | 只有快乐路径 | 增加反向破坏性场景 |
| AI 漏分值/选项仍可编译 | Parser 与 Assistant 验收边界过宽 | 集中领域门禁 |
| 答案分组可能错配 | 只按位置回填 | 校验题型、顺序和多余分组 |
| 续答后没有原始计划 | 问题回答只形成普通对话 | 持久化待续文档请求并合并 |
| 单版本选择不影响组装 | 交付版本在底层硬编码 | 从类型化计划投影运行时策略 |
| 解析没有进入答案 Word | Parser 和 Renderer 合同断裂 | Renderer 消费解析并报告证据 |
| 输出存在即成功 | 缺少产物真实性校验 | 校验 DOCX 后缀和包结构 |
| 预检/生成中断无法继续 | 恢复只覆盖执行阶段 | 增加阶段化恢复动作 |
| 旧低层测试绕过卷面冻结 | 测试与产品执行边界不一致 | 测试使用真实执行会话 |

## 13. 最终验收判断

### 13.1 当前可发布判断

对于以下承诺，可以判定为工程闭环：

> 用户通过 AI 描述试卷要求，或授权使用 DOCX 材料；系统生成并严格校验结构化 Markdown 题稿；用户确认后，系统使用冻结的卷面和模板生成约定的学生卷、答案卷或双版本 Word，并对交付文件做真实性与完整性校验。

### 13.2 当前不可宣传的能力

不得宣传为：

- AI 自动保证所有题目正确；
- AI 自动保证难度和区分度；
- 任意材料格式都能直接组卷；
- 已支持教师卷、答题卡和评分细则的任意组合；
- 只要 Word 文件能打开就代表视觉排版完美。

### 13.3 后续合理扩展顺序

1. 若要支持复杂组卷，先建立 `ExamBlueprint`，不要继续扩展散乱正则；
2. 若要支持教师卷/答题卡，先扩展 `DeliveryContract` 和组装器版本合同；
3. 若要验证教学质量，建立独立的人工审阅/题库校验阶段；
4. 若要支持 PDF、扫描件和图片题，建立独立材料抽取与视觉证据链；
5. 若要声明打印质量，增加真实 Office/PDF 渲染和逐页视觉验收。

---

最终结论：当前“AI 生成 → 本地严格验收 → 冻结资源 → 批准 → 试卷组装 → 版本化 DOCX 交付”链路在已声明边界内完整；此前的假闭环点已经被改为可验证合同或明确残余边界。

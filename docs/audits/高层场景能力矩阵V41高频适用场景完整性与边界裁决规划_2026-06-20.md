# 高层场景能力矩阵 V41 高频适用场景完整性与边界裁决规划

日期：2026-06-20

## 1. 文档定位

本文继续承接 V39/V40、N2.182、V33 maturity audit 和 N2.183-N2.187 的产品化闭环记录，专门回答一个更高层的问题：

```text
当前功能点仍不完善时，怎样规划场景能力矩阵，
才能不遗漏高频适用场景，也不让边界变模糊？
```

V41 不新增顶层 pack，也不把任何 subject 升为 Green/L5。它的作用是把“场景能力完整”的判断从场景名称、按钮数量或模块开关，提升为一套可执行的裁决模型：

```text
高频自然请求
-> 承载层裁决
-> 输入事实源
-> 模板/控件契约
-> Word/OpenXML 风险面
-> runtime consumer
-> report / artifact / repair
-> success / degraded / failure / manual / ambiguous / negative journey
-> release gate。
```

只要中间任一段无法解释，就不能宣称该场景能力完整。

## 3. V41 的完整性定义

一个高频场景能力必须同时通过五个问题：

| 问题 | 通过标准 | 未通过时的处理 |
| --- | --- | --- |
| 用户会怎么说 | 自然话术能进入 request-cell、lexicon 或 ambiguity registry | 新增 request sample 或 ambiguity rule |
| 应由谁承载 | 明确是 pack、family、profile、schema、preset、manual gate、plugin 还是 negative | 不允许先加 UI 按钮 |
| 输入事实是什么 | DOCX、JSON、XLSX、Bib/CSL、MaterialSchema、CountProfile、RuleSource 等可声明 | 不能把自由文本当可靠事实源 |
| Word 风险在哪 | 对应 paragraph/run、styles、numbering、fields、headers、comments、sdt、textbox、OLE、media 等 surface | 进入 ObjectPreflight、fixed-layout、manual gate 或 boundary report |
| 用户如何验收 | runtime、report、artifact、repair、fixture 和 release gate 能追同一条链 | 只能算规划或边界，不能算完整能力 |

V41 将完整性分成三层，不再混用：

| 层级 | 目标 | 当前状态 |
| --- | --- | --- |
| 高频覆盖层 | 不遗漏用户自然请求 | 基本闭合，52 request-cell 可验 |
| 业务语义层 | 成功、降级、失败/人工和歧义有稳定解释 | 17/17 ready |
| 产品成熟层 | 前台可操作、执行可达、报告可修复、产物可验收 | 0 Green/L5，仍是主战场 |

## 4. 不新增顶层 pack 的原因

当前 12 个 pack 已经覆盖主要高频心智：

```text
quick_formatting
chinese_academic
english_journal
exam_education
bidding_materials
official_policy
technical_long_docs
application_reports
contract_delivery
batch_forms
professional_disclosure
import_ai_boundary
```

继续新增顶层入口会带来三个问题：

1. 导航膨胀：普通用户不知道该选“产品手册”“技术手册”“售前方案”还是“白皮书”。
2. 边界漂移：合同、法律、财务、审计、专利、医学等专业责任容易被误吸收到核心能力。
3. 链路变浅：每个入口都有名字，但缺 schema、preset、report、artifact、repair 和 fixture。

因此 V41 的原则是：

```text
顶层 pack 少而稳；
高频差异用 family/profile/schema/preset/manual gate 承载；
只有事实源、交付语义和 Word 风险组合都独立时，才考虑新 pack。
```

| 薄弱点 | 建议承载 | 后续动作 |

## 8. 边界裁决规则

新增需求先裁决，不先设计 UI。

| 判断问题 | 归属 |
| --- | --- |
| 只影响字体、段落、页面、题注、目录、普通表格外观 | TemplateConfig / 模板管理 |
| 决定是否处理、处理范围、失败策略、对象风险、交付版本 | Scene / DeliveryPreset / ObjectPreflight |
| 来自公司、人员、项目、产品、题目、图片、签章、附件 | MaterialSchema / AssetsPanel |
| 字数、词数、图表、参考文献、公式、学校/期刊规则 | CountProfile / RuleSourceGovernance |
| 多版本、compare、report、manifest、zip、archive、命名目录 | DeliveryPreset / OutputConfig |
| 多人员、多公司、多项目、多记录生成 | BatchPreset |
| 固定行高、套打、证书、答题卡、文本框、内容控件 | fixed-layout profile |
| 批注、修订、隐藏文字、OLE、宏、外链、嵌入包 | ObjectPreflight / manual gate |
| 法律、财务、审计、专利、医学、翻译质量、AI 内容质量 | professional/plugin/manual boundary |
| PDF/OCR/LaTeX/AI 导入 | import_ai_boundary + target handoff |
| PPT、网页、海报、出版系统终版 | negative / external plugin |

顶层 pack 新增条件必须同时满足：

1. 用户长期以该大类表达，而不是行业别名。
2. 输入事实源明显不同。
3. 交付 artifact 和失败策略明显不同。
4. Word/OpenXML 风险组合无法被既有 pack 覆盖。
5. 能同步补 request-cell、fixture、report、repair 和 release gate。

否则只允许新增 family、profile、schema、preset、manual gate 或 request-cell。

## 9. 控件样式一致性准入

场景配置中的样式类控件必须继承模板管理的控件契约。场景可以因业务理由覆盖模板默认值，但不能改名、换单位、断开执行字段或绕过报告。

重点裁决：

| 参数/控件 | 场景侧要求 | 不允许 |
| --- | --- | --- |
| 左缩进、右缩进 | 与模板管理同名、同单位、可同一行展示 | 场景页另造“左距/右距”字段 |
| 段前、段后 | 与模板管理同名、同单位、可同一行展示 | 改成无法追溯的前距/后距 |
| 特殊缩进 | 必须可交互切换无/首行/悬挂；无时禁用并归零 | 只显示当前值但不能切换 |
| 行距类型/行距值 | 类型和值联动，固定/多倍/最小值单位清楚 | runtime 不消费却表现为可执行 |
| 普通表格 | 只管理普通表格外观 | 混入固定版位行高 |
| 固定行高 | 归 fixed-layout profile，对应 Word `w:trHeight` | 作为 `TableConfig.row_height_pt` 残留参数继续悬挂 |
| 水印 | 版本/状态语义归场景，外观控件继承模板语言 | 当成模板杂项装饰 |
| 公式/引用 | 外观基线与场景策略分离 | 把转换置信度、引用源治理塞进模板样式 |
| 素材/图片 | 归 MaterialSchema/AssetsPanel，缺项进入 repair target | 只在 UI warning，不进入运行时和报告 |

统一准入链：

```text
control contract
-> ScenePanel / AssetsPanel / Workbench control
-> resolver / pipeline consumer
-> report field
-> issue queue / repair target
-> fixture / test / release gate
```

缺任一段时，前台只能显示 planned/boundary/needs setup，不得表现为已可执行。

# 高层场景能力矩阵 N2.354 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决重放失败补偿终态归档持久调度闭环

日期：2026-06-23

## 1. 定位

N2.353 已把 retry/replay failure compensation 的 final audit 与 follow-up connector 统一推进到 terminal archive worker：dead-letter、authorization refresh 和 remote snapshot review 都能落入同一类终态归档事实源。这个事实源解决的是“补偿链路已经到达可审计终点”，但它还没有回答一个更高频的运维问题：归档后的 dead-letter、授权刷新、远端快照治理是否已经进入可恢复、可重试、可监控的持久调度队列。

N2.354 闭合的是 terminal archive 后的 durable scheduler 首片。它不声明真实后台线程、跨进程 worker、外部授权刷新、远端快照重拉或二次补偿自动执行已经完成；本轮只承诺从前台显式记录“这些归档项已经进入持久调度计划”，并保留 worker scope、lock 状态、retry 策略、后续 execution monitor 路由、manifest 和 metadata。

## 2. 本轮闭环

- terminal archive 记录后，表格从 `archived` 状态显示 `Schedule` 与 `Manifest`。
- `Schedule` 消费 latest terminal archive record，而不是新建第二套事实源。
- dead-letter 项进入 `dead_letter_terminal_archive_scheduler_queued`，调度路由为 `manual_dead_letter_archive_scheduler`，后续监控路由为 `dead_letter_manual_followup_monitor`。
- authorization refresh 项进入 `authorization_refresh_terminal_archive_scheduler_queued`，调度路由为 `authorization_refresh_connector_scheduler`，后续监控路由为 `authorization_refresh_connector_monitor`。
- remote snapshot review 项进入 `remote_snapshot_terminal_archive_scheduler_queued`，调度路由为 `remote_snapshot_governance_scheduler`，后续监控路由为 `remote_snapshot_governance_monitor`。
- 所有调度项统一写入 `worker_scope = cross_archive_terminal_archive_durable_scheduler`、`lock_status = pending_lock`、`retry_scheduler_status = scheduled`、`retry_limit = 3`、`backoff_seconds = 2`、`attempt_count = 0`。
- 调度 manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_retry_replay_failure_compensation_terminal_archive_durable_schedulers`。
- profile metadata 回写 durable scheduler status、id、worker scope、lock status、retry scheduler status、retry/backoff、item count 和 manifest path。
- 调度记录后，表格状态推进为 `scheduled`，动作收敛为 `Manifest`，并阻止重复 Schedule、重复 Archive、重复 Connector、重复 Audit、重复 Execute 和重复 Queue。

## 3. 链路视角

N2.354 后链路变为：

```text
... -> Failure Queue -> Execute -> Handoff -> Final Audit
                                                |
                         +----------------------+----------------------+
                         |                                             |
                  no follow-up                                  follow-up required
                         |                                             |
                         v                                             v
                    Terminal Archive        Authorization/Snapshot Follow-up Connector
                         |                                             |
                         +----------------------+----------------------+
                                                |
                                                v
                                      Terminal Archive Durable Scheduler
                                                |
                                                v
                              Terminal Archive Execution Monitor (next)
```

这个链路把“归档事实”推进为“可恢复的调度事实”。它仍然保留清晰边界：本轮不是实际执行监控，也不是授权刷新或远端快照治理结果回收；下一轮应处理 execution monitor，把 scheduled item 转换为执行心跳、恢复结果、失败重试和最终 dead-letter/二次补偿归档。

## 5. 控件样式与场景一致性

本轮继续沿用模板管理/素材管理已经形成的控件契约：

- 行动作仍使用紧凑表格按钮：`Schedule` 与 `Manifest`。
- 状态仍进入原状态列：`archived` 推进为 `scheduled`。
- manifest drilldown 复用既有 `locate_manifest` 行动作，不新增说明性大卡片。
- 调度参数不暴露为零散表单；当前固定为 manifest/metadata 中的 retry policy，避免在场景板块出现与模板管理不一致的临时控件。

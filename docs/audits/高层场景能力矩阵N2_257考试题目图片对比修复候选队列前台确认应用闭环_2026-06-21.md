# 高层场景能力矩阵 N2.257 考试题目图片对比修复候选队列前台确认应用闭环

## 1. 本轮定位

N2.256 已经让 repair queue entry 具备 `confirmation_status=ready|blocked`、`replacement_source_path` 和 `apply_blockers`，并在 AssetsPanel 内部提供 `apply_question_figure_repair_candidate(..., confirmed=True)` 的受控替换入口。但这仍需要测试或内部代码直接调用 helper，Workbench 前台问题队列还不能把 ready 候选作为一个可执行动作传给 AssetsPanel。

N2.257 关闭的是“候选队列前台确认应用”的首片：ready 候选在 Workbench issue queue 中生成 `profile_question_figure_repair_candidate` action，QuickExecutionDetail 的问题处理按钮可发出该 action，WorkbenchPanel 通过 bridge 把候选传给 AssetsPanel，AssetsPanel 选择 profile 后执行受控替换。blocked 候选仍只回退为行级定位，不会被误当成可确认替换。

## 2. 已实现能力

- `question_figure_repair_queue_issue_items()` 在 issue `repair_context` 中保留候选 JSON。
- `workbench_issue_action_target()` 对 ready repair queue issue 输出：
  - `target_type=profile_question_figure_repair_candidate`
  - `target_key` 中保留 `profile_id`、`profile_name`、`target_key` 与完整 `candidate`。
- blocked 或不可应用候选继续输出 `profile_question_figure_item`，只定位题图行。
- `QuickExecutionDetail` 不新增平行按钮，复用现有问题处理按钮：
  - `current_issue_action_targets()` 可读到新的 candidate action；
  - `_issue_action_btn.click()` 会发出 `issue_repair_requested("profile_question_figure_repair_candidate", payload)`。
- `PanelBridge` 新增 `material_profile_repair_candidate_requested` 信号与 pending 存储/消费方法。
- `WorkbenchPanel._open_issue_repair_target()` 新增 `profile_question_figure_repair_candidate` 分支：
  - 解码 profile 与 candidate；
  - 将 `target_key` 回填到 candidate 的 `repair_target_key`；
  - 调用 `bridge.request_material_profile_repair_candidate()`；
  - 导航到 AssetsPanel。
- `AssetsPanel` 监听候选信号：
  - 先选择目标 profile；
  - 聚焦候选的 `question_figure_item`；
  - 调用 `apply_question_figure_repair_candidate(candidate, confirmed=True)`；
  - 替换后同步 `EntityArchive`、`MaterialExecutionContext`、题图表与预览。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue frontstage apply bridge` evidence。

## 3. 链路闭合

当前链路为：

`question_figure_repair_queue.entries[]` -> `question_figure_repair_queue_issue_items()` -> `WorkbenchIssueItem(repair_context.repair_candidate_json)` -> `workbench_issue_action_target()` -> `profile_question_figure_repair_candidate` -> QuickExecutionDetail 问题处理按钮 -> WorkbenchPanel issue route -> `PanelBridge.material_profile_repair_candidate_requested` -> AssetsPanel 选中 profile -> `apply_question_figure_repair_candidate(..., confirmed=True)` -> `_replace_question_figure_item_path()` -> archive/context/table/preview 同步。

这让 N2.256 的“可审计确认计划”推进为真实前台可触发的单候选人工确认应用入口。

## 4. 明确不宣称完成

- 不做批量确认应用；
- 不做自动替换；
- 不做候选冲突裁决；
- 不做撤销、回滚、审计日志或替换前快照；
- 不写回 Word、资料包或远端素材库；
- 不下载远端 comparison reference 再替换；
- 不做内容级错图识别、视觉 diff 或 AI 判图；
- 不把按钮文案升级成完整的向导式确认 UI。

当前能力只承诺：ready 的本地文件候选能从 Workbench 问题队列触发，并在 AssetsPanel 中按人工确认语义执行单候选替换。blocked 候选仍只能定位，不会误替换。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.256 的“候选队列确认替换计划”推进到 N2.257 的“候选队列前台确认应用”。已闭合能力新增：ready 候选不再只停留在报告或内部 helper，而是可以从 Workbench 问题处理按钮进入 AssetsPanel 并完成单候选受控替换。

## 3. 链路边界

当前链路是：

1. 批量失败恢复报告闭合。
2. Drilldown artifact 写入恢复明细。
3. SLA center、followup、自动 trace repair 完成。
4. Word media rewrite 执行记录写入。
5. 持久 worker 队列表从最新 Word media rewrite 记录派生候选。
6. 用户点击“登记队列”。
7. 系统生成幂等 lock key、重试策略快照和 queue manifest。
8. 若无 DOCX 目标，queue status 为 `scheduled_waiting_for_docx`，retry scheduler status 为 `waiting_for_docx_targets`。
9. 系统写入审计历史、artifact 路径和题图 metadata。
10. readiness/maturity 把 persistent worker queue/idempotent lock/retry scheduler UI 移入 evidence，并把剩余缺口推进到 durable worker execution monitor/resume/dead-letter UI。

这仍是“持久队列登记首片”，不是“真实 worker 执行系统”。尤其在 Word 本身视角下，本轮只读取 N2.331 的 DOCX 扫描和 manifest 结果，不会打开 `word/document.xml`、`word/_rels/document.xml.rels`、`word/media/*` 进行真实 relationship 重写，也不会生成缺失的历史 DOCX。此边界必须继续保留，避免把队列治理误读为 Word XML 修复已完成。

## 4. 剩余缺口

N2.332 后的下一层明确缺口是：

- durable worker execution monitor：后台执行态、心跳、进度、运行中/失败/完成状态。
- resume：断点续跑、跨进程恢复、重复启动幂等保护。
- dead letter：长期失败项、超限重试项、人工介入和二次补偿入口。
- 真实跨 archive 文件级恢复中心。
- Word XML / relationship / media 一致性重写与校验。
- 历史 DOCX 缺失时的生成、定位或用户补交策略。
- Word media rewrite 与题图修复候选、替换审计、回滚审计、二次补偿 connector 的深度合流。
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

# 高层场景能力矩阵 N2.326 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复后台任务治理闭环

日期：2026-06-22

## 1. 本轮目标

N2.325 已经把恢复报告推进到 Drilldown Artifact：用户可以从批次恢复报告生成 JSON/Markdown 明细，并从明细表回到题图素材。但恢复链路仍缺少统一任务视角，无法一次性判断“批量裁决、失败恢复、恢复报告、明细产物”各自处在哪个阶段，也无法从一个任务台账跳回对应前台入口。

本轮闭合的是 `batch failure recovery background task governance UI` 首片：新增前台后台任务治理表，把已有批量裁决执行、失败队列治理、恢复报告和 Drilldown artifact 投影为一致的任务台账。它不引入真正后台 worker，也不声明任务持久化、自动重试、并发限流、取消/暂停、指数退避、失败 SLA、批量回滚或二次补偿完成。

## 2. 已闭合能力

- 新增 `question_figure_asset_library_master_subscription_drift_batch_failure_recovery_background_task_table`。
- 表格列为“任务 / 阶段 / 状态 / 进度 / 治理 / 处理”，与素材库其他前台治理表共享主题样式、按钮 variant 和表格行为。
- `question_figure_library_cross_package_master_subscription_drift_conflict_batch_decision_execution` 投影为“批量裁决 / 批量执行”任务：
  - 展示成功数、总执行数、失败/跳过摘要；
  - 操作入口为“定位批次”，若批量入口已消失则回退到失败/报告入口。
- `question_figure_library_cross_package_master_subscription_drift_conflict_batch_failure_queue_governance` 与批量执行 failed items 叠加后投影为“失败恢复 / 队列治理”任务：
  - 展示已恢复、已跳过、重试失败、未处理计数；
  - 未闭合时定位失败队列，闭合后定位恢复报告。
- `question_figure_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_report` 投影为“恢复报告 / 报告固化”任务：
  - 展示已解决/失败总数；
  - 根据是否已有 Drilldown artifact 提示下一步治理状态。
- `question_figure_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_report_drilldown_artifact` 投影为“恢复明细 / 产物复核”任务：
  - 展示明细项数和未闭合项数；
  - 操作入口为“定位明细”，回到 Drilldown 明细表及素材行。
- 任务行全部来自现有 history records，不另建会漂移的任务事实源。
- 新任务表跟随 `_refresh_summary()` 统一刷新，批量执行、失败恢复、报告生成和 Drilldown 生成后都会同步更新。

## 3. 链路视角

N2.326 保持四层事实源关系：

1. 批量裁决执行记录仍是失败来源。
2. 失败队列治理记录只补充 recovered/skipped/retry_failed/open 状态。
3. 恢复报告记录固化批次级恢复事实。
4. Drilldown artifact 负责可读/可机读明细。

后台任务治理表只把这四层投影成前台台账：它回答“当前任务链路推进到哪里、下一步点哪里”，不改变任何恢复事实。

## 5. 仍未闭合边界

N2.326 后，明确剩余缺口不再是后台任务可视化，而是任务治理策略可执行：

- 真正后台 worker、队列调度和任务状态持久化；
- 幂等任务锁、跨批次互斥和断点续跑；
- 并发限流、暂停、取消和恢复；
- 自动重试、指数退避和失败重放；
- 失败 SLA、提醒、责任人升级；
- 跨 archive 失败恢复中心；
- 批量回滚、二次补偿和历史 Word 输出追溯修复；
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

# 高层场景能力矩阵 N2.269 考试题目图片对比修复批量应用审计回滚闭环

日期：2026-06-21

## 1. 本轮目标

N2.269 接在 N2.268 的“批量应用执行结果审计”之后，补上一个审计驱动的回滚首片：当题图修复批量应用已经把替换图写入 Word 副本，并且留下 `question_figure_batch_apply_audit.json` 后，可以基于该审计记录生成一份新的回滚 docx 副本。

本轮不覆盖已修复稿，也不声称完成完整批量事务中心。它只承诺：在审计记录、当前 docx 状态和原始图片文件都能被校验时，把 Word 包内对应的 `word/media/*` 字节恢复为审计记录中的原始图片字节。

## 2. 链路定位

批量应用链路目前被拆成以下可验收切片：

- N2.263：批量确认前预检计划；
- N2.264：执行前冻结计划和 fingerprint 契约；
- N2.265：冻结计划 dry-run 守卫；
- N2.266：dry-run 通过后的执行计划草案；
- N2.267：计划内单个 docx 副本的 Word media 写入；
- N2.268：成功写入后的执行审计 artifact；
- N2.269：基于执行审计 artifact 的回滚 docx 副本生成。

因此，N2.269 的边界是“审计记录驱动的可验真回滚副本”，不是“跨任务、跨文档、可调度的事务回滚系统”。

## 3. 回滚契约

新增 `_rollback_question_figure_repair_batch_apply_from_audit()`，输入为：

- `question_figure_repair_queue`
- `applied_docx_path`
- `rollback_docx_path`
- 可选显式 `audit_record`
- `confirmed=True`
- `expected_audit_id`
- `expected_output_sha1`

回滚前必须满足：

- 执行审计记录存在；
- 审计记录 `status=applied`；
- 审计记录 `action=question_figure_repair_batch_apply_word_media_write`；
- 人工显式确认；
- `expected_audit_id` 与审计记录一致；
- `expected_output_sha1` 与审计记录一致；
- 当前 applied docx 文件存在且是有效 zip/docx；
- 当前 applied docx 的 SHA-1 仍等于审计记录中的 `output_sha1`；
- 回滚输出路径存在且不能等于 applied 输入路径；
- 审计记录中存在 `entry_results[]`。

每个 entry 会继续校验：

- `media_path` 存在于当前 docx 的 `word/media/*`；
- 当前 media bytes 的 SHA-1 等于审计记录中的 `replacement_sha1`；
- `original_path` 仍存在；
- 原始文件 SHA-1 等于审计记录中的 `original_sha1`；
- 同一回滚批次中不存在重复 media 目标。

所有校验通过后，函数复制 applied docx 的 zip 条目，只替换审计记录命中的 media bytes，写出新的 rollback docx。

## 4. 回滚审计

回滚成功后追加新的 audit record：

- `action=question_figure_repair_batch_apply_word_media_rollback`
- `linked_apply_audit_id`
- `plan_id`
- `execution_plan_fingerprint`
- `confirmed_by`
- `confirmed_at`
- `input_path`
- `output_path`
- `output_sha1`
- `applied_docx_sha1`
- `restored_count`
- `restored_target_count`
- `entry_results[]`

回滚记录默认写入原执行审计记录所在目录的 `question_figure_batch_apply_audit.json`，从而让 apply record 与 rollback record 可以在同一个 artifact 中连续追溯。

## 5. 前台与报告

Markdown batch report 新增回滚结果摘要：

```text
Batch apply rollback result: status=<status>; restored=<n>; output=<path>; word_write=<true|false>; audit=<written|not_written>
```

Workbench artifact detail 新增：

```text
rollback=<status>; restored=<n>; rollback_audit=<written|not_written>
```

`scene_product_readiness` 中 `pack:exam_education` 和 `family:exam_teaching` 新增独立 evidence：

```text
question asset comparison repair queue batch apply audit rollback bridge
```

它与既有的单项前台回滚 `question asset comparison repair queue rollback bridge` 区分开：前者面向批量应用后的 Word docx 审计回滚，后者面向 AssetsPanel 单个候选替换后的当前题图路径回滚。

## 6. 不宣称完成

本轮仍不宣称：

- 完整批量事务中心；
- 批量事务级原子回滚；
- 审计记录驱动的自动回滚；
- 跨多 docx 后台任务调度；
- 文件快照系统；
- 远程素材库写回；
- 重复图片智能 disambiguation；
- 内容级错图识别；
- 复杂学科图或 AI 质量判断；
- 自动候选优先级排序；
- 完整候选对比选择器。

N2.269 只把“成功写入后的审计记录”变成“可生成回滚副本的依据”，并继续把完整事务系统留作后续独立闭环。

# 高层场景能力矩阵 N2.383 发布例外账本闭环

## 目标

N2.383 将 N2.380、N2.381、N2.382 的结果合并成顶层发布例外账本。当前 release gate 已通过，但仍会保留若干有意存在的状态：managed warning、dashboard warning projection、非满分 readiness、static closed but not Green/L5、maturity L5-blocked。它们不应被隐藏，也不应被误读为未闭合缺口。

本轮的目标是建立 `release_gate_projection`：只要这些状态都能追到治理账本，release gate 可以通过；只要出现 unmanaged warning、unreconciled readiness、未守护的 L5-blocked 或静默 dashboard warning，release gate 必须失败。

其中 warning 类例外统一使用 `managed_warning_governance` 口径：warning 可以存在，但必须证明它已经进入托管账本，并且不会被误判为普通未闭合缺口。

## 发布例外类型

| 例外 | 观测值 | 治理值 | 来源 |
| --- | ---: | ---: | --- |
| managed residual warnings | 10 | 10 | N2.381 residual warning governance |
| dashboard warning projection | 3 | 3 | dashboard 只投影已治理 warning |
| boundary readiness reconciliation | 15 | 15 | N2.382 readiness reconciliation |
| boundary guarded maturity | 6 | 6 | N2.380 boundary guarded completion |
| static closed boundary | 2 | 2 | static closed but Blue/Boundary |

发布门禁目标值：

- `exception_count = 5`
- `governed_exception_count = 5`
- `ungoverned_exception_count = 0`
- `managed_warning_count = 10`
- `readiness_reconciliation_count = 15`
- `boundary_guarded_maturity_count = 6`
- `static_closed_boundary_count = 2`

## 产品口径

N2.383 明确区分三件事：

- **Blocking issue**：必须为 0，否则 release gate 不通过。
- **Governed exception**：可以存在，但必须有明确治理账本和 release gate projection。
- **Core Green/L5 promise**：不能被 governed exception 冒充。

因此 `scene_matrix_dashboard_warning_count=3` 不再是一个孤立提示；它必须由 `scene_residual_warning_governance_audit` 证明全部 managed。`maturity_l5_blocked=6/27` 也不再是模糊未完成项；它必须由 `scene_boundary_guarded_completion_audit` 与 `scene_boundary_readiness_reconciliation_audit` 证明为边界守护状态。

## UI 与报告要求

Dashboard 应展示 Terminal release exceptions 卡片，说明发布例外是 `5/5 governed`。Drilldown 应提供 Terminal release exceptions 面板，让用户看到每一类例外的观测值、治理值、证据来源和失败条件。

摘要区域可以继续显示 warning、L5-blocked、非满分读数，但必须同时显示：

- `10/10 managed warnings`
- `15/15 readiness reconciled`
- `5/5 release exceptions governed`
- `0 unmanaged/unreconciled/ungoverned`

## 闭环要求

N2.383 的验收包括：

- 独立审计模块 `scene_terminal_release_exception_audit` 返回 passed。
- 导出脚本支持 JSON 与 Markdown。
- dashboard 新增发布例外计数与卡片。
- drilldown 新增 Terminal release exceptions 条目。
- release gate 输出 `scene_terminal_release_exception_count`、`scene_terminal_release_exception_governed_count` 与 `scene_terminal_release_exception_ungoverned_count`。
- CI workflow 纳入对应测试。

后续如果新增 warning、非满分 readiness、static boundary 或 L5-blocked，必须先进入对应下层治理账本，再进入本顶层发布例外账本；否则不能把 release gate 视为产品闭环。

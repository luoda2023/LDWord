## 1. 结论

当前“样式预览”确实还不是一份完整的“当前方案生效结果预览”。它更接近一张由 `TemplateConfig` 驱动的静态模板参数示意图。

用户提出的核心判断是成立的：

1. 当前方案关闭页面设置后，模板页边距、装订线、纸张规格、页眉页脚距离等计算线不应继续以“将要生效”的样子出现；
2. 当前方案跳过表格格式后，表格格式样例不应继续出现；
3. 标题编号关闭后，应去掉标题编号，不应直接删掉标题文字；
4. 正文排版关闭后，模板正文样式样例应消失，或明确退化为不表达模板格式的中性内容；
5. 页眉页脚、目录、题注都应服从各自的方案模块开关和模板内部子开关；
6. 目录和题注目前只出现在“预览覆盖范围”的说明文字里，实际上没有画进页面；
7. 当前预览没有读取 `SceneWorkspace.module_switches`，所以从现有数据流上就不可能随方案开关正确变化。

但“关闭后都整体消失”不能机械套用到所有对象。正确规则应是：只隐藏由该模块拥有的视觉结果，保留仍由其他模块负责的内容。例如关闭“标题编号”只去掉编号前缀，标题文字和标题排版仍可能由正文排版模块负责；关闭“表格格式”也不应自动关闭独立的题注模块。

## 2. 本轮已处理的交互问题

模板概览中的预览现在只承担静态展示，不再提供第二层查看交互：

- 已移除右上角“放大查看”按钮；
- 已移除整张预览画布的鼠标点击、回车键和空格键激活；
- 已移除模板预览专用放大弹窗实现；
- 已取消预览画布上的“模板基线：当前模板……”悬停卡片；
- `StylePresentationEnvelope` 等结构化来源属性仍保留，后续状态计算和测试仍可使用，不再把它们强制显示成 tooltip。

这部分改动不改变页面绘制逻辑。

## 3. 当前数据链路为什么无法联动

当前链路实际是两条互不相交的数据流：

```text
模板参数链
TemplateConfig
  -> TemplateOverviewDetail.refresh(cfg)
  -> TemplateStylePreview.refresh(cfg)
  -> _build_template_preview_paragraphs(cfg)
  -> _CachedPageLayout
  -> paintEvent()

方案开关链
SceneWorkspace.module_switches
  -> _ReformatToggleCard
  -> _on_reformat_toggle_changed()
  -> 更新 scene.module_switches
  -> _sync_reformat_toggles()
  -> 结束
```

第二条链没有调用预览刷新，也没有把开关状态传给预览。

直接证据包括：

- `TemplateOverviewDetail.refresh()` 只接收 `TemplateConfig`；
- `TemplateStylePreview.refresh()` 也只接收 `TemplateConfig`；
- `_build_template_preview_paragraphs()` 无条件加入正文、标题、表格占位和“摘要”；
- `_on_reformat_toggle_changed()` 只更新当前方案和开关 UI，不重建预览缓存；
- 运行时探针确认关闭 `page_setup`、`section_format` 和 `table_format` 后，预览仍持有同一个 `_CachedPageLayout`，段落块列表不变。

因此，这不是少写了几个 `if` 的局部问题，而是预览输入契约缺少“当前方案执行状态”。

## 4. 预览当前真正画了什么

| 视觉对象 | 当前读取的模板参数 | 当前是否读取方案开关 | 当前结果 |
|---|---|---:|---|
| 纸张外形 | 纸型、方向 | 否 | 始终按模板显示 |
| 纸张徽标 | `paper_size` | 否 | 始终显示 A4/A3 等 |
| 页边距色带 | 四边页边距、装订线 | 否 | 始终显示 |
| 内容区角标 | 由模板页边距计算 | 否 | 始终显示 |
| 四边尺寸线 | 页边距、装订线 | 否 | 空间足够时始终显示 |
| 页眉页脚距离线 | 页眉/页脚距边界 | 否 | 空间足够时始终显示 |
| 正文段落 | `styles.body` 及回退样式 | 否 | 始终加入固定样例 |
| 一级至三级标题 | 标题样式、编号绑定 | 否 | 始终加入，最多只画三级 |
| 非编号标题 | 固定“摘要”样例 | 否 | 始终加入 |
| 表格 | `table` | 否 | 始终加入表格占位；空间不足时可能静默不画 |
| 页眉 | `header_footer.header` | 否 | 会响应模板内部页眉开关 |
| 页脚/页码 | `header_footer.footer`、页码计划 | 否 | 会响应部分模板内部开关 |
| 目录 | 无 | 否 | 完全未绘制 |
| 图题/表题 | 无 | 否 | 完全未绘制 |

当前说明文案却由七组概览数据自动生成，明确声称：

> 预览页面、正文、标题、表格、页眉页脚、目录和题注在同一页中的效果。

这条文案与真实画布不一致。目录和题注只有摘要投影，没有渲染实现。

## 5. 方案级开关的正确显示规则

### 5.1 页面设置

页面卡片当前同时控制：

- `page_setup`
- `section_format`

两者职责不同，预览不能只使用一个总布尔值。

`page_setup = false` 时建议：

- 保留一个中性的白色页面容器，因为正文、标题、表格等仍需要展示载体；
- 隐藏纸张规格徽标；
- 隐藏页边距色带；
- 隐藏内容区四角标；
- 隐藏上下左右页边距尺寸线；
- 隐藏装订线数值；
- 隐藏页眉页脚距离尺寸线；
- 内容区域使用固定的中性安全内边距，不能继续用模板页边距计算，否则视觉上仍暗示模板页面设置会生效；
- 不应直接把整张预览卡片删掉。

`section_format = false` 时：

- 单页样式预览通常无可见变化；
- 如果以后增加分节符、章节起始页或封面分节示意，应只隐藏这些结构标记；
- 不应影响纸型和页边距，因为它们由 `page_setup` 所有。

如果两个开关处于“部分开启”，应按各自职责分别渲染，不能按照页面卡片的聚合状态整体隐藏。

### 5.2 正文排版

正文卡片对应 `paragraph_style`。

`paragraph_style = false` 时建议：

- 移除模板正文格式样例；
- 不再使用模板的正文/标题字体、字号、缩进、段距和行距来暗示生效结果；
- 如果标题编号仍开启，可保留中性字体的标题文字，用于承载编号效果；
- 如果目录或题注仍开启，它们继续按自己的模块规则显示；
- 不应把所有页面内容一并清空。

需要注意：运行时 `paragraph_style` 还会同步 Word 标题样式定义，因此它不仅影响普通正文，也影响标题字形。但标题编号是否存在由另一个模块决定。

### 5.3 标题编号

标题卡片对应 `heading_numbering`，标题识别 `heading_recognition` 在当前逻辑中仍保持开启。

`heading_numbering = false` 时正确结果是：

- “第一章”“1.1”“（一）”等编号前缀消失；
- “绪论”“研究背景”等标题文字仍保留；
- 标题字体、字号、段距是否按模板显示，由 `paragraph_style` 决定；
- 目录如果仍开启，应显示无编号的目录条目，而不是删除目录；
- 每级 `HeadingLevelBindingConfig.enabled = false` 时，只关闭该级编号，不关闭该级标题本身。

因此，“标题编号关闭后标题整体消失”是不准确的。应消失的是编号视觉层。

### 5.4 表格

表格卡片对应 `table_format`。

`table_format = false` 时建议：

- 移除当前三行三列表格格式样例；
- 立即回收该样例占用的布局高度，不留下空洞；
- 不再展示模板表格字体、边框、底色、对齐、行距等效果；
- 不自动关闭题注模块；
- 不自动关闭图表居中等其他独立模块。

必须区分两种“表格被跳过”：

1. 方案级 `table_format = false`：可以立即从通用样式预览中隐藏表格；
2. 文档预检发现某个富内容表格需要跳过：这属于具体输入文档的对象级结果，只有拿到预检数据后才能显示“部分表格不处理”，不能仅凭模板预览推断。

另外，`border_mode = "none"` 只是“无边框表格”，不等于表格模块关闭；此时表格文字仍应存在。

### 5.5 页眉与页脚

页眉页脚卡片对应 `header_footer`。

`header_footer = false` 时建议：

- 隐藏预览生成的页眉文字；
- 隐藏页眉横线；
- 隐藏预览生成的页脚文字和页码；
- 保留由 `page_setup` 控制的页面本体和页边距；
- 页眉页脚距离线是否保留需要按产品语义决定。运行时这些距离由 `page_setup` 写入，即使页眉页脚模块关闭也可能影响原文已有页眉页脚，因此严格按执行结果应在 `page_setup` 开启时保留；如果产品只想表达“新生成内容”，则应隐藏。本文建议保留页面距离设置，但改为弱化的页面几何线，不与页眉内容绑定。

模板内部还需继续细分：

- `header.enabled = false` 或 `header.mode = "none"`：只隐藏页眉与横线；
- `footer.enabled = false` 或 `footer.content_mode = "none"`：只隐藏页脚；
- `page_number_enabled = false`：只隐藏页码，固定页脚文字仍可能保留；
- 首页不同、奇偶页不同、封面隐藏属于多页状态，当前单页预览没有覆盖。

### 5.6 目录

目录卡片对应 `toc`，同时还有模板内部的 `toc.enabled`。

目录样例的有效条件应为：

```text
scene.module_switches["toc"]
AND template.toc.enabled
```

任一为 false，目录样例都应消失。

目录开启时至少应展示：

- 一至 `max_level` 的代表性目录项；
- 目录层级缩进；
- `toc1`、`toc2` 等样式；
- 页码和引导符的基本效果；
- 标题编号关闭后，目录项中的标题编号也同步消失。

当前目录完全未绘制，是明确的功能缺口。

### 5.7 题注

题注卡片对应 `caption`，当前 `CaptionConfig` 没有总 `enabled` 字段，是否执行主要由方案模块开关决定。

`caption = false` 时，图题和表题样例都应消失。

`caption = true` 时至少应展示：

- 图题样例；
- 表题样例；
- `figure_prefix`、`table_prefix`；
- 章节编号或全文连续编号；
- 分隔符；
- `figure_caption` / `table_caption` 对应样式。

`auto_insert = false` 不代表题注样式关闭。它只表示缺失题注时不自动补齐，已有题注仍可能被识别和格式化。因此不能因为 `auto_insert` 关闭就隐藏所有题注样例。

当 `table_format = false`、`caption = true` 时，表格格式样例应消失，但题注样例仍可独立存在。可以用一条“表 1　示例表题”表达题注格式，不应为了展示题注重新画出一张带模板格式的表格。

## 6. 组合状态矩阵

| 状态组合 | 建议画布结果 |
|---|---|
| 页面设置关，正文开 | 中性页面容器 + 正文；无 A4 徽标、页边距色带和尺寸线 |
| 正文关，标题编号开 | 中性标题文字 + 编号；无模板正文/标题字形暗示 |
| 标题编号关，正文开 | 标题文字和标题排版保留；编号前缀消失 |
| 表格关，题注开 | 表格样例消失；独立题注样例保留 |
| 表格开，题注关 | 表格样例保留；图题/表题消失 |
| 页眉关，页脚开 | 只画页脚 |
| 页脚关，页眉开 | 只画页眉与允许的横线 |
| 页码关，固定页脚开 | 固定页脚文字保留；页码消失 |
| TOC 模块开，`toc.enabled` 关 | 目录消失 |
| 所有可预览模块都关 | 保留中性空白页，在页内显示简短空态；不弹 tooltip，不留旧缓存内容 |
| 没有绑定当前方案 | 回退为模板基线预览，不应用方案隐藏规则，并在内部状态标记 `template_baseline` |
| 页面卡片部分开启 | 分别读取 `page_setup` 与 `section_format`，不使用聚合后的 `any()` 结果 |

## 7. 除开关联动外的完整性缺口

### 7.1 覆盖声明与实际渲染不一致

这是当前最直接的产品问题：预览说明宣称包含目录和题注，画布却没有对应块。应选择“补齐渲染”，而不是仅修改说明，因为目录和题注本身就是用户要核对的模板能力。

### 7.2 预览会修改模板配置

`_build_template_preview_paragraphs()` 创建 `HeadingNumberingAdapter` 后调用 `set_template()`；后者会执行 `ensure_default_scheme()`。

对一个标题绑定为空的 `TemplateConfig()` 做只读预览，实测会产生以下副作用：

```text
预览前：0 个标题级别绑定
预览后：8 个标题级别绑定
```

而且预览会直接显示“第一章　绪论”。只读预览不应补默认配置，更不能因此把模板标记为发生变化。后续实现必须使用纯函数格式化器、不可变快照或深拷贝，禁止渲染路径写回配置。

### 7.3 横向页面的比例换算不正确

页面外形在横向模式下交换了宽高，但 `_content_rect_from_page()`、页眉页脚位置和字体点数换算仍使用未交换的纸张宽高。

以 A4 横向页面为例：

- 页面视觉宽度应对应 29.7 cm；
- 当前横向左页边距换算仍用 21 cm 作分母，水平边距会被放大；
- 当前垂直换算仍用 29.7 cm 作分母，上下页边距会被缩小。

这会导致横向预览中的页边距、页眉页脚位置和字号缩放与真实参数不一致。

### 7.4 只展示前三个标题级别

模板支持最多八级标题，预览强制截断为三级。作为单页代表样例可以接受，但不能对外声称已经完整展示所有标题层级。建议：

- 页面只展示前三个代表级别；
- 测试和文案明确“代表性预览”；
- 标题详情页继续负责完整八级核对。

### 7.5 “摘要”被无条件当作非编号标题

当前固定加入 `style_key="non_numbered_heading"` 的“摘要”，没有根据当前 `non_numbered_title_texts` 和前缀规则决定它是否仍属于非编号标题。

如果用户从跳过列表移除“摘要”，页面仍会把它画成非编号标题。正确做法应从当前规则选择一个真实匹配的示例；若没有任何非编号规则，则不画该块。

### 7.6 单页布局会静默丢块

表格计算在剩余高度不足时直接返回 `None`，后续段落超出页面也会直接停止。结果可能是：

- 概览说明仍写“包含表格/目录/题注”；
- 实际块因前面段距、行距或字体过大而没有画出；
- 用户看不到任何“未能容纳”的提示。

后续需要基于可见模块动态压缩样例、分页、分区布局，或保证每类关键对象至少保留一个最小代表块。

### 7.7 页眉页脚只覆盖了部分配置

当前只画默认页的单一页眉和页脚，并且存在以下缺口：

- 首页不同、奇偶页不同未展示；
- 多个页码阶段只取第一个可见阶段；
- 封面隐藏与选择器范围未展示；
- 页码模板未完整映射；
- 页眉边框样式、宽度、颜色被简化成固定灰线；
- `inside` / `outside` 对齐在单页中没有表达；
- `template`、`preserve` 等内容模式没有完整表达。

### 7.8 表格预览只覆盖简单表格

当前固定使用三行三列纯文本数据，虽然已覆盖部分边框、底色、字体、字号、对齐和行距，但没有表达：

- `smart_levels` 的真实决策；
- 跨页重复表头；
- 合并单元格；
- 富内容表格被跳过；
- 输入表格原宽度在 `keep` 模式下的结果；
- 图表居中和续表等邻接能力。

其中“跨页重复表头”天然需要至少两页，不能在当前单页示意中完整证明。

### 7.9 当前使用原始模板，不是最终解析配置

预览读取 `TemplateConfig`，没有读取：

- 当前方案的 `template_overrides`；
- 方案分区样式 `section_styles`；
- 执行前会话覆盖；
- 输入文档已有版式和保留策略；
- 对象预检产生的跳过结果。

所以即使补上模块开关，它仍只能成为“当前方案下的模板效果示意”，不能自动等同于最终 Word 输出。

### 7.10 模板中的其他可视配置没有进入本预览

`TemplateConfig` 还包含公式表格、公式样式、公式编号、参考文献样式、水印等配置。当前七张模板详情卡和概览预览并未完整覆盖这些对象。

`reference_style` 已经存在摘要投影代码，但不在当前详情顺序和概览覆盖列表中。`formula_table`、`formula_style`、`equation_numbering`、`watermark` 也没有进入此页面预览。

`output` 属于产物选择，不需要画进文档页面；其余可视配置如果继续由模板管理，就需要明确分配到预览或独立详情，否则“模板完整预览”这一命名仍然过度承诺。

## 8. 建议的预览状态模型

不要在绘制函数中到处直接查询控件。应先生成一份不可变的预览计划，再由布局和绘制层消费。

建议至少拆出两层状态：

```text
TemplatePreviewFeatureState
  source_mode: template_baseline | current_plan
  page_setup_enabled
  section_format_enabled
  paragraph_style_enabled
  heading_numbering_enabled
  table_format_enabled
  header_footer_enabled
  toc_module_enabled
  caption_module_enabled

TemplatePreviewBlockPlan
  show_page_guides
  show_body
  show_heading_text
  show_heading_numbers
  show_table
  show_header
  show_footer
  show_toc
  show_figure_caption
  show_table_caption
  empty_state
```

第一层只表达方案与模块事实；第二层再结合模板内部配置计算最终可见块。例如：

```text
show_toc = toc_module_enabled AND cfg.toc.enabled
show_header = header_footer_enabled AND cfg.header_footer.header.enabled
show_heading_numbers = heading_numbering_enabled AND 当前级绑定.enabled
show_table = table_format_enabled
```

这样可以避免把模块关闭、模板子开关关闭和对象级跳过混在一起。

## 9. 建议的数据接入与刷新路径

### 9.1 输入

模板概览应同时接收：

- 当前模板或解析后的有效模板参数；
- 当前方案，可为空；
- 可选的输入文档预检摘要，仅用于对象级“部分跳过”状态。

没有当前方案时，保持模板基线模式；有当前方案时，切换到当前方案生效模式。

### 9.2 刷新

以下事件都应重建 `TemplatePreviewBlockPlan` 和布局缓存：

- 选择模板；
- 编辑模板参数；
- 切换任一方案模块；
- 修改页眉、页脚、页码、TOC 等模板内部开关；
- 当前方案变化；
- 解析配置变化；
- 预检结果变化。

不能只调用 `update()` 重画旧缓存；开关变化必须执行布局重建，否则隐藏块仍会占位。

### 9.3 只读约束

预览链路必须满足：

```text
refresh / layout / paint 前后，TemplateConfig 与 SceneWorkspace 深比较相等
```

任何默认值补齐和迁移都应在加载/迁移层完成，不能由预览适配器偷偷写入。

## 10. 分阶段落地顺序

### 阶段 0：交互收敛，已完成

- 移除放大按钮；
- 移除画布激活；
- 移除专用放大弹窗；
- 移除概览 tooltip；
- 保留结构化预览元数据。

### 阶段 1：方案开关主联动

- 增加 `TemplatePreviewFeatureState`；
- 把当前方案开关传入预览；
- 页面引导线、正文、标题编号、表格、页眉页脚先完成显示/隐藏；
- 开关变化立即重建缓存；
- 增加无方案和全部关闭空态。

### 阶段 2：补齐目录与题注

- 增加 TOC 代表块；
- 增加图题、表题代表块；
- 实现模块开关与模板内部开关的 AND 规则；
- 修正覆盖说明，使说明来源与实际块计划一致。

### 阶段 3：正确性修复

- 消除预览修改模板的副作用；
- 修复横向纸张的宽高换算；
- 根据非编号规则动态生成样例；
- 处理单页溢出，保证关键块不静默丢失；
- 补页眉页脚变体与页码计划的代表状态。

### 阶段 4：明确“示意预览”和“真实 Word 预览”的边界

当前 QPainter 画布适合即时参数反馈，不应被定义为像素级 Word 所见即所得。需要精确验证跨页表头、Word 字体回退、域、目录、分页和节行为时，应接入真实 DOCX 渲染链路。

建议产品文案最终采用“样式示意”或“当前方案样式预览”，并在真实 Word 预览能力可用时另设明确入口，不再用当前轻量画布承担全部版式证明责任。

## 11. 验收测试矩阵

至少需要补充以下自动化测试：

1. 页面设置关闭后，`show_page_guides = false`；
2. 页面设置关闭后，纸张容器仍存在；
3. 页面卡片部分开启时按模块分别计算；
4. 正文关闭后不产生 `body` 模板样式块；
5. 标题编号关闭后标题文字仍在、编号为空；
6. 单级标题绑定关闭后只去掉该级编号；
7. 表格模块关闭后无 `table_preview` 块且无空白占位；
8. 表格关闭、题注开启时题注仍在；
9. 页眉页脚模块关闭后页眉文字、横线、页脚、页码均不存在；
10. 只关闭页眉时页脚仍存在；

12. TOC 模块与 `toc.enabled` 任一关闭时无 TOC；
13. 标题编号关闭后 TOC 条目无标题编号；
14. 题注模块关闭后无图题和表题；
15. `auto_insert = false` 时已有题注样式样例仍可见；
16. 无当前方案时回退模板基线；
17. 所有模块关闭时展示页内空态且没有 tooltip；

19. 预览前后模板配置深比较不变；
20. A4 横向页边距按 29.7 cm × 21 cm 正确换算；

22. 覆盖说明中的对象集合与实际 `TemplatePreviewBlockPlan` 完全一致。

## 12. 最终判断

当前预览“参数映射已有一定深度，但执行状态和对象覆盖不完整”。它已经能表达页面几何、正文和标题样式、部分编号、简单表格、基本页眉页脚，但仍缺少决定其可信度的三层闭环：

1. 当前方案是否执行该模块；
2. 模板内部是否启用该子能力；
3. 具体输入文档中的对象是否真正可处理。

下一步不应继续在 `paintEvent()` 里零散增加判断，而应先建立统一的预览状态和块计划。完成该层后，用户提出的“关闭什么，预览就撤掉什么”才能稳定成立，同时不会误伤仍由其他模块负责的内容。

# 高层场景能力矩阵 V22 完善闭环与高频无遗漏规划（2026-06-18）

## 1. 本轮问题

用户继续强调：当前功能点仍然不完善，不能只围绕已有模块继续补小缺口。高层场景能力矩阵必须回答更前置的问题：

```text
高频用户请求是否都有归属？
相似请求的边界是否足够清楚？
一个场景从规划、UI、默认配置、执行、报告到测试是否互相打通？
公式、输出、水印、固定版位、专业判断、AI/OCR/PDF/LaTeX 这些边界是否被放到正确层级？
```

V22 的结论是：完善的场景矩阵不是“新增更多顶层场景”，而是建立一套稳定的场景能力准入模型。任何高频请求进来，都必须能被裁决到下面其中一类：

```text
coverage pack
planned scene family
profile
material schema
count profile / inventory evidence
delivery preset
session override
plugin/manual gate
```

找不到落点，就是遗漏；落点有多个但没有裁决规则，就是边界不清；落点有规划但没有 defaults/report/test，就是链路断链。

## 4. 完整场景能力的八层模型

一个高层场景能力必须同时过 8 层审计。

| 层级 | 必须回答 | 失败表现 |
| --- | --- | --- |
| L1 自然请求 | 用户会怎么说？有哪些别名？ | 高频说法找不到入口 |
| L2 归属裁决 | 落到哪个 pack/family/profile/preset？ | 产品手册、报价、证书、双语等边界混乱 |
| L3 事实源 | 机器可信数据来自 docx、JSON、XLSX、BibTeX/CSL 还是资料包？ | AI/Markdown/手输文本被误当真相源 |
| L4 能力组合 | 需要模板、资料、计数、对象预检、显隐、批量、交付中的哪些？ | 只做一个开关，缺完整工作流 |
| L5 Word 风险 | 会触碰哪些 OOXML/package surface？ | 内容控件、文本框、字段、修订、OLE 被静默破坏 |
| L6 UI/控件契约 | 用户能否看见配置、边界和禁用原因？ | ScenePanel 与模板管理控件风格和语义不一致 |
| L7 执行/报告 | pipeline、report、issue queue、artifact 是否有证据？ | UI 说能做，执行和报告无记录 |
| L8 测试/回归 | registry、projection、runtime、report 是否有测试？ | 后续新增 family 再次断链 |

未过 L1-L2，只是需求；未过 L3-L5，只是配置草稿；未过 L6-L8，不能宣称为完整可用场景。

## 7. 高频边界裁决规则

### 7.1 裁决优先级

```text
专业判断 > 导入风险 > 业务事实源 > 输出版本 > 模板外观
```

解释：

- 如果涉及法律、审计、财务、专利、翻译质量，先进入 plugin/manual gate；
- 如果输入来自 OCR/PDF/完整 LaTeX/AI，先进入 import boundary；
- 如果有 JSON/XLSX/BibTeX/CSL/资料包事实源，先绑定 schema/profile；
- 如果只是 final/review/student/customer/internal 等版本，落 DeliveryPreset；
- 如果只是字体、字号、缩进、段距、页边距、题注样式，回模板管理。

### 7.2 高频歧义裁决

| 用户说法 | 裁决 |
| --- | --- |
| 产品手册 | 客户/售前材料 -> `application_reports/product_sales_documents`；操作/接口/SOP -> `technical_long_docs` |
| 报价方案 | 方案正文和产品资产 -> product/pre-sales；金额表/预算附件 -> `professional_disclosure/finance_quote_documents` |
| 证书材料 | 套打生成 -> `batch_forms/form_batch_documents`；投标资质 -> `bidding_materials/qualification_archive_packages` |
| 会议材料 | 行政会议纪要/制度 -> `official_policy`；普通会议总结 -> `quick_formatting` 或 `application_reports` |
| 双语文档 | 普通排版 -> `quick_formatting`；术语一致性/对照审阅 -> `professional_disclosure/bilingual_translation_documents`；翻译质量 -> plugin/manual gate |
| 专利说明书 | 格式/图号/术语清单可登记；法律质量、权利要求有效性、侵权风险 -> plugin/manual-only |
| PDF 论文 | 先 `import_ai_boundary` 形成置信度和人工确认，再路由到 `chinese_academic` |
| LaTeX 公式 | 公式片段可进入目标场景；完整工程 -> import/plugin boundary |
| 水印 | 状态语义归 Scene/DeliveryPreset；颜色、字号、角度等视觉基线必须走控件契约/模板基线 |

## 8. Word/OOXML 反推矩阵

只按业务名称规划会漏掉真实风险。场景必须从 Word 本体反推。

| OOXML/package 面 | 高频场景 | 必须声明 |
| --- | --- | --- |
| `w:p` / `w:r` | 所有场景 | 是否重写 run、是否保留内联格式 |
| `styles.xml` | 模板、论文、公文、报告 | 外观基线归模板；场景覆盖需有理由 |
| `numbering.xml` | 公文、论文、标书、合同 | rebuild/preserve/repair 策略 |
| `w:tbl` / `w:tr` / `w:tc` | 试卷、报价、表单、披露 | 表格网格、合并、分页、重复表头 |
| `w:trHeight` | 固定版位表单、答题卡、证书 | fixed-layout policy，不回普通 `TableConfig.row_height_pt` |
| `w:sdt` | 表单、合同、HR、套打 | 内容控件映射、填充、残留检查 |
| `w:txbxContent` / VML shape | 表单、证书、旧模板 | 文本框/shape 预检和残留报告 |
| fields / TOC / PAGE / REF | 论文、公文、技术文档 | preserve/update/skip 策略 |
| comments / revisions | 合同、期刊、披露、双语 | preserve/block/compare/report |
| headers/footers/sectPr | 公文、论文、合同、水印 | 外观归模板，状态归场景/交付 |
| footnotes/endnotes | 学术、长文档 | 是否计数、是否格式化、是否报告 |
| hidden text | 披露、合同、审阅稿 | 预检、显隐、计数/交付影响 |
| OLE/embedded/VBA/Visio | 财务、技术、标书 | block/warn/isolate，不能静默改写 |
| relationships/package parts | 附件、图片、外链、归档包 | manifest、外链风险和 artifact 引用 |

## 9. 公式、输出、水印的正确归属

这三类不是“暂时不管”的边角项，而是横切场景能力。

| 对象 | Template | Scene | Material | Session | Plugin/manual |
| --- | --- | --- | --- | --- | --- |
| 公式 | 字体、字号、编号外观、行距基线 | 是否处理、范围、低置信度策略、报告 | 本次公式内容或题源公式 | 本次跳过/降级 | 完整 LaTeX、复杂图形、专业转换 |
| 输出 | 默认 artifact 基线可选 | final/review/student/teacher/signing/submission/archive preset | 文件名变量、附件角色 | 本次输出目录、覆盖确认 | 外部提交系统、PDF/OCR 管线 |
| 水印 | 颜色、角度、字号、透明度视觉基线 | 内部传阅、征求意见、归档、保密等状态策略 | 项目名/单位名/水印文本变量 | 本次临时启停 | 权限、法律效力、DRM |

控件要求：

- 同名格式参数必须复用模板管理控件；
- 场景专属控件也必须复用模板管理的尺寸、禁用态、表单行、摘要组件；
- 输出 preset、水印状态、公式策略、plugin/manual gate 不能做成场景私有风格的 combo/switch；
- 禁止把高频业务能力藏在“高级设置”文本区。

## 13. 验收清单

1. 用户自然会怎么说？
2. 落在哪个需求带和 pack？
3. 是 family、profile、schema、preset、session，还是 plugin boundary？
4. 事实源是什么？
5. 是否需要结构化 JSON/XLSX/BibTeX/CSL？
6. 是否需要 MaterialSchema？
7. 是否需要 CountProfile 或专用 inventory evidence？
8. 是否触碰内容控件、文本框、字段、修订、隐藏文本、OLE、VBA 或关系包？
9. 是否需要多版本输出或内容显隐？
10. 输出 preset 是否能解释业务版本？
11. 水印是否是状态策略，而非页眉页脚装饰？
12. 公式是否有低置信度、fallback 和插件边界？
13. ScenePanel 是否可见？
14. Workbench issue queue 是否可解释？
15. report 是否记录边界、跳过、缺项和产物？
16. artifact 是否可定位？
17. 是否有静态 registry/projection 测试？
18. 是否有 runtime/report 测试？

如果任何一项回答“不知道”，就是边界不清；如果回答“以后再说”，就是仍有高频遗漏风险；如果回答“UI 有”，但执行/报告/测试没有，就是链路断链。

# 素材管理功能分析与规划（2026-06-02）

## 1. 结论摘要

`素材管理` 不是普通的图片库入口，也不是 UI 组件资产池。结合当前代码、测试和旧规划残留判断，它预留的是一个 **运行上下文素材编排能力**：

- 管理不同企业、组织、角色、项目的一组实体字段；
- 关联这些实体字段所需的图片、盖章、资质、附件、Logo、签名、水印等素材目录；
- 将实体字段、数据源、占位符规则、图片插入计划、水印配置统一转成执行期 payload；
- 服务标书、公文、技术文档、批量生成等“同一模板/场景，多套主体资料”的工作流。

当前状态是：**Phase 1-6 的执行闭环已落地：侧边栏已有真实素材管理面板，多 profile 选择、实体字段、替换规则、图片素材、Excel/CSV/JSON 映射、缺失素材阻塞、Workbench 批量按钮和统一批量报告都已进入执行链路。后续主要剩余素材角色手动编辑、素材预览网格、结构化图片规则编辑、字段 schema / 必填字段 UI、复杂锚点与复杂表格映射等增强能力。**

后续应把它定义为 `执行素材 / 业务资产` 管理，而不是孤立的“上传图片”功能。

## 3. 它到底是为了什么功能预留的

### 3.1 不是为了“图片管理器”

如果只是图片管理器，现有结构不需要：

- `EntityArchive`
- `EntityProfile`
- `fields`
- `assets_dir`
- `entity_data`
- `replacements`
- `batch_preset`

这些字段说明它关注的是“业务主体资料”，不是图片浏览。

### 3.2 不是为了“模板管理”

模板管理负责版式默认值，例如：

- 页面尺寸；
- 字体字号；
- 标题编号；
- 表格样式；
- 页眉页脚；
- 参考文献样式。

素材管理负责运行期内容，例如：

- 哪个公司；
- 哪个项目；
- 哪个法人；
- 哪套资质图片；
- 哪个 Logo；
- 哪些章、签名、附件；
- 哪些占位符应替换成什么。

同一个模板可以绑定不同素材包。同一个素材包也可以应用到多个模板或场景。

### 3.3 不是为了“场景配置”

场景配置回答的是“这类文档要启用哪些能力，以及怎么执行”：

- 标书排版；
- 公文排版；
- 技术文档；
- 论文排版；
- 是否启用内容填充；
- 是否启用图片插入；
- 是否启用水印。

素材管理回答的是“本次执行要使用哪套资料”：

- 甲公司投标主体；
- 乙公司联合体成员；
- 某项目资料；
- 某批次资质附件；
- 某个文件夹里的章和 Logo。

场景决定能力开关，素材决定运行数据。

### 3.4 它预留的真实功能

最终应该服务四类核心工作流：

1. **实体字段填充**

   用户维护一组实体档案，如公司、学校、项目、人员、角色。执行时把 `{{company_name}}`、`${legal_person}` 等占位符替换成当前实体值。

2. **素材包选择与图片插入**

   用户为实体或项目关联素材文件夹，如 Logo、签章、资质图片、封面图、二维码。执行时根据插入规则把图片放到文档指定位置。

3. **映射规则与自由替换**

   用户维护可复用映射表，把 Excel/CSV/JSON 或手工规则转为 `ReplacementRule`，执行时批量替换。

4. **批量生成**

   一个场景和模板可以套多个实体档案，分别输出到不同目录。例如陪标、联合体、多分公司、多项目批量文档。

## 5. 推荐最终产品定义

建议把一级入口命名继续保留为 `素材管理`，但内部语义定义为：

> 管理执行时使用的业务资料、实体字段、素材包和映射规则，并把它们编排成可被排版管线消费的运行上下文。

不要把它做成简单文件浏览器。它应该是模板、场景之外的第三类配置资产：

| 类型 | 回答的问题 | 示例 |
| --- | --- | --- |
| 模板 | 文档长什么样 | 页面、字体、标题、表格、页码 |
| 场景 | 这次要做什么 | 标书、公文、技术文档，启用哪些模块 |
| 素材 | 用谁的资料执行 | 公司字段、项目字段、Logo、章、资质图、替换规则 |

## 6. 推荐数据模型

### 6.1 `EntityArchive`

继续保留，作为“组织级资料档案”。

建议扩展：

```python
@dataclass
class EntityArchive:
    archive_id: str
    archive_name: str
    profiles: list[EntityProfile]
    asset_collections: list[AssetCollection]
    field_schema: list[EntityFieldDefinition]
```

### 6.2 `EntityProfile`

表示一个可执行主体。

建议字段：

```python
@dataclass
class EntityProfile:
    profile_id: str
    profile_name: str
    role: str
    fields: dict[str, str]
    assets_dir: str
    asset_collection_ids: list[str]
```

示例角色：

- 投标人主体；
- 联合体牵头人；
- 联合体成员；
- 分包方；
- 学校；
- 作者；
- 项目业主。

### 6.3 `AssetCollection`

表示一个素材包。

```python
@dataclass
class AssetCollection:
    collection_id: str
    name: str
    root_dir: str
    items: list[AssetItem]
```

### 6.4 `AssetItem`

表示一个具体素材。

```python
@dataclass
class AssetItem:
    item_id: str
    label: str
    role: str
    path: str
    mime_type: str
    tags: list[str]
    width_cm: float | None
```

建议 `role` 预置：

- `logo`
- `seal`
- `signature`
- `qualification`
- `cover_image`
- `qrcode`
- `watermark_image`
- `attachment_image`
- `other`

### 6.5 `AssetInsertionRule`

把素材项变成图片插入计划。

```python
@dataclass
class AssetInsertionRule:
    rule_id: str
    asset_role: str
    target: str
    position: str
    width_cm: float
    required: bool
```

`target` 可以逐步支持：

- 文档末尾；
- 第 N 段；
- 指定占位符段落；
- 指定标题后；
- 页眉；
- 页脚；
- 封面区域。

第一版不必全做，可以先做“占位符锚点 + 文档末尾”。

### 6.6 `MaterialExecutionContext`

建议新增一个执行上下文模型，用于 Workbench 和执行器之间传递。

```python
@dataclass
class MaterialExecutionContext:
    archive_id: str = ""
    profile_id: str = ""
    entity_data: dict[str, str] = field(default_factory=dict)
    entity_assets_dir: str = ""
    images: list[ImageInsertionItem] = field(default_factory=list)
    replacements: list[ReplacementRule] = field(default_factory=list)
```

它的职责是将素材管理页面的复杂状态压平成 `resolve_config()` 已经能消费的 payload。

## 7. 推荐 UI 规划

### 7.1 一级页面：素材管理

建议布局使用主从结构：

左侧：

- 素材库 / 档案列表；
- 搜索；
- 新建档案；
- 导入 JSON；
- 最近使用。

中间：

- 当前实体档案；
- profile 列表；
- 字段表；
- 素材包列表。

右侧：

- 当前 profile 详情；
- 素材预览；
- 缺失项校验；
- 映射规则；
- 执行影响摘要。

### 7.2 页面功能分区

建议分为 5 个 Tab 或二级对象：

1. **实体档案**

   管理公司、项目、人员等字段。支持增删 profile，编辑字段，设置默认 profile。

2. **素材包**

   关联本地文件夹，扫描图片素材，给素材打角色标签。

3. **映射规则**

   维护占位符规则、Excel/CSV/JSON 映射规则、自由替换规则。

4. **插入规则**

   定义素材角色如何插入文档，如 Logo 插入到 `{{logo}}` 位置，签章插入到 `{{seal}}` 位置。

5. **批量执行**

   选择多个 profile，预览输出目录，生成批量执行上下文。

### 7.3 Workbench 中的轻量入口

Workbench 不应承载完整素材管理，只显示高频摘要：

- 当前实体：未选择 / 某公司 / 某项目；
- 当前素材包：未挂载 / 8 个素材 / 缺 1 个必需素材；
- 映射状态：已完成 / 有缺失；
- 操作：
  - 选择实体；
  - 快速映射；
  - 打开素材管理；
  - 预览填充范围。

这与旧规划里的 `Quick Fill` 定位一致：Workbench 是执行入口，素材管理是深度配置入口。

## 9. 优先级建议

### 基础闭环已完成

1. `MaterialExecutionContext`
2. Workbench 执行器注入 `entity_data / images / replacements`
3. 简单实体字段 UI
4. `assets` 面板真实挂载
5. 多 profile 选择和批量执行
6. Excel/CSV/JSON 映射
7. 缺失素材阻塞
8. 统一批量报告

### 下一批增强

1. 图片预览网格；
2. 高级素材标签；
3. 素材角色手动编辑；
4. 字段 schema / 必填字段 UI；
5. 复杂锚点插入；
6. 多行复杂表格映射；
7. 素材版本管理。

### 暂时不要做

1. 大而全的文件管理器；
2. 云素材库；
3. 素材权限系统；
4. 类似 DAM 的复杂元数据系统；
5. 直接把素材写进模板。

这些会把边界拉得太大，且不是当前执行闭环的瓶颈。

## 10. 与现有模块的职责边界

### 模板管理

保留：

- 版式；
- 样式；
- 页眉页脚；
- 页码；
- 题注；
- 参考文献；
- 表格；
- 输出报告默认项。

不放：

- 公司名称；
- 项目名称；
- Logo；
- 签章；
- 资质图片；
- 本次执行的数据源。

### 场景配置

保留：

- 是否启用内容填充；
- 是否启用图片插入；
- 是否启用水印；
- 范围和模块开关；
- 场景级行为参数。

不放：

- 当前实体是谁；
- 当前素材文件夹是什么；
- 当前图片清单是什么。

### 素材管理

负责：

- 实体档案；
- 业务字段；
- 素材目录；
- 素材项；
- 映射规则；
- 图片插入规则；
- 批量 profile；
- 执行上下文生成。

## 12. 第一版最小可行验收用例

当前基础闭环验收 6 件事：

1. 用户在素材管理中新建 `测试公司` profile，字段包含：
   - `company_name = 测试公司`
   - `legal_person = 张三`

2. 用户在 Workbench 或素材管理中同步该 profile。

3. 文档中存在：
   - `{{company_name}}`
   - `${legal_person}`

4. 点击执行后输出文档里占位符被替换，报告记录 `entity_fill` 变更。

5. 用户在素材管理选择多个 profile 后点击 Workbench 批量执行，可生成多份独立输出和统一批量报告。

6. 当图片规则要求 `logo` 但素材目录中缺失 `logo.png` 时，runner 返回 failed 并在错误文本中提示缺失角色。

这能证明素材管理从 UI 到执行管线已经打通。

图片、素材包、映射规则都可以在这个基础上逐步增强。

## 13. 最终形态一句话

`素材管理` 最终应该成为 Lark Formatter 的 **业务资料中枢**：

> 模板决定格式，场景决定流程，素材决定本次执行使用哪套真实业务资料。

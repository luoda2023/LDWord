# 高层场景能力矩阵 N2.197 考试题目图片问题队列行级跳转闭环
日期：2026-06-20

## 1. 目标

N2.196 已经证明“缺文件题图”不会从 AssetsPanel 明细表消失，并且能在同一行替换修复。本轮继续闭合它留下的明确缺口：

```text
批量运行 / 报告发现 question_figure 文件缺失
-> batch_issue_items 写入 row 级 repair target
-> Workbench 问题队列点击处理
-> bridge 携带 profile + question_figure_item
-> AssetsPanel 选择对应 profile
-> question_figure_asset_items_table 自动选中缺文件行
```

本轮关注的是“报告问题队列能跳到对应行”，不是新增复杂素材库、远端素材管理或一题多图排序。

## 2. 落地内容

### 2.1 批量上下文承接结构化素材条目

`build_material_batch_items()` 现在会把 `EntityProfile.asset_items` 合入每个批量 profile 的 `MaterialExecutionContext.asset_items`。

这修复了一个真实断链：前台已经能导入和保存逐题题图，但批量执行上下文此前只消费扫描目录与 `asset_paths`，导致报告层无法看到结构化 `question_figure` 条目。

### 2.2 缺文件题图进入运行时诊断

`WorkbenchProductionRunner` 新增 `question_figure` 文件存在性诊断：

- 仅扫描 `role=question_figure` 的结构化素材条目；
- 有 path 但本地文件不存在时写入 `preflight_missing_question_figure_file`；
- severity 为 `warning`，不直接阻断整批执行；
- 诊断携带 `missing_asset_items`；
- 诊断携带 `repair_target_type=question_figure_item`；
- `repair_target_key` 使用 JSON 保存 `role`、`item_id`、`question_index`、`path`、`metadata`。

这样报告与问题队列不再只能知道“缺素材角色 question_figure”，而是知道“哪一道题的哪一张题图缺文件”。

### 2.3 Workbench 问题队列 profile 级路由

`workbench_issue_action_target()` 现在会把带有 profile 上下文的 `question_figure_item` 包装为：

```text
profile_question_figure_item
```

`WorkbenchPanel._open_issue_repair_target()` 会解码 profile payload，并通过 `PanelBridge.request_material_profile_repair_target()` 把目标交给 AssetsPanel。

### 2.4 AssetsPanel 行级定位

AssetsPanel 新增 `question_figure_item` 修复目标消费：

- 先按 `profile_id` / `profile_name` 选择批量 profile；
- 解码 `question_figure_item` 的 JSON target；
- 优先按 `item_id` 匹配；
- 其次按 `metadata.question_index` / `question_id` / `question_no` / `number` 匹配；
- 最后按原 path 兜底匹配；
- 匹配后选中 `question_figure_asset_items_table` 对应行，并滚动到该行。

## 3. 成熟度证据

`scene_product_readiness` 已更新：

- `pack:exam_education` evidence 增加 `question asset issue queue row routing`；
- `family:exam_teaching` evidence 增加 `question asset issue queue row routing`；
- remaining gap 仍保持 `advanced question asset library UI` / `advanced asset library UI`。

保留 gap 的原因是：本轮只闭合“报告/问题队列到缺图行”的路由，不包含远端素材源、一题多图/图组排序、批量错图匹配、复杂学科图生成或素材/AI 质量判断。

## 4. 全局修复路由

`scene_repair_routing` 的 material route 已纳入：

```text
question_figure_item
profile_question_figure_item
```

这保证 row 级题图问题不是孤立 target，而是归属到 material repair route，与 field、asset、schema 和 profile-scoped material repair 使用同一治理框架。

## 6. 后续边界

N2.197 后，`advanced question asset library UI` 的剩余边界收窄为：

- 远端 `asset_id` / `source` 解析；
- 一题多图 / 图组排序；
- 批量自动匹配错图的检测与修复；
- 复杂学科图生成或插件接管；
- AI 出题质量、素材质量、版权或真实性判断；
- 更完整的素材库批量审阅与历史版本管理。

后续 N2.198 已承接并闭合远端 `asset_id` / `source` 桥接；真实远端素材下载、鉴权、缓存和预览仍不属于 N2.197 范围。

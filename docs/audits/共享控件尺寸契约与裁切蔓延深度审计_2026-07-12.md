# 共享控件尺寸契约与裁切蔓延深度审计

- 日期：2026-07-12
- 范围：`src/shared/ui`、`src/ui/panels`、相关 UI 架构与布局测试
- 起因：资料包“选图片”页的目录选择器和操作按钮多次出现底边裁切、控件显示不完整
- 状态：系统性整改与本审计范围验收已完成；全仓测试另有 17 条既有非尺寸链路失败，已在 11.5 节记录

## 1. 执行结论

本问题不是“选图片”页的孤立样式缺陷，而是共享 UI 尺寸系统存在多套互不兼容的高度语义：

1. 主题层把 `control_height_*`、`button_height_md` 当作尺寸令牌；
2. 普通 `QLineEdit` / `QPushButton` 的 QSS 把令牌写入 `min-height` / `max-height`，同时继续叠加上下 padding 和 border；
3. `resolved_control_height()` 又把令牌解释为接近最终外框高度，只额外加 2px；
4. `StyledComboBox` / `StyledSpinBox` 通过清空垂直 padding，把同一个 `md` 收敛到 32px；
5. 业务页面和复合控件继续使用 `setFixedHeight`、`min=max` 或 `setFixedSize` 限制父容器和子控件。

因此同一个 `md` 在真实 Qt 运行时并不代表一个稳定高度，而是至少产生以下结果：

| 控件 | `md` 真实结果 | 说明 |
|---|---:|---|
| `SearchInput` | 20px | 设置了 `sizeClass=md`，但自身 QSS 没有匹配该属性，尺寸类实际未生效 |
| `StyledComboBox` | 32px | 自定义 QSS 清空垂直 padding，基本符合当前 `resolved_control_height()` |
| `StyledSpinBox` | 外框 32px / `minimumSizeHint` 35px | 已形成硬约束冲突 |
| 普通 `QLineEdit` + shared QSS | 40px | 30px 内容高度 + 8px 垂直 padding + 2px border |
| 普通 `QPushButton` + shared QSS | 42px | 32px 内容高度 + 8px 垂直 padding + 2px border |

结论：必须重构共享尺寸契约。继续按页面增加 margin、调大父容器或单独覆盖按钮高度，只会把问题推迟到下一个主题、复合控件或响应式状态。

## 2. 本次审计方法

本次没有只做关键词判断，而是使用四层证据：

1. 静态扫描高度 API：
   - `apply_size_class(...)`
   - `resolved_control_height(...)`
   - `setFixedHeight(...)`
   - `setMinimumHeight(...)` + `setMaximumHeight(...)`
   - `setFixedSize(...)`
2. 追踪主题令牌到 QSS 生成器，再到共享控件和复合父容器；
3. 使用 `QT_QPA_PLATFORM=offscreen` 实例化真实 PySide6 控件，记录：
   - `height()`
   - `sizeHint().height()`
   - `minimumSizeHint().height()`
   - `minimumHeight()`
   - `maximumHeight()`
   - 子控件是否超出父控件边界
4. 对默认主面板、资料图片页、标题编号页和题注详情页分别执行运行时探针。

静态扫描概况：

| 模式 | 数量 |
|---|---:|
| `apply_size_class()` 调用点 | 45 |
| `resolved_control_height()` 消费点 | 16 |
| 含 `setFixedHeight()` 的文件 | 21 |
| 业务面板中仍含 `setFixedHeight()` 的文件 | 3 |
| `SpacingInput` 使用点 | 24 |
| `SearchInput` 使用点 | 2 |

这些数字不是缺陷数量。风险只在以下组合中成立：

```text
主题 QSS 声明内容高度
  + QSS padding / border 扩大真实外框
  + 父容器或业务代码按原始令牌限制高度
  = 底边裁切、文字压缩、边框缺失或相邻控件覆盖
```

## 3. 已确认的根因

### 3.1 高度令牌没有唯一语义

关键令牌位于 `src/shared/ui/theme.py`：

- `button_height_md = 32`
- `button_padding_y = 4`
- `input_padding_y = 4`
- `control_height_sm = 24`
- `control_height_md = 30`
- `control_height_lg = 36`

当前代码没有明确这些数值代表：

- 内容区高度；
- 不含 border 的 QSS box；
- 最终 QWidget 外框高度；
- 还是仅用于视觉密度分级的基础值。

普通输入框和按钮把它们当“内容区最小高度”，`resolved_control_height()` 却把它们当“接近最终外框高度”。这是第一处结构性冲突。

### 3.2 普通 QSS 与自绘控件使用不同 box model

普通输入框在 `src/shared/ui/input_metrics.py` 中同时声明：

```text
min-height: control_height_md
padding: input_padding_y input_padding_x
border: 1px
```

真实外框因此为：

```text
30 + 4 * 2 + 1 * 2 = 40px
```

普通按钮在 `src/shared/ui/button_style.py` 中同理：

```text
32 + 4 * 2 + 1 * 2 = 42px
```

而 `StyledComboBox` / `StyledSpinBox` 的 `sizeClass` 分支会设置：

```text
padding-top: 0
padding-bottom: 0
min-height/max-height: resolved_control_height(...)
```

于是同一个 `md` 在普通控件和自绘控件之间天然相差 8～10px。

### 3.3 `resolved_control_height()` 的名称与实际能力不一致

`src/shared/ui/sizing.py` 当前实现为：

```python
token = theme.control_height_md
return int(token) + 2
```

对默认主题而言返回 32px。它没有接收控件类型、padding、border、variant，也没有读取真实 `minimumSizeHint()`，所以不能称为“rendered pixel height”。

它最多只能代表“无垂直 padding、1px 双边框的标准自绘控件外框高度”。

当这个值被用于普通 `QLineEdit`、普通 `QPushButton` 或它们的父容器时，就会低估真实高度。

### 3.4 `apply_size_class()` 不是完整尺寸契约

`apply_size_class()` 只负责：

1. 设置动态属性 `sizeClass`；
2. 对当前 style 执行 unpolish / polish。

它不能保证：

- 当前控件 QSS 中真的存在 `[sizeClass="md"]` 选择器；
- 选择器的高度语义和其他控件一致；
- 后续 `setStyleSheet()` 不改变尺寸结果；
- 父容器为新尺寸预留空间；
- `maximumHeight >= minimumSizeHint().height()`。

`SearchInput` 是最直接的反例：它对容器调用 `apply_size_class(self, "md")`，但容器样式只有对象名选择器，没有 `sizeClass` 分支，运行时高度最终只有 20px。

### 3.5 业务层绕过共享尺寸系统

当前仍存在三类绕过方式：

1. `setFixedHeight(...)`；
2. 分别设置同一个 `minimumHeight` 和 `maximumHeight`；
3. `setFixedSize(width, height)`。

现有测试只扫描业务面板源码中的字面量 `setFixedHeight(`，因此后两类不会被发现。

图片页操作按钮就是典型情况：按钮先应用普通按钮 QSS，最小尺寸提示为 42px，随后又被固定为 34×34px。

### 3.6 主题刷新和响应式切换会放大问题

尺寸约束通常由多个阶段重复写入：

```text
构造控件
→ apply_size_class
→ apply_button_variant / setStyleSheet
→ 页面 _apply_theme
→ 响应式逻辑 setFixedSize
→ 再次主题刷新
```

不同调用顺序会让 Qt 在 `sizeHint`、QSS min/max、显式 min/max 和布局分配之间反复取舍。结果可能表现为：

- 控件实际高度大于 `maximumHeight()`；
- 圆角下边框缺失；
- 文本基线偏上；
- 父容器 `sizeHint` 小于子控件实际需要；
- 宽屏正常、窄屏或主题刷新后出现问题。

它们仍存在 40px 输入框、42px 按钮、32px下拉框混用的问题。应在 P0/P1 核心迁移完成后统一，不建议现在逐点写补丁。

### 4.9 不应纳入本轮重构的固定尺寸

以下固定尺寸通常是合法的，不应机械删除：

- 1px 分隔线；
- 状态圆点；
- 图标画布和头像；
- 日历日期格；
- 预览图片按比例设置的高度；
- 进度条轨道；
- 抽屉标题栏；
- 纯装饰 summary tile；
- 明确具有独立视觉规格的图标按钮。

判断标准不是“是否出现 fixed”，而是该对象是否参与共享表单交互尺寸契约。

## 5. 目标尺寸契约

### 5.1 令牌必须表示最终外框高度

建议明确：

```text
control_height_sm / md / lg = QWidget 最终可见外框高度
```

建议保留当前自绘控件已经使用的密度基线：

| 尺寸类 | 建议最终外框高度 |
|---|---:|
| `sm` | 26px |
| `md` | 32px |
| `lg` | 38px |

具体数值可在视觉验收时调整，但语义必须唯一。`button_height_md` 不应再和 `control_height_md` 并存为两个竞争的“标准高度”；如果按钮确实需要更高，应命名为明确的视觉规格，而不是复用 `md`。

### 5.2 尺寸指标应结构化

建议新增只读尺寸对象，例如：

```python
@dataclass(frozen=True)
class ControlSizeMetrics:
    outer_height: int
    horizontal_padding: int
    vertical_padding: int
    border_width: int
    icon_size: int
```

每类控件的 QSS 生成器只消费这个对象，不再各自组合 theme 字段。

### 5.3 普通控件和自绘控件必须共享最终高度

必须保证：

```text
QLineEdit(md).height
= QPushButton(md).height
= StyledComboBox(md).height
= StyledSpinBox(md).height
= SearchInput(md).height
= SpacingInput(md).height
```

允许宽度、水平 padding、图标区不同；不允许标准表单行中的垂直外框高度不同。

### 5.4 复合控件不得复制子控件高度令牌

复合控件父容器应遵循：

```text
parent minimum height
= layout margins
+ max(visible child minimumSizeHint.height)
```

父容器不应再次调用 `resolved_control_height()` 固定自己，除非它本身负责绘制统一边框、内部子控件已经被定义为 geometry-neutral editor。

### 5.5 图标按钮必须从文字按钮中拆分

图标按钮的视觉契约应包括：

- `padding: 0`；
- 独立 `icon_button_size`；
- 独立 `icon_button_icon_size`；
- 无文字时不继承 `button_padding_x/y`；
- compact / responsive 切换只切组件 variant，不直接调用 `setFixedSize` 覆盖普通按钮。

### 5.6 `apply_size_class()` 必须可验证

两种可行方向：

1. 保留动态属性方案，但所有参与控件必须使用统一 QSS builder；
2. 由共享基类重写 `sizeHint()` / `minimumSizeHint()`，QSS 只负责绘制，不负责高度。

无论选择哪一种，都必须让 `apply_size_class()` 之后满足：

```python
widget.maximumHeight() >= widget.minimumSizeHint().height()
widget.height() == metrics.outer_height  # 在正常布局后
```

## 6. 建议重构分期

### Phase 0：建立门禁，不改视觉

目标：先让问题可量化，防止迁移过程中继续新增。

新增测试工具：

- `assert_control_geometry_contract(widget)`；
- `assert_children_inside_parent(parent)`；
- `audit_widget_tree_geometry(root)`。

门禁覆盖：

- `maximumHeight >= minimumSizeHint.height`；
- 可见子控件不超出父控件 rect；
- 同一 size class 的标准表单控件高度一致；
- 主题刷新前后高度不漂移；
- 窄屏响应式切换前后没有残留 fixed size。

### Phase 1：统一核心 metrics 和 QSS builder

修改：

- `theme.py`
- `sizing.py`
- `button_style.py`
- `input_metrics.py`
- `input_style.py`

完成标准：

- `md` 只有一个最终外框高度；
- 普通输入框、按钮、ComboBox、SpinBox 的运行时高度一致；
- `resolved_control_height()` 要么删除，要么改为返回结构化 metrics 中的 `outer_height`；
- QSS 不再把同一个 token 同时当内容高度和外框高度。

### Phase 2：迁移共享控件

顺序：

1. `StyledComboBox`
2. `StyledSpinBox`
3. `SpacingInput`
4. `SearchInput`
5. `FolderPicker`
6. `FileDropZone`
7. `FormActionButtonRow`
8. `ParagraphStyleInputs`

迁移后删除各控件内部重复的 min/max 计算。

### Phase 3：拆出图标按钮契约

优先迁移：

- 图片槽位四个操作按钮；
- 附件角色按钮；
- 大图预览按钮；
- Assets 响应式 compact 按钮；
- 时间线复制/删除按钮；
- 其他 30～36px 纯图标按钮。

### Phase 4：迁移高风险页面

顺序：

1. Assets 图片页；
2. Workbench 执行动作区；
3. 标题编号；
4. 题注详情；
5. 模板正文/引用/目录/表格中的 `SpacingInput`；
6. Scene 输入 + 浏览组合；
7. 对话框与低风险页面。

### Phase 5：删除业务层高度补丁

重点删除或收敛：

- 页面级 `normalize_form_control_heights(...)`；
- `min=max` 的表单控件高度同步；
- 响应式路径直接 `setFixedSize(34, 34)`；
- 主题刷新函数重复写 min/max；
- 仅为修复裁切添加的 margin / spacer 补丁。

注意：布局本身需要的间距仍可保留，不能机械删除所有 margin。

## 8. 验收标准

系统性整改完成必须同时满足：

1. 同一 size class 的标准表单控件外框高度一致；
2. `maximumHeight < minimumSizeHint.height()` 的交互控件数量为 0；
3. 可见交互子控件超出父 rect 的数量为 0；
4. Assets 图片页 29 个图标按钮不再套用文字按钮 box model；
5. `StyledSpinBox` 外框高度不小于自身最小尺寸提示；
6. `SearchInput(md)` 高度等于标准 `md`；
7. Workbench 所有条件动作状态均无裁切；
8. 主题切换、窗口缩放、compact 切换后高度不漂移；
9. 不再通过页面 margin 掩盖控件自身高度冲突；
10. 所有例外固定尺寸均有明确组件语义或测试说明。

## 9. 风险与非目标

### 9.1 主要迁移风险

- 控件高度统一后，长表单总高度可能变化；
- FormRow、TemplateFormGrid 和滚动容器的 size hint 会重新计算；
- 快照测试和截图基线可能需要更新；
- 部分页面使用 32px 紧凑密度，直接统一到 40/42px 会显著降低信息密度；
- 直接缩小普通按钮和输入框的内容区时，需要重新检查中文字体基线。

因此应先统一语义，再通过视觉验收决定最终 `md` 是 32、34、36 还是其他值，不能反过来继续用局部像素补丁决定架构。

### 9.2 本轮非目标

- 不重构普通表格高度；
- 不删除合法的装饰性 fixed size；
- 不改变业务功能和信号语义；
- 不同时重构动态列表生命周期；
- 不借本次尺寸整改重新设计所有页面信息架构。

动态列表和滚动容器的高度刷新属于另一条底层链路，参见：

- `docs/audits/动态列表交互与布局刷新底层统一管理深度审计_2026-07-12.md`

两条链路可能共同表现为“控件显示不完整”，但应分别治理：

```text
尺寸契约问题：控件自身或父容器从一开始就太矮
动态布局问题：内容变化后父布局保留旧高度或错误滚动位置
```

## 10. 最终建议

建议将本问题作为独立 UI 基础设施重构处理，而不是继续归入 Assets 页面修复：

```text
P0 统一最终外框高度语义
→ P0 修复普通 QSS box model
→ P0 抽取图标按钮
→ P1 迁移 StyledSpinBox / SpacingInput / SearchInput
→ P1 迁移 Assets 和 Workbench 高风险状态
→ P2 清理标题编号、题注和其他页面级高度补丁
→ 建立真实 Qt 几何门禁
```

只有完成核心 metrics、共享控件和运行时门禁三层收敛，才能避免“修完一个页面，另一个页面或另一个状态再次出现底边裁切”。

## 11. 实施记录（2026-07-12）

### 11.1 尺寸契约已经收敛

本轮确定 `control_height_sm/md/lg` 的唯一语义为“最终 QWidget 外框高度”，当前分别为 `26 / 32 / 38px`。`resolved_control_height()` 不再额外猜测 border；新增 `ControlSizeMetrics` / `control_size_metrics()`，由 QSS 生成器按照：

```text
内容区高度 = 最终外框高度 - 上下 padding - 上下 border
```

反算 `min-height` / `max-height`。因此按钮和输入框即使保留垂直 padding 与 border，最终外框也不会再被二次放大。

已统一的共享层包括：

- `button_style.py`：primary / secondary / danger / ghost 等变体使用同一 box model；
- `input_metrics.py`：普通行编辑器、组合框和数值框使用同一外框语义；
- `styled_spin_box.py`：`sizeHint()` / `minimumSizeHint()` 与尺寸类一致；
- `search_input.py`：补齐 `sm/md/lg` 样式和尺寸提示，`md` 从 20px 收敛为 32px；
- `folder_picker.py`：路径框与浏览按钮均由尺寸类控制，父容器不再用硬高度夹住子控件；
- `icon_button.py`：新增专用图标按钮样式入口，图标按钮不再继承文字按钮的 padding 和内容高度。

组件确实需要脱离标准 `sm/md/lg` 节奏时，必须显式声明最终外框高度：`StyledComboBox` / `StyledSpinBox` 新增 `set_outer_height()`。时间线材料字段通过该 API 声明 40px；模板摘要头部操作按钮显式声明 34px，从而保持 48px 头部节奏。两者都不再依赖旧 box model 的隐式膨胀或主题刷新末尾的覆盖顺序。

`button_height_md` 暂时只作为兼容令牌保留，生产构建器已经不再用它决定按钮外框高度。

### 11.2 高风险业务页面已经迁移

Assets：

- “选图片”页删除顶部最大摘要卡，图片材料卡成为页面首项；

- 29 个图片操作按钮全部迁移到专用 `IconButton` 契约；
- 图片预览、时间线、响应式 compact 状态的图标按钮不再被通用文字按钮 QSS 二次覆盖；
- 批量输出命名、图片对比等原生组合框迁移到 `StyledComboBox`；
- 时间线和字段公式中的原生 `QSpinBox` 迁移到 `StyledSpinBox`；
- 业务面板内用于表单控件的 `setFixedHeight()` 已清零。

Workbench：

- 执行、批量、重试、修复、取消按钮统一使用 `lg` 尺寸类；
- 日志切换按钮统一使用 `sm` 尺寸类；

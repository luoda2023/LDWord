# 高层场景能力矩阵 N2.323 考试题目图片素材库跨包主数据订阅漂移冲突批量失败队列 UI 闭环

日期：2026-06-22

## 1. 本轮目标

N2.323 承接 N2.322 后的明确缺口：批量裁决执行已经可以聚合多个订阅漂移 decision plan 并逐项应用，但当某个主数据键执行失败时，前台还缺少可见、可定位、可处理、可审计的失败队列。本轮把该缺口推进为前台闭环首片。

本轮不声明后台 worker、自动重试调度、并发限流、取消/暂停、失败恢复报告、导出、回滚、二次补偿、SLA 提醒、跨 archive 持久化、历史 Word 输出追溯修复或非题图素材族的订阅漂移批量失败治理完成。

## 3. 链路说明

N2.323 不额外制造第二套失败事实源。失败队列以批量裁决执行审计记录中的 `subscription_drift_batch_decision_result_items` 为准，只展示 `result_status=failed` 且尚未被 recovered/skipped governance 记录关闭的项。

处理后写入的 governance 审计记录使用稳定队列 ID，并保留 batch id、master key、source、asset id、原始失败原因、处理动作和下一步。这样后续恢复报告可以直接从同一事实链路统计：失败多少、恢复多少、人工跳过多少、仍未处理多少。

## 4. 本轮边界

本轮完成的是前台失败队列闭环首片，而不是完整批处理平台。仍未完成：

- 失败恢复报告、导出和 Drilldown；
- 后台 worker、自动重试、指数退避、并发限流、取消/暂停；
- 失败项 SLA、提醒、责任人升级；
- 批量回滚、二次补偿和历史 Word 输出追溯修复；
- 跨 archive 的持久化失败中心；
- 非题图素材族的同类治理。

下一跳应转向 `advanced question asset library cross-package asset master data subscription drift conflict batch failure recovery report UI`，而不是继续把 batch failure queue UI 视作未打通。

# 高层场景能力矩阵 N2.185 考试答题卡固定版式运行时闭环

日期：2026-06-20

## 1. 目标

本轮承接 N2.183 和 V40 的判断：`exam_teaching` 已经有结构化题源 JSON -> Markdown preview -> Word multi-version 的运行时链路，但答题卡固定版式仍被记录为 L5 缺口。这个缺口不能继续停留在“后续再说”，因为答题卡是考试教学的高频交付形态，也是 `TableConfig.row_height_pt` 退出普通模板参数后必须被 fixed-layout profile 承接的关键场景。

N2.185 的目标是闭合一条明确首片：

```text
DeliveryPreset.answer_sheet
-> fixed-layout table runtime
-> Word w:trHeight / w:hRule
-> ExamRenderedVersion fixed_layout evidence
-> JSON/Markdown report
-> fixed-layout profile audit
-> product maturity gap reduction
```

本轮不承诺复杂答题卡版位设计器、自动识别学校答题卡规格、AI 题目质量判断、复杂几何/电路/化学图自动生成，也不引入新的 Word 模板引擎。这些仍分别属于后续 fixed-layout profile 深化、AssetsPanel/结构化资产链路或 plugin/manual boundary。

## 2. Word XML 视角

答题卡固定行高对应 Word 表格行属性：

| 产品参数 | Word/OOXML 对应 | 本轮处理 |
| --- | --- | --- |
| `exam_teaching.answer_sheet.row_height_pt` | `w:trHeight/@w:val` | 22pt -> 440 twips |
| 固定行高策略 | `w:trHeight/@w:hRule` | `exact` |
| 答题区表格 | `w:tbl` / `w:tr` / `w:tc` | 4 列：No.、Question type、Answer area、Score |
| 固定版式归属 | fixed-layout profile | 不回流到普通 `TableConfig.row_height_pt` |

这说明本轮处理的是 Word 本身的固定版式能力，而不是普通表格样式。普通模板管理仍不暴露 `row_height_pt`，避免用户在任意表格样式中误以为行高可以无条件稳定套打。

## 3. 落地链路

### 3.1 Runtime

`src/shared/engine/exam_question_schema.py` 新增/扩展：

- `answer_sheet` preset 会走 `_render_exam_answer_sheet_docx()`；
- 生成固定 4 列答题卡表格，不输出题干、答案和解析；
- 使用 `FixedLayoutRowHeightPolicy` 写入 `w:trHeight=440`、`w:hRule=exact`；
- `ExamRenderedVersion` 记录：
  - `fixed_layout_kind="answer_sheet"`；
  - `fixed_layout_row_count`；
  - `fixed_layout_column_count`；
  - `fixed_layout_row_height_twips`；
  - `fixed_layout_row_height_rule`。

### 3.2 Report

`src/report_writer.py` 已把固定版式字段纳入 `exam_delivery_runtime.rendered_versions`：

- JSON 报告保留结构化字段，便于前台 drilldown 或后续报告浏览器读取；
- Markdown 报告在版本行追加 `fixed_layout=answer_sheet, rows=..., cols=..., trHeight=...`；
- 这让用户可以从报告判断答题卡不是“空版本”或“只隐藏题干”，而是真实写入固定版式表格。

### 3.3 Fixed-Layout Profile Audit

`src/config/scene_fixed_layout_profile_audit.py` 新增 `exam_answer_sheet_fixed_layout_runtime` 通道：

| 审计维度 | 内容 |
| --- | --- |
| coverage | `exam_education` / `exam_teaching` |
| fixed-layout surface | `fixed_row_height`、`answer_sheet_table` |
| OOXML touchpoint | `w:tbl`、`w:tr`、`w:trHeight`、`w:hRule` |
| runtime surface | `_render_exam_answer_sheet_docx`、`apply_fixed_layout_row_height_policy`、`ExamRenderedVersion.fixed_layout_kind` |
| UI surface | `DeliveryPreset.answer_sheet`、`Exam delivery runtime` |
| report surface | `exam_delivery_runtime.rendered_versions.fixed_layout_kind`、`fixed_layout_row_height_twips`、Markdown report |
| repair target | `fixed_layout`、`row_height` |

固定版式 profile 因此从 11/11 ready 扩展为 12/12 ready；`exam_education` 不再只有 ObjectPreflight 风险可见性，而有了运行时写入证据。

## 5. 与模板管理/场景控件一致性的关系

本轮确认一条产品裁决：

- 左缩进、右缩进、段前段后、特殊缩进等段落样式参数，可以在模板管理和场景配置中共享控件语言；
- 行高不同，它在普通表格模板中已经退场，只能在 fixed-layout profile 下作为固定版式参数出现；
- 场景配置如果暴露答题卡行高，必须用 `exam_teaching.answer_sheet.row_height_pt` 这类场景/版式路径，并能追到 `w:trHeight`、报告字段和测试；
- UI 不能把“普通表格行高”和“固定版式答题卡行高”混在同一语义里，否则会重新制造 `TableConfig.row_height_pt` 残留。

这也回应了更高层场景能力矩阵的原则：模板管理提供共享样式语言，场景配置负责业务事实源、交付形态、固定版式风险、报告证据和边界承诺。

## 6. 仍不完整的部分

N2.185 闭合的是固定行高首片，不是完整考试产品：

- 题目图片已经有本地路径运行时首片，但素材替换/预览 UI 仍缺；
- 学科素材质量、答案正确性、难度判断仍属于 plugin/manual boundary；
- 更复杂的答题卡版位，例如准考证号填涂区、选择题网格、条形码区、扫描定位点，需要后续 fixed-layout profile 深化；
- 前台如果要提供答题卡版位设计，应以 fixed-layout profile/preview/repair 进入，而不是复活普通 `TableConfig.row_height_pt`。

# 高层场景能力矩阵 N2.394 发布验收证书闭环

## 目标

N2.393 已经把最终发布摘要中的非满分读数做成 `release_residual_ratio_ledger`。继续向上看，发布态还缺少一个面向验收的总证据：release gate 是绿的、projection 是齐的、closure ledger 是齐的、边界成熟度封套是齐的、残留比例账本也是齐的，但这些仍然分散在多个审计里。

N2.394 新增 `release_acceptance_certificate`。它不是把 Blue/Boundary 主体强行升级为 Green/L5，也不是实现真实专业插件；它只回答一个更高层的问题：当前场景能力矩阵是否已经具备可发布、可解释、可追踪、可导出的验收证据。

## 闭环链路

新增审计模块 `scene_release_acceptance_certificate_audit` 动态读取上述发布组件审计。若未来高频覆盖、projection、closure ledger 或残留治理层新增关键发布组件但证书没有同步更新期望读数，审计会失败；若任意组件审计失败，证书也会失败。

证书本身也必须被发布面接住：

- N2.394 baseline release gate 输出 `high_frequency_coverage=12/12`、`count_delivery_alignment=4/4`、`maturity_l5_alignment=6/6`、`boundary_scope_alignment=6/6`、`acceptance_certificate=12/12` 与 `release_export_scripts=15/15 ready`；N2.400 后当前输出提升为 `acceptance_certificate=14/14` 与 `acceptance_evidence=15/15`；
- dashboard 新增 `release_acceptance_certificate` 卡片，并在相关卡片明细中展示 `4/4 count/delivery boundary links aligned`、`6/6 boundary scopes guarded` 与 `6/6 L5 blockers aligned`；
- drilldown 新增 `Release acceptance certificate`；
- summary projection 在 N2.394 baseline 展示 `12/12 release acceptance certificate`、`4/4 count/delivery boundary links aligned`、`6/6 boundary scopes guarded` 与 `6/6 L5 blockers aligned`；N2.400 后当前展示 `14/14 release acceptance certificate`；
- `release_projection_surface_parity` 从 `12/12` 回填到 `13/13`；
- `release_closure_ledger` 从 `12/12` 回填到 `13/13`；
- CI workflow 纳入 `tests/test_scene_release_acceptance_certificate_audit.py`。

同时，证书审计必须检查自身的 self-surface evidence：导出脚本要包含 JSON/Markdown 输出与 `Certificates ready` 摘要，测试文件要覆盖 release gate payload 与 Markdown 导出，release gate 人类摘要要包含 `acceptance_certificate=`、`acceptance_evidence=` 与 `release_export_scripts=`。这样证书不是只证明别人，也证明自己的发布面没有断链。

## 验收

- `scene_release_acceptance_certificate_audit` 返回 `12/12 ready`、`0 issues`；
- release gate 保持 `passed`；
- dashboard、drilldown、summary、export、workflow、doc 均含证书投影；
- 保留 `count_profiles=14/15`、`delivery_families=14/15`、`maturity_l5_blocked=6/27`，并继续由 N2.393 的 residual ratio ledger 解释。

# 高层场景能力矩阵 N2.293 考试题目图片素材库远端写回批量执行队列 UI 闭环

## 1. 背景

N2.292 已经把远端写回批量事务计划从“缺口”推进为可审阅、可冻结、可防重复的计划 UI。但计划冻结后仍只能定位首项，用户无法从冻结计划直接执行当前 ready 项，也无法得到批量层面的执行摘要。本轮继续收窄剩余边界：先闭合“冻结计划 -> 执行就绪队列 -> 记录批量执行摘要”的首片。

本轮不宣称完整失败队列、后台任务、事务回滚或 report artifact 已完成。它只负责把已冻结计划中的 ready 项按当前状态复核后逐项执行，并把批量执行结果写入审计历史。

## 2. 已闭合能力

- 远端写回批量表在计划冻结且存在 ready 项时，处理列显示“执行队列”和“定位首项”。
- 计划冻结后，下一步列从笼统“计划已冻结”细化为“可执行 N 项”。
- “执行队列”只读取已冻结 plan signature 对应的 `transaction_plan_items`。
- 执行前逐项重新读取当前单项远端写回表状态，避免使用过期冻结快照盲写。
- 仅执行当前仍处于 `待执行写回` 或 `执行失败` 的 ready 项。
- 非 ready 项进入本次批量执行摘要的 skipped 结果，不被强制执行。
- 每个 ready 项复用单项远端写回 connector，不另起批量 HTTP 逻辑。
- 单项执行继续复用原有授权 header、幂等键、retry attempt、权限失败、冲突和失败分类。
- 执行完成后追加 `question_figure_library_remote_writeback_batch_execution` 审计记录。
- 批量执行审计记录包含 plan signature、plan changed_at、候选数、attempted/success/failed/permission/conflict/skipped 计数、状态摘要和 JSON 化 `transaction_result_items`。
- `transaction_result_items` 保存每项的题号、目标、source、asset_id、执行前状态、结果状态、结果分类、endpoint、幂等键、retry attempt、HTTP 状态和执行审计时间。
- 全部尝试项成功且没有跳过时，批量执行记录标记 `transaction_status=executed`；否则标记 `partial` 或 `blocked`。
- 批量执行成功后，已成功单项会从 active batch 候选中退出；若全部候选终局，批量表隐藏。
- 修复远端写回记录来源匹配的秒级碰撞问题：handoff、execution、conflict resolution、snapshot、decision 和 retry attempt 不再只用 `changed_at` 关联来源更新，而是同时校验 `item_id` / `question_index`。
- 新增测试锁定“两条同秒 metadata 更新 -> 两条 handoff -> 冻结计划 -> 执行队列 -> 两条单项执行 + 一条批量执行摘要”的完整链路。

## 4. 仍不宣称完成

- 失败项批量队列 UI 与分组处理；
- 失败队列的单项/批量重试策略；
- 指数退避、后台任务、并发控制和限流；
- 批量事务 manifest/artifact；
- 批量事务报告与 report drilldown；
- 远端批量回滚或本地补偿回滚；
- 已成功项跳过后的恢复/重放策略；
- 幂等窗口管理、重复提交防护中心；
- OAuth/SSO 登录、token 自动续期、签名 URL 自动续签；
- 组织、角色、题库权限申请或审批；
- 跨资料包素材主数据版本系统。

- 场景能力矩阵已经能区分静态闭合、产品成熟度、边界型能力和真实剩余缺口。

本轮 N2.375 进入批量表单/HR/固定版式组，目标是关闭此前剩余的三个高频缺口：

- `batch_forms`：fixed-layout profile browser、exam answer-sheet reuse path。
- `hr_batch_documents`：profile-specific fixed-layout previews。
- `form_batch_documents`：profile browser、answer-sheet reuse path。

## 2. 本轮实现内容

### 2.1 MaterialSchema

`personnel_records_v1` 新增可选字段：

- `fixed_layout_profile_id`
- `profile_preview_manifest`
- `source_row_manifest`

`form_batch_fields_v1` 新增可选字段：

- `fixed_layout_profile_id`

这些字段都是可选字段，不改变原有必填资料校验。它们的作用是让 HR 批量、固定版式表单和答题卡复用能够在资料包里留下可审计的 profile 选择、预览和行高策略痕迹。

- `batch_forms_fixed_layout` 增加 `fixed_layout_profile_browser`、`profile_specific_preview`、`answer_sheet_reuse_path`。

- `batch_forms_hr_missing_fields_manual_boundary` 增加 `profile_specific_preview`。
- `batch_forms_fixed_layout_placeholder_manual_boundary` 增加 `fixed_layout_profile_browser`、`profile_specific_preview`、`answer_sheet_reuse_path`。

这样固定版式 profile 浏览、按 profile 预览、答题卡复用、占位残留、逐记录失败隔离不再只是散落在不同模块里的能力，而是能被 fixture 证据链显式覆盖。

### 2.3 场景概览投影

新增 `build_fixed_layout_batch_evidence_summary_items(scene)`，并接入 `build_scene_overview_summary_items(scene)`。

它会在 `batch_forms`、`hr_batch_documents`、`form_batch_documents` 相关场景中显示：

- schema：`personnel_records_v1`、`form_batch_fields_v1`

这个概览卡的意义是让用户在场景定义页能看到“为什么该场景被判定为可交付”，而不是只看到成熟度颜色。

## 3. Word/OOXML 视角复核

本轮固定版式链路覆盖的 Word 视角：

- 表格固定行高：`w:trHeight`、`w:hRule`
- 内容控件：`w:sdt`
- 文本框：`w:txbxContent`
- 表格网格：`w:tbl` / `w:tr`
- 字段和页眉页脚：用于 HR/固定表单批量替换和风险预检

关键结论：

- `TableConfig.row_height_pt` 不应回到模板管理通用表格配置。
- `form_batch_documents.table.row_height_pt` 作为固定版式 control contract 仍然有效。
- 固定版式 profile browser 和 scene overview 必须解释它关联的是 Word 固定版式风险面，而不是普通表格样式。

## 4. 控件样式一致性要求

场景配置中的 fixed-layout profile 控件需要复用模板管理控件规范：

- profile 选择用同一套 select/combobox 风格。
- profile-specific preview 使用同一套预览、禁用、警告态。
- 行高/固定版式相关提示用 tooltip 和报告证据，不在表格模板 UI 中重新暴露 legacy row height 输入。
- 场景页中的报告/证据卡使用现有 SummaryGridItem 风格，不新增独立视觉体系。

这保证模板管理与场景配置看到的是同一套参数语义：普通模板控件负责通用格式，固定版式控件负责 `w:trHeight` 等 Word 风险面。

## 6. 最终目标

最终目标不是把所有功能点堆到一个页面里，而是建立高层场景能力矩阵的可交付闭环：

1. 每个高频场景都有明确入口和边界。
2. 每个入口能映射到资料 schema、模板/profile、功能开关和输出 preset。
3. 每个关键 Word 风险面都有 OOXML 视角、执行策略、报告证据和测试。
4. 每个 Green/L5 场景都能在 UI 概览、fixture、release gate 和文档中互相证明。
5. 不属于核心能力的专业判断、外部系统治理、AI/OCR/插件能力必须保持边界，不伪装成已完成。

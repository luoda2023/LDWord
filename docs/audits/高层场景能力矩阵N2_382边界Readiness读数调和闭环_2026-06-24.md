# 高层场景能力矩阵 N2.382 边界 Readiness 读数调和闭环

## 目标

N2.382 处理 release gate 中“全部通过但读数不是 100%”的可解释性问题。N2.380 已要求 `maturity_l5_blocked=6/27` 保留，N2.381 已把残留 warning 管理为 `managed_warning`；本轮继续把 `14/15`、`11/12`、`static_closed_but_not_green=2` 这类非满分读数变成显式账本。

核心原则是：不要为了好看把边界读数抹平。只要某个非满分读数来自专业边界、插件/导入边界、业务上不适用的能力面，或者静态闭合但不应声明 Green/L5，就应该登记为 `readiness_delta_reconciliation`，并能追到来源审计、边界守护、dashboard 和 release gate。

## 调和对象

N2.382 管理 15 条非满分读数：

| 类别 | 数量 | 来源 | 调和方式 |
| --- | ---: | --- | --- |
| family readiness delta | 4 | InputSource、CountProfile、ObjectPreflight、DeliveryPreset | `ip_patent_documents` 作为专业审查边界保留 |
| pack readiness/applicability delta | 3 | CountProfile、DeliveryPreset | `quick_formatting` 无场景计数承诺；`import_ai_boundary` 为导入边界 |
| static closed but not Green/L5 | 2 | ProductReadiness | `professional_disclosure` 与 `import_ai_boundary` 静态闭合但保持 Blue/Boundary |
| maturity L5 blocked | 6 | ProductMaturityUpgrade | 6 个 Blue/Boundary subject 均已通过 BoundaryGuardedCompletion |

发布门禁目标值：

- `row_count = 15`
- `reconciled_count = 15`
- `unreconciled_count = 0`
- `not_applicable_count = 2`
- `static_closed_boundary_count = 2`
- `maturity_boundary_guarded_count = 6`

## 为什么不把它们清零

`ip_patent_documents` 不是普通缺口。它可以被场景矩阵识别、路由、生成格式化报告和触发交付链路，但专利权利要求、审查意见、专业法律判断不属于核心格式化能力。因此 InputSource、CountProfile、ObjectPreflight、DeliveryPreset 里的 `14/15` 应解释为专业边界，而不是未做完。

`quick_formatting` 没有场景专属 CountProfile 不是缺口。它是通用格式化入口，不承担论文、期刊、投标、技术长文、表单批处理等场景计数语义，因此 CountProfile pack 行为应是 `not_applicable_count_surface`。

`import_ai_boundary` 是导入/OCR/PDF/LaTeX/AI 转换入口，不是核心格式化引擎内置完整转换质量的承诺。它在 CountProfile 中可不适用，在 DeliveryPreset 中可保持 boundary，并通过 handoff、报告、失败策略和边界能力矩阵说明。

`professional_disclosure` 与 `import_ai_boundary` 的 static closure 是规划闭合，不等于产品 Green/L5。它们应保持 Blue/Boundary，以免对专业判断或外部导入质量过度承诺。

## UI 与产品口径

Dashboard 和场景摘要应同时展示两种事实：

- release gate 已通过，所有非满分读数均被解释；
- 这些 subject 仍不应被包装成 Green/L5 或核心能力完成。

因此 UI 不应把 `14/15`、`11/12` 统一渲染成红色缺口，也不应隐藏它们。正确做法是在 Drilldown 中给出 “Boundary readiness reconciliation” 面板，让用户能看到每个非满分读数的来源、观察到的状态、调和方式和边界证据。

## 闭环要求

N2.382 的验收包括：

- 独立审计模块 `scene_boundary_readiness_reconciliation_audit` 返回 passed。
- 导出脚本支持 JSON 与 Markdown。
- dashboard 新增边界 readiness 调和计数与卡片。
- drilldown 新增 Boundary readiness reconciliation 条目，15 条记录可按来源筛选。
- release gate 输出 `scene_boundary_readiness_reconciliation_count`、`scene_boundary_readiness_reconciliation_reconciled_count` 与 `scene_boundary_readiness_reconciliation_unreconciled_count`。
- CI workflow 纳入对应测试。

后续如果某个非满分读数消失，调和表也必须同步删除对应 spec；如果新增非满分读数，必须先证明它是边界、不适用或真实缺口，不能静默混入通过状态。

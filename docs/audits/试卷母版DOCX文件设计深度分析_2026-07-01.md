# 试卷母版 DOCX 文件设计深度分析

日期：2026-07-01

## 1. 核心判断

试卷母版的 `.docx` 文件必须同时满足两类需求：

```text
用户打开后觉得它是一张正常、专业、可理解的空白试卷。
程序读取后能稳定知道：哪里填标题，哪里填考试信息，哪里插入题目，哪里生成页码。
```

所以它不能只是“看起来像试卷”的 Word，也不能只是“写满字段占位符”的工程模板。

最合理的定义是：

```text
试卷母版 docx = 可编辑的 Word 卷面 + 稳定的装配锚点 + 可校验的母版元数据。
```

## 2. 不能再使用的做法

以下做法都不适合作为正式母版：

- 用 `【试卷标题】`、`【题目内容】` 这类可见调试占位符。
- 在母版里预置 1、2、3、4 道假题。
- 用一堆下划线模拟答题区。
- 运行时临时生成一个空白 Word 当母版。
- 把母版和样张混成同一个文件。
- 让用户修改内置母版原件。

这些做法会让用户误以为：

```text
这就是正式试卷会出现的内容。
```

但实际它只是程序临时造出来的展示物。

## 3. 推荐文件形态

第一阶段建议仍使用 `.docx`，不急着切到 `.dotx`。

原因：

- 现有生成链路已经围绕 `.docx` 工作。
- Python 工具链处理 `.docx` 更直接。
- 用户双击打开、复制、编辑都更容易理解。
- `.dotx` 更像 Office 模板文件，后续可以作为高级导出格式。

推荐目录：

```text
exam_masters/
  builtin/
    default_exam.docx
    compact_exam.docx
  user/
    default_exam_copy.docx
```

推荐配置引用：

```json
{
  "blank_style_id": "default_exam",
  "master_docx_path": "exam_masters/builtin/default_exam.docx",
  "master_kind": "builtin"
}
```

用户副本：

```json
{
  "blank_style_id": "user_default_exam_copy",
  "master_docx_path": "exam_masters/user/default_exam_copy.docx",
  "base_style_id": "default_exam",
  "master_kind": "user"
}
```

## 4. DOCX 内部应分三层

### 4.1 可见卷面层

这是用户打开 Word 后看到的部分。

它应该像正常试卷：

```text
试卷标题

科目：        年级：        考试时间：        满分：
姓名：        班级：        考号：

注意事项
1. 请在规定区域内作答。
2. 保持卷面整洁。

一、题目区
题目将从这里开始。

页脚：第 1 页 / 共 N 页
```

要求：

- 没有 `{{field}}`、`【字段】`、`<<slot>>` 这类技术符号。
- 没有假题。
- 没有大面积灰块。
- 没有奇怪的字段底纹。
- 能直接打印出来给普通用户理解卷面结构。

### 4.2 程序锚点层

这是程序识别和替换用的部分，用户不需要理解。

推荐使用 Word 内容控件，也就是 `w:sdt`：

| 用途 | 推荐 tag |
| --- | --- |
| 试卷标题 | `exam.field.title` |
| 科目 | `exam.field.subject` |
| 年级 | `exam.field.grade` |
| 考试时间 | `exam.field.duration` |
| 满分 | `exam.field.total_score` |
| 姓名 | `exam.field.student_name` |
| 班级 | `exam.field.class_name` |
| 考号 | `exam.field.student_id` |
| 注意事项 | `exam.slot.notice` |
| 题目插入位置 | `exam.slot.questions` |
| 页脚页码 | `exam.footer.page_number` |

内容控件的显示文字可以是自然文案，例如：

```text
试卷标题
科目
题目将从这里开始
```

但程序读取的是 tag，不靠显示文字判断。

如果内容控件实现成本较高，第一阶段可以用书签作为降级方案：

| 用途 | bookmark |
| --- | --- |
| 题目插入位置 | `exam_questions_start` |
| 标题位置 | `exam_title` |
| 注意事项位置 | `exam_notice` |

但最终建议以内容控件为主。

### 4.3 样式契约层

题目装入后不能全靠默认 Normal 样式。

母版应定义一组 Word 样式，程序生成题目时直接使用这些样式：

| 样式名 | 用途 |
| --- | --- |
| `Exam.Title` | 试卷标题 |
| `Exam.Meta` | 考试信息栏 |
| `Exam.Candidate` | 考生信息栏 |
| `Exam.NoticeTitle` | 注意事项标题 |
| `Exam.NoticeText` | 注意事项正文 |
| `Exam.SectionTitle` | 大题标题 |
| `Exam.QuestionStem` | 题干 |
| `Exam.Option` | 选项 |
| `Exam.Score` | 分值 |
| `Exam.AnswerArea` | 答题区 |
| `Exam.Footer` | 页脚 |

这样用户改副本时，不需要理解程序逻辑，只要改 Word 样式，生成效果就会跟着变。

## 5. 推荐页面结构

### 5.1 页面设置

默认试卷：

| 项 | 建议 |
| --- | --- |
| 纸张 | A4 |
| 上边距 | 2.0-2.3 cm |
| 下边距 | 1.8-2.0 cm |
| 左右边距 | 2.0-2.2 cm |
| 正文字号 | 五号或小五 |
| 行距 | 1.15-1.25 |
| 页眉 | 可空，或显示考试名称 |
| 页脚 | 居中页码 |

紧凑试卷：

| 项 | 建议 |
| --- | --- |
| 上下边距 | 略小 |
| 题间距 | 略小 |
| 正文字号 | 不小于小五 |
| 用途 | 题量较多时使用 |

### 5.2 标题区

标题区应当是自然居中的卷面标题，不要出现括号占位。

可见文本：

```text
试卷标题
```

程序锚点：

```text
content_control tag="exam.field.title"
style="Exam.Title"
```

运行时替换为：

```text
七年级语文期中测试
```

### 5.3 考试信息栏

不建议用点线连接：

```text
科目：语文 …… 年级：七年级
```

更稳定的是无边框表格：

```text
| 科目： |      | 年级： |      | 考试时间： |      | 满分： |      |
```

原因：

- Word 中表格对齐比空格和点线稳定。
- 用户调整列宽直观。
- 程序填值不容易把整行撑乱。

每个值单元格放内容控件：

```text
exam.field.subject
exam.field.grade
exam.field.duration
exam.field.total_score
```

### 5.4 考生信息栏

考生信息栏不一定每个场景都要开。

建议母版保留，但场景可以控制显示：

```text
姓名：        班级：        考号：
```

程序锚点：

```text
exam.field.student_name
exam.field.class_name
exam.field.student_id
```

如果工作台不填写这些字段，生成时可以保留空线或隐藏整行。

### 5.5 注意事项区

注意事项区应当是普通文本区，不要当成题目的一部分。

程序锚点：

```text
exam.slot.notice
```

默认可见文案：

```text
注意事项
1. 请在规定区域内作答。
2. 保持卷面整洁。
```

用户可以改注意事项文本，但不要删除 `exam.slot.notice` 锚点。

### 5.6 题目插入区

这是最关键的区域。

母版里应该只有一个清晰的装配槽：

```text
一、题目区
题目将从这里开始。
```

程序锚点：

```text
content_control tag="exam.slot.questions"
```

正式生成时：

- 删除提示文本。
- 把解析后的题目插入到该槽位。
- 插入题目时使用母版里的 `Exam.SectionTitle`、`Exam.QuestionStem`、`Exam.Option` 等样式。

不应该在母版里预置 4 道假题。

### 5.7 答题区

第一阶段不建议在母版里固定大量答题线。

原因：

- 不同题型答题空间差异很大。
- 固定线条容易导致分页难看。
- 正式试卷的答题区应该跟题型或题目配置走。

母版可以只定义答题区样式：

```text
Exam.AnswerArea
```

样张生成时再展示答题区效果。

### 5.8 页眉页脚

页脚建议使用 Word 页码字段，而不是普通文本：

```text
第 { PAGE } 页 / 共 { NUMPAGES } 页
```

程序层需要检查：

- 是否存在页脚。
- 是否存在页码字段。
- 是否只是普通文本。

页眉可选：

- 默认试卷可以不显示页眉。
- 学校场景副本可显示考试名称或学校名称。

## 6. 内容控件 vs 书签 vs 可见占位符

推荐顺序：

1. 内容控件 `w:sdt`
2. 书签 `w:bookmarkStart`
3. 可见占位符

可见占位符只能作为调试或导入兼容，不应作为内置母版方案。

对比：

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 内容控件 | 用户可见自然，程序可读 tag | 需要 XML 级读写 | 推荐 |
| 书签 | 实现相对简单 | 用户容易误删，范围不直观 | 可作为降级 |
| 可见占位符 | 最容易实现 | 不专业，容易误导用户 | 不推荐 |

## 7. 母版元数据

母版文件应带元数据，避免只靠文件名判断。

建议写入自定义属性或隐藏配置块：

```text
lf.master.kind = exam
lf.master.version = 1
lf.master.id = default_exam
lf.master.base = builtin
lf.master.schema = exam_master_v1
```

用途：

- 判断这是不是合法试卷母版。
- 判断母版版本是否过旧。
- 判断用户副本基于哪个内置母版。
- 迁移时可自动升级。

## 8. 用户可改和不可改边界

用户可以改：

- 标题字体、字号、位置。
- 信息栏列宽和显示顺序。
- 注意事项文本。
- 页边距。
- 页眉页脚内容。
- 题目相关 Word 样式。

用户不应该改：

- 删除 `exam.slot.questions`。
- 删除所有必要字段锚点。
- 把题目插入槽放进页眉、文本框或不可编辑区域。
- 把关键样式名全部删除。

程序不应简单禁止用户编辑，而应提供检测：

```text
母版检查：题目插入区缺失，请恢复或重新复制默认母版。
```

## 9. 打开、复制、编辑的正确交互

内置母版状态：

```text
默认试卷    内置
[查看母版] [生成样张] [复制后修改]
```

行为：

- `查看母版`：打开内置母版只读副本，避免误改原件。
- `生成样张`：用内置母版 + 固定示例题生成样张。
- `复制后修改`：复制内置母版到 `exam_masters/user/`，切换到副本。

用户母版状态：

```text
默认试卷 副本    可修改
[打开编辑] [生成样张] [恢复内置]
```

行为：

- `打开编辑`：打开用户副本源文件。
- `生成样张`：用用户副本生成。
- `恢复内置`：当前场景重新指向内置母版，不删除用户文件。

## 10. 母版校验

每次生成样张或正式执行前，都应校验母版。

最低校验：

| 校验项 | 失败后 |
| --- | --- |
| 文件存在 | 提示重新选择或恢复内置 |
| 是合法 docx | 提示文件损坏 |
| 母版元数据存在 | 提示不是试卷母版 |
| `exam.slot.questions` 存在 | 阻断生成 |
| 标题/考试信息字段可定位 | 警告，可继续 |
| 页脚页码可定位 | 警告，可继续 |

更强校验：

- 渲染样张首屏。
- 检查页面非空白。
- 检查标题区没有跑出页面。
- 检查题目区不是在页眉或文本框里。

## 11. 与正式生成器的关系

当前 `exam_question_schema.py` 是从空白 `Document()` 开始生成试卷。

这和母版体系不一致。

后续应改为：

```text
打开当前母版 docx
替换字段内容
定位 exam.slot.questions
清空槽位提示文本
按母版样式插入题目
按答案策略隐藏或输出答案
保存为正式输出
```

也就是说，正式生成器不应该再自己决定标题、正文、页脚的布局。

布局来自母版。

## 12. 分阶段落地

### 第一阶段

- 建立 `exam_masters/builtin/default_exam.docx`。
- 母版内至少包含 `exam.slot.questions`。
- `查看母版` 打开真实母版文件。
- `复制后修改` 复制真实文件。
- `生成样张` 从母版文件生成，而不是从 `Document()` 生成。
- 校验缺失 `exam.slot.questions` 时阻断。

### 第二阶段

- 标题、考试信息栏、注意事项使用内容控件。
- 正式生成时替换字段。
- 题目样式使用母版定义。
- 支持母版校验报告。

### 第三阶段

- 支持用户从已有学校试卷导入为母版。
- 支持母版版本升级。
- 支持答案版不同页眉或不同版式。
- 支持答题卡或密封线等更复杂试卷结构。

## 13. 最终验收口径

最合适的母版 docx 不是“空白 Word 文件”，而是：

```text
用户能看懂的卷面文件
+ 程序能识别的装配槽位
+ 可复制可编辑的长期资源
+ 样张和正式生成都会使用的唯一来源
```

只有做到这一点，用户打开母版时才会相信：

```text
我现在看到和修改的，就是以后生成试卷真正使用的外框。
```

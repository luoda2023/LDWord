# 高层场景能力矩阵 V30 完整场景能力矩阵与准入验收规划（2026-06-19）

本文件继续回答一个更高层的问题：当前功能点仍然不够完整时，怎样规划场景能力矩阵，才能避免高频适用场景遗漏、边界不清晰、以及链路互相没有打通。

V30 的结论是：场景能力矩阵不能再按“场景页里有哪些开关”来判断完善度。完善的矩阵必须能把用户的高频请求映射到明确承载层，并说明它触达哪些事实源、资料 schema、模板控件、Word/OOXML 风险、插件/人工门、输出交付、报告证据和产品成熟度。

## 2. 完整能力的十个准入槽位

每个高频场景族或任务族必须回答以下十个槽位。只要有一个槽位缺失，它就不能被视为完整场景能力。

| 槽位 | 必须回答的问题 | 证据来源 |
| --- | --- | --- |
| 用户请求 | 用户会怎么说，是否有 matched / ambiguous / negative / handoff 样本 | request samples、natural router、request-cell registry |
| 承载层 | 属于 pack、family、profile、schema、preset、plugin 还是 negative | coverage manifest、family registry、task lexicon |
| 事实源 | 数据来自 Word 本体、资料包、结构化 JSON、Excel、外部转换还是人工确认 | MaterialSchema、InputSourceProfile、plugin gate |
| 模板/控件 | 是否复用模板管理的控件语言与参数语义 | control contract registry |
| 场景策略 | 是否有场景 profile、计数 profile、显隐 preset、批量 preset 或交付 preset | scene family、count profile、delivery preset |
| Word 风险 | 是否触达段落、样式、编号、表格、字段、批注、对象、rels、宏等 OOXML 风险 | Word risk closure audit、object preflight |
| 边界状态 | 是否明确专业判断、AI/OCR/LaTeX/法律/财务/IP/医学/翻译等边界 | plugin/manual gate、ambiguous boundary、negative control |
| Handoff | 是否有 source pack、target pack/family、人工状态、报告字段和回退策略 | import handoff audit |
| 证据链 | 是否可追到 fixture、report anchor、release gate、CI 测试 | fixture registry、report writer、release gate |
| 产品成熟度 | 是否只是静态闭合，还是已进入 UI、执行、报告、修复和交付闭环 | product readiness registry、dashboard |

## 3. 高频全集不得遗漏的任务域

V30 不要求把所有任务域都升级成顶层入口，但要求每个高频任务域都有归属和边界。

| 任务域 | 推荐承载 | 必备能力 | 边界 |
| --- | --- | --- | --- |
| 快速排版/套模板 | `quick_formatting` pack | 模板基线、样式清洗、目录/页码/字段保护、报告 | 不替代业务内容判断 |
| 个人文档/简历/陈述 | `quick_formatting` family/profile | 页面样式、版式修复、基础对象预检 | 不生成履历事实 |
| 中文论文/课程论文/开题 | `chinese_academic` + `thesis_cn` | 学校规则源、字数 profile、公式/参考文献、题注、页码 | 学校特规需 rule source |
| 英文投稿/返修 | `english_journal` + `journal_en` | 投稿包、引用、cover letter、response letter、归档 | 期刊特规需外部规则审阅 |
| 试卷/教学材料 | `exam_education` + `exam_teaching` | 结构化题目、答案显隐、多版本、答题卡、复杂图形 gate | 不承诺 AI 题目质量 |
| 标书/资质包 | `bidding_materials` | 证照附件、原件/副本、签章清单、目录归档 | 不验证资质真实性 |

| 技术长文档/SOP/接口验收 | `technical_long_docs` | 长文档结构、对象预检、章节清单、交付包 | 不验证技术真伪 |

| 非 Word 原生交付 | negative / external plugin | 明确拒绝、外部 handoff、替代输出说明 | 不冒充 Word 场景 |

## 4. 边界裁决规则

新增需求不能先问“要不要加一个开关”，而要先按下面顺序裁决：

1. 是否是 Word 文档交付。如果不是，优先 negative 或外部插件。
2. 是否已有稳定用户心智和高频说法。如果没有，先进入规划 family 或 request-cell backlog。
3. 是否与已有 pack 易混。如果易混，必须先补 ambiguous boundary。
4. 是否涉及专业判断、外部识别、AI 生成质量或无损转换。如果涉及，必须进入 plugin/manual gate。
5. 是否能从导入边界交给目标 pack。如果能，必须补 handoff 报告字段和回退策略。
6. 是否需要结构化事实源。如果需要，先补 MaterialSchema / CountProfile / DeliveryPreset，而不是只补 UI。
7. 是否触达固定版式、表格行高、文本框、字段、批注、宏、包关系等 OOXML 风险。如果触达，必须进入 Word risk closure。
8. 是否复用模板管理控件。场景配置不得重新发明左/右缩进、段前段后、特殊缩进、行距、字体、字号、颜色、开关、下拉等控件语义。
9. 是否有 fixture、报告和 release gate。没有证据链就不能升级为完整能力。

## 5. 公式、输出、水印和固定行高的归属

先前暂不处理的公式、输出和水印，不应回流到模板页的杂项参数，而应按场景能力归属：

| 能力 | 归属 | 理由 |
| --- | --- | --- |
| 公式转换/公式图片/公式编号 | 场景能力 + plugin/manual gate | 牵涉 MathML/OMML/图片替换、AI 识别和学科正确性 |
| 输出命名/PDF/ZIP/提交包 | DeliveryPreset / OutputConfig | 属于交付工作流，不是模板外观 |
| 水印/盖章/签章图层 | 场景交付 + 对象预检 | 涉及页眉页脚、DrawingML、关系包和真实性边界 |
| 固定行高 `w:trHeight` | fixed-layout profile / Word risk | 高频出现在表单、证书、批量固定版式，不应作为通用表格模板参数 |

## 6. UI 与控件一致性要求

场景配置页可以根据场景隐藏或组合控件，但不能改变模板管理的控件语言。

必须保持一致的控件族：

- 左缩进/右缩进、段前/段后必须能按同一行语义组合展示；
- 特殊缩进必须提供可交互切换，不能只有只读文本；
- 行距类型与行距值必须绑定，避免用户选了固定值但执行链不消费；
- 表格固定行高只能在 fixed-layout profile 中出现，并说明 Word `w:trHeight` 风险；
- 输出、水印、公式等场景能力必须使用 scene/output/plugin 的控件契约，不混进模板外观参数。

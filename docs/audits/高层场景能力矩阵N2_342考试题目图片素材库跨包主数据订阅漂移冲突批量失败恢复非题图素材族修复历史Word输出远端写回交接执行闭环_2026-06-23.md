N2.341 已经把 `.header-footer-rewrite.docx` 接管为 adopted historical DOCX，并完成第二轮 Word XML/media 验证。本轮 N2.342 继续补上 repaired historical Word output remote writeback handoff execution：adoption 完成后前台出现 `Writeback`，把 adopted repaired DOCX 封装成正式输出/远端写回交接包，生成 writeback manifest，记录幂等键、冲突策略、远端 connector 待执行状态，并把 formal output/handoff path 回写到素材族 metadata。

## 2. 新增能力

- 新增 action：`asset_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_non_question_asset_family_repaired_historical_word_output_remote_writeback_handoff_execution`。
- 非题图素材族链路推进为：`Record -> Execute -> Verify -> Rewrite -> Adopt -> Writeback -> Manifest`。
- Writeback handoff 消费 adoption record 的 adopted DOCX 路径，不再回读原始 stale historical DOCX。
- 对 adopted DOCX 再次执行 Word XML/media scan，只有 `xml_media_consistent` 且文件可读时才生成 `writeback_handoff_prepared` row。
- 对每个正式输出 DOCX 生成稳定 idempotency key，作为后续远端 connector、重试、冲突裁决的输入。
- 生成 JSON/Markdown manifest，记录 handoff docx count、verified docx count、idempotency key count、conflict policy 和 pending connector 状态。
- metadata 回写 `formal_output_docx_path(s)`、`remote_writeback_handoff_docx_path(s)`、writeback status、manifest path、idempotency keys 和 next step。
- 修复 entry manifest 优先级：当前阶段 manifest 优先级为 `writeback -> adoption -> rewrite -> verification -> execution -> governance`，避免旧 manifest 覆盖新阶段证据。

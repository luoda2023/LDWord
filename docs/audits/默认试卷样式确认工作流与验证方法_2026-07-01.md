# 默认试卷样式确认工作流与验证方法

日期：2026-07-01

## 1. 当前问题

现在 `试卷装配` 页已经能选择 `默认试卷`，但用户仍然无法回答一个关键问题：

```text
这个默认试卷到底长什么样？
我怎么知道它能不能直接用？
```

当前页面只提供了一个下拉值和实时摘要，缺少三件事：

- 可见样式：用户看不到默认试卷的实际卷面。
- 可验证样张：用户不能生成一份样例 Word 来检查。
- 可修改路径：用户不知道默认样式不满意时应该在哪里复制、调整和回退。

因此，`默认试卷` 不能只作为一个下拉选项存在，它必须有一条确认工作流。

## 2. 核心判断

默认试卷样式应当是试卷场景的内置能力，而不是要求普通用户先去模板管理理解底层模板。

合理的用户认知应是：

```text
试卷场景自带默认卷面。
我可以先预览，满意就直接用。
不满意就复制一份再改。
每次真正生成试卷时，只需要回到工作台填写本次考试信息。
```

底层可以继续复用模板文件或 Word 样式，但用户入口应该留在 `试卷装配` 中。

## 3. 完整用户工作流

### 3.1 第一次使用内置默认试卷

入口：

```text
场景配置 -> 试卷-默认 -> 试卷装配
```

用户看到：

```text
空白试卷样式：默认试卷
状态：内置，可直接使用
动作：预览样式 / 生成样张 / 复制后修改
```

用户操作：

1. 点击 `预览样式`。
2. 页面展示一份固定样例卷面。
3. 用户检查标题区、考试信息栏、题目区、页眉页脚、页码和留白。
4. 如果满意，点击 `确认使用` 或直接 `去工作台填写`。
5. 如果不满意，点击 `复制后修改`。

结果：

```text
默认试卷样式被确认为当前场景样式。
场景仍然只保存长期装配规则，不保存某一次考试的标题和科目。
```

### 3.2 用户想看真实 Word 效果

入口仍在 `试卷装配` 页。

用户操作：

1. 点击 `生成样张`。
2. 系统使用内置示例题目生成一份 Word 样张。
3. 用户打开 Word 样张检查打印效果。
4. 用户回到场景页确认使用或复制修改。

结果：

```text
用户能用真实 Word 文件确认默认试卷是否符合学校/个人使用习惯。
```

### 3.3 默认样式不满意时

用户操作：

1. 点击 `复制后修改`。
2. 系统从内置默认样式复制出一份用户样式。
3. 新样式自动命名，例如 `默认试卷 副本`。
4. 当前场景自动切换到这份副本。
5. 用户进入样式编辑。
6. 保存后再次预览或生成样张。

关键防呆：

- 内置默认样式不可被直接覆盖。
- 修改前必须复制。
- 用户样式可以删除、重命名、恢复默认。
- 改坏后可重新选择 `默认试卷`。

结果：

```text
用户能改样式，但不会破坏内置默认样式。
```

### 3.4 每次生成正式试卷

入口：

```text
工作台 -> 选择试卷场景
```

工作台展示：

```text
当前试卷样式：默认试卷
题目装配：按 Markdown 标题识别
答案处理：学生卷 + 答案版
本次需要填写：标题、科目、年级、考试时间、满分
```

用户操作：

1. 导入 Markdown 或 Word 题稿。
2. 填写本次考试信息。
3. 查看题目识别预览。
4. 点击生成。

结果：

```text
工作台用场景中确认过的试卷样式生成本次试卷。
```

### 3.5 用户动作与验证对应关系

这条链路不能只验证配置是否存在，还要验证用户每一步看到的东西都能落到真实产物。

| 用户动作 | 用户想确认什么 | 程序验证方法 | 通过标准 |
| --- | --- | --- | --- |
| 进入 `试卷装配` | 默认试卷是否已经可用 | 读取场景默认配置和样式注册表 | 当前样式显示为 `默认试卷`，状态不是缺失 |
| 点击 `预览样式` | 卷面长什么样 | 渲染固定示例预览 | 标题区、信息栏、题目区、页眉页脚可见 |
| 切换学生卷/答案版 | 答案会不会暴露 | 预览模型和渲染结果检查 | 学生卷隐藏答案，答案版显示答案 |
| 点击 `生成样张` | Word 打开后是否也正确 | 生成固定样例 `.docx` 并解析/渲染 | Word 可打开，第一页非空白，结构与预览一致 |
| 点击 `复制后修改` | 不满意时能否安全改 | 创建用户样式副本并切换当前场景 | 内置默认样式不变，当前样式变成副本 |
| 点击 `恢复默认` | 改坏后能否回退 | 将场景样式重新指向内置默认 | 当前样式回到 `default_exam` |
| 点击 `去工作台填写` | 正式生成是否用同一套样式 | 工作台读取同一场景配置 | 工作台显示同一试卷样式和同一组本次填写字段 |
| 导入题稿并生成 | 最终产物是否可信 | 用固定 Markdown 题稿端到端生成 | 输出 Word 的卷面结构与样式预览一致 |

## 4. 试卷装配页建议结构

建议把 `空白试卷样式` 从单纯下拉升级为带动作的样式选择区。

```text
试卷装配

空白试卷样式
[ 默认试卷                         v ]  [预览样式] [生成样张] [复制后修改]
内置样式，可直接使用。不会被用户修改覆盖。

题目装配
[ 按 Markdown 标题识别             v ]

答案处理
[ 学生卷 + 答案版                  v ]

工作台填写
[标题] [科目] [年级] [考试时间] [满分] [班级] [命题人] [日期]

当前会使用“默认试卷”，按 Markdown 标题识别，生成“学生卷 + 答案版”；
工作台会填写：标题、科目、年级、考试时间、满分。

[恢复默认] [去工作台填写]
```

### 4.1 预览样式

`预览样式` 不应该只是打开模板管理页。

更合理的是在当前页或弹窗中展示一份试卷样式预览：

- A4 页面比例。
- 标题区。
- 考试信息栏。
- 注意事项。
- 题目区占位。
- 页眉页脚和页码。
- 学生卷/答案版切换。

预览内容使用固定示例，不使用用户真实题稿。

### 4.2 生成样张

`生成样张` 用固定示例题目输出 Word。

样张应该包含：

- 试卷标题。
- 科目、年级、考试时间、满分。
- 至少 2 个大题。
- 至少 4 个小题。
- 选择题、填空题、解答题各至少一个。
- 学生卷隐藏答案。
- 答案版显示答案。

样张不是正式输出，不进入最近结果。

### 4.3 复制后修改

用户点击 `复制后修改` 后，系统应做：

```text
复制默认试卷样式 -> 生成用户样式 -> 切换当前场景到用户样式 -> 打开编辑入口
```

编辑入口第一阶段可以很轻：

- 标题区是否显示。
- 信息栏字段顺序。
- 页眉页脚是否显示。
- 题目区起始位置。
- 字体大小。
- 行距。
- 页边距。

复杂 Word 卷面导入可以作为后续阶段。

## 5. 状态模型

建议为样式选择区提供三个用户可见状态。

| 状态 | 用户含义 | 是否阻断执行 |
| --- | --- | --- |
| 可直接使用 | 内置默认样式存在并通过基础检查 | 不阻断 |
| 已预览 | 用户打开过预览或样张 | 不阻断 |
| 需要处理 | 样式缺失、样张生成失败或缺少题目区 | 阻断或提醒 |

不建议强制每个用户必须点击 `确认使用` 才能执行。

原因：

- 内置默认样式应开箱可用。
- 强制确认会增加普通用户负担。
- 更合理的是给用户可见、可验证、可回退的路径。

## 6. 验证方法

### 6.1 配置层验证

目标：确认默认试卷样式确实存在，并且可以从场景配置追踪到。

验证点：

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 默认样式存在 | 单元测试读取样式注册表 | `default_exam` 可解析 |
| 场景默认绑定 | 构造 `create_exam_scene()` | `exam_paper.blank_style_id == "default_exam"` |
| 内置样式不可覆盖 | 保存用户样式时检查来源 | 内置样式只读 |
| 缺失样式降级 | 删除或模拟缺失样式 | UI 显示需要处理，不静默失败 |

建议测试名：

```text
test_exam_default_blank_style_is_registered
test_exam_scene_binds_default_blank_style
test_builtin_exam_style_is_readonly
test_missing_exam_style_reports_user_action
```

### 6.2 UI 交互验证

目标：确认用户能在 `试卷装配` 页完成确认动作。

验证点：

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 样式动作可见 | PySide 面板测试 | 看到预览样式、生成样张、复制后修改 |
| 下拉切换更新摘要 | 修改 `blank_style_id` | 实时摘要同步显示新样式 |
| 复制后修改切换场景 | 点击复制后修改 | 当前样式变成用户副本 |
| 恢复默认可用 | 点击恢复默认 | 样式回到 `default_exam` |
| 去工作台返回点正确 | 点击去工作台填写 | `return_card_id == "scn_exam_paper"` |

建议测试名：

```text
test_exam_paper_detail_exposes_style_confirmation_actions
test_exam_paper_style_preview_action_is_available
test_exam_paper_style_copy_switches_to_user_style
test_exam_paper_restore_default_style
test_exam_paper_workbench_navigation_returns_to_detail
```

### 6.3 预览渲染验证

目标：确认用户看到的预览和最终生成逻辑一致。

验证点：

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 预览非空 | 渲染预览图或预览组件截图 | 页面区域非空白 |
| 关键区域存在 | 检查预览模型 | 标题区、信息栏、题目区、页脚存在 |
| 学生卷隐藏答案 | 切换学生卷预览 | 答案文本不显示 |
| 答案版显示答案 | 切换答案版预览 | 答案文本显示 |
| 预览和样张同源 | 预览与样张使用同一示例数据 | 文案和结构一致 |

建议测试名：

```text
test_exam_style_preview_contains_required_regions
test_exam_style_preview_student_version_hides_answers
test_exam_style_preview_answer_version_shows_answers
test_exam_style_preview_and_sample_docx_share_fixture
```

### 6.4 Word 样张验证

目标：确认 `生成样张` 产物可打开、可检查、可打印。

验证点：

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 样张生成成功 | 调用样张生成器 | 输出 `.docx` |
| Word 可解析 | 用文档解析工具读取 | 没有打开错误 |
| 页面元素存在 | 解析段落或渲染页面 | 标题、信息栏、题目区存在 |
| 学生卷隐藏答案 | 读取学生卷文本 | 不包含答案段落 |
| 答案版显示答案 | 读取答案版文本 | 包含答案段落 |
| 渲染不空白 | 渲染首屏 PNG | 页面非空白且主体在可见区域 |

建议测试名：

```text
test_exam_default_style_sample_docx_is_generated
test_exam_sample_docx_contains_exam_header
test_exam_student_sample_docx_hides_answers
test_exam_answer_sample_docx_shows_answers
test_exam_sample_docx_renders_nonblank_first_page
```

### 6.5 工作台端到端验证

目标：确认用户在场景页确认样式后，工作台会使用同一套样式生成正式试卷。

验证点：

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 工作台显示当前样式 | 进入工作台 | 显示 `默认试卷` 或用户样式名 |
| 本次字段来自场景 | 查看工作台表单 | 字段与 `runtime_fields` 一致 |
| 导入 Markdown 后识别题目 | 使用固定题稿 | 大题、小题、分值被识别 |
| 正式输出用所选样式 | 生成试卷 | 输出结构与样式预览一致 |
| 修改样式后生效 | 切换用户样式再生成 | 输出使用新样式 |

建议测试名：

```text
test_workbench_exam_summary_uses_selected_blank_style
test_workbench_exam_runtime_fields_follow_scene_config
test_workbench_exam_markdown_fixture_is_assembled
test_workbench_exam_output_uses_selected_style
```

## 7. 实现边界

### 第一阶段必须做

- `试卷装配` 页显示默认样式状态。
- 提供 `预览样式`。
- 提供 `生成样张`。
- 提供 `复制后修改`。
- 预览和样张使用同一份固定示例题稿。
- 工作台显示当前试卷样式。

### 第一阶段不做

- 不做题图。
- 不做 AI 出题。
- 不做查重。
- 不做答题卡。
- 不做复杂学校 Word 卷面导入。
- 不要求用户进入模板管理。

## 8. 最终验收口径

默认试卷样式确认链路完成后，普通用户应该能做到：

```text
打开试卷场景 -> 看到默认试卷已可用 -> 预览样式 -> 生成样张确认 Word 效果 -> 去工作台填写本次信息 -> 生成正式试卷
```

高级用户应该能做到：

```text
复制默认试卷样式 -> 修改副本 -> 生成样张验证 -> 保存为当前场景样式 -> 工作台使用该样式生成试卷
```

程序验收必须同时满足：

- 配置可追踪。
- UI 可操作。
- 预览可见。
- 样张可生成。
- 工作台端到端使用同一份样式。

只有这五个条件都满足，`默认试卷` 才不只是一个下拉选项，而是一个用户能确认、能信任、能继续使用的试卷样式。

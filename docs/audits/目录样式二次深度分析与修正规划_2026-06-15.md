# 目录样式二次深度分析与修正规划（2026-06-15）

## 1. 这次反馈指出的核心问题

本轮目录页优化里，有三个方向判断错误：

1. **把实现概念暴露成用户选项**
   “目录共享样式”是底层 fallback 机制，不是用户自然理解的目录对象。用户真正要调的是“目录标题”“一级目录”“二级目录”“三级目录”等可见结果；共享基准最多只能存在于内部，不应该作为左侧第一个可编辑角色占位。

2. **用静态样例冒充预览**
   当前预览写死为“第一章 绪论 / 1.1 研究背景 / 1.1.1 国内外现状”。它既不来自真实文档，也不跟随当前目录深度变化。截图里目录深度为 4 级，但预览只有 3 级，这会直接制造错误信号。更关键的是，这不是实时预览，而是装饰性样例。

3. **用说明文本填补产品结构缺口**
   “目录联动”卡把标题收录、页码策略等信息解释出来，但它没有提供操作，也没有形成更好的目录结果判断。它占据了页面空间，却把用户带回工程配置解释，而不是完成目录样式编辑任务。

结论：目录页的问题不是“缺少更多说明”，而是需要更准确地区分哪些信息应该出现在主工作流里，哪些只能在真实预览或诊断场景中出现。

## 2. 为什么“目录共享样式”不应该是一个选项

目录样式内部确实存在 `styles.toc` 作为共享 fallback，但这类概念更适合放在代码里，而不是 UI 里。

用户看到“目录共享样式”会产生几个疑问：

- 它和“目录标题样式”是什么关系；
- 它是否会覆盖一级、二级、三级目录；
- 调了共享样式后，之前单独设置过的级别会不会变；
- 为什么它排在所有真实目录条目前面。

这些问题都说明它不是一个清晰的用户对象。

更合理的 UI 角色应只保留可见结果：

- 目录标题样式；
- 一级目录样式；
- 二级目录样式；
- 三级目录样式；
- 后续如果支持 4-6 级，再按目录深度动态出现。

“跟随正文”可以作为每个角色的默认状态和恢复动作，但不应独立成一个可编辑角色。这样用户心智会更直接：我正在编辑某一种会出现在目录里的文本。

## 3. 为什么当前静态预览不成立

当前静态预览至少有四个问题。

第一，它不是实时数据。
目录真实内容取决于当前文档的标题识别结果、标题编号、目录模式、目录深度和实际页码。静态写死的“第一章 绪论”无法反映这些信息。

第二，它和目录深度脱节。
当目录深度选择 4 级、5 级或 6 级时，预览仍然只显示到三级，用户会误以为设置没有生效，或者误以为系统最多只支持三级样式。

第三，它的结构不一定合理。
“第一章 绪论 / 1.1 研究背景 / 1.1.1 国内外现状”是一种论文式结构，但模板可能用于技术文档、投标文件、简历、报告或其它材料。固定样例会把模板对象误导成某一种文档类型。

第四，它只展示形态，不展示 Word 目录真实机制。
Word 自动目录最终由 TOC 域、标题样式、页码刷新共同决定；普通目录则由程序收集标题并重建。静态 QLabel 无法表达制表位、页码对齐、字段刷新和真实分页这些核心差异。

因此，在没有真实文档上下文时，目录页不应放“目录预览”。如果未来要做预览，应满足最低条件：

- 预览数据来自当前文档或一个明确选择的样本文档；
- 层级数量跟随目录深度；
- 样式渲染跟随当前角色设置；
- 普通目录和 Word 自动目录的差异可被明确表达；
- 不能有解释性占位文案替代真实结果。

## 4. 为什么“目录联动”卡应该删除

目录页当然和标题编号、页码策略有关，但“联动卡”不是合适的呈现方式。

它的问题在于：

- 信息是解释性的，不是操作性的；
- 它把用户从“调整目录样式”带回“理解系统依赖”；
- 它和预览一样容易在没有真实文档时变成猜测；
- 它增加了页面层级，让目录页重新变重。

跨模块信息更适合在这些场景出现：

1. **真实预览中出现异常时**
   例如某一级没有进入目录，应在预览对应位置提示“该级标题被标题编号排除”。

2. **执行前诊断中出现风险时**
   例如目录页页码被排除、页码分组不覆盖目录页，这应进入诊断/校验，而不是常驻编辑表单。

3. **用户正在配置相关模块时**
   标题编号页配置 `include_in_toc`，页眉页脚页配置目录页页码，这些模块应承担自己的解释。

所以目录样式页当前应该删除“目录联动”卡，只保留真正服务当前任务的控件。

## 5. 修正后的当前边界

当前目录页应先收敛为三个区域：

```text
顶部摘要卡
目录结构
目录样式
```

目录结构只处理：

- 是否启用目录；
- 目录模式；
- 目录深度；
- 插入位置。

目录样式只处理：

- 样式预设；
- 目录标题样式；
- 一级目录样式；
- 二级目录样式；
- 三级目录样式。

不再显示：

- 目录共享样式角色；
- 静态目录预览；
- 预览说明文本；
- 目录联动说明卡。

这样页面虽然少了一些“看起来丰富”的内容，但主任务会更干净。

## 6. 后续真正值得做的方向

### 6.1 按目录深度动态呈现样式级别

截图里目录深度为 4 级，但样式只显示到三级。这是比静态预览更真实的问题。

下一步应该考虑：

- 目录深度为 1 时，只显示一级目录样式；
- 目录深度为 3 时，显示一级到三级；
- 目录深度为 4-6 时，显示对应级别样式；
- 如果底层执行暂时只支持三级样式，需要明确补齐执行层，而不是 UI 假装支持。

这比做静态预览更重要，因为它直接决定用户能不能配置当前选择的目录深度。

### 6.2 预设应该是动作，不是解释

样式预设可以保留，但它应当只是一键写入当前可见角色样式：

- 跟随正文；
- 学位论文目录；
- 技术文档目录；
- 紧凑目录。

预设不应该引入新的说明卡，也不应该生成“共享样式”这种不可见角色。应用后用户可以直接在当前角色 Inspector 中看到字段变化。

### 6.3 真实预览需要独立设计

真正的目录预览不是一张 UI 卡就能解决，它至少需要接入文档结构。

推荐未来设计为：

```text
目录预览（仅在有文档上下文时出现）
├─ 当前文档标题树
├─ 按目录深度裁剪
├─ 应用当前目录样式
├─ 显示真实/估算页码状态
└─ 标注被排除或无法解析的标题
```

没有文档上下文时，不显示预览，而不是显示静态样例。

### 6.4 跨模块联动应进入诊断系统

标题编号和页码策略确实影响目录，但它们不应该常驻在目录样式编辑页中。

更合理的方式是：

- 执行前诊断：报告目录页页码是否覆盖、标题层级是否缺失；
- 文档预览诊断：在真实目录预览中标注“某级被排除”；
- 模块跳转：必要时提供跳到标题编号或页眉页脚的入口。

这样既保留系统透明度，又不会让目录页变成说明面板。

## 8. 判断标准

目录页后续改动应遵守三个标准：

1. **不展示假预览**：没有真实文档上下文，就不要放目录结果预览。
2. **不暴露底层 fallback 对象**：共享样式可以存在于模型里，但不作为用户编辑对象。
3. **不靠说明文本补产品结构**：如果某条说明不能转化为操作、诊断或真实结果，就不应该常驻在编辑页里。

这一次的关键结论是：目录页应该先变少、变准，再考虑变丰富。

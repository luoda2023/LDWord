# 高层场景能力矩阵 N2.322 考试题目图片素材库跨包主数据订阅漂移冲突批量裁决执行闭环
日期：2026-06-22

## 本轮定位

N2.321 已经把单项字段合并裁决执行补齐：`alt_text` 与 `reference` 可以按字段选择本地或远端来源，并形成独立审计。本轮 N2.322 继续处理上一轮留下的明确缺口：当多个跨包主数据订阅漂移冲突已经完成 queue、triage、decision plan，且尚未执行基础裁决时，前台需要一个批量入口统一执行这些 planned decision，而不是要求用户逐条点击。

本轮只承诺“批量成功路径 + 批量审计首片”：它把多个待执行基础裁决聚合为一个批次，复用现有单项裁决执行逻辑逐项写回 metadata，并额外生成批量执行审计记录。它不声明批量失败队列、后台 worker、失败重试、回滚、二次补偿、SLA、提醒或跨 archive 持久化已经完成。

## 已闭合内容

- 新增 `question_figure_asset_library_master_subscription_drift_batch_decision_execution_table`。
- 批量表从当前 archive 内所有尚未执行的 `question_figure_library_cross_package_master_subscription_drift_conflict_decision_plan` 反推批次。
- 表格展示批次、计划数、接受远端字段、保留本地字段、状态和处理动作。
- 提供“批量执行”和“定位首项”两个前台动作。
- 批量执行逐项复用 `question_figure_library_cross_package_master_subscription_drift_conflict_decision_execution` 单项执行记录，避免绕过已有字段写回与幂等逻辑。
- 新增批量审计 action：`question_figure_library_cross_package_master_subscription_drift_conflict_batch_decision_execution`。
- 批量审计记录包含 batch execution id、connector、计划数、成功数、失败数、跳过数、master keys、source/asset pairs、result items JSON 与 next step。
- metadata 新增 `master_subscription_drift_batch_decision_*` 字段，记录批量执行状态、批次 id、执行时间、计划数、成功/失败/跳过计数。
- 批量成功后基础裁决表与批量裁决表退场；字段合并表仍可继续展示待人工合并字段，边界不混淆。
- `scene_product_readiness` 在 `pack:exam_education` 与 `family:exam_teaching` 新增 per-question asset library cross-package master subscription drift conflict batch decision execution UI evidence。
- 成熟度 gap 从 `advanced question asset library cross-package asset master data subscription drift conflict batch decision execution UI` 收敛为 `advanced question asset library cross-package asset master data subscription drift conflict batch failure queue UI`；家族口径同步收敛为 `advanced asset library cross-package asset master data subscription drift conflict batch failure queue UI`。

## 边界说明

本轮后仍不伪装完成：

- 批量执行中的失败队列、权限失败队列、冲突失败队列；
- 后台执行 worker、暂停、取消、并发、限流、指数退避与失败重放；
- 批量裁决失败后的回滚、补偿清单、二次补偿与字段合并回滚；
- 队列 SLA、提醒、优先级人工调整、跨 archive 持久化；
- 历史 Word 输出追溯修复；
- 非题图素材族的订阅漂移批量裁决执行。

下一轮高优先缺口应转向“batch failure queue UI”：当批量执行出现失败、权限不足、冲突或部分跳过时，需要前台可筛选、可定位、可重试、可升级处理的失败队列，而不是继续把批量执行入口列为未打通。

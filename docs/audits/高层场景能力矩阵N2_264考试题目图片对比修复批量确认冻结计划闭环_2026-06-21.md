# 高层场景能力矩阵 N2.264 考试题目图片对比修复批量确认冻结计划闭环

## 1. 本轮定位

N2.263 已经把题图修复队列推进到“批量确认预检计划”：系统能区分 eligible、blocked、conflict 和 duplicate target。N2.264 补的是执行前的二次确认与计划冻结契约：在真正进入未来批量执行之前，必须把当时的 eligible 集合、计划指纹、确认人、确认时间和阻断边界固定下来。

本轮仍不执行批量替换，不批量写回 Word，不提供事务回滚。它只把“可以进入批量执行前确认的候选集合”冻结成可审计 payload。

## 2. 已实现能力

- `batch_confirmation_plan` 新增 `plan_fingerprint`。
- 新增 `_freeze_question_figure_repair_batch_confirmation_plan()`：
  - 输入当前 `question_figure_repair_queue`；
  - 可选 `selected_queue_ids`；
  - 必须显式传入 `confirmed=True` 才能冻结；
  - 可传入 `expected_plan_fingerprint`，用于检测前台看到的计划是否已经过期；
  - 返回 queue 副本，并写入 `batch_confirmation_freeze`。
- `batch_confirmation_freeze` 契约包含：
  - `kind=question_figure_repair_batch_confirmation_freeze`
  - `action=freeze_question_figure_repair_batch_confirmation_plan`
  - `status=not_confirmed|blocked|frozen|partial_frozen`
  - `confirmed`
  - `confirmed_by`
  - `confirmed_at`
  - `confirmation_note`
  - `plan_fingerprint`
  - `expected_plan_fingerprint`
  - `fingerprint_matched`
  - `requested_queue_ids`
  - `frozen_queue_ids`
  - `frozen_candidate_count`
  - `frozen_target_count`
  - `blocked_count`
  - `conflict_count`
  - `duplicate_target_count`
  - `blocked_queue_ids`
  - `conflict_queue_ids`
  - `eligible_queue_ids`
  - `frozen_entries`
  - `excluded_eligible_queue_ids`
  - `blockers`
  - `batch_apply_supported=false`
  - `execution_plan_ready`
- 未确认时返回 `status=not_confirmed`，并写入 `manual_confirmation_required`。
- 前台传入过期 fingerprint 时返回 `status=blocked`，并写入 `plan_fingerprint_mismatch`。
- 指定了不在 eligible 集合中的 queue id 时返回 `selected_queue_id_not_eligible` 和 `invalid_queue_ids`。
- 若成功冻结但队列仍有 blocked/conflict/duplicate 或只冻结 eligible 子集，则状态为 `partial_frozen`。
- batch Markdown report 在存在冻结 payload 时新增 `Batch confirmation freeze` 摘要。
- Workbench artifact detail 在存在冻结 payload 时新增：
  - `freeze=<status>`
  - `frozen=<n>`
- `scene_product_readiness` 为 `pack:exam_education` 和 `family:exam_teaching` 新增 `question asset comparison repair queue batch confirmation freeze bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`question_figure_repair_queue.entries[]` -> `batch_confirmation_plan` -> `plan_fingerprint` -> 显式人工确认 -> `batch_confirmation_freeze` -> batch Markdown report -> Workbench artifact detail -> product readiness evidence -> tests/release gate

这使未来的批量执行不再直接消费一个可变的 queue，而是可以先要求前台确认某个 fingerprint 对应的候选集合。若队列变化导致 fingerprint 不一致，冻结会阻断。

## 4. 明确不宣称完成

- 不做批量替换执行。
- 不做批量写回 Word。
- 不做批量事务回滚。
- 不做自动候选优先级排序。
- 不做完整候选对比选择器。
- 不做图像内容质量判断。
- 不绕过 conflict/blocked 候选。

当前能力只承诺：显式确认后可以冻结一组 eligible 候选，且冻结结果可报告、可审计、可被后续执行前校验。

## 5. 验收锚点

- `test_question_figure_repair_batch_confirmation_plan_summarizes_queue`
  - 断言 `batch_confirmation_plan` 包含 `plan_fingerprint`。
- `test_question_figure_repair_batch_confirmation_freeze_requires_confirmation`
  - 断言未确认时不能冻结；
  - 断言 fingerprint mismatch 会阻断；
  - 断言 confirmed 且 fingerprint 匹配时冻结 eligible 候选；
  - 断言 invalid queue id 不会进入冻结集合；
  - 断言 Markdown report 暴露 `Batch confirmation freeze`。
- `test_question_figure_repair_queue_resolves_selected_conflict_candidate`
  - 断言冲突裁决后新计划仍带 fingerprint。
- `test_execution_adapter_exposes_question_figure_repair_queue_artifact`
  - 断言 Workbench artifact detail 暴露 `freeze` 和 `frozen`。
- `test_product_maturity_upgrade_audit_maps_every_subject_to_l5_blockers`
  - 断言 exam pack/family 包含 batch confirmation freeze evidence。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.263 的“批量确认预检计划桥”推进到 N2.264 的“批量确认冻结计划桥”。这一步把“计划可见”进一步收紧为“计划可确认、可冻结、可用 fingerprint 校验”。

仍保留的高级素材库边界包括：真实素材库 API 登录/续期/签名与授权续期、跨资料包后台定时清理、后台全局任务中心、断点续传/后台队列/并发下载调度、跨资料包长期命中率趋势中心、真实素材库预览服务/签名预览 URL 续期、自由框选/多区域标注图层编辑、完整候选对比选择器、自动候选优先级策略、批量确认执行、批量/事务回滚、内容级错图识别、复杂学科图或 AI 质量判断。

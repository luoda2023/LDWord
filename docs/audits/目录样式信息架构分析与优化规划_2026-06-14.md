# 目录样式信息架构分析与优化规划（2026-06-14）

状态：规划记录，后续已按本文路线进入实现闭环。

范围：模板编辑中的“目录”详情页，主要涉及 `src/ui/panels/template_elements_detail.py` 与 `src/ui/panels/template_elements_toc.py`。本文最初用于分析现状、问题原因、横向参照和后续优化路径；2026-06-15 起追加记录按规划落地的执行结果。

## 1. 结论摘要

当前“目录”页看起来和前面的模板详情页差距明显，根因不是单个控件颜色、字体或圆角不一致，而是三层问题叠在一起：

1. **信息架构偏底层实现**：目录页直接暴露“目录结构 + Word 目录样式角色”的字段编辑器，而不是围绕“生成什么目录、放在哪里、长什么样、哪些级别进入目录”组织任务。
2. **视觉层级过重**：`目录样式` 外层是 `Card`，内部每个样式角色又是 `FlowSection`，而 `FlowSection` 本身继承自 `Card`。这形成了卡片套卡片的视觉结构，截图中“目录共享样式”的大边框和外层“目录样式”卡片叠在一起，显得比正文、页面、表格等模块更重。
3. **表单密度和阅读节奏失衡**：目录样式默认展开一个包含 10 个字段的两列表单，第二列标签又被 `TemplateFormGrid` 默认右对齐，导致“英文字体 / 字形 / 左缩进”等标签贴近中轴，视觉上像一张工程参数表，而不是模板对象的编辑器。

短期最有效的方向不是“再调一点边距”，而是把目录页改成“摘要优先 + 结果预览 + 局部编辑”的结构：先让用户判断当前目录会如何生成，再允许深入调整共享样式或某一级样式。

## 2. 当前实现梳理

### 2.1 页面入口

`ElementsDetail` 会根据 `scope` 选择构建页眉页脚或目录：

- `scope == "toc"` 时标题为“目录”，图标为 `chart-no-axes-gantt`。
- 顶部统一使用 `TemplateSummaryCard`。
- 下方编辑区交给 `TocDetailSection` 构建。

对应位置：

- `src/ui/panels/template_elements_detail.py:93-133`
- `src/ui/panels/template_elements_detail.py:170-185`

这说明顶部摘要体系本身已经接入了统一设计系统；真正的问题主要在目录编辑区。

### 2.2 目录编辑区

`TocDetailSection` 当前只创建两张主卡片：

1. `目录结构`
   - 启用目录
   - 目录模式
   - 目录深度
   - 插入位置

2. `目录样式`
   - `目录共享样式`
   - `目录标题样式`
   - `一级目录样式`
   - `二级目录样式`
   - `三级目录样式`

对应位置：

- `src/ui/panels/template_elements_toc.py:73-92`
- `src/ui/panels/template_elements_toc.py:112-143`

样式角色由 `TOC_STYLE_META` 固定声明，`toc` 默认展开，其余默认折叠：

```python
TOC_STYLE_META = (
    ("toc", "目录共享样式", True),
    ("toc_title", "目录标题样式", False),
    ("toc_level1", "一级目录样式", False),
    ("toc_level2", "二级目录样式", False),
    ("toc_level3", "三级目录样式", False),
)
```

### 2.3 样式字段

每个样式角色都包含同一组字段：

- 中文字体
- 英文字体
- 字号
- 字形
- 对齐
- 左缩进
- 行距类型
- 行距值
- 段前
- 段后

对应位置：

- `src/ui/panels/template_elements_toc.py:145-257`

这些字段本身没有错，问题是它们被默认以“完整参数表”的姿态直接呈现。用户还没有看到目录结果，就已经被要求理解所有样式角色和 Word 输出细节。

### 2.4 样式继承语义

目录样式实际有一套 fallback 逻辑：

- 先找当前角色样式；
- 找不到时回退到共享 `styles.toc`；
- 再回退到 `body` 或 `normal`。

对应位置：

- `src/ui/panels/template_elements_toc.py:289-308`
- `src/shared/engine/toc_style_ops.py`

但 UI 没有把“当前是继承还是自定义”表达出来。用户看到的是每个角色都有完整编辑表单，容易误以为每一级都已经独立配置。更隐蔽的是，用户一编辑某个角色，`_ensure_style()` 会创建该角色的显式样式覆盖，但界面没有明显的“恢复跟随共享样式”入口。

## 3. 截图中的直接观感问题

从截图看，主要问题集中在下半部分“目录结构”和“目录样式”：

### 3.1 顶部摘要卡还算统一

顶部“目录”摘要卡与其它模板详情页共享 `TemplateSummaryCard` 和 `SummaryGrid`，包括大标题、恢复/保存按钮、两个摘要 tile。这部分只是内容偏少，不是主要视觉断点。

### 3.2 目录结构卡过于稀疏

`目录结构` 卡只有 4 个字段，却使用了纵向单行全宽排列。每个下拉框横向拉满，导致“目录模式 / 目录深度 / 插入位置”这类短选项占据整行，视觉重量超过了它的任务复杂度。

对比页面设置、正文、表格等模块，类似字段通常会用 `InspectorForm.add_grid()` 或成对布局压缩为两列，让控件密度和信息重要性匹配。

### 3.3 目录样式卡过重

当前结构是：

```text
Card：目录样式
└─ FlowSection/Card：目录共享样式
   └─ TemplateFormGrid：10 个样式字段
└─ FlowSection/Card：目录标题样式
└─ FlowSection/Card：一级目录样式
...
```

`FlowSection` 继承自 `Card`，因此目录样式卡内部又出现多个卡片表面。这和正文页“每个主题一张卡，卡里直接放表单”的节奏不同，也比参考文献页“FlowSection 直接作为主层级”的结构更重。

对应位置：

- `src/shared/ui/flow_section.py:14-20`
- `src/ui/panels/template_elements_toc.py:87-92`
- `src/ui/panels/template_elements_toc.py:139-146`

### 3.4 第二列表单标签显得不自然

`TemplateFormGrid` 默认在标准列间距下会把第二列标签右对齐：

- `src/shared/ui/template_form_layout.py:251-302`

这对紧凑的两列参数表是合理的，但目录样式这种大字段集合里，第二列标签离控件太近，和截图里的中轴拥挤感直接相关。

### 3.5 缺少目录预览

目录样式字段最需要即时预览，因为用户调“左缩进 / 行距 / 段前段后 / 标题样式”时，真正关心的是目录条目如何排列。但当前页没有目录预览或结果条，只能从字段值推断输出效果。

这会让目录页比正文样式页更难用：正文样式至少是用户熟悉的段落排版；目录样式还包含 Word TOC 角色、级别、页码、制表符等隐含语义。

## 4. 横向比较

### 4.1 正文排版页

正文页结构非常清楚：

```text

文字样式
对齐与缩进

```

对应位置：

- `src/ui/panels/template_style_detail.py:177-228`

它的优点是每张卡只承载一个认知主题，每个主题里字段数量相对可控。目录页目前把多个角色的完整文字样式编辑器放在同一张“目录样式”卡下，所以复杂度显得陡增。

- 有 `InlineAlert` 承载状态问题；

目录页也需要类似的“结果对象”表达，例如“目录生成”“目录预览”“目录样式策略”，而不是直接进入 `toc_level1/toc_level2/toc_level3`。

## 5. 根因拆解

### 5.1 产品对象没有被重新定义

当前页面等价于：

```text
目录 = TocConfig 字段 + TOC 相关 StyleConfig 字段
```

用户心智更接近：

```text
目录 = 是否生成 + 目录层级 + 放置位置 + 条目来源 + 目录外观 + Word 更新行为
```

这两个模型没有对齐，所以 UI 显得像技术字段集合。

### 5.2 样式角色缺少“继承/覆盖”状态

当前存在 `toc` 共享样式，也存在 `toc_title/toc_level1/toc_level2/toc_level3` 角色样式，但 UI 没有明确区分：

- 正在跟随共享样式；
- 已对某个角色单独覆盖；
- 这个角色的有效值来自正文或 normal fallback；
- 编辑后会写入新的显式覆盖。

这会让用户无法判断“目录共享样式”和“一级目录样式”的关系。

### 5.3 折叠只是隐藏字段，没有形成摘要

当前折叠区折起来后只剩标题，例如“一级目录样式”。它没有展示：

- 当前是否自定义；
- 字体字号摘要；
- 缩进摘要；
- 和共享样式是否不同。

所以折叠只是在省空间，不是在帮助判断。

这和标题编号规划里的“摘要优先 + 深入编辑”不同。

### 5.4 嵌套卡片让页面变重

外层 `目录样式` 已经是一个卡片，内层 `FlowSection` 又是卡片，视觉上会出现多层白底、边框、阴影和内边距。前面的正文、页面、表格页多数是“一张主题卡 + 直接表单”，因此目录页明显更厚重。

### 5.5 结构配置没有体现输出依赖

目录生成依赖标题识别、标题编号、`include_in_toc`、Word 原生 TOC 或 plain 目录模式，但当前结构区只显示模式、深度、插入位置。

已有标题编号闭环文档提到必须确认 `include_in_toc` 是否被目录模块实际读取，并在后续闭环中兑现。这说明目录页未来不应孤立编辑，而要和标题编号的“是否进入目录”形成可见联系。

对应文档：

- `docs/audits/标题编号方案与级别行为闭环定义_2026-06-02.md`

## 6. 优化目标

### 6.1 设计目标

1. 让目录页和其它模板详情页共享同一视觉节奏：摘要卡、主题卡、局部表单、必要时的折叠高级区。
2. 让用户先看到结果判断，再进入参数编辑。
3. 明确目录样式的继承关系，避免“共享样式”和“按级样式”混在一起。
4. 减少默认展开字段数量，降低第一屏压迫感。
5. 为后续目录预设、按级样式、标题编号联动留下结构位置。

### 6.2 非目标

1. 不在第一轮重写目录执行引擎。
2. 不改变 `TemplateConfig.toc` 和 `styles` 的持久化结构。
3. 不把目录页扩展成完整 Word TOC 域代码编辑器。
4. 不在普通用户路径中暴露 `TOC 1/TOC 2/TOC Heading` 这类 Word 内部命名。

## 7. 推荐目标结构

建议把目录详情页调整为：

```text
目录
├─ 顶部摘要卡
│  ├─ 目录结构：Word 自动目录 / 3 级 / 自动位置
│  └─ 目录样式：标题 12 磅 / 条目 12 磅 / 宋体
├─ 目录生成
│  ├─ 启用目录
│  ├─ 生成方式
│  ├─ 收录深度
│  └─ 插入位置
├─ 目录预览
│  ├─ 目录标题预览
│  ├─ 一级条目预览
│  ├─ 二级条目预览
│  └─ 三级条目预览
├─ 样式策略
│  ├─ 跟随正文/标题基准
│  ├─ 使用目录共享样式
│  └─ 按角色单独设置
└─ 样式细节（高级）
   ├─ 左侧角色列表：目录标题 / 一级 / 二级 / 三级
   └─ 右侧当前角色 Inspector
      ├─ 有效样式摘要
      ├─ 文字
      ├─ 缩进
      └─ 行距段距
```

### 7.1 第一屏应该表达什么

第一屏重点不是展示所有字段，而是回答：

- 目录是否启用；
- 用 Word 自动目录还是普通目录；
- 收录几级；
- 放在什么位置；
- 当前样式是否跟随共享；
- 输出大概长什么样。

### 7.2 目录预览建议

目录预览不需要一开始就读取真实文档，可以先用模板样式渲染静态样例：

```text
目录

第一章 绪论 ................................ 1
  1.1 研究背景 ............................ 2
    1.1.1 国内外现状 ...................... 3
```

预览至少要体现：

- 标题样式；
- 一级/二级/三级字体字号；
- 左缩进；
- 行距；
- 段前段后的大致节奏；
- 目录关闭态。

这比直接看“左缩进 0.0 字 / 行距值 2.0 倍”更接近用户判断。

### 7.3 样式策略建议

样式策略可以分三层：

1. **跟随正文**：目录条目继承正文基准，只做必要的 TOC 样式同步。
2. **共享样式**：所有目录条目使用一套共享目录样式。
3. **按级自定义**：目录标题、一级、二级、三级可分别覆盖。

在现有数据结构下，不一定需要新增字段。可以通过 `template.styles` 中是否存在 `toc_title/toc_level1/toc_level2/toc_level3` 来推断“自定义覆盖”，通过删除角色样式恢复继承。

需要注意：如果未来要把“样式策略”持久化为显式字段，应先定义迁移规则，避免和当前 fallback 行为冲突。

## 8. 分阶段实施建议

### P0：基线确认

目标：不改代码，只确认现状和验收基线。

建议动作：

1. 保存当前目录页截图，覆盖 1280 宽度和窄宽度。
2. 记录默认模板、目录关闭态、普通目录模式、样式折叠展开四种状态。
3. 对照正文页、页面设置页、表格页、标题编号页截图建立横向基线。

验收标准：

- 能明确指出目录页和其它页面在卡片层级、表单密度、摘要信息、预览能力上的差异。

### P1：视觉层级收敛

目标：在不改变数据模型的前提下，让目录页先“看起来属于同一套系统”。

建议方向：

1. `目录结构` 改用 `InspectorForm` 或两列 grid，不再让短下拉框横向拉满整行。
2. 移除 `目录样式` 的卡片套卡片结构：
   - 方案 A：取消外层 `目录样式` Card，让各个 `FlowSection` 作为主层级；
   - 方案 B：保留外层 Card，但内部改用轻量折叠组，不使用继承自 Card 的 `FlowSection`；
   - 方案 C：只保留一个“样式策略”卡，细节区默认折叠到高级编辑。
3. 大表单中的第二列标签不要默认右对齐，或使用更紧凑的 label scope。
4. 默认不要展开 10 字段完整样式表，先显示样式摘要。

验收标准：

- 第一屏不出现明显卡片套卡片；
- 默认展开字段数量从 10 个以上降到 4-6 个以内；
- 结构区与页面、正文、表格页的表单节奏接近。

### P2：摘要优先与预览

目标：让用户可以先判断目录结果。

建议方向：

1. 新增目录预览区，使用当前有效样式渲染静态样例。
2. 每个样式角色折叠时展示摘要：
   - 目录标题：宋体 / 小四 / 加粗 / 居中；
   - 一级目录：宋体 / 小四 / 左缩进 0 / 行距 2.0；
   - 二级目录：跟随共享；
   - 三级目录：自定义。
3. 摘要卡中的 `目录样式` tile 补充继承状态，而不是只显示字号和字体。

验收标准：

- 用户不展开高级区也能判断当前目录外观；
- 编辑字体、字号、缩进、行距后，预览和摘要同步更新；
- 目录关闭时显示关闭态，不继续展示大量可编辑样式。

### P3：按角色 Inspector

目标：把“目录标题 / 一级 / 二级 / 三级”改成对象选择，而不是纵向堆叠。

建议方向：

1. 左侧角色列表：
   - 目录标题；
   - 一级目录；
   - 二级目录；
   - 三级目录。
2. 右侧展示当前角色：
   - 当前状态：跟随共享 / 自定义；
   - 有效样式摘要；
   - 编辑按钮或展开区；
   - 恢复跟随共享。
3. 保留 `toc` 共享样式作为策略对象，不和四个角色平级堆叠。

验收标准：

- 默认只编辑一个当前角色；
- 所有角色都有清晰的继承/覆盖状态；
- 用户能一键恢复某个角色跟随共享样式。

### P4：目录预设与跨模块联动

目标：让目录页从字段编辑器升级为完整目录对象。

建议方向：

1. 增加目录样式预设：
   - 学位论文目录；
   - 技术文档目录；
   - 招投标目录；
   - 用户自定义目录样式。
2. 与标题编号联动：
   - 显示标题编号中哪些级别进入目录；
   - 当某级 `include_in_toc=false` 时，在目录预览或摘要中提示。
3. 与页码策略联动：
   - 显示目录页是否显示页码；
   - 显示目录页是否属于前置部分。

验收标准：

- 目录页能解释“为什么某一级没有进入目录”；
- 目录页能解释“目录页本身的页码显示规则来自哪里”；
- 目录样式可保存和复用。

## 9. 推荐优先级

建议优先顺序：

1. **先做 P1**：解决视觉断层和卡片套卡片问题，收益最快。
2. **再做 P2**：加入目录预览和摘要优先，解决用户判断困难。
3. **然后做 P3**：按角色 Inspector，解决长期可维护性和复杂度。
4. **最后做 P4**：预设与跨模块联动，属于产品能力升级。

不建议一开始就重做执行层或预设系统。目录页目前最影响体验的是“用户还没判断结果，就先面对一堆工程字段”。

## 11. 最终建议

目录页下一版不应继续被理解为：

- `TocConfig` 的字段表；
- 一组 TOC 样式角色的折叠表单；
- 把正文样式编辑器复制五份后套进目录。

它更应该被理解为：

> 一个用于决定目录如何生成、收录哪些层级、放在哪里、以及以什么视觉样式输出的结果导向型 Inspector。

第一轮改造只要做到“结构配置更紧凑、样式区不再卡片套卡片、默认摘要优先、保留深入编辑入口”，目录页就会和前面的模板详情页明显拉齐。

# 标题编号面板输出与样式重构分析

日期：2026-06-02

范围：标题编号面板中“按级编辑”区域，重点分析当前“输出与衔接”、标题字体/段落样式、非编号标题样式和高级模板表达式的重构方式。

本记录只做产品与工程分析，不执行界面代码修改。

## 一、当前问题判断

当前面板已经具备比较完整的参数能力，但信息架构仍然偏内部实现视角。用户看到的控件名和分组，很多不是他们正在完成的任务，而是配置字段的直译。

最明显的问题集中在这几个控件：

| 当前文案 | 对应字段 | 真实含义 | 用户可能的误解 |
|---|---|---|---|
| 起始编号 | `start_at` | 当前级别第一次出现时从几开始计数 | 还算能理解，但不知道作用范围是“当前级别” |
| 重启编号 | `restart_on` | 下级/本级计数在什么结构变化时重新从起始编号开始 | “重启”像系统操作，不像排版规则 |
| 跟随上级结构 | `restart_on=None` | 上级标题变化后，本级重新从起始编号开始 | 不知道“上级结构”具体指哪个级别 |
| 全文连续 | `restart_on=document` | 不随上级变化重置，整个文档持续递增 | 需要例子才能理解 |
| 标题分隔符 | `title_separator` | 标题编号和标题正文之间的间隔 | 容易理解成两个标题之间的分隔 |
| 交叉引用样式 | `reference_core_style` | 本级编号被下级标题带入时，使用什么数字样式 | 容易理解成 Word 交叉引用功能 |

这些参数本身都有价值，不应该删掉。但现有展示方式会让用户觉得自己在配置程序，而不是配置模板。

## 二、必须保留的核心参数

标题编号面板的核心参数可以分成四类。

### 1. 编号外观

决定当前级别标题前面长什么样。

- 启用编号
- 编号样式
- 前缀
- 后缀
- 带上级编号
- 多级连接符

对应字段：

- `enabled`
- `display_core_style`
- `display_template`
- `chain`
- `chain_separator`

示例：

```text
第一章
1.1
（一）
1)
```

### 2. 编号计数

决定当前级别的编号怎么递增、什么时候重新开始。

- 起始编号
- 重新计数规则

对应字段：

- `start_at`
- `restart_on`

示例：

```text
第一章
  1.1
  1.2
第二章
  2.1
```

这是“上级变化时重新开始”。

```text
第一章
  1.1
  1.2
第二章
  2.3
```

这是“全文连续编号”。

### 3. 输出位置与衔接

决定编号进入哪些输出，以及编号和标题正文之间如何拼接。

- 计入目录
- 编号后间隔

对应字段：

- `include_in_toc`
- `title_separator`
- `ooxml_separator_mode`
- `ooxml_suff`

这里不建议继续叫“标题分隔符”。更准确的文案是“编号后间隔”。

### 4. 下级引用本级时的样式

决定下级标题带上本级编号时，本级那一段如何显示。

对应字段：

- `reference_core_style`

示例：

一级标题正文显示：

```text
第一章 绪论
```

二级标题可能希望显示：

```text
1.1 研究背景
```

这里一级标题在正文里是“第一章”，但被二级标题引用时变成“1”。这就是 `reference_core_style` 的真实含义。

现有“交叉引用样式”这个名字不合适。建议改为：

- “下级引用样式”
- 或“被下级带入时”
- 或“上级编号样式（用于下级）”

三个里最推荐“下级引用样式”，短、准确、不会误解成 Word 交叉引用。

## 三、标题字体和段落样式不能折叠

用户已经明确指出：字体设置等重要参数不能折叠。这个判断是对的。

原因有三点：

1. 标题编号配置不是只改编号，还直接决定标题最终效果。
2. 字体、字号、加粗、对齐、行距、段前段后是模板最常调整的参数。
3. 标题级别切换时，用户天然会比较“一级标题”和“二级标题”的样式差异，如果样式被折叠，需要不断展开/收起，操作成本很高。

所以主标题样式区应该常驻展示，不能是“展开样式细节”。

当前 `_build_format_section` 已经包含完整参数：

- 中文字体
- 英文字体
- 字号
- 字形
- 对齐方式
- 行距类型
- 行距值
- 段前
- 段后

这些应作为“当前级别标题样式”的一级可见模块。

## 四、推荐信息架构

建议把“按级编辑”右侧重构为 4 个常驻模块 + 1 个高级折叠模块。

### 模块 1：编号显示

目的：配置当前级别标题编号长什么样。

建议控件：

| 控件 | 建议文案 | 备注 |
|---|---|---|
| toggle | 启用编号 | 保留 |
| combo | 编号样式 | 保留 |
| input | 前缀 | 保留 |
| input | 后缀 | 保留 |
| combo | 带上级编号 | 文案可改为“包含上级编号” |
| input | 连接符 | 仅在包含上级编号时显示 |

建议布局：

```text
编号显示
启用编号        编号样式
前缀            后缀
包含上级编号    连接符
```

### 模块 2：编号计数

目的：配置编号从几开始，何时重新开始。

建议控件：

| 当前文案 | 建议文案 | 选项建议 |
|---|---|---|
| 起始编号 | 起始编号 | 保留 |
| 重启编号 | 重新计数 | 上级变化时重新开始 / 全文连续编号 / 指定级别变化时重新开始 |

建议默认显示方式：

```text
编号计数
起始编号        1
重新计数        上级变化时重新开始
```

如果选择“指定级别变化时重新开始”，再出现第二个选择控件：

```text
触发级别        级别 1
```

不要把所有“级别 1 变化时重启、级别 2 变化时重启”都塞进同一个下拉里。这样读起来像程序状态。

### 模块 3：输出与引用

目的：决定当前级别编号如何进入目录、标题正文、下级标题。

建议控件：

| 当前文案 | 建议文案 | 说明 |
|---|---|---|
| 计入目录 | 加入目录 | 更口语 |
| 标题分隔符 | 编号后间隔 | 准确表达“编号和标题正文之间” |
| 交叉引用样式 | 下级引用样式 | 避免误解成 Word 交叉引用 |

建议布局：

```text
输出与引用
加入目录        开/关
编号后间隔      全角空格
下级引用样式    1, 2, 3...
```

“编号后间隔”的选项建议：

- 全角空格
- 半角空格
- 无间隔
- 冒号
- 制表符
- 自定义

不建议使用单独的 `□` 作为闭合态显示。它可以作为辅助符号，但主文案必须可读。

### 模块 4：标题样式

目的：配置当前级别标题文本本身的外观。

必须常驻，不折叠。

建议布局参考正文样式和表格样式面板：

```text
标题样式
中文字体        英文字体
字号            字形
对齐方式
行距类型        行距值
段前            段后
```

如果空间紧张，也不要折叠；可以改为左右两列或更紧凑的表单网格。

### 模块 5：模板表达式

目的：给高级用户直接编辑 `display_template`。

这个可以折叠，甚至默认收起。

原因：

- 它是高级能力。
- 普通用户用“前缀/编号样式/后缀/包含上级编号”已经能完成大多数需求。
- 它会和普通控件产生互斥关系，默认展开会增加复杂度。

建议文案：

- 模块名：“高级表达式”
- toggle：“使用自定义表达式”
- 输入框 placeholder：“如：第{cn}章、{chain}、（{cn}）”

## 五、非编号标题也应重新组织

当前“非编号标题”是折叠 FlowSection，里面包含：

- 跳过完整文本
- 跳过前缀文本
- 样式来源
- 中文字体
- 英文字体
- 字号
- 字形
- 对齐方式

问题是：非编号标题常见于“摘要、目录、参考文献、致谢、附录”等，它们往往是模板中非常重要的标题类型。其样式不应该完全藏起来。

建议改成标题编号面板底部常驻模块：

```text
非编号标题
匹配完整标题    参考文献, 致谢, 摘要
匹配标题前缀    附录, 附件, Appendix
样式来源        沿用一级标题 / 独立设置
```

当“样式来源 = 独立设置”时，样式编辑器应展开显示，而不是再藏一层。

如果担心页面过长，可以只折叠“匹配规则示例/说明”，不要折叠实际参数。

## 七、具体文案建议

### 当前“输出与衔接”

建议改为“输出与引用”。

原因：

- “衔接”太抽象。
- 这里同时包含目录、标题正文拼接、下级编号引用。
- “输出与引用”更贴近实际结果。

### 当前“重启编号”

建议改为“重新计数”。

选项建议：

| 旧选项 | 新选项 |
|---|---|
| 跟随上级结构 | 上级变化时重新开始 |
| 全文连续 | 全文连续编号 |
| 级别 1 变化时重启 | 指定级别变化时重新开始 + 触发级别=级别 1 |

### 当前“标题分隔符”

建议改为“编号后间隔”。

选项建议：

| 当前显示 | 建议显示 |
|---|---|
| □ | 全角空格 |
| · | 半角空格 |
| ➡ | 制表符 |
| 自定义 | 自定义 |

如果要保留符号，可以显示为：

```text
全角空格（□）
半角空格（·）
制表符（→）
```

### 当前“交叉引用样式”

建议改为“下级引用样式”。

补充说明不建议做成大段文本，可以用 tooltip 或短状态说明。

tooltip 可写：

```text
当下级标题包含本级编号时，本级编号在下级标题中使用的数字样式。
```

## 八、执行顺序建议

### 第一步：只改信息架构和文案

目标：

- 不改字段语义。
- 不改执行算法。
- 先让用户看得懂。

动作：

- “输出与衔接”改为“输出与引用”。
- “重启编号”改为“重新计数”。
- “标题分隔符”改为“编号后间隔”。
- “交叉引用样式”改为“下级引用样式”。
- 重启选项改成更口语的文案。
- 空白分隔符选项改为完整文案。

### 第二步：重排模块

目标：

- 将计数、输出、样式拆开。
- 标题样式常驻，不折叠。

动作：

- 把 `_build_output_section` 拆为 `_build_counter_section` 和 `_build_output_reference_section`。
- 保留 `_build_format_section` 常驻。
- 移除“展开样式细节/收起样式细节”作为主路径。

### 第三步：重构“重新计数”控件

目标：

- 从一个难懂下拉改成“模式 + 条件级别”的组合。

建议数据映射：

```text
上级变化时重新开始 -> restart_on = None
全文连续编号 -> restart_on = "document"
指定级别变化时重新开始 + level N -> restart_on = "headingN"
```

这样 UI 文案清晰，底层字段不需要改。

### 第四步：非编号标题常驻化

目标：

- 非编号标题不再是“可忽略的小设置”。
- 摘要、目录、参考文献、致谢等标题的样式配置可见。

动作：

- 将 FlowSection 改成普通 Card 或常驻 Inspector block。
- “独立设置”时展开样式编辑器。
- “沿用一级标题”时只显示来源，不展示不可编辑字段。

### 第五步：测试和截图验证

建议新增/调整测试：

- 文案测试：旧文案不再出现，新文案存在。
- 计数映射测试：三种重新计数模式写入正确 `restart_on`。
- 空白间隔测试：全角空格/半角空格/无间隔/制表符显示清楚且写入正确。
- 样式常驻测试：标题样式控件不依赖展开按钮可见。
- 非编号标题样式测试：独立设置时字体/字号控件可见。
- Playwright 或 Qt grab 截图：桌面宽度和窄宽度下无重叠。

## 九、风险点

### 1. 页面变长

标题样式常驻后，右侧内容会更长。

解决方式不是折叠，而是：

- 使用更紧凑的两列表单。
- 让右侧详情区独立滚动。
- 左侧级别列表固定。
- 预览区域位置保持稳定。

### 2. 字段之间存在互斥

例如启用“自定义表达式”后，前缀/编号样式/后缀会失去直接控制意义。

建议：

- 高级表达式默认收起。
- 开启后明确禁用普通编号外观控件。
- 关闭后重新从表达式拆回普通控件。

### 3. “下级引用样式”很难用短文案完全解释

建议用示例预览辅助，而不是长说明文字。

例如在控件旁展示一行小型结果：

```text
下级示例：1.1 示例标题
```

但不要使用大段解释文本，避免违反当前界面“去说明文本”的方向。

## 十、最终判断

最佳执行方式不是删参数，而是重命名、重分组、常驻关键样式。

这块应该从“内部字段配置器”重构成“标题级别结果编辑器”：

- 用户先看到当前级别最终效果。
- 然后按任务调整编号显示、编号计数、输出引用、标题样式。
- 高级表达式只给少数高级用户。
- 字体、字号、行距、段前段后必须常驻。

这会比单纯改几个 label 更彻底，也更符合一个新发布产品应有的完成度。

## 十一、不可折叠与可折叠边界

这一轮重构最重要的边界是：用户高频调整、会直接影响最终标题结果的参数，不能折叠；只有高级、低频、会增加理解成本的参数，才可以折叠。

必须常驻的参数：

- 当前级别预览。
- 启用编号。
- 编号样式。
- 前缀、后缀。
- 包含上级编号。
- 起始编号。
- 重新计数。
- 加入目录。
- 编号后间隔。
- 下级引用样式。
- 中文字体。
- 英文字体。
- 字号。
- 字形。
- 对齐方式。
- 行距类型。
- 行距值。
- 段前。
- 段后。

可以折叠的参数：

- 高级表达式。
- 自定义表达式输入框。
- 复杂 OOXML 分隔模式的底层细项。
- 示例说明或帮助信息。

不建议折叠的模块：

- 标题样式。
- 非编号标题的核心匹配规则。
- 非编号标题在“独立设置”时的字体和段落样式。

换句话说，“说明可以藏，参数不能藏”。页面变长应该通过更紧凑的网格、右侧独立滚动和模块排序解决，而不是把关键参数塞进折叠区。

## 十二、控件归属重新定义

当前问题不是字段太多，而是字段放错了语义位置。建议按用户任务重新归属：

| 字段 | 当前位置倾向 | 推荐模块 | 推荐文案 |
|---|---|---|---|
| `enabled` | 编号组成 | 编号显示 | 启用编号 |
| `display_core_style` | 编号组成 | 编号显示 | 编号样式 |
| `prefix` / `suffix` | 编号组成 | 编号显示 | 前缀 / 后缀 |
| `chain` | 编号组成 | 编号显示 | 包含上级编号 |
| `chain_separator` | 编号组成 | 编号显示 | 连接符 |
| `start_at` | 输出与衔接 | 编号计数 | 起始编号 |
| `restart_on` | 输出与衔接 | 编号计数 | 重新计数 |
| `include_in_toc` | 输出与衔接 | 目录与引用 | 加入目录 |
| `title_separator` | 输出与衔接 | 标题显示 | 编号后间隔 |
| `reference_core_style` | 输出与衔接 | 目录与引用 / 编号显示辅助 | 下级引用样式 |
| `StyleConfig` 字体段落字段 | 折叠样式细节 | 标题样式 | 常驻显示 |
| `display_template` | 模板表达式 | 高级表达式 | 默认收起 |

这里有一个关键判断：`reference_core_style` 不应该叫“交叉引用样式”，也不应该和 Word 的交叉引用功能产生任何关联。它真正表达的是“当前级别作为上级片段出现在下级编号里时，用什么编号样式”。因此它可以放在“目录与引用”，也可以放在“包含上级编号”附近，但文案必须改。

## 十三、推荐执行切分

为了避免一次性重构过大，建议按以下顺序执行：

### 阶段 1：文案和选项语义先收敛

目标是先把用户看得懂的问题解决掉，不改变底层行为。

涉及位置：

- `src/ui/heading_numbering_logic.py`
- `src/ui/panels/heading_numbering_panel.py`

动作：

- 将“输出与衔接”改为“输出与引用”，或拆成“编号计数”“目录与引用”。
- 将“重启编号”改为“重新计数”。
- 将“跟随上级结构”改为“上级变化时重新开始”。
- 将“全文连续”改为“全文连续编号”。
- 将“标题分隔符”改为“编号后间隔”。
- 将“交叉引用样式”改为“下级引用样式”。

### 阶段 2：拆分输出模块

目标是把现在混在一起的控件拆到正确模块。

涉及位置：

- `_build_output_section`
- `_build_detail_panel_inspector`
- `_sync_numbering_lock_state`
- 相关 signal 绑定与 state 同步逻辑

建议拆分为：

- `_build_counter_section`
- `_build_output_reference_section`
- `_build_title_spacing_section`，如果“编号后间隔”需要单独和预览绑定

### 阶段 3：标题样式常驻化

目标是移除“展开样式细节”作为主操作路径。

涉及位置：

- `_build_style_inspector`
- `_build_format_section`
- 当前样式折叠按钮和可见性同步逻辑

动作：

- 让 `_build_format_section` 直接进入当前级别详情区。
- 删除或弱化“展开样式细节”按钮。
- 保持字体、字号、字形、对齐、行距、段前段后始终可见。
- 如果高度压力明显，用两列紧凑表单解决。

### 阶段 4：重新计数控件产品化

目标是把一个难懂下拉改成“模式 + 触发级别”的组合。

UI 值映射：

```text
上级变化时重新开始 -> restart_on = None
全文连续编号 -> restart_on = "document"
指定级别变化时重新开始 + 触发级别 N -> restart_on = "headingN"
```

如果实现时要避免空值歧义，可以在 UI 层使用明确枚举，再由 adapter 写回 `None`。这样既能保持底层语义，又不会让用户面对“跟随上级结构”这类内部化文案。

### 阶段 5：非编号标题重构

目标是让摘要、目录、参考文献、致谢、附录等标题规则不再像边角设置。

涉及位置：

- `_build_non_numbered_section`
- 非编号标题样式编辑控件
- 相关配置同步逻辑

动作：

- 保留“匹配完整标题”“匹配标题前缀”常驻。
- 保留“样式来源”常驻。
- 当选择“独立设置”时，字体和段落样式直接展开。
- 当选择“沿用一级标题”时，不展示不可编辑样式字段，只展示来源状态。

## 十四、验收标准

重构完成后，应满足这些标准：

- 用户不需要展开任何折叠区，就能完成一个标题级别的常规配置。
- 用户能一眼分清“编号长什么样”“编号怎么计数”“进不进目录”“标题文字长什么样”。
- 字体、字号、加粗、对齐、行距、段前段后始终可见。
- “交叉引用样式”不再出现。
- “标题分隔符”不再出现。
- “重启编号”不再出现。
- 空白类选项不再只显示符号，必须有可读名称。
- 高级表达式仍然存在，但默认不是主路径。
- 非编号标题规则和样式不是隐藏的次要设置。
- 级别切换后，右侧模块顺序稳定，不出现控件跳动或大面积重排。

建议验证测试：

- UI 文案断言测试。
- `restart_on` 三种模式的读写映射测试。
- `title_separator` 的显示名和真实值映射测试。
- 标题样式控件常驻可见测试。
- 非编号标题独立样式可见测试。
- 桌面宽度和窄宽度截图检查，重点看标签、下拉框、输入框是否重叠。

## 十五、范围修正：只优化右侧详情区

根据最新判断，左侧“按级编辑”的级别选择列表设计可以保留。它已经提供了用户需要的快速定位能力：

- 当前级别高亮清楚。
- 每个级别同时展示级别名、示例编号和启用状态。
- “编号启用 / TOC / 样式继承”这类短状态适合放在列表里辅助扫描。
- 列表结构稳定，不应该在本轮右侧重构中被打散。

因此后续优化范围应明确收敛为：只调整右侧选中级别的详情编辑区。不要越界改动左侧级别列表、顶部摘要、编号方案区、左侧导航或其他模板面板。

右侧当前问题集中在三点：

1. 分组语义不够清楚：“输出与衔接”混合了目录、计数、间隔和下级引用样式。
2. 高频参数被折叠：“标题样式”里的字体、字号、行距、段前段后不应该隐藏。
3. 个别文案是内部字段视角：“重启编号”“交叉引用样式”“标题分隔符”会让用户误解。

### 右侧保留项

右侧不是全部推翻。以下结构可以保留：

- “级别 N”标题。
- “正文预览”模块。
- “编号组成”模块的大体位置和控件集合。
- “模板表达式”作为高级能力默认收起。

其中“正文预览”应该继续放在右侧顶部，因为它是用户判断修改是否正确的即时反馈。

### 右侧需要重构的项

建议只重构右侧这些部分：

- 将“输出与衔接”拆成更明确的模块。
- 将“标题样式”从折叠模块改为常驻模块。
- 将“重启编号”的控件语义产品化。
- 将“标题分隔符”改为“编号后间隔”。
- 将“交叉引用样式”改为“下级引用样式”。

### 推荐右侧结构

右侧最终结构建议为：

```text
级别 1

正文预览
  第一章 示例标题 1

编号组成
  启用编号        编号样式
  前缀            后缀
  包含上级编号

编号计数
  起始编号        1
  重新计数        上级变化时重新开始
  触发级别        级别 1（条件显示）

标题显示
  编号后间隔      全角空格

目录与下级引用
  加入目录        开/关
  下级引用样式    1, 2, 3...

标题样式
  中文字体        英文字体
  字号            字形
  对齐方式
  行距类型        行距值
  段前            段后

高级表达式
  默认收起
```

这个结构只影响右侧详情编辑体验，不改变左侧级别选择方式。

### 右侧执行原则

- 不调整左侧列表布局。
- 不调整级别列表的状态文案，除非右侧字段命名变更后必须同步一致。
- 不调整顶部“编号方案”区域。
- 不改变底层编号算法。
- 不新增跨面板功能。
- 不把字体、字号、行距、段前段后折叠起来。
- 不使用长段说明文字替代清晰控件文案。

### 右侧验收标准

- 用户选中左侧级别后，只看右侧就能完成该级别配置。
- 用户不需要展开“标题样式”才能修改字体、字号、行距、段前段后。
- “输出与衔接”不再作为混合模块出现。
- “重启编号”“标题分隔符”“交叉引用样式”这些旧文案不再出现在右侧。
- 左侧列表视觉和交互保持当前方案。

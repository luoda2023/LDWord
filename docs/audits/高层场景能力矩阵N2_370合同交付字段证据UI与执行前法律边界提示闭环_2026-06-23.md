# 高层场景能力矩阵 N2.370 合同交付字段证据 UI 与执行前法律边界提示闭环

日期：2026-06-23

## 目标

本轮承接 `contract_delivery` 的明确 L5 blocker：字段证据 UI 与更强的执行前法律边界提示。此前合同交付已经有 `contract_parties_v1` 字段一致性运行检查、签署素材 schema、审阅/签署 delivery preset、合同样本 fixture 与 coverage boundary 报告，但前台仍缺少两个产品化承接点：

1. 用户在场景概览里不能直接看到“字段证据链已经由哪个 schema、哪个 report、哪个 fixture 支撑”。
2. Workbench 执行前问题队列只显式提示插件边界，没有把合同“只做字段/签署交付，不提供法律意见或条款效力判断”的边界作为非阻塞提醒。

N2.370 将 `contract_delivery` pack 与 `contract_delivery` family 从 `orange_l4` 推进为 `green_l5`。本轮不声明法律审查、条款有效性判断、签名真实性鉴别、合同事实审计或外部签署系统交付已经完成。

## 本轮闭合内容

1. 合同字段证据 UI
   - 场景概览新增 `contract_field_evidence` summary item。
   - 证据卡展示 `schema=contract_parties_v1`、`report=contract_field_consistency_report`、`preset=field_consistency_report` 与 `fixture=contract_delivery_signature_fields_degraded`。
   - 证据卡说明 `material_field_consistency` 是字段一致性证据，不提供法律意见或条款效力判断。

2. 执行前法律边界提示
   - `coverage_boundary_issue_items()` 不再只服务 plugin boundary；对 `contract_delivery` 也生成非阻塞 `coverage_boundary` issue。
   - Workbench issue queue 中合同边界归属为 `scene` owner，避免被误算为插件缺口。
   - Workbench issue queue 将 `coverage_boundary` 显示为“边界覆盖”，避免把内部枚举暴露给用户。
   - issue summary 明确 `does not provide legal advice or judge clause validity`，并继续复用 coverage manifest 的承载、资料 schema、ObjectPreflight 与 delivery preset 事实源。

3. 成熟度同步
   - `contract_delivery` pack evidence 新增 `field evidence UI` 与 `pre-execution legal-boundary banner`，remaining gaps 清零。
   - `contract_delivery` family evidence 新增 `field evidence UI`，remaining gaps 清零。
   - 产品成熟度总览从 3 个 Green/L5 增加到 5 个 Green/L5，L5-blocked 从 24 降到 22，remaining gaps 从 45 降到 42。

## Word/OOXML 视角

合同交付的 Word 风险仍围绕字段、批注、修订、隐藏文本、嵌入包和签章素材：

- 字段一致性只检查合同主体、金额、日期、编号等资料字段是否与文档可见文本冲突或缺失，不解释条款含义。
- 批注、修订、隐藏文本继续走 ObjectPreflight 与合同样本 fixture，不默认删除审阅证据。
- 签章/签名素材只作为 material schema 与 delivery preset 的交付资料，不鉴别签署真实性。
- 合同法律审查、诉状、法律意见书等仍应进入 professional manual gate，不被 `contract_delivery` 静默吸收。

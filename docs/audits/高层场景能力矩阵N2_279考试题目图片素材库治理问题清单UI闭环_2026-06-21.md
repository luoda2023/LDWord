# 高层场景能力矩阵 N2.279 考试题目图片素材库治理问题清单 UI 闭环

日期：2026-06-21

## 1. 本轮定位

N2.279 承接 N2.278 的按题素材库 metadata 编辑器。上一轮已经让单题 `source / asset_id / alt_text` 可编辑、可写回，但 `advanced question asset library governance UI` 仍然过宽：用户要靠肉眼逐行发现缺说明、缺来源、重复素材 ID 等治理问题。

本轮只补“治理问题清单 UI”首片：在按题素材库编辑区下方列出可自动识别的高频 metadata 治理问题，并允许从问题行定位回原题图和同一个 metadata 编辑器。它不宣称完成批量治理、版本治理、远端素材库写回或素材主数据管理。

## 2. 已闭合能力

- AssetsPanel 新增 `question_figure_asset_library_governance_table`。
- 治理表展示 `问题 / 题目 / 库来源 / 素材ID / 处理`。
- 自动识别缺图片说明。
- 自动识别远端或库管素材缺库来源。
- 自动识别已声明非本地库来源但缺素材 ID。
- 自动识别同一库来源下同一素材 ID 被多题重复引用。
- 治理行选择或点击“定位”会选中原题图明细行。
- 治理行定位会同步选中按题素材库索引行，并把 metadata 带入 N2.278 的编辑器。
- 修正 `asset_id` 或 `alt_text` 后，治理问题清单会随 `asset_items` 刷新。
- 新表复用 AssetsPanel 既有表格、按钮和选择样式，继续满足场景配置控件与模板管理控件样式一致性的规划要求。
- `scene_product_readiness` 为 `pack:exam_education` 与 `family:exam_teaching` 新增 `question asset per-question asset library governance issue UI bridge` evidence。
- 成熟度剩余 gap 从 `advanced question asset library governance UI` 细化为 `advanced question asset library bulk version governance UI`。

## 3. 链路视角

```text
CSV/XLSX/JSON question figure asset items
  -> EntityProfile.asset_items
  -> per-question asset library index
  -> metadata governance issue scan
  -> governance issue table
  -> select issue row
  -> select original question figure row
  -> select asset library row
  -> metadata editor
  -> save canonical metadata
  -> refresh governance issue table
```

这条链路补的是“治理问题可见、可定位、可由同一编辑器修复”。此前用户可以编辑 metadata，但还缺少一个明确问题入口；现在缺说明、缺来源、缺 ID、重复 ID 这类高频问题可以在素材库区直接暴露。

## 4. 场景矩阵影响

`exam_education` 与 `exam_teaching` 的高级题图素材库边界继续被拆细：

- 按题索引可见性由 N2.277 闭合；
- 单题 metadata 编辑由 N2.278 闭合；
- 高频 metadata 治理问题清单由 N2.279 闭合；
- 后续 remaining gap 明确转为 `advanced question asset library bulk version governance UI`。

这意味着后续不能再把“缺少治理问题入口”重复计算为 L5 blocker。真正剩余的是批量治理、版本治理、远端写回、素材主数据和跨资料包治理。

## 5. 仍不宣称完成的边界

- 不做批量 metadata 自动修复。
- 不做素材 ID 合并、拆分、去重的完整裁决 UI。
- 不做版本历史、变更审计或版本回滚。
- 不做远端素材库写回。
- 不做素材库 API 登录、续期或签名 URL 管理。
- 不做学校、学科、题型规则治理。
- 不做跨资料包素材主数据管理。
- 不做内容级错图识别。
- 不做复杂学科图或 AI 质量判断。

本轮只承诺：高频 metadata 治理问题可被清单化、可定位、可进入同一编辑器修正，并被测试锁定。

# 高层场景能力矩阵 N2.371 标书资质联合体 Schema 与盖章残留证据闭环

日期：2026-06-23

## 目标

本轮承接 `bidding_materials` 与 `qualification_archive_packages` 的相邻 L5 blocker：`multi-party consortium schema`、`seal-position residual checks`、`expiry metadata governance` 与 `multi-party archive depth`。此前招投标/资质包已经具备资料包、附件 inventory、缺项报告、正副本人工边界与基础样本，但联合体成员、证照有效期、盖章版位残留还没有被自然请求、schema、fixture、场景概览和成熟度审计串成闭环。

N2.371 将 `bidding_materials` pack 与 `qualification_archive_packages` family 推进为 `green_l5`。本轮不声明系统可以判断投标策略、证照真实性、资质有效性、法律结论或外部招采平台提交结果。

## 本轮闭合内容

1. 联合体与有效期资料结构
   - `bid_materials_v1` 新增 `consortium_lead`、`consortium_members`、`consortium_roles`。
   - `qualification_archive_assets_v1` 新增 `certificate_no`、`license_no`、`valid_from`、`valid_until`、`consortium_member_name`、`consortium_member_role`。
   - schema boundary 明确不验证证照真实性、不判断资质有效性或联合体成员资格。

2. 高频请求与样本证据
   - 新增请求样本 `bidding_consortium_seal_archive`：`联合体投标资料包盖章残留检查`。
   - 新增 fixture `bidding_materials_consortium_seal_residue_degraded`，绑定 `qualification_archive_packages`。
   - fixture 覆盖 `table_grid`、`fields`、`comments`、`drawing_media_rels`、`headers_footers` 与 `package_relationships`。
   - report expectations 新增 `expiry_metadata_report`、`consortium_archive_manifest`、`seal_position_residue_report`。

3. 场景概览证据
   - 场景概览新增 `bidding_archive_evidence` summary item。
   - 证据卡展示 `bid_materials_v1`、`qualification_archive_assets_v1`、有效期报告、联合体归档 manifest、盖章残留报告与新 fixture。
   - 用户能在场景定义层看到“标书资质证据”已打通，而不是只在后台 audit 中看到。

4. 成熟度同步
   - `bidding_materials` evidence 新增 `multi-party consortium schema` 与 `seal-position residual checks`，remaining gaps 清零。
   - `qualification_archive_packages` evidence 新增 `expiry metadata governance` 与 `multi-party archive depth`，remaining gaps 清零。
   - 产品成熟度总览从 5 个 Green/L5 增加到 7 个 Green/L5，L5-blocked 从 22 降到 20，remaining gaps 从 42 降到 38。

## Word/OOXML 视角

- 联合体资料通过结构化字段表达，不把多主体资格有效性判断交给格式化引擎。
- 有效期字段只作为 metadata governance 与报告证据，不自动裁定是否可提交。
- 盖章版位残留通过 header/footer、drawing relationship、字段与包关系样本承载，定位为场景交付前的残留报告，不归入通用 ObjectPreflight 风险分类。
- 正本/副本、盖章状态、证照真实性和过期元数据是否可接受仍需要人工确认。

## 后续边界

`bidding_materials` 与 `qualification_archive_packages` 当前不再保留联合体 schema、盖章残留、有效期元数据和多主体归档深度缺口。后续增强应转向真实招采平台提交包、外部回执、跨项目资质库复用、人工确认记录留痕与证照过期策略来源治理；不得把证照真实性、资质有效性或投标策略判断伪装成核心格式化能力。

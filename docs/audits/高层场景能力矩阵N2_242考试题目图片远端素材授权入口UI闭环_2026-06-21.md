# 高层场景能力矩阵 N2.242 考试题目图片远端素材授权入口 UI 闭环

日期：2026-06-21

## 本轮定位

N2.208 已经让执行层支持受控 header 鉴权下载，N2.209 又补了 401/403 权限失败诊断。但前台仍缺少明确入口，用户只能在“更多资料”里手写 `question_asset_download_auth` JSON。这个缺口会造成两个问题：

- 鉴权能力存在于 runtime，却没有进入场景配置/资料面板的可见控件；
- 高级考试素材库的剩余边界里一直保留“UI 授权入口”，容易和真实素材库账号登录、续期、签名 URL 混在一起。

本轮只闭合通用 Header 授权入口首片：让用户在 `AssetsPanel` 图片材料区域配置来源、Header 名和 Header 值，并写入执行层既有字段。真实素材库 API 登录、令牌续期、签名 URL 生成和素材库账号体系仍不伪装为已完成。

## 已实现能力

- `AssetsPanel` 图片材料表单新增“远端素材授权”控件组。
- 控件由来源、Header 名、Header 值三部分组成：
  - 来源为空时写成全局 header；
  - 来源填写 `lark_asset_library`、`math_bank` 等值时写成 source-scoped payload；
  - Header 名支持 `Authorization`、`X-API-Key`、`Cookie`，并允许手动输入自定义 header。
- 控件写入执行层已有 `question_asset_download_auth` 字段，不新增 runtime 字段。
- 前台识别并回填执行层已有鉴权 key：
  - `question_asset_download_auth`
  - `question_figure_download_auth`
  - `remote_question_asset_download_auth`
  - `asset_download_auth`
  - `remote_asset_download_auth`
  - `asset_auth`
- 前台可解析 runtime 已支持的简写形态：
  - `headers` / `request_headers` / `requestHeaders`
  - `authorization` / `auth_header`
  - `bearer_token` / `access_token` / `token`
  - `cookie`
  - `api_key`
- 前台统一写回 `headers` 结构，例如：

```json
{
  "lark_asset_library": {
    "headers": {
      "Authorization": "Bearer exam-secret"
    }
  }
}
```

- 前台与执行层保持同一 forbidden header 口径，不写入 `Host`、`Content-Length`、`Connection`、`Proxy-Authorization`、`Transfer-Encoding` 等不应由资料配置注入的 header。
- 如果现有鉴权 JSON 过于复杂、控件无法无损表达，则保留在“更多资料”中，不强行吞并。
- 控件值进入 `current_archive()`、`material_context()` 和当前 profile fields，执行侧仍负责下载、敏感信息过滤和 report/manifest 不泄漏密钥。

## 未伪装完成的边界

本轮不是完整素材库账号系统，仍不承诺：

- 真实素材库 API 登录。
- access token / refresh token 生命周期管理。
- 签名 URL 生成、续期、过期前刷新。
- 多素材库账号切换、组织权限、角色权限。
- 401/403/签名失效后的自动重新授权。
- 密钥加密存储或系统凭据管理。

后续边界应收窄为“真实素材库 API 登录/续期/签名与授权续期”，而不是泛称“UI 授权入口”。

# 高层场景能力矩阵 N2.393j 保留 Gap 退出准入读数归因补充

## 背景

N2.393i 已把发布残留读数统一到 `residual_explanations=14/14 covered`。
但 6 个 retained gaps 仍需要进一步约束：它们可以作为 Blue/Boundary
发布保留项存在，却不能变成永久模糊例外。

因此本轮新增 `SCENE_RETAINED_GAP_EXIT_CRITERIA_SPECS`，对每个 retained
gap 记录退出触发条件、发布期间必须满足的准入条件，以及发布前禁止宣称的
核心能力。

## 本轮闭合读数

- `retained_gap_exit_criteria=6/6 release-allowed`
- 6/6 retained gaps 链接到 release envelope。
- 6/6 retained gaps 链接到 external handoff contract。
- 6/6 retained gaps 链接到 guarded completion。
- 每个 retained gap 至少有一个 exit signal。
- 每个 retained gap 至少有一组 prohibited core claims，且这些 claim 必须被 external handoff 的 `excluded_core_claims` 覆盖。

## 链路要求

`scene_retained_gap_exit_criteria_audit` 必须进入：

- release gate：阻止缺少退出准入条件的 retained gap 继续发布。
- dashboard：显示 6/6 release-allowed、exit signals、prohibited claims。
- drilldown：让每个 retained gap 能被点开看到退出条件和禁止宣称。
- summary projection：在场景配置摘要里显示 retained gap exit criteria。
- workflow/test：防止后续改动绕过该审计。

## 裁决

这不是把 6 个 retained gaps 升级为 Green/L5，而是明确它们为什么仍能发布、
发布时不能宣称什么，以及未来满足什么信号后才允许退出 Blue/Boundary。

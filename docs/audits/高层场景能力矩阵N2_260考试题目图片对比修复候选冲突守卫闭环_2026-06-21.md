# 高层场景能力矩阵 N2.260 考试题目图片对比修复候选冲突守卫闭环

## 1. 本轮定位

N2.259 已经让单条已应用审计记录可以显式确认回滚。但在继续推进批量确认前，仍有一个高风险缺口：同一个 `question_figure_item` 可能出现多个本地可应用候选。如果这些候选都保持 `ready`，Workbench 前台就可能把其中任意一条当成可应用动作，后续批量确认也会面临“同一目标多次替换”的风险。

N2.260 关闭的是“冲突守卫首片”：repair queue 生成时按 `repair_target_type + repair_target_key` 检测多个 ready 候选。同一目标下超过一个可应用候选时，这些候选统一降级为 `confirmation_status=conflict`，关闭前台应用动作，只允许回到题图行定位，等待后续人工裁决。

## 2. 已实现能力

- `_batch_question_figure_repair_queue()` 生成候选后调用冲突守卫。
- 冲突分组只统计原本可应用的 ready 候选：
  - `confirmation_apply_supported=True`；
  - `confirmation_status=ready`；
  - `repair_target_type` 与 `repair_target_key` 非空。
- 同一目标多个 ready 候选时：
  - 队列顶层 `status=conflict`；
  - 队列顶层写入 `conflict_group_count` 与 `conflict_count`；
  - 每个冲突候选写入同一个 `conflict_group_id`；
  - 每个冲突候选写入 `conflict_candidate_count` 与 `conflict_candidate_queue_ids`；
  - 每个冲突候选改为 `confirmation_apply_supported=False`；
  - 每个冲突候选改为 `confirmation_status=conflict`；
  - 每个冲突候选改为 `confirmation_action=resolve_question_figure_replacement_conflict`；
  - `apply_blockers` 追加 `candidate_conflict_same_repair_target`。
- Workbench issue action 继续只对 `confirmation_status=ready` 且可应用的候选输出 `profile_question_figure_repair_candidate`；冲突候选自动回退为 `profile_question_figure_item` 行级定位。
- Markdown batch report 的 repair queue 摘要在有冲突时展示 `conflicts: N`。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue conflict guard bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`question_figure_repair_queue.entries[]` -> 按 repair target 分组 -> 多 ready 候选同目标命中冲突 -> 候选转为 `confirmation_status=conflict` + `candidate_conflict_same_repair_target` blocker -> Workbench 问题队列仍可展示 -> `workbench_issue_action_target()` 不再输出应用动作 -> 前台只定位题图行。

这让“同一目标多候选”的风险在批量确认前被挡住，不会被误当作普通 ready 候选进入前台替换链路。

## 4. 明确不宣称完成

- 不做自动裁决；
- 不做人工选择候选 UI；
- 不做批量确认执行；
- 不做冲突候选优先级排序；
- 不比较图片内容质量；
- 不写回 Word 或远端素材库；
- 不做批量/事务回滚。

当前能力只承诺：同一 repair target 下多个 ready 候选会被识别并阻断应用。真正的候选裁决、人工选择和批量应用仍是后续缺口。

## 5. 验收锚点

- `test_question_figure_repair_queue_blocks_conflicting_ready_candidates`
  - 构造同一题图目标的两个本地可应用候选；
  - 断言队列 `status=conflict`；
  - 断言 `conflict_group_count=1`、`conflict_count=2`；
  - 断言两个候选均为 `confirmation_status=conflict`；
  - 断言两个候选均不可应用，并带 `candidate_conflict_same_repair_target` blocker。
- `test_question_figure_repair_queue_issue_items_keep_conflicts_as_row_route`
  - 断言冲突候选进入 Workbench issue 后只输出 `profile_question_figure_item` 行级定位；
  - 断言不会输出 `profile_question_figure_repair_candidate` 应用动作。
- `test_question_figure_repair_queue_issue_items_route_candidates_to_rows`
  - 继续锁定非冲突 ready 候选仍可进入前台确认应用。
- `test_question_figure_repair_queue_issue_items_keep_blocked_candidates_as_row_route`
  - 继续锁定 blocked 候选仍只定位。
- `test_product_maturity_upgrade_audit_maps_every_subject_to_l5_blockers`
  - 断言 exam pack/family 包含 `question asset comparison repair queue conflict guard bridge` evidence。

## 完整矩阵的判定标准

一个能力行不能只回答“有没有这个场景”。它必须同时回答五件事：

1. 高频入口是否覆盖：用户会怎么自然表达，是否有 matched、ambiguous、manual boundary、negative control。
2. 承载层是否清楚：顶层 pack、planning family、profile、material schema、delivery preset、plugin/manual gate 谁负责。
3. 旅程是否完整：成功、降级、失败或人工边界、handoff 是否按优先级要求可见。
4. Word/OOXML 证据是否真实：是否有 DOCX fixture、surface、preflight finding、expected behavior、report expectation。
5. UI、runtime、report、tests 是否同链：场景控件字段是否追到执行消费者、报告字段和回归测试。

验收口径：P0/P1/P1_CANDIDATE 不要求马上 Green/L5，但不允许“入口有了，边界没说；UI 有了，执行没接；fixture 有了，旅程没分型”。

## 防遗漏的六轴扫描

高频场景应按六个轴横向扫，而不是只按文档类型列名。

| 轴 | 要防止遗漏的内容 | 当前承载 |
| --- | --- | --- |
| 文档族 | 论文、投稿、试卷、标书、公文、技术文档、合同、HR、表单、长文档、附件包、披露材料 | pack/family |
| 工作流 | 快速规范化、结构识别、资料填充、多版本、批量生成、合规计数、审阅对比、对象保护、提交包、归档 | workflow archetype + delivery preset |
| 输入源 | docx、markdown、json、xlsx、bibtex、latex fragment、PDF/OCR、AI 结构化内容 | InputSourceProfile + plugin boundary |
| 资料契约 | 公司、项目、人、产品、题目、附件、签章、图片、清单、预算、成果 | MaterialSchema |
| Word 风险 | 域、批注、修订、隐藏文字、文本框、内容控件、表格行高、OLE、宏、嵌入包、公式、图片 | ObjectPreflight + fixture |
| 交付产物 | final/review/report/compare/intermediate/material package/zip/pdf/多版本 | DeliveryPreset + artifact drilldown |

只要一个高频任务在六轴里找不到归属，就必须新增 capability row、profile、schema、preset、manual gate 或明确 negative/control 边界。

## 控件样式一致性规则

场景配置中的控件必须复用模板管理的参数语言，尤其是样式类控件：

- 段落：左缩进、右缩进、特殊缩进、首行/悬挂值、行距类型、行距值、段前、段后必须使用同名字段和同单位。
- 表格：固定行高归 `fixed_layout_profile`，不是普通 `TableConfig.row_height_pt` 残留参数。
- 页面与输出：页边距、页眉页脚、水印、输出目标、compare、package、PDF 属场景交付策略时，也要复用 control contract 的命名、禁用态、报告字段。
- 公式与专业对象：公式、化学式、图形、图片质量属于场景能力域，但样式选择、对象保护和失败策略必须接 ObjectPreflight/report/test。
- 禁用态：只要 runtime consumer 或 report field 不存在，UI 只能展示为 planned/boundary，不得表现为可执行开关。

这个规则直接回应模板管理和场景定义的关系：模板负责外观基线，场景负责业务理由、范围、策略、风险和交付。场景可以覆盖模板参数，但必须说清楚为什么覆盖、覆盖到哪里、谁执行、谁报告。

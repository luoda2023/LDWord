# 高层场景能力矩阵 N2.272 考试题目图片对比修复批量应用事务台账报告闭环

日期：2026-06-21

## 1. 本轮定位

N2.272 承接 N2.270/N2.271 的事务台账路线：N2.270 已把 apply/rollback 审计记录归并成运行时事务状态，N2.271 已把这份状态写成可留存的 `question_figure_batch_apply_transaction_manifest.json`。本轮继续补齐一个明确断点：JSON artifact 能被系统追踪，但用户仍缺少一份可直接阅读、可在 Workbench 产物区打开的 Markdown 事务报告。

本轮不扩大能力边界，不做后台任务中心、原子事务、自动回滚、跨多 docx 调度或失败补偿。它只把同一份 apply/rollback 审计事实同步物化为可读报告，使“执行结果、事务台账、Workbench artifact、用户复查”形成更完整的 report drilldown 链路。

## 2. 已闭合能力

- `_write_question_figure_batch_apply_transaction_manifest()` 在写出 JSON 台账时同步写出 `question_figure_batch_apply_transaction_manifest.md`。
- 事务台账 payload 新增 `report_supported`、`report_written`、`report_path` 和 `report_write_blockers[]`。
- Markdown 报告包含总状态、事务数、active/rolled_back/orphan rollback 计数、审计路径、期望 apply audit 命中状态、每条 transaction 的 apply/rollback id、输出路径、hash、恢复数量和 `rollback_available`。
- 批量执行 Markdown 摘要新增 `report=<written|not_written>`，与已有 `artifact=<written|not_written>` 并列。
- Workbench `question_figure_repair_queue` artifact detail 新增 `tx_report=<written|not_written>`。
- Workbench artifact list 新增 `question_figure_batch_apply_transaction_report`，指向可打开的 Markdown 报告，并保留独立 fragment `question-figure-batch-apply-transaction-report`。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 新增 `question asset comparison repair queue batch apply transaction manifest report bridge` evidence。

## 3. 链路视角

```text
question_figure_batch_apply_audit.json
  -> _question_figure_batch_apply_transaction_manifest_from_audit()
  -> batch_apply_transaction_manifest
  -> question_figure_batch_apply_transaction_manifest.json
  -> question_figure_batch_apply_transaction_manifest.md
  -> Workbench artifact: transaction_manifest + transaction_report
  -> batch Markdown summary: artifact/report written state
```

这条链路让用户不必只读 JSON：在同一次批量应用或回滚后，可以从 Workbench 看到事务状态、打开 JSON 做机器复核，也可以打开 Markdown 报告快速确认“哪次 apply、哪次 rollback、当前是否还能回滚”。

# 高层场景能力矩阵 N2.369 快速格式化字段级模板修复路由与真实业务模板样本闭环

日期：2026-06-23

## 目标

本轮承接高层场景能力矩阵中 `quick_formatting` 的明确 L5 blocker：字段级模板修复路由和真实业务模板 fixture。此前快速格式化已经有自然请求路由、模板控件、问题队列、报告和基础样本，但遇到“按模板清理 Word、简历/个人文档格式化、字段/缩进/表格样式不一致”时，仍容易停在场景页泛化提示，缺少回到模板管理字段 owner 的闭环。

N2.369 将 `quick_formatting` 从“主流程可用但真实模板深度不足”的 `orange_l4` 推进为 `green_l5`。本轮不声明专业规则判断、内容质量评估、个人履历事实生成、法律/财务/医疗审阅，也不新增顶层 pack；个人轻量文档仍作为 `quick_formatting` 的 thin profile/request-cell 进入同一条通用模板清理链路。

## 本轮闭合内容

1. 字段级模板修复路由
   - 新增 `template_field_repair` 路由，覆盖 `template_field`、`template_style_field`、`template_page_field`、`template_table_field`、`template_output_field`。
   - 修复入口从 Workbench issue queue 进入模板面板，而不是落入泛化的 scene/profile 修复。
   - issue owner 判定支持 `template_*` target/category，保证统计和问题队列归属为 template owner。

2. 真实业务模板样本
   - 新增 `quick_formatting_business_template_cleanup` DOCX fixture。
   - 样本覆盖 `paragraph_run`、`table_grid`、`fields`、`comments`，期望行为为 `detect` 与 `preserve_layout`。
   - 报告期望加入 `template_field_repair`、`object_preflight`、`formatting_report`。
   - 绑定 `quick_word_cleanup` 与 `personal_resume_formatting` 两个高频自然请求样本。

3. 用户旅程与矩阵统计
   - `quick_formatting` 样本 fixture 从 2 个增加到 3 个。
   - 全局 sample fixtures 从 32 增加到 33。
   - 用户旅程路径从 90 增加到 92，其中新增两条 preserve-layout degraded 路径，用于表达业务模板清理遇到字段/批注/表格风险时必须保留与报告，而不是盲改。
   - `quick_formatting` 产品成熟度从 `orange_l4` 升级为 `green_l5`。
   - 产品成熟度总览从 2 个 Green/L5 增加到 3 个 Green/L5，L5-blocked 从 25 降到 24，remaining gaps 从 47 降到 45。

## Word/OOXML 视角

本轮按 Word 本体结构重新核对了 quick formatting 的边界：

- 段落/样式字段：缩进、特殊缩进、段前段后、行距等应回到模板字段 owner，不应只作为一次性执行参数散落在场景页。
- 表格字段：业务模板清理经常同时出现表格网格、标题、行/列布局和段落样式，fixture 必须覆盖 `table_grid`，并把修复路由接到模板表格/样式明细。
- 字段与批注：`fields`、`comments` 属于高风险 Word 对象。快速格式化只做识别、保留、报告和修复定位，不默认重写字段语义或批注内容。
- 个人轻量文档：简历/求职信等仍是通用模板排版问题；系统只处理页面、段落、表格、字段保留与导出，不生成或验证个人事实。

## 后续边界

`quick_formatting` 当前不再保留字段级模板修复路由和真实业务模板 fixture 缺口。后续若继续强化，应进入更细的非阻塞增强：更多行业模板样本、更多字段组合的 fixture、模板字段 drilldown 更细定位、个人 thin profile 的隐私提示与导出预设深化。不得把专业判断、内容生成、事实审查或外部系统交付塞进 `quick_formatting`。

# 高层场景能力矩阵 N2.324 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复报告 UI 闭环

日期：2026-06-22

## 1. 本轮目标

N2.324 承接 N2.323 后的明确缺口：批量失败队列已经可以把 `result_status=failed` 的项暴露到前台，并支持重试、跳过和治理审计，但批次级别仍缺少一个可复盘的恢复报告视图。没有这层视图时，用户只能知道“队列是否还有未处理项”，却不能稳定回答“这个失败批次原本失败多少、恢复多少、跳过多少、还剩多少、报告事实是否已经固化”。

本轮完成的是前台恢复报告 UI 首片：从批量裁决执行记录和失败队列治理记录反推批次恢复状态，生成可重复识别的恢复报告审计记录，并把恢复报告状态回写到可匹配的题图素材 metadata 中。

本轮不声明导出、报告 Drilldown artifact、后台 worker、自动重试调度、并发限流、取消/暂停、失败 SLA、跨 archive 失败中心、回滚、二次补偿、历史 Word 输出追溯修复或非题图素材族的同类治理完成。

## 2. 已闭合能力

- 新增 `question_figure_asset_library_master_subscription_drift_batch_failure_recovery_report_table`。
- 恢复报告从 `question_figure_library_cross_package_master_subscription_drift_conflict_batch_decision_execution` 的 failed result items 出发。
- 恢复状态由 `question_figure_library_cross_package_master_subscription_drift_conflict_batch_failure_queue_governance` 反推：
  - `open`：失败项尚未处理；
  - `retry_failed`：重试仍失败；
  - `recovered`：重试成功并关闭失败项；
  - `skipped`：人工跳过并关闭失败项。
- 报告表展示批次、失败数、已恢复数、跳过数、未处理数和处理动作。
- 报告动作支持“生成报告”“定位失败”“定位报告”。
- 报告签名由 batch id 与失败项恢复状态组成，避免同一恢复事实重复生成。
- 新增审计动作 `question_figure_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_report`。
- 报告记录保留 original failed、recovered、skipped、retry failed、open、unresolved、summary、items、status、next step 等字段。
- 对能匹配到素材 source/asset id 的 profile 回写 `master_subscription_drift_batch_failure_recovery_report_*` metadata。
- 恢复后的失败项即便不在原 batch record 所在 profile，也会通过 report item 的 source/asset id 关联写入报告状态。

## 3. 链路视角

本轮没有制造第二套失败事实源。链路仍保持单向可追溯：

1. 批量裁决执行记录产生 `subscription_drift_batch_decision_result_items`。
2. 失败队列只读取 failed result items，并由 recovered/skipped governance 记录关闭队列项。
3. 恢复报告再次读取同一批 failed result items，并叠加最新失败队列治理记录。
4. 报告根据恢复状态计算 `complete` 或 `attention_required`。
5. 报告生成后写入独立审计记录，并回写题图素材 metadata。
6. readiness/maturity 矩阵把 `batch failure recovery report UI` 移入 evidence，把下一缺口推进到 `batch failure recovery report drilldown artifact UI`。

这个设计避免了 UI 表格、治理审计、报告审计三者各自维护失败计数的分叉风险。当前恢复报告是“批次恢复状态摘要与审计事实”，不是完整可导出的报告文件，也不是逐项 drilldown artifact。

## 5. 仍未闭合边界

N2.324 之后，明确剩余缺口不再是“恢复报告 UI”，而是更下一层的报告 Drilldown artifact：

- 报告项逐条展开、筛选、定位与复制；
- 可导出报告 artifact；
- 报告与失败队列、批量执行记录、素材项之间的 drilldown 路由；
- 跨 archive 的失败恢复报告中心；
- 后台 worker、自动重试、指数退避、并发限流、取消/暂停；
- 失败 SLA、提醒、责任人升级；
- 批量回滚、二次补偿和历史 Word 输出追溯修复；
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

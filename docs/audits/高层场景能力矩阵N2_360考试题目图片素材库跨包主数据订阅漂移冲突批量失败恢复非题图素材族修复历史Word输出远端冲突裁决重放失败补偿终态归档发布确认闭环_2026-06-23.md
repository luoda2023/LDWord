日期：2026-06-23

## 背景

N2.359 已经把 closure report 后的 release handoff 打通：dead-letter、authorization refresh、remote snapshot review 都有外部确认路由、运营入口路由、post-release dashboard 状态和 handoff manifest。剩余断点在于：这些 handoff 仍停在“需要发布确认”，还没有成为可审计的发布确认事实。

N2.360 闭合的是 terminal archive release confirmation 首片。它不声明真实外部发布系统已经自动回调、不声明发布后运营看板已经完成，也不伪装跨系统最终回写已经全自动完成；本轮只承诺 release handoff 可以被前台显式登记为 release confirmation，并留下 external release confirmed、operations entry confirmed、post-release dashboard ready、final delivery confirmation ready、manifest 和 metadata。

## 本轮闭合内容

1. `AssetsPanel` 新增 release confirmation 输出目录、record finder、confirmation item 派生、artifact/record 构造和 metadata 回写。
2. release handoff 后表格动作从只保留 `Manifest` 改为 `Confirm` + `Manifest`；执行 confirm 后状态推进为 `confirmed`，动作收敛为 `Manifest`。
3. `locate_manifest` 优先打开 release confirmation manifest，再回退到 release handoff、closure report 和更早阶段 manifest。
4. dead-letter confirmation 被记录为 `manual_dead_letter_release_confirmed`，并进入 `manual_dead_letter_post_release_dashboard`。
5. authorization refresh confirmation 被记录为 `authorization_refresh_release_confirmed`，并进入 `authorization_refresh_post_release_dashboard`。
6. remote snapshot confirmation 被记录为 `remote_snapshot_release_confirmed`，并进入 `remote_snapshot_post_release_dashboard`。
7. maturity/readiness 将 release confirmation UI bridge 移入 evidence，并把剩余 L5 blocker 推进为 terminal archive post release dashboard UI。

## 链路变化

N2.360 后链路变为：

`terminal archive` -> `durable scheduler` -> `execution monitor` -> `result finalization` -> `final closure audit` -> `closure report` -> `release handoff` -> `release confirmation`

状态投影变为：

`archived` -> `scheduled` -> `monitored` -> `finalized` -> `closed` -> `reported` -> `handoff` -> `confirmed`

## 边界

这个链路把“发布交接已记录”推进为“发布确认已记录”。它仍然保留明确边界：本轮不完成发布后运营看板 UI、不完成最终交付大屏、不完成跨系统自动回写任务，也不声明真实外部发布平台已经被自动调用。下一轮应处理 post release dashboard，把 confirmed items 汇总为运营看板和最终交付视角的可追踪入口。

## 矩阵迁移

本轮将以下 evidence 纳入 `exam_education` pack 与 `exam_teaching` family：

- `question asset per-question asset library cross-package master subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive release confirmation UI bridge`

剩余 gap 从 release confirmation 推进为：

- pack：`advanced question asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive post release dashboard UI`
- family：`advanced asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive post release dashboard UI`

这意味着 release confirmation UI 已从 L5 blocker 中移出。后续不应再把“缺发布确认”作为开放缺口；真正还未完成的是发布后运营看板、最终交付视角和跨系统自动化回写。

## 控件一致性

release confirmation 继续沿用场景矩阵与模板管理一致的控件规则：行内动作用短动词 `Confirm`，状态列只显示 `confirmed`，manifest 为只读 drilldown，重复确认由 handler 拒绝。该模式与 `Handoff`、`Report`、`Close`、`Finalize`、`Monitor` 保持一致，避免用户在同一闭环链路中遇到不同的按钮语义或状态命名。

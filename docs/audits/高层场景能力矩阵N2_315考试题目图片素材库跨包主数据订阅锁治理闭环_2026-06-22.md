# 高层场景能力矩阵 N2.315 考试题目图片素材库跨包主数据订阅锁治理闭环

日期：2026-06-22

## 本轮定位

N2.314 已经让跨包题图主数据在本地推广后可以同步到远端 Registry/API。N2.315 继续关闭“远端登记后无人治理后续变更”的第一段缺口：当资料显式提供订阅锁治理端点时，跨包主数据版本治理表会在 Registry 同步成功后保留该 master key，并把动作切换为“治理订阅锁”，通过 HTTP JSON POST 建立订阅/锁定治理记录。

这一轮仍不声明真实后台订阅服务、远端变更回调、冲突扩散队列、自动拉取远端版本或主数据中心完成。当前只承诺：已有治理计划、已本地推广、已 Registry 同步、且 metadata 中存在订阅锁端点时，前台可以发起订阅锁治理、审计、回写 metadata 并退场。

## 已闭合内容

- 跨包主数据版本表新增第四阶段状态：`记录计划 -> 执行推广 -> 同步Registry -> 治理订阅锁`；
- 无订阅锁端点的数据保持 N2.314 行为：Registry 同步后退场；
- 有 `subscription_lock_url` / `master_subscription_lock_url` / `change_subscription_url` 等端点的数据，在 Registry 成功后显示“待治理订阅锁”；
- 新增导入别名：`SubscriptionLockUrl`、`MasterSubscriptionLockUrl`、`AssetSubscriptionLockUrl`、`RegistrySubscriptionLockUrl`、`MasterDataLockUrl`、`AssetMasterLockUrl`、`MasterDataSubscriptionUrl`、`ChangeSubscriptionUrl`、`SubscriptionLockMode`、`SubscriptionLockScope`、`SubscriptionConflictPolicy`；
- 订阅锁治理复用现有远端素材授权 Header 控件；
- payload 包含 `master_data_key`、source、asset id、Registry id/version/sync changed_at、canonical 主版本、lock policy、package/profile 列表和 affected_items；
- 请求带 `qfig-master-lock-*` 幂等键；
- 成功后写入 `question_figure_library_cross_package_master_subscription_lock_governance_execution` 审计记录，并回写题图 metadata：`master_subscription_lock_status`、`master_subscription_locked_at`、`master_subscription_lock_endpoint`、`master_subscription_id`、`master_subscription_lock_token`、`master_subscription_remote_status`、`master_subscription_lock_version`、lock mode/scope/conflict policy；
- 失败、权限失效或冲突只沉淀执行记录，不把订阅锁链路判定为完成；
- `scene_product_readiness` 在 `exam_education` 与 `exam_teaching` 新增 per-question asset library cross-package master subscription lock governance UI evidence；
- 成熟度 gap 从 `advanced question asset library cross-package asset master data subscription lock governance UI` 收敛为 `advanced question asset library cross-package asset master data subscription change callback execution UI`，家族口径同步收敛为 `advanced asset library cross-package asset master data subscription change callback execution UI`。

## 边界说明

本轮不声明以下能力完成：

- 真实远端订阅服务与推送通道；
- 远端变更 callback 执行和签名校验；
- 后台扫描、定时拉取、变更广播和冲突扩散队列；
- 主数据锁的跨租户审批、多人编辑锁、租约续期和释放；
- 跨 archive 的持久化主数据中心；
- 对历史 Word 输出的追溯修复；
- 非题图素材族的跨包主数据订阅锁治理。

当前剩余缺口应聚焦：订阅锁已经能建立后，远端变化如何通过 callback/队列进入本地，如何判定漂移、冲突和审批边界，而不是继续把“订阅锁治理入口”列为未打通。

# 高层场景能力矩阵 N2.344 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决执行闭环

## 1. 定位

N2.343 已把非题图素材族 repaired historical Word output 从 writeback handoff 推进到真实远端 Connector，并在 409/412 时提供冲突治理记录。本轮 N2.344 补齐 `remote conflict decision execution UI`：冲突治理后不再停在人工计划，而是提供文件级最终裁决动作，并把裁决 payload、manifest、metadata 和表格状态接通。

## 2. 本轮闭环

- 前台表格在 `conflict_governance_planned` 后提供 `Abandon`、`Overwrite`、`NewVer`、`Manifest`。
- `Abandon` 对应 `abandon_local`：放弃本地 repaired DOCX，保留远端当前文档，不发起远端 POST，但写入裁决 manifest 和 profile metadata。
- `Overwrite` 对应 `overwrite_remote`：以冲突裁决 connector POST repaired DOCX，要求远端覆盖当前文档。
- `NewVer` 对应 `keep_remote_upload_new_version`：保留远端当前文档，同时把 repaired DOCX 上传为新版本。
- 远端裁决 payload 使用 `non_question_asset_family_repaired_historical_word_output_remote_conflict_decision`，携带 `docx_base64`、`docx_sha256`、文件名、大小、幂等键、connector id、governance id 和 decision id。
- 裁决状态区分 `conflict_decision_applied`、`conflict_decision_abandoned_local`、`conflict_decision_permission_required`、`conflict_decision_remote_conflict`、`conflict_decision_failed` 和 blocked 类状态。
- Manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decisions`，避免和 Connector 执行产物混淆。

## 3. 链路变化

本轮后链路为：

```text
Record -> Execute -> Verify -> Rewrite -> Adopt -> Writeback -> Connector -> Govern -> Decide -> Manifest
```

表格状态从 `conflict` 推进到 `decided`；成功裁决后操作收敛为 `Manifest`，失败或权限问题保留重试入口。

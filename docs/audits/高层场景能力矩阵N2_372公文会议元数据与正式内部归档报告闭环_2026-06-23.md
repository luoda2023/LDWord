# 高层场景能力矩阵 N2.372 公文会议元数据与正式内部归档报告闭环

日期：2026-06-23

## 目标

本轮承接 `official_policy` pack 与 `meeting_policy_documents` family 的相邻 L5 blocker：`official metadata schema` 与 `formal/internal/archive report depth`。

此前公文/会议/制度材料已经具备 official profile、编号保留、状态水印、归档 preset、基础 DOCX fixture 与正式/内部/归档人工边界，但“公文元数据和版记字段到底由谁管理、报告里是否能证明正式稿/内部稿/归档稿链路、场景概览能否看到证据”仍停在规划口径。N2.372 将这两项推进为可验证闭环，并把 `official_policy` 与 `meeting_policy_documents` 升级为 `green_l5`。

本轮不声明系统可以判断行政决定实质、文件是否真实签发、盖章是否合法、归档办是否批准，也不把每一种行政文种扩成新的顶层入口。

## 闭合内容

1. 公文与会议物料 Schema 深化
   - `official_document_v1` 新增 `document_type`、`security_level`、`urgency`、`signer`、`copy_scope`、`archive_status`、`archive_no`、`retention_period`。
   - `administrative_meeting_fields_v1` 新增 `document_no`、`issuer`、`document_type`、`security_level`、`copy_scope`、`retention_period`，并继续保留 `archive_status`、`archive_no`。
   - 两套 schema 均明确边界：不验证行政决定实质，不认证正式签发有效性，不替代归档办公室审批。

2. DOCX fixture 与 Word XML 证据
   - 新增 `official_policy_metadata_archive_report` fixture，绑定 `official_policy_collection` 高频请求样本。
   - fixture 覆盖 `paragraph_run`、`fields`、`comments`、`headers_footers`、`package_relationships`。
   - expected preflight 仍聚焦 `fields` 与 `comments`；页眉页脚和包关系作为公文版记/归档证据面，不被误判为需要跳出 official 场景的高危对象。

3. 报告与 UI 证据
   - 新 fixture 声明 `policy_archive`、`official_metadata_report`、`formal_internal_archive_manifest`、`official_delivery_status_report`、`watermark_status_report`、`object_preflight`。
   - 场景概览新增 `official_policy_evidence` summary item，直接展示 `official_document_v1`、`administrative_meeting_fields_v1`、四类报告项和证据 fixture。
   - 这让用户在场景定义页能看到公文元数据链路已打通，而不是只在后端 audit 里看到成熟度变化。

4. 成熟度同步
   - `official_policy` evidence 新增 `official metadata schema` 与 `formal/internal/archive report depth`，remaining gaps 清零，升级为 `green_l5`。
   - `meeting_policy_documents` evidence 同步新增公文元数据和正式/内部/归档报告深度，remaining gaps 清零，升级为 `green_l5`。
   - 矩阵摘要推进为 9 个 Green/L5、18 个 L5-blocked、35 个 remaining gaps、35 个 DOCX fixtures、53 个 request cells、95 条 user journeys。

## Word/OOXML 视角

- 公文元数据不应只落在 UI 文案里；它需要通过 structured schema 进入 `document_no`、`document_type`、`security_level`、`urgency`、`signer`、`copy_scope`、`archive_no`、`retention_period` 等字段。
- Word 内部的 `w:fldSimple` / `w:instrText` 字段、批注、页眉页脚和 package relationships 共同承载“版记、文号、归档交付证据”的检测面。
- `headers_footers` 和 `package_relationships` 已经在样本构建器中可生成，本轮把它们用于公文场景证据，而不是把它们当成泛化装饰。
- 正式稿、内部稿、归档稿、水印状态和归档 manifest 是交付状态证据；能报告、能提示、能要求人工确认，但不代表系统自动确认行政有效性。

## 场景边界

- `official_policy` 继续覆盖通知、函、请示、批复、会议纪要、制度汇编、内部传阅和归档稿，不新增碎片化顶层入口。
- `meeting_policy_documents` 是 official 子 profile，负责会议纪要、议程、制度汇编、归档清单和内部/正式交付，不抢顶层导航。
- “普通会议总结/活动复盘”可进入 `quick_formatting` 或 `application_reports`；只有涉及文号、行政版记、正式/内部/归档状态时才进入 `official_policy`。
- “批量通知”仍需要在 `batch_forms` 与 `official_policy` 之间澄清：多人生成是批量表单，正式公文通知是公文场景。

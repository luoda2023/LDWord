# 高层场景能力矩阵 N2.392 边界成熟度发布保留项证据封套闭环

## 背景

N2.391 已把发布投影面回填到 10/10，但 release gate 摘要仍保留 `maturity_l5_blocked=6/27`。这不是普通未完成项：6 个主体都属于 Blue/Boundary，核心格式化器不应伪装具备真实专业插件、OCR/PDF/LaTeX 无损转换、金融保证、专利质量判断、翻译质量保证或外部审阅结论。

本轮补 `boundary_maturity_release_envelope`：把 6 个 retained gaps 做成逐 subject 的发布证据封套。目标不是升绿，而是证明每个保留项都能从成熟度阻断一路追踪到外部 handoff、边界守护、readiness 调和、终端 release trace、发布证据包和主体连续性。

## 封套对象

| 主体 | 保留项 | 发布判断 |
| --- | --- | --- |
| `pack:professional_disclosure` | `real plugin ecosystem` | 保留专业插件生态边界，核心仅提供 handoff、报告和排除声明。 |
| `pack:import_ai_boundary` | `real OCR/PDF/LaTeX plugin integration` | 保留真实转换插件边界，核心仅提供置信度、fallback 和 handoff。 |
| `family:finance_quote_documents` | `finance plugin handoff` | 保留金融保证边界，核心仅处理表格映射和提交包。 |
| `family:ip_patent_documents` | `IP plugin handoff` | 保留专利质量判断边界，核心仅处理结构、题注和审查入口。 |
| `family:bilingual_translation_documents` | `translation-quality plugin handoff` | 保留翻译质量保证边界，核心仅处理术语表、双语结构和 handoff。 |
| `family:regulated_disclosure_documents` | `external assurance review handoff` | 保留外部审阅/鉴证边界，核心仅处理规则来源、归档和审阅入口。 |

## 证据要求

每个封套必须同时具备：

| 证据层 | 要求 |
| --- | --- |
| `maturity_boundary_gap` | `scene_product_maturity_upgrade_audit` 中仍为 Blue/Boundary 且保留同一 gap。 |
| `external_handoff_contract` | `scene_external_handoff_contract_audit` 有同 subject/gap 的 contract。 |
| `boundary_guarded_completion` | `scene_boundary_guarded_completion_audit` 证明边界守护完成且 retained gap 未丢失。 |
| `readiness_reconciliation` | 读数调和层能解释该 subject 的非 Green 状态。 |
| `terminal_release_trace` | 终端 release exception trace 能追踪到该 subject。 |
| `boundary_subject_release_dossier` | 发布证据包持有 retained gap、handoff、trace 和排除声明。 |
| `boundary_subject_release_continuity` | 同一 subject 在成熟度、守护、readiness、terminal trace、dossier 五层连续。 |

## 链路定义

- 审计模块：`src/config/scene_boundary_maturity_release_envelope_audit.py`
- 导出脚本：`scripts/export_scene_boundary_maturity_release_envelope_audit.py`
- Release gate：新增 `scene_boundary_maturity_release_envelope_audit` check，并输出 `scene_boundary_maturity_release_envelope_*` 计数。
- Dashboard：新增 `boundary_release_envelopes` 卡片。
- Drilldown：新增 `boundary_maturity_release_envelope` 明细源，6 行逐 retained gap 展示封套状态。
- Summary projection：Boundary、Evidence、Readiness 展示 `6/6 boundary release envelopes` 与 `0 boundary envelope gaps`。
- CI：纳入 `tests/test_scene_boundary_maturity_release_envelope_audit.py`。

## 边界

本轮不把 `maturity_l5_blocked=6/27` 消成 0，也不实现真实外部插件。封套闭环只证明“保留边界是可发布的、可追踪的、可解释的”，并确保未来如果任何 subject/gap 在成熟度、handoff、dossier 或 continuity 中断链，release gate 会暴露为明确问题。

## 验收标准

- 6 个 Blue/Boundary retained gaps 均生成 `release_envelope_ready` 行。
- 每行都绑定同一 subject/gap 的 maturity、handoff、guarded、readiness、terminal trace、dossier、continuity 证据。
- Dashboard、drilldown、summary、release gate 和 workflow 都能看到该审计。
- Release gate 汇总显示 `boundary_envelopes=6/6`，同时仍保留 `maturity_l5_blocked=6/27`。

# 高层场景能力矩阵 N2.384 发布例外账本行级追踪闭环

## 目标

N2.383 已经把 release gate 中保留的 managed warning、dashboard warning projection、非满分 readiness、static closed boundary 和 L5-blocked boundary maturity 合并为 5 类 governed exception。本轮继续补齐 `row_level_exception_trace`：顶层账本不能只说明 `5/5 governed`，还必须能追到每一类例外背后的具体 source row、scope、family、pack 和 boundary subject。

这不是把边界读数改成 Green/L5，也不是取消 warning；它解决的是可解释性粒度。用户在 dashboard 或 drilldown 看到发布例外时，应能判断这些例外来自哪一条 residual warning、哪一个 readiness reconciliation row、哪一个 boundary guarded maturity subject，以及哪些 static closed but not Green/L5 项被保留。

## 行级追踪范围

发布例外账本保留 5 个顶层 exception row，同时新增 trace row：

| 顶层例外 | trace 来源 | trace 数 |
| --- | --- | ---: |
| managed residual warnings | `scene_residual_warning_governance_audit.rows` | 10 |
| dashboard warning projection | dashboard 来源的 managed residual warning rows | 3 |
| boundary readiness reconciliation | `scene_boundary_readiness_reconciliation_audit.rows` | 15 |
| boundary guarded maturity | `scene_product_maturity_upgrade_audit` 中 `boundary_guarded` subjects | 6 |
| static closed boundary | readiness reconciliation 中 `static_closed_boundary` rows | 2 |

因此发布例外账本新增验收读数：

- `exception_trace_count = 36`
- `unique_source_trace_count = 31`
- `linked_boundary_subject_count = 6`
- `row_level_exception_trace_mismatch = 0`

`exception_trace_count` 按顶层例外归属计数，所以 dashboard projection 与 static closed boundary 会分别作为独立发布例外追踪；`unique_source_trace_count` 按底层 source row 去重，避免误读为新增了更多真实缺口。

## 产品含义

发布例外链路现在分为三层：

1. release gate projection：证明顶层发布例外全受控；
2. governed exception row：说明是哪一类可发布例外；
3. row-level trace：定位到底层审计行、scope、family/pack/boundary subject。

如果后续新增 warning、非满分 readiness、static boundary 或 L5-blocked，但没有进入 `trace_rows`，`scene_terminal_release_exception_audit` 必须失败，而不能只依赖顶层 count 对齐。

## 验收

- `scene_terminal_release_exception_audit` payload 中每个 row 输出 `trace_rows`、`trace_ids`、`source_trace_ids`、`linked_pack_ids`、`linked_family_ids` 和 `linked_boundary_subject_ids`。
- release gate 输出 `scene_terminal_release_exception_trace_count`、`scene_terminal_release_exception_unique_source_trace_count` 和 `scene_terminal_release_exception_linked_boundary_subject_count`。
- dashboard 的 Release exceptions 卡片显示 trace 行数。
- drilldown 的 Terminal release exceptions 行显示 trace 数，并把底层 source trace 纳入 capability/evidence 链。
- JSON/Markdown 导出显示 trace 读数。

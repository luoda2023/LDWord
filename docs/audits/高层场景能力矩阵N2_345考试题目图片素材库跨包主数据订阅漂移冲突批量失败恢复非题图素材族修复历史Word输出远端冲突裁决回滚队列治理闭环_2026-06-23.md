# 高层场景能力矩阵 N2.345 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决回滚队列治理闭环

## 1. 定位

N2.344 已经让非题图素材族 repaired historical Word output 的远端冲突拥有 `Abandon`、`Overwrite`、`NewVer` 三类最终裁决动作。本轮 N2.345 补齐裁决失败后的 rollback queue governance 首片：当裁决遇到权限不足、远端仍冲突、缺少正式输出 DOCX、缺少 endpoint 或普通执行失败时，前台不再只给 `Retry`，而是提供 `Queue` 记录失败/回滚治理队列。

## 2. 本轮闭环

- 失败裁决状态下表格提供 `Queue`、`Retry`、`Manifest`。
- `Queue` 生成 `remote_conflict_decision_rollback_queue_governance` 记录，状态为 `rollback_queue_governance_recorded`。
- 队列条目按失败原因分类：
  - `permission_required`：刷新授权后重试裁决；
  - `remote_conflict`：刷新远端快照或改选裁决；
  - `blocked_input`：重建 repaired DOCX 或 writeback handoff；
  - `execution_failed`：退避重试并人工复核远端副作用。
- 队列记录写入 retry required、rollback review required、formal output DOCX、sha256、decision id、decision status 和 resolution action。
- 队列 manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_queues`。
- 队列 metadata 回写到相关 profile 的 asset item，并把表格状态推进为 `queued`。

## 3. 链路变化

本轮后异常链路为：

```text
... -> Govern -> Decide -> Queue -> Manifest
```

成功裁决仍保持：

```text
... -> Govern -> Decide -> Manifest
```

也就是说，失败/冲突/权限类裁决不再和成功裁决混在同一个状态里，而是进入可审计队列。

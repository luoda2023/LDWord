# AI 文档助手全量改动审计整改与回归记录

> 日期：2026-07-29
> 范围：AI 文档助手、Design/Flow 对话迁移、快速执行、素材预览、模板选择、执行会话、公文/试卷组装与发布审计
> 性质：在既有混合工作树上进行的定向整改与自动化回归；不等同于可直接发布的独立提交

## 1. 最终结论

本轮发现的问题不是一个单纯的 UI 偏差，而是以下几类问题叠加：

1. 发布审计仍检查旧调用文本，导致实现已经迁移后门禁反而误报。
2. AI 附件内容混入 system prompt，格式证据、正文和模型输出缺少统一边界。
3. 多附件场景会把所有 DOCX 都隐式标记为格式参考，语义不确定。
4. 素材槽位的“可打开、可清除、可预览”分别读取不同状态源，可能出现控件互相矛盾。
5. 模板测试仍允许用户模板覆盖同 ID 内置模板，与当前严格库边界冲突。
6. 若干素材/试卷/公文测试绕过了产品实际使用的模式、模板、母版和冻结执行会话。
7. UI 中残留了不准确的“当前场景”文案、无必要的固定表头高度和过期架构契约。

整改后，本地自动化链路已经闭合：

```text
用户输入 / 附件
  -> Assistant 用户消息上下文
  -> 场景能力与计划
  -> 结构化内容生成
  -> 模式 / 方案 / 模板 / 母版预检
  -> 冻结执行会话
  -> 专业终端组装器
  -> 试卷、公文、资料包与报告
  -> 交付物完整性校验
```

当前未发现已知的本地逻辑回归，但仓库仍不满足“可直接发布”的工作树条件，详见第 6 节。

## 2. 已执行的结构性整改

### 2.1 AI 输入与附件证据边界

涉及：

- `src/assistant/runtime/turn_runner.py`
- `src/assistant/domain/docx_format_evidence.py`
- `src/assistant/runtime/provider_contract.py`
- `src/assistant/runtime/providers/openai_compatible.py`
- `src/assistant/application/content_generation_service.py`

整改结果：

- 附件正文和格式证据不再拼入 system prompt，而是作为独立 user message 提交。
- 附件名称、正文和格式证据中的标记字符进行 HTML 转义，避免伪造内部分隔标签。
- 附件正文预算、格式证据预算和 Provider 输出预算分别限制：
  - 附件正文：40,000 字符；
  - 格式证据：20,000 字符；
  - 单次 Provider 输出：100,000 字符。
- OpenAI 兼容 SSE 流增加 1,000,000 字符的未完成行缓存上限，防止异常流持续占用内存。
- Turn Runner 与独立内容生成服务都执行输出上限；超限时取消网关请求并返回明确失败。
- 只有“单个 DOCX 且没有显式格式参考”时才自动推断为格式参考；多附件不再全部隐式标记。
- 审计信息会记录正文/格式证据截断，而不是静默丢失。

这组修改解决的是信任边界和资源边界，不是仅为测试增加特殊分支。

### 2.2 素材槽位与预览状态统一

涉及：

- `src/ui/panels/assets/asset_file_operations_presenter.py`
- `src/ui/panels/assets/asset_slot_status_presenter.py`
- `tests/test_assets_panel_asset_groups.py`

整改结果：

- 文件打开、缩略图和清除按钮统一从同一解析路径读取状态。
- 路径解析保留对 `_asset_paths` 的兼容回退，避免迁移期间已存在的素材无法打开。
- 图片规则测试改为验证当前 `image_material_rules`、来源角色、基数和 profile binding，不再依赖旧 `image_rules` 壳层。

### 2.3 模板库与执行参数契约

涉及：

- `tests/test_template_library_controller.py`
- `tests/test_template_panel_architecture.py`
- `tests/test_pipeline_module_phases.py`

整改结果：

- 用户模板使用独立 ID，不再通过同 ID 覆盖内置模板。
- 模板架构测试先显式选择目标用户模板，再验证损坏、删除和回退。
- Pipeline 测试补齐 `safe_package` 关键字参数，保持与生产调用签名一致。
- 清理测试文件中无效、重复导入，避免架构测试自身制造假依赖。

### 2.4 执行会话、试卷和公文链路

涉及：

- `tests/test_material_execution_context.py`
- `tests/conftest.py`

整改结果：

- 试卷素材测试现在显式设置 exam 模式、方案、模板和 `default_exam` 母版。
- 公文素材测试现在显式设置 official 模式、`official_gbt` 模板、`official_gbt_standard` 母版与文种。
- 两类测试都通过 `build_execution_session_snapshot()` 建立冻结执行会话，再交给真实 `WorkbenchProductionRunner`。
- 测试报告先判断执行状态，再读取产物，失败时能暴露真实根因而不是被 `FileNotFoundError` 掩盖。
- 全局素材库隔离 fixture 改用独立 `tmp_path_factory` 目录，不再污染测试自己的 `tmp_path`。

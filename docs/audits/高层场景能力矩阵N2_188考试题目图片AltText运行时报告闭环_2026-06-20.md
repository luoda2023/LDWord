# 高层场景能力矩阵 N2.188 考试题目图片 AltText 运行时报告闭环

日期：2026-06-20

## 1. 目标

N2.187 已经把 `AssetsPanel question_figure` 到 exam runtime 的首片桥接打通，但 V41 仍把 `exam_education` 的 L5 缺口定位在高级题目素材库：逐题素材映射、预览、altText、复杂图/AI 质量边界等仍未完整产品化。

N2.188 只闭合其中一个窄切片：

```text
question.figure.alt / alt_text / altText / description / caption
-> Word wp:docPr/@descr
-> exam_delivery_runtime altText coverage counters
-> JSON/Markdown report
-> regression tests
```

这不是完整素材库 UI，也不宣称 Green/L5。

## 2. 落地内容

### 2.1 Word XML 写入

`src/shared/engine/exam_question_schema.py` 在渲染题目图片时读取结构化题源中的 alt 文本：

- `alt`
- `alt_text`
- `altText`
- `description`
- `caption`

如果存在显式 alt 文本，则写入 Word 图片的 `wp:docPr/@descr`；若同时有 `title`、`caption`、`asset_id` 或 `source`，写入 `wp:docPr/@title`。

没有 alt 文本时不阻断生成，也不自动用题干脑补；只在报告中记录缺失。

### 2.2 运行时统计

`ExamRenderedVersion` 新增：

- `question_asset_alt_text_count`
- `rendered_question_asset_alt_text_count`
- `missing_question_asset_alt_text_count`

这些字段按版本统计。题干隐藏的 `answer_key`、`analysis_version` 或 `answer_sheet` 不渲染题目图片，因此不会错误计入 altText 缺失。

### 2.3 报告输出

`src/report_writer.py` 已把 altText 字段纳入 JSON 清洗结果，并在 Markdown 的 `## 试卷多版本运行时渲染` 中输出：

```text
assets=<rendered>/<total>, altText=<with_alt>/<rendered>, missing_altText=<missing>
```

这让用户能在报告里看到“图片已插入但缺少可访问性描述”的问题。

## 4. 边界

仍不承诺：

- 自动生成准确 altText；
- 判断图片是否对应题意；
- 多题多图逐项绑定 UI；
- 学科图形自动生成；
- 完整素材库治理。

本轮只保证：如果结构化题源已经提供 altText，则 Word 正式输出和报告会兑现它；如果没提供，报告能暴露缺口。

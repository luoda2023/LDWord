# 高层场景能力矩阵 N2.327 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复并发限流取消重试治理闭环

日期：2026-06-22

## 1. 本轮目标

N2.326 已经把批量裁决执行、失败恢复、恢复报告和 Drilldown artifact 投影成统一后台任务治理表。但任务台账仍只是观察视角，用户无法在恢复动作前控制“本轮最多处理几项、是否暂停恢复、重试上限是多少、退避策略如何留痕”。

本轮闭合的是 `batch failure recovery concurrency limit cancel retry governance UI` 首片：新增订阅恢复治理控件，并让它进入失败队列的恢复执行判断、审计记录、恢复报告、Drilldown artifact 和任务台账。它不声明真正后台 worker、定时退避、自动重试调度、跨进程任务锁、失败 SLA、跨 archive 恢复中心、批量回滚或二次补偿完成。

## 2. 已闭合能力

- 新增“订阅恢复治理”控件组：
  - 固定并发 `1`；
  - 每轮最多；
  - 重试上限；
  - 退避秒数；
  - 暂停恢复。
- 控件样式复用现有输入控件契约：`QSpinBox` 使用 `build_text_input_stylesheet(..., selector="QSpinBox")`，暂停开关使用 `build_checkbox_stylesheet`，并统一 size class。
- 失败队列“重试/跳过”在执行前读取策略：
  - 暂停时不执行、不写伪治理记录；
  - 每轮上限会阻断超出本轮候选范围的行；
  - 重试次数超过上限时写入 `retry_failed / retry_limit_exceeded` 审计，不继续执行单项裁决。
- 失败队列治理记录新增策略字段：
  - `task_governance_status`
  - `task_concurrency_limit`
  - `task_batch_limit`
  - `task_retry_limit`
  - `task_backoff_seconds`
  - `task_cancel_requested`
  - `task_candidate_count_before_policy`
  - `task_candidate_count_after_policy`
  - `task_policy_limited_count`
  - `task_policy_summary`
  - `task_policy_item_status`
  - `task_retry_limit_exceeded`
- 恢复报告 items 继承失败治理策略字段，报告记录同步保留策略摘要。
- Drilldown artifact payload 和 artifact record 继承策略摘要，明细行可复盘恢复策略。
- 后台任务治理表在失败恢复、恢复报告和恢复明细行的治理列追加策略摘要。
- readiness/maturity 把 concurrency limit cancel retry governance UI 移入 evidence，并把下一缺口推进到 SLA / cross archive governance UI。

## 3. 链路边界

本轮只让策略进入前台恢复事实链路：

1. 用户在“订阅恢复治理”中设置策略。
2. 失败队列重试/跳过读取策略。
3. 成功、失败、跳过或超过上限都通过失败队列治理记录留痕。
4. 恢复报告从失败治理记录派生策略字段。
5. Drilldown artifact 从恢复报告派生策略字段。
6. 后台任务治理表投影策略摘要。

`backoff_seconds` 当前是审计策略，不会让前台 sleep。报告生成、Drilldown 生成、定位和打开产物属于复核链路，不被“暂停恢复”阻断。

## 5. 仍未闭合边界

N2.327 后，明确剩余缺口不再是前台并发/取消/重试策略，而是跨批次治理与持续运营：

- 真正后台 worker、队列调度和任务状态持久化；
- 跨进程幂等任务锁、跨批次互斥和断点续跑；
- 自动重试调度和真实指数退避；
- 失败 SLA、提醒、责任人升级；
- 跨 archive 失败恢复中心；
- 批量回滚、二次补偿和历史 Word 输出追溯修复；
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

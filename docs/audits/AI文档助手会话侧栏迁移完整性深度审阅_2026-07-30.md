## 1. 执行摘要

本轮已经完成的修复是真实有效的：

- 会话行不再是“标题 + 时间”的扁平字符串，而是独立 `_SessionRow`；
- 时间拥有固定右侧槽位，悬停后切换为固定、重命名、删除操作；
- 支持行内重命名、双击重命名、删除确认、右键菜单和跨区拖拽固定；
- 相对时间补齐“月/年”，并由 60 秒定时器更新；
- 新增 `activity_at`，重命名和固定不再直接重置最近活动时间；
- 修复了 `QListWidget` 重排时缓存已销毁 C++ 行控件的问题；
- 已有 Assistant 自动化基线为 `240 passed`，完整面板基线为 `55 passed`。

但是，继续逐项对照 Design、Flow 和 Form 当前状态合同后，结论是：

> **会话侧栏已经从“功能藏在后台”提升为可用的桌面鼠标交互版本，但仍不能写成“完整等价迁移”。**

剩余缺口不是同一种性质：

1. **P1 正确性/可操作性缺口**：会话切换选中态提前提交、状态徽标错误、活动时间仍有语义污染和刷新延迟、异常会话无法从 UI 清理、键盘不可操作、搜索链路只有残留代码没有入口。
2. **P2 迁移保真与体验缺口**：重排会中断行内编辑、紧凑抽屉导航后不关闭、重复空会话堆积、同组排序和任务图标没有迁移、错误反馈与空结果状态不足。
3. **明确排除项**：委托、项目、计划独立域、长期记忆、技能中心已经在既有审计第 29 节中按“无完整链路不展示”删除，不应在本轮重新列为缺陷。

## 4. P1 缺口：必须先解决的正确性与可操作性问题

### P1-01 会话选择不是事务提交，失败时侧栏和中央区会错位

#### 当前链路

`AssistantSessionSidebar._select_session()` 当前先调用：

```text
select_session(target)
→ session_selected.emit(target)
→ AssistantPanel._open_session_by_id(target)
→ flush draft
→ load session
```

`_request_new_session()` 同样先清除列表选中态，再发出新建意图。

这意味着 UI 在操作真正成功前已经提交了视觉状态。

#### 可复现结果

动态探针把 `_flush_active_draft()` 模拟为失败，结果为：

```text
SWITCH_MISMATCH True True
NEW_MISMATCH True True
```

含义：

- 中央区仍然持有旧会话；
- 侧栏已经选中新会话，或者已经清空选择。

草稿内容仍保留，因此不是数据丢失，但用户看到的导航状态是错误的。

#### 正确修复

侧栏只应发意图，不应先提交选中态：

```text
点击目标
→ Panel flush/load/create
→ 成功
→ Panel 调用 sidebar.select_session(committed_id)
```

失败时应保持原选中态并显示保存/加载错误。

#### 验收

- 草稿保存失败后，侧栏和中央区仍指向原会话；
- 会话文件加载失败后，不改变当前选中态；
- 新建失败后，不清空当前选中态；
- 腐损会话的“恢复说明选中态”需要单独定义，不与活动会话选中态混用。

---

### P1-02 状态投影只覆盖少数状态，会把重要失败和等待显示成普通会话

当前 `_status_marker()` 和 `_status_tooltip()` 只识别：

- 4 个 running 状态；
- `success/completed`；
- turn 的 `failed/cancelled`。

但真实合同包含：

- `waiting_user_question`；
- `waiting_data_permission`；
- `waiting_tool_permission`；
- `blocked`；
- `needs_route_clarification`；
- `needs_data_disclosure`；
- `preflight_failed`；
- `needs_execution_approval`；
- `partial_success`；
- document job 的 `failed/cancelled` 等。

动态探针结果：

```text
waiting           → · / 对话
preflight_failed  → · / 对话
partial_success   → · / 对话
blocked           → · / 对话
```

这会导致：

- 等待用户回答或授权的会话没有待处理提示；
- 预检失败和执行失败看起来像普通会话；
- 部分成功不显示警告；
- `blocked` 不显示阻塞状态。

Flow 参考还投影了 `dirty_draft`、`unread` 和预览；当前 `AssistantSessionSummary` 不包含这些字段。

#### 正确修复

新增一个唯一的纯函数投影，例如：

```text
AssistantSessionSummary
→ AssistantSessionRowPresentation
   ├─ state: running/waiting/success/warning/failed/draft/idle
   ├─ status_label
   ├─ status_icon_or_marker
   ├─ preview
   ├─ dirty_draft
   └─ accessible_description
```

状态优先级建议：

```text
corrupt
> running
> waiting user/permission/approval
> failed/blocked/cancelled
> partial_success
> success
> dirty_draft
> idle
```

不要继续在 QWidget 内散落字符串集合。

### P1-03 `activity_at` 语义只修了一半，且草稿更新不会刷新侧栏摘要

#### 已完成部分

`rename()` 和 `set_pinned()` 只更新 `updated_at`，不会更新 `activity_at`。这一点正确。

#### 未完成部分 A：通用 `update_state()` 总是更新活动时间

`AssistantSessionCoordinator.update_state()` 无论是：

- 模型选择；
- Provider Profile 切换；
- Context Ref 调整；
- Disclosure Grant 更新；
- 真正的对话或文档任务状态变化；

都会执行：

```python
updated_at=now
activity_at=now
```

动态探针确认：

```text
MODEL_CHANGE_TOUCHES_ACTIVITY True
```

因此“最近活动时间”仍可能因为单纯切换模型而跳到“刚刚”。

#### 未完成部分 B：草稿 activity 已更新，但侧栏继续使用旧 Summary

`stage_draft()` 会更新内存中的 `activity_at`，350ms 后持久化；但 `_flush_active_draft()` 成功后不调用 `_refresh_session_list()`。

60 秒侧栏计时器只基于行中旧的 `_summary.activity_at` 重新计算标签，不会重新拉取会话摘要。

动态探针确认：

```text
DRAFT_ROW_STALE True True
```

即：

- 活动会话里的 `activity_at` 已变化；
- 会话行持有的时间仍是旧值。

#### 正确修复

需要明确区分：

- `updated_at`：任何持久化变更；
- `activity_at`：用户或任务活动；
- 可选 `last_message_at`：消息活动；
- 可选 `last_user_activity_at`：输入/草稿活动。

最低可行方案：

1. 给 `update_state()` 增加显式 `touch_activity: bool`，默认值必须谨慎；
2. 模型、Provider、固定、重命名等纯元数据调用传 `False`；
3. turn、消息、草稿、文档任务状态变化传 `True`；
4. 草稿持久化成功后，使用内存 Summary 增量更新对应行，或统一刷新侧栏；
5. 增加旧 v1 JSON 无 `activity_at` 的兼容测试。

### P1-04 损坏会话只有“查看文件夹”，没有可完成的清理生命周期

`AssistantSessionStore.list_summaries()` 会创建 `corrupt=True` 的恢复条目。

点击条目时，Panel 可以显示：

- 文件无法解析；
- 原文件被保留；
- 打开所在文件夹。

但会话行仍显示固定、重命名、删除按钮，而实际行为是：

- `start_rename()` 对 corrupt 直接返回；
- 右键菜单先 `load_session()`，解析失败后直接返回；
- 删除处理也先 `load_session()`，解析失败后直接返回。

因此损坏条目会永久留在侧栏，按钮看得见但没有效果。

#### 正确修复

为损坏条目定义独立动作合同：

- 打开所在文件夹；
- 查看恢复说明；
- “从列表移除/删除损坏文件”；
- 删除前展示绝对目标文件名，并明确不可恢复；
- 删除只能通过 Store 已验证的 `recovery_path` 或内部安全 ID，不能让 UI 任意删除路径；
- 可选先移动到回收站，而不是永久删除。

损坏行不应显示不可用的固定和重命名按钮。

### P1-05 键盘用户无法完成会话导航和管理

当前动态探针确认：

```text
KEYBOARD_OPENED []
ROW_SELECTION_SYNC False
ACTION_FOCUS [True, True, True]
```

含义：

- 在 `QListWidget` 中按上下键改变当前项后，行的 `_selected` 高亮没有同步；
- 对当前项按 Enter 不会打开会话；
- 固定、重命名、删除三个按钮全部被显式设置为 `Qt.NoFocus`。

鼠标悬停和右键因此成为主要入口。对于键盘、部分辅助技术和无 hover 环境，功能仍不可达。

#### 正确修复

最低键盘合同：

| 按键 | 行为 |
|---|---|
| Up/Down | 改变高亮行 |
| Enter/Space | 打开当前会话 |
| F2 | 行内重命名 |
| Delete | 进入删除确认 |
| Ctrl/Cmd+F | 打开会话搜索 |
| Esc | 取消重命名或关闭搜索 |
| Shift+F10/Menu | 打开当前行菜单 |

同时：

- `currentItemChanged` 必须同步自定义行选中态；
- 行或标题控件需要包含状态、固定状态和时间的 Accessible Description；
- 不得只依赖 hover 显示关键能力；
- 操作按钮应进入合理的 Tab 顺序，或由行级快捷键提供完整替代路径。

### P1-06 搜索是“幽灵链路”：函数和样式存在，但没有控件或入口

当前仓库存在：

- `AssistantPanel._filter_sessions()`；
- `AssistantSessionSidebar.filter_sessions()`；
- `panel_theme_mixin.py` 中 `QLineEdit#assistant_session_search` 样式。

但没有：

- `assistant_session_search` 控件；
- 搜索按钮；
- `textChanged` 连接；
- Ctrl/Cmd+F；
- 清除搜索按钮；
- 无结果状态。

动态探针：

```text
SEARCH_WIDGET False 0
```

Flow 参考实现具有 `show_search()`、`hide_search()` 和“关闭对话搜索”按钮。

#### 正确修复

在侧栏顶部或“对话”模式行增加搜索按钮：

```text
搜索按钮 / Ctrl+F
→ 展示搜索框并聚焦
→ textChanged → filter_sessions
→ Esc/关闭按钮 → 清空、隐藏、恢复列表
```

过滤只匹配标题的现有逻辑可以保留，但应补：

- 置顶/最近区在过滤后均无结果时的空状态；
- 被隐藏的当前会话是否继续保持选中；
- 搜索状态在刷新会话列表后保持；
- 拼音或模糊搜索属于后续增强，不是本轮门禁。

## 5. P2 缺口：迁移保真、稳定性与体验

### P2-01 会话重排会安全重建整组行，但会丢失正在编辑的标题

为避免 `QListWidget` 销毁被移动 item widget 后留下悬空 Python 包装，当前在相对顺序变化时执行：

```text
self.clear()
self._rows.clear()
```

这修复了崩溃，但不是 Flow 的长期 keyed-row 等价实现。

动态探针：

```text
ROW_REBUILT True
INLINE_EDIT_LOST True A
```

后台会话完成、草稿活动或新消息导致排序变化时，用户正在输入的行内标题会被中断。

#### 建议

优先选择以下之一：

1. 改为 Flow 类似的 `QScrollArea + QVBoxLayout + keyed QWidget rows`；
2. 使用正式 `QAbstractListModel + Delegate/PersistentEditor`；
3. 若暂时保留 QListWidget，编辑期间冻结排序，并在提交/取消后重排。

---

### P2-02 紧凑抽屉导航后仍保持打开，遮挡中央会话

动态探针：

```text
DRAWER_STAYS_OPEN True True
```

会话已经切换成功，但左侧 Drawer 仍覆盖中央内容。点击“新任务”也存在同样问题。

建议在成功打开/创建会话之后关闭 drawer；失败时保持 drawer 打开并显示错误。该行为也应服从 P1-01 的事务提交顺序。

---

### P2-03 重复点击“新任务”会持续创建并落库空会话

动态探针：

```text
EMPTY_SESSIONS 2
```

当前 `new_session()` 每次都立即创建并保存 Aggregate。用户连续点击会产生多个没有消息、没有草稿的“新对话”。

可选策略：

- 当前活动会话为空且无草稿时复用；
- 首条输入前只创建内存 draft session，提交时再持久化；
- 保留即时落库，但定期折叠未命名、无内容、无上下文的空会话。

必须明确产品选择，并补测试。

---

### P2-04 Design 的同组排序和任务图标没有迁移

Design 支持：

- 置顶区内部排序；
- 最近区内部排序；
- 跨区拖拽时指定插入位置；
- 为任务选择图标。

当前：

- 同一列表的 drop 被忽略；
- 会话合同没有持久化顺序字段；
- 会话合同没有图标字段；
- 所有正常会话都显示 `message-circle`。

这两项已经在旧审计中被明确列为“尚未完成的原始能力”。如果产品不需要，应正式标记为“有意不迁移”；如果需要，应增加独立的展示元数据，不能滥用 `activity_at` 表达人工顺序。

---

### P2-05 操作失败没有行级反馈

以下失败大多只返回 `False` 或直接 `return`：

- 重命名持久化失败；
- 固定持久化失败；
- 删除在 worker 仍运行时的竞态失败；
- 会话加载失败；
- corrupt 条目菜单失败。

行内编辑会退出，但用户不知道为什么标题没有变化。

建议增加非阻塞行级错误或统一 Toast，并让失败操作恢复焦点和编辑内容。

---

### P2-06 空列表、过滤空结果和时间可访问描述仍不完整

- 最近任务为空时没有“还没有最近对话”；
- 搜索后分区可能只剩标题和空白区域；
- 时间 Tooltip 使用原始 ISO 字符串，不是本地化时间；
- 标题按钮的 Accessible Name 只有标题，没有状态、时间、固定状态；
- 60 秒定时器始终运行，即使侧栏长期隐藏在 embedded/compact 状态。

这些不阻塞主链，但应在可访问性和能耗收尾阶段处理。

## 11. 2026-07-31 回归审阅与二次修复

### 11.1 回归审阅推翻了两项过早结论

在已有测试全部通过的情况下，进一步做交错操作和故障注入，仍复现了两个数据一致性问题：

1. **防抖草稿被元数据操作覆盖**
   - 草稿只存在于活动会话的内存快照时，立即重命名、固定、换图标或拖拽；
   - 原处理重新从磁盘加载旧快照并替换 `_active_session`；

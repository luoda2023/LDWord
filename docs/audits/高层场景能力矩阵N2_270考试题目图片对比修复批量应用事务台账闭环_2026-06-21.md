# 高层场景能力矩阵 N2.270 考试题目图片对比修复批量应用事务台账闭环

日期：2026-06-21

## 1. 本轮目标

N2.270 接在 N2.269 的“批量应用审计回滚”之后，补上事务台账首片。N2.268 已经能留下 apply audit record，N2.269 已经能追加 rollback audit record，但用户和后续系统仍需要一个汇总视角来回答：某次批量应用当前到底是已应用、已回滚，还是存在孤立回滚记录。

本轮目标是从同一个 `question_figure_batch_apply_audit.json` 中归并 apply/rollback 记录，生成 `batch_apply_transaction_manifest`，并把该状态接入 batch Markdown report、Workbench artifact detail 和成熟度证据。

## 2. 边界定义

N2.270 只承诺“审计记录归并后的事务台账”，不承诺：

- 后台任务中心；
- 跨多 docx 调度；
- 原子事务；
- 自动回滚；
- 文件快照；
- 远程素材库写回；
- 失败后自动补偿执行。

它的价值是让现有 apply/rollback 审计记录不再只是离散日志，而是可被 UI、报告和后续任务中心继续消费的事务状态。

## 3. 事务 manifest 契约

新增 `_question_figure_batch_apply_transaction_manifest_from_audit()`，输入为：

- `history_path`
- 可选 `expected_apply_audit_id`

输出 `batch_apply_transaction_manifest`，核心字段包括：

- `kind=question_figure_repair_batch_apply_transaction_manifest`
- `status=tracked|orphaned|empty|blocked`
- `audit_path`
- `expected_apply_audit_id`
- `expected_apply_audit_found`
- `transaction_count`
- `active_count`
- `rolled_back_count`
- `orphan_rollback_count`
- `transactions[]`
- `orphan_rollback_records[]`
- `blockers[]`

每个 transaction 以 apply audit id 为主键归并：

- `transaction_id`
- `transaction_status`
- `apply_audit_id`
- `apply_status`
- `plan_id`
- `execution_plan_fingerprint`
- `input_path`
- `applied_output_path`
- `applied_output_sha1`
- `applied_count`
- `applied_target_count`
- `rollback_count`
- `rollback_audit_ids`
- `latest_rollback_audit_id`
- `latest_rollback_status`
- `latest_rollback_output_path`
- `latest_rollback_output_sha1`
- `restored_count`
- `restored_target_count`
- `rollback_available`

如果 rollback record 的 `linked_apply_audit_id` 找不到对应 apply record，则进入 `orphan_rollback_records[]`，用于后续诊断审计链断裂。

## 4. 链路接入

本轮接入点：

- `_apply_question_figure_repair_batch_execution_to_docx()` 成功追加 apply audit 后生成 manifest；
- `_rollback_question_figure_repair_batch_apply_from_audit()` 成功追加 rollback audit 后重新生成 manifest；
- Markdown batch report 新增事务台账摘要；
- Workbench artifact detail 新增事务台账摘要；
- `scene_product_readiness` 为 exam pack/family 增加 evidence。

Markdown 摘要格式：

```text
Batch apply transaction manifest: status=<status>; transactions=<n>; active=<n>; rolled_back=<n>; orphan_rollback=<n>
```

Workbench artifact detail 摘要：

```text
transaction=<status>; tx=<n>; rolled_back=<n>
```

新增成熟度证据：

```text
question asset comparison repair queue batch apply transaction manifest bridge
```

## 5. 与完整事务中心的关系

N2.270 是完整事务中心之前的状态基座。后续若要做后台任务中心或自动补偿，必须能够先可靠地回答：

- 哪些 apply audit 已经生成；
- 哪些 apply audit 已被 rollback audit 覆盖；
- 哪些 rollback audit 找不到 apply record；
- 当前可展示给用户的事务状态是什么。

因此，本轮不是执行层的扩大，而是追溯层和产品可解释性的补强。

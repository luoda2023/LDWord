# 高层场景能力矩阵 N2.299 考试题目图片素材库远端写回批量二次补偿执行计划 UI 闭环

## 1. 背景

N2.298 已经把回滚失败项推进到“二次补偿计划 + 人工审批”阶段，但审批后仍然停在“等待二次补偿执行计划”。这会让后续 connector 无法判断自己应执行哪一版计划，也无法稳定追溯计划、审批和待执行项之间的关系。

本轮闭合“二次补偿执行计划 UI/审计首段”。它不执行远端二次补偿，也不创建后台任务；只负责在计划已审批后冻结 execution plan 记录，让审批后的补偿项有明确的待执行状态和审计入口。

## 2. 已闭合能力

- 二次补偿表在计划已审批但未生成执行计划时显示“生成执行计划”和“定位失败”。
- “生成执行计划”追加 `question_figure_library_remote_writeback_batch_second_compensation_execution_plan` 历史记录。
- 执行计划记录保存 plan changed_at、approval changed_at、plan signature、approval status、item count、category summary 和 JSON 化执行计划项。
- 执行计划项从已冻结的二次补偿计划项派生，并补充 `execution_status=pending` 与 `execution_connector=pending`。
- 执行计划生成后，二次补偿表显示“执行计划已冻结，等待 connector / 待执行”。
- 执行计划已存在时再次触发不会重复写入历史记录。
- 二次补偿表仍保留“定位失败”，继续回链到回滚失败队列。
- 新增测试锁定“回滚权限失败 -> 二次补偿计划 -> 审批 -> 执行计划 -> 授权重试回滚清空失败队列”的链路。

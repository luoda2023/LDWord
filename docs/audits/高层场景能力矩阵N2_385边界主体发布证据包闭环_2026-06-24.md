# 高层场景能力矩阵 N2.385 边界主体发布证据包闭环

## 目标

N2.384 已经把发布例外从 5 个顶层 exception row 下钻到 36 个 row-level trace。本轮继续补 `boundary_subject_release_dossier`：把这些 trace 重新按 6 个 Blue/Boundary subject 汇总，形成用户能直接验收的发布证据包。

这个能力不把边界主体提升为 Green/L5，也不取消 `maturity_l5_blocked=6/27`。它要证明的是：每一个仍保留边界的主体，都有完整的 guarded completion、readiness reconciliation、terminal release exception trace、外部 handoff、保留缺口和排除核心声明。

## 边界主体

当前 subject-level 发布证据包覆盖 6 个主体：

| 主体 | 类型 | 产品含义 |
| --- | --- | --- |
| `professional_disclosure` | pack | 专业披露仍需外部审阅和责任边界 |
| `import_ai_boundary` | pack | OCR/PDF/LaTeX/AI 转换属于插件或人工边界 |
| `finance_quote_documents` | family | 财务保证和报价核验不属于核心格式化 |
| `ip_patent_documents` | family | 专利权利要求质量和法律判断不属于核心格式化 |
| `bilingual_translation_documents` | family | 翻译质量不属于核心格式化 |
| `regulated_disclosure_documents` | family | 监管/审计保证不属于核心格式化 |

## 验收读数

N2.385 新增审计读数：

- `subject_count = 6`
- `ready_subject_count = 6`
- `subject_trace_count = 26`
- `unique_source_trace_count = 24`
- `readiness_reconciliation_row_count = 14`
- `terminal_exception_count = 4`
- `issue_count = 0`

`subject_trace_count` 只统计能落到 6 个边界主体的发布例外 trace；它小于 N2.384 的 `exception_trace_count=36` 是正常的，因为 dashboard projection 和部分 warning projection 是发布层 trace，不一定直接归属到某个边界主体。
`terminal_exception_count=4` 也符合预期：`dashboard_warning_projection` 是发布视图投影，不归属于单一边界主体。

## 闭环规则

每个 subject 必须同时满足：

- 有 `boundary_guarded_completion` 行，并且状态为 `boundary_guarded_complete`；
- readiness 为 `blue_boundary`；
- maturity 状态为 `boundary_guarded`；
- 至少有一条 readiness reconciliation row；
- 至少有一条 terminal release exception trace；
- 有 retained gap、boundary capability、external handoff contract 和 excluded core claim。

如果后续新增 Blue/Boundary subject，必须进入本 dossier；如果某个 subject 的 trace、handoff 或 excluded claim 断链，release gate 不能只依赖总体 `5/5 release exceptions` 判定通过。

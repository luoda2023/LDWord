# 高层场景能力矩阵 N2.340 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族历史 Word 页眉页脚媒介改写执行闭环

## 1. 本轮定位

N2.339 已经能证明历史 DOCX 的 `word/media/*` 是否含有恢复后的非题图素材，但当 Logo、签章、签名、二维码等素材位于页眉或页脚时，仅扫描 `document.xml` 视角不足。本轮 N2.340 把缺口推进为可执行 rewrite：当 verification 进入 `verification_attention_required` 时，前台出现 `Rewrite` 动作，执行后生成 header/footer relationship media rewrite manifest 和修复后的 `.header-footer-rewrite.docx`。

本轮闭合的是：历史 Word 页眉/页脚中已有图片引用时，可以把其 relationship target 改写到恢复素材生成的新 media，并写入 `word/media/*`，再通过 post-scan 和内容命中验证。

## 2. 新增能力

- DOCX scanner 从正文扩展到 Word part 级视角：`word/document.xml`、`word/header*.xml`、`word/footer*.xml` 及各自 `.rels`。
- scanner 保留旧字段，同时新增 `word_image_part_rows`、`header_footer_part_count`、`header_footer_relationship_status`、`header_footer_media_status`。
- 通用 deep repair 从单一 `word/_rels/document.xml.rels` 扩展为按 part 修复，避免把 header/footer 的 `rId` 错写到正文 rels。
- 新增非题图素材族 rewrite action：`asset_library_cross_package_master_subscription_drift_conflict_batch_failure_recovery_non_question_asset_family_historical_word_header_footer_relationship_media_rewrite_execution`。
- rewrite 执行读取最新 execution 与 verification 记录，定位 header/footer 中的图片 relationship，改写 target 到新的 `word/media/non-question-*.png`，写入恢复素材内容。
- rewrite manifest 记录 docx target count、rewritten docx count、header/footer media rewritten count、added relationship count、pre/post scan 和 repaired docx path。
- metadata 回写 rewrite status、rewrite id、manifest paths、media rewritten count，并写入 `repaired_docx_path` / `repaired_docx_paths`，供后续接管和复验消费。
- UI 状态切换为：`Record -> Execute -> Verify -> Rewrite -> Manifest`；如果 verification 已经完成，则不会出现 Rewrite。

## 3. Word XML 视角

本轮将历史 Word 图片关系拆成三个层级：

1. XML part：正文、页眉、页脚分别扫描 `r:embed` / `r:link`。
2. Relationship part：每个 XML part 对应自己的 `.rels`，例如 `word/_rels/header1.xml.rels`。
3. Media part：relationship target 归一化到 `word/media/*`，并用恢复素材文件内容验证命中。

rewrite 不直接修改 drawing XML 结构，而是改写已存在图片关系的 target；对 XML 引用了缺失 relationship 的场景，会在对应 header/footer `.rels` 中补 relationship 和 media。这样比盲目插入新图更稳，不会破坏页眉页脚排版结构。

## 4. 当前边界

本轮仍不声明最终闭环：

- 已生成 repaired DOCX，但还没有“采用修复副本作为正式历史输出”的显式 UI。
- rewrite 后没有自动再次触发完整 verification 记录；目前 post-scan 与 manifest 是执行内证据。
- 没有接入远端写回、审批、覆盖/保留原件策略。
- 没有处理封面文本框、脚注、尾注、批注、VML 等更多 Word part。
- 没有批量差异合并或跨输出版本对账。

下一缺口推进为：

- pack：`advanced question asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output adoption second pass verification UI`
- family：`advanced asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output adoption second pass verification UI`

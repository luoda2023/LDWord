# 题注页面信息架构分析与整合规划（2026-06-15）

状态：规划记录；2026-06-15 已按本文路线完成第一轮实现闭环。

范围：模板编辑中的“题注”详情页，主要涉及 `src/ui/panels/template_caption_detail.py`、`src/config/feature_configs.py`、`src/modules/table/caption.py` 与 `src/ui/panels/template_summary_projection.py`。本文只分析题注页面的信息架构、字段语义、交互分组和后续实现路径，不讨论表格样式、目录、页眉页脚等其它页面。

## 1. 结论摘要

当前题注页的问题不是某个控件样式错了，而是页面仍然像一个 `CaptionConfig + styles.caption` 的字段清单：

1. 所有字段堆在同一张卡片里，用户看不出“题注文本、编号规则、缺失题注处理、题注样式”的边界。
2. `自动补题注`、`域代码编号`、`编号模式`、`编号格式` 这些名称偏实现层，用户很难直接判断会对文档产生什么结果。
3. 页面没有“输出示例”，用户改前缀、分隔符、编号格式时，只能靠想象推断最终会变成 `图1.1　标题` 还是 `图 1-1 标题`。
4. 当前表单使用 `TemplateFormStack` 纵向堆叠，和正文、目录、页眉页脚已经形成的两列表单节奏不一致。
5. 当前 UI 只编辑共享 `styles["caption"]`，但执行层已经支持 `figure_caption` / `table_caption` 对图题注和表题注分别取样式；这个能力暂时没有被产品化表达。

建议把题注页重新定义为：

> 配置图、表说明文字的生成方式、编号方式和显示样式的结果导向页面。

页面主体建议收敛为三张卡片：

1. 题注文本
2. 编号与生成
3. 题注样式

顶部摘要卡继续保留，但删除额外说明句。不要新增卡片内折叠，不新增特殊控件风格。

## 2. 当前实现梳理

### 2.1 配置模型

`CaptionConfig` 当前字段很少，位于 `src/config/feature_configs.py`：

```python
figure_prefix: str = "图"
table_prefix: str = "表"
separator: str = "\u3000"
placeholder: str = "[待补充]"
numbering_format: str = "chapter.seq"
numbering_mode: str = "chapter"
auto_insert: bool = True
format_inserted: bool = False
```

这些字段可以完整覆盖当前 UI 的“题注文本”和“编号规则”部分。

### 2.2 执行语义

`src/modules/table/caption.py` 的执行层有几个重要事实：

- 会扫描已有图题注和表题注；
- 会对已有题注按当前规则重写编号和样式；
- `auto_insert` 只控制“图片或表格缺少题注时是否自动插入”；
- `format_inserted` 控制是否用 Word 域代码生成编号；
- 图题注默认插在图片后；
- 表题注默认插在表格前；
- 如果选择章节编号但无法识别章节上下文，会跳过章节感知编号，只应用样式并记录 skip。

因此，UI 中的“自动补题注”不能让用户误以为关闭后就不处理已有题注。更准确的表达应是“缺失题注：自动补齐 / 不自动补齐”。

### 2.3 样式语义

执行层 `_resolve_caption_style()` 的顺序是：

1. 图题注优先取 `styles["figure_caption"]`，表题注优先取 `styles["table_caption"]`；
2. 没有独立样式时取共享 `styles["caption"]`；
3. 再回退到正文或 normal。

当前 UI 只编辑共享 `styles["caption"]`，字段包括：

- 中文字体
- 英文字体
- 字号
- 加粗
- 斜体
- 对齐
- 段前
- 段后

执行层实际还会应用行距和缩进，但当前题注页没有提供行距、左右缩进、特殊缩进入口。对题注这种短文本来说，默认不暴露缩进是合理的；但行距是否需要补齐，需要在实现时决定。

## 3. 当前页面的主要问题

### 3.1 信息分组缺失

截图中的字段顺序是：

```text
图前缀
表前缀
分隔符
占位文本
编号模式
编号格式
自动补题注
域代码编号
中文字体
英文字体
字号
字形
题注对齐
段前
段后
```

这对开发者是完整字段清单，但对用户不是任务路径。用户需要先理解：

- 哪些字段决定输出文字；
- 哪些字段决定编号；
- 哪些字段决定是否新增题注；
- 哪些字段决定样式。

当前页面没有帮用户完成这层归类。

### 3.2 技术词直接暴露

以下标签需要重新命名：

| 当前名称 | 问题 | 建议名称 |
| --- | --- | --- |
| 编号模式 | 不知道是按什么模式 | 编号范围 |
| 编号格式 | 太抽象 | 显示格式 |
| 自动补题注 | 容易误解为自动处理全部题注 | 缺失题注 |
| 域代码编号 | Word 技术词 | 编号类型 |
| 分隔符 | 不知道分隔谁和谁 | 编号后间隔 |
| 占位文本 | 不知道何时出现 | 缺失题注标题 |

`域代码编号` 尤其不适合直接展示给普通用户。更好的选项文案是：

- 固定文本编号
- Word 可更新编号

底层仍然写入 `format_inserted`，UI 不需要出现“域代码”这个词。

### 3.3 缺少结果预览

题注页最需要即时预览。用户真正关心的是：

```text
图1.1　[待补充]
表1.1　[待补充]
```

或者：

```text
图 1-1 [待补充]
表 1-1 [待补充]
```

没有预览时，`separator`、`numbering_format`、`placeholder` 的关系很难理解。

建议在“题注文本”卡片内加入两个只读预览行：

- 图题注示例
- 表题注示例

预览不要做成新控件风格，可以使用现有卡片内的普通预览块或轻量 QLabel 组合，视觉上参考目录样式的“样式预览”。

### 3.4 表单布局没有跟上全局规则

当前 `CaptionDetail._build_form()` 使用 `TemplateFormStack(rows)`，所有字段纵向堆叠。

对比正文、页眉页脚、目录样式目前的规则，题注页也应该改成 `InspectorForm.add_grid()` 或 `TemplateFormGrid`：

- 短字段一行两列；
- 长字段或预览全宽；
- 不强行压缩复合控件；
- 不新增新的控件高度或按钮样式。

### 3.5 顶部说明文本多余

当前顶部摘要卡下面有：

```text
编辑图表题注前缀、编号方式，以及共享题注样式。
```

这类说明文本已经被摘要卡和分区标题覆盖，继续保留只会增加阅读噪音。按照前面页面的整理标准，应删除。

底部还有：

```text
当前编辑的是共享 caption 样式；图/表独立题注样式后续再细化。
```

这句话暴露了内部模型，也不适合出现在正式产品界面。能力未开放时不需要解释；能力开放时应该变成清晰的交互，而不是提示文字。

## 4. 建议的信息架构

### 4.1 顶部摘要卡

保留现在的三个摘要 tile：

- 题注文本
- 编号规则
- 题注样式

但摘要文案应更结果化：

```text
题注文本：图 / 表
编号规则：按章节编号，图1.1 / 表1.1
题注样式：宋体 / Times New Roman，小四，居中
```

不要在摘要卡下方再放说明句。

题注总开关如果关闭，不建议折叠整页。用户仍然可能要先配置再启用。但摘要要明确表达“当前不执行题注处理”，保存按钮状态仍按现有模板编辑规则处理。

### 4.2 卡片一：题注文本

目的：回答“生成出来的题注长什么样”。

建议字段：

| 字段 | 来源 | 布局 | 说明 |
| --- | --- | --- | --- |
| 图题注前缀 | `caption.figure_prefix` | 左列 | 默认 `图` |
| 表题注前缀 | `caption.table_prefix` | 右列 | 默认 `表` |
| 编号后间隔 | `caption.separator` | 左列 | 当前是全角空格 |
| 缺失题注标题 | `caption.placeholder` | 右列 | 仅在自动补缺失题注时使用 |
| 图题注示例 | 派生 | 全宽 | 只读预览 |
| 表题注示例 | 派生 | 全宽 | 只读预览 |

字段命名建议：

- `图前缀` 改为 `图题注前缀`
- `表前缀` 改为 `表题注前缀`
- `分隔符` 改为 `编号后间隔`
- `占位文本` 改为 `缺失题注标题`

关于“编号后间隔”：

当前可以先保留输入框，不必立刻新增下拉或自定义选择器。后续如果要优化，可以复用标题编号里的空白符/连接符思路，但不要单独发明控件样式。

### 4.3 卡片二：编号与生成

目的：回答“编号怎么算，缺失题注怎么处理，编号是否可更新”。

建议字段：

| 字段 | 来源 | 布局 | 建议选项 |
| --- | --- | --- | --- |
| 编号范围 | `caption.numbering_mode` | 左列 | 按章节编号 / 全文连续 |
| 显示格式 | `caption.numbering_format` | 右列 | 1.1 / 1-1 / 1:1 / 1 |
| 缺失题注 | `caption.auto_insert` | 左列 | 自动补齐 / 不自动补齐 |
| 编号类型 | `caption.format_inserted` | 右列 | 固定文本编号 / Word 可更新编号 |

文案映射：

```text
chapter -> 按章节编号
global -> 全文连续
chapter.seq -> 1.1
chapter-seq -> 1-1
chapter:seq -> 1:1
seq -> 1
auto_insert true -> 自动补齐
auto_insert false -> 不自动补齐
format_inserted false -> 固定文本编号
format_inserted true -> Word 可更新编号
```

注意：`缺失题注` 应该只解释“图片/表格没有题注时是否新增”，不应该影响已有题注重排。已有题注会继续按规则处理，这一点不需要用长说明写在界面里，但测试和实现文档要明确。

### 4.4 卡片三：题注样式

目的：回答“题注段落看起来什么样”。

建议先保持共享题注样式，不默认拆成图题注样式和表题注样式。原因：

- 大多数论文/正式文档中图题注和表题注样式一致；
- 当前页面已经有较多编号和生成语义，默认拆分会显著增加学习成本；
- 执行层虽然支持 `figure_caption` / `table_caption`，但 UI 不必一开始就把能力暴露到主流程。

建议字段与布局：

| 字段 | 来源 | 布局 |
| --- | --- | --- |
| 中文字体 | `styles.caption.font_cn` | 左列 |
| 字号 | `styles.caption.size_pt` | 右列 |
| 英文字体 | `styles.caption.font_en` | 左列 |
| 字形 | `styles.caption.bold / italic` | 右列 |
| 对齐方式 | `styles.caption.alignment` | 左列 |
| 行距类型 | `styles.caption.line_spacing_type` | 右列，可选补齐 |
| 行距值 | `styles.caption.line_spacing_pt` | 左列，可选补齐 |
| 段前 | `styles.caption.space_before_*` | 左列 |
| 段后 | `styles.caption.space_after_*` | 右列 |

如果本轮只做低风险整理，可以先不新增行距字段，只把现有字段改成：

```text
中文字体 + 字号
英文字体 + 字形
题注对齐
段前 + 段后
```

如果要追求样式完整性，应补齐行距类型和行距值，因为执行层已经会应用行距。

## 5. 图题注/表题注是否需要独立样式

判断：不建议作为默认主流程，但需要为后续保留模型位置。

原因：

1. 从常规论文和正式文档模板看，图题注和表题注通常同字体、同字号、同对齐，只是位置不同：图题注在图下，表题注在表上。
2. 当前执行层的位置策略已经固定：图后、表前；UI 不需要把这个变成用户必须理解的设置。
3. 图/表独立样式一旦展开，会让页面从三张卡变成至少五张卡，复杂度明显上升。
4. 底层已经支持 `figure_caption` / `table_caption`，后续可以加“图表样式分别设置”开关，但不应默认开启。

如果后续确实要开放，建议交互是：

```text
题注样式
  样式范围：图表共用 / 分别设置
  共用时：一套样式表单
  分别设置时：图题注样式 + 表题注样式，中间用横线隔开
```

这仍然可以复用现有 `InspectorForm`、`TemplateFormGrid`、`ToggleSwitch`、`StyledComboBox`，不需要新的控件风格。

## 6. 建议的页面结构草案

```text
摘要卡：题注
  题注文本 / 编号规则 / 题注样式

卡片：题注文本
  图题注前缀          表题注前缀
  编号后间隔          缺失题注标题
  图题注示例：图1.1　[待补充]
  表题注示例：表1.1　[待补充]

卡片：编号与生成
  编号范围            显示格式
  缺失题注            编号类型

卡片：题注样式
  中文字体            字号
  英文字体            字形
  题注对齐            行距类型（可选）
  行距值（可选）      段前 / 段后
```

如果不补行距字段，则题注样式卡为：

```text
中文字体            字号
英文字体            字形
题注对齐
段前                段后
```

## 7. 实现边界

本轮后续如果执行，应遵守这些边界：

1. 不新增预设、另存为方案、删除方案等交互。题注配置体量还不需要方案管理。
2. 不新增折叠区。题注页面字段数量可控，展开更符合目前模板详情页的一致性。
3. 不新增自定义控件样式。使用现有 `Card`、`InspectorForm`、`TemplateFormGrid`、`StyledComboBox`、`ToggleSwitch`、`QLineEdit`、`FontCombo`、`SizeCombo`、`SpacingInput`。
4. 不把 `域代码`、`caption`、`SEQ`、`STYLEREF` 这类实现词展示给普通用户。
5. 不把底层“图后、表前”的位置策略做成主流程设置，除非后续明确需要。
6. 不因为总开关关闭就折叠整页。配置可以编辑，摘要应表达当前是否执行。

## 8. 验收标准

后续实现完成后，应满足：

1. 页面主体由三张语义卡片组成：题注文本、编号与生成、题注样式。
2. 无多余说明文本；尤其删除“共享 caption 样式后续再细化”这类实现说明。
3. `域代码编号` 不再作为用户可见文案出现。
4. `自动补题注` 改成“缺失题注”或等价结果化表达。
5. 题注文本卡能显示图题注和表题注示例。
6. 短字段按两列排列，长字段和预览不强行压缩。
7. 现有配置字段仍然完整写回：`figure_prefix`、`table_prefix`、`separator`、`placeholder`、`numbering_mode`、`numbering_format`、`auto_insert`、`format_inserted`。
8. 现有共享样式仍然完整写回：字体、字号、字形、对齐、段前、段后；若补行距，则同步写回行距类型和值。
9. 顶部摘要、左侧导航摘要和 dirty/save 链路不退化。

# 高层场景能力矩阵 N2.215 考试题目图片远端缓存命中索引闭环

## 1. 本轮定位

N2.215 继续执行 V43 的 P0 高级考试素材库路线，在 N2.214 “远端缓存索引 Manifest”之后，补齐索引链路里的一个短路空洞：

```text
当 question_figure 已有可用 cache_path 且不需要刷新时，Workbench 也会写入 `_remote_asset_cache/index.json`，并标记本次为 cache_hit。
```

本轮不是完整缓存命中统计系统，仍不实现：
- 跨 profile / output_dir 的全局命中统计；
- 前台缓存索引浏览器；
- 批量缓存清理和失效策略；
- 后台失败重试；
- 素材库版本治理。

它的意义是让“已有缓存直接渲染”的高频路径不再绕过索引，后续才能基于 index 做命中统计、缓存健康检查和前台浏览。

## 2. 命中链路

```text
question_figure metadata.cache_path exists
-> cache_expires_at / TTL 未触发刷新
-> cache_path 是可读本地文件
-> metadata 写入 cache_status=reused
-> metadata 写入 download_status=cache_hit
-> 补 download_content_type / download_size_bytes
-> 写入 _remote_asset_cache/index.json
-> Word 继续使用旧 cache_path 渲染
```

## 3. 无远端 URL 的索引 key

已有缓存命中时，素材可能只有 `asset_id/source/cache_path`，没有 `download_url`。本轮不伪造下载 URL：

```json
{
  "cache_key_type": "cache_path",
  "download_url": "",
  "cache_path": "C:/cache/question_1_cached.png",
  "cache_status": "reused",
  "download_status": "cache_hit"
}
```

如果素材仍携带远端 URL，则 index 继续沿用 download URL hash。否则使用 `cache_path` 作为 fallback key，并显式写入：

```text
cache_key_type = cache_path
```

## 4. 索引条目

缓存命中条目会记录：

- `cache_path`
- `cache_name`
- `item_id`
- `asset_id`
- `source`
- `question_index`
- `cache_status=reused`
- `download_status=cache_hit`
- `download_content_type`
- `download_size_bytes`
- `indexed_at`

这与 N2.214 的下载/刷新/304 复用条目保持同一 schema。

## 5. 成熟度证据

`scene_product_readiness` 新增 evidence：

```text
question asset remote cache-hit index bridge
```

覆盖对象：
- `pack:exam_education`
- `family:exam_teaching`

这使高级考试素材库从“下载/刷新成功才进入 index”，推进到“已有缓存直接命中也进入 index”。

## 6. 仍未闭合的边界

N2.215 后，`advanced question asset library UI` / `advanced asset library UI` 的剩余边界收窄为：
- 真实素材库 API：登录、续期、签名 URL、远程查询下载 URL；
- UI 授权入口：401/403/过期/无权限/签名失效后的重新授权、token 刷新、权限申请或账号切换；
- 深层缓存治理：跨 profile 共享缓存索引、后台失败重试、批量失效、统一清理、缓存命中统计面板；
- 远端预览 UI：下载前缩略图、失败占位、尺寸展示、批量审阅；
- 内容级错图识别：图片内容、OCR、题干语义或图像相似度比对；
- 复杂学科图、几何图、公式图的生成或插件接管；
- AI 出题质量、素材质量、版权或真实性判断；
- 更完整的素材库批量审阅、历史版本、学科/题型标签和复用治理。

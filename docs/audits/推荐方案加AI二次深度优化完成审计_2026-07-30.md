日期：2026-07-30  
审计对象：`Alavette-Form_V1.0` Windows 正式发布包  
结论状态：产品边界优化完成；架构与发布门禁通过；不宣称当前整个并行工作树的全部功能测试为全绿

## 1. 最终结论

本轮不是继续按目录猜测“哪些代码可能没用”，而是以正式 PyInstaller 构建的 `Analysis-00.toc` 与 `PYZ-00.toc` 为唯一产品闭包依据，去重后重新计算。

| 物理行 | 205,051 |

| 全部 `main.py + src/**/*.py` 源码有效行 | 273,325 |
| 未进入产品闭包的工程/审计代码 | 92,876 行 |

| AI 层占产品有效行 | 9.78% |

有效行口径：

- 统计本次正式构建 TOC 中、位于仓库 `main.py` 或 `src/**/*.py` 的唯一源文件；
- 排除空行和纯注释行；
- 保留模块、类、函数文档字符串，因为它们仍是实际 Python 对象和发布字节码的一部分；
- 不把测试、脚本、文档、工程审计代码错误计入最终产品。

### 是否臃肿

结论是：**不再存在“明显可直接删除的大块发布垃圾”，但产品仍属于大型桌面应用，结构复杂度为中等偏高。**

可以区分为三层：

1. 发布垃圾：已基本清理完。用户配置、内容工件、本机路径和未支持的 AVIF 二进制均未进入成品。
2. 无效产品代码：高置信可拆分的工程审计闭包已移出产品运行时。
3. 真实复杂度：Qt 桌面 UI、Word/OOXML 引擎、材料服务、AI 工作流仍然是产品能力本身，不能仅凭行数删除。

## 6. 当前并行工作树中仍存在的非本轮阻断项

为了不把“优化完成”误写成“整个仓库全绿”，以下既有并行改动导致的失败需单独记录：

1. 表格和公式表格直接调用测试有 11 项失败。当前产品采用显式文档范围、无范围证据时 fail-closed；旧测试仍按“无 `doc_tree` 即全局可写”断言。该失败在本轮最终拆分前已经复现，本轮没有把产品恢复为隐式全局写入。
2. `test_phase0_smoke.py` 的两个测试桩没有声明新的强制 `scope_behavior`，被模块阶段契约拒绝。正式注册模块的契约门禁通过。
3. `test_scene_journey_runtime.py` 有一项仍期待 `boundary_confirmation` 修复目标；当前结果只给出 `material_repair` 与 `plugin_manual_gate`。
4. `test_scene_product_summary_projection.py` 收集时仍引用已经移除的 `build_section_style_override_projection` 导出。

这些项不属于本轮“非必要代码与发布闭包”改动，且在本轮运行时边界拆分前已存在或由并行功能演进产生。本审计没有修改断言来制造假绿，也没有放宽 fail-closed 边界。

正式发布包构建和启动已经通过，但若要把当前整个工作树标记为功能发布候选，以上 4 组契约/测试迁移仍应由对应功能变更统一收口。

### 7.2 包体主体不是一方垃圾

最终目录 122,879,731 字节，其中 `_internal` 为 112,962,757 字节，占 91.93%。最大项包括：

- Qt 软件 OpenGL 回退：20,639,544 字节；
- Qt6Core：10,480,440 字节；
- Qt6Gui：9,589,560 字节；
- PDFium：7,216,128 字节；
- Python 运行库：6,945,272 字节；
- Qt6Widgets：6,594,360 字节。

这些主要是桌面运行时、兼容性和 PDF 能力。没有硬件矩阵、PDF 功能边界和 Windows 兼容验证前，不建议继续删除：

- `opengl32sw.dll`：删除可省约 20.6 MB，但会降低无兼容 GPU/远程桌面环境的启动可靠性；
- PDFium：删除可省约 7.2 MB，但会伤害 PDF 预览/解析能力；
- Qt Core/Gui/Widgets：属于当前桌面产品基础，不是冗余。

### 7.3 推荐的下一边界

如果继续优化，推荐顺序是：

1. 先完成上述 4 组并行功能契约/测试迁移，恢复仓库功能回归的统一绿线；
2. 对 `scene_panel.py` 与 `config/library.py` 做职责分层，不以净删功能为目标；
3. 建立真实用户功能遥测或可选功能开关后，再评估 PDFium、软件 OpenGL 回退和冷门 Pillow 格式；
4. 保持 AI 层、推荐方案层和工程审计层三者分别计量，禁止用“仓库总行数”冒充“最终产品行数”。

## 8. 最终判断

**最终产品有效代码为 180,449 行。**

相较最初基线已经下降 32.99%，相较本轮执行前正式包再下降 1.99%；ZIP 再下降 10.60%。发布包中已经没有用户配置、内容工件、本机路径、AVIF 二进制和本轮识别出的高置信工程审计闭包。

因此，当前问题不再是“还有大量明显没用的代码没有删”，而是“真实产品复杂度仍集中在少数大型 UI、配置和文档引擎模块”。下一步应做职责拆分和功能契约收口，而不是继续无边界删行。

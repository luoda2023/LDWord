# 参考文献页面信息架构分析与整合规划（2026-06-15）

状态：规划记录；后续按本文路线执行第一轮优化。

范围：模板编辑中的“参考文献”详情页，主要涉及 `src/ui/panels/template_reference_detail.py`、`src/modules/special/reference_format.py`、`src/config/feature_configs.py` 与 `src/ui/panels/template_summary_projection.py`。本文只讨论参考文献页面的信息架构、字段语义、交互分组和后续实现路径，不讨论题注、目录、页眉页脚等其它页面。

## 1. 结论摘要

当前参考文献页的主要问题不是控件本身，而是页面仍然按内部实现关系组织：

1. 顶部摘要卡后又出现说明文本，和其它已优化页面的“摘要即结果”原则不一致。
2. `段落样式`、`当前跟随正文`、`独立设置`、`引文规则` 分散在多张卡里，用户需要推断哪些设置真正生效。
3. 页面使用多个 `FlowSection`，视觉上像折叠面板；而当前模板详情页的方向是普通卡片展开，不让用户先理解折叠层级。
4. `引文规则` 这个名称容易被理解为正文中的引用规则，但这里实际配置的是参考文献条目的缩进和段后。
5. 独立样式里暴露了 `特殊缩进` 和 `高级缩进`，但执行层会用 `reference_style.hanging_indent_cm` 强制覆盖条目的特殊缩进，容易造成“我改了为什么不生效”的错觉。
6. 当前页面有多段说明和帮助文本：顶部说明、跟随正文提示、缩进说明、行距说明、规则说明。它们单独看都合理，堆在一起反而增加学习成本。

建议把参考文献页重新定义为：

> 配置参考文献条目的样式来源、文字排版、行距段距以及条目缩进规则的结果导向页面。

页面主体建议收敛为三块：

1. 样式来源
2. 条目样式
3. 条目规则

其中 `条目样式` 只在“独立设置”时显示；“跟随正文”时不再单独放一张继承说明卡，只在“样式来源”卡内显示当前正文样式摘要。

## 2. 当前实现梳理

### 2.1 配置模型

参考文献页面实际涉及两类配置：

1. `template.reference_style`
   - `hanging_indent_cm`
   - `space_after_pt`
   - `space_after_unit`
   - 还有 `font_cn/font_en/size_pt` 旧字段，但当前 UI 不直接编辑它们。

2. `template.styles["references_body"]`
   - 当用户选择“独立设置”时创建；
   - 用于参考文献条目的字体、字号、字形、对齐、行距等段落样式；
   - 未启用独立设置时，参考文献条目跟随正文样式。

### 2.2 执行语义

`src/modules/special/reference_format.py` 的执行层会：

- 识别参考文献区域；
- 只处理参考文献条目；
- 先取 `styles["references_body"]`，没有则取正文或 normal；
- 再应用 `reference_style` 的覆盖规则；
- 最终一定会执行 `apply_style_special_indent(base_style, "hanging", ref_cfg.hanging_indent_cm, "cm")`。

因此，参考文献条目的“特殊缩进”不是普通段落样式的一部分，而是参考文献条目规则的一部分。UI 应把悬挂缩进放在“条目规则”中，而不是让用户在“段落结构”里再设置一套特殊缩进。

### 2.3 当前 UI 结构

当前页面大致是：

```text
摘要卡：参考文献
  段落样式 / 引文规则
  说明文本

卡片：段落样式
  跟随正文 / 独立设置

卡片：当前跟随正文
  当前跟随正文: ...
  切换到“独立设置”后...

FlowSection：文字样式
FlowSection：段落结构
  对齐
  特殊缩进
  缩进说明
  高级缩进（折叠）
FlowSection：段落节奏
  行距类型 / 行距值
  段前 / 段后
  行距说明
FlowSection：引文规则
  悬挂缩进
  条目段后
  规则说明
```

这个结构的问题是用户必须理解：

- 跟随正文时哪些表单隐藏；
- 独立设置时哪些表单生效；
- 特殊缩进和悬挂缩进谁优先；
- 引文规则和段落样式有什么区别。

## 3. 主要问题与判断

### 3.1 顶部说明文本应删除

当前顶部说明：

```text
参考文献段落的排版样式。可跟随正文基准或设置独立样式。
```

这句话没有提供操作价值，且内容已经由“样式来源”卡承担。按照题注、页眉页脚、目录的优化标准，摘要卡下不应再放此类说明文本。

### 3.2 “当前跟随正文”不应独立成卡

跟随正文是一种样式来源，不是一个独立模块。单独放一张继承说明卡会让页面显得像还有一个可编辑区域。

建议：

- “样式来源”卡内放下拉选择：跟随正文 / 独立设置；
- 跟随正文时，在同卡内显示一行当前正文样式摘要；
- 独立设置时，直接显示“条目样式”卡。

### 3.3 “引文规则”应改为“条目规则”

`引文规则` 容易被理解成正文中的引用标注规则，例如 `[1]`、作者年份、交叉引用等。但当前字段只控制参考文献列表条目：

- 悬挂缩进；
- 条目段后。

建议改名为：

```text
条目规则
```

或更明确：

```text
条目缩进与段后
```

为了与摘要 tile 兼容，推荐主卡标题为 `条目规则`，字段仍叫 `悬挂缩进`、`条目段后`。

### 3.4 独立样式里的缩进设置应收敛

当前独立样式包含：

- 特殊缩进；
- 左缩进；
- 右缩进；
- 高级缩进折叠区。

但执行层会用 `reference_style.hanging_indent_cm` 覆盖特殊缩进。继续保留这些控件会产生错误预期。

建议第一轮优化：

- 从参考文献独立样式主流程中移除 `特殊缩进` 和 `高级缩进`；
- 保留 `对齐方式`，因为执行层会应用 alignment；
- 保留 `行距类型 / 行距值 / 段前 / 段后`，因为执行层会应用段落间距和行距；
- 悬挂缩进与条目段后放入 `条目规则`。

如果后续确实需要左/右缩进，应作为更明确的高级能力另行设计，不在本轮继续保留折叠区。

### 3.5 多余帮助文本应删除

应删除或不再展示：

- “切换到‘独立设置’后，会以当前正文样式为基础创建独立副本。”
- “缩进支持字 / 磅 / cm...”
- 行距说明文本；
- “引文规则由参考文献模块在排版时执行...”

原因：

- 这些说明解释的是内部机制；
- 多个灰色说明段会打断表单阅读；
- 控件本身和摘要预览应承担结果反馈。

## 4. 建议的信息架构

### 4.1 顶部摘要卡

保留两个摘要 tile：

- 条目样式
- 条目规则

建议把 `段落样式` 改为 `条目样式`，把 `引文规则` 改为 `条目规则`。

摘要文案应表达结果：

```text
条目样式：跟随正文
条目规则：悬挂缩进 0.74cm，条目段后 0 磅
```

### 4.2 卡片一：样式来源

目的：回答“参考文献条目的文字样式从哪里来”。

建议字段：

| 字段 | 来源 | 布局 |
| --- | --- | --- |
| 样式来源 | 是否存在 `styles["references_body"]` | 下拉选择 |
| 当前样式 | 派生自正文或独立样式 | 只读摘要行 |

“当前样式”可以显示：

```text
宋体 / Times New Roman / 小四 / 两端对齐
```

这不是说明文本，而是结果摘要。

### 4.3 卡片二：条目样式

只在“独立设置”时显示。

建议字段：

| 字段 | 来源 | 布局 |
| --- | --- | --- |
| 中文字体 | `styles.references_body.font_cn` | 左列 |
| 字号 | `styles.references_body.size_pt` | 右列 |
| 英文字体 | `styles.references_body.font_en` | 左列 |
| 字形 | `bold / italic` | 右列 |
| 对齐方式 | `alignment` | 左列 |
| 行距类型 | `line_spacing_type` | 右列 |
| 行距值 | `line_spacing_pt` | 左列 |
| 段前 | `space_before_*` | 左列 |
| 段后 | `space_after_*` | 右列 |

不再展示 `特殊缩进 / 左缩进 / 右缩进 / 高级缩进`。

### 4.4 卡片三：条目规则

始终显示。

建议字段：

| 字段 | 来源 | 布局 |
| --- | --- | --- |
| 悬挂缩进 | `reference_style.hanging_indent_cm` | 左列 |
| 条目段后 | `reference_style.space_after_*` | 右列 |

这张卡是参考文献执行规则的最小用户心智：参考文献条目的第二行从哪里开始、每条之间留多少空。

## 5. 实现边界

第一轮优化遵守：

1. 不新增预设、另存为、删除方案。
2. 不新增折叠区。
3. 不新增控件样式，只复用 `Card`、`InspectorForm`、`TemplateFormGrid`、`StyledComboBox`、`FontCombo`、`SizeCombo`、`SpacingInput`、`ToggleSwitch`。
4. 不暴露 `references_body`、`reference_style`、`doc_tree` 等内部名。
5. 不继续暴露与执行层冲突的“特殊缩进/高级缩进”。
6. 保留跟随正文与独立设置的配置能力。

## 6. 验收标准

后续实现完成后，应满足：

1. 页面主体由三块语义区域组成：样式来源、条目样式、条目规则。
2. 无顶部说明文本、继承说明文本、缩进说明文本、行距说明文本、规则说明文本。
3. `引文规则` 不再作为用户可见标题，改为 `条目规则`。
4. 跟随正文时不显示独立样式编辑表单，但样式来源卡显示当前样式结果。
5. 独立设置时显示条目样式卡，字段按两列表单排布。
6. 条目样式不再出现特殊缩进、高级缩进、左缩进、右缩进。
7. 条目规则始终可编辑悬挂缩进和条目段后。
8. 切换“独立设置”仍创建 `styles["references_body"]`；切回“跟随正文”仍移除该独立样式。
9. 字体、字号、字形、对齐、行距、段前、段后仍能写回独立样式。
10. 悬挂缩进和条目段后仍能写回 `reference_style`。
11. 顶部摘要、左侧导航摘要、dirty/save/restore 链路不退化。

## 7. 建议执行顺序

1. 把 `ReferenceDetail` 中的 `FlowSection` 替换为普通 `Card + InspectorForm`。
2. 合并“段落样式”切换和“当前跟随正文”摘要为一张 `样式来源` 卡。
3. 删除所有解释性说明 `QLabel`。
4. 移除独立样式中的特殊缩进和高级缩进控件。
5. 将 `引文规则` 改为 `条目规则`。
6. 同步更新摘要投影中的 tile 文案和导航摘要。
7. 补测试覆盖结构、文案清理、模式切换、样式写回、规则写回。

## 8. 本轮落地记录

已按上述方向完成第一轮优化：

1. 页面主体收敛为 `样式来源`、`条目样式`、`条目规则` 三张主卡。
2. `跟随正文 / 独立设置` 与当前生效样式合并到 `样式来源` 卡，不再额外显示继承说明卡。
3. 仅在独立设置时显示 `条目样式`，并保留字体、字号、字形、对齐、行距、段前、段后。
4. 从参考文献独立样式中移除与执行层冲突的特殊缩进、左缩进、右缩进和高级缩进。
5. 将用户可见的 `引文规则` 改为 `条目规则`，保留悬挂缩进和条目段后。
6. 移除参考文献页中的非必要说明文本，仅保留字段本身和摘要卡。
7. 将样式来源从大面积分段按钮改为标准下拉框，降低视觉权重并与其它参数页表单一致。

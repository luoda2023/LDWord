# 高层场景能力矩阵 N2.353 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决重放失败补偿终态归档 Worker 闭环

日期：2026-06-23

## 1. 定位

N2.352 已经把 final audit 中的 authorization refresh 与 remote snapshot review 项推进为可审计的 follow-up connector 交接记录，但链路仍有一个终态断点：final audit 与 follow-up connector 之后缺少统一的终态归档事实源。纯 dead-letter 只能停在 final audit，authorization/snapshot 只能停在 follow-up handoff，表格没有一个共同的 `archived` 状态来表示本轮补偿链路已经被终态归档。

N2.353 闭合这个前台归档 worker 首片：它不声明真实后台线程、跨进程调度器、自动授权刷新、远端快照自动重拉、跨 archive 重试或最终二次补偿自动执行已经完成；本轮只承诺终态归档入口、归档项、manifest、metadata、表格状态与成熟度 evidence 已经打通。

## 2. 本轮闭环

- final audit 不含 authorization/snapshot 后续项时，表格从 `audited` 显示 `Archive` 与 `Manifest`。
- final audit 含 authorization/snapshot 后续项时，必须先记录 follow-up connector；connector 后表格从 `followup` 显示 `Archive` 与 `Manifest`。
- `Archive` 消费 latest final audit record 与可选 follow-up connector record，不新建第二套事实源。
- dead-letter 项归档为 `dead_letter_terminal_archive_recorded`，路由为 `manual_dead_letter_archive`。
- authorization refresh 项归档为 `authorization_refresh_terminal_archive_recorded`，并保留来源 connector route。
- remote snapshot review 项归档为 `remote_snapshot_terminal_archive_recorded`，并保留来源 governance route。
- terminal archive manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_retry_replay_failure_compensation_terminal_archives`。
- profile metadata 回写 terminal archive status、id、item count、dead-letter count、authorization count、snapshot count 与 manifest path。
- 归档记录后，表格状态变为 `archived`，动作收敛为 `Manifest`，并阻止重复 Archive、重复 Connector、重复 Audit、重复 Execute 和重复 Queue。

## 3. 链路变化

N2.353 后链路变为：

```text
... -> Failure Queue -> Execute -> Handoff -> Final Audit
                                                |
                         +----------------------+----------------------+
                         |                                             |
                  no follow-up                                  follow-up required
                         |                                             |
                         v                                             v
                    Terminal Archive        Authorization/Snapshot Follow-up Connector
                                                                       |
                                                                       v
                                                               Terminal Archive
```

这个归档 worker 是前台首片：它把无法继续自动补偿的 dead-letter、需要授权刷新的 handoff、需要远端快照治理的 handoff 都归入同一个终态归档 manifest。它不把后续真实执行伪装成完成，只把“当前系统已经把失败补偿链路推进到可审计终点”这个事实固定下来。

## 4. 矩阵口径

新增 evidence：

- `question asset per-question asset library cross-package master subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive worker UI bridge`

剩余 gap 推进为：

- pack：`advanced question asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive durable scheduler UI`
- family：`advanced asset library cross-package asset master data subscription drift conflict batch failure recovery non-question asset family repaired historical Word output remote conflict decision retry replay failure compensation terminal archive durable scheduler UI`

这个口径表示 terminal archive worker UI 已从 L5 blocker 中退场；后续应继续处理 durable scheduler、跨 archive 持久调度、失败归档重试、后台恢复与最终二次补偿自动归档，而不是继续把前台归档入口列为未打通。

## 5. 控件样式约束

本轮继续沿用模板管理/素材管理既有控件体系：

- 动作仍使用紧凑表格内按钮：`Archive` 与 `Manifest`。
- 状态仍进入原状态列：`audited`、`followup`、`archived`。
- manifest drilldown 仍复用既有 `locate_manifest` 行动作，不新增解释型大卡片或独立场景控件语言。
- 后续 durable scheduler UI 也应保持同一控件约束：队列表、状态标签、动作按钮、只读 manifest drilldown、必要 confirmation guard。

# 高层场景能力矩阵 V33：产品成熟度升级审计与 L5 缺口矩阵

日期：2026-06-19

## 1. 背景

V32 已经把高层场景能力矩阵收敛成“全域高频任务矩阵 + 十三个验收槽位 + 边界裁决树”。N2.169 继续补一个更高层的缺口：现有 `scene_product_readiness` 能说明 pack/family 当前是 Yellow/L3、Orange/L4、Blue/Boundary 还是 Green/L5，但它还不足以回答：

- 为什么它还不能升到 Green/L5；
- 下一档该补 UI、执行、报告、样本、治理、边界、修复还是结构化输入；
- pack/family 是否都有同等可筛选的升级路径；
- dashboard、drilldown、release gate 是否能防止 static closed 被误读为产品完整。

因此本轮新增 `scene_product_maturity_upgrade_audit`。它不把任何 subject 升级为 Green/L5，而是把“不能升绿的原因”变成机器可读、可导出、可筛选、可进 release gate 的审计源。

## 5. Subject 粒度与防遗漏规则

N2.169 的 row 粒度为 27 条：

- 12 个 coverage pack；
- 15 个 planned family。

pack row 会带上自身 `pack_ids` 和关联 `family_ids`；family row 会反查覆盖它的 `pack_ids`。这样前台按 pack、family、query 或 source drilldown 时，不会出现“规划里有，但 UI 点不到”的断链。

特殊处理：

- row id 使用 `pack:<id>` / `family:<id>`，避免 `contract_delivery` 这种 pack/family 同名对象混淆；
- `blue_boundary` 的 next goal 是 `boundary_guarded_orange_l4`，表示先补清边界/插件/人工链路，再谈核心 Green/L5；
- `orange_l4` 的 next goal 是 `green_l5`；
- `yellow_l3` 的 next goal 是 `orange_l4`；
- Green/L5 必须没有 remaining product gaps，目前没有任何 subject 满足。

## 6. 与模板管理和场景控件一致性的关系

N2.169 不再把控件样式问题视为单纯 UI 整理，而是纳入成熟度升级条件：

- 如果场景页控件与模板管理同名参数出现不同单位、不同禁用语义、不同分组或不同交互方式，只能算 `ui_control` 或 `repair_confirmation` 缺口，不能升 Green/L5；
- 场景配置中的公式、输出、水印、固定版式、行高、内容控件、对象预检等参数，必须通过 control contract 或专项审计说明 owner；
- 模板管理可以提供共享控件语言和默认视觉基线，但不能吞掉场景级事实源、交付策略、边界状态和报告证据。

这意味着后续 N2.175“场景控件一致性运行时验收”不是美化项，而是 Green/L5 准入条件。

## 7. 与高频场景不遗漏的关系

V33 的核心判断仍然是：不要继续盲目新增顶层 pack。当前 12 个 pack 已经覆盖主要高频入口，真正的风险在于以下几类高频链路仍未产品化：

- 规则来源高频：学校论文、期刊投稿、项目申报、监管披露；
- 固定版式高频：答题卡、登记表、证书资料、HR 批量文书；
- 资料/资产高频：标书附件、售前产品资料、题目图片、资质归档；
- 专业边界高频：财务、法律、医疗、IP、翻译、审计/披露；
- 导入/AI 高频：PDF/OCR、LaTeX、AI 初稿、复杂图形；
- 交付高频：多版本、报告、归档包、失败隔离、artifact 浏览；
- 修复/确认高频：字段证据、歧义澄清、section scope、残留检查。

只要这些链路没有 UI、执行、报告、样本、边界和修复闭环，就只能称为 Yellow/L3、Orange/L4 或 Blue/Boundary，不能称为 Green/L5。

## N2.171 更新：InputSourceProfile 纳入 L5 缺口判断

V36 将输入事实源和渲染来源纳入 release gate、dashboard、drilldown 与 summary projection。产品成熟度不再只看 pack/family 是否静态闭合，也要看输入来源、结构化资料、边界输入和渲染来源是否可解释。

对 V33 的影响：

- dashboard source 从 16 增至 17，drilldown 从 11/184 增至 12/199。
- `exam_education`、`professional_disclosure`、`import_ai_boundary` 在 dashboard 中保留 `needs_depth` warning，用来表达 AI/专业判断/导入边界，不阻断 release gate，但阻止过度宣称 Green/L5。
- PDF/OCR、完整 LaTeX 工程、AI 内容生成、复杂图形生成必须继续留在 boundary/handoff/plugin/manual 视角。
- L5 后续准入应要求成功、降级、失败、人工门旅程 fixture 同时覆盖输入事实源和交付渲染源。

# 高层场景能力矩阵 V40 产品化闭环与高频边界验收规划

日期：2026-06-20

## 1. 文档定位

本文继续承接 V38/V39/N2.181/N2.182 的高层场景能力矩阵审计。上一轮已经把“有没有高频入口、有没有业务能力行、有没有 user journey fixture”推进到 release gate 可验：当前 12 个 coverage pack、15 个 planned family、17 个 business capability row、32 个 DOCX fixture 和 90 条 user journey path 已经能覆盖主要高频用户心智，且 user journey warning 与 business capability warning 均为 0。

但这仍不是 Green/L5。V40 的重点不是继续扩大顶层入口，而是回答一个更高层的问题：

```text
怎样才算一个高频场景能力真的完善？
```

V40 的结论：

```text
高层场景能力矩阵 = 高频任务域
  × 承载层
  × 输入事实源
  × 模板/控件契约
  × Word/OpenXML 风险面
  × 资料/规则/素材
  × 输出/批量/artifact
  × 成功/降级/失败/人工门旅程
  × 报告/修复
  × 专业/导入/非 Word 边界。
```

只要其中任何一段无法追到 UI、runtime、report、artifact、fixture 或 release gate，就不能把它描述成完整产品能力。

## 3. 高频不遗漏的三层定义

V40 将“不遗漏”拆成三层，避免把所有缺口都误解成“新增一个场景入口”。

| 层级 | 目标 | 判断标准 | 典型载体 |
| --- | --- | --- | --- |
| 高频入口层 | 用户自然说法不悬空 | request-cell、lexicon、ambiguous/negative/handoff 均有归属 | coverage pack、planned family |
| 业务能力层 | 高频任务有业务语义 | success/degraded/failure/manual journey 和边界承诺清楚 | business capability row |
| 产品闭环层 | 用户能完成、修复、验收 | UI、runtime、report、artifact、issue queue、fixture、release gate 同链 | L5 subject / maturity upgrade |

当前第一层和第二层已经基本闭合；第三层仍是主缺口。

后续新增需求时，不能只问“矩阵有没有这个名字”，必须问：

1. 用户高频说法是否已进入 request-cell 或 lexicon。
2. 该需求是否已有承载层，还是需要新增 profile/schema/preset/manual gate。
3. 成功、降级、失败或人工边界是否能形成 journey path。
4. Word/OOXML 风险是否有真实 fixture 和 action。
5. 输出产物、报告和修复入口是否能回到前台。

## 5. 边界裁决树

新增需求先走裁决树，不先新增按钮。

1. 是否要求 Word 原生交付。不是 Word 核心交付时，进入 negative 或 external plugin。
2. 是否只是外观样式、页边距、标题、页眉页脚、目录、题注、表格外观。是则归模板管理和 TemplateConfig。
3. 是否是场景侧复用模板样式控件。是则必须继承同名、同单位、同禁用语义、同 runtime field。
4. 是否是资料事实、人员、项目、产品、签章、附件、图片。是则归 MaterialSchema / AssetsPanel。
5. 是否是字数、词数、图表、公式、参考文献、规则来源。是则归 CountProfile / RuleSourceGovernance。
6. 是否是输出版本、命名、目录、PDF/ZIP/report/manifest/intermediate。是则归 DeliveryPreset / OutputConfig。
7. 是否是多记录、多人员、多公司、多项目、多模板。是则归 BatchPreset。
8. 是否是固定版位、证书、答题卡、套打、固定行高。是则归 fixed-layout profile 和 Word risk。
9. 是否触达字段、批注、修订、内容控件、文本框、OLE、宏、嵌入包。是则必须先走 ObjectPreflight。
10. 是否涉及法律、财务、审计、专利、医学、翻译质量、AI 内容质量、OCR/LaTeX 无损转换。是则进入 PluginManualGate。
11. 是否能从导入边界 handoff 到目标 pack/family。能则必须有 handoff 报告、置信度和回退策略。

顶层 pack 新增条件必须同时满足：

| 条件 | 标准 |
| --- | --- |
| 稳定用户心智 | 用户长期以该大类表达，而不是一次性行业别名 |
| 独立事实源 | 输入事实源、资料 schema 或规则 profile 明显不同 |
| 独立交付 | 输出版本、目录、artifact 或失败策略明显不同 |
| 独立 Word 风险 | OOXML 风险组合不能由现有 pack 承载 |
| 独立证据链 | 有 request-cell、fixture、report、repair、release gate 计划 |

## 6. 控件一致性与模板管理继承

场景配置中的控件样式控制必须与模板管理保持同一套语言。场景可以组合、隐藏、禁用或按业务原因覆盖模板参数，但不能改名、换单位、写到不同字段或绕过执行消费链。

| 控件族 | 场景侧必须保持 | 当前/后续重点 |
| --- | --- | --- |
| 左缩进/右缩进 | 与模板管理同名、同单位、同数值步进，可同一行展示 | UI 布局可优化，但字段不能分裂 |
| 段前/段后 | 保持“段前/段后”命名和磅值语义，可同一行展示 | 不能改成不可追溯的前距/后距 |
| 特殊缩进 | 必须能切换无/首行/悬挂；无时禁用数值并归零 | 不能只显示文本，必须可交互切换 |
| 行距类型/行距值 | 类型和值联动；固定/多倍/最小值的单位语义清楚 | UI 可选但 runtime 不消费时只能标 boundary/planned |
| 普通表格参数 | TableConfig 只管通用表格外观，如宽度、边框、对齐 | 不混入固定版位行高 |
| 固定行高 | 归 fixed-layout profile，对应 Word `w:trHeight` | 不再作为普通 `TableConfig.row_height_pt` 残留参数推进 |
| 水印/输出/公式 | 归场景能力板块，但复用 control contract 命名和报告字段 | 不当成模板杂项，也不在无执行消费时表现为可执行 |
| 资料/素材控件 | 归 MaterialSchema/AssetsPanel，缺项进入 repair target | 不停留在孤立 warning |

统一验收链：

```text
Template control contract
-> ScenePanel runtime control
-> resolver / pipeline consumer
-> report field
-> issue queue / repair target
-> fixture / test / release gate
```

如果链路中任一段缺失，UI 只能显示为 planned/boundary，不能以可执行开关呈现。

## 7. Word/OpenXML 反推的风险视角

高频场景不能只从业务名出发，还要从 Word 本身反推缺口。下面这些 XML 面若没有动作和证据，场景就不完整。

| Word/OpenXML 面 | 高频触发场景 | 必须动作 |
| --- | --- | --- |
| `word/document.xml` paragraph/run | 全部格式化、论文、合同、长文档 | 范围定位、样式清理、差异报告 |
| `word/styles.xml` | 模板基线、标题、正文、表格样式 | TemplateBaseline、ControlContract |
| `word/numbering.xml` | 论文、公文、合同条款、技术手册 | 编号保留/重建策略、报告证据 |
| `w:tbl` / `w:trHeight` | 表单、证书、答题卡、套打 | fixed-layout profile、预览、残留报告 |
| `w:sectPr` / headers / footers | 论文、公文、合同、长文档 | WordStoryScope、页眉页脚/页码策略 |
| fields / TOC / PAGE / REF | 目录、页码、交叉引用、题注 | ObjectPreflight、update/report/repair |
| comments / revisions | 合同、投稿修回、审阅稿、披露材料 | preserve/block/manual/report |
| hidden text | 论文、披露、内部稿、归档稿 | 可见性策略、边界报告 |
| `w:txbxContent` / shapes | 证书、套打、复杂版式 | fixed-layout profile、preflight、residue check |
| `w:sdt` content controls | 表单、合同、资料填充 | MaterialSchema、field mapping、residue report |
| footnotes / endnotes | 学术、投稿、技术文档 | ReferenceCitation、CountProfile |
| relationships / media | 图片、产品素材、签章、附件 | AssetInventory、missing asset report |
| embeddings / OLE | 资质包、报价表、长文档附件 | ObjectPreflight、archive manifest、manual boundary |
| macros / ActiveX | 外部导入、旧模板、安全风险 | block/manual/report |
| settings/protection | 表单保护、合同修订保护 | preserve/report/manual confirmation |

V40 对固定行高保持明确裁决：`TableConfig.row_height_pt` 不应作为普通表格参数继续悬挂；固定行高对应 Word `w:trHeight`，只在 fixed-layout profile 中产品化。

## 8. L5 成熟度验收模型

静态闭合不等于 Green/L5。V40 建议继续把场景能力分成五级：

| 等级 | 定义 | 用户承诺 |
| --- | --- | --- |
| L1 Gray | 只有规划或概念 | 不承诺可用 |
| L2 Blue Boundary | 边界、人工门、负例或插件门清晰 | 可以解释为什么不能自动完成 |
| L3 Yellow | 有 route、profile、schema、preset 或 first-slice 执行证据 | 可试用，必须提示限制 |
| L4 Orange | UI、runtime、report、fixture、release gate 基本闭合 | 可作为主流程能力，但保留缺口 |
| L5 Green | 高频成功、降级、失败/人工门路径均产品化，真实业务 fixture 足够 | 可稳定推荐给普通用户 |

L5 必须同时满足：

1. 前台可发现：用户能在场景、profile、drilldown 或修复入口看见它。
2. 可配置：控件继承模板管理语言，且禁用/边界态清楚。
3. 可执行：pipeline 有 consumer，不只是 UI 字段。
4. 可报告：成功、降级、跳过、失败、人工门都写入报告。
5. 可修复：资料缺项、对象风险、输出冲突等能进入 issue queue。
6. 可验收：artifact browser 能打开、分组、解释主要产物。
7. 可回放：fixture、drilldown、release gate 和测试能复现核心路径。
8. 可解释边界：专业判断、导入质量、AI 内容质量、非 Word 输出不越界。

## 9. 下一阶段路线

当前不应继续扩张顶层入口，而应按 L5 缺口推进产品深度。

| 优先级 | 路线 | 首个闭环目标 | 覆盖价值 |
| --- | --- | --- | --- |
| P0 | 新增 fixture 证据进入 runtime/report/artifact | project/product/professional/import 的 degraded/manual 第一片进入执行报告、修复入口和 drilldown | 让 N2.182 不是只停在 registry |
| P0 | fixed-layout profile 前台化 | 固定行高、文本框、内容控件、证书/表单/答题卡可预览、可报告、可修复 | 覆盖表单、HR、试卷、证书、套打 |
| P0 | exam JSON -> Markdown preview -> Word multi-version | 同一结构化源渲染学生版、教师版、答案版、解析版，复杂图/AI 质量进 manual gate | 覆盖教育试卷高频闭环 |
| P0 | report/artifact drilldown 深化 | 从报告跳到 output、compare、manifest、intermediate、material package 和 repair target | 覆盖所有交付型场景 |
| P1 | CountProfile / RuleSource UI 化 | 中文论文、英文投稿、项目申报的规则来源、口径、适用范围、过期状态可见 | 解决“字数/词数/规则”长期边界混乱 |

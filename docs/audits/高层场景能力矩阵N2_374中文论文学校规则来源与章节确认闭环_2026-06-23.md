# 高层场景能力矩阵 N2.374 中文论文学校规则来源与章节确认闭环

日期：2026-06-23

## 目标

N2.374 承接 `chinese_academic` pack 与 `thesis_cn` family 的相邻 L5 blocker：`school rule source governance UI`、`section classifier confirmation`、`school profile editing` 与 `section-scope confirmation`。

此前中文论文已经具备 thesis 场景入口、`school_thesis` / `thesis_cn` CountProfile、规则来源治理 registry、引用/公式置信度报告、对象预检与基础 DOCX 样例。但“学校规则来源选择”和“章节分类确认”仍停在规划或后台 registry 视角，无法在场景配置、材料 schema、DOCX fixture、报告期望、用户旅程和成熟度审计之间形成闭环。

本轮目标是把这组能力产品化到可验证链路：用户进入中文论文场景时可以看到规则来源/章节确认的证据；矩阵能证明这不是泛化计数 profile；同时仍保留明确边界：本地默认规则不等于所有学校的权威细则，严格学校合规必须依赖经审核的学校规则数据。

## 闭合内容

1. 场景材料契约
   - 新增 `thesis_school_rule_context_v1` MaterialSchema。
   - 必填字段：`school_rule_source_id`、`section_classifier_decisions`。
   - 可选字段：`school_name`、`rule_source_version`、`reviewed_by`、`reviewed_on`、`confirmed_by`、`confirmed_at`。
   - batch mode 为 `review_context`，明确不把本地默认规则当作所有学校的权威依据。

2. Family 与内置场景接线
   - `thesis_cn` family 正式挂载 `thesis_school_rule_context_v1`。
   - `create_thesis_scene()` 默认带上该 material schema。
   - `apply_planned_scene_family_defaults()` 会合并该 schema，但仍保持 `require_material_package=False`，避免普通论文格式化被学校规则包硬阻断。
   - `chinese_academic` coverage pack 增加 `material_schema` 能力轴，并补 `structured_input` workflow，避免矩阵轴和工作流脱节。

3. 规则来源治理与 DOCX fixture
   - `school_thesis_rule_defaults` 规则来源治理记录绑定 `thesis_school_rule_context_v1`。
   - 新增 `chinese_academic_school_rule_section_confirmation` DOCX fixture，覆盖 `paragraph_run`、`fields`、`comments`、`hidden_text`。
   - fixture 绑定 `chinese_thesis_count` 高频请求样本，报告期望包含 `rule_source_governance`、`school_rule_source_selection`、`section_classifier_confirmation`、`count_report`、`object_preflight`。
   - 用户旅程新增 `manual_boundary:chinese_thesis_count`，明确严格学校规则和章节分类需要人工确认。

4. 场景配置 UI 证据
   - 场景概览新增 `academic_rule_source_evidence` summary item。
   - 该卡片展示 `thesis_school_rule_context_v1`、规则来源/章节确认报告项和中文论文确认 fixture。
   - tooltip 明确：覆盖的是规则来源选择、章节分类确认、计数报告与对象预检；不承诺本地默认规则适用于所有学校。

5. 成熟度同步
   - `chinese_academic` 从 `orange_l4` 升级为 `green_l5`。
   - `thesis_cn` 从 `yellow_l3` 升级为 `green_l5`。
   - 矩阵摘要推进为 13 个 Green/L5、14 个 L5-blocked、27 个 remaining gaps、37 个 DOCX fixtures、53 个 request cells、97 条 user journeys。

## Word/OOXML 视角

- 中文论文的规则来源和章节分类不能只存在于 CountProfile 名称里；它们需要进入 schema、fixture、报告期望和场景概览证据。
- `fields` 用于承载目录、引用、公式和交叉引用等 Word 原生对象风险；`comments` 用于承载人工确认/规则来源提示；`hidden_text` 用于锁定隐藏文本和统计口径边界。
- `section_classifier_confirmation` 是确认链路，不是自动语义理解引擎。系统可以提示、记录、要求确认；不能自动保证“摘要、正文、参考文献、附录”等章节分类一定符合某学校的最新细则。

## 场景边界

- `chinese_academic` 覆盖中文学位论文、课程论文、综述、开题报告等格式化、计数、引用/公式和交付场景，不吸收英文期刊投稿、考试生成或专业审查。
- `thesis_cn` 的 Green/L5 表示产品链路已经打通：规则来源上下文、章节确认、计数 profile、DOCX fixture、报告和 UI 证据均可追溯。
- Green/L5 不表示已经内置所有高校的权威规则库，也不表示用户上传的规则表已经自动审核为可信来源。后续真实学校 profile、规则表导入、版本审核和 reviewer metadata 仍是增强方向。

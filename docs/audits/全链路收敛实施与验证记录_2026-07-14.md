# 全链路收敛实施与验证记录（2026-07-14）

## 目标

本轮不是继续扩展功能，而是把当前大批改动收敛到以下可验证状态：

1. 源文件和既有交付产物不会因失败、路径冲突或并发而被意外覆盖。
2. 普通、资料装配、试卷、公文四类运行入口共享明确的预检、staging、提交和回滚语义。
3. 场景、资料包、模板和工作模式切换具有一致的未保存更改处理协议。
4. 字段、时间轴、运行时 Context 和 profile 的身份及所有权不会跨对象污染。
5. 测试验证真实行为和失败路径，不再把源码关键词存在当成业务闭环证明。
6. 高风险模块形成清晰边界，不以继续增加共享 `self` mixin 的方式掩盖复杂度。

## 实施原则

- 所有最终产物先写 staging；只有全部验证通过后才允许提交。
- 源路径、最终路径和临时路径必须使用解析后的规范身份比较，而不是字符串比较。
- 多产物提交必须有统一 ownership；失败时恢复既有产物并清理本次 staging/backup。
- UI 保存采用 prepare/commit/cancel 协议；不得在确认前或事务中途切换 owner scope。
- 删除字段必须处理所有引用 owner；不能仅删除字段表面的值和 scope。
- 运行时任务快照不得反向写入资料包，除非携带匹配的显式 package/profile identity。
- 每项修复至少包括一个先前可失败的行为测试或失败注入测试。
- source-marker 只允许标注为静态可追溯证据；不得单独提升运行时、交付或发布就绪结论。

#### C. P1：official 文种、schema 与 master 身份仍有四套 owner

#### D. P1：v5 资料包字段 registry 在四条链路上分裂

6 个 tracked official builtin package 共含 74 个 `fields`/`declared_field_keys`，但 `field_scopes` 全为空；排除 6 个 `document_type` 元数据后，有 68 个隐式活动字段。当前 `material_field_inventory.py` 会在读取时把它们全部猜为 fixed 并写回 scopes，这正是未发布阶段不应保留的多源兼容和读时迁移。

然而不能直接删除 fallback，也不能把 68 项机械标成 fixed：

- 依据 official `source_scope`，约 17 项属于 organization default、40 项属于单次 task、5 项 `printing_date` 属于 generated、6 项归档字段属于 archive metadata；现有二态 fixed/floating 无法诚实表达后 11 项。

- 当前同一包会出现：Workbench readiness 按 active scopes 判 0 映射并显示红；direct/runtime 直接相信 `entity_data` 可继续；Assets scope-only 投影为空；batch 又直接合并全部 `profile.fields`。

- official export、mapping import、CSV/Excel batch import、imported-profile 清洗、official table batch、附件准备和 timeline anchor 等生产写路径仍能继续制造“有 fields/declared、无 scopes”的包；仅迁移 6 个 seed JSON 会很快复发。

发布前需要先决定 builtin 是“可复用模板”还是“ready-to-run 示例”，再建立 `field_scopes` 或更完整 owner model 为唯一 registry；统一 Assets/direct/batch/runtime projection；强化 v5 semantic validator；迁移所有 producer 和 6 个内置包；最后删除 legacy fallback 与 `declared_field_keys` 的 registry 语义。

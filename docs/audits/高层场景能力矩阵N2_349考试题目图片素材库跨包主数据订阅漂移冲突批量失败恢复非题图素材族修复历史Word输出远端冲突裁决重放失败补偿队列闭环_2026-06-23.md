# 高层场景能力矩阵 N2.349 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决重放失败补偿队列闭环

## 1. 定位

N2.348 已经把 `remote_state_review_completed` 后的 retry/replay 接成真实远端裁决重放：前台可执行 `Replay`，并记录 replay manifest 与 metadata。N2.349 继续处理 replay 的失败态：当复核后的重放仍然失败、权限不足或再次远端冲突时，不再只停留在 replay 记录里的 `needs follow-up`，而是显式进入失败补偿队列。

本轮只承诺“失败补偿队列 UI/记录/manifest/metadata/测试闭合”，不声明补偿执行、后台 worker、自动重试调度、死信处理或最终二次补偿归档已经完成。

## 2. 本轮闭环

- replay 非完成态下，非题图素材族恢复表格提供 `Queue` 与 `Manifest`。
- `Queue` 从最新 retry/replay record 派生 compensation queue record，避免另起第二套事实源。
- compensation queue items 按失败原因分为 `permission_required`、`remote_conflict`、`retry_replay_failed`。
- 队列项给出后续补偿动作：刷新授权后重放、刷新远端快照并重开冲突治理、人工补偿或 dead-letter 复核。
- 队列 manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_retry_replay_failure_compensation_queues`。
- metadata 回写 `master_subscription_drift_non_question_asset_family_remote_conflict_decision_retry_replay_failure_compensation_queue_*` 字段。
- 列表投影、状态标签、按钮策略和 manifest 优先级同步改为 queue > replay > review > execution > queue governance > decision > connector。

## 3. 链路变化

N2.349 后的失败链路变为：

```text
... -> Queue -> Execute -> Review -> Replay
                              |
                              v
                         Failure Queue -> Manifest
```

成功 replay 仍然保持 `replayed -> Manifest`；只有 replay status 不是 `retry_replay_after_review_completed` 时，前台才展示 `Queue`。补偿队列记录后，行状态变为 `queued`，前台只保留 `Manifest`，为后续补偿执行入口留下明确承载点。

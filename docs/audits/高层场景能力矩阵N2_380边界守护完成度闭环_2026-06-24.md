# 高层场景能力矩阵 N2.380 边界守护完成度闭环

本文承接 N2.378 边界能力矩阵与 N2.379 外部 handoff 合同。N2.380 解决一个口径问题：N2.379 后剩余 6 个 `L5-blocked` 主题已经不是普通未完成缺口，而是有意保留的 Blue/Boundary 外部能力边界。

## 结论

新增 `scene_boundary_guarded_completion_audit`，将 6 个 Blue/Boundary subject 标记为 `boundary_guarded_complete`。

这不是 Green/L5。它表达的是：

- 核心格式化系统不承诺外部专业判断或真实外部插件执行；
- 但产品已经具备边界能力、人工/插件门禁、外部 handoff 合同、回执字段、失败策略、报告证据和不承诺声明；
- 因此这些条目应从“普通没做完”中分离出来，作为“边界守护已完成”的产品状态。

## 守护完成准入

每个 Blue/Boundary subject 必须同时满足以下证据：

| 证据 ID | 含义 |
| --- | --- |
| `blue_boundary_readiness` | readiness 仍为 Blue/Boundary，不误升 Green/L5 |
| `maturity_gap_retained` | maturity 仍保留外部缺口，防止静默承诺 |
| `boundary_capability_ready` | N2.378 的边界能力矩阵 ready |
| `plugin_manual_gate_ready` | plugin/manual gate ready |
| `external_handoff_contract_ready` | N2.379 的外部 handoff 合同 ready |
| `excluded_core_claims_declared` | 明确列出核心系统不会承诺的外部结论 |

## 与成熟度的关系

N2.380 不删除 `remaining_product_gaps`，也不把 6 个 subject 升成 Green/L5。原因是这些能力的最终结果依赖真实外部插件、专业人员或第三方系统。

新的产品口径是：

- `green_l5`：核心系统可以完整承诺的成熟能力；
- `boundary_guarded_complete`：核心系统不能承诺外部结论，但边界、交接、回执和失败策略已经闭环；
- `boundary_guarded_incomplete`：存在 Blue/Boundary 主题，但缺少能力矩阵、gate、handoff 合同、报告或不承诺声明。

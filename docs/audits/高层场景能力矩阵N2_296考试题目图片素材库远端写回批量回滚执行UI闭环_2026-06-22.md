# 高层场景能力矩阵 N2.296 考试题目图片素材库远端写回批量回滚执行 UI 闭环

## 1. 背景

N2.295 已经把批量执行结果沉淀为事务报告，并把部分完成批次中的成功项标记为 `rollback_candidate`。但这些候选仍停留在报告记录里，无法真正把远端素材库恢复到执行前的候选值。

本轮闭合“批量回滚执行 UI 首片”。它不做后台调度、不做回滚失败二次队列，也不做回滚前远端当前快照校验；只负责从已生成的事务报告里读取待回滚候选，按报告中保存的 source、asset_id、alt_text 候选值执行远端回滚，并保存独立审计记录。

## 2. 已闭合能力

- 远端写回批量事务报告表在报告已生成且存在待回滚候选时显示“执行回滚”。
- “执行回滚”只处理 `compensation_action=rollback_candidate` 且 `rollback_available=true` 的报告项。
- 已在历史回滚执行中成功的候选不会重复出现在 pending 集合中。
- 回滚执行复用当前远端素材授权控件，并按原写回 source 匹配授权 header，避免跨库误用 token。
- 回滚请求使用独立 connector 标识 `question_figure_library_remote_writeback_batch_rollback`。
- 回滚请求 payload 写入 `metadata.source`、`metadata.asset_id`、`metadata.alt_text`，取自事务报告保存的 rollback 候选值。
- 回滚请求 payload 同时写入 `rollback_from`，记录被回滚的远端写回值。
- 回滚执行使用独立幂等键 `qfig-rollback-*`。
- 回滚执行结果按 success、permission、conflict、failed、skipped 分类。
- 批量回滚完成后追加 `question_figure_library_remote_writeback_batch_rollback_execution` 历史记录。
- 回滚执行记录保存 report changed_at、execution changed_at、plan signature、attempted/success/failed/permission/conflict/skipped 计数和 JSON 化结果项。
- 报告表在回滚成功后显示“回滚已执行”，补偿列显示“回滚成功 N/N；待回滚 0”。
- 新增测试锁定“一项成功、一项跳过 -> 生成事务报告 -> 执行成功项远端回滚 -> payload 写回原 source/asset_id/alt_text -> 记录回滚执行审计”的链路。

## 4. 仍不宣称完成

- 回滚失败队列；
- 权限失效后的回滚授权重试队列；
- 回滚冲突处理队列；
- 回滚前远端当前快照校验；
- 回滚二次补偿与人工审批；
- 回滚任务后台化、并发控制、限流、取消和指数退避；
- 回滚 manifest 文件导出和独立 drilldown；
- OAuth/SSO 登录、token 自动续期、签名 URL 自动续签；
- 组织、角色、题库权限申请或审批；
- 跨资料包素材主数据版本系统。

# 运行时目录与母版打开入口横向审计（2026-07-09）

## 背景

试卷版“打开母版文件夹”会打开 `exam_masters/user/`。该目录累计出现大量
`user_default_exam_copy*.docx` 与 `user_imported_exam*.docx`，容易让人误判为
“内置母版库有很多产品资源”。

## 结论

这些文件不是内置母版，而是历史运行时副本：

- `create_exam_blank_master_copy()` 会把当前试卷母版复制到 `exam_masters/user/`。
- `import_exam_blank_master_docx()` 会把外部 DOCX 复制到 `exam_masters/user/`。
- `_unique_docx_path()` 会自动避让重名，因此长期调试后会递增出 `_2`、`_3` 等文件。
- `sync_user_exam_blank_master_files()` 会跳过 `user_default_exam_copy*` 与
  `user_imported_exam*` 这类程序管理文件，因此它们不会自动灌入母版下拉列表。

## 产品进入风险

当前风险分两类：

1. Git 提交风险：`exam_masters/user/` 已被 `.gitignore` 忽略，默认不会进入提交。
2. 发布打包风险：当前 PyInstaller 脚本只显式加入 `defaults` 和图标资源，不会整包加入
   `exam_masters/user/`。但手动源代码发布时仍可能误带运行时目录。

本次补强：

- 发布检查脚本新增 `exam_masters/user`、`exam_samples`、`artifacts`、`output` 运行时目录警告。
- `.gitignore` 新增 `config_library/plans/*/user/`、`config_library/templates/*/user/`、
  `config_library/masters/*/user/`，防止未来方案、模板、母版的用户桶误入产品资源。

## UI 导向修复

修复前：

- `ScenePanel` 试卷母版详情页的“打开母版文件夹”固定打开 `USER_EXAM_MASTER_DIR`。
- `MastersPanel` 每个试卷母版行的“打开母版文件夹”也固定打开 `USER_EXAM_MASTER_DIR`。

修复后：

- 两个入口都改为“打开当前母版文件夹”。
- 内置母版打开 `exam_masters/builtin/`。
- 用户副本或导入母版才打开 `exam_masters/user/`。

## 横向复核

| 区域 | 当前行为 | 结论 |
| --- | --- | --- |
| 方案管理 | 打开当前方案 JSON 所在目录；无当前文件时回退到当前模式的 user 方案目录 | 正常 |
| 模板管理 | 打开当前模板 JSON 所在目录；无当前文件时回退到当前模式的 user 模板目录 | 正常 |
| 母版管理 | 已改为打开当前母版 DOCX 所在目录 | 已修复 |
| 资料包 | 打开当前资料包/归档实际路径 | 正常 |
| 编号方案 | 打开 `heading_numbering_schemes` 用户编号方案目录 | 名称有重叠，但不是工作模式方案 |

## 后续建议

- 不自动删除 `exam_masters/user/` 中的历史文件，避免误删用户可能还要的母版副本。
- 后续可以增加一个“清理未引用用户母版”的显式工具：先列出未被任何方案引用的 DOCX，再由用户确认移动到归档目录或删除。

# 高层场景能力矩阵 N2.237 考试题目图片远端缓存清理前台确认 UI 闭环

## 1. 背景

N2.231 已经把远端题图缓存清理推进到 dry-run 预览，N2.232/N2.236 又补上运行级和共享缓存目录级 `cleanup_history.json`，AssetsPanel 也能查看最近清理任务历史。

但 N2.236 后仍有一个产品面断点：用户能看到 dry-run 候选项，却没有前台确认入口；如果后续直接进入真实删除或后台任务，会缺少“用户明确确认过这次预览”的证据。本轮只闭合前台确认首片：在共享缓存目录被选中、且最新清理历史是有候选项的 dry-run 时，AssetsPanel 显示确认摘要和危险确认按钮；点击后写入目录级确认 artifact。

## 2. 闭合范围

本轮闭合：
- AssetsPanel 在 `question_figure_shared_cache_cleanup_table` 下方新增清理确认摘要行；
- 只有最新 `cleanup_history.json` 记录满足 `mode=dry_run`、`dry_run=true`、`status=previewed` 且候选数大于 0 时，`确认清理计划` 按钮启用；
- 前台摘要显示 stale index 候选数、孤儿文件候选数和来源任务；
- 点击按钮不会直接删除文件，而是写入 `<shared_cache_dir>/cleanup_confirmation.json`；
- 点击后同步写回当前资料档字段：`remote_asset_cache_cleanup=true`、`remote_asset_cache_cleanup_dirs=<shared_cache_dir>`、`remote_asset_cache_cleanup_dry_run=false`、`remote_asset_cache_cleanup_confirmed_task_id` 和 `remote_asset_cache_cleanup_confirmation_id`；
- 同一个 dry-run `task_id` 已确认后，按钮自动禁用并显示已确认状态；
- 无 history、非 dry-run、无候选项或已执行清理的目录不会启用确认按钮；
- 共享缓存目录切换时，目录条目、命中率历史、清理历史和确认摘要同步刷新；
- 共享缓存相关表纳入 AssetsPanel 统一表格样式，确认按钮使用危险按钮变体；
- 成熟度矩阵增加 `question asset remote cache cleanup confirmation UI bridge` evidence。

本轮不做：
- 真实删除动作的前台直接执行；
- 跨 profile 后台定时清理；
- 全局任务列表、任务取消、任务重试；
- 后台队列、并发调度和断点续传；
- 清理策略编辑 UI；
- 真实素材库 API 登录、续期和签名 URL。

## 3. 数据链路

输入事实源：
```text
<shared_cache_dir>/cleanup_history.json
```

前台确认 artifact：
```text
<shared_cache_dir>/cleanup_confirmation.json
```

资料档执行参数：
```text
remote_asset_cache_cleanup=true
remote_asset_cache_cleanup_dirs=<shared_cache_dir>
remote_asset_cache_cleanup_dry_run=false
remote_asset_cache_cleanup_confirmed_task_id=<source_task_id>
remote_asset_cache_cleanup_confirmation_id=<confirmation_id>
```

确认记录字段：
```text
confirmation_id
source_task_id
status
action
cache_dir
stale_index_entry_candidate_count
orphan_file_candidate_count
candidate_total
source_updated_at
confirmed_at
requires_execute_cleanup
```

前台入口：
```text
素材管理 -> 图片材料 -> 共享缓存目录表 -> 选中目录 -> 清理历史表 -> 清理确认摘要 -> 确认清理计划
```

## 4. 边界说明

`cleanup_confirmation.json` 是用户确认 dry-run 结果的可审计证据，不等于已经执行清理。确认后当前资料档会写入下一次执行清理所需参数；真正删除仍只会在后续生成/任务链路消费这些字段时发生。后续如果接入全局任务队列，应由任务调度器读取确认记录、匹配来源 dry-run task、再触发 `remote_asset_cache_cleanup=true` 且 `dry_run=false` 的执行链路。

本轮因此只把“前台确认 UI”从空白推进到可记录、可测试、可审计的首片，不宣称完成后台任务系统或真实删除确认闭环。

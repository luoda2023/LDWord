# 高层场景能力矩阵 N2.271 考试题目图片对比修复批量应用事务台账 Artifact 闭环

日期：2026-06-21

## 1. 本轮目标

N2.271 接在 N2.270 的“批量应用事务台账首片”之后，补上事务台账的可留存 artifact。N2.270 已经能在 payload、Markdown 和 Workbench 摘要里展示 `batch_apply_transaction_manifest`，但它仍主要是运行时状态。本轮把该 manifest 写成独立 JSON 文件，让它可以被打开、交付、复查，也能作为后续后台任务中心的输入。

## 2. 新增 Artifact

新增文件：

```text
question_figure_batch_apply_transaction_manifest.json
```

写入位置：

- 默认写入 `question_figure_batch_apply_audit.json` 所在目录；
- apply 成功追加审计后写入一次；
- rollback 成功追加审计后覆盖写入最新事务状态。

manifest payload 新增：

- `artifact_supported`
- `artifact_written`
- `artifact_path`
- `artifact_write_blockers[]`

写入失败时，主链路不反向回滚已经完成的 Word apply/rollback，只在 manifest 中保留 `artifact_written=false` 和写入 blocker。

## 3. Workbench 入口

Workbench artifact detail 继续展示事务摘要：

```text
transaction=<status>; tx=<n>; rolled_back=<n>; tx_artifact=<written|not_written>
```

同时新增独立 artifact item：

```text
kind=question_figure_batch_apply_transaction_manifest
label=transaction_manifest
fragment=question-figure-batch-apply-transaction-manifest
```

这样用户不只是在候选队列摘要中看到台账状态，还能在产物列表中直接打开对应 JSON。

## 4. 边界说明

N2.271 只承诺事务台账 artifact 可写入、可展示、可验证，不承诺：

- 后台任务中心；
- 跨多 docx 调度；
- 原子事务；
- 自动回滚；
- 文件快照系统；
- 远程素材库写回；
- 失败后自动补偿执行。

它把 N2.270 的状态基座从“运行时可计算”推进为“运行后可留存”。

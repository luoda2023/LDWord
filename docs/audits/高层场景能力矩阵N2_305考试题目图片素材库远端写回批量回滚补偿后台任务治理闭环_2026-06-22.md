# 高层场景能力矩阵 N2.305 考试题目图片素材库远端写回批量回滚补偿后台任务治理闭环

## 1. 背景

N2.304 已经把批量回滚/补偿结果沉淀为 manifest，并在事务报告表里提供“生成清单 / 定位清单”。但完成清单之后，用户仍缺少一个统一视角来判断整条批量链路到底有哪些任务、各自处于什么阶段、下一步应该定位到哪里。

本轮闭合 N2.304 后的 `background task governance` 缺口首片：新增远端写回批量后台任务治理表。它不是线程池，也不声明真正异步调度、取消、限流或指数退避已经完成；它承诺把现有批量执行、事务报告、回滚执行、二次补偿执行和 manifest 导出投影成一致的任务台账，并提供前台 drilldown。

## 2. 已闭合能力

- 远端写回区域新增 `question_figure_asset_library_remote_writeback_background_task_table`。
- 表格列为“任务 / 阶段 / 状态 / 进度 / 治理 / 处理”，与既有远端写回表格共享主题样式、按钮 variant 和表格行为。
- 批量写回执行记录投影为“批量写回 / 执行”任务，展示成功数、尝试数、权限/冲突/失败摘要，并可定位批次。
- 事务报告投影为“事务报告 / 补偿冻结”任务，展示待回滚余量与回滚候选，并可定位事务报告。
- 所有 batch rollback execution 投影为“批量回滚 / 回滚执行”任务：
  - `executed` 显示“已执行”，治理提示“回滚任务已闭合；等待清单或后续审计”；
  - `partial` 或仍有 pending 时显示失败队列治理入口。
- 所有 second compensation execution 投影为“二次补偿 / 补偿执行”任务：
  - `executed` 可定位补偿治理表；
  - 非完整执行可定位二次补偿失败队列。
- manifest 记录投影为“清单导出 / 交付产物”任务，展示清单项数，并提供“定位清单”。
- 任务行来自现有 history records，不另建一套会漂移的任务状态模型。
- 新任务表跟随 `_refresh_summary()` 统一刷新，批量回滚、字段合并、二次补偿和 manifest 生成后都会同步更新。

## 3. UI 链路

- 任务表只在存在批量写回执行记录时出现。
- 未生成报告时，至少展示批量写回执行任务。
- 生成事务报告后，展示报告冻结任务。
- 回滚执行后，展示一条或多条回滚任务，并根据失败/闭合状态定位到失败队列或报告。
- 二次补偿执行后，展示补偿任务，并根据结果定位到补偿失败队列或补偿治理表。
- manifest 生成后，最新任务通常为“清单导出”，处理按钮为“定位清单”。

## 5. 仍不宣称完成

- 真正后台 worker / 队列调度；
- 并发控制、限流、任务锁和跨批次互斥；
- 用户可取消、暂停、恢复和断点续跑；
- 指数退避、失败重放和自动重试策略；
- OAuth/SSO 登录、token 自动续期、签名 URL 自动续签；
- 组织、角色、题库权限申请或审批；
- 跨资料包素材主数据版本系统。

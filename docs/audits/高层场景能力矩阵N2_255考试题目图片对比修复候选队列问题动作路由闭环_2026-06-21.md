# 高层场景能力矩阵 N2.255 考试题目图片对比修复候选队列问题动作路由闭环

## 1. 本轮定位

N2.254 已经把 `question_figure_repair_queue` 接入最近运行产物清单，但用户仍需要打开报告再手动定位候选项。候选队列还没有进入 Workbench 问题队列，也就不能复用现有 issue action 按钮回到 AssetsPanel 的题图行。

N2.255 关闭的是“候选队列问题动作路由”的首片：把 repair queue entries 投影为 `WorkbenchIssueItem`，并通过现有 `workbench_issue_action_target()` 生成 `profile_question_figure_item` 路由。它仍不做自动替换，不写回文件，只把候选项变成可点击、可定位的修复动作。

## 2. 已实现能力

- `WorkbenchExecutionAdapter.build_result_state()` 将 `question_figure_repair_queue` entries 加入 `issue_items`。
- 新增 `question_figure_repair_queue_issue_items()`：
  - 读取 `question_figure_repair_queue.entries`；
  - 保留 `queue_id` 作为 issue id；
  - 设置 `category=question_figure_repair_queue`；
  - 设置 `title=题图修复候选`；
  - 保留题号、候选状态、对比对象、差异区域、来源 issue、人工确认和自动应用关闭说明；
  - 复用 `repair_target_type=question_figure_item` 与 `repair_target_key`；
  - 保留 `profile_id` / `profile_name` 到 `repair_context`。
- `workbench_issue_action_target()` 对带 profile context 的 `question_figure_item` 继续输出 `profile_question_figure_item` action。
- 现有 WorkbenchPanel 路由会把 `profile_question_figure_item` 送到 `PanelBridge.request_material_profile_repair_target()`，再导航到 AssetsPanel。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 增加 `question asset comparison repair queue issue action bridge` evidence。

## 3. 链路闭合

当前链路为：

`question_figure_repair_queue.entries[]` -> `question_figure_repair_queue_issue_items()` -> `ExecutionResultState.issue_items` -> QuickExecutionDetail issue queue -> `workbench_issue_action_target()` -> `profile_question_figure_item` -> WorkbenchPanel repair routing -> AssetsPanel 对应 profile 的题图行。

这让 N2.254 的“可见产物入口”进一步变成“可点击修复入口”。后续的一键确认执行可以复用同一份 `repair_target_key`，不需要重新设计候选项定位 schema。

## 4. 明确不宣称完成

- 不自动替换题图；
- 不批量应用候选项；
- 不保存应用确认记录；
- 不做回滚或撤销；
- 不写回 Word 或资料包；
- 不处理候选冲突；
- 不做内容级错图识别或 AI 判图。

当前能力只承诺“候选项可进入问题队列，并可路由到题图行”。真正的“一键确认执行/自动替换”仍是下一层边界。

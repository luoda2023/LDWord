# 模板场景 Policy 双向定位闭环记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经打通：

```text
模板正文样式 policy 行
-> 场景分区样式
-> 同一分区成为当前态
```

但返回时仍有断点：场景页只知道返回模板页和 `tpl_style`，没有把原始 `field_id=scene.section_styles.references_body` 带回去。用户返回模板后，还要重新找到刚才点过的覆盖项。

本轮目标是补成双向定位：

```text
模板 policy 行
-> 场景分区样式
-> 返回模板正文样式
-> 同一 policy 行继续高亮
```

## 2. 审计结论

### 2.1 已有信息

模板页发往场景页的 intent 已经带：

```python
field_id = "scene.section_styles.references_body"
return_panel_id = "template"
return_card_id = "tpl_style"
```

### 2.2 原断点

`ScenePanel._set_return_navigation_intent(...)` 只保存：

```python
{
    "panel_id": "template",
    "card_id": "tpl_style",
}
```

没有保存 `field_id`。

`StyleDetail.focus_navigation_field(...)` 也只支持模板正文编辑字段，不支持 `scene.section_styles.<variant>` 定位到 policy 行。

## 3. 本轮实现

### 3.1 场景页返回 intent 保留 field_id

`ScenePanel._set_return_navigation_intent(...)` 新增：

```python
if issue_key:
    self._return_navigation_intent["field_id"] = issue_key
```

这里的 `issue_key` 来自 incoming intent 的 `field_id` 或 payload issue key。

### 3.2 模板正文详情支持 policy 行定位

`StyleDetail.focus_navigation_field(...)` 新增对以下路径的识别：

```text
scene.section_styles.references_body
section_styles.references_body
references_body
```

命中后：

```text
StylePolicyControlDeck.set_current_policy_key("references_body")
NavigationHighlighter.highlight(row["references_body"], raw field id)
```

这样模板页能高亮同一个只读 policy 行，而不是尝试去正文编辑器找不存在的字段控件。

## 4. 双向链路

完整链路现在是：

```text
TemplatePanel / tpl_style
  policy row: references_body
    click
      -> intent:
         panel_id=scene
         card_id=scn_style_rules
         field_id=scene.section_styles.references_body
         return_panel_id=template
         return_card_id=tpl_style

ScenePanel / scn_style_rules
  focus_navigation_field(scene.section_styles.references_body)
    -> current_policy_key = references_body

ScenePanel return
  -> intent:
     panel_id=template
     card_id=tpl_style
     field_id=scene.section_styles.references_body

TemplatePanel / tpl_style
  StyleDetail.focus_navigation_field(scene.section_styles.references_body)
    -> template policy row references_body highlighted
```

## 7. 剩余差距

### P0：返回模板后上下文文案仍可再打磨

现在定位正确，但返回模板页的 entry context 文案仍沿用通用导航逻辑。后续可以让模板 policy 返回时显示更贴近用户的话：

```text
已从场景分区返回：参考文献正文覆盖项
```

### P0：全量场景覆盖总览仍未完成

双向定位只是当前场景闭环。完整设计仍需要：

```text
模板 -> 所有使用它的场景 -> 每个场景覆盖的分区 -> 点击进入对应场景
```

### P1：policy 路径解析可以继续下沉

当前模板详情和场景详情各自有路径解析逻辑。后续可提取一个共享 helper：

```python
scene_style_policy_key_from_field_id(field_id)
```

避免路径识别散落在多个页面。

## 8. 本轮结论

模板管理和场景规划之间现在不再是单向跳转：

- 模板页能进入场景分区。
- 场景页返回时保留同一 field id。
- 模板页能重新定位同一 policy 覆盖行。

这让“模板基线”和“场景覆盖”的关系更像一个连续工作流，而不是两个相似但割裂的页面。

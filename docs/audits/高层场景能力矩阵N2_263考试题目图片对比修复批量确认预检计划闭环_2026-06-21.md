# 高层场景能力矩阵 N2.263 考试题目图片对比修复批量确认预检计划闭环

## 1. 本轮定位

N2.262 已经把“冲突候选选择动作”接入 Workbench -> PanelBridge -> AssetsPanel 的单候选确认替换链路。N2.263 继续推进的是队列级能力：当 `question_figure_repair_queue` 同时存在 ready、blocked、conflict、rejected 等状态时，系统必须能先生成一份可审计的批量确认预检计划，清楚回答哪些候选可进入后续批量确认、哪些必须阻断、是否仍有冲突或同目标重复。

本轮只承诺“批量确认前的计划与预检”，不承诺批量写回 Word、不承诺事务回滚、不承诺自动候选优先级。

## 2. 已实现能力

- `_batch_question_figure_repair_queue()` 现在会在队列 payload 中生成 `batch_confirmation_plan`。
- `_refresh_question_figure_repair_queue_status()` 会同步重算 `batch_confirmation_plan`，因此冲突裁决后不会留下旧计划。
- 新增队列级计划契约：
  - `kind=question_figure_repair_batch_confirmation_plan`
  - `status=empty|ready|partial|blocked`
  - `action=review_question_figure_repair_batch_confirmation_plan`
  - `requires_user_confirmation`
  - `auto_apply_supported=false`
  - `batch_apply_supported=false`
  - `batch_confirmation_supported`
  - `entry_count`
  - `target_count`
  - `eligible_count`
  - `blocked_count`
  - `conflict_count`
  - `duplicate_target_count`
  - `eligible_queue_ids`
  - `blocked_queue_ids`
  - `conflict_queue_ids`
  - `duplicate_target_groups`
  - `eligible_entries`
  - `blocked_entries`
- 预检规则复用既有单候选字段：
  - `confirmation_status=ready`
  - `confirmation_apply_supported=true`
  - `replacement_source_kind=local_file`
  - `replacement_source_path` 必须仍指向本地存在文件
  - `repair_target_type=question_figure_item`
  - `repair_target_key` 必须存在
  - `apply_blockers` 必须为空
- 冲突候选不会被误算为可批量确认；它们进入 `blocked_entries` 并保留 `candidate_conflict_same_repair_target` 等阻断原因。
- 队列中若出现同一目标下多个 ready 候选，计划会生成 `duplicate_target_groups` 并把这些候选从 eligible 移到 blocked。
- batch Markdown report 的 `Question Figure Repair Queue` 小节新增 `Batch confirmation plan` 摘要。
- Workbench artifact 摘要新增 ASCII 级稳定字段：
  - `batch_plan=<status>`
  - `eligible=<n>`
  - `blocked=<n>`
  - `conflicts=<n>`
- `scene_product_readiness` 为 `pack:exam_education` 和 `family:exam_teaching` 新增 `question asset comparison repair queue batch confirmation preflight bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`comparison_issue_items` -> `question_figure_repair_queue.entries[]` -> `confirmation_status/apply_blockers` -> conflict guard -> `batch_confirmation_plan` -> batch JSON/Markdown report -> Workbench artifact detail -> product readiness evidence -> tests/release gate

这使队列级批量确认不再依赖前台临时扫描候选项，而是有运行时生成、报告可见、Workbench 可见、审计可锁定的统一计划。

## 4. 明确不宣称完成

- 不做批量替换执行。
- 不做批量事务回滚。
- 不做自动候选优先级排序。
- 不做图像内容质量判断。
- 不做完整候选对比选择器。
- 不把 conflict 或 blocked 候选绕过人工确认放入可执行集合。

当前能力只承诺：在进入未来的批量确认执行之前，系统可以稳定生成一份队列级预检计划，明确 eligible、blocked、conflict 和 duplicate target 的边界。

## 5. 验收锚点

- `test_question_figure_repair_batch_confirmation_plan_summarizes_queue`
  - 覆盖 ready、blocked、conflict 混合队列；
  - 断言 conflict 不进入 eligible；
  - 断言 remote/non-local reference 被阻断；
  - 断言 `batch_apply_supported=false`。
- `test_question_figure_repair_queue_resolves_selected_conflict_candidate`
  - 断言冲突裁决后 `batch_confirmation_plan` 同步重算；
  - 断言 selected 候选进入 eligible，rejected 候选进入 blocked。
- `test_workbench_batch_runner_reports_question_figure_comparison_matrix`
  - 断言 batch Markdown report 暴露 `Batch confirmation plan`。
- `test_execution_adapter_exposes_question_figure_repair_queue_artifact`
  - 断言 Workbench artifact detail 暴露 `batch_plan/eligible/blocked/conflicts`。
- `test_product_maturity_upgrade_audit_maps_every_subject_to_l5_blockers`
  - 断言 exam pack/family 包含 batch confirmation preflight evidence。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.262 的“冲突选择动作桥”推进到 N2.263 的“批量确认预检计划桥”。此前剩余边界中的“批量确认执行”被拆成两步：本轮先闭合“批量确认前的计划/预检”，后续再考虑真正的批量执行和事务回滚。

仍保留的高级素材库边界包括：真实素材库 API 登录/续期/签名与授权续期、跨资料包后台定时清理、后台全局任务中心、断点续传/后台队列/并发下载调度、跨资料包长期命中率趋势中心、真实素材库预览服务/签名预览 URL 续期、自由框选/多区域标注图层编辑、完整候选对比选择器、自动候选优先级策略、批量确认执行、批量/事务回滚、内容级错图识别、复杂学科图或 AI 质量判断。

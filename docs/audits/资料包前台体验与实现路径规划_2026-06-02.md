# 资料包前台体验与实现路径规划（2026-06-02）

## 1. 本文目标

这份文档用于重新定义原 `素材管理` 的前台产品体验，并规划后续实现路径。

本次不直接执行代码改造。当前重点是先把用户能理解、能操作、能完成任务的前台体验定义清楚，再把它映射到底层已有的 `EntityArchive`、`EntityProfile`、`AssetItem`、`ReplacementRule`、`MaterialExecutionContext` 等模型。

## 2. 结论

原 `素材管理` 如果直接展示 `archive_id`、`profile_id`、`key=value`、`image_rules`、`ReplacementRule`、输出目录模板，会非常像后台管理系统。用户面对这类页面会发懵，因为它要求用户理解系统内部模型，而不是顺着用户的真实任务推进。

前台产品应该改为一句更直接的用户语言：

> **资料包：先帮用户把生成文档要用的资料准备好；缺什么就提示补什么，准备好就直接生成。**

这里的 `资料包` 是用户语言；`素材管理` 可以继续作为内部模块或历史入口名，但前台不应以“素材管理后台”的方式呈现。

## 3. 命名建议

### 3.1 推荐显示名

推荐把一级入口从 `素材管理` 调整为：

**资料包**

原因：

- 它比“素材”更宽，可以包含公司资料、项目资料、联系人、Logo、公章、资质图、替换词、多份生成；
- 它天然表示“一套可复用资料”，符合用户对投标、公文、项目文档生成的心智；
- 它不会让用户误以为这里只是图片库或文件上传区。

### 3.2 备选名称

- `业务资料`
- `生成资料`
- `套打资料`
- `客户资料`
- `项目资料`

综合建议：一级导航用 `资料包`，页面里根据场景显示 `公司资料包`、`项目资料包`、`投标资料包`。

## 4. 用户侧心智

用户不是来“配置 profile”的，也不是来维护一个资料后台的。用户打开这个入口时，最自然的问题是：

> **我现在能不能生成？不能的话还缺什么？**

所以用户日常路径应该是：

```text
生成 -> 发现缺什么 -> 补资料 / 选图片 -> 看预览 -> 生成文档
```

用户真正想完成的是：

1. 我现在要给哪家公司、哪个项目生成文档？
2. 文档里需要填哪些信息？
3. Logo、公章、资质、签名这些图有没有准备好？
4. 模板里的占位符会被替换成什么？
5. 还缺哪些资料？
6. 如果要批量生成，多份文档分别给谁？
7. 生成完成后去哪里看结果？

因此前台页面要围绕这些任务组织，而不是围绕数据结构组织。

## 5. 前台术语与后台模型映射

| 前台术语 | 用户理解 | 后台模型 |
| --- | --- | --- |
| 资料包 | 一套可复用的公司/项目/投标资料 | `EntityArchive` |
| 生成 | 当前资料能不能生成、会生成几份、还缺什么 | `MaterialExecutionContext` + 执行状态 |
| 填资料 | 填公司名称、法人、地址、项目名称、日期等文字资料 | `fields` / `entity_data` |
| 选图片 | 选择 Logo、公章、签名、资质图、二维码、封面图 | `AssetItem` |
| 图片用途 | 这张图是 Logo、公章还是资质 | `AssetItem.role` |
| 放置位置 | 图片放到文档哪里，普通用户不必默认看到 | `AssetInsertionRule.target` |
| 看预览 | 看模板占位符会被填成什么 | `ReplacementRule` + `entity_data` |
| 准备情况 | 缺字段、缺图片、未匹配占位符、建议确认项 | `missing_required_asset_roles()` + 未来 placeholder scan |
| 多份生成 | 一次生成多份文档，分别对应不同公司、成员或版本 | `EntityProfile` + `MaterialBatchSelection` |
| 执行资料 | 交给排版管线消费的压平结果 | `MaterialExecutionContext` |

实现时可以保留后台模型名，但 UI 文案、按钮、面板、提示中不要直接暴露这些词。

## 6. 前台信息架构

### 6.1 一级入口

侧边栏建议显示：

`资料包`

图标可继续用 package，但含义从“素材箱”转为“一套生成资料”。

### 6.2 页面整体结构

资料包页面不应是后台表单堆叠，也不应先让用户看“概览”。默认页必须是 `生成`。

推荐主结构：

```text
资料包
├─ 生成
├─ 填资料
├─ 选图片
├─ 看预览
├─ 多份生成
└─ 高级
```

这组标题的逻辑是：

- 先回答“能不能生成”；
- 再按缺失项引导用户去 `填资料` 或 `选图片`；
- 再让用户 `看预览`，确认文档会被填成什么；
- 需要批量时进入 `多份生成`；
- 原始字段、锚点、输出模板、导入导出等能力全部放进 `高级`。

`准备情况` 不是导航项，只是 `生成` 页里的状态区。

### 6.3 当前资料包头部

顶部显示一条自然语言摘要：

```text
测试公司投标资料包
资料已填 12 项 · 图片已选 4 个 · 生成 2 份 · 缺少公章
```

主要按钮：

- `生成文档`
- `补齐资料`
- `批量生成`

如果当前执行链路还需要先把资料注入 Workbench，可以把 `应用到当前文档` 作为次级动作，但不应压过 `生成文档` 这个主目标。

不要显示：

- `archive_id`
- `profile_id`
- `MaterialExecutionContext`
- `image_rules`

这些应进入高级/开发视图，或完全隐藏。

## 7. 页面功能分区

### 7.1 生成

生成页是默认首页，只做三件事：

1. 告诉用户现在能不能生成；
2. 告诉用户会生成几份；
3. 告诉用户如果不能生成，还缺什么。

建议内容：

- 当前资料包；
- 当前文档 / 模板；
- 生成份数；
- 准备情况；
- 缺失资料；
- 建议确认项；
- 主操作按钮。

示例摘要：

```text
当前使用“测试公司投标资料包”，将生成 2 份文档。
还缺公章，补齐后即可生成。
```

### 7.2 填资料

这里不应首先展示 `key=value` 文本框。默认应是结构化表单。

常见字段：

- 公司名称；
- 统一社会信用代码；
- 法定代表人；
- 地址；
- 联系人；
- 电话；
- 项目名称；
- 招标编号；
- 投标日期；
- 编制日期。

交互原则：

- 常见字段用表单；
- 未识别字段放入“更多资料”；
- 高级用户可以展开“高级字段”，但默认收起；
- 字段为空时显示明确缺失状态；
- 字段来源可显示为手动填写、映射导入、模板扫描推荐。

### 7.3 选图片

导航里不叫“图片规则”，也不主叫“图片材料”，而叫 `选图片`。页面内部可以用“图片材料位”解释 Logo、公章、签名这些具体位置。

建议固定几个常用材料位：

- Logo；
- 公章；
- 法人签名；
- 授权代表签名；
- 资质证书；
- 二维码；
- 封面图；
- 其他附件图。

每个材料位是一个材料卡片：

```text
Logo
已选择：logo.png
将用于：{{logo}}
状态：已准备
[更换] [查看]
```

缺失时：

```text
公章
模板需要，但当前没有选择
[选择图片]
```

高级设置可放在展开区：

- 宽度；
- 插入锚点；
- 是否必需；
- 同类多张图片。

### 7.4 看预览

这是前台体验的关键，不应让用户手写规则后猜结果。

看预览页回答：

1. 当前模板/文档里有哪些占位符？
2. 每个占位符会替换成什么？
3. 哪些占位符没有匹配资料？
4. 哪些资料没有被用到？

建议展示：

| 文档占位符 | 将替换为 | 来源 | 状态 |
| --- | --- | --- | --- |
| `{{company_name}}` | 测试公司 | 填资料 | 已匹配 |
| `{{project_name}}` | XX 项目 | 填资料 | 已匹配 |
| `{{seal}}` | 未选择公章 | 选图片 | 缺失 |
| `{{agent_name}}` | 未匹配 | 无 | 需处理 |

按钮：

- `自动匹配`
- `导入映射表`
- `只显示问题项`
- `添加自定义替换`

`ReplacementRule` 作为后台能力保留，但前台表达为“自定义替换”。

### 7.5 多份生成

这里不叫 `profile`。单份生成时不用强调这个页面；只有要生成多份文档时，才显示“多份生成”。

适用场景：

- 一个总部资料包下有多个分公司；
- 一个联合体有多个成员；
- 同一模板要给多个客户生成；
- 同一项目要生成甲方版、乙方版、归档版。

列表显示：

```text
[x] 主体公司     测试公司
[x] 联合体成员A  测试公司二分公司
[ ] 联合体成员B  测试公司三分公司
```

按钮：

- `新增一份`
- `复制当前`
- `设为默认`
- `批量导入`

每一份生成的详情里显示要使用的资料和图片，但文案仍是用户语言，不显示 `profile_id`。

### 7.6 高级

高级设置承接系统能力，默认靠后，不进入普通用户第一屏。

可以包含：

- 原始字段；
- 自定义替换；
- 图片锚点；
- 图片宽度；
- 输出目录模板；
- 导入 / 导出 JSON。

`准备情况` 放在 `生成` 页里，不单独作为导航页。它不是技术日志，也不是“待办概览”，而是行动清单：

```text
还缺：公章
建议确认：资质证书
已匹配：18 项资料
```

## 8. Workbench 中的前台体验

Workbench 是执行入口，不应承载完整资料包管理。

Workbench 只需要一个生成优先的轻量摘要：

```text
资料包：测试公司投标资料包
准备情况：还缺公章
生成份数：2 份
```

按钮：

- `选择资料包`
- `补齐资料`
- `生成文档`
- `批量生成`

点击 `补齐资料` 进入资料包页面，并根据缺失项落到 `填资料` 或 `选图片`；Workbench 不直接展开后台表单。

## 9. 前台状态设计

### 9.1 资料包状态

| 状态 | 用户含义 | UI 表达 |
| --- | --- | --- |
| 未选择 | 当前还没有使用资料包 | `请选择资料包` |
| 草稿 | 已创建但资料不完整 | `资料未完成` |
| 可生成 | 必需项已完整 | `可以生成` |
| 有风险 | 可以生成但有未匹配/未使用项 | `可生成，有提醒` |
| 阻塞 | 缺必填字段或必需图片 | `不能生成，需处理` |

### 9.2 资料项状态

| 状态 | 说明 |
| --- | --- |
| 已准备 | 有值且通过校验 |
| 缺失 | 必填但为空 |
| 可选未填 | 非必填为空 |
| 未匹配 | 文档需要但资料包没有对应项 |
| 未使用 | 资料包有值但当前文档未使用 |

## 10. 实现路径规划

### Phase 0：冻结前台语义

目标：先统一语言，不动底层行为。

工作：

- 确认 `生成` 是资料包页第一个入口和默认页；
- 确认一级入口显示名是否改为 `资料包`；
- 确认 `Profile` 前台统一放到 `多份生成`，说明文案可写成“这一份给谁生成”；
- 确认 `实体字段` 前台统一改叫 `填资料`；
- 确认 `替换规则` 前台统一改叫 `自定义替换`；
- 确认 `图片规则` 前台统一改叫 `选图片 / 高级放置设置`；
- 确认 `待办概览`、`概览` 不作为资料包导航词。

输出：

- 文案词表；
- 页面信息架构草图；
- 前台/后台术语映射表。

验收：

- 主要 UI 文案不再出现 `profile`、`archive`、`entity_data`、`image_rules`、`replacement rule`。
- 导航顺序固定为 `生成`、`填资料`、`选图片`、`看预览`、`多份生成`、`高级`。

### Phase 1：低风险文案与壳层改造

目标：不改变现有执行链路，只把页面从后台感改成前台感。

工作：

- 侧边栏 `素材管理` 改为 `资料包`；
- 当前面板最上方先出现 `生成` 状态和主操作；
- `Profile 列表` 改为 `多份生成`；
- `当前 Profile` 不再作为用户可见标题，当前项详情归入 `填资料`；
- `实体字段` 改为 `填资料`；
- `替换规则` 改为 `自定义替换`；
- `图片规则` 改为 `选图片`，锚点等规则放入 `高级`；
- `设为当前素材` 改为 `应用到当前文档`，但放在 `生成文档` 之后；
- `加载映射` 改为 `导入资料表`。

验收：

- 用户看到页面时能理解“我在准备生成文档用的资料”；
- 现有测试不破坏；
- 不新增复杂交互。

### Phase 2：生成首页与准备情况

目标：让用户一进入页面先看到能不能生成，而不是表单。

工作：

- 新增 `生成` 默认首页；
- 展示当前资料包、当前文档和生成份数；
- 展示 `准备情况`，包括缺失项和建议确认项；
- 将当前散落的 summary 改为可行动状态；
- 提供 `补齐资料`、`生成文档`、`批量生成` 等主操作；
- `应用到当前文档` 保留为执行链路需要时的次级动作。

验收：

- 不打开高级表单，也能判断能不能生成；
- 缺 Logo / 公章 / 必填字段时能明确看到。

### Phase 3：填资料结构化编辑

目标：从 `key=value` 文本框过渡到用户表单。

工作：

- 定义常用字段 schema；
- 常用字段用表单控件；
- 未识别字段放到“更多资料”；
- 保留高级文本模式作为兼容入口；
- 导入 JSON/CSV/Excel 后优先填充结构化字段。

验收：

- 用户可以不懂占位符 key，也能填写公司名称、项目名称、法人等资料；
- 高级字段仍可保留，不损失现有能力。

### Phase 4：选图片卡片化

目标：把图片从规则文本变成可见材料位。

工作：

- 固定 Logo、公章、签名、资质、二维码等材料卡片；
- 支持选择 / 更换 / 清除 / 查看；
- 显示缩略图和缺失状态；
- 文件名 stem 自动推断 role，但允许用户改用途；
- 高级区配置锚点、宽度、是否必需。

验收：

- 用户能一眼看出 Logo、公章是否准备好；
- 不需要写 `logo={{logo}}` 也能完成常用图片配置。

### Phase 5：看预览与文档匹配

目标：从“用户写规则”变成“系统解释将发生什么”。

工作：

- 扫描当前模板/文档中的占位符；
- 展示占位符匹配表；
- 自动匹配 `填资料` 和 `选图片` 中已有内容；
- 标出未匹配项；
- 支持添加自定义替换；
- 允许用户只看问题项。

验收：

- 执行前用户能看到 `{{company_name}} -> 测试公司`；
- 未匹配占位符会进入 `生成` 页的 `准备情况`；
- 自定义替换不再是主要入口，而是补充入口。

### Phase 6：多份生成前台化

目标：把 `profile` 从系统对象变成用户能理解的多份生成设置。

工作：

- 列表标题改为 `多份生成`；
- 增加角色标签：主体公司、联合体成员、分公司、客户、项目版本；
- 批量勾选用自然语言显示输出预览；
- 输出目录模板默认隐藏，放入高级设置；
- 支持复制当前对象快速创建新对象。

验收：

- 用户知道自己将生成几份文档、分别对应谁；
- 批量输出预览不依赖用户理解 `{profile_id}`、`{entity_name}`。

### Phase 7：Workbench 轻量入口

目标：Workbench 只显示“当前用哪套资料、能不能生成”。

工作：

- 在 Workbench 快速执行区增加当前资料包摘要；
- `选择资料包` 打开资料包选择器；
- `补齐资料` 跳转资料包页，并落到缺失项所在的 `填资料` 或 `选图片`；
- `生成文档` 使用当前资料包执行；
- 单次执行和批量执行都复用资料包状态。

验收：

- Workbench 不变成后台资料编辑页；
- 用户执行前能明确当前资料包和风险。

### Phase 8：兼容与迁移

目标：保留当前底层链路，不推翻已有代码。

工作：

- 继续使用 `EntityArchive` / `EntityProfile` 存储；
- 前台新增字段通过 adapter 映射到底层模型；
- 旧 JSON 可继续加载；
- 新 UI 产生的数据仍能构建 `MaterialExecutionContext`；
- `key=value` 高级模式作为兼容 fallback。

验收：

- 已有测试继续通过；
- 旧资料档案不会失效；
- 新前台只是改善用户入口，不破坏执行链路。

## 11. 实现边界

### 11.1 本轮不做

- 不做云素材库；
- 不做权限系统；
- 不做 DAM 级别复杂元数据；
- 不做完整文件管理器；
- 不要求一次性实现所有复杂锚点；
- 不把所有系统字段直接暴露给用户。

### 11.2 必须保留

- 当前执行链路；
- `MaterialExecutionContext` 注入能力；
- 批量 runner；
- JSON/CSV/Excel 映射；
- 缺失素材阻塞；
- 统一批量报告。

## 12. 验收标准

前台体验改造完成后，应满足：

1. 非技术用户能在 3 分钟内理解 `资料包` 是干什么的；
2. 用户不需要看到 `profile_id` / `archive_id` 也能设置单份或多份生成；
3. 用户不需要写 `logo={{logo}}` 也能配置常用 Logo / 公章；
4. 执行前能看到哪些资料会替换到哪些占位符；
5. 缺必需资料时，系统用用户语言说明“缺什么、去哪里补”；
6. Workbench 只显示资料包摘要、准备情况和补齐入口，不堆完整配置表单；
7. 高级用户仍能使用导入映射、自定义替换和高级字段；
8. 旧资料档案和当前执行测试继续可用。

## 13. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 前台改造破坏已打通的执行链路 | 前台只做 adapter 映射，底层 `MaterialExecutionContext` 保持稳定 |
| 文案改了但结构仍像后台 | Phase 2 必须先做 `生成` 首页和可行动的准备情况 |
| 结构化字段无法覆盖所有场景 | 常用字段结构化，其他字段进入“更多资料/高级字段” |
| 图片卡片无法覆盖复杂规则 | 常用材料卡片优先，复杂锚点放高级设置 |
| 批量生成被过度产品化导致失去灵活性 | 输出目录模板保留在高级设置中 |

## 14. 后续决策点

在进入代码实现前，需要确认：

1. 一级入口是否正式改名为 `资料包`；
2. 资料包是否区分“公司资料包”和“项目资料包”；
3. `填资料` 的常用字段清单；
4. `选图片` 的常用材料位清单；
5. Workbench 中资料包摘要放在快速执行区还是右侧状态区；
6. 是否允许保留一个“高级模式”查看原始字段和规则。

## 15. 推荐下一步

下一步不要直接改执行逻辑。建议先做一个最小前台原型定义：

1. 定稿 `生成` 默认页；
2. 确认 `填资料`、`选图片`、`看预览`、`多份生成` 的页面骨架；
3. 画出 Workbench 当前资料包摘要；
4. 决定哪些后台字段必须隐藏；
5. 再进入 Phase 1 的文案和壳层改造。

## 16. 二级标题与日常逻辑复审

### 16.1 最终判断

资料包不是“后台管理”，也不是“素材库”。它是生成文档前的资料准备入口。

用户进来后最想先看到的是：

> **现在能不能生成？不能的话还缺什么？**

因此 `生成` 必须放在最上面，并且作为默认页。其他页面不是并列后台模块，而是帮助用户把生成这件事完成的步骤。

### 16.2 最终导航定稿

```text
资料包
├─ 生成
├─ 填资料
├─ 选图片
├─ 看预览
├─ 多份生成
└─ 高级
```

这个顺序符合用户日常动作：

1. 先看能不能生成；
2. 缺文字资料就去填；
3. 缺 Logo、公章、签名就去选图片；
4. 生成前看一眼文档里会填成什么；
5. 需要一次出多份时再设置多份生成；
6. 原始字段、锚点、输出模板等复杂能力最后再看。

### 16.3 每个标题承担什么

| 标题 | 用户问题 | 页面任务 |
| --- | --- | --- |
| `生成` | 现在能不能生成？还缺什么？ | 显示当前资料包、当前文档、准备情况、生成份数和主按钮 |
| `填资料` | 公司、项目、联系人这些文字资料填好了吗？ | 用表单补齐字段，隐藏原始 key |
| `选图片` | Logo、公章、签名、资质图准备好了吗？ | 用材料卡片选择、替换、查看图片 |
| `看预览` | 文档里会被填成什么？ | 展示占位符和资料的匹配结果 |
| `多份生成` | 这次要生成几份，分别对应谁？ | 勾选或新增多份资料，预览输出 |
| `高级` | 我要处理更复杂的规则 | 收纳原始字段、自定义替换、图片锚点、输出模板、导入导出 |

### 16.4 弃用词表

这些词不应作为用户可见的主导航或卡片标题：

| 弃用词 | 问题 | 替代方式 |
| --- | --- | --- |
| `待办概览` | 像项目管理工具，用户不知道和生成文档有什么关系 | 不再使用；状态放进 `生成` 页的 `准备情况` |
| `概览` | 太泛，不能告诉用户下一步做什么 | `生成` |
| `生成对象` | 偏系统模型 | `多份生成`，单份详情写“这一份” |
| `基础资料` | 偏抽象 | `填资料` |
| `图片材料` | 可作说明词，但不适合作为导航 | `选图片` |
| `替换预览` | 略书面 | `看预览` |
| `检查并生成` | 适合按钮逻辑，不适合导航 | 主按钮用 `生成文档`；状态区用 `准备情况` |
| `Profile` | 后台模型名 | `多份生成` / `这一份` |

### 16.5 生成页骨架

`生成` 页不是静态概览，也不是执行日志，而是用户生成前的第一屏。

建议第一版长这样：

```text
生成文档

当前资料：测试公司投标资料包        [更换]
当前文档：标准投标模板.docx         [更换]

准备情况
  还缺：公章
  建议确认：资质证书
  已匹配：18 项资料

本次生成
  生成份数：2 份
  对应：主体公司、联合体成员 A
  输出位置：默认输出目录

主要操作
  [补齐资料] [生成文档] [批量生成]
```

按钮规则：

- 如果有必需项缺失，主按钮显示 `先补齐资料`；
- 如果必需项齐全，主按钮显示 `生成文档`；
- `批量生成` 只有在多份生成打开或已选择多份时突出；
- `应用到当前文档` 可保留为次级动作，不抢主按钮位置。

### 16.6 日常交互路径

用户日常路径应是：

```text
打开资料包 -> 看到生成页 -> 补齐缺失资料 -> 看预览 -> 生成文档
```

如果缺公章：

```text
生成页提示“还缺公章”
点击“补齐资料”
系统进入“选图片”
选择公章
回到“生成”
点击“生成文档”
```

如果缺公司名称：

```text
生成页提示“还缺公司名称”
点击“补齐资料”
系统进入“填资料”
填写公司名称
回到“看预览”确认
回到“生成”
点击“生成文档”
```

### 16.7 Workbench 对应表达

Workbench 也只保留生成相关摘要，不展开完整资料编辑：

```text
资料包：测试公司投标资料包
准备情况：还缺公章
生成份数：2 份

[补齐资料] [生成文档] [批量生成]
```

Workbench 的职责是执行，不是让用户维护资料后台。完整编辑仍回到资料包页完成。

### 16.8 对实现路径的约束

后续实现必须遵守这些约束：

- `生成` 是第一个入口和默认页；
- `准备情况` 只出现在 `生成` 页里，不成为独立导航；
- `填资料`、`选图片`、`看预览` 都由 `生成` 页的缺失项自然跳转；
- `多份生成` 只在批量场景突出，单份场景不强迫用户理解它；
- `高级` 永远靠后，承接系统能力，不抢普通用户第一屏。

- 新副本默认进入本次批量生成选择，减少用户从空白重新配置第二份资料的负担。
- `多份生成` 列表增加角色和状态标签，例如 `主体公司`、`联合体成员`、`项目版本`、`当前编辑`、`本次生成`、`未选择`；

## 18. 二级功能点卡片化复审（2026-06-03）

### 18.1 新判断

前一轮已经把后台词和执行链路前台化，但页面结构仍偏向“一个长页面里堆多个功能区”。这和目标体验还有差距。

新的结构判断是：

> **二级功能点本身必须是独立卡片。**

这里的“独立卡片”不是右侧内容区里的普通区块，而是类似模板设置页左侧的二级入口卡片：

- 有图标；
- 有清晰标题；
- 有一行用户能读懂的摘要；
- 有状态标签，例如 `可生成`、`需补齐`、`已完成`、`有提醒`；
- 有选中态；
- 点击后右侧只显示这个功能点的详情。

也就是说，资料包页应该从“纵向滚动页面”改成“左侧二级功能卡片 + 右侧功能详情”的工作台结构。

### 18.2 现有方案的问题

当前实现虽然已经按 `生成`、`资料包信息`、`填资料`、`选图片`、`看预览`、`多份生成`、`高级` 排序，但它们仍然是同一个滚动内容区里的连续卡片。

这个结构会带来三个理解负担：

1. 用户会觉得自己进入了一个配置后台，而不是一个生成前的资料准备前台。
2. `生成` 下面的跳转按钮只能帮助滚动定位，不能让用户一眼看到所有二级功能的状态。
3. 右侧内容一次性暴露太多，用户需要自己判断“我现在应该看哪一块”。

截图里的交互逻辑更清晰：左侧每张二级卡片就是一个任务入口，右侧才是当前任务的详细操作。

### 18.3 二级功能卡片最终结构

推荐结构：

```text
资料包
├─ 生成
├─ 导入导出
├─ 资料准备
│  ├─ 填资料
│  ├─ 选图片
│  ├─ 看预览
│  └─ 多份生成
└─ 更多设置
   └─ 高级
```

`生成` 仍然放在最上面，并且默认选中。它不是“概览”，而是用户进入资料包后的第一件事：判断现在能不能生成。

`导入导出` 可以成为独立二级卡片，但它的文案要控制好。它不是技术文件管理，而是“把资料带进来 / 保存这套资料”。其中 `导入资料表` 偏日常，`导入资料包 / 导出资料包` 偏复用与交接。

`资料包信息` 不建议作为独立二级卡片。它更像当前资料上下文，应放在 `生成` 右侧详情里的 `当前资料` 卡片中，避免用户把“改名称”误解为一个主要步骤。

`准备情况`、`待办概览`、`概览` 都不应成为二级卡片标题。它们是状态内容，不是用户动作。

### 18.4 每张二级卡片的定义

| 二级卡片 | 一句话摘要 | 状态标签 | 右侧详情重点 |
| --- | --- | --- | --- |
| `生成` | 能不能生成、还缺什么 | `可生成` / `需补齐` / `有提醒` | 当前资料、当前文档、准备情况、本次生成、主按钮 |
| `导入导出` | 导入资料表，或保存这套资料 | `可导入` / `已保存` | 导入资料表、批量导入多份、导入资料包、导出资料包 |
| `填资料` | 公司、项目、联系人等文字资料 | `已填 8/10` / `缺 2 项` | 常用字段、更多资料、模板推荐、字段来源 |
| `选图片` | Logo、公章、签名、资质图 | `已选 4/7` / `缺公章` | 材料位卡片、缩略图、清晰度提醒、查看与替换 |
| `看预览` | 模板占位符会被替换成什么 | `18 项匹配` / `2 项未处理` | 占位符表格、问题筛选、自动匹配、行内处理 |
| `多份生成` | 本次生成几份，分别给谁 | `1 份` / `已选 3 份` | 份数列表、复制当前、批量导入、输出预览 |
| `高级` | 复杂规则和少用设置 | `默认收起` / `有自定义` | 自定义替换、图片放置、必填规则、自定义命名 |

卡片摘要必须是用户行动语言，不能写成数据模型语言。例如：

- 好：`缺公司名称、公章`
- 不好：`profile 字段缺失`
- 好：`公章已选，签名缺失`
- 不好：`image_rules 未配置`

### 18.5 推荐页面布局

桌面端推荐为两栏：

```text
┌──────────────────────┬────────────────────────────────────────┐
│ 二级功能卡片列表      │ 当前选中功能详情                       │
│                      │                                        │
│ [生成] 可生成         │ 生成                                   │
│   能不能生成          │ ┌ 当前资料 ┐                           │
│                      │ ┌ 准备情况 ┐                           │
│ [导入导出] 可导入     │ ┌ 本次生成 ┐                           │
│                      │                                        │
│ 资料准备             │                                        │
│ [填资料] 缺 2 项      │                                        │
│ [选图片] 缺公章       │                                        │
│ [看预览] 2 项未处理   │                                        │
│ [多份生成] 已选 3 份  │                                        │
│                      │                                        │
│ 更多设置             │                                        │
│ [高级] 默认收起       │                                        │
└──────────────────────┴────────────────────────────────────────┘
```

右侧可以继续使用内容卡片，但它们是“当前功能详情卡片”，不是二级功能导航。不要再把所有二级功能一次性堆在右侧。

窄屏时不应强行保持左右两栏，可以切换为顶部横向二级卡片条或抽屉式二级卡片列表，但仍要保留“每个二级功能是独立入口”的逻辑。

### 18.6 用户日常路径复审

新的卡片结构应支持这些日常路径：

```text
打开资料包
-> 左侧看到生成卡片选中
-> 右侧看到能不能生成
-> 缺什么就点击对应左侧卡片，或点补齐资料自动切过去
-> 补完后回到生成
-> 看预览
-> 生成文档
```

如果缺公章：

```text
生成卡片显示：需补齐
选图片卡片显示：缺公章
点击选图片
选择公章
选图片卡片变为：已完成
生成卡片变为：可生成
```

如果要批量：

```text
多份生成卡片显示：1 份
点击多份生成
复制当前或批量导入
多份生成卡片变为：已选 3 份
回到生成
点击批量生成
```

这比在长页面里找区块更符合用户日常使用逻辑，因为用户不需要先理解整个系统，只需要看左侧卡片的状态。

### 18.7 实现路径修正

后续实现不应继续沿用“滚动到卡片”的方案，而应改为以下路径：

1. 新增二级功能卡片模型，例如 `AssetsSectionSpec`，包含 `id`、`title`、`icon`、`summary`、`status`、`detail_widget`。
2. 将资料包面板改为左右布局：左侧为二级功能卡片列表，右侧为 `QStackedWidget` 或等价详情容器。
3. 把当前 `生成`、`填资料`、`选图片`、`看预览`、`多份生成`、`高级` 从同一个滚动区拆成独立详情页。
4. 增加每张二级卡片的状态汇总函数，复用现有字段、图片、预览、批量生成统计。
5. 将 `补齐资料`、预览行内处理、Workbench 跳转从“滚动并高亮”改为“切换到对应二级卡片并定位具体项”。
6. 保留右侧详情内必要的局部卡片，例如 `当前资料`、`准备情况`、`材料位`，但避免卡片嵌套卡片。
7. 更新回归测试，断言默认选中 `生成`，左侧存在全部二级功能卡片，右侧不会同时渲染所有二级功能详情。
8. 重新做桌面与窄屏截图验证，重点确认二级卡片状态可读、选中态明确、无横向裁切。

### 18.8 新验收标准

这一轮结构调整完成后，验收标准应改为：

- 用户打开 `资料包` 后，第一眼能看到左侧二级功能卡片，而不是一整页表单；
- `生成` 卡片位于最上方并默认选中；
- 每个二级功能点都有独立卡片、图标、摘要、状态标签；
- 右侧一次只展示当前选中二级功能的详情；
- `资料包信息` 不再作为主要二级入口，而是归入 `生成` 的当前资料详情；
- `导入导出` 作为独立卡片时，文案聚焦“把资料带进来 / 保存这套资料”，不暴露 JSON 等技术结构；
- `补齐资料` 可以自动切换到 `填资料` 或 `选图片`；
- `看预览` 的问题行可以切换到对应二级卡片；
- 窄屏下仍能清楚选择二级功能，不出现横向滚动或文字裁切；
- 视觉上更像用户前台任务面板，而不是资料后台配置页。

## 20. 二级卡片视觉完整性复审（2026-06-03）

### 20.1 问题复盘

上一轮虽然完成了“左侧二级功能卡片 + 右侧详情切换”的结构迁移，但视觉语义仍不完整。

具体问题是：资料包左侧使用了通用 `NavigationCard`，而这个组件默认用于导航栏时，非选中项是透明背景。这样会导致：

- 选中的 `生成` 像独立卡片；
- 未选中的 `导入导出`、`填资料`、`选图片`、`看预览`、`多份生成`、`高级` 更像列表项；
- 用户无法一眼感知“每个二级功能点都是一个可进入、可判断状态的独立卡片”。

这说明迁移只完成了信息架构，没有完全完成视觉层级。

### 20.2 类似潜在问题

本轮复审后，需要特别防止以下同类问题：

1. **结构改了，但视觉组件仍沿用旧导航样式。**
   例如使用透明底导航项，会让二级功能重新退化成列表。

2. **测试只检查有几个二级入口，不检查卡片是否真的是卡片。**
   这会让“看起来像后台列表”的问题漏过回归。

3. **右侧详情拆分完成，但左侧状态没有完整表达。**
   如果左侧只显示标题，不显示摘要和状态标签，用户仍需要点进去才知道发生了什么。

4. **二级功能和右侧内容卡片混淆。**
   左侧二级入口卡片负责导航和状态判断，右侧内容卡片负责具体操作，两者不能互相替代。

5. **旧文档里的“滚动到卡片”表述继续影响实现。**
   后续应统一理解为“切换到对应二级卡片并定位具体项”。

### 20.3 已修正内容

本轮已补齐视觉迁移：

- `NavigationCard` 增加实底卡片模式；
- 资料包左侧所有二级功能卡片启用实底模式；
- 选中卡片保持蓝色主背景；
- 非选中卡片使用独立白色卡片背景和浅边框；
- 图标仍保留独立图标底，形成“卡片 + 图标块 + 标题 + 摘要 + 状态标签”的层级；
- 测试新增断言：资料包二级功能卡片必须启用实底背景，且不能退回透明列表态。

### 20.4 新增验收点

- 所有二级功能入口都有独立背景色；

## 21. 正式样式差距复核与修正执行（2026-06-03）

### 21.1 对上一轮口径的修正

第 20 节把问题主要归因到“左侧非选中二级入口没有实底卡片”，这个判断不够准确。

对照正式模板详情页后，真正的差距不是单个导航卡片背景，而是资料包页没有迁入正式详情体系：

- 正式模板页使用 `MasterDetailShell` 统一左侧导航 rail、右侧滚动区、边距和背景；
- 右侧首屏必须先出现当前二级功能自己的 `TemplateSummaryCard`，而不是页面外置标题；
- 摘要卡内部使用 `SummaryGrid` 模块卡片，先告诉用户当前状态、关键数量和是否需要处理；
- 具体操作区再使用带图标标题的内容卡片；
- 左侧导航保持正式 `NavigationCard` 语义：选中项是蓝色主卡，未选中项依靠白色导航 rail、图标块、标题、摘要和状态标签形成入口感，不强制改成每张都有边框的后台卡片。

因此，“独立卡片”的验收重点应从“左侧全部实底白卡”修正为：

> 每个二级功能都是独立入口；每个入口切换后，右侧都有自己的正式摘要卡和编辑卡片，而不是把所有功能堆成后台表单。

### 21.2 本轮执行修正

本轮按正式样式体系完成以下迁移：

- 资料包面板外层改用 `MasterDetailShell`；
- 移除右侧外置 `资料包` 大标题和散落状态文案，保留为隐藏兼容状态，不进入视觉首屏；
- 每个二级功能页顶部新增 `TemplateSummaryCard`：`生成`、`导入导出`、`填资料`、`选图片`、`看预览`、`多份生成`、`高级` 都有自己的摘要卡；
- 每个摘要卡统一显示 3 个 `SummaryGridItem`，分别表达当前状态、关键数量和后续处理方向；
- `生成文档` 作为主动作进入 `生成` 摘要卡右侧动作区，`补齐资料`、`批量生成` 保留在 `准备与生成` 编辑卡中，窄屏时可收为图标按钮；
- 右侧普通内容卡改为“图标 + 标题”的正式编辑卡片头；
- `当前资料`、`填资料`、`选图片`、`多份生成`、`高级设置` 中的主要表单改用 `InspectorForm` 组织；
- 左侧导航取消上一轮强制 `solid_background` 的误判，回到正式模板页导航语义。

### 21.3 新验收点

后续验收资料包页时，以以下点为准：

- 打开资料包后，首屏右侧第一块必须是 `生成` 的正式摘要卡；
- 左侧七个二级功能仍然都是独立入口，默认选中 `生成`；
- 切换任意二级入口时，右侧只展示当前功能详情；
- 每个二级入口对应的右侧详情都必须有自己的顶部摘要卡；
- 摘要卡不能只放说明文字，必须有模块化状态项；
- 具体操作必须进入带图标标题的编辑卡片；
- 不再把“左侧非选中卡片必须是强边框白卡”作为正式样式要求；
- 不允许退回“页面标题 + 状态行 + 后台表单”的结构。
- 窄屏下摘要模块和图片材料行必须降级为不横向溢出的布局。

## 22. 快速执行资料填充预览落地（2026-07-28）

### 22.1 定位

快速执行页在“处理方案与模板”和“输出目录”之间增加只读的“资料填充”回执条。它只回答“本次执行将填入什么”，不承担资料编辑、资料准备或问题修复职责。

默认态保持 59px 左右的紧凑高度，只展示：

- 当前资料包名称；
- 与执行门禁一致的必填完成度或缺项数量；
- 最多三个必要字段或素材状态；
- 非零的图片、内容块和附件数量。

只有存在第四项必要信息时才显示明确的“展开”按钮。展开后使用双列只读布局，仍不展示说明段落、不增加 Hover 说明、不增加“准备资料”或第二个修复入口。

### 22.2 数据与状态链

```text
当前方案资料规则
  + _effective_material_context()
  + resolved_entity_data()
  + asset_items / content_bindings / attachment_bindings
  + material_readiness_issue_groups()
  + material_readiness_gate_decision()
  → QuickMaterialPreviewProjection
  → QuickMaterialPreview
```

关键约束：

- 展示解析后的执行值，不展示资料编辑器的原始草稿；
- 缺失项、警告、阻塞与执行按钮共用同一个资料门禁，不另写判断；
- 缺失必填项优先于已填写可选项；
- 公文自由字段继续由“自由字段填写”编辑，预览不重复展示这些值；
- 试卷尚未上传题源时隐藏预览，避免与“题源与装配”的空状态重复；
- 场景无资料包要求且上下文无资料时整条隐藏；
- 长内容只显示“已填写”，避免把正文或结构化载荷塞进快速执行页。

# 高层场景能力矩阵 N2.275 考试题目图片对比修复批量应用事务任务报告锚点动作闭环

日期：2026-06-21

## 1. 本轮定位

N2.275 承接 N2.274 的事务任务 issue/action 桥。N2.274 已经能把 `active`、`blocked`、`orphaned` 事务任务摘要放进 Workbench 问题队列，并在 QuickExecutionDetail 点击“处理”时发出 `question_figure_batch_apply_transaction_task_summary` action target。但 action 到达 WorkbenchPanel 后只切回 `quick_execute`，尚未真正调用已有的 artifact opener 打开事务报告锚点。

本轮只做 issue action 到报告锚点的打开桥，不执行回滚、不做后台任务中心、不做任务调度。

## 2. 已闭合能力

- WorkbenchPanel 新增事务任务 action payload 解码。
- `question_figure_batch_apply_transaction_task_summary` action 优先打开 `report_path#fragment`。
- 无 `report_path` 时退回 `artifact_path`。
- 打开能力复用 RecentRunPanel 已有 `_open_artifact_file(path, fragment=...)`。
- 点击后仍切回 `quick_execute`，保持用户处于执行上下文中。
- 路径不存在或打开失败不阻断 UI；历史报告被移动时仍可回到执行中心继续查看问题状态。
- `test_workbench_panel_routes_issue_repair_targets_to_existing_surfaces` 覆盖 action 会调用带 fragment 的 artifact opener。
- `scene_product_readiness` 中 `pack:exam_education` 与 `family:exam_teaching` 新增 `question asset comparison repair queue batch apply transaction task report-drilldown action bridge` evidence。

## 3. 链路视角

```text
Workbench issue: question_figure_batch_apply_transaction_task
  -> QuickExecution action: question_figure_batch_apply_transaction_task_summary
  -> WorkbenchPanel payload decode
  -> RecentRunPanel._open_artifact_file(report_path, fragment)
  -> question_figure_batch_apply_transaction_manifest.md
     #question-figure-batch-apply-transaction-task-summary
```

这条链路补上的是“可点击”之后的真实落点：用户点击事务任务问题后，不只是回到快速执行页，还会尝试打开事务 Markdown 报告里的 `Task Summary` 锚点。

## 4. 仍不宣称完成的边界

- 不自动裁决是否应该回滚。
- 不做后台任务中心。

- 不做跨 docx 队列。
- 不做原子事务。
- 不做自动补偿。
- 不做文件快照系统。

本轮只承诺：事务任务 issue action 已经能落到已生成报告的 task summary 锚点。

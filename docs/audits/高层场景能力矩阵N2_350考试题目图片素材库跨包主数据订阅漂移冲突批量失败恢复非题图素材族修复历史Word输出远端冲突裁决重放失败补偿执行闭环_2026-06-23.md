# 高层场景能力矩阵 N2.350 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复非题图素材族修复历史 Word 输出远端冲突裁决重放失败补偿执行闭环

## 1. 定位

N2.349 已经把复核后 retry/replay 的失败态推进为补偿队列：失败项可见、可分类、可写入 manifest 和 metadata。N2.350 继续补齐队列后的执行入口，让补偿队列不再停在 `queued` 状态，而是能被前台 `Execute` 消费并生成独立执行审计。

本轮不声明后台 worker、自动重试调度、授权刷新真实外呼、远端快照重新拉取、dead-letter 最终处置或二次补偿归档已经完成。当前只承诺 compensation queue execution 首片：把队列项转成可审计的执行 handoff。

## 2. 本轮闭环

- compensation queue 记录后，非题图素材族恢复表格显示 `Execute` 与 `Manifest`。
- `Execute` 从最新 compensation queue record 派生 execution record，避免新增第二套事实源。
- execution items 按 queue failure class 分发：
  - `permission_required` -> `compensation_execution_authorization_refresh_required`
  - `remote_conflict` -> `compensation_execution_remote_snapshot_review_required`
  - `retry_replay_failed` -> `compensation_execution_dead_letter_review_required`
- execution manifest 独立写入 `artifacts/subscription_drift_non_question_asset_family_word_output_remote_conflict_decision_retry_replay_failure_compensation_executions`。
- metadata 回写 `master_subscription_drift_non_question_asset_family_remote_conflict_decision_retry_replay_failure_compensation_execution_*` 字段。
- 执行记录后表格状态进入 `handoff`，并只保留 `Manifest`，为后续 dead-letter/final audit 留出明确下一段。

## 3. 链路变化

N2.350 后链路变为：

```text
... -> Review -> Replay
                  |
                  v
             Failure Queue -> Execute -> Handoff Manifest
```

`Execute` 不伪装成最终远端修复完成，而是把补偿队列项正式交接到授权刷新、远端快照复核或 dead-letter 复核。这样用户链路从“有队列但不可推进”变成“队列可执行、执行结果可审计、下一步责任可定位”。

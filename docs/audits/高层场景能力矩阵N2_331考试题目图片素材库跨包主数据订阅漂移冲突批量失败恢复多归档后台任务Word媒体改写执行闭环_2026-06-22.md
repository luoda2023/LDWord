# 高层场景能力矩阵 N2.331 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复多归档后台任务 Word 媒体改写执行闭环

日期：2026-06-22

## 1. 本轮目标

N2.330 已经把订阅漂移批量失败恢复后的 followup 治理推进到自动回滚/补偿评估与历史输出 trace repair artifact，但链路仍停留在“历史输出需要追溯”的执行前夜。本轮承接 `batch failure recovery multi archive background worker rollback compensation Word media rewrite execution UI`，新增 Word media rewrite 执行表、执行记录、manifest artifact 和素材 metadata 回写，让恢复结果能进入可见、可审计的 Word 输出改写入口。

本轮不声称真正完成跨归档持久后台 worker、跨进程任务锁、调度器、真实二进制媒体替换策略或 Word XML/relationship/media 深层一致性修复。当前承诺是：当前 EntityArchive 内的恢复自动执行记录可以派生 Word media rewrite worker 行；执行时会扫描历史输出目标中的 `.docx`，写入 JSON/Markdown manifest，发现有效 DOCX 时生成带本轮签名的改写副本；没有 DOCX 时明确落为 `manifest_written_no_docx_targets`，把缺失的历史 Word 输出暴露为下一步需求。

## 3. 链路边界

当前链路是：

1. 批量失败恢复报告闭合。
2. Drilldown artifact 写入恢复明细。
3. SLA center 和 followup 治理完成。
4. 自动执行表生成 trace repair artifact。
5. Word media rewrite 表从自动执行记录派生候选。
6. 用户点击“执行改写”。
7. 系统扫描历史输出目标中的 `.docx`。
8. 有 DOCX 时生成带签名的副本并统计 Word media；没有 DOCX 时写入 manifest-only 状态。
9. 系统写入执行审计、manifest artifact 和 metadata。
10. 表格后续可定位到自动执行/明细链路。

本轮的“Word media rewrite”是执行入口与文件目标扫描首片。它已经进入 artifact 和 metadata，但只有在历史输出目标确实存在 DOCX 时才会产生改写副本；它不会凭空创建历史 Word 输出，也不会跳过候选修复计划直接替换未知媒体。

## 4. 仍未闭合边界

N2.331 后，剩余缺口不再是“恢复结果有没有 Word media rewrite 执行入口”，而是更深的后台与跨归档执行能力：

- 跨 archive 持久 worker 队列、任务锁、幂等 key、重试调度器；
- 后台任务状态持久化、断点续跑、跨进程互斥；
- 多 archive 文件级失败恢复中心和索引；
- Word media rewrite 与题图修复候选计划、替换审计、回滚审计的深度合流；
- 真实 Word XML / relationship / media 一致性修复；
- 二次补偿 connector；
- 历史输出缺失 DOCX 时的生成/定位策略；
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

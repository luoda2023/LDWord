# 高层场景能力矩阵 N2.266 考试题目图片对比修复批量应用执行计划草案闭环

日期：2026-06-21

## 1. 本轮目标

N2.266 承接 N2.265 的 `batch_apply_dry_run` 守卫。N2.265 已经能证明冻结计划在当前文件和当前队列下是否仍可执行，但工作台仍缺少一个稳定的“如果进入批量执行，会处理哪些目标”的任务草案。

本轮闭合的是批量应用前的执行计划草案：

- 从 ready 的 dry-run 生成 `batch_apply_execution_plan`；
- 要求显式 `confirmed=True`、`expected_freeze_id` 和 `expected_plan_fingerprint`；
- 生成稳定 `plan_id` 和 `execution_plan_fingerprint`；
- 输出 planned queue、planned entries、目标数、阻断项和 final confirmation 状态；
- Markdown 报告和 Workbench artifact detail 均可见；
- 继续保持 `batch_apply_supported=false` 和 `word_write_enabled=false`。

## 2. 已实现结构

运行时新增 `_plan_question_figure_repair_batch_apply_execution()`，它会先刷新当前 repair queue，再基于已有 dry-run 重新运行守卫，避免前台拿旧 dry-run 继续生成执行计划。

`batch_apply_execution_plan` 的核心字段：

- `kind=question_figure_repair_batch_apply_execution_plan`
- `status=planned|blocked`
- `freeze_id`
- `dry_run_status`
- `plan_fingerprint`
- `current_plan_fingerprint`
- `expected_freeze_id`
- `expected_plan_fingerprint`
- `fingerprint_matched`
- `final_confirmation_provided`
- `planned_queue_ids`
- `planned_candidate_count`
- `planned_target_count`
- `planned_entries[]`
- `blocked_queue_ids`
- `dry_run_blocked_queue_ids`
- `blockers`
- `execution_plan_fingerprint`
- `plan_id`
- `batch_apply_supported=false`
- `word_write_enabled=false`

`planned_entries[]` 只描述任务草案，不执行替换。每个 entry 包含 queue id、操作名、profile、题号、repair target、replacement source、source issue、guard status 和 entry blockers。

## 3. 阻断边界

执行计划草案会在以下情况阻断：

- 没有已有 `batch_apply_dry_run`；
- dry-run 不是 ready；
- `execution_guard_passed=false`；
- dry-run 自身存在 blockers；
- 未提供最终确认；
- 未提供或不匹配 `expected_freeze_id`；
- 未提供或不匹配 `expected_plan_fingerprint`；
- 当前 plan fingerprint 与冻结 fingerprint 不一致；
- dry-run 没有 ready candidates；
- 单条计划 entry 的 target 或 replacement source 已失效；
- planned target 重复。

这使 N2.263 到 N2.266 的职责边界更清晰：

- N2.263：批量确认前预检；
- N2.264：执行前冻结计划；
- N2.265：冻结计划 dry-run 守卫；
- N2.266：dry-run 通过后的非写入执行计划草案。

## 4. 前台与报告

Markdown batch report 新增摘要：

```text
Batch apply execution plan: status=<status>; planned=<n>; final_confirmation=<provided|required>; batch_apply=false
```

Workbench artifact detail 新增：

```text
exec_plan=<status>; planned=<n>
```

因此用户可以从工作台结果里看到：队列数量、批量确认预案、冻结状态、dry-run 守卫状态，以及执行计划草案状态。

## 5. 不宣称完成

本轮仍不宣称：

- 批量替换题图；
- 批量写回 Word；
- 批量执行结果审计；
- 批量事务回滚；
- 自动候选优先级排序；
- 完整候选对比选择器；
- 图像内容质量判断。

`batch_apply_execution_plan` 是执行前任务草案，不是执行器。

# 模板详情预览统一规划

日期：2026-06-02

## 背景

模板参数详情页的顶部预览区目前已经形成了一个较好的视觉方向：`正文排版` 页用一行三张模块预览卡表达「文字样式 / 对齐与缩进 / 行距与段距」，信息层级稳定，视觉负担也低。

但其它详情页并没有共享同一套信息组织规则：

- `页面设置` 有 5 个预览项，当前按 6 栏网格自然换成两行。
- `标题编号` 的摘要项来自 `HeadingNumberingAdapter.summary_items()`，数量随最大级数变化，天然不稳定。
- `表格` 有 4 个信息密度较高的预览项，当前两行展示。
- `页眉页脚 / 目录` 已有 `SummaryGrid`，但实际在模板面板中按 scope 拆成两个详情页。
- `参考文献 / 题注` 只有左侧导航和概览摘要，右侧详情顶部没有同等的模块预览规则。

因此，目标不应该是“把所有字段都硬塞进一行”，而应该是：

> 所有详情页统一使用同一套预览摘要模型；桌面宽度下顶部预览项优先排成一行；每张卡保留 `value + detail` 两层信息，避免过度压缩和信息丢失。

## 现状定位

### 共享渲染层

当前顶部模块预览主要使用：

- `src/shared/ui/summary_grid.py`
  - `SummaryGridItem` 只有 `key / label / value / detail / column_span / icon_name` 等展示字段。
  - `_ModuleSummaryTile` 固定为图标 + 三层文字。
  - `_effective_columns()` 直接返回固定列数，没有根据宽度或卡片数量重新计算列。
  - 是否换行完全由 `columns`、`column_span` 和条目数量决定。

这意味着“压缩到一行”目前不是组件层能力，而是每个详情页手写 `column_span` 的结果。

### 左侧概览与右侧顶部不是同一条链路

左侧导航摘要和模板概览使用：

- `src/ui/panels/template_format.py`
  - `TemplatePreviewGroupSpec`
  - `build_template_preview_groups()`

右侧顶部预览则分散在各 detail pane 的 `_refresh_summary()` 中：

- `src/ui/panels/template_page_detail.py`
- `src/ui/panels/template_style_detail.py`
- `src/ui/panels/template_table_detail.py`
- `src/ui/panels/template_elements_detail.py`
- `src/ui/panels/heading_numbering_panel.py`

这会导致同一模块的“左侧短摘要”和“右侧顶部预览”各自演化，长期容易漂移。

### 顶部执行开关来自外层

截图中标题旁边的蓝色开关不是各 detail 自己实现的，而是 `TemplatePanel._attach_reformat_toggle()` 把 `_ReformatToggleCard` 插入每个详情页的 summary header。

统一重构时必须保留 header 插槽能力，否则会破坏：

- 标题旁执行开关
- 左侧导航的 `执行 / 跳过 / 部分` badge
- 当前场景模块开关同步

## 设计原则

1. **统一管理，不统一卡片数量**
   - 2 个、3 个、4 个、5 个模块都可以存在。
   - 统一的是数据来源、字段优先级、布局策略和渲染组件。

2. **一行卡片，不强求一行文字**
   - 顶部预览项在桌面宽度下尽量同一行。
   - 卡片内部保留 `value` 和 `detail` 两层，必要时允许轻微换行。

3. **摘要优先，但不隐藏关键信息**
   - `value` 放用户第一眼判断需要的信息。
   - `detail` 放二级参数。
   - 完整字段仍在下方编辑区。

4. **左侧导航摘要和右侧顶部卡片同源**
   - 左侧使用 `nav_summary`。
   - 右侧使用 `detail_items`。
   - 两者由同一个模块 summary spec 构建。

5. **不把局部 UI hack 当成最终方案**
   - 不建议只在某个 detail 里改 `column_span`。
   - 不建议每页单独写压缩规则。

## 统一管理层方案

建议把 `template_format.py` 从“左侧概览摘要”扩展为“模板摘要投影层”，或新建：

`src/ui/panels/template_summary_projection.py`

核心结构建议：

```python
@dataclass(frozen=True, slots=True)
class TemplateSummaryTileSpec:
    key: str
    label: str
    value: str
    detail: str = ""
    icon_name: str = ""
    detail_emphasis: bool = True
    preferred_span: int | None = None
    min_span: int = 2


@dataclass(frozen=True, slots=True)
class TemplateDetailSummarySpec:
    detail_card_id: str
    title: str
    icon_name: str
    nav_label: str
    nav_summary: str
    field_names: tuple[str, ...]
    tiles: tuple[TemplateSummaryTileSpec, ...]
```

再提供统一构建函数：

```python
def build_template_detail_summary(
    cfg: TemplateConfig,
    detail_card_id: str,
) -> TemplateDetailSummarySpec:
    ...
```

现有 `build_template_preview_groups()` 可以变成兼容适配层：

```python
def build_template_preview_groups(cfg: TemplateConfig) -> list[TemplatePreviewGroup]:
    return [
        TemplatePreviewGroup(
            group_id=...,
            detail_card_id=summary.detail_card_id,
            label=summary.nav_label,
            icon_name=summary.icon_name,
            summary=summary.nav_summary,
            field_names=summary.field_names,
        )
        for summary in all_detail_summaries(cfg)
    ]
```

这样左侧概览、左侧导航、右侧顶部预览都能共享同一批字段和格式化 helper。

## 统一渲染策略

### SummaryGrid 扩展

建议让 `SummaryGrid` 支持模块摘要的一行策略，而不是每个 detail 自己算：

```python
SummaryGrid(
    columns=12,
    tile_style="module",
    layout_policy="single_row_preferred",
)
```

推荐 span 策略：

| 卡片数量 | 默认分配 | 用途 |
|---:|---|---|
| 2 | `6 + 6` | 页眉页脚、目录、参考文献 |
| 3 | `4 + 4 + 4` | 正文排版、题注、表格优化后 |
| 4 | `3 + 3 + 3 + 3` | scope=all 的页眉页脚+目录、保留四组时的表格 |
| 5 | `2 + 2 + 2 + 3 + 3` 或按 item 指定 | 页面设置 |

说明：

- 12 栏比当前 6 栏更适合表达 5 卡一行。
- 卡片内部仍可用 `value/detail` 两行表达，不把所有文字压成单行。
- 每个 tile 应设置 tooltip，包含 `label + value + detail`，防止窄宽度下信息不可读。

### 统一 SummaryCard

建议增加共享组件：

`src/shared/ui/template_summary_card.py`

职责：

- 内部包含 `Card`
- 使用 `TemplateSummaryHeader`
- 暴露 `add_control()` 给外层插入执行开关
- 暴露 `add_action()` 给恢复、保存按钮
- 内部持有 `SummaryGrid`
- 提供 `set_summary_items(items)`

兼容要求：

- detail pane 仍保留 `_summary_card` 属性，供 `TemplatePanel._attach_reformat_toggle()` 找到头部。
- summary header 必须继续支持 `add_control()`。
- 迁移期间可以先只统一数据层，暂不一次性替换所有 header。

## 页面级分析与方案

### 1. 页面设置

判断：基本同意“只需要横向调整”，不需要业务逻辑重构。

当前信息结构是合理的：

- 纸张规格
- 页面方向
- 分节方式
- 页边距与装订线
- 页眉与页脚

问题主要是布局：

- 现在 `columns=6`
- 前 3 项 `column_span=2`
- 后 2 项 `column_span=3`
- 结果必然是第一行 3 张，第二行 2 张

推荐方案：

- 保留 5 个预览项。
- 改为 12 栏单行策略。
- span 建议：
  - 纸张规格：2
  - 页面方向：2
  - 分节方式：2
  - 页边距与装订线：3
  - 页眉与页脚：3

这样总和为 12，视觉上仍是一行，而且后两张信息量更大的卡片获得更宽空间。

不推荐方案：

- 不建议把页面设置强行合并成 3 张卡。
- 原因是纸张、方向、分节属于低复杂度但高识别度参数，独立成短卡反而清晰。

需要同步调整：

- `tests/test_template_page_detail.py` 中对 `column_span` 和布局位置的断言。
- loading skeleton 的 summary 高度大概率可保持，但需要截图确认。

### 2. 正文排版

判断：保留为标准参照。

当前结构是最接近目标态的：

- 文字样式
- 对齐与缩进
- 行距与段距

推荐方案：

- 视觉不做明显改动。
- 迁移到统一 summary projection。
- 将当前 `_size_text()`、`_special_indent_text()`、`_line_spacing_text()` 等格式化 helper 收敛到统一投影层，避免左侧概览和右侧卡片各自格式化。

注意：

- 当前 6 栏下每项 span=2。
- 迁移到 12 栏后等价 span 应为 4。

### 3. 标题编号

判断：需要逻辑重构，不适合只调横向布局。

当前问题：

- `HeadingNumberingAdapter.summary_items()` 返回可变数量卡片。
- 默认包含「当前预设」「最大级数」和最多 4 个级别预览。
- 当最大级数为 4 时，span 总量会超过当前 6 栏，最后一个级别容易落到第二行。
- 摘要卡片与下方“结果条 / 样式摘要 / 专家摘要”之间存在信息重复。

推荐改成语义分组，而不是每一级一个顶部卡：

1. 编号方案
   - `value`: 当前预设 / 自定义
   - `detail`: 最大级数、启用级数

2. 级别预览
   - `value`: `第一章 / 1.1 / 1.1.1`
   - `detail`: 最多展示 3-4 级，更多用 `另 N 级`

3. 特殊规则
   - `value`: 非编号标题 / 分隔符 / 目录规则的关键摘要
   - `detail`: 例如 `摘要、目录、参考文献不编号`

下方已有的逐级编辑、行内预览和专家展开继续保留，顶部只做全局判断。

需要新增 adapter 方法：

```python
def detail_summary_tiles(self) -> tuple[TemplateSummaryTileSpec, ...]:
    ...
```

或把构建逻辑完全放进统一 projection，并只调用 adapter 的稳定查询方法：

- `detect_active_preset()`
- `max_levels`
- `preview_number(level)`
- `get_binding(level)`
- `get_non_numbered_texts()`
- `get_non_numbered_prefixes()`

不推荐方案：

- 不建议把当前 6 个卡片改成更窄的一行。
- 级别卡片的数量随着配置变化，信息结构不稳定，压缩后更难读。

### 4. 表格

判断：需要优化信息分组，但不需要像标题编号那样大规模重构。

当前 4 张卡：

- 边框与布局
- 线宽
- 字体与对齐
- 输出行为

问题：

- 4 张卡如果强行同一行，每张只有 1/4 宽。
- `输出行为` 文案容易变长，例如 `不首行加粗 / 不跨页重复表头 / 表格居中`。
- `线宽` 与 `边框/行距` 在用户心智上更接近，拆开会让顶部预览显得碎。

推荐优化成 3 张卡：

1. 表格结构
   - `value`: 边框样式 / 布局模式
   - `detail`: 智能层级、颜色表子样式

2. 线宽与行距
   - `value`: 三线表外线 / 表头下线，或网格线宽
   - `detail`: 表格行距、边框模式下不生效提示

3. 文字与输出
   - `value`: 字体 / 字号 / 单元格对齐
   - `detail`: 首行加粗、重复表头、表格对齐

这样和正文排版一样成为一行三卡，但不是简单照搬正文排版。

需要同步：

- `tests/test_template_secondary_details.py` 中 `border / width / type / behavior` 的断言。
- 左侧概览 `_table_group_summary()` 可由同一 projection 生成短摘要。

### 5. 页眉与页脚

判断：已有同款 SummaryGrid，scope 分页后实际是两张卡，一行展示即可。

当前模板面板中：

- `tpl_header_footer` 使用 `ElementsDetail(scope="header_footer")`
- 右侧顶部只有：
  - 页眉
  - 页脚内容

推荐方案：

- 保持 2 张卡。
- 12 栏下每张 span=6。
- 文案可微调，但不需要重构。
- 页码分区信息仍放在 `页脚内容.detail`，最多展示 2 个 phase，更多用 `另 N 段`。

注意：

- `ElementsDetail()` 默认 scope=`all` 在测试里仍可能出现 4 张卡。
- 统一布局策略要同时支持 2 卡和 4卡。

### 6. 目录

判断：已有同款 SummaryGrid，scope 分页后实际是两张卡，一行展示即可。

当前模板面板中：

- `tpl_toc` 使用 `ElementsDetail(scope="toc")`
- 右侧顶部只有：
  - 目录结构
  - 目录样式

推荐方案：

- 保持 2 张卡。
- 12 栏下每张 span=6。
- `目录结构` 展示开启状态、模式、级数。
- `目录样式` 展示标题/条目字号、主要字体。

### 7. 参考文献

判断：缺少右侧顶部预览规则，需要补齐。

当前问题：

- `ReferenceDetail` 顶部只有说明卡。
- 没有 `_summary_grid`。
- 只有左侧概览能看到 `悬挂缩进 / 段后`。
- 右侧进入后，用户无法像其它页一样先扫一眼当前规则。

推荐新增 summary card，并保留现有编辑结构：

1. 段落样式
   - `value`: 跟随正文 / 独立设置
   - `detail`: 有效字体、字号、字形、对齐

2. 引文规则
   - `value`: 悬挂缩进 `0.74cm`
   - `detail`: 条目段后、单位

如需第三张卡，可后续加入“继承来源 / 输出范围”，但当前配置字段不够丰富，不建议为了凑三张而造概念。

实现建议：

- 增加 `_summary_card` 和 `_summary_grid`。
- header 使用统一 `TemplateSummaryHeader`，这样外层执行开关可自然插入。
- 原 `_header_card` 可以降级为说明/模式区，或直接并入 summary card 下方。
- `_update_inherit_summary()` 的内容应与 summary projection 共享同一套有效样式格式化 helper。

测试建议：

- `ReferenceDetail` 构造后存在 `_summary_grid`。
- 跟随正文模式下显示 `跟随正文`。
- 独立设置模式下显示 `独立设置` 和有效字体字号。
- 修改悬挂缩进后 summary 和左侧导航同步更新。

### 8. 题注

判断：缺少右侧顶部预览规则，并且当前表单过长，顶部摘要更有必要。

当前问题：

- `CaptionDetail` 只有一个大 Card，里面放 header、说明、全部表单和 footer note。
- 没有 `_summary_grid`。
- 左侧概览能显示题注前缀、编号模式、自动补题注、域编号，但右侧顶部没有结构化预览。

推荐新增 3 张 summary 卡：

1. 题注文本
   - `value`: `图 / 表`
   - `detail`: 分隔符、占位文本

2. 编号规则
   - `value`: 章节编号 / 全局编号
   - `detail`: 编号格式、自动补题注、域编号/纯文本编号

3. 题注样式
   - `value`: 字体 / 字号
   - `detail`: 字形、对齐、段前段后

实现建议：

- 增加 `_summary_card` 和 `_summary_grid`。
- 将现有 `_card` 改为 `_editor_card`，避免 summary 和编辑表单混在一个大 Card。
- 题注样式使用 `styles["caption"]`，不存在时按当前逻辑回退到 `body / normal / StyleConfig()`。
- `_caption_group_summary()` 改用统一 projection 的短摘要。

测试建议：

- `CaptionDetail` 存在同款 `SummaryGrid(tile_style="module")`。
- 修改 `format_inserted` 后右侧 summary 和左侧 nav 都显示 `域编号`。
- 修改 caption style 后 summary 的字体、字号、对齐更新。

## 推荐迁移步骤

### 阶段 1：建立统一 projection，不改视觉

目标：

- 新建或扩展 `template_summary_projection.py`。
- 先让它能生成所有 detail 的 `nav_summary` 和 `tiles`。
- 保持现有 detail pane 自己渲染，先通过测试确认文案一致。

收益：

- 降低一次性 UI 改动风险。
- 先统一“信息从哪里来”。

### 阶段 2：页面设置横向调整

目标：

- `页面设置` 改为 12 栏一行：`2/2/2/3/3`。
- 不改变 5 个预览项。

原因：

- 这是最小、最符合当前信息结构的改动。

### 阶段 3：表格摘要优化

目标：

- 4 卡改 3 卡。
- 文案从字段堆叠改为语义分组。

原因：

- 表格的字段多，但可以自然归并。

### 阶段 4：补齐参考文献和题注 summary card

目标：

- `ReferenceDetail`、`CaptionDetail` 使用与其它页一致的顶部 summary card。
- 外层执行开关仍可插入。

原因：

- 这是当前一致性缺口最大的位置。

### 阶段 5：标题编号摘要逻辑重构

目标：

- 摘要从“每级一个卡片”改为“编号方案 / 级别预览 / 特殊规则”。
- 下方逐级编辑继续保留，不把所有级别塞进顶部。

原因：

- 标题编号的信息结构最复杂，应该最后改，且需要回归较多交互测试。

### 阶段 6：抽出 TemplateSummaryCard

目标：

- 所有详情页统一 header、执行开关插槽、保存/恢复按钮、SummaryGrid。
- 清理各 detail 中重复的 `_build_summary_card()`。

原因：

- 等 projection 和页面行为稳定后再抽组件，风险更低。

- 标题编号最大级数变化后，顶部 summary 仍为固定 3 卡，下方级别列表正常更新。

### 视觉回归建议

- 用截图覆盖至少三个宽度：
  - 1280 级别桌面宽度
  - 960 中等宽度
  - 700 窄宽度
- 重点检查：
  - 顶部 summary 是否一行优先。
  - `value/detail` 是否被挤到不可读。
  - header 执行开关是否仍贴近标题。
  - 保存/恢复按钮是否仍靠右。

## 风险与注意事项

1. `SummaryGridItem` 目前没有 tooltip、优先级和布局策略字段。
   - 如果只改 `column_span`，会继续依赖局部经验。

2. `TemplatePanel._attach_reformat_toggle()` 依赖 detail 的 `_summary_card` 和第一项 header。
   - 抽新组件时必须兼容这个查找方式，或同步改成明确接口。

3. loading skeleton 高度可能需要调整。
   - `DETAIL_LOADING_SKELETONS` 里 summary 高度现在多为 112-118。
   - 单行 5 卡后高度理论上仍接近，但需要截图确认。

4. 标题编号已有较多结构测试。
   - 重构顶部 summary 时要避免影响下方 fixed three-section layout、inline preview、inspector summary。

5. 参考文献和题注补 summary 后，当前测试里对表单 label baseline 的断言仍应保留。
   - 新 summary card 不应改变下方表单行对齐策略。

## 最终目标形态

最终每个模板详情页都应满足：

- 顶部：统一 summary card
  - 标题 + 执行开关 + 恢复/保存
  - 一行优先的模块 summary grid

- 中部：当前模块的编辑区
  - 字段完整
  - 不为了顶部摘要而隐藏必要控制

- 左侧：导航短摘要
  - 与右侧顶部来自同一 projection
  - 只展示最短可判断信息

一句话目标：

> 让所有模板详情页都先给用户一个稳定、可扫读、不中断上下文的“当前规则预览”，再进入完整参数编辑；摘要由统一规则生成，展示由统一组件控制，各页面只关心自己的业务字段。

# 高层场景能力矩阵 N2.393g Gap Domain 分类读数归因补充

## 背景

N2.393e 已将 `scene_product_maturity_upgrade_gap_count=6` 补成 `retained_gaps=6/6 enveloped`。继续扫描 release gate 后，剩下一个容易被误读的成熟度读数是 `scene_product_maturity_upgrade_gap_domain_count=3`。

这不是新的缺口数量，而是 6 个 retained gaps 被归入的 3 类边界域。本轮补充的发布读数是：`gap_domains=3/3 classified`。

## 闭环定义

`gap_domains=3/3 classified` 表示：

- 分母 3 来自 `scene_product_maturity_upgrade_audit.gap_domain_count`；
- 分子 3 来自同一审计报告的已分类 domain 集合；
- 如果某个 retained gap 缺少 `gap_domain_ids`，`scene_product_maturity_upgrade_audit` 会产生 issue；
- `gap_domain_counts` 必须能说明每类 domain 的分布。

当前分类结果：

| domain | count |
| --- | ---: |
| `runtime_execution` | 1 |
| `report_artifact` | 1 |
| `boundary_gate` | 6 |

## 链路

```text
scene_product_maturity_upgrade_audit.gap_domain_ids
  -> scene_product_maturity_upgrade_audit.gap_domain_counts
  -> verify_scene_matrix_release_gate.py: gap_domains=3/3 classified
  -> maturity_upgrade dashboard card
  -> scene_summary_projection
```

## 发布要求

- release gate 最终摘要必须展示 `gap_domains=3/3 classified`；
- `maturity_upgrade` 卡片必须展示 `3/3 domains classified`；
- summary projection 的 Boundary、Evidence、Readiness 视角必须展示 `3/3 gap domains classified`；
- `scene_product_maturity_upgrade_audit` 的 source evidence 必须检查 release gate 中的 `gap_domains=` marker。

## 非目标

本轮不改变 gap domain 分类规则，也不消除 retained gaps。它只关闭“gap domain count 是否只是分类维度”的读数解释缺口。

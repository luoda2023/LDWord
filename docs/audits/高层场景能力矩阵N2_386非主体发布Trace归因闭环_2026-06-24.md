# 高层场景能力矩阵 N2.386 非主体发布 Trace 归因闭环

## 目标

N2.385 已经把 26 条能落到 Blue/Boundary subject 的发布例外 trace 汇总成 6 个边界主体发布证据包。但 N2.384 的总账共有 36 条 trace，剩余 10 条并不应该被硬塞进边界主体：它们是 dashboard 投影、registry-only profile、pack-level plugin/manual warning 或 generic not-applicable surface。

本轮补 `non_subject_trace_attribution`：任何不属于边界主体的 release trace，也必须有明确产品归因。这样发布账本不会出现“有 trace，但既不属于 subject dossier，也没有解释”的悬空残留。

## 归因类型

| 归因类型 | trace 数 | 产品含义 |
| --- | ---: | --- |
| `dashboard_projection_surface` | 6 | dashboard 只是投影已治理 warning，不拥有独立边界主体 |
| `registry_only_profile_reference` | 2 | `basic`、`word_xml_full` 是共享/审计型 CountProfile reference，不是场景主体 |
| `plugin_manual_pack_boundary` | 1 | `exam_education` 的 AI/复杂图示能力保留 pack-level plugin/manual gate |
| `generic_not_applicable_surface` | 1 | `quick_formatting` 不承担场景专属 CountProfile |

验收读数：

- `trace_count = 10`
- `attributed_trace_count = 10`
- `unattributed_trace_count = 0`
- `dashboard_projection_trace_count = 6`
- `registry_only_profile_trace_count = 2`
- `plugin_manual_pack_trace_count = 1`
- `generic_not_applicable_trace_count = 1`
- `issue_count = 0`

## 闭环规则

非主体 trace 的处理原则：

- 能归属 Blue/Boundary subject 的 trace 必须进入 N2.385 subject dossier；
- 不能归属 subject 的 trace 必须进入本归因账本；
- 如果新增 non-subject trace 没有匹配归因规则，`unattributed_trace_count` 必须大于 0，并阻断 release gate；
- dashboard projection 不能冒充真实业务缺口，registry-only profile 不能冒充 family readiness 缺口，generic not-applicable 不能冒充未实现能力。

最终发布口径应同时满足：

- `exception_trace_count = 36`
- `boundary subject traces = 26`
- `non-subject attributed traces = 10`
- `unattributed trace = 0`

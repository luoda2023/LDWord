# 高层场景能力矩阵 N2.378 边界能力矩阵证据闭环

本文承接 N2.375-N2.377 的 Green/L5 场景收口，并专门处理剩余 Blue/Boundary 主题。目标不是把外部专业判断或真实 OCR/PDF/LaTeX 插件伪装成核心能力，而是把边界型高频场景做成可审计、可呈现、可阻断误承诺的产品能力矩阵。

## 本轮结论

本轮新增 `scene_boundary_capability_matrix`，将剩余 6 个 Blue/Boundary 主题显式登记为边界能力：

| 能力 | 主题 | 分组 | 核心可做 | 明确不做 |
| --- | --- | --- | --- | --- |
| `professional_disclosure_boundary_matrix` | `pack:professional_disclosure` | professional | 专业请求路由、专业 family 报告、人工/插件门禁 | 审计、法律、财务、专利、医疗、翻译质量判断 |
| `import_ai_boundary_confidence_matrix` | `pack:import_ai_boundary` | import_ai | 转换置信度、阻断对象、handoff 路由 | 无损转换保证、AI 内容正确性、复杂图生成质量 |
| `finance_quote_boundary_depth` | `family:finance_quote_documents` | professional | 报价字段、工作簿来源、表格映射、附件清单 | 财务审计判断、报价正确性验证 |
| `ip_patent_boundary_depth` | `family:ip_patent_documents` | professional | 章节/图号/术语/权利要求占位符 inventory | 授权前景、侵权、权利要求质量判断 |
| `bilingual_translation_boundary_depth` | `family:bilingual_translation_documents` | professional | 语种、术语库、未解决术语、双语对照版式 | 翻译质量保证、静默改写双语含义 |
| `regulated_disclosure_boundary_depth` | `family:regulated_disclosure_documents` | professional | 披露期间、规则来源、章节/表格/附件、归档包 | 审计保证、监管披露完整性结论 |

## 吸纳的既有规划

- V7/V8/V9 规划中反复出现的财务报价、IP/专利、双语审校、年报/ESG/披露材料，均保留为高频边界型 family。
- V43 中提出的 `professional_disclosure`、`import_ai_boundary` 不应升级为核心自动能力，本轮继续保留 Blue/Boundary，但补齐证据矩阵。
- `count_engine_tech_record.md` 中与表格、附件、双语对照、章节 inventory 有关的计数/结构思想，吸收到 finance、bilingual、regulated 的 schema 和 report expectation 中。
- `exam_generator_tech_stack_record.md` 中的 AI 内容质量、复杂图、置信度/人工确认边界，继续作为 `import_ai_boundary` 的 confidence artifact 与 handoff 规则，不并入核心执行。

## UI 与控件风格一致性

场景配置页仍复用模板管理的控件语言：

- 表单输入、缩进、段前段后、特殊缩进等交互继续由共享控件和同一行布局约束；
- 边界能力矩阵不新增独立表单控件，而是接入 `SummaryGrid` 的 `boundary_capability_evidence` 证据卡；
- `build_boundary_capability_evidence_summary_items()` 只展示 reports、UI surfaces、gate 和 fixture，不承担专业判断入口；
- `scene_control_runtime_consistency_audit` 与既有 `test_scene_panel_controls_follow_template_management_contract` 继续保证控件样式和控制语义不分叉。

## 成熟度口径

本轮关闭的缺口：

- `professional-family report depth`
- `confidence report artifacts`
- `spreadsheet table mapping depth`
- `claim-quality boundary UI`
- `termbase UI`
- `regulated rule source governance`
- `assurance boundary UI`

仍保留的非核心缺口：

- `real plugin ecosystem`
- `real OCR/PDF/LaTeX plugin integration`
- `finance plugin handoff`
- `IP plugin handoff`
- `translation-quality plugin handoff`
- `external assurance review handoff`

这些不是当前核心格式化能力缺失，而是明确的外部专业/插件实现边界。产品可以展示、阻断、记录、交接，但不能在核心执行里承诺完成。

## 验证目标

本轮应满足：

- `scene_boundary_capability_matrix`：6/6 ready；
- release gate 增加 `scene_boundary_capability_count`、`scene_boundary_capability_ready_count`、fixture/report/UI 计数；
- Scene Summary 出现 `boundary_capability_evidence`；
- family fixture depth 中 4 个 P2 专业 family 均有 family 级报告深度；
- product maturity gap 从 12 收敛到 6，只剩外部专业/插件 handoff 类缺口。

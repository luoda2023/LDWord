# 高层场景能力矩阵 N2.330 考试题目图片素材库跨包主数据订阅漂移冲突批量失败恢复自动回滚补偿历史输出追溯修复闭环

日期：2026-06-22

## 1. 本轮目标

N2.329 已经让订阅漂移批量失败恢复后的回滚、补偿、历史输出追溯进入治理记录，但还没有执行层承接。本轮承接 `batch failure recovery automated rollback compensation execution historical Word output trace repair UI`，新增自动执行与历史输出追溯修复首片：用户可以从 followup 治理记录继续生成执行审计，并产出 JSON/Markdown trace repair artifact。

本轮不声明已经实现多 archive 后台 worker、自动批量回滚真实改写、二次补偿 connector 或历史 Word 媒体文件重写。当前只承诺：当前 EntityArchive 内的题图素材订阅漂移恢复后续治理记录，可以进入自动执行/追溯修复表，写入执行审计、trace repair artifact 和题图素材 metadata。

## 3. 链路边界

当前链路是：

1. 批量失败恢复队列形成恢复报告。
2. 恢复报告生成 Drilldown artifact。
3. SLA center 记录恢复 SLA。
4. followup 表记录回滚、补偿、历史输出治理。
5. 自动执行表从 followup 记录派生执行候选。
6. 用户点击“执行修复”。
7. 系统写入自动执行审计。
8. 系统生成 trace repair JSON/Markdown artifact。
9. 可匹配题图素材同步写入自动执行与 trace repair metadata。
10. 表格仍可定位回恢复明细。

本轮的 `historical Word output trace repair` 是 trace 级修复产物：它建立历史输出需要复核与后续媒体重写的证据链，不直接打开并改写历史 `.docx` 文件中的媒体关系、图片二进制或 Word XML。

## 5. 仍未闭合边界

N2.330 后，明确剩余缺口不再是“有没有自动执行与 trace repair 入口”，而是更深的后台和 Word 文件级执行：

- 真正后台 worker、队列调度和任务状态持久化；
- 多 archive 文件级失败恢复中心与索引；
- 跨进程幂等任务锁、跨批次互斥和断点续跑；
- 自动批量回滚对素材主数据与本地引用的真实改写；
- 二次补偿 connector；
- 历史 `.docx` 输出的 Word media rewrite；
- 历史 Word XML / relationship / media 文件一致性修复；
- 非题图素材族的同类跨包主数据订阅漂移批量失败恢复治理。

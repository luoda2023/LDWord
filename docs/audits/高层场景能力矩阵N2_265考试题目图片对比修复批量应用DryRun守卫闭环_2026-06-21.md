# 高层场景能力矩阵 N2.265 考试题目图片对比修复批量应用 Dry-Run 守卫闭环

## 1. 本轮定位

N2.264 已经把批量确认从“预检计划”推进到“冻结计划”：前台必须显式确认某个 `plan_fingerprint` 后，才能形成 `batch_confirmation_freeze`。N2.265 补的是冻结计划进入未来批量执行前的 dry-run 守卫：在不写回 Word、不替换题图的前提下，重新验证冻结候选是否仍然可执行。

本轮仍不执行批量替换。它只回答：当前冻结计划如果进入未来批量执行，是否已经满足最基本的执行前条件。

## 2. 已实现能力

- 新增 `_dry_run_question_figure_repair_batch_apply_guard()`。
- 输入当前 `question_figure_repair_queue`，重新刷新队列状态和当前 `batch_confirmation_plan`。
- 消费既有 `batch_confirmation_freeze`，并校验：
  - freeze 是否存在；
  - freeze 是否为 `frozen|partial_frozen`；
  - freeze 是否已显式确认；
  - freeze 自身是否有 blockers；
  - 可选 `expected_freeze_id` 是否匹配；
  - 可选 `expected_plan_fingerprint` 是否匹配；
  - freeze 的 `plan_fingerprint` 是否仍等于当前 plan fingerprint；
  - `frozen_queue_ids` 是否仍在当前 eligible 集合；
  - replacement source 本地文件是否仍存在；
  - repair target 是否存在；
  - 冻结候选之间是否存在重复目标。
- 生成 `batch_apply_dry_run` payload：
  - `kind=question_figure_repair_batch_apply_dry_run`
  - `action=dry_run_question_figure_repair_batch_apply_guard`
  - `status=ready|blocked`
  - `freeze_id`
  - `freeze_status`
  - `plan_fingerprint`
  - `current_plan_fingerprint`
  - `expected_plan_fingerprint`
  - `expected_freeze_id`
  - `fingerprint_matched`
  - `checked_queue_ids`
  - `checked_candidate_count`
  - `checked_target_count`
  - `ready_queue_ids`
  - `blocked_queue_ids`
  - `candidate_results`
  - `blockers`
  - `batch_apply_supported=false`
  - `execution_guard_passed`
- 若冻结后来源文件丢失，当前 plan fingerprint 会变化，dry-run 会同时暴露 `plan_fingerprint_mismatch` 和 `frozen_candidate_not_currently_eligible`。
- batch Markdown report 新增 `Batch apply dry-run` 摘要。
- Workbench artifact detail 新增：
  - `dry_run=<status>`
  - `checked=<n>`
- `scene_product_readiness` 为 `pack:exam_education` 和 `family:exam_teaching` 新增 `question asset comparison repair queue batch apply dry-run guard bridge` evidence。

## 3. 链路闭合

当前链路推进为：

`question_figure_repair_queue.entries[]` -> `batch_confirmation_plan` -> `batch_confirmation_freeze` -> `batch_apply_dry_run` -> batch Markdown report -> Workbench artifact detail -> product readiness evidence -> tests/release gate

这让未来批量执行之前拥有最后一层非破坏性守卫：即使计划曾经被冻结，只要队列或本地文件状态变化，dry-run 也会阻断，而不是继续进入写回。

## 4. 明确不宣称完成

- 不做批量替换执行。
- 不做批量写回 Word。
- 不做批量事务回滚。
- 不做自动候选优先级排序。
- 不做完整候选对比选择器。
- 不做图像内容质量判断。
- 不绕过 conflict/blocked/rejected 候选。

当前能力只承诺：冻结计划进入未来批量执行前，可以进行一次非破坏性 dry-run 守卫检查，并把结果报告到 Markdown、Workbench artifact 和成熟度 evidence。

## 6. 与 V43 主矩阵的关系

V43 的 P0 高级考试素材库路线从 N2.264 的“批量确认冻结计划桥”推进到 N2.265 的“批量应用 dry-run 守卫桥”。此前“批量确认执行”边界继续被拆细为：

1. N2.263：批量确认前预检；
2. N2.264：执行前冻结计划；
3. N2.265：冻结计划 dry-run 守卫；
4. 后续仍需单独推进真正批量执行、执行结果审计和批量/事务回滚。

# 图片规则独立卡片与恢复空态一致性审计

日期：2026-07-12，2026-07-13 更新  
状态：已实施、已做真实界面验证

## 1. 本轮目标

1. 将图片插入与水印策略从“图片资料”内部移出，作为图片页最上方的独立“图片规则”卡片。
2. 查清点击“恢复”后，“未选”缩略图为何从带边框方框变成悬空文字。
3. 将逐 Token 微调收敛为一次设置、全部图片统一继承，同时保持资料包兼容。
4. 收口恢复链路中的重复投影、默认规则误报 dirty 和动态行主题生命周期问题。

## 2. 改造前后的所有权

改造前：

```text
图片页
└─ 图片资料 Card
   ├─ 单图
   ├─ 多图文件夹
   ├─ 图片规则（尺寸、水印）
   └─ 题图相关内容
```

改造后：

```text
图片页
├─ 图片规则 Card
│  ├─ 插入方式：直接插入 / 自适应缩放
│  └─ 全局图片水印
└─ 图片资料 Card
   ├─ 单图
   ├─ 多图文件夹
   └─ 题图相关内容
```

两张卡片都是图片页的直接子项，顺序固定为“图片规则 → 图片资料”。规则卡由 `ImageRulesPresenterMixin` 自己创建，不再由图片清单 presenter 顺带装配。

## 3. “恢复后未选变样”的真实根因

数据没有变成另一种状态，控件类型也没有变化。恢复前后仍然是：

- `QLabel` 缩略图控件；
- 固定 `52 × 52`；
- 文本为“未选”；
- 路径框占位为“尚未选择图片”。

问题来自样式生命周期：

```text
恢复图片资料
→ set_archive
→ 资料投影到编辑器
→ 根据 Token 清单 reconcile 图片行
→ 旧 key 包含 role + label + target
→ Token 回滚被误判成“另一行”
→ 销毁旧行并创建新行
→ 新行只获得部分构造期样式
→ 缩略框、序号、路径框没有再次执行面板级主题扫描
```

所以界面出现“半正常、半原生”的混合态：

- Token 编辑器和右侧操作按钮在构造时自带主题，因此仍正常；
- 外层行每次 update 都会刷新，因此仍正常；
- 缩略框、蓝色序号和路径输入框过去只依赖面板初始化时的一次全局扫描，因此新行的 QSS 为空。

真实复现的样式签名：

| 状态 | 缩略图 QSS 长度 | 序号 QSS 长度 | 路径框 QSS 长度 | 路径框 sizeClass |
|---|---:|---:|---:|---|
| 初始未选 | 314 | 89 | 1652 | `md` |
| 旧实现 Token 重建后 | 0 | 0 | 0 | 空 |
| 修复后恢复重建 | 314 | 89 | 1652 | `md` |

## 4. 已采用的修复

### 4.1 稳定业务身份

单图和多图行统一以 `role` 作为稳定身份。`label`、`target`、tooltip 都是可变展示数据，由 updater 原位刷新，不再用它们决定控件身份。

收益：

- Token 改名与恢复不再无意义地销毁控件；
- 焦点、几何和空态视觉保持稳定；
- 规则展开后的锚点始终取当前 Token，不残留旧值。

### 4.2 动态组件立即投影主题

列表 reconcile 发现新增行时，立即执行局部资料行主题投影。它覆盖单图、多图和动态附件行，不再依赖“面板启动后恰好扫过一次”。全局主题切换仍复用原有完整主题入口。

这不是在恢复按钮后硬补 `_apply_theme()`；样式责任归属于动态组件的创建生命周期，因此新增、恢复、场景变化都走同一条规则。

### 4.3 缩略图尺寸统一

单图缩略图加载尺寸改为读取控件实际尺寸，默认回退 `52 × 52`，消除控件为 52、图片却按 56 请求缩放的偏差。

### 4.4 默认规则与持久化基线归一化

旧资料包可能没有显式 `image_material_rules`，但编辑器会为现有 Token 补出默认规则。如果持久化基线仍保留原始空字典，资料包刚加载或刚恢复就会被误判为 dirty。

现在保存基线取“完成兼容归一化后的工作快照”，保证：

- 默认规则仍能进入现有运行链；
- 刚加载、刚恢复时恢复/保存按钮保持禁用；
- 用户真正改插入策略或水印后才进入 dirty；
- 恢复后回到默认值并重新变为 clean。

### 4.5 恢复只 hydrate 一次

旧 `set_archive()` 先通过资料列表加载当前 profile，随后又手工投影同一 profile，导致每次恢复重复 reconcile 两遍。现已收敛为：

```text
一次模型装载 → 一次编辑器投影 → 一次批次状态同步
```

### 4.6 单开关取代固定厘米宽度

旧“固定尺寸 6.0 cm”实际表示固定宽度，高度按图片宽高比计算。该语义已不再暴露给用户。新界面只暴露一个全局功能开关“自适应缩放”：

- **未启用**：直接插入，按图片在 96 DPI 下的自然尺寸插入；若超过当前栏宽，只缩小到栏宽，不按页面剩余高度强制压缩。
- **已启用**：单图按锚点页剩余宽高等比缩放，保持标题与图片同页；多图按当前栏宽统一缩放并参与正常分页。

内部仍按每个角色展开 `ImageMaterialRule`，以兼容既有装配、冻结和审计链，但用户只管理一份策略。旧包中的逐 Token 固定宽度会归一为未启用；任一旧规则已经使用锚点页自适应时，整包归一为已启用。水印同样归一为一份全局设置。

### 4.7 缩放与水印独立启用，水印来源显式建模

“自适应缩放”和“图片水印”是两条正交策略，界面分别以前置复选框启用，任何一项变化都不能改写另一项。水印启用后再选择来源：

- **固定字段**：在图片规则卡填写固定文本或 `{{字段}}` 模板，执行前用冻结字段值解析；
- **自由字段**：图片规则卡不保存本次文本，输入框提示“在工作台填写”，由工作台为本次执行提供运行时文本。

数据链路采用两个不同所有权：`ImageWatermarkPolicy.text_source` 是资料包配置，`MaterialExecutionContext.image_watermark_text` 是单次执行数据。自由字段依次经过 Workbench context、`MaterialAssemblyRequest.runtime_image_watermark_text`、`ImagePolicyFreezer`，只在 Freeze 边界固化为 `ResolvedImageWatermark`。未填写时由 Workbench 预检明确报错，不允许执行阶段猜值，也不把自由文本污染到实体字段表。

### 4.8 单图、多图列引导与用户名称

单图和多图文件夹统一增加轻量列引导：`序号 / 预览 / 占位符 / 名称 / 来源 / 操作`。表头和数据行共用 `AssetColumnMetrics`，操作列按各分区的最大动作数量预留稳定宽度，因此多图在选中目录后显示“刷新/打开”时不会推动前方列跳动。

“名称”直接复用资料包已有的 `AssetTokenSpec.label`，不是新的旁路元数据。用户可填写诸如“ISO9001质量管理体系认证证书”的业务名称；名称与 `{{占位符}}` 独立编辑，修改占位符不再重置名称。名称和占位符共同复用 `InlineCopyEdit` 交互状态机：单击复制、双击进入编辑、Esc 回滚本次编辑、失焦后回到只读展示态；两者只保留各自的视觉子类，不再重复维护鼠标和键盘事件。保存、恢复、复制资料包继续走现有 `asset_token_specs` 原子快照。

视觉语义保持两类而不再增加配置注册层：`MaterialTokenEdit` 是无边框的精确占位符文本，`MaterialNameEdit` 是有边框的可填写名称。名称输入框直接调用全局 `build_text_input_stylesheet`，与字段内容共享背景、边框、圆角、内边距、尺寸分级和主题切换；双击编辑时才把焦点边框切换为强调色。数据所有权、提交函数和持久化结构均不因此改变。

宽度低于 900 logical px 时只折叠可选的只读来源列，`序号 / 预览 / 占位符 / 名称 / 操作` 导航仍保留；低于 680 logical px 才整体折叠列引导。这样在 Windows 缩放和常见笔记本宽度下不会出现“数据行存在、列语义消失”的状态。宽屏下六列起点通过实际 Qt 几何逐列校验。

### 4.9 路径动作语义统一

路径按钮不再按页面临时挑图标，统一由 `PathAction` 注册表提供语义：

| 动作 | 图标 | 边界 |
|---|---|---|
| 选择图片 | `image` | 打开图片文件选择器 |
| 选择文件 | `file-text` | 打开通用文件选择器 |
| 选择文件夹 | `folder-output` | 绑定一个目录作为来源 |
| 打开文件 | `square-arrow-out-up-right` | 用系统程序打开文件 |
| 打开所在文件夹 | `folder-open` | 打开当前来源的父目录 |

单图行因此同时保留“选择图片”和“打开所在文件夹”两个独立动作：空态时后者禁用，选择图片后启用；多图行的目录选择使用 `folder-output`，已绑定目录的打开动作使用 `folder-open`。文件资料、附件和工作台输出目录选择也接入同一注册表。资料包、方案、模板和运行结果中原有的 `folder-open` 经审计均确实是打开目录，因此保持不变。本产品尚未发布，本轮直接收敛当前模型和控件，不增加旧图标行为兼容层。

### 4.10 单击复制与双击编辑的会话边界

名称控件不再设置“单击复制，双击修改名称”的操作说明 Tooltip，避免它遮挡同一行的操作按钮。操作说明只保留为无视觉弹层的无障碍名称。后续长文本核验补充了内容型悬浮卡片：仅当名称或 Token 的可见投影确实省略时显示完整值，未省略或进入编辑后立即清空；它不承担交互教学。

Qt 的普通 `QLabel`、空白容器通常不接收焦点，因此仅依赖 `QLineEdit.editingFinished` 会产生“点了外部仍停留在蓝框编辑态”的卡死状态。现在由共享 `InlineEditDismissalGuard` 在编辑期间管理会话：

- 点击编辑器之外的任意控件或空白区域时结束编辑；
- 窗口失活、页面隐藏时结束编辑并移除应用级事件过滤器；
- 修改后点击外部按正常完成提交，未修改时只退出，不产生图片域 dirty；
- `Esc` 恢复进入编辑前的文本，回车或正常失焦提交；
- 控件销毁时事件过滤器随 QObject 所有权自动清理，不残留跨页面监听。

真实双击包含第一次单击释放。若在该释放事件里立即弹出复制反馈，用户会先看到“复制成功”再进入编辑。`ConfirmedCopyEmitter` 因此将剪贴板写入与可视反馈分离：剪贴板在单击时立即更新，复制成功信号只在系统双击判定间隔结束后发出；一旦收到双击事件就取消待发反馈。

审阅还发现 `OfficialFieldValueEdit` 曾有一套独立的旧事件过滤逻辑，存在相同的外部点击卡死与双击误提示风险。它现在和名称/Token 控件共同复用 `InlineEditDismissalGuard` 与 `ConfirmedCopyEmitter`；单行、正文多行两种字段值编辑器继续保留各自编辑能力，但不再各自定义会话边界。多行 `QTextEdit` 的真实鼠标事件由内部 viewport 接收，交互监听同时覆盖编辑器和 viewport，避免测试调用外层控件能进入编辑、用户真实双击正文区域却没有反应的伪通过。

## 5. 为什么只拆视觉卡片，没有强拆两套恢复事务

图片规则虽然视觉上独立，但 `ImageMaterialRule.anchor_token`、必填性和单图/多图基数仍由图片 Token 清单派生。若现在把恢复域硬拆成“图片资料”和“图片规则”两份，会出现以下问题：

- 恢复图片 Token 后，规则锚点可能仍指向旧 Token；
- 单图/多图类型变化可能与规则 placement/cardinality 不一致；
- 两张卡片分别恢复后，组合状态未必是一个可执行快照。

因此本轮边界是：

- **视觉所有权独立**：两张同级 Card；
- **持久化仍原子**：图片 Token、选择、绑定与规则仍属于同一个 `images` 恢复事务；
- **保存仍是资料包级保存**。

图片域共用的“恢复/保存”入口放在位于页面首位的“图片规则”卡片右上角，不再挂在下方“图片资料”卡片上。按钮作用域仍是整个图片域；本次只修正操作入口的视觉归属，不拆分事务。

如果未来确实要做两套独立恢复，前置条件是先把规则中的派生字段改为运行时解析，或建立显式的跨卡一致性事务，不能只把字段列表机械拆开。

## 6. 回归不变量

1. 图片规则 Card 在图片资料 Card 之前，两者均直接属于图片页。
2. 规则容器不能成为图片资料 Card 的后代。
3. 同一 `role` 的 Token 改名不改变行控件身份。
4. 动态新增或恢复重建的单图、多图、附件行无需手工刷新主题。
5. 初始未选、选图后清除、Token 改名后恢复的空态视觉签名一致。
6. 规则卡不显示 Token 列表、厘米输入或说明段落。
7. 旧包默认规则加载与恢复后不制造假 dirty。
8. 一次 `set_archive()` 只 hydrate 当前 profile 一次。
9. 全局策略变更后，所有单图和多图规则使用同一用户意图及同一水印。
10. 缩放与水印开关互不改写；自由字段文本只属于单次 Workbench 执行。
11. 名称与占位符均为单击复制、双击编辑，交互状态机只有一个实现。
12. `folder-open` 只表示打开目录；选择图片、文件、目录使用各自独立语义。
13. 外部点击、窗口失活或页面隐藏后不能残留蓝框编辑态和应用级事件过滤器。
14. 双击进入编辑不能先发出单击复制反馈；未修改退出不能制造 dirty。

## 7. 验证结果

- 真实 Qt 抓图验证：通过。
- 卡片布局索引：规则 `0`，图片资料 `1`。
- 全局规则卡高度约 `126px`，无说明段落、Token 列表和厘米输入。
- 恢复后样式签名：`314 / 89 / 1652 / md`。
- 相关 UI、资料包、冻结、计划构建、Office 预检、装配事务回归：`305 passed`。
- 本轮列引导、名称交互、路径语义、行级持久化、内容资料和工作台输出目录定向回归：`88 passed`；扩展周边回归 `151 passed / 4 failed`，4 项为工作树既有的过期架构断言（已删除方法/旧模板图标调用），不属于本轮链路。
- 本轮追加的外部点击、单双击消歧、无 Tooltip、未修改 dirty、字段资料值编辑回归：`66 passed`。
- 最终会话边界、正文 viewport 和控件销毁清理定向回归：`18 passed`。
- 名称标准输入框、列几何与输入样式架构回归：`15 passed`，输入基础设施扩展回归：`23 passed`。
- 仓库完整测试共 `2746` 项；本轮全量运行在 10 分钟上限被终止，期间未输出失败，但没有完成汇总，因此不记为“全量通过”。

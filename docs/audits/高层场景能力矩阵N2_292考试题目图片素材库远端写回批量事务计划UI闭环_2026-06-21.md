# 高层场景能力矩阵 N2.292 考试题目图片素材库远端写回批量事务计划 UI 闭环

## 1. 背景

N2.291 已经把远端写回权限失效推进为“可见、可更新授权、可重试”的单项治理链路。继续往后看，剩余问题不能再笼统叫“批量事务”：真正需要先落地的是批量执行前的可审阅计划。用户在同一份考试资料里可能同时有多个题图 metadata 待写回，其中一部分已 ready，一部分需要更新授权，一部分仍处于冲突裁决或交接准备阶段。如果没有批量事务计划 UI，后续做批量执行、失败队列或回滚时会缺少冻结时刻、候选范围、风险分类和审计快照。

本轮只闭合“远端写回批量事务计划 UI 与冻结审计首片”。它不执行批量 POST、不做后台队列、不做指数退避、不做自动回滚，也不把批量执行结果报告伪装为完成。

## 2. 已闭合能力

- 在题图素材库卡片中新增 `question_figure_asset_library_remote_writeback_batch_table`，展示当前资料远端写回批量事务概览。
- 批量事务表按 `事务范围 / 数量 / 风险 / 下一步 / 处理` 五列显示。
- 当当前 profile 至少存在 2 个未终局的远端写回候选时，表格自动显示；候选不足时保持隐藏。
- 候选范围复用单项远端写回表的同一套记录派生逻辑，避免批量视角与单项视角出现口径分叉。
- 已终局状态不进入批量候选，包括“已执行”“已应用远端”“已覆盖远端”“已合并字段”。
- 批量计划把候选状态分为五类：
  - ready：`待执行写回`、`执行失败`；
  - auth：`权限失效`；
  - conflict：`远端冲突`、`冲突已记录`、`待拉取远端`、`远端已取值`、`覆盖失败`、`覆盖仍冲突`、`合并失败`、`合并仍冲突` 等；
  - preparation：`待生成交接`；
  - blocked：`缺端点`、`需复核`。
- 风险列输出稳定摘要：`待执行=N；授权=N；冲突=N；准备=N；阻断=N`。
- 下一步列按优先级提示：先处理阻断项、先更新授权、先完成冲突裁决、先生成交接，或在全 ready 时提示“冻结后逐项执行”。
- “冻结计划”会生成稳定 signature，并写入 `question_figure_library_remote_writeback_batch_transaction_plan` 审计记录。
- 冻结审计记录包含候选数量、ready/auth/conflict/preparation/blocked/completed 计数、状态摘要、候选题号、来源更新时间、计划 signature 和 JSON 化 `transaction_plan_items`。
- `transaction_plan_items` 保存每个候选的记录索引、题号、目标标签、source、asset_id、变更字段、状态分类、writeback endpoint 和 current endpoint。
- 已冻结的相同 signature 不会重复追加计划记录，状态栏明确提示“远端写回批量事务计划已冻结”。
- 冻结后批量表动作从“冻结计划”切换为“定位首项”。
- 选中批量计划行或点击“定位首项”会定位到单项远端写回表中的首个候选，并继续回链到题图行。
- 批量事务表与动作按钮继续复用共享表格样式、动作容器和按钮 variant，保持与模板管理控件风格一致。
- 新增测试锁定“两个远端题图变更 -> 两条 handoff -> 批量计划展示 -> 冻结审计 -> 防重复冻结 -> 定位首项”的完整链路。

## 3. 模型与成熟度变化

- `scene_product_readiness` 在 `pack:exam_education` 与 `family:exam_teaching` 新增 `question asset per-question asset library remote writeback batch transaction plan UI bridge` evidence。
- `pack:exam_education` 的 remaining gap 从 `advanced question asset library remote writeback batch transaction governance UI` 收窄为 `advanced question asset library remote writeback batch execution rollback queue governance UI`。
- `family:exam_teaching` 的 remaining gap 从 `advanced asset library remote writeback batch transaction governance UI` 收窄为 `advanced asset library remote writeback batch execution rollback queue governance UI`。
- `scene_product_maturity_upgrade_audit` 为新 gap 显式归入 `ui_control`、`runtime_execution`、`report_artifact`、`rule_governance`、`boundary_gate`。
- `report_artifact` 被纳入新 gap，是因为后续批量执行必须有事务结果、失败项、回滚证据和可交付报告，而不只是前台按钮。

## 4. 仍不宣称完成

- 批量远端写回真实执行；
- 批量 POST 编排、并发控制或限流；
- 失败队列、指数退避、后台重试；
- 批量执行事务结果报告；
- 批量事务 manifest/artifact；
- 失败项单独重试与已成功项跳过；
- 远端批量回滚或本地补偿回滚；
- 幂等窗口管理、重复提交防护中心；
- OAuth/SSO 登录、token 自动续期、签名 URL 自动续签；
- 组织、角色、题库权限申请或审批；
- 跨资料包素材主数据版本系统。

# 方案处理范围与文档识别最小落地执行方案

> 日期：2026-07-29  
> 状态：已实施，待产品审阅  
> 实施归档：2026-07-30  
> 前提：产品尚未发布，不考虑旧配置兼容  
> 核心约束：闭合真实工作流，同时保证功能数量、页面数量和说明文本净收缩

## 0. 最终落地结论

本轮不建设“文档结构管理平台”，不建设“识别规则中心”，也不把自动识别包装成方案页功能。

只实现以下闭环：

```text
方案页
  用户定义以后要处理哪些内容区域

工作台导入文档后
  系统自动定位这篇文档中的具体区域

识别有歧义时
  用户只校正当前文档

执行时
  方案范围过滤实际区域
  模板提供格式
```

产品表面只增加：

1. 方案页一个“处理范围”控件；
2. 工作台一行“文档范围”状态；
3. 仅在需要时出现的“确认文档范围”弹层。

同时删除当前整块“格式例外”选择、样式编辑、模板跟随、差异比较和恢复操作。

因此 UI 复杂度应当净减少，而不是增加。

## 1. 必须守住的边界

### 1.1 方案页只能表达用户意图

未导入文档时，方案只能知道：

```text
将来遇到哪些区域时需要处理。
```

不能知道：

- 当前文档是否存在摘要；
- 当前文档是否存在参考文献；
- 具体从哪一段开始；
- 具体到哪一段结束；
- 当前识别是否可信。

所以方案页不得出现：

- 已识别；
- 当前分区；
- 当前章节；
- 第几页到第几页；
- 识别置信度；
- 确认识别结果。

### 1.2 自动识别只在导入文档后运行

自动识别是工作台内部能力，不是方案配置项。

它依据：

- 段落文本；
- Word 标题样式；
- 大纲级别；
- 标题编号；
- 文档相对位置；
- 区域顺序；
- 参考文献条目等内容特征。

这些证据只有文档导入后才存在。

### 1.3 用户校正只属于当前文档

用户在工作台做出的：

- 排除错误区域；
- 修改区域起点；
- 补充缺失区域；

默认只绑定当前源文件修订号和当前执行会话。

不得自动写回：

- 方案；
- 模板；
- 全局识别规则；
- 其他文档。

### 1.4 模板只负责格式

摘要、参考文献、附录等区域最终使用的：

- 字体；
- 字号；
- 缩进；
- 行距；
- 段前段后；
- 标题外观；

继续由模板管理。

方案不再保存区域样式副本。

## 2. 首版明确不做什么

为防止功能蔓延，以下内容不进入本轮：

- 不做用户自定义任意语义类型；
- 不做识别规则编辑器；
- 不做“保存为长期识别规则”；
- 不做系统自动学习；
- 不接入 AI 或大模型识别；
- 不做独立“文档结构”导航页；
- 不做模板级区域识别配置；
- 不做拖拽式 Word 页面范围选择器；
- 不做页码范围持久化；
- 不显示数字置信度；
- 不支持一个角色对应多个不连续范围；
- 不支持嵌套语义区域编辑；
- 不把标题树编辑器一起塞进来；
- 不为每一种工作模式复制一套说明文案；
- 不在方案概览、左侧导航、工作台和报告中重复同一段解释。

首版只支持系统已有的封闭区域角色。

## 3. 产品模型压缩为三个对象

不先引入 `DocumentStructureProfile`。

首版只新增或正式化三个对象。

### 3.1 方案范围策略

```python
@dataclass
class DocumentScopePolicy:
    mode: Literal["all", "body", "selected"] = "all"
    selected_roles: tuple[str, ...] = ()
```

语义：

| 模式 | 用户含义 |
| --- | --- |
| `all` | 处理识别出的全部适用区域 |
| `body` | 只处理正文区域 |
| `selected` | 只处理用户勾选的区域类型 |

规则：

- `selected` 必须至少包含一个角色；
- 角色来自当前工作模式支持列表；
- 方案不保存段落下标、页码或当前文档信息；
- 自动识别是否开启不作为用户字段。

### 3.2 当前文档结构证据

```python
@dataclass(frozen=True)
class DocumentStructureEvidence:
    source_path: str
    source_revision: str
    evidence_digest: str
    regions: tuple[DetectedRegion, ...]
    review_items: tuple[StructureReviewItem, ...]
```

单个区域只保留执行必需信息：

```python
@dataclass(frozen=True)
class DetectedRegion:
    role_id: str
    start_anchor: ParagraphAnchor
    end_anchor: ParagraphAnchor | None
    detection_status: Literal["accepted", "review"]
    evidence_codes: tuple[str, ...]
```

不在产品界面展示内部评分。

### 3.3 当前文档校正

```python
@dataclass(frozen=True)
class RegionDecision:
    role_id: str
    action: Literal["accept", "exclude", "set_start"]
    start_anchor: ParagraphAnchor | None = None
```

首版只有三种动作：

- 接受；
- 排除；
- 修改起点。

区域终点默认由下一个已确认区域起点推导。

这样可以避免同时建设复杂的起止范围编辑器。

## 4. 为什么首版只允许修改起点

当前支持的摘要、正文、参考文献、附录、致谢等顶层区域，本质上通常按顺序连续排列。

例如：

```text
正文起点
-> 参考文献起点
-> 附录起点
-> 致谢起点
-> 文档结束
```

当用户修改“参考文献起点”时：

- 正文终点随之确定；
- 参考文献终点由下一个区域起点确定。

因此首版不需要：

- 自由框选任意区间；
- 同时编辑开始和结束；
- 拖拽页面边界；
- 处理重叠范围。

遇到不能表达的不连续或重叠结构，首版应保留原格式并报告，而不是继续增加编辑能力。

## 5. 方案页的最小设计

### 5.1 删除现有“格式例外”

完整删除：

- 分区列表；
- “跟随模板”开关；
- 当前分区选择器；
- 样式编辑器；
- 模板基线摘要；
- 差异摘要；
- 恢复模板；
- 全部跟随模板；
- 撤销恢复。

不保留折叠入口，不改名复用。

### 5.2 “处理范围”只保留一个控件组

建议结构：

```text
处理范围

[ 全部内容 ] [ 仅正文 ] [ 指定区域 ]
```

选择“指定区域”时才展开区域复选项。

论文模式示例：

```text
☑ 摘要
☑ 目录
☑ 正文
☑ 参考文献
☐ 附录
☐ 致谢
```

区域列表按工作模式裁剪。

技术文档、标书和报告不显示：

- 个人简历；
- 致谢；
- 论文声明等论文专属角色。

母版装配型场景继续隐藏该控件，不新增“由母版决定”的说明卡。

### 5.3 方案页不显示“自动识别”

不增加：

```text
识别方式：自动识别
```

理由：

- 当前没有文档可识别；
- 自动扫描是执行基础设施，不是用户必须选择的功能；
- 增加该字段只会让用户误以为方案已经识别当前文档；
- 首版没有第二种可选识别引擎。

## 6. 工作台的最小设计

### 6.1 不新增导航卡

不新增：

- 文档结构；
- 章节管理；
- 识别中心；
- 结构规则；

等左侧导航入口。

结构状态放在现有快速执行页。

### 6.2 文件导入后增加一行状态

在现有文件选择区和方案/模板区之间增加一行：

```text
文档范围    识别中
```

扫描完成且无需处理：

```text
文档范围    已识别 5 个区域    [检查]
```

存在歧义：

```text
文档范围    1 项待确认         [检查]
```

扫描失败：

```text
文档范围    无法确认           [检查]
```

不增加卡片描述、置信度百分比或识别原理说明。

### 6.3 默认不展开明细

只有以下两种情况显示明细：

1. 用户点击“检查”；
2. 执行前仍有待确认项。

高置信度文档不会多出一个必经操作步骤。

### 6.4 “确认文档范围”弹层

弹层只显示：

| 区域 | 起点 | 状态 | 操作 |
| --- | --- | --- | --- |
| 摘要 | 摘要 | 已识别 | 调整 / 排除 |
| 正文 | 第一章 绪论 | 已识别 | 调整 |
| 参考文献 | 参考资料 | 待确认 | 接受 / 调整 / 排除 |
| 附录 | 未识别 | — | 添加 |

点击“调整”或“添加”时，只选择起点。

起点候选来自：

- 已识别标题；
- 短标题段落；
- 当前候选附近段落。

不提供自由文本规则编辑。

### 6.5 弹层按钮

底部只保留：

```text
[取消] [确认范围]
```

没有：

- 保存规则；
- 应用到同类文档；
- 学习本次操作；
- 高级识别设置；
- 重置所有算法参数。

## 7. 可见文案预算

### 7.1 统一术语

产品只使用：

| 位置 | 术语 |
| --- | --- |
| 方案页 | 处理范围 |
| 工作台摘要 | 文档范围 |
| 明细行 | 区域 |
| 用户动作 | 检查、调整、排除、添加、确认范围 |

不再混用：

- 分区；
- 章节例外；
- 格式例外；
- 结构 Profile；
- 语义分类器；
- 区域实例；
- 自动识别策略。

这些内部名词只留在代码和技术文档。

### 7.2 文案长度约束

- 卡片标题不超过 6 个汉字；
- 状态文字不超过 10 个汉字；
- 主操作不超过 4 个汉字；
- 页面不放解释段落；
- 没有问题时不显示帮助文本；
- 错误原因进入弹层明细，不堆在主页面；
- Tooltip 不重复控件标签；
- 左侧导航不重复显示区域数量。

### 7.3 允许出现的全部首版文案

```text

全部内容
仅正文
指定区域

文档范围
识别中
已识别 N 个区域
N 项待确认
无法确认
检查

确认文档范围
已识别
待确认
未识别
接受
调整
排除
添加
取消
确认范围
```

除具体区域名称、起点文本和错误原因外，不再扩展说明性文案。

## 8. 识别状态规则

界面不显示数值分数，只显示三种业务状态。

### 8.1 已识别

满足以下条件：

- 标题证据明确；
- 区域顺序无冲突；
- 与相邻区域不重叠；
- 起点可稳定定位。

用户可以检查，但无需确认才能执行。

### 8.2 待确认

出现以下任一情况：

- 依靠内容回退识别；
- 标题不是精确命中；
- 存在两个候选起点；
- 区域顺序异常；
- 用户方案选择了该区域，但检测证据不稳定。

该区域在用户确认前不得被修改。

### 8.3 未识别

区域未出现时：

- 如果该区域只是方案中的可选范围，不提示；
- 如果相关执行模块要求该区域存在，则在检查弹层显示“未识别”；
- 不在主页面为每个缺失可选区域制造警告。

## 9. 处理范围和自动识别的关系

系统始终扫描完整输入文档。

方案范围只过滤后续修改行为。

```text
完整扫描
-> 得到文档区域
-> 应用当前文档校正
-> 根据方案范围保留可处理区域
-> 模块执行
```

不能根据“仅正文”就只扫描正文，因为系统必须先知道正文在哪里。

### 9.1 三种模块范围

这是工程内部契约，不进入 UI。

| 类型 | 行为 | 示例 |
| --- | --- | --- |
| 结构发现 | 总是读取全文，但不改文档 | heading recognition |
| 区域过滤 | 只修改有效范围内的对象 | 段落、标题、表格、题注、参考文献 |
| 文档级 | 按自身配置作用于文档 | 输出、报告、对象预检 |

每个写入模块必须在测试中声明属于哪一类。

不为此新增用户可见开关。

## 10. 只读分析和执行必须分开

### 10.1 工作台扫描

文件选中后异步执行：

```text
读取源文件
-> 计算源文件修订号
-> 只读生成结构证据
-> 缓存证据
-> 更新“文档范围”一行状态
```

扫描不得：

- 写入源文件；
- 生成正式输出；
- 运行格式化模块；
- 改变方案；
- 改变模板。

### 10.2 复用现有预检证据模式

当前对象预检已经具备：

- 源文件修订号；
- 证据摘要；
- 缓存有效性判断；
- 执行前确认；
- 确认失效；
- 执行会话冻结。

文档结构证据复用同一模式，不新造第二套任务基础设施。

建议抽取通用的：

```text
source_revision
evidence_digest
is_current
confirmation_status
```

但不要强行把对象风险和文档区域合并成一个巨大业务模型。

### 10.3 来源变更必须失效

以下任一变化发生时，清除当前文档范围确认：

- 用户更换文档；
- 源文件内容发生变化；
- 工作模式变化；
- 识别器版本变化。

仅修改：

- 模板；
- 输出目录；
- 交付文件名；

不应重新扫描文档结构。

方案的处理范围变化只需重新计算有效范围，不需要重新识别。

## 11. 稳定锚点而不是页码和段落下标

格式化会改变分页，前置填充或清理也可能改变段落位置。

所以校正结果不能只保存：

```text
第 48 页
第 186 段
```

首版锚点建议包含：

```python
@dataclass(frozen=True)
class ParagraphAnchor:
    text_digest: str
    previous_text_digest: str
    next_text_digest: str
    occurrence: int
```

页码只用于显示，不参与最终定位。

### 11.1 执行时的绑定

执行开始后：

1. 对冻结输入重新验证源文件修订号；
2. 把确认过的锚点解析到实际段落；
3. 解析失败时不扩大范围；
4. 仅阻断受影响区域，或按严格模式阻断整个执行；
5. 不自动退回“全文处理”。

### 11.2 前置模块改变结构时

当前管线中填充、替换和清理可能先于语义模块执行。

因此运行时需要：

- 在任何结构写入前把确认锚点绑定到源段落对象；
- 结构变化后根据仍存在的段落对象重建索引；
- 无法重新定位时 fail closed；
- 不允许写入模块重新猜测边界。

## 12. 统一结构事实源

### 12.1 重用 `DocTree`

不再新增一套与 `DocTree` 平行的运行时章节树。

建议：

- 工作台只读扫描生成可序列化证据；
- 执行时把确认结果投影为有效 `DocTree`；
- Pipeline 模块继续消费 `context.doc_tree`；
- `DocTree` 增加“来源状态”和“用户校正”标记即可。

### 12.2 移除模块私有回退识别

当前参考文献模块在缺少统一范围时仍会自行寻找参考文献。

目标行为：

```text
有有效 references 区域
  -> 执行参考文献格式化

没有有效 references 区域
  -> 跳过并报告
```

不得：

```text
统一识别失败
-> 写入模块再次静默猜测
-> 直接修改文档
```

目录、附录等模块也遵守同一原则。

## 13. 执行会话绑定

`ExecutionSessionSnapshot` 增加最小字段：

```python
structure_confirmation_status: str
structure_source_revision: str
structure_evidence_digest: str
structure_decisions: tuple[RegionDecision, ...]
```

执行前验证：

- 来源修订号一致；
- 证据摘要格式有效；
- 决策引用的角色受当前模式支持；
- 所有待确认项已处理；
- 方案范围至少包含一个有效区域；
- 锚点能在冻结输入中重新解析。

不把完整 UI 状态塞入会话。

### 13.1 高置信度文档

无需用户点击确认，但执行会话仍记录：

```text
structure_confirmation_status = auto_accepted
```

### 13.2 有人工校正

记录：

```text
structure_confirmation_status = user_confirmed
```

不记录“用户训练了系统”等不存在的语义。

## 16. 关键验收用例

### 16.1 未导入文档

- 不显示任何识别结果；

- 执行时按方案范围处理；

- 显示一项待确认；
- 用户接受或调整起点；
- 未确认前参考文献模块不修改该区域；

- 不运行标题文本猜测。

- 同一冻结源文件可复用一次确认；
- 不同源文件若存在待确认项，则跳过对应项并报告；

## 20. 最终实施裁决

本轮的正确方向不是继续丰富“格式例外”，也不是把自动识别搬到方案页。

应当执行：

```text
方案页一个范围选择
        ↓
导入文档后自动扫描
        ↓
工作台一行状态
        ↓
仅有歧义时进行最小校正
        ↓
执行会话冻结确认
        ↓
所有模块使用同一有效范围
```

功能预算：

```text
新增 1 个方案控件组
新增 1 行工作台状态
新增 1 个按需弹层
删除 1 整块格式例外编辑器及其附属能力
```

这保证最终产品不是“功能更多”，而是对象边界更正确、执行范围真正生效、用户解释成本更低。

## 21. 实施归档

### 21.1 已落地裁决

- 方案页只保存 `all / body / selected` 处理意图，不展示识别状态或识别设置。
- 自动扫描只在工作台取得 DOCX 后启动，始终只读扫描全文。
- 工作台只增加一行“文档范围”状态；检查弹层按需出现。
- 用户校正只冻结到当前源文件修订号和执行会话，不回写方案、模板或全局规则。
- “添加区域”在运行时仍归一为设置该区域起点，没有增加第四种范围模型。
- 所有自动语义和格式写入模块共享同一有效 `DocTree`；缺少有效结构时生产执行 fail closed。
- 模板是字体、段落、标题等格式的唯一 owner；方案不再保存区域样式副本。
- `section_styles`、旧 application boundary、格式例外 UI、恢复/比较/跟随模板链已直接删除，没有兼容层。
- 执行回执只保留 `document_scope` 摘要，没有新增独立识别报告。

### 21.2 工程边界

| 边界 | 最终职责 |
| --- | --- |
| 配置 | `DocumentScopePolicy` 和封闭角色集合 |
| 证据 | 源修订号、证据摘要、区域、待确认项 |
| 工作台 | 扫描生命周期、当前文档校正、执行前确认 |
| 运行时 | 锚点绑定、有效区域投影、写入过滤 |
| 模块 | 显式声明结构发现、区域过滤或文档级行为 |
| 报告 | 最小范围回执 |

`WorkbenchPanel` 不再直接持有扫描与弹层细节，方法数由 72 收敛到 60；结构确认校验函数由 112 行拆为 87 行。范围功能没有继续堆入页面主类或执行会话主函数。

生产执行显式开启范围门。独立模块单元调用只有在未进入生产范围门时才允许无结构上下文运行，避免测试夹具伪造文档边界，同时保证正式执行缺证据不扩大到全文。

### 21.3 功能与文案预算

最终用户表面仍是：

```text
1 个方案控件组
1 行工作台状态
1 个按需弹层
```

没有新增导航页、说明卡、自动识别开关、规则编辑器、学习入口或置信度展示。方案页文案只保留“处理范围 / 全部内容 / 仅正文 / 指定区域”和具体区域名；识别状态与校正动作只出现在导入文档后的工作台。

源码白名单审计确认旧“格式例外”等术语不再出现在产品代码中。

### 21.4 文件预算偏差

实施稿原建议“新增文件不超过三个”。最终保留了 7 个范围专用文件：

```text
src/config/document_scope.py
src/config/document_structure_contract.py
src/services/document_structure_evidence.py
src/shared/engine/document_structure_model.py
src/shared/engine/document_scope_runtime.py
src/ui/panels/workbench/document_scope_controller.py
src/ui/panels/workbench/document_scope_review.py
```

这是工程拆分偏差，不是产品功能扩张。配置、证据生成、运行时模型、运行时过滤、工作台生命周期和 Qt 表面不跨层合并，避免形成新的大文件或反向依赖。未增加 registry、插件、独立面板或第二套报告。该偏差保留给产品与工程审阅。

### 21.5 验收结果

最终定向验收：

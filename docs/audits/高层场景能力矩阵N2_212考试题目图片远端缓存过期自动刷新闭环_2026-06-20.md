# 高层场景能力矩阵 N2.212 考试题目图片远端缓存过期自动刷新闭环

## 1. 本轮定位

N2.212 继续执行 V43 的 P0 高级考试素材库路线，在 N2.210 “显式缓存刷新”与 N2.211 “下载内容元数据”之后，补齐自动缓存治理的第一片：

```text
远端 question_figure 已有 cache_path 时，如果 metadata 明确声明缓存已过期，Workbench 会自动进入刷新链路，不再要求用户手动写 force_refresh。
```

本轮不是完整缓存治理系统，仍不实现：
- ETag / Last-Modified 条件请求；
- If-None-Match / If-Modified-Since 的 304 复用；
- 后台失败重试队列；
- 多 profile 共享缓存索引；
- 素材库版本锁定、批量失效、人工审阅。

它的意义是把“缓存已经过期但用户忘记手动刷新”的高频场景，从静默沿用旧缓存推进到可执行、可报告、可降级的自动刷新链路。

## 2. 输入契约

### 2.1 绝对过期时间

`question_figure.metadata` 可携带以下任一字段：

```text
cache_expires_at / cacheExpiresAt
cache_expiry / cacheExpiry
expires_at / expiresAt
```

支持 ISO 时间或 Unix 时间戳：

```json
{
  "cache_path": "C:/cache/question_1.png",
  "download_url": "https://example.com/question_1.png",
  "cache_expires_at": "2000-01-01T00:00:00Z"
}
```

当该时间早于当前 UTC 时间时，刷新原因写为：

```text
cache_refresh_reason = expired_at
```

### 2.2 最大缓存年龄

`question_figure.metadata` 可携带以下任一字段：

```text
cache_max_age_seconds / cacheMaxAgeSeconds
cache_ttl_seconds / cacheTtlSeconds
ttl_seconds / ttlSeconds
max_age_seconds / maxAgeSeconds
```

时间基准优先使用：

```text
cache_downloaded_at / cacheDownloadedAt
downloaded_at / downloadedAt
cache_timestamp / cacheTimestamp
```

如果没有显式下载时间，则使用本地 `cache_path` 文件 mtime。超过最大年龄后，刷新原因写为：

```text
cache_refresh_reason = max_age_expired
```

## 3. 成功链路

```text
cache_path exists
-> cache_expires_at 已过期，或 cache_max_age_seconds 已过期
-> refresh_requested=true
-> 复用 N2.210 的刷新下载链路
-> 成功后写入新 cache_path
-> cache_refresh_status=refreshed
-> cache_refresh_reason=expired_at / max_age_expired
-> Word 使用新缓存渲染
```

成功 metadata 示例：

```json
{
  "cache_path": "<output_dir>/_remote_asset_cache/question_1_<hash>.png",
  "download_url": "https://example.com/question_1.png",
  "cache_expires_at": "2000-01-01T00:00:00Z",
  "cache_refresh_status": "refreshed",
  "cache_refresh_reason": "expired_at",
  "download_status": "downloaded",
  "download_content_type": "image/png",
  "download_size_bytes": "763"
}
```

## 4. 失败降级链路

自动刷新失败时，继续复用 N2.210 的保守降级：

- 不删除旧缓存；
- 不把题图判为缺失；
- Word 继续使用旧 `cache_path` 渲染；
- material diagnostics 生成 `preflight_remote_question_figure_cache_refresh_failed`；
- `remote_asset_items` 透传 `cache_refresh_reason`、`cache_refresh_status`、HTTP 状态和失败原因；
- repair target 继续回到 `question_figure_item`。

失败 metadata 示例：

```json
{
  "cache_path": "C:/cache/question_1_old.png",
  "cache_max_age_seconds": "0",
  "cache_refresh_status": "failed",
  "cache_refresh_reason": "max_age_expired",
  "cache_refresh_failure_type": "http_status",
  "cache_refresh_http_status": "401"
}
```

## 5. 成熟度证据

`scene_product_readiness` 新增 evidence：

```text
question asset remote cache expiry refresh bridge
```

覆盖对象：
- `pack:exam_education`
- `family:exam_teaching`

这使高级考试素材库从“只支持手动 force refresh”，推进到“可按明确过期策略自动刷新，并在失败时保留旧缓存交付”。

## 6. 仍未闭合的边界

N2.212 后，`advanced question asset library UI` / `advanced asset library UI` 的剩余边界收窄为：
- 真实素材库 API：登录、续期、签名 URL、远程查询下载 URL；
- UI 授权入口：401/403/过期/无权限/签名失效后的重新授权、token 刷新、权限申请或账号切换；
- 深层缓存治理：ETag、Last-Modified、条件请求、304 复用、失败重试、共享缓存索引、批量失效；
- 远端预览 UI：下载前缩略图、失败占位、尺寸展示、批量审阅；
- 内容级错图识别：图片内容、OCR、题干语义或图像相似度比对；
- 复杂学科图、几何图、公式图的生成或插件接管；
- AI 出题质量、素材质量、版权或真实性判断；
- 更完整的素材库批量审阅、历史版本、学科/题型标签和复用治理。

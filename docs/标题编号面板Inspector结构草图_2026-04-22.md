# 标题编号面板 Inspector 结构草图（2026-04-22）

## 1. 目标

本稿不是最终视觉稿，而是：

- 把标题编号面板从“字段平铺页”改成“对象属性检查器（Inspector）”
- 在不阉割功能的前提下，显著降低阅读负担
- 给后续代码改造提供一份不会再来回摇摆的结构蓝图

本稿承接：

- `docs/标题编号面板结构重构策略_2026-04-22.md`

---

## 2. 总体结构

### 2.1 面板定位

标题编号面板应被定义为：

**左侧选择对象，右侧编辑当前对象属性**

而不是：

**左侧摘要表 + 右侧大表单**

因此它更像：

- Figma / Sketch 的属性检查器
- IDE 的属性面板
- 专业工具中的 object inspector

不应继续沿用传统“设置页”心智。

### 2.2 顶层布局

```text
标题编号
├─ 顶部概览区
│  ├─ 当前方案
│  ├─ 最大级数
│  └─ 级别预览
└─ 按级编辑
   ├─ 左侧：级别导航
   └─ 右侧：当前级别 Inspector
      ├─ 顶部结果条
      ├─ 编号构造器
      ├─ 输出行为
      ├─ 标题样式摘要
      └─ 专家区
```

### 3.2 右侧结构原则

右侧不是“所有字段总表”，而是 4 层：

1. **结果**
2. **核心规则**
3. **次级行为**
4. **专家项**

顺序绝不能颠倒。

## 4. 左侧导航设计

## 4.1 左侧项只显示什么

左侧项建议只显示：

- `级别名`：例如 `级别 1`
- `编号预览`：例如 `第一章`
- `轻量标记`：例如 `目录` / `停用`

左侧项不建议再显示：

- 完整样式摘要（宋体 / 小四 / 加粗 / 左对齐）
- 多个并列字段
- 过长的描述句

### 推荐单项结构

```text
级别 1
第一章
```

或：

```text
级别 1        目录
第一章
```

### 原因

- 左侧职责是**导航**
- 导航项最怕高密度说明文
- 样式细节属于右侧 Inspector 的职责

---

## 5. 顶部结果条设计

这是本次结构里最重要的部分之一。

### 5.1 必须始终可见的信息

顶部结果条建议固定显示：

- 当前级别：`级别 1`
- 实时编号效果：`第一章`
- 标题效果：`第一章 示例标题 1`
- 目录状态：`包含 / 不包含`
- 引用状态：`1, 2, 3... / 一, 二, 三...`

### 5.2 设计目标

用户进入右侧后，第一眼先看到：

- “我正在编辑谁”
- “它现在长什么样”
- “我改这个会影响什么”

而不是先看到一长列输入框。

### 5.3 不建议做法

- 不要把预览放在最底部
- 不要把结果只放在左侧导航里
- 不要要求用户修改后自己脑补结果

---

## 6. 编号构造器

这是右侧第一主区块，优先级最高。

## 6.1 目标

把以下离散字段合成一个任务单元：

- `enabled`
- `prefix`
- `display_core_style`
- `suffix`
- `chain`
- `chain_separator`

### 现状问题

当前用户实际上是在连续完成一句话：

> 这个级别启用编号，前缀是“第”，样式是中文小写，后缀是“章”，只显示当前级。

但界面把它拆成 5 行平权字段，阅读负担很高。

## 6.2 目标交互

```text
启用编号 [开关]

编号长相
[前缀输入] [编号样式下拉] [后缀输入]
结果：第一章

层级关系
[仅当前级 / 包含上一级 / 包含所有上级]
[分隔符]   ← 仅当 chain 不是 current_only 时出现
```

### 6.3 决策

- `前缀 / 样式 / 后缀` 必须在同一视觉任务单元中
- `层级关系` 作为次级配置单独放在其下
- `分隔符` 只在需要时显示

### 6.4 不建议

- 再拆成 3 行独立表单行
- 把 `前缀`、`样式`、`后缀` 放到不同卡片
- 把 `前缀/后缀` 折进高级设置

---

## 7. 输出行为区

这是第二主区块，负责“文档行为”，不是“编号长相”。

## 7.1 包含内容

- `include_in_toc`
- `start_at`
- `reference_core_style`
- `title_separator`

### 目标交互

```text
输出行为
生成 TOC [开关]   起始编号 [1]
引用显示 [1,2,3 ▼]
标题分隔 [留空表示默认]
```

### 7.2 原因

这组字段共同回答的问题是：

- 这个编号怎么进入文档系统
- 在目录和引用里怎么表现

它们不该继续和“编号长相”混在一起。

### 7.3 排列原则

- `生成 TOC` 与 `起始编号` 放同一行
- `引用显示` 独占一行
- `标题分隔` 独占一行

因为它们的阅读优先级不同。

---

## 8. 标题样式区

这是第三主区块，但默认不应该是一整张参数墙。

## 8.1 目标

把以下字段降级成“摘要优先”：

- 中文字体
- 英文字体
- 字号
- 字形
- 对齐方式
- 行距类型
- 行距值
- 段前
- 段后

### 目标交互

默认显示：

```text
标题样式
宋体 / Times New Roman / 小四 / 加粗 / 左对齐
固定值 20pt / 段前 0 / 段后 0
[调整标题样式]
```

点击后进入细编辑区：

```text
中文字体 [宋体]     英文字体 [Times New Roman]
字号 [小四]         字形 [加粗/斜体]
对齐方式 [左对齐]
行距类型 [固定值]   行距值 [20.0]
段前 [0.0]          段后 [0.0]
```

### 8.2 这不是普通折叠

重点不在“省空间”，而在：

- 先给可判断摘要
- 再进入细节

也就是说这是：

**摘要优先 + 深入编辑**

而不是：

**默认隐藏 + 点击才看**

### 8.3 为什么这样比整块展开更好

- 样式是重要信息，但不是每次都需要逐项编辑
- 默认展开会让界面重心落到排版细节上
- 对多数操作来说，用户只需要知道“当前样式是不是大致正确”

---

## 9. 专家区

专家区只保留真正低频项。

## 9.1 建议内容

- `直接编辑原始模板`
- 原始模板输入框
- 后续扩展的高级链式模板能力

### 目标交互

```text
高级模板编辑
[展开]

展开后：
[ ] 直接编辑原始模板
[第{cn}章____________________]
```

### 9.2 原则

- 专家区入口文案必须明确
- 不允许把高频项混进专家区
- 只保留一个专家入口，避免“高级设置 A / B / C”散落

## 11. 常见任务路径

## 11.1 任务 A：把“1.1”改成“第一节”

路径：

1. 左侧点 `级别 2`
2. 右侧顶部先看到当前效果
3. 在 `编号构造器` 中修改：
   - 前缀：`第`
   - 样式：中文小写
   - 后缀：`节`
4. 顶部实时预览立即更新

用户不需要读到：

- 标题样式区
- 专家模板区

## 11.2 任务 B：只是不想让某一级进目录

路径：

1. 左侧点对应级别
2. 在 `输出行为` 中关闭 `生成 TOC`
3. 顶部结果条同步显示 `目录：不包含`

用户不需要读到：

- 前缀/后缀
- 标题样式

## 11.3 任务 C：调整标题样式

路径：

1. 左侧点对应级别
2. 先看当前样式摘要
3. 点 `调整标题样式`
4. 进入细编辑

这比默认展开一大片字段更轻。

## 11.4 任务 D：手写复杂模板

路径：

1. 进入 `高级模板编辑`
2. 打开 `直接编辑原始模板`
3. 修改模板

这条路径明确是专家路径，不污染基础路径。

## 12. 视觉策略约束

这份文档主要讨论结构，但为了避免实现时再次偏成“只是换皮”，视觉上明确约束如下：

1. 少线条，多留白
   - 大部分分组依靠留白与背景，不依靠虚线

2. 结果重于控件
   - 顶部结果条视觉权重高于表单控件

3. 导航像导航，不像表格
   - 左侧选中项更像导航卡，而不是表格行高亮

4. 摘要比细项更有层次
   - 标题样式摘要必须明显轻于展开后的细项表单

---

## 13. 建议实现顺序

### Step 1：先改信息单元，不改视觉皮肤

目标：

- 左侧降噪
- 顶部结果条前置
- 编号构造器合并
- 输出行为独立
- 标题样式摘要化

### Step 2：再补局部展开能力

目标：

- 标题样式细项后入
- 专家区清晰隔离

### Step 3：最后做视觉统一

目标：

- 选中态
- 分区留白
- 弱边框
- 结果条强化

---

## 14. 测试护栏建议

为防止再次回到“全量字段墙”，建议新增以下 UI 架构测试：

1. 左侧列表项不再包含完整样式长句
2. 顶部结果条位于右侧详情首屏
3. `前缀 / 样式 / 后缀` 在同一组编辑器中
4. `标题样式` 默认显示摘要，不默认平铺全部细项
5. 专家区存在独立入口，且默认关闭

---

## 15. 最终结构结论

标题编号面板下一版不应被理解为：

- 更多卡片
- 更多折叠
- 更漂亮的表单

而应被理解为：

**一个结果驱动的、任务分层的 Inspector**

最核心的改动只有四条：

1. 左侧只导航，不再重复摘要
2. 预览前置，结果先于参数
3. 高频字段合并为复合编辑器
4. 低频与专家字段明确后移

如果这四条没落地，再换多少皮肤都不会真正变轻。

# 场景样式覆盖状态投影与模板基线一致性执行记录

日期：2026-06-28

## 1. 本轮继续推进的问题

上一轮已经把普通执行诊断接入场景字段 Issue，并让用户能从工作台问题跳到场景里的共享 `ParagraphStyleEditor`。但继续审计后发现，场景样式覆盖本身仍有一个可读性和一致性断点：

- 场景页已经拆出“处理范围”和“样式覆盖”。
- 场景页也已经复用模板正文排版同源的 `ParagraphStyleEditor`。
- 但用户仍不容易看出当前分区到底是“跟随模板”、 “已开启覆盖但未改动”，还是“已覆盖了哪些具体样式项”。

这意味着设计仍停在“控件复用”层，还没有完全进入“状态语言复用”层。优秀设计不应只让控件长得一致，还应该让用户在任何入口下都能用同一套概念理解当前状态。

## 2. 发现的关键问题

### 2.1 场景覆盖缺少结构化状态投影

原先 `_ScopeDetail` 的“样式覆盖”摘要只有两类信息：

- 覆盖状态：全部跟随模板 / 已覆盖 N 个分区
- 影响边界：仅当前场景

这能说明总量，但不能说明当前编辑分区的状态。例如用户选中“参考文献”时，页面没有稳定地告诉用户：

- 参考文献是否正在处理范围内。
- 当前是否跟随模板。
- 已开启覆盖时，是否真的与模板不同。
- 如果不同，具体不同项是字体、字号、缩进、行距，还是段距。

因此，用户仍需要靠控件是否禁用、提示文字和自己的猜测来理解状态。

### 2.2 开启场景覆盖时不应丢失模板分区基线

原先 `enable_section_style_override(scene, template, variant_key)` 的注释和实现都偏向“从模板正文复制”。但 `get_effective_section_style()` 的语义是：

```text
scene override -> template variant -> template body -> default
```

如果模板本身已经定义了 `references_body` 这样的分区样式，场景开启参考文献覆盖时，正确基线应该是模板中该分区的有效样式，而不是总是模板正文。

否则用户一打开覆盖，看到的就可能不是模板当前实际效果，而是退回正文默认值。这会破坏“模板管理是基准，场景管理是覆盖”的边界。

## 3. 本轮实现

### 3.1 新增 `SectionStyleOverrideProjection`

文件：`src/config/style_variant_semantics.py`

新增领域层投影：

```python
SectionStyleOverrideProjection
build_section_style_override_projection(scene, template, variant_key)
```

它输出当前分区的用户可读状态：

- `section_enabled`
- `overridden`
- `changed_labels`
- `status_value`
- `status_detail`
- `editor_hint`
- `variant`

状态语言统一为：

```text
未处理
跟随模板
已覆盖 0 项
已覆盖 N 项
```

其中 `changed_labels` 按字段组输出，不直接暴露内部字段名：

```text
中文字体、英文字体、字号、字形、对齐、特殊缩进、左缩进、右缩进、行距、段前、段后
```

这比把 `font_cn`、`line_spacing_pt`、`space_before_unit` 直接显示给用户更符合当前产品语言。

### 3.2 开启覆盖改为复制模板有效基线

文件：`src/config/style_variant_semantics.py`

调整：

```python
enable_section_style_override(scene, template, variant_key)
```

由复制模板正文改为复制：

```python
get_effective_style(template, variant_key)
```

这样模板如果已有分区专用样式，场景覆盖会从该分区的模板有效样式开始，而不是从正文样式开始。

### 3.3 场景页摘要接入当前分区状态

文件：`src/ui/panels/scene_panel.py`

`_ScopeDetail._refresh_style_override_summary()` 新增一项：

```text
当前分区
```

示例：

```text
参考文献 · 跟随模板
参考文献 · 已覆盖 0 项
参考文献 · 已覆盖 11 项
```

详情里显示字段组差异：

```text
不同项：中文字体、英文字体、字号、字形、对齐、特殊缩进、左缩进、右缩进、行距、段前、段后
```

### 3.4 编辑器提示改为投影生成

文件：`src/ui/panels/scene_panel.py`

原先提示由 `_sync_style_editor()` 直接拼字符串。现在优先使用 `SectionStyleOverrideProjection.editor_hint`。

这让摘要和提示来自同一套状态判断，减少 UI 内部重复判断，避免后续改一处漏一处。

## 4. 对一致性和可读性的影响

### 4.1 一致性从“共享编辑器”推进到“共享状态语义”

本轮之前：

```text
模板页和场景页共用 ParagraphStyleEditor
```

本轮之后：

```text
模板有效样式
  -> 场景覆盖基线
  -> 字段组差异投影
  -> 场景摘要 / 编辑器提示
```

也就是说，场景页不只是使用模板控件，而是更明确地承认模板是基准，场景只表达相对模板的覆盖。

### 4.2 用户看到的是动作状态，而不是配置字段

界面主语言变成：

- 跟随模板
- 已覆盖 0 项
- 已覆盖 N 项
- 不同项：中文字体、字号、行距

技术字段仍存在于底层契约和测试中，但不作为用户主文案暴露。这与前几轮“删除冗余文本、减少内部术语”的方向一致。

### 4.3 “恢复默认”的含义更清楚

当状态显示“已覆盖 0 项”时，用户能理解：当前虽然打开了覆盖，但实际值与模板一致。此时关闭覆盖不会改变输出效果，只是恢复跟随模板。

当状态显示“已覆盖 N 项”时，用户能理解：关闭覆盖会放弃这些与模板不同的场景设置。

这为后续增加“一键恢复模板”或“关闭覆盖前确认”提供了明确证据。

## 6. 仍然未完成的部分

### 6.1 还缺显式“恢复模板”动作

当前关闭覆盖等价于恢复跟随模板，但按钮/开关文案仍是“启用独立样式”。后续可以把覆盖行设计为：

```text
跟随模板 / 覆盖
恢复模板
```

这样比单个 toggle 更接近用户语言。

### 6.2 还缺轻量预览投影

本轮只做状态投影，没有渲染视觉预览。下一步可以把：

```text
TemplateConfig + SectionStyleOverrideProjection
```

投影成一个轻量段落预览摘要，用在场景页样式覆盖卡片内。这样用户不仅知道“改了哪些项”，还能看到“改后大概长什么样”。

### 6.3 Issue 队列分组仍待优化

普通诊断和批量诊断都已能进入场景字段跳转，但工作台问题队列还没有完全按用户动作分组。后续应继续从技术 category 转向：

- 先处理
- 建议确认
- 仅查看

## 7. 结论

本轮把场景样式覆盖从“共用控件”推进到“共用模板基线和状态语言”。这比继续增加说明文字更有价值，因为它让界面自然表达：

- 模板是默认样式来源。
- 场景只负责当前场景的覆盖。
- 当前分区是否覆盖、覆盖了哪些项，可以直接读出来。

后续应沿着同一方向继续推进：减少解释性长文，增加结构化状态和可验证投影。

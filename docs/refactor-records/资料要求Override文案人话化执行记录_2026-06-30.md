# 资料要求 Override 文案人话化执行记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经把 `required_material_fields` 和 `required_image_roles` 纳入 `_MaterialRequirementBlock`，结构边界变清楚了。但用户可见文案仍保留配置味：

```text
必填字段
资产角色
每行一个必填字段，例如 party_a
每行一个图片/资产角色，例如 seal
```

这些表达对开发者准确，但对用户不够自然。用户真正要理解的是：

```text
还有哪些资料字段必须填
还需要哪些图片或签章材料
```

因此本轮只收敛可见文案，不改存储字段名、不改执行语义。

## 2. 本轮实现

### 2.1 标签调整

| 原标签 | 新标签 | 理由 |
| --- | --- | --- |
| 必填字段 | 必填资料字段 | 明确这是资料包字段，不是 Word 字段或样式字段 |
| 资产角色 | 必需图片/签章 | 用用户能理解的材料类型替代 role 概念 |

### 2.2 占位说明调整

| 原占位 | 新占位 | 理由 |
| --- | --- | --- |
| 每行一个必填字段，例如 party_a | 留空则按资料规则执行；每行一个资料字段 | 先说明可留空，不把 raw key 当教程 |
| 每行一个图片/资产角色，例如 seal | 留空则按资料规则执行；每行一个图片或签章要求 | 说明这是对资料规则的补充要求 |

这里保留真实字段值的输入能力。用户或高级配置仍可输入：

```text
contract_no
legal_signature
seal
```

但这些不再作为占位示例出现在主界面。

## 3. 边界说明

本轮不改这些内部字段：

```text
required_material_fields
required_image_roles
```

原因：

- 执行前校验依赖它们；
- 诊断跳转依赖它们；
- 历史配置和 scene JSON 依赖它们；
- tooltip 和审计层仍需要保留真实 key。

文案层和存储层的边界保持为：

| 层级 | 表达方式 |
| --- | --- |
| 主控件标签 | 必填资料字段、必需图片/签章 |
| 占位说明 | 留空则按资料规则执行 |
| 输入值 | 可使用真实字段 key / 角色 key |
| tooltip / 审计 | 可展示 raw key 和来源 |

## 4. 代码落点

| 文件 | 变化 |
| --- | --- |
| `src/ui/panels/scene_panel.py` | `_MaterialRequirementBlock.form_rows(...)` 的 override 标签和 TextArea placeholder 改成人话表达 |

## 6. 仍需继续

文案已经进一步靠近用户语言，但下一步还有两个更深的点：

### 6.1 区分“资料规则内置要求”和“额外补充要求”

现在“必填资料字段 / 必需图片/签章”本质是 override。后续可以考虑在界面上更明确：

```text
额外必填资料字段
额外图片/签章要求
```

但这会增加标签长度，需要看界面宽度和用户理解成本。

### 6.2 预览里标明 override 来源

当前预览 tooltip 会出现 `profile override`。下一步可以把 tooltip 里的英文来源也人话化：

```text
来自本场景补充要求
```

这样主界面、tooltip 和诊断层会更一致。

## 7. 本轮结论

这轮不是大功能，但它继续收紧“场景规划不说人话”的根因：主控件不应该把内部 key 和 role 当教程。现在资料要求 block 的主入口更像用户在配置资料要求，而不是在编辑 schema override。

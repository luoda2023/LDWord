# 输出目标模板下拉显示名与 ID 分层执行记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经把资料规则下拉从：

```text
合同方字段资料 (contract_parties_v1)
```

改成主路径只显示业务名称。继续审计输出设置后，发现“模板选项”下拉也存在同类问题：它通过 `_template_label_with_id(...)` 把模板 ID 拼进可见文本。

目标模板对用户来说是“交付版本使用哪个业务模板”，不是让用户先理解 `template_id`。因此本轮把目标模板下拉也改成：

```text
主路径显示模板名称
data / tooltip 保留 template_id
```

## 2. 本轮实现

新增两个 helper：

```text
_template_display_label(template_id)
_template_option_tooltip(template_id)
```

下拉可见项现在使用：

```text
_template_display_label(template_id)
```

tooltip 保留：

```text
模板名称
模板 ID
```

`itemData` 仍然是真实 `template_id`，所以选择和写回链路不变。

## 3. 具体变化

| 场景 | 原可见表达 | 新可见表达 | ID 去向 |
| --- | --- | --- | --- |
| 跟随当前模板 | 跟随当前模板 - 模板名 (template_id) | 跟随当前模板 - 模板名 | tooltip |
| 兼容模板 | 模板名 (template_id) | 模板名 | tooltip / data |
| 非兼容但存在模板 | 自定义: template_id | 自定义模板 - 模板名 | tooltip / data |
| 不存在模板 | 自定义: missing_template_id | 自定义模板 | tooltip / data |

## 4. 边界规则

本轮不改变这些内部行为：

- `target_template_id` 仍写入真实模板 ID；
- 校验摘要仍可显示缺失模板 ID；
- `findData("thesis_custom")` 仍可定位下拉项；
- 手动输入框仍可输入模板 ID。

分层原则：

| 层级 | 表达 |
| --- | --- |
| 下拉可见项 | 模板业务名称 |
| item data | `template_id` |
| tooltip | 模板名称 + 模板 ID |
| 文本输入框 | 真实 `target_template_id` |
| 校验摘要 | 可显示真实 ID，尤其是缺失/非兼容时 |

## 5. 代码落点

| `tests/test_scene_panel_architecture.py` | 守住 `thesis_custom` / `default` 不进入目标模板下拉可见文本，但仍出现在 tooltip |

## 7. 仍需继续

输出设置里还有更高级的入口可以继续审：

- 交付 ID 输入框仍有 `review_copy` 示例；
- 输出目录 / 文件命名仍直接暴露 `{preset_id}`、`{stem}`；
- 变量插入下拉显示 `{preset_id}` 这类变量。

这些属于高级命名与报告区域，不一定要完全隐藏内部变量，但仍可以继续做“主路径解释人话，变量 key 留在 tooltip / 插入结果”的分层。

## 8. 本轮结论

目标模板下拉现在和资料规则下拉采用同一套设计原则：用户选择时看到业务名称，系统仍能通过 data / tooltip 保留真实 ID。这样输出设置继续向模板管理的“对象名优先、ID 证据化”靠近。

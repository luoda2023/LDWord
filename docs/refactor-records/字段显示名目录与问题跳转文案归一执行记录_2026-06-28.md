# 字段显示名目录与问题跳转文案归一执行记录（2026-06-28）

## 1. 为什么做这一轮

上一轮已经把 `schema` 路由从资料面板收敛到场景输入契约，但界面仍有一个明显问题：很多入口仍把内部字段路径直接展示给用户。

典型例子：

- `scene.section_styles.references_body.font_cn`
- `scene.section_styles.*.line_spacing_pt`
- `template.page_setup.margin.left_cm`
- `input_source_profile.material_schema_id`
- `body.special_indent`

这些 key 对开发和审计有价值，但不应该出现在主交互文案中。用户需要看到的是“参考文献正文中文字体”“所有处理分区行距”“左页边距”“主资料 Schema”“正文特殊缩进”。

## 2. 本轮边界

本轮没有改运行时规则，也没有改真实 repair target。目标是：

- 展示文本使用人能理解的字段名。
- 点击修复仍保留原始字段路径作为 action value。
- 场景、模板、资料三个面板的“从执行问题进入”返回条使用同一套 fallback。
- 工作台证据行不再把“参数路径”作为主要可见文本。

## 3. 已落地实现

新增纯投影适配器：

- `src/ui/adapters/field_display_names.py`

核心函数：

- `field_display_name(value, target_type="")`
- `navigation_issue_hint(issue_title, issue_key, issue_type="")`

覆盖的字段族：

- 模板正文样式：字体、字号、对齐、缩进、行距、段前段后。
- 场景分区样式：参考文献、摘要、附录、致谢、个人简历等分区覆盖。
- 场景处理范围：`format_scope.sections.*`。
- 模板页面设置：纸张、方向、页边距、页眉页脚距离。
- 场景输入契约：资料 Schema、必填字段、图片角色。
- 常见资料字段：公司名称、项目名称、统一社会信用代码、公章等。

接入位置：

- `src/ui/panels/workbench/panel_v2.py`
  - 导航 payload 增加 `issue_display_name`。
- `src/ui/panels/scene_panel.py`
  - 返回条优先显示 `issue_display_name`，否则用共享目录转译字段。
- `src/ui/panels/template_panel.py`
  - 同步使用共享目录。
- `src/ui/panels/assets_panel.py`
  - 同步使用共享目录。
- `src/ui/adapters/workbench_execution_adapter.py`
  - 证据行 `参数` 显示可读字段名，但 `action_value` 继续保留原始路径。
- `src/ui/panels/workbench/quick_execution_detail.py`
  - action 文案复用字段显示名；`schema` 动作文案改为“去场景页确认资料 Schema”。

## 4. 行为变化

已改变：

- 场景返回条从 `从执行问题进入：scene.section_styles.references_body.font_cn` 变为 `从执行问题进入：参考文献正文中文字体`。
- Schema 问题返回条从裸 `signature_assets_v2` 变为 `资料 Schema：signature_assets_v2`。
- 工作台证据行从 `参数：body.special_indent` 变为 `参数：正文特殊缩进`。
- 工作台证据行从 `参数：scene.section_styles.references_body.font_cn` 变为 `参数：参考文献正文中文字体`。

保持不变：

- `repair_target_key` 不变。
- `field_id` 不变。
- `current_issue_evidence_actions()` 返回的 action value 不变。
- 导航高亮仍使用原始字段路径。
- 测试里用于证明诊断源头的 raw details 仍可保留，避免丢失审计能力。

## 5. 设计原则

这轮确立一个规则：

> UI 可见文案不直接展示内部路径；定位、审计、报告可以保留内部路径。

更具体地说：

- 主界面、返回条、证据行正文使用显示名。
- tooltip、action payload、测试断言、审计报告可以保留 raw key。
- 如果有 issue title，优先使用 issue title。
- 如果没有 issue title，才使用 `field_display_name()` fallback。
- Schema ID 本身是用户需要确认的对象时，使用 `资料 Schema：xxx`，不是把它伪装成普通字段。

## 6. 后续缺口

仍未完全完成：

1. 问题队列标题和 tooltip 中仍有少量 raw key，用于审计源头说明；后续应区分“可见问题标题”和“调试/审计详情”。
2. `field_display_name` 目前覆盖高频字段，后续应继续吸收表格、题注、目录、页眉页脚、输出 preset 字段。
3. NavigationHighlighter 的 tooltip 仍显示原始 field id，后续可以改为“显示名 + 原始路径”的形式。
4. 场景概览状态卡仍有内部成熟度/计数表达，需按上一份规划继续重排成六个结果导向板块。

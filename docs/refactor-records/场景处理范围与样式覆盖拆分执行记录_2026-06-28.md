本轮目标：在共享 `ParagraphStyleEditor` 已经接入模板 owner 和场景 owner 后，继续推进信息架构边界，把场景页中混在一起的“处理范围”和“样式覆盖”拆成更清楚的板块。

## 1. 本轮已执行

### 1.1 同一详情页内拆成两张卡

修改：

- `src/ui/panels/scene_panel.py`

`_ScopeDetail` 原来只有一张 `处理范围` 卡，里面同时包含：

- 处理哪些文档区域；
- 哪些分区开启独立样式；
- 编辑分区样式。

本轮改为同一详情页内两张卡：

```text
_ScopeDetail
  -> 处理范围
    -> 区域复选框
    -> 处理范围摘要

  -> 样式覆盖
    -> 覆盖状态摘要
    -> 覆盖分区开关
    -> 编辑分区
    -> ParagraphStyleEditor
```

这一步没有新增左侧导航入口，仍然保留原来的 `scn_scope` 路由。选择这种方式是为了先明确用户边界，同时避免一次性牵动 `FIXED_CARDS`、导航意图和动态卡片映射。

### 1.2 精简和重写可见说明

`处理范围` 现在只说：

```text
选择本场景要处理的文档区域。
```

不再把样式覆盖混在处理范围说明里。

`样式覆盖` 新卡只保留短说明：

```text
默认跟随模板；只有需要让某个分区不同于模板时开启覆盖。
```

旧的重复标题 `分区样式编辑` 已移除，改为更短的 `编辑样式`。

### 1.3 增加样式覆盖动态摘要

新增 `_refresh_style_override_summary()`。

无覆盖时显示：

```text
覆盖状态：全部跟随模板
影响边界：仅当前场景
```

开启覆盖后显示：

```text
覆盖状态：已覆盖 N 个分区
detail：参考文献、致谢、摘要...
```

这个摘要让用户不必阅读长说明，也能立刻知道当前是“跟随模板”还是“场景覆盖”。

### 1.4 保留现有数据链路

这轮只拆 UI 板块，不改数据结构。

仍然使用：

- `scene.format_scope.sections` 保存处理范围；
- `scene.section_styles[variant_key]` 保存场景样式覆盖；
- `ParagraphStyleEditor` 编辑段落样式；
- `scope_changed` 通知场景被编辑。

因此这轮是产品边界和布局拆分，不是数据模型迁移。

### 1.5 更新测试

修改：

- `tests/test_scene_panel_architecture.py`

新增约束：

- `scene_panel.py` 必须存在 `.set_header("样式覆盖", icon_name="type-outline")`；
- 旧标题 `分区样式编辑` 不应再出现；
- `编辑样式` 应存在；
- 未开启覆盖时，样式覆盖摘要显示 `全部跟随模板`；
- 开启参考文献覆盖后，摘要显示 `已覆盖 1 个分区`，并包含 `参考文献`；
- 关闭覆盖后，摘要恢复 `全部跟随模板`。

## 3. 当前达成状态

已达成：

- `处理范围` 和 `样式覆盖` 在视觉和信息架构上分离；
- `处理范围` 不再解释样式覆盖；
- `样式覆盖` 明确表达默认跟随模板、只影响当前场景；
- 样式覆盖状态有动态摘要；
- 场景 owner 仍复用 `ParagraphStyleEditor`；
- 旧路由 `scn_scope` 仍可用。

这一步把上一轮记录中的“场景信息架构还没拆分”推进到同页双卡拆分。

## 4. 仍未完成

### 4.1 还不是导航级拆分

当前仍是一个左侧入口：

```text
处理范围
```

只是详情页内部拆成两张卡。后续如果用户测试表明样式覆盖仍然难找，可以进一步升级为左侧两个入口：

- 处理范围；
- 样式覆盖。

但那会牵动固定卡片、导航分组、路由意图和更多测试，适合单独一轮做。

### 4.2 处理范围本身仍不完整

当前处理范围仍主要是分区复选框，还没有产品化：

- 页码范围；
- 正文起点页；
- 正文起始关键词；
- Word story 范围；
- 只读/只报告区域。

这些是处理范围能力本身的后续缺口，不属于本轮样式覆盖拆分。

### 4.3 场景详情页骨架还没整体归一

本轮只处理 `_ScopeDetail`。其他场景详情页仍有大量 `_SimpleFormDetail + Card + SummaryGrid + template_form_row`，尚未统一到更像模板管理的 detail shell。

### 4.4 release gate 集成项仍未复验

此前记录的完整 release gate 集成项长时间无输出问题仍未在本轮处理。本轮只跑了聚焦 UI 和组件验证。

## 5. 下一步建议

1. 继续把场景页其他详情页迁移到共享 detail shell，而不是只靠 `_SimpleFormDetail`。
2. 为处理范围补“页码范围 / 正文起点 / Word story”这类真正的范围能力。
3. 判断是否需要把“样式覆盖”升级为左侧独立导航入口。
4. 单独排查 release gate 集成项耗时或卡住原因。

## 6. 本轮判断

当前已经从“控件复用”推进到了“用户边界更清晰”：

- 处理范围回答“这次改哪里”；
- 样式覆盖回答“哪些区域不跟随模板默认样式”；
- 段落样式编辑仍由共享 `ParagraphStyleEditor` 负责。

这比上一轮只共享控件更进一步，但还不是场景页整体信息架构的最终形态。下一步应继续推进场景详情页骨架归一，或补齐处理范围本身缺失的定位能力。

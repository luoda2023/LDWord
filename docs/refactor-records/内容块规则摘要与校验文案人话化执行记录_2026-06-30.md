# 内容块规则摘要与校验文案人话化执行记录 2026-06-30

## 本轮结论

前几轮已经完成：

- 内容块 selector 在主路径显示为业务名。
- `ContentVisibilityRule.label` 写入业务名。
- `selector` 继续作为执行层稳定 key。

但场景输出设置里的“规则校验”摘要仍然保留工程词：

- 成功时显示 `marker block 规则可解析`。
- 失败时显示 `缺少 selector`、`重复 selector: answer`。

这会让用户在最需要判断“规则有没有配对”的位置重新遇到内部概念。本轮将该摘要和错误提示改成业务可读表达。

## 改动内容

### 规则摘要

原来：

```text
marker block 规则可解析
```

现在：

```text
答案：删除块；解析：隐藏块
```

规则原文仍保留在 tooltip：

```text
answer=remove · 答案：删除块
analysis=hide · 解析：隐藏块
```

### 校验错误

原来：

```text
第 2 行缺少 selector
第 3 行重复 selector: answer
第 1 行未知动作: drop
```

现在：

```text
第 2 行缺少内容块名
第 3 行重复内容块: 答案 (answer)
第 1 行未知处理动作: drop
```

### 摘要卡命名

摘要项 label 从“规则校验”改为“内容块规则”，让它和高级区里的“添加内容块 / 内容块规则”保持一致。

## 边界保持

本轮没有改变：

- 文本规则格式：仍是 `answer=remove`。
- `ContentVisibilityRule.selector`。
- `ContentVisibilityRule.action`。
- pipeline 执行逻辑。
- 重复规则去重逻辑。

只改变摘要和校验文案。

# 场景样式控件共享编辑器执行记录

日期：2026-06-28

后续进展：本文第 4.1 节记录的“模板正文排版页尚未接入共享 editor”已在 `docs/refactor-records/模板正文排版接入共享编辑器执行记录_2026-06-28.md` 中继续推进。当前模板 owner 和场景 owner 已共同使用 `ParagraphStyleEditor`。

关联分析文档：

- `docs/audits/场景样式控件与模板管理高度复用深度分析_2026-06-28.md`

本轮目标：不再停留在“场景页使用了同款底层控件”的表层一致性，而是先落地一个可验证的复用切口：把场景分区样式覆盖中的字体、字号、字形、对齐、缩进、行距、段距编辑能力收敛到共享编辑器。

## 1. 本轮已执行

### 1.1 新增共享样式编辑器

新增：

- `src/shared/ui/paragraph_style_editor.py`

`ParagraphStyleEditor` 负责：

- 创建 `FontCombo`、`SizeCombo`、`ToggleSwitch`、`SpecialIndentInput`、`IndentInput`、`SpacingInput`、`StyledComboBox`；
- 使用 `template_form_row`、`template_form_pair_row`、`TemplateFormStack` 组织段落样式字段；
- 从 `StyleConfig` 同步 UI；
- 将 UI 状态写回 `StyleConfig`；
- 维护行距类型和行距值的禁用态；
- 维护段前/段后 `auto` 单位的禁用态；
- 维护字号变化后的缩进 reference size；
- 提供 `set_editable()` 和 `focus_field()` 基础接口。

它不直接知道 `TemplateConfig` 或 `SceneWorkspace`，因此可以作为模板 owner 和场景 owner 之间的共享控件层。

### 1.2 场景分区样式覆盖接入共享 editor

修改：

- `src/ui/panels/scene_panel.py`

`_ScopeDetail` 现在不再直接实例化：

- `FontCombo`
- `SizeCombo`
- `SpecialIndentInput`
- `IndentInput`
- `SpacingInput`
- `build_emphasis_widget`
- `LINE_SPACING_OPTIONS`

场景页只挂载：

- `ParagraphStyleEditor`

并保留场景 owner 逻辑：

- 当前编辑哪个分区；
- 分区是否启用；
- 分区是否开启独立样式；
- 从模板读取有效样式作为展示值；
- 将编辑结果写回 `SceneWorkspace.section_styles[variant_key]`；
- 发出 `scope_changed`。

这一步把“样式控件怎么长、怎么同步、怎么禁用”从场景页移走，让场景页更专注于“这个样式覆盖属于哪一个场景分区”。

### 1.3 更新共享 UI 导出

修改：

- `src/shared/ui/__init__.py`

新增 `ParagraphStyleEditor` 懒加载导出，保持共享 UI 组件的统一入口。

### 1.4 更新运行时一致性审计证据

修改：

- `src/config/scene_control_runtime_consistency_audit.py`

旧证据指向 `scene_panel.py` 里的直接控件构造，例如 `_section_font_cn = FontCombo`、`_section_line_value = SpacingInput`。

新证据指向 `src/shared/ui/paragraph_style_editor.py`，表达新的事实：

- 控件构造在共享 editor；
- 场景页通过 `ScenePanel._section_style_editor` 挂载；
- 样式字段回写在 `ParagraphStyleEditor.apply_to_style()`；
- 运行时审计继续能追踪字体、字号、缩进、特殊缩进、行距、段距。

### 1.5 更新测试口径

修改：

- `tests/test_scene_panel_architecture.py`

旧测试把“`scene_panel.py` 里出现 `FontCombo/SpacingInput/IndentInput`”当作一致性证据。这个口径已经和新目标冲突。

新测试改为：

- `scene_panel.py` 必须使用 `ParagraphStyleEditor`；
- `scene_panel.py` 不应直接构造段落样式控件；
- `paragraph_style_editor.py` 必须包含这些共享控件和成对表单布局；
- 场景样式覆盖仍能写回 `SceneWorkspace.section_styles`。

新增：

- `tests/test_paragraph_style_editor.py`

覆盖：

- `StyleConfig` 到 editor 控件同步；
- editor 控件修改后写回新的 `StyleConfig`；
- 行距预设锁定行距值；
- `set_editable(False)` 禁用关键控件。

## 2. 当前架构变化

本轮后，场景样式覆盖链路变为：

```text
ScenePanel._scope
  -> _ScopeDetail
    -> ParagraphStyleEditor
      -> FontCombo / SizeCombo / IndentInput / SpacingInput ...
    -> apply_to_style(scene.section_styles[variant])
```

旧链路是：

```text
ScenePanel._scope
  -> _ScopeDetail
    -> 直接创建 FontCombo / SizeCombo / IndentInput / SpacingInput ...
    -> 手写同步和回写逻辑
```

这不是最终态，但已经把最明显的复制点切掉了。

## 4. 未完成与风险

### 4.1 模板正文排版页尚未接入共享 editor

本轮先让场景页脱离复制实现，但 `TemplateStyleDetail` 仍保留原来的控件创建和同步逻辑。

这意味着当前状态是：

- 场景页已经使用 `ParagraphStyleEditor`；
- 模板页还未使用 `ParagraphStyleEditor`；
- 真正的“一个 editor，两个 owner”尚未完全完成。

下一步应把 `TemplateStyleDetail` 改成 owner shell：

- 摘要卡、保存、恢复、snapshot 留在模板页；
- 段落样式控件和读写逻辑委托给 `ParagraphStyleEditor`；
- `focus_navigation_field()` 委托给 editor 或共享 field map。

### 4.2 场景“处理范围”和“样式覆盖”仍未拆板块

本轮只抽控件层，没有调整信息架构。

`_ScopeDetail` 仍同时承担：

- 处理范围；
- 分区样式开关；
- 分区样式编辑。

下一步仍应拆出 `StyleOverrideDetail`，避免用户把“处理哪里”和“覆盖模板样式”混为一件事。

### 4.3 release gate 集成项未完成

执行完整：

```text
python -m pytest tests/test_scene_control_runtime_consistency_audit.py -q
```

前三项已输出通过，但最后的 release gate 集成项长时间无输出。为避免本轮验证被长耗时任务阻塞，已停止该 pytest 进程，并单独跑通过前三个审计项。

后续需要单独排查：

- `test_release_gate_includes_scene_control_runtime_consistency_audit`
- `scripts.verify_scene_matrix_release_gate.build_scene_matrix_release_gate_payload`

当前不能声明 release gate 集成项已验证通过。

## 5. 下一步建议

1. 让 `TemplateStyleDetail` 接入 `ParagraphStyleEditor`，完成“一个 editor，两个 owner”。
2. 把 `_ScopeDetail` 拆成 `ScopeDetail` 和 `StyleOverrideDetail`。
3. 将 `control_contract_registry.py` 的 `scene_surface` 文案从“must reuse FontCombo/SpacingInput”升级为“must use ParagraphStyleEditor owner shell”，让字段契约也表达组件层复用。
4. 增加源码守门：模板页和场景页都不应再各自复制整套段落样式 editor。
5. 单独处理 release gate 集成项耗时或卡住的问题。

## 6. 本轮判断

这轮已经从分析进入了执行层：场景页最明显的样式控件复制被切掉，审计证据和测试也改成支持共享 editor 的新事实。

但距离最终优秀设计还有两步：

- 模板页也要接入同一个 editor；
- 场景页的信息架构还要把“范围”和“覆盖”拆清楚。

当前进度可以视为 P1 的第一半：共享 editor 已建立，场景 owner 已接入，模板 owner 尚未接入。

# 场景概览首屏文案瘦身与人话状态执行记录

日期：2026-06-30

## 1. 本轮目标

前几轮已经把模板、场景、执行诊断之间的样式路径语义收口到共享 helper。底层链路更稳之后，本轮回到用户可见层，处理场景概览第一屏仍然偏“工程说明”的问题。

目标不是删除证据，而是重新分层：

```text
第一屏：任务、当前状态、下一步动作
高级证据：样本、契约、字段、schema、内部 key、诊断依据
```

## 2. 修改前的问题

实际打印多个场景的第一屏文本后，发现虽然禁词测试已经覆盖 `custom_basic`、`quick_formatting` 等明显内部 key，但仍有几类体验问题：

| 问题 | 用户感受 |
| --- | --- |
| 风险摘要重复 `发现风险先提醒；发现风险先提醒` | 像机器拼接 |
| 风险步骤列出一串 Word 对象 | 主流程太重，不像概览 |
| `宏 会阻断`、`宏 会停止执行` 中间有生硬空格 | 不像自然中文 |
| 输出版本显示 `最终 Word；共 1 个输出版本：最终 Word` | 重复 |
| `schema`、`preset`、`manual_review`、`content_controls` 等词仍可能通过模板动作或诊断摘要漏出 | 不说人话 |
| ` / ` 作为主文案分隔符 | 像内部清单，不像中文界面 |

## 3. 本轮实现

### 3.1 风险摘要压缩

新增首屏风险摘要压缩：

```text
发现风险先提醒；检查 嵌入对象、嵌入表格、嵌入附件、Visio 图；高风险模块会先跳过；宏 会阻断
```

压缩为：

```text
发现风险先提醒；高风险对象先跳过；宏会阻断
```

严格保护场景同理：

```text
严格保护；高风险对象先跳过；宏会阻断
```

### 3.2 输出版本摘要压缩

单版本输出不再重复：

```text
最终 Word
```

多版本输出只保留默认版本和数量：

```text
审阅稿；共 4 个版本
```

不在第一屏列出每个版本名称，具体版本仍在输出设置详情中查看。

### 3.3 首屏清洗词扩展

第一屏新增清洗和禁词守门：

| 内部词 | 第一屏表达 |
| --- | --- |
| `schema` / `Schema` | 资料规则 |
| `preset` | 输出版本 |
| `manual_review` | 人工确认 |
| `content_controls` | 内容控件 |
| `tracked_changes` | 修订 |
| `hidden_text` | 隐藏文字 |
| `embedded_packages` | 嵌入附件 |
| `docx` | Word 文档 |
| `xlsx` | Excel 表格 |
| ` / ` | `、` |
| `_` | 空格 |

同一批清洗词也补到了 `style_source_projection.py`，避免模板预览动作从样式来源行把内部词带回第一屏。

### 3.4 通用边界说明去重

通用格式清理场景原来会出现：

```text
清理格式时会保留域和批注，不会静默改写高风险对象、清理格式时会保留域和批注；遇到高风险对象先提醒
```

现在压缩为：

```text
会保留域和批注；遇到高风险对象先提醒
```

## 4. 代码落点

| 文件 | 变更 |
| --- | --- |
| `src/ui/panels/scene_overview_projection.py` | 首屏风险摘要、输出摘要、边界说明、人话清洗词 |
| `src/ui/panels/style_source_projection.py` | 样式来源行同步清洗内部词；4 个及以上模板核对项压成数量 |

## 5. 当前效果示例

### 通用格式清理

```text
检查风险：发现风险先提醒；高风险对象先跳过；宏会阻断
风险与确认：发现风险先提醒；高风险对象先跳过；宏会阻断；请确认：会保留域和批注；遇到高风险对象先提醒
输出版本：最终 Word
```

### 合同交付

```text
检查风险：严格保护；高风险对象先跳过；宏会阻断
输入与资料：Word 文档、结构化数据，资料包必需
输出版本：审阅稿；共 4 个版本
```

## 6. 仍需继续优化

### P0：概览高级证据仍要继续降噪

本轮处理的是第一屏。高级证据区域仍然有一些必要的内部 key 出现在 tooltip 或证据详情中，例如样本 id、schema id、报告 id。下一步应该按“默认隐藏，展开后仍尽量有中文标签”的方向继续整理。

### P0：导航卡副标题仍有内部词

`ScenePanel._content_navigation_snapshot(...)` 仍会显示：

```text
字段 / schema
```

这些不是第一屏主文案，但会出现在左侧导航卡。后续应继续把它改为：

```text
资料字段 N 个，资料规则 N 项
```

### P1：风险确认行应进一步拆成两个槽位

当前 `风险与确认` 仍把对象预检和人工边界合在一行。长期更清晰的结构是：

```text
风险处理：发现风险先提醒；宏会阻断
人工确认：会保留域和批注；遇到高风险对象先提醒
```

但这涉及第一屏板块重排，本轮先做文本瘦身。

## 7. 本轮结论

场景概览第一屏现在更接近用户能直接理解的状态页：

- 不再重复风险状态。
- 不再把扫描对象清单塞进主流程。
- 不再用英文内部 key、下划线、斜杠作为主文案。
- 输出版本只说默认交付和版本数量。
- 风险和边界说明更像自然中文。

这一步让“场景规划”和“模板管理”的表达进一步靠拢：用户先看到当前会怎么处理、哪里需要确认、用哪个模板和输出版本；证据和内部依据继续下沉。

# 资料规则首要概览可读性执行记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经把资料规则预览归属到 `_MaterialRuleSelectorBlock`，但用户看到的仍是六个并列格子：

```text
资料规则校验
资料规则
适用场景族
字段预览
图片/签章
附件清单
```

这些信息都正确，但第一眼仍要用户自己拼结论：到底识别了几个规则、缺不缺、会要求哪些资料。模板管理更成熟的地方在于它通常先给“当前状态”，再给明细。因此本轮补一个首要概览项。

## 2. 本轮实现

在 `_build_material_schema_validation_items(scene)` 返回项最前面新增：

```text
schema_rule_overview
```

显示方式：

```text
规则概览
已识别 2 个资料规则
字段：5 个必填项；图片/签章：2 必填 / 3 全部；附件：无
```

当存在未登记规则时：

```text
规则概览
已识别 1 个，未识别 1 个
字段：5 个必填项；图片/签章：2 必填 / 3 全部；附件：无
```

当未配置规则时：

```text
规则概览
未配置资料规则
选择资料规则后可预览字段、图片和附件要求
```

这个项设置为 `column_span=3`，在 SummaryGrid 里横跨整行，形成类似模板管理“当前状态”的阅读入口。

## 3. 文案边界

本轮继续遵守前面定下的主界面与证据层边界：

| 层级 | 表达 |
| --- | --- |
| 主值 | 已识别 / 未识别 / 未配置 |
| 明细 | 字段、图片/签章、附件数量 |
| tooltip | 真实规则 ID、字段 key、英文 label、来源证据 |

新增概览的 detail 明确不放：

```text
contract_parties_v1
signature_assets_v1
contract_no
profile override
```

这些仍保留在 tooltip，用于高级排查和诊断定位。

## 4. 同步调整

资料规则校验状态从：

```text
未知 1 个
```

改为：

```text
未识别 1 个
```

原因是按钮和修复动作已经使用“替换未识别 / 移除未识别”。如果摘要仍写“未知”，同一对象语言就不一致。

tooltip 中的“未注册资料规则”也收敛为“未登记资料规则”，避免把系统 registry 的实现词直接露在主阅读路径里。

## 7. 仍需继续

这轮解决的是“第一眼能不能看懂资料规则预览”。下一步还有两个方向：

### 7.1 明细格子继续瘦身

有了首要概览后，下面的“资料规则 / 适用场景族 / 字段预览 / 图片签章 / 附件清单”可以进一步区分主次。尤其是“适用场景族”可能更像证据，不一定需要和字段、资产同等权重。

### 7.2 把资料要求 override 也对象化

必填字段和资产角色目前仍在 `_ContentDetail` 里，它们会影响资料规则预览。后续可以考虑抽出更大的：

```text
MaterialRequirementBlock
```

它包含：

- 资料规则选择；
- 必填字段 override；
- 资产角色 override；
- 当前资料要求预览。

但这需要先确认交互边界，否则容易把 block 做得过大。

## 8. 本轮结论

现在资料规则 block 已经不只是“能编辑”，也开始“能解释”。这一步让输入资料详情更接近模板管理的体验模型：

```text
先给当前状态
再给具体参数
最后把证据藏进 tooltip / 高级区域
```

这比继续堆说明文字更合适，也能减少用户在场景规划页读到内部配置语言的概率。

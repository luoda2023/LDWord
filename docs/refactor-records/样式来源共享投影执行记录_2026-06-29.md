# 样式来源共享投影执行记录（2026-06-29）

后续进展：共享投影已继续推进到 `StyleSourceCompactRow` 共享 UI 控件，并已接入场景概览，详见 `docs/refactor-records/样式来源共享紧凑控件执行记录_2026-06-29.md`。

## 1. 本轮继续推进的问题

上一轮已经确认：分区样式页底层已经复用模板管理的样式编辑控件，但概览层的 `样式来源` 仍然由 `scene_overview_projection.py` 自己拼装。

这会带来三个问题：

1. 场景概览能显示“模板 + 分区”的组合状态，但模板管理和 Workbench 无法复用同一份投影。
2. `样式来源` 的状态、摘要、主动作、次动作散在场景概览行里，后续要做共享控件时没有稳定数据契约。
3. 文案清洗也绑定在场景概览里，`OOXML 对象` 这类内部词容易在不同入口产生不一致结果。

本轮先做 P0：抽出纯数据投影，不急着替换 UI 控件。

## 2. 设计目标

共享投影要回答同一个用户问题：

```text
本次样式从哪里来？和模板有没有分区差异？我应该看模板还是调分区？
```

投影不负责渲染，只负责给后续控件提供稳定字段：

| 字段 | 作用 |
| --- | --- |
| `template_label` | 当前模板名称 |
| `template_action_summary` | 模板预览覆盖范围的人话摘要 |
| `section_status_label` | 分区跟随或独立样式状态 |
| `independent_section_count` | 独立样式分区数量 |
| `independent_section_labels` | 独立样式分区名称 |
| `status_label` | 概览状态 chip：跟随模板 / 同源预览 / 有独立样式 |
| `summary` | 兼容当前概览行的一句摘要 |
| `primary_action` | 看模板 |
| `secondary_action` | 调分区 |
| `diff_tags` | 后续差异标签入口，目前先承载独立分区标签 |

这样下一步做 `StyleSourceCompactRow` 时，不需要再从场景里重新推导这些信息。

## 3. 已执行代码改动

### 3.1 新增共享投影模块

文件：`src/ui/panels/style_source_projection.py`

新增：

- `StyleSourceActionSpec`
- `StyleSourceProjection`
- `build_style_source_projection()`

投影当前输出：

```text
模板：默认格式，核对页面、正文和 Word 对象；分区：1 个分区使用独立样式：参考文献
```

并提供：

```text
primary_action = 看模板 -> tpl_overview
secondary_action = 调分区 -> scn_style_rules
```

### 3.2 场景概览改为消费共享投影

文件：`src/ui/panels/scene_overview_projection.py`

变更：

- `build_scene_key_setting_rows()` 不再直接调用私有 `_style_source_setting_summary()` / `_style_source_setting_status()`。
- 改为调用 `build_style_source_projection()`。
- `style_source` 行的 summary、status、主目标、次目标、主按钮、次按钮都来自共享投影。
- 删除场景概览内部的样式来源拼装 helper。

这一步保持 UI 表现不变，但让 `样式来源` 从“场景概览特例”变成“可被其他页面消费的投影”。

### 3.3 文案清洗修正

新增测试暴露出一个边界：

```text
`OOXML 对象` 被先替换 `OOXML` 后保留原“对象”后缀，形成重复词。
```

原因是先把 `OOXML` 替换成 `Word 对象`，再保留原来的“对象”后缀。本轮在共享投影和场景首屏清洗里都增加完整短语替换：

```text
OOXML 对象 -> Word 对象
```

避免后续入口出现重复词。

## 7. 下一步建议

### P1：共享样式来源紧凑控件

新增 `src/shared/ui/style_source_compact_row.py`，用投影直接渲染：

- 模板状态。
- 分区状态。
- 主动作 `看模板`。
- 次动作 `调分区`。
- 窄屏动作列竖排。

### P1：Workbench 执行前检查接入

Workbench 不应该重新解释样式规则，只显示只读样式来源：

```text
模板：默认格式
分区：全部分区跟随模板
```

有独立样式时显示：

```text
分区：参考文献、摘要使用独立样式
```

### P2：字段级差异投影

当前 `diff_tags` 只承载独立分区名称。后续应接入真正的样式差异：

- 字体。
- 字号。
- 缩进。
- 行距。
- 段前段后。

这样概览可以从“有独立样式”推进到“有 3 项样式差异”，可读性和可信度都会更强。

## 8. 当前判断

这一步让 `样式来源` 终于从场景概览里的特例文案，变成了可复用的数据投影。它还不是最终优秀设计，但已经把后续复用控件、Workbench 只读摘要、模板管理入口一致性所需的底座补上了。

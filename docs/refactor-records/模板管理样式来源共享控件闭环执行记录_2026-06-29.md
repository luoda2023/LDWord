# 模板管理样式来源共享控件闭环执行记录（2026-06-29）

## 1. 本轮继续推进的问题

上一轮已经把 `StyleSourceProjection + StyleSourceCompactRow` 接入了场景概览和 Workbench 快速执行页，但模板管理概览仍然只显示模板选择、来源 chip、参数概览和样式预览。

这会造成一个结构性问题：

- 场景页说“样式来源”。
- Workbench 执行前也说“样式来源”。
- 真正定义样式基线的模板管理页却没有同一个控件。

用户看到的结果是：两端消费页面已经统一，但源头页面还没有进入同一套表达，复用链路没有闭环。

## 2. 本轮判断

模板管理不应该伪装成场景页，也不应该出现“调分区”这种不属于模板页的动作。

更合适的方式是让共享控件支持模板基线视角：

```text
模板页：模板：默认格式，作为样式基线；场景分区：默认跟随此模板
场景页：模板：默认格式；分区：1 个分区使用独立样式：参考文献
Workbench：执行前使用同一套模板/分区来源表达
```

这样三处共用同一套控件，但每处只暴露自己负责的动作。

## 3. 已执行代码改动

### 3.1 新增模板基线投影

文件：

- `src/ui/panels/style_source_projection.py`

新增：

```python
build_template_style_source_projection(...)
```

它返回同一类 `StyleSourceProjection`，但语义切换为模板基线：

- `status_label`：`模板基线`
- `template_action_summary`：`作为样式基线`
- `section_line_prefix`：`场景分区`
- `section_status_label`：`默认跟随此模板`
- primary action：`编辑正文 -> tpl_style`
- secondary action：空
- `view_mode`：`template_baseline`

这避免模板页为了复用控件而伪造一个 `SceneWorkspace`。

### 3.2 共享控件支持不同前缀

文件：

- `src/shared/ui/style_source_compact_row.py`

`StyleSourceCompactRow.apply_projection()` 现在读取：

- `template_line_prefix`
- `section_line_prefix`
- `view_mode`

场景页继续显示：

```text
模板：...
分区：...
```

模板页显示：

```text
模板：...
场景分区：...
```

同一个控件承载两种上下文，但不会把场景页语言硬塞进模板页。

显式模式当前包括：

```text
template_baseline
scene_editable
execution_review
readonly
```

按钮显隐由模式和 action target 一起决定，不再只靠空 target 暗示模板页状态。

### 3.3 模板概览接入共享控件

文件：

- `src/ui/panels/template_panel.py`

在 `TemplateOverviewDetail` 的“当前模板”卡片中加入：

```python
self._style_source_row = StyleSourceCompactRow(...)
```

刷新模板时调用：

```python
build_template_style_source_projection(self._current_template)
```

按钮路由复用既有 `edit_navigate` 信号：

```text
编辑正文 -> tpl_style
```

模板概览因此成为样式来源链路的源头，而不是旁路说明。

## 6. 当前闭环程度

已打通：

```text
模板管理概览
  -> StyleSourceProjection(template baseline)
  -> StyleSourceCompactRow
  -> 编辑正文

场景概览
  -> StyleSourceProjection(scene section source)
  -> StyleSourceCompactRow
  -> 看模板 / 调分区

Workbench 快速执行
  -> StyleSourceProjection(scene section source)
  -> StyleSourceCompactRow
  -> 看模板 / 调分区
```

这意味着“样式来源”不再只是场景页和执行页的解释文本，而是从模板源头开始统一。

## 7. 仍然不足

还没有达到优秀设计，主要差在三点：

1. 模板概览只接入了基线来源行，还没有把字段级差异投影带进模板参数概览。
2. `StyleSourceCompactRow` 已有显式 `view_mode`，但还没有经过真实窗口视觉验证，不能证明不同模式下的按钮密度已经足够舒服。
3. 后续已补 Qt offscreen 三入口视觉审计，详见 `docs/refactor-records/样式来源三入口视觉审计执行记录_2026-06-29.md`。真实 Windows 字体截图仍未完成。

## 8. 下一步建议

### P2：字段级差异投影

把模板参数和场景分区差异拆成可读的字段级结果：

```text
正文：跟随模板
参考文献：独立行距
题注：独立字号
```

不要再让用户从“有独立样式”猜具体差异。

### P2：模式视觉验证

共享控件已经有显式模式。下一步要验证不同模式在真实窗口中的密度和动作边界：

```text
template_baseline：模板页只保留模板侧动作
scene_editable：场景页保留模板和分区动作
execution_review：执行页按分区状态显示定位动作
readonly：只展示来源，不展示动作
```

### P2：真实窗口视觉验证

已补 Qt offscreen 布局截图和 metrics，并继续压缩长模板摘要、隐藏 Workbench 跟随模板时的分区动作、把场景双按钮改成宽屏横排，详见 `docs/refactor-records/样式来源三入口视觉审计执行记录_2026-06-29.md`、`docs/refactor-records/样式来源摘要压缩与执行复核减负记录_2026-06-29.md` 与 `docs/refactor-records/样式来源双动作响应式布局减负记录_2026-06-29.md`。还需要补真实 Windows 桌面截图，重点看：

- 首屏是否仍然过密；
- “样式来源”是否像同一个控件；
- 模板页是否因为新增行变得啰嗦；
- 按钮是否和模板管理其他动作一致。

## 9. 当前判断

这一轮把复用链路从“消费侧统一”推进到了“源头也统一”。

现在的结构已经更接近一个完整产品契约：模板管理定义基线，场景表达是否偏离，Workbench 在执行前复核同一件事。下一步不应该继续增加说明文字，而应该继续推进字段级差异和真实窗口视觉验证。

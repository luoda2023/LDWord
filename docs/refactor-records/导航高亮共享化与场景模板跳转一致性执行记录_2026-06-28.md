本轮目标：继续推进“模板管理”和“场景样式覆盖”的一致性。上一轮已经把字段路径归一和字段到控件的映射收回 `ParagraphStyleEditor`，但字段定位后的高亮行为仍在不同页面重复实现。本轮把高亮状态也抽成共享 helper。

## 1. 本轮发现的问题

上一轮之后，链路变成：

```text
诊断字段路径 -> ParagraphStyleEditor.widget_for_field() -> 具体控件
```

但“控件被定位后如何高亮”仍有三处重复：

```text
StyleDetail._highlight_navigation_widget()
_SimpleFormDetail._highlight_navigation_widget()
_ScopeDetail._highlight_navigation_widget()
```

这些方法做的是同一件事：

1. 清除上一个控件的 `navigation_field_highlight`。
2. 恢复上一个控件的原始 stylesheet。
3. 给当前控件设置高亮边框。
4. 设置 `当前执行问题定位：...` tooltip。
5. 聚焦控件。

这类重复会带来两个问题：

- 视觉一致性风险：模板页和场景页未来可能出现不同高亮样式。
- 维护风险：如果要调整 tooltip 或高亮清除逻辑，需要改多个页面。

## 2. 本轮执行

### 2.1 新增共享高亮状态对象

新增：
- `src/shared/ui/navigation_highlight.py`

核心对象：

```text
NavigationHighlighter
```

职责：

- 保存当前高亮控件；
- 保存控件原始 stylesheet；
- `highlight(widget, label)` 时自动清除旧高亮；
- `clear()` 时恢复旧控件状态；
- 统一设置 `navigation_field_highlight` 属性、tooltip、边框和焦点。

它只处理 UI 状态，不判断业务字段应该跳到哪里。

### 2.2 模板正文详情接入共享高亮

修改：
- `src/ui/panels/template_style_detail.py`

变化：

```text
StyleDetail.focus_navigation_field()
  -> ParagraphStyleEditor.widget_for_field(target)
  -> NavigationHighlighter.highlight(widget, target)
```

模板页不再保留自己的 `_navigation_highlight_base_style`，也不再直接写 `当前执行问题定位` 这类 tooltip 文案。

### 2.3 场景详情接入共享高亮

修改：
- `src/ui/panels/scene_panel.py`

接入位置：

```text
_SimpleFormDetail
_ScopeDetail
```

其中 `_SimpleFormDetail` 覆盖输出页等普通场景详情，`_ScopeDetail` 覆盖处理范围和样式覆盖。页面仍保留 `_highlight_navigation_widget(widget, label)` 这个轻量 wrapper，避免大范围改调用点，但内部已经委托给 `NavigationHighlighter`。

### 2.4 导出共享组件

修改：
- `src/shared/ui/__init__.py`

新增导出：

```text
NavigationHighlighter
```

## 3. 一致性收益

本轮之后，场景和模板跳转链路进一步收口：

```text
字段路径归一：
  ParagraphStyleEditor

字段到控件：
  ParagraphStyleEditor.widget_for_field()

定位后的高亮状态：
  NavigationHighlighter

页面 owner：
  只负责“这个字段属于哪个业务区域”
```

这让“模板正文排版”和“场景样式覆盖”更接近同一套交互系统，而不是两个看起来相似但内部各自维护的页面。

结果：

```text

```

测试约束新增/收紧：

- `NavigationHighlighter` 必须能在两个控件之间移动高亮，并恢复旧控件原始样式。
- 模板正文页必须使用 `NavigationHighlighter`。
- 场景面板必须使用 `NavigationHighlighter`。
- 模板正文页和场景面板源码不再直接包含 `当前执行问题定位`。
- 模板正文页和场景面板源码不再保留 `_navigation_highlight_base_style` 这类局部状态字段。

## 5. 仍未完成的缺口

当前 `样式覆盖` 已经从 `处理范围` 中拆成独立卡片，但左侧导航仍只有 `处理范围`。这不会阻断当前交互，但如果后续样式覆盖配置继续增长，应考虑变成独立导航项。

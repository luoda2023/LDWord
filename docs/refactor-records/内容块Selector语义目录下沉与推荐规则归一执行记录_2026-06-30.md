# 内容块 Selector 语义目录下沉与推荐规则归一执行记录

日期：2026-06-30

## 本轮结论

输出区的内容块规则已经完成一次更底层的语义归一：内容块 selector 的业务名称不再只存在于 UI 适配器里，而是下沉到配置层的共享目录。这样“手动添加规则”“版本模板套用”“场景族应用推荐”三条入口都能使用同一套“答案、解析、解题过程、教师备注、知识点、题干正文”等业务标签。

这一步解决的是隐藏很深的一致性问题：界面看起来已经人话化，但场景族推荐生成的数据仍可能带着 `preset_id:selector:action` 这样的技术 label。现在推荐规则写入场景时就已经是可读标签，不再等 UI 临时翻译。

## 原问题

此前三条链路的规则 label 来源不一致：

- 手动编辑：`_parse_visibility_rules()` 使用 `content_visibility_selector_label()`，能生成“答案、解析”。
- 版本模板：`_build_delivery_preset_template_rules()` 使用同一 UI 投影，也能生成“答案、解析”。
- 场景族推荐：`scene_family_application._content_visibility_rules_from_spec()` 生成 `student_version:answer:remove` 这类技术 label。

这会造成两个问题：

1. 数据层不一致。不同入口生成的 `ContentVisibilityRule.label` 语义不同。
2. 后续任何复用规则 label 的地方都有风险，一旦不重新按 selector 翻译，就会把技术串暴露给用户。

## 本轮实现

涉及文件：

- `src/config/content_visibility_selectors.py`
- `src/ui/adapters/content_visibility_display.py`
- `src/config/scene_family_application.py`
- `tests/test_scene_panel_architecture.py`

主要变更：

- 新增配置层 `content_visibility_selectors.py`，承载常用内容块 selector 的业务名和说明。
- 将原先 UI adapter 内部的 `ContentVisibilitySelectorOption`、`COMMON_CONTENT_VISIBILITY_SELECTOR_OPTIONS`、`content_visibility_selector_label()` 下沉到配置层。
- UI adapter 继续负责 tooltip、扫描问题和显示组合，但不再独占 selector 语义目录。
- 场景族推荐生成 `ContentVisibilityRule` 时改用 `content_visibility_selector_label(selector)`。
- 扩充考试/教学场景常见 selector：
  - `teacher_note` → 教师备注
  - `knowledge_points` → 知识点
  - `student_blank` → 学生留白区
  - `question_body` → 题干正文

## 链路复核

当前考试/教学场景应用推荐后，规则 label 已归一：

```text
student_version:
answer -> 答案
analysis -> 解析
solution -> 解题过程
teacher_note -> 教师备注
knowledge_points -> 知识点

answer_sheet:
answer -> 答案
analysis -> 解析
solution -> 解题过程
teacher_note -> 教师备注
knowledge_points -> 知识点
question_body -> 题干正文
```

这说明推荐规则进入数据层时已经是业务语义，而不是 UI 层临时修饰。

## 与模板管理一致性的关系

模板管理的稳定模式是：字段/对象 ID 可以存在，但显示名必须有统一目录，且不同入口不能各自解释同一个字段。

本轮将内容块 selector 也纳入这个模式：

- selector 是稳定技术锚点，例如 `answer`、`teacher_note`。
- label 是用户理解层，例如“答案”“教师备注”。
- tooltip 和校验详情可以同时保留 selector，用于排查。
- 生成规则的业务层、输出区 UI、快速执行详情都从同一套 selector 目录取名称。

这比单独在 scene panel 里替换文本更可靠，因为它减少了未来新增推荐规则时再次出现 raw label 的概率。

## 测试覆盖

新增测试：

- `test_scene_family_application_uses_shared_content_visibility_rule_labels`

覆盖内容：

## 后续建议

1. 内容块规则编辑器仍然保留文本区，这是高级能力需要，但可以继续把“内容块 + 处理方式 + 添加规则”做成主路径，文本区只作为高级编辑。
2. 场景族推荐的交付版本 label 仍有部分英文，例如 `Student version`、`Answer key`。后续可按同样思路建立交付版本显示名目录或补齐场景族 spec 的中文业务 label。
3. 如果后续执行器也需要识别内容块 selector，建议直接依赖 `src.config.content_visibility_selectors`，避免再从 UI adapter 反向导入。

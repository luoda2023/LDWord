# 模板 Policy 覆盖项跳转场景分区闭环记录

日期：2026-06-30

## 1. 本轮目标

上一轮模板正文样式页已经能只读显示当前场景覆盖关系：

```text
模板正文样式
-> policy: 场景覆盖
-> references_body checked
```

但这还只是提示。用户看到“当前场景参考文献正文使用独立样式”后，仍需要自己回到场景页找对应分区。这个交互仍不够优秀。

本轮目标是把它推进成可操作入口：

```text
模板正文样式 policy 行
-> 点击参考文献正文
-> 跳到场景页分区样式
-> 定位同一分区
-> 场景页 policy 行成为当前态
```

## 2. 现有协议审计

### 2.1 已有可复用协议

| 协议 | 当前状态 |
| --- | --- |
| `StylePolicyControlDeck.policy_selected` | 已支持只读行点击发出 key |
| `TemplatePanel.bridge.navigate_to_intent` | 已用于跨面板导航 |
| `ScenePanel.handle_navigation_intent` | 已支持按 `card_id + field_id` 聚焦 |
| `_StyleRulesDetail.focus_navigation_field` | 已支持具体字段和 bare variant key |

### 2.2 缺失点

缺的是两个小环节：

1. 模板页没有把 `policy_selected("references_body")` 转成跨面板 intent。
2. 场景页对 `scene.section_styles.references_body` 这种“分区整体路径”解析不完整。

## 3. 本轮实现

### 3.1 `StyleDetail` 发出覆盖项请求

模板正文样式详情新增信号：

```python
scene_policy_requested = Signal(str)
```

只读 policy deck 点击后：

```text
StylePolicyControlDeck.policy_selected("references_body")
-> StyleDetail._on_template_policy_selected(...)
-> scene_policy_requested("references_body")
```

### 3.2 `TemplatePanel` 转成跨面板 intent

模板面板新增 handler：

```python
_on_template_scene_policy_requested(policy_key)
```

发出的 intent：

```python
{
    "panel_id": "scene",
    "card_id": "scn_style_rules",
    "field_id": "scene.section_styles.references_body",
    "issue_id": "scene_style_field",
    "return_panel_id": "template",
    "return_card_id": "tpl_style",
}
```

这里使用完整语义路径 `scene.section_styles.references_body`，避免继续传播内部 bare key。

### 3.3 `ScenePanel` 支持分区整体路径

场景页 `_style_navigation_target(...)` 新增：

```text
scene.section_styles.references_body
-> ("references_body", "")
```

这样它和已有路径保持同一套解析逻辑：

```text
scene.section_styles.references_body.font_cn
scene.section_styles.references_body
references_body
```

都能定位到同一分区。

## 4. 用户链路

现在链路是：

```text
TemplatePanel / tpl_style
  StylePolicyControlDeck(read_only=True)
    row: references_body
      click
        -> navigate_to_intent
          panel_id=scene
          card_id=scn_style_rules
          field_id=scene.section_styles.references_body

ScenePanel / scn_style_rules
  focus_navigation_field("scene.section_styles.references_body")
    -> current variant = references_body
    -> current policy key = references_body
    -> row[references_body].style_policy_row_current = True
```

这让模板页的“场景覆盖”不再是静态说明，而是可以直达场景配置位置。

## 7. 剩余差距

### P0：返回模板页后的上下文还可更强

当前 intent 已带：

```text
return_panel_id=template
return_card_id=tpl_style
```

场景页会显示返回条，但返回模板页后还没有自动重新高亮对应 policy 行。后续可以把 `active_issue_id` 或 `field_id` 回填给模板页，让模板页返回时也定位到同一覆盖项。

### P0：全量场景覆盖总览仍未完成

本轮仍只处理当前场景。完整设计还需要：

```text
模板
-> 使用该模板的所有场景
-> 每个场景覆盖了哪些分区
-> 点击任意覆盖项进入对应场景
```

这需要更完整的场景索引和覆盖摘要，不应在当前数据不足时伪造。

### P1：导航文案需要继续打磨

当前 payload 使用“场景分区样式”“来自模板：查看场景覆盖”等人话文案。后续可以统一到同一套 `field_display_names` 或 style policy display helper，避免多处散写。

## 8. 本轮结论

这一轮完成了一个小但关键的体验闭环：

- 模板页能看到当前场景覆盖。
- 覆盖行可以点击。
- 点击后进入场景页分区样式。
- 场景页同一分区策略行成为当前态。

这让模板管理和场景规划不再只是“视觉上复用控件”，而是开始形成真实的跨面板工作流。

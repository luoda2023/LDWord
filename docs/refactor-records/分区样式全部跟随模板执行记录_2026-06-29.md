# 分区样式全部跟随模板执行记录（2026-06-29）

## 1. 本轮目标

前几轮已经完成：

- 分区样式从“样式覆盖”改成“独立样式 / 跟随模板”的用户语言。
- 模板管理与分区样式共享 `来源 / 影响 / 编辑` owner 状态。
- 分区样式页展示 `模板基线 / 当前分区 / 差异` 对照。

但操作闭环还缺一步：当多个分区都启用了独立样式时，用户只能逐个分区点“恢复模板”。这不适合批量检查和回退，也会让“当前分区恢复”和“全部分区恢复”的边界不够清楚。

本轮补齐“全部跟随模板”动作。

## 2. 设计判断

### 2.1 当前分区恢复和全部恢复必须分开

保留现有 owner toolbar 按钮：

```text
恢复模板
```

含义：只恢复当前正在编辑的分区。

新增卡片头部动作：

```text
全部跟随模板
```

含义：关闭所有已知分区的独立样式，让它们重新跟随模板。

这两个动作分层明确：

| 动作 | 位置 | 影响范围 |
| --- | --- | --- |
| 恢复模板 | 编辑样式工具条 | 当前分区 |
| 全部跟随模板 | 分区样式卡片头部 | 所有已开启独立样式的分区 |

### 2.2 不加长确认文案

为了避免界面回到“不说人话”的说明堆砌，本轮没有新增大段说明，也没有加复杂弹窗。

影响范围通过 tooltip 给出：

```text
将关闭独立样式：参考文献、附录
```

这样主界面仍然短，悬停时能确认会影响哪些分区。

### 2.3 只恢复已知分区样式

批量恢复只处理 `STYLE_VARIANTS` 里注册的分区样式，避免误删未来可能挂在 `scene.section_styles` 下但不属于当前 UI 管理范围的扩展数据。

## 3. 已执行代码改动

### 3.1 服务层

```python
restore_all_scene_section_styles_to_template(scene, variants=STYLE_VARIANTS)
```

```python

```

没有可恢复项时返回空 tuple。

### 3.2 UI Section

更新：

- `src/ui/panels/scene_style_override_sections.py`

```text

```

启用规则：

### 3.3 ScenePanel 接入

更新：

- `src/ui/panels/scene_panel.py`

新增：

- `_section_style_override_labels()`
- `_on_restore_all_styles_to_template()`
- `_restore_all_section_styles_btn`

刷新链路：

1. 点击 `全部跟随模板`。
2. 服务层返回被恢复的分区 key。
3. 所有对应 toggle 取消选中。
4. 当前编辑区重新同步为“跟随模板”。
5. 摘要、owner 状态、对照条、预览全部刷新。
6. 触发 `style_rules_changed`。

## 4. 当前用户链路

### 4.1 多个分区独立时

```text
跟随状态：2 个分区独立样式
按钮：全部跟随模板（启用）
tooltip：将关闭独立样式：参考文献、附录
```

点击后：

```text
跟随状态：全部跟随模板
来源：跟随模板
影响：来自模板
差异：无差异
按钮：全部跟随模板（禁用）
```

### 4.2 没有独立样式时

```text
按钮：全部跟随模板（禁用）
tooltip：当前没有独立样式
```

这避免用户误以为还能执行某种隐藏操作。

本轮之后，分区样式的操作闭环更完整：

- 看得懂：来源、影响、编辑状态清楚。
- 比得清：模板基线、当前分区、差异清楚。
- 改得动：开启独立样式后可编辑。
- 退得回：当前分区可恢复，所有分区也可一次回到模板。

这一步让“分区样式”更像一个完整的管理面板，而不只是模板管理的局部附属控件。

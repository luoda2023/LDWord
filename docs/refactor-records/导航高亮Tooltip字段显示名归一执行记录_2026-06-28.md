# 导航高亮 Tooltip 字段显示名归一执行记录（2026-06-28）

## 1. 本轮问题

上一轮已经把工作台证据行和面板返回条改为显示可读字段名，但控件被导航高亮后，tooltip 仍直接显示原始字段路径。

这会造成一个割裂体验：

- 返回条显示：`参考文献正文中文字体`
- 证据行显示：`参考文献正文中文字体`
- 控件 tooltip 又显示：`scene.section_styles.references_body.font_cn`

用户 hover 到控件时会重新看到内部 key，等于前面“说人话”的工作只完成了一半。

## 2. 设计取舍

本轮没有把原始路径完全删除，而是改为：

```text
当前执行问题定位：参考文献正文中文字体（scene.section_styles.references_body.font_cn）
```

原因：

- 主读法是用户语言。
- 括号里保留原始路径，便于开发、审计、测试定位。
- 共享高亮控件不直接依赖业务字段目录，避免 `src/shared/ui` 反向依赖 `src/ui/adapters`。

## 3. 已落地实现

更新共享控件：

- `src/shared/ui/navigation_highlight.py`
  - `NavigationHighlighter.highlight(widget, label, *, display_label="")`
  - 当 `display_label` 与 `label` 不同时，tooltip 展示 `display_label（label）`。
  - 当没有 `display_label` 时保持旧行为。

接入字段目录：

- `src/ui/panels/scene_panel.py`
  - 场景样式覆盖、处理范围、资料 Schema、输出交付等高亮入口使用 `field_display_name()`。
- `src/ui/panels/template_page_detail.py`
  - 页面设置字段高亮使用 `field_display_name()`。
- `src/ui/panels/template_style_detail.py`
  - 正文样式字段高亮使用 `field_display_name()`。
- `src/ui/adapters/field_display_names.py`
  - 增加输出交付字段显示名：默认交付方案、文件名规则、输出目录规则、终稿 Word、资料包等。

## 4. 行为变化

已改变：

- 场景样式字段 tooltip：`参考文献正文中文字体（scene.section_styles.references_body.font_cn）`
- 场景通配字段 tooltip：`所有处理分区行距（scene.section_styles.*.line_spacing_pt）`
- 场景输出字段 tooltip：`文件名规则（filename_template）`
- 场景资料字段 tooltip：`主资料 Schema（input_source_profile.material_schema_id）`
- 模板页面字段 tooltip：`左页边距（template.page_setup.margin.left_cm）`
- 模板正文字段 tooltip：`正文中文字体（body.font_name）`

保持不变：

- 高亮属性仍是 `navigation_field_highlight`。
- 原始 `field_id` / `repair_target_key` 不变。
- `NavigationHighlighter` 仍只负责显示与样式，不知道业务字段目录。
- 未传 `display_label` 的调用仍显示原 label。

## 5. 对“模板管理一致性”的推进

这次让模板管理和场景管理在一个更细的交互层对齐：

- 模板页面字段和场景输出字段都用同一种 tooltip 格式。
- 模板正文样式和场景分区样式都用同一个字段显示名目录。
- 工作台跳转、面板返回条、证据行、控件高亮四个触点开始使用同一套字段语言。

这比继续加说明文本更有效，因为用户在每个触点看到的是同一个对象名称。

## 6. 后续缺口

仍需要继续推进：

1. `NavigationHighlighter` 目前只在 tooltip 中保留 raw key；后续可以为调试模式/审计模式单独显示 raw key，普通模式只显示字段名。
2. 表格、题注、目录、页眉页脚的高亮字段名还应继续补齐。
3. 问题队列标题和 tooltip 中仍有部分 raw key，后续应拆分“用户摘要”和“审计详情”。
4. 场景概览卡片仍需要按六个结果导向板块重排，减少内部计数和成熟度标签。

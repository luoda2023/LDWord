# 模板草稿暂存与 JSON 显式保存语义修正记录

- 日期：2026-07-13
- 范围：模板详情、主面板、模板选择、工作模式、Workbench 绑定、程序关闭、JSON 持久化
- 状态：已实施

## 1. 本次纠正的错误

上一轮虽然隔离了 draft 与 committed，但把“离开编辑页”误当成“必须结束事务”，导致详情切换、主面板切换、模板切换和工作模式切换都要求保存/放弃/取消。同时又把 `source_type=builtin` 误当成绝对只读，把主保存强制改成“创建副本并保存”。

这两个判断都不符合本项目的真实语义：

1. 草稿的价值就是可以临时保留，导航不应该隐式提交或销毁它。
2. 当前项目还未发布，`config_library/templates/*/builtin/*.json` 是真实、可写、权威的当前配置文件；来源标签不能取代文件能力判断。

## 2. 最终状态模型

```text
Saved JSON
    │ load / deep copy
    ▼
Committed Template ─────────→ Bridge / Workbench / Execution
    │ deep copy
    ▼
Draft Template ──────────────→ Editor / Local Preview
    │ explicit Save only
    └── atomic write JSON ──→ new Committed Template ──→ publish once
```

核心不变式：

- 字段编辑只修改 draft；
- 编辑区预览可以立即投影 draft；
- Bridge、Workbench 和执行只能看到 committed 深拷贝；
- 只有明确的“保存”或关闭时用户选择“保存全部”才写盘。

## 3. 导航与持久化边界

| 操作 | 草稿 | JSON | Bridge/执行 |
|---|---|---|---|
| 切换参数详情 | 保留 | 不变 | 不变 |
| 切换主面板 | 保留 | 不变 | 不变 |
| 切换模板 | 按模板身份缓存，返回后恢复 | 不变 | 切换到新选中模板的 committed 版本 |
| 切换工作模式 | 按模式隔离缓存 | 不变 | 加载目标模式的 committed 默认模板 |
| Workbench/方案绑定 | 不变且不拦截 | 不变 | 使用 committed 模板正常切换 |
| 保存 | 接纳为 committed | 原子写入当前路径 | 成功后发布一次 |
| 创建副本 | 建立新身份 | 新建独立 JSON | 选中副本的 committed 版本 |
| 重命名模板 | 只修改当前 draft，并标记待保存 | 不变 | 不变；后续点击“保存”才发布 |
| 删除模板 | 明示告知并丢弃该模板草稿，从缓存移除 | 删除当前可管理 JSON | 切换到默认 committed 模板 |
| 关闭程序 | 保存全部/放弃全部/取消 | 按用户选择 | 只在保存成功后更新 |

## 4. 保存语义

1. 当前有 `.json/.yaml/.yml` 路径时，主“保存”直接写回该路径，不区分 builtin/user/external。
2. 当前没有文件路径时，使用同一 `template_id` 在当前工作模式的模板库中落盘，不弹出副本命名。
3. 写入继续使用同目录临时文件和 `os.replace()` 的原子链。
4. 保留路径、大小、mtime 和 SHA-256 版本校验；外部修改时必须明确确认后才覆盖。
5. 模板概览不提供直接“导入 / 另存为 / 恢复”动作；外部模板入库只走模板工作区的“待导入”校验链，复用模板使用“创建副本”，不得再建立第二套文件选择器导入或任意路径导出入口。
6. 原位保存保持当前逻辑 `template_id`，不得用文件名 stem 偷换方案绑定身份。
7. “保存全部”先完成共享引用确认、目标去重、缓存碰撞和外部版本预检，再统一暂存并提交；任一写入失败时恢复本批次原文件，所有 Session 继续保持 dirty。
8. 若原路径在编辑开始时不存在、保存前却被外部新建，按“已有目标”请求覆盖确认；目录、损坏链接或不可读取目标在写盘前直接拒绝。
9. 序列化即使在 staging 文件中途失败，也会清理该半成品，不在模板目录留下隐藏垃圾文件。

## 5. 实施点

- `TemplateDraftStore` 缓存多个 `TemplateEditSession`：有路径资源以“工作模式 + 规范化路径”为身份，无路径资源以“工作模式 + 模板 ID”为身份；rekey 不得覆盖其他缓存上下文。
- `TemplateDraftSaveCoordinator` 从 TemplatePanel 中接管保存目标解析、源版本观察、缓存碰撞与 committed 接纳，Panel 只保留用户确认和界面反馈。
- `TemplatePanel.request_leave_pending_changes()` 对普通导航始终放行。
- `TemplatePanel.prepare_close_pending_changes()` 与 `commit_close_pending_changes()` 将关闭处理拆成无写盘预检和最终提交；旧的 `request_close_pending_changes()` 仅保留为兼容入口。
- `template_save_transaction.save_template_batch()` 负责多文件预暂存、替换和运行时失败回滚，避免“保存全部”只成功一半。
- `MainWindow` 的工作模式 dirty 决策只处理方案，不再暗中保存模板。
- `MainWindow.closeEvent()` 先暂停后台模板导入、收集关闭决策并停止执行任务，全部通过后才提交模板草稿；关闭被否决时恢复后台协调器。
- Workbench 和 ScenePanel 不再使用 `template_dirty` 拦截绑定或触发重算。
- TemplatePanel 不再通过 Bridge 的 dirty 信号回调自己；详情保存按钮直接由当前 Session dirty 状态驱动，Bridge 只保留兼容投影。
- Workbench 下拉框保持“纯名称 + 来源 badge”的当前交互；回归断言不再要求已被 UI 移除的“内置方案：”文字前缀。

## 6. 验收要点

- 详情切换不弹窗，草稿值和 dirty 状态保留，Bridge 仍是 committed 值。
- 模板 A 修改后切到 B，再回到 A，A 的草稿恢复。
- 切换工作模式不询问模板草稿，返回原模式后草稿恢复且未进入执行链。
- 内置模板点击主“保存”写回同一 JSON，不调用副本命名。
- 文件名与逻辑模板 ID 不一致时，原位保存后 ID 和方案绑定保持不变。
- 重命名只暂存名称和既有草稿，不写盘；明确点击保存后才一次提交。
- 关闭时可一次保存多个缓存草稿，或全部放弃，或取消关闭。
- 批量第二个目标提交失败时，第一个目标恢复原内容，全部草稿仍为 dirty。
- 同一物理路径的别名不会建立重复草稿；rekey 与跨模式同目标保存会在写盘前拒绝冲突。
- 外部文件冲突被拒绝时，草稿与外部文件均保留。
- 保存准备后目标再次变化时，整批提交在写盘前中止；外部新建目标、非文件目标和 staging 半成品清理均有故障注入回归。
- 模板概览没有直接导入、导出或全局恢复 Signal、按钮、处理函数；正式待导入协调器和关闭时 `discard_all` 事务保持独立可用。

## 7. 最终原则

> 导航不是保存，draft 不是 committed，来源标签不是文件权限。样式决定预览；只有显式保存才改写 JSON 并更新真实执行链。

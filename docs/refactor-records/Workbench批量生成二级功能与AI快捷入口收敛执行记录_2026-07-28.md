# Workbench「批量生成」二级功能与 AI 快捷入口收敛执行记录

> 日期：2026-07-28
>
> 范围：Workbench 左侧二级导航、快速执行输出区、批次资料准备、批次执行反馈
>
> 状态：已完成二次 UI/UX 收敛、链路修正及自动化/离屏视觉校验

## 1. 本轮问题

原界面有两个信息架构问题：

1. 左侧只有“快速执行”，批量能力被藏在快速执行页的条件按钮中。用户无法提前知道系统支持批量，也无法在一个独立页面完成批次复核。
2. “AI 帮我生成”位于快速执行的执行输出区，但 AI 已经是独立一级功能。这个快捷入口重复了一级导航，并把“AI 创作”和“确定性格式执行”重新混在一起。

因此，本轮不再给快速执行继续叠按钮，而是明确拆分：

```text
Workbench
  ├─ 快速执行：一份输入文档 -> 一次确定性生成
  └─ 批量生成：多份资料 -> 同一方案/模板 -> 多个隔离输出

AI 文档助手
  └─ 保持独立一级功能，不在快速执行中重复提供快捷按钮
```

## 2. 「批量生成」的产品定义

### 2.1 目标

“批量生成”用于把同一套处理方案和模板应用于多份明确选择的资料，每份资料生成一个独立结果。

它不是：

- 一次选择多个无关 DOCX 后并行点击“快速执行”；
- AI 自动创作多份内容；
- 把单份“生成文档”循环调用若干次；
- 只显示一个没有实际 Runner 的占位页面。

### 2.2 输入合同

一次批量任务必须绑定：

| 输入 | 说明 |
|---|---|
| 批次资料选择 | `MaterialBatchSelection`，包含明确的 profile IDs |
| 处理方案 | 当前 Workbench 方案 |
| 模板 | 当前 Workbench 模板 |
| 输出命名规则 | 每份资料的独立子目录规则 |
| 输出根目录 | 批量页独立选择；为空时使用系统默认位置 |
| 源文档 | 通用批次需要，可在批量页直接选择；可直接装配的公文资料表批次不需要 |

资料准备仍由独立的资料功能负责。批量页不再提供“准备/调整资料”按钮，也不再保留仅用于该按钮的跳转信号；它只读取已经发布的 `MaterialBatchSelection`。通用批次需要的 DOCX 源文档仍由批量页自己的输入面板选择，并发布到 Workbench 共享文档状态；不要求用户先切换到“快速执行”完成隐藏前置操作。

### 2.3 输出合同

每份资料必须拥有独立输出目录和独立执行上下文。批次结果应包含：

- 成功数；
- 失败数；
- 每项结果与错误归属；
- 批次历史 run ID；
- 可重试的失败 profile IDs；
- 批次汇总报告和产物引用。

单项失败不能覆盖其他项，也不能把整个批次压缩成一个无法定位的错误字符串。

## 3. 独立面板结构

批量页不再使用“页面标题 + 四张编号大卡片”的向导式结构，而是与快速执行使用同一套操作语法：

1. **批次资料输入面板**
   - 与快速执行文件输入面板同为 70px 高；
   - 显示已选择数量、来源和 profile 摘要；
   - 未选择时只显示中性状态，不提供“准备/调整资料”操作；
   - 通用批次在同一区域直接选择共用 DOCX。
2. **处理方案与模板**
   - 使用与快速执行一致的 `StyledComboBox`；
   - 两个下拉框等宽、同排，并显示内置/自定来源徽标；
   - 用户在任一页面切换后都通过 Bridge 发布同一份方案/模板状态。
3. **输出目录**
   - 使用与快速执行一致的“默认 / 自定义”单选；
   - 只有选择自定义时才显示目录按钮；
   - 右侧给出批量独立目录数量，完整路径放入提示信息。
4. **执行输出**
   - 主按钮、状态区、4px 进度条、取消和失败项重试同排；
   - 阻断和警告使用短状态文案，完整原因进入提示信息；
   - 执行日志按需出现；失败或存在可重试项时自动展开；
   - 日志承接批次隔离明细、产物路径和报告信息。

左侧导航卡固定放在“快速执行”之后，不再依赖当前是否已载入批次资料：

```text
快速执行
批量生成
────────
高级功能（按方案动态出现）
```

空状态显示“尚未选择批次资料 / 待补充”，资料满足条件后变为“可执行”，运行中显示“执行中”，终态显示“已完成”或“需处理”。

## 4. 执行链

```text
资料包 / 方案内容
  -> 发布 MaterialBatchSelection
  -> Workbench 批量生成页同步选择
  -> 逐 profile 资料门禁
  -> 输出路径预检
  -> 用户点击批量生成
  -> WorkbenchExecutionSessionController.build_batch_worker
  -> 每项独立 MaterialExecutionContext
  -> 批次 Runner
  -> 进度 / 取消
  -> Batch Isolation 结果
  -> 失败项 profile IDs
  -> 只重试失败项
```

批量页没有新建第二套 Runner。它复用项目已有的：

- `build_material_batch_items`；
- `check_material_batch_preflight`；
- `material_batch_readiness_gate_decision`；
- `build_batch_worker`；
- 官方公文批次历史与失败项重试合同。

## 5. 单份与批量互斥

Workbench 当前只有一个活动执行 Session，因此必须遵守：

- 单份执行开始后，批量执行按钮禁用；
- 批量执行开始后，单份执行按钮禁用；
- Worker 反馈只投影到发起任务的面板；
- 导航切换不会改变当前 Worker 的反馈归属；
- 执行结束后，两处按钮按各自门禁重新计算，而不是无条件启用。

这避免了单份进度出现在批量页、批量失败项出现在快速执行页，以及两个任务争用同一个 Worker 的问题。

## 6. “AI 帮我生成”删除边界

已从快速执行中删除：

- `AI 帮我生成`按钮；
- `assistant_requested` 信号；
- Workbench 到 Assistant 的快捷跳转连接；
- 对应主题刷新分支。

没有删除独立一级“AI 文档助手”。用户需要 AI 创作时，应从全局一级导航进入；需要确定性单份或批量生产时，从 Workbench 进入。

快速执行的“执行输出”现在只承担：

```text
生成文档 + 可信状态 + 取消/必要处理
```

批量动作、批量重试和 AI 跳转都不再挤在这一行。

## 9. 最终判定

本轮完成后：

- “批量生成”是 Workbench 中固定可见、可进入、可执行、可取消、可重试的独立二级功能；
- 它与快速执行共享方案、模板和文档状态，但拥有自己的批次资料、输出目录和执行反馈；
- 批量页已恢复与快速执行一致的输入、选择、输出和反馈控件语法；
- 批量页不再包含“准备/调整资料”按钮或对应跳转壳子；
- 通用批次可在当前页直接选择 DOCX，不再依赖用户先进入快速执行；
- 批量终态可查看执行日志、批次隔离明细和失败项重试入口；
- “AI 帮我生成”已从快速执行彻底删除；
- 独立一级 AI 功能不受影响；
- 没有新增第二套批次执行逻辑，也没有保留无底层能力的占位交互。

## 10. 快速执行交付闭环与背景修复

后续深度校验确认，快速执行的 Runner 链路已经存在，但执行结果的用户交付仍有两个缺口：

1. 成功产物只写入折叠日志，缺少直接打开文件和所在目录的操作；
2. 成功后更换输入文档、方案、模板、资料或输出位置，旧的成功状态和旧日志仍会保留，造成“当前配置未执行、界面却持有上次成功结果”的状态混淆。

本轮补齐如下：

- 成功后在“执行输出”卡片内显示紧凑结果回执；
- 主产物可直接“打开文档/打开文件”和“打开目录”；
- 多产物与技术信息继续通过“查看全部产物与日志”承接，不新增结果详情页；
- 输入、方案、模板、公文文种、资料或输出位置变化后，旧结果、旧日志和旧回执立即失效；
- 空输入主按钮改为“选择文档并生成”，真实表达其会先打开文件选择器再继续执行；
- 主按钮文件选择复用拖拽区的场景格式合同，试卷场景选择 Markdown，其他场景选择 DOCX；
- 输出区只保留“默认 / 自定义”和必要的目录选择控件，不显示默认路径说明或悬停解释；
- 对象预检确认阶段将日志入口改为“查看 N 项对象风险”；
- 相同执行阶段的重复进度回调不再重复写入日志。

离屏视觉复核还发现，共享 `RoundedSurfaceFrame` 不能正确把 QSS `rgba(...)` 字符串转换为 `QColor`。这会让快速执行已选文档状态和批量已选资料状态的透明浅色背景被绘制为黑色。现已在共享圆角表面层统一解析 RGBA，避免在两个业务面板内分别打补丁。

本次新增/更新的验证包括：

```text
快速执行 + 批量生成 + 圆角表面定向回归：69 passed
Workbench 执行/会话/导航/布局扩展回归：75 passed
圆角表面 + 快速执行 + 批量生成视觉语义回归：102 passed
其他执行/结果/运行时相关回归：241 passed，1 项工作区既有全局布局门禁失败
```

既有失败来自未改动的 `src/ui/panels/scene_content_detail.py` 含 `setFixedHeight(`，与本轮快速执行、批量生成和圆角背景修复无关。

760、960、1200、1500 四种内容宽度下：

- 快速执行空态高度保持 371px；
- 批量生成空态高度保持 371px；
- 方案与模板控件保持等宽；
- 成功回执按需增加内容高度，不影响执行前视觉节奏；
- 快速执行和批量生成的选中态背景均恢复为透明浅蓝，而非黑色。

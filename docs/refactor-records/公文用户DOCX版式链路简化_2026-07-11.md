# 公文用户 DOCX 版式链路简化（2026-07-11）

## 决策

公文生成场景以 DOCX 为唯一视觉样式来源。普通用户不需要创建、导入或手工维护方案 JSON、母版 manifest JSON，也不需要理解 Word 自带的全部样式清单。

- DOCX 负责字体、字号、页边距、红头、红线、段落、落款、版记和分页。
- 文种契约负责字段适用性、必填项和少量结构增删。
- 方案 JSON 只由软件保存规则与当前版式绑定。
- 用户 DOCX 只需保留 `official_title`、`official_body` 两个必要占位符；其余占位符按需要保留。

## 用户链路

1. 在版式管理点击“创建副本”，得到可修改的用户 DOCX；或把修改好的 DOCX 放入用户版式目录。
2. 使用 Word 修改该 DOCX 的真实样式并保存。
3. 点击“刷新公文版式”；软件扫描必要占位符，合格文件自动成为用户版式。
4. 设为当前版式后，方案只保存该 DOCX 的稳定资源 ID 和路径。
5. 重启或重新加载方案时优先恢复用户 DOCX；文件缺失时才回退内置版式。

用户版式目录：

```text
config_library/masters/official/user/
```

该目录为运行时用户资源目录，不进入公开发行包。

## 现有按钮

按产品要求，方案页现有“打开方案文件夹”按钮的文字、位置和样式保持不变；在公文模式下，其目标改为用户 DOCX 版式目录。其他工作模式仍按原规则打开当前方案配置目录。

版式管理中的“打开公文母版文件夹”也指向同一用户目录，避免用户直接修改15个文种共同引用的内置 DOCX。

## 样式边界

Word 文件可能登记大量内置样式，但软件不要求用户逐项管理。当前内置公文母版实际正文只使用少量 Word 样式；占位符替换会保留所在段落和文本运行的现有格式。

15个文种继续默认复用 GB/T 9704 通用 DOCX。以后只有在版面确实不同且有验证证据时，才增加文种专属 DOCX 覆盖，不复制15套样式 JSON。

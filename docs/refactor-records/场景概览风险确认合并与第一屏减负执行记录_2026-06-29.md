# 场景概览风险确认合并与第一屏减负执行记录（2026-06-29）

## 1. 本轮继续推进的问题

上一轮已经把概览页的 `模板与样式` 和 `分区样式` 合并成 `样式来源`。继续审阅第一屏后，还剩一组明显冗余：

```text
风险处理
人工确认
```

这两行在概览里都指向同一个详情页：`scn_cleanup`，也就是“校验与合规”。当没有人工确认事项时，原界面仍然显示：

```text
人工确认：无需人工确认
状态：不处理
```

这对用户没有增加决策信息，反而让第一屏变长。用户真正要知道的是：有风险时怎么处理，是否需要我确认。

本轮把两行合并为：

```text
风险与确认
```

## 2. 设计判断

### 2.1 合并概览表达，不合并业务能力

本轮只调整概览页的信息组织：

| 层级 | 处理方式 |
| --- | --- |
| 概览页 | `风险处理` + `人工确认` 合并为 `风险与确认` |
| 详情页 | 仍跳到 `scn_cleanup` |
| 风险通知卡 | 仍保留 `风险与边界` 卡片，最多展示 3 条边界提醒 |
| 执行与报告 | 不改变对象预检、阻断、跳过、人工确认报告链路 |

也就是说，第一屏更短，但能力边界没有丢。

### 2.2 没有人工确认时不再占一行

无人工确认时，摘要只保留风险处理：

```text
风险与确认：发现风险先提醒
状态：会提醒
```

不再额外显示“人工确认：无需人工确认”。

### 2.3 需要人工确认时并入同一行

需要人工确认时，摘要合并风险处理和确认事项：

```text
风险与确认：发现风险先提醒；请确认：...
状态：需确认
```

这样用户仍然能在第一屏看到“有事需要我确认”，但不需要理解两个入口为什么都去同一个页面。

## 5. 当前判断

本轮之后，场景概览第一屏从“功能枚举”更进一步转向“用户决策摘要”：

- `样式来源` 告诉用户样式从哪里来。
- `风险与确认` 告诉用户哪里需要注意、是否要人工介入。
- `输出版本` 告诉用户会得到什么。

这比继续列出 `风险处理` 和 `人工确认` 两个普通条目更像真实用户会问的问题，也减少了“不处理”这类对用户没有帮助的冗余状态。

# 文档执行与成套交付共享工作区重构落地记录

日期：2026-07-30

依据：

- `docs/audits/文档执行与成套交付页面重构深度分析_2026-07-30.md`
- `docs/audits/文档执行统一入口落地记录_2026-07-30.md`

## 1. 最终产品结构

工作台固定保留两个一级入口：

1. 文档执行
2. 成套交付

文档执行不提供手工模式开关。用户可以拖入单文件、多文件或文件夹，也可以从资料包选择记录；系统根据输入关系静默识别：

| 拓扑 | 输入关系 | 输出基数 |
|---|---|---|
| `single` | 1 份文档，0 条批次记录 | 1 份 |
| `files` | N 份文档，0 条批次记录 | N 份 |
| `records` | 0/1 份共用底稿，N 条记录 | N 份 |
| `mapping_required` | 多文档与批次记录同时存在 | 阻断 |

`mapping_required` 不按顺序、文件名或笛卡尔积猜测映射。

## 2. source requirement 合同

新增 `required / optional / generated` 三态：

- `required`：按资料生成必须有一份共用底稿；
- `optional`：没有底稿也可执行，存在一份时作为共用输入；
- `generated`：方案直接生成文档，不显示“等待底稿”。

正式公文资料表且当前方案使用公文装配表面时投影为 `generated`。拓扑、准备度和展示均由纯函数生成，可脱离 Qt 测试。

## 3. 权威工作区状态

新增 `DocumentExecutionSnapshot`，统一捕获：

- 输入 manifest；
- 克隆后的资料批次选择；
- 克隆后的当前资料上下文；
- 方案和模板绑定；
- source requirement；
- 输出策略；
- 执行状态。

可变资料对象在进入快照时 clone，避免 Bridge、上下文页面与执行会话共享同一可变引用。

## 4. 单一页面骨架

文档执行现在按以下顺序渲染：

1. 工作区直接拥有的文件/文件夹输入区；
2. 动态拓扑摘要；
3. 唯一可见的方案与模板卡；
4. 随拓扑替换的任务资料与预检上下文；
5. 唯一可见的输出目录卡；
6. 唯一可见的执行 Footer。

工作台嵌入模式不再构造三个旧详情各自的方案、输出和执行卡；不是将重复控件隐藏，而是从构造阶段跳过。独立详情类默认仍可构造完整兼容界面，供单独使用和历史扩展调用。工作台内因此只有一套文档执行方案/模板、输出目录和执行 Footer QWidget 实例。

默认进入工作台时只构造共享骨架与单份上下文。多文件共享资料上下文、按资料记录上下文分别在 `files`、`records` 拓扑首次命中时创建，并立即从此前保存的路径、资料选择、场景和资料上下文状态完成投影；`mapping_required` 不会为了展示阻断信息而提前构造两套上下文。

公共输入区不再调用 `take_source_area()` 从多文件页面转移。多文件上下文在创建时接受工作区拥有的 source area；旧转移 API 已删除。

方案、模板和输出策略在单份、多文件、按资料之间切换时保持不变。模式命中时只 hydrate 当前上下文，不再在每次方案变化时向三个 QWidget 广播同一状态。

## 5. 统一执行与反馈

新增 `DocumentExecutionCoordinator`，根据拓扑选择单份、多文件或按资料适配器，并统一处理重试和取消入口。生产执行引擎、文件批次 runner 和资料批次 session builder 未修改。

新增共享 `WorkbenchExecutionFooter`，统一：

- 主操作位置和动态操作文案；
- 状态、进度、取消；
- 失败项重试；
- 结果回执与日志；
- 对象预检确认和阻断提示；
- `success / partial_success / failed / cancelled` 状态语义。

状态规则：

- `partial_success`：显示“部分完成”，warning；
- `cancelled`：显示“已取消”，neutral；
- 技术日志默认折叠；
- 对象预检确认显示在共享 Footer，不再落入不可见的旧单份执行卡；
- 多文件资料确认同样投影到共享 Footer。

旧模式详情的结果字段暂保留只读兼容投影，以兼容现有扩展和历史测试；共享 Footer 是界面反馈的权威来源。

## 6. 成套交付

成套交付继续保留独立领域模型、预检矩阵和运行计划，只复用表现层：

- 使用 `WorkbenchExecutionFooter`；
- 删除可见的重复页标题；
- 将拓扑数量移动到“输出与预检”卡；
- 保留资料包记录、可执行/阻断数量、产物映射和独立输出目录。

文档执行拓扑没有进入成套交付计划编译或 runner。

## 7. 视觉与几何

- 共享绑定卡、输出卡和 Footer 在拓扑切换时不重建；
- 页面末尾使用伸缩区吸收剩余高度，卡片按内容连续排列；
- 去除上下文堆栈和执行卡吞占剩余高度造成的大块空白；
- 宽窗口下完成空态、多文件、按资料和成套交付截图核验；
- 保留输入格式、文件夹递归、数量、风险、阻断和修复入口等决策信息。

## 11. 资料包选择基线补正

后续界面核验确认，文档执行中的“资料包”曾被实现为只读摘要框，交互层级低于同卡组的方案、模板选择器；资料管理页首次进入又优先采用用户包或空白“未命名资料包”，导致内置样例存在但没有稳定测试基准。

本轮补正如下：

- 工作台资料包控件改为与方案、模板一致的 `StyledComboBox`，选项直接读取模式隔离资料包库；
- 选项使用 `builtin/<package_id>`、`user/<package_id>` 完整身份，保留“内置/自定”徽标，避免同名资料包发生来源折叠；
- 用户选择资料包后加载默认记录，解析字段、时间流和素材，生成真实 `MaterialExecutionContext` 并经既有 Bridge 发布；
- 工作台已选择的执行上下文优先于资料页实时草稿，防止预览显示与实际执行来源不一致；
- `custom` 模式新增只读 `builtin/default_test_package`，界面名称为“默认测试资料包”，默认记录为“默认测试记录”；
- `official` 模式沿用 `builtin/notice_archive_check` 作为确定性默认样例；
- 资料管理页首次进入优先载入当前模式的默认内置包；没有内置包的未来模式才回退到首个可用资料包或空白包；
- 内置包保持不可保存、不可删除，可通过“创建副本”进入用户可编辑分支。

通用版的标准测试路径为：工作台“资料包”下拉选择“默认测试资料包”，或进入资料管理页直接查看同名内置包。默认数据包含项目编号 `TEST-2026-001`，可用于确认资料包选择、字段映射与执行上下文是否来自同一基准。

补正后的验证结果：

- 资料包选择、资料库、公文样例、工作台详情/布局和成套基数扩大回归：`200 passed, 2 skipped`；跳过项仅为当前 Windows 账户没有创建文件/目录符号链接权限；
- 资料编辑、保存、恢复、切包、事务回滚和并发保护回归：`83 passed`；
- 场景矩阵发布聚合门禁：`status=passed`，全部检查 `issue_count=0`；
- Ruff `F / I / UP`、`compileall`、默认包 JSON 解析和 `git diff --check`：通过。

## 12. 资料包 Token 预览与五域测试基线

后续核验发现，展开后的“资料包内容预览”只显示字段名称和值。英文键会被转成 `entity name`、`project no` 一类文本，既不像用户名称，也不是模板可直接使用的 Token；普通字段数量较多时，时间、文件、图片和附件还会全部落入“另有 N 项”，无法用一个默认包完成跨域检查。

本轮将预览合同明确为三层：

1. 名称：面向用户的中文含义，例如“公司名称”“默认项目说明”；
2. Token：模板可复制使用的完整规范代码，必须保留 `{{`、`}}`、`@`、命名空间和稳定标识；
3. 值：当前解析值或绑定状态。

规范 Token 不是裸 `{{字段名}}`，而是按资料域区分：

| 资料域 | 示例 |
|---|---|
| 文本 | `{{@text:company_name}}` |
| 时间 | `{{@time:issue_date}}` |
| 文件内容 | `{{@file:project_brief}}` |
| 图片 | `{{@img:product_image}}` |
| 附件 | `{{@attach:validation_notes}}` |

预览不展示 Python、JSON 等内部实现代码；只展示模板真正识别、用户需要复制的规范 Token。Token 使用现有只读 `MaterialTokenEdit`，沿用资料管理页的一键复制、完整值 Tooltip 和主题样式。

展开区最多投影 10 项。缺失必填项仍优先，但投影算法会为已载入的文本、时间、文件、图片、附件各保留至少一个代表项，避免单一资料域挤占全部可见位置。

`builtin/default_test_package` 同步扩展为自包含五域样例：

- 13 个固定字段；
- 1 个时间流，基于 `start_date=2026-07-01`、`end_date=2026-12-31` 计算 `issue_date=2026-10-01`；
- 1 个已编译并随包内置的 Markdown 文件资料 `project_brief`；
- 1 张无品牌管线监测示意图 `product_image`；
- 1 个文本附件 `validation_notes`；
- 文件、图片和附件均使用包内相对路径或内容寻址工件，资料包移动后仍可解析；
- 图片哈希、附件哈希、内容工件 manifest 和时间流均进入自动化校验。

标准检查路径仍为工作台“资料包”下拉选择“默认测试资料包”，展开“资料包内容预览”。此时应同时看到五种 Token，摘要显示“图片 1 · 文件 1 · 附件 1”。

本轮验证结果：

- 资料包、时间流、内容工件、附件、工作台装配和资产面板扩大回归：`199 passed, 2 skipped`；跳过项仍仅为当前 Windows 账户没有创建符号链接权限；
- 页面投影与资料域 UI 回归：`103 passed, 1 deselected`；暂不纳入的是本记录第 10 节已注明的既有动态附件行局部样式断言；
- 场景矩阵发布聚合门禁：`passed`，全部检查 `0 issues`；
- 默认内容工件 manifest、图片 SHA-256、附件 binding revision、时间流输出、JSON、Ruff `F / I / UP`、`compileall` 和 `git diff --check`：通过。

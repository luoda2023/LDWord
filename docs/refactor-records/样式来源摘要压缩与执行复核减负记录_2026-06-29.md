# 样式来源摘要压缩与执行复核减负记录（2026-06-29）

## 1. 本轮继续推进的问题

三入口视觉审计证明 `StyleSourceCompactRow` 已经在模板管理、场景概览和 Workbench 快速执行中复用，但也暴露了两个设计问题：

1. 场景概览的模板线过长：`核对页面、正文、标题、表格、页眉页脚、目录、参考文献和题注`。
2. Workbench 在“全部分区跟随模板”时仍显示 `调分区`，导致执行前复核行被不必要地撑高。

这两个问题都不是功能缺失，而是首屏密度和动作边界不够克制。

## 2. 本轮执行

### 2.1 压缩长模板核对摘要

文件：

- `src/ui/panels/style_source_projection.py`

新增内部压缩规则：

```text
核对页面、正文、标题、表格、页眉页脚、目录、参考文献和题注
-> 8 类参数可核对
```

规则只用于 `StyleSourceProjection` 的首屏摘要，不改变 `build_template_preview_context()` 的完整 action。也就是说：

- 模板页入口上下文仍保留完整核对范围。
- 场景/Workbench 的样式来源行只显示可扫读短状态。

短列表仍保留原表达，例如：

```text
核对页面、正文和 Word 对象
```

### 2.2 Workbench 跟随模板时隐藏分区动作

文件：

- `src/ui/panels/style_source_projection.py`

规则：

```text
view_mode == execution_review
且没有独立分区
-> secondary_action 为空
```

这样 Workbench 在执行复核时只保留 `看模板`，不再展示看起来像编辑入口的 `调分区`。

场景概览不受影响：只要场景页需要在模板和分区之间切换，仍然保留 `看模板 / 调分区` 双入口。

## 6. 当前判断

这轮把上一轮视觉审计发现的问题处理掉了一半：

- 长模板核对列表不再直接挤在首屏样式来源行。
- Workbench 在跟随模板时不再显示不必要的分区动作，行高从 98px 降到 50px。

后续已经把场景概览双按钮改成宽屏横排，桌面高度降到 50px。仍需真实 Windows 字体截图和窄屏截图继续验证断点是否舒服。

## 7. 下一步建议

### P2：场景页双按钮布局评估

场景页有独立分区时是否一定要竖排双按钮，还需要继续看真实窗口。如果高度仍显得沉，可以评估：

- 双按钮横排。
- 二级动作折叠进菜单。
- `调分区` 改为更明确的 `编辑分区样式`。

# 样式来源共享紧凑控件执行记录（2026-06-29）

后续进展：`StyleSourceCompactRow` 已继续接入 Workbench 快速执行页和模板管理概览，样式来源链路已从模板源头、场景概览到执行前形成第一轮闭环，详见 `docs/refactor-records/Workbench样式来源共享控件接入执行记录_2026-06-29.md` 与 `docs/refactor-records/模板管理样式来源共享控件闭环执行记录_2026-06-29.md`。

## 1. 本轮继续推进的问题

上一轮已经完成 `StyleSourceProjection`：场景概览的 `样式来源` 行不再自己拼装模板、分区和双动作数据。

但 UI 仍然停在过渡状态：`style_source` 还是 `_SceneOverviewSettingRow` 的特例，只是多了第二个按钮。这样数据虽然统一了，控件还没有统一：

- 场景概览仍用普通设置行展示样式来源。
- 模板来源和分区状态仍挤在一句 summary 里。
- 后续 Workbench 想复用时，还得重做按钮和布局。
- `看模板 / 调分区` 的双动作仍没有共享控件契约。

本轮推进 P1：新增共享 `StyleSourceCompactRow`，让 `样式来源` 具备独立控件形态。

## 2. 设计目标

`样式来源` 不应该只是普通设置行，而应该是一张紧凑来源卡，专门回答：

```text
模板基线是什么？
分区有没有独立样式？
用户要看模板还是调分区？
```

控件结构：

| 区域 | 内容 |
| --- | --- |
| 标题 | 样式来源 |
| 状态 chip | 跟随模板 / 同源预览 / 有独立样式 |
| 模板线 | `模板：默认格式，核对页面、正文...` |
| 分区线 | `分区：全部分区跟随模板` 或 `分区：N 个分区使用独立样式...` |
| 主动作 | 看模板 |
| 次动作 | 调分区 |

这样比一句 summary 更容易扫读，也更接近模板管理的“当前模板 + 参数状态 + 动作”节奏。

## 3. 已执行代码改动

### 3.1 新增共享 UI 控件

文件：`src/shared/ui/style_source_compact_row.py`

新增：

- `StyleSourceCompactRow`
- `navigate_requested = Signal(str)`
- `apply_projection(projection)`
- `set_spec(spec)` 兼容旧行数据
- `summary_text()` 兼容现有概览测试和外部读取

控件可直接消费 `StyleSourceProjection`：

```text
模板：默认格式，核对页面、正文和 Word 对象
分区：1 个分区使用独立样式：参考文献
```

并通过按钮发出：

```text
看模板 -> tpl_overview
调分区 -> scn_style_rules
```

### 3.2 导出共享控件

文件：`src/shared/ui/__init__.py`

新增导出：

```text
StyleSourceCompactRow
```

后续 Workbench 或模板管理如果需要同款来源行，可以从共享 UI 直接复用。

### 3.3 场景概览接入新控件

文件：`src/ui/panels/scene_panel.py`

变更：

- `self._setting_rows["style_source"]` 改为 `StyleSourceCompactRow`。
- 其他设置行继续使用 `_SceneOverviewSettingRow`。
- `_refresh_summary()` 中：
  - `style_source` 行调用 `row.apply_projection(spec.style_source)`。
  - 其他行继续 `row.set_spec(row_spec)`。

这一步让场景概览真正从共享投影驱动共享控件。

### 3.4 场景概览 spec 携带投影

文件：`src/ui/panels/scene_overview_projection.py`

变更：

- `SceneOverviewSpec` 新增 `style_source: StyleSourceProjection`。
- `build_scene_overview_spec()` 只构建一次 `style_source` 投影。
- `build_scene_key_setting_rows()` 继续输出兼容的 `style_source` row spec，但内容来自同一个投影。

这样既保留旧的关键设置行协议，也支持新控件直接消费完整投影。

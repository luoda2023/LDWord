# 场景概览执行预览步骤化执行记录（2026-06-29）

## 1. 本轮继续推进的问题

前几轮已经把概览页的关键设置压缩成更像用户决策的结构：

```text
输入与资料
处理范围
样式来源
风险与确认
输出版本
```

继续看第一屏后，剩下一个明显不够优秀的地方：`执行预览` 仍然是一个长文本标签，把 5 个步骤写成多行字符串。

这种方式能读，但不利于快速扫视，也不像一个真正的流程预览。用户想知道的是“接下来会怎么走”，不是读一段编号文本。

本轮把执行预览从长文本改成步骤行。

## 2. 设计判断

### 2.1 不改投影，只改呈现

场景概览已经通过 `SceneRunStepSpec` 和 Workbench 执行阶段共享同一组阶段：

```text
读取
检查风险
统一格式
生成报告
交付文件
```

本轮不新增阶段、不改执行链路，只把现有 `SceneRunStepSpec` 渲染成可扫读的行。

### 2.2 保留兼容文本源

旧的 `_run_steps_label` 仍保留完整文本，但隐藏，不参与布局。原因是：

- 现有测试和首屏文本守门仍可读取完整步骤文本。
- UI 不再显示一整段编号文本。
- 以后如果需要无障碍或复制文本，可以继续消费这个兼容文本源。

### 2.3 每一步只放标题和短说明

新步骤行结构：

```text
[图标] 读取文件
       读取 Word 文档

[图标] 检查风险
       发现风险先提醒
```

比旧格式：

```text
1. 读取文件：读取 Word 文档
2. 检查风险：发现风险先提醒
...
```

更接近用户扫视流程的方式。

### 3.2 概览页接入步骤行

文件：`src/ui/panels/scene_panel.py`

变更：

- `执行预览` 卡片创建 5 个 `_SceneOverviewRunStepRow`。

- 多余步骤行会隐藏，避免未来阶段数变化导致空行。

## 5. 当前限制

1. 当前是静态步骤预览，不是运行时 live stepper。
2. 还没有把 Workbench 执行状态回填到场景概览步骤上。
3. offscreen 环境仍不能可靠验证中文字体真实渲染，真实桌面截图仍需后续补。

## 6. 当前判断

本轮之后，概览页的阅读方式更接近用户真实任务：

- 当前任务：我要处理什么。
- 执行预览：接下来按哪几步走。
- 关键设置：哪些入口需要检查。
- 风险与边界：哪里需要注意。

这不是新增功能，而是把已有流程从“文本说明”升级成“可扫读步骤”。它让第一屏继续向优秀设计靠近。

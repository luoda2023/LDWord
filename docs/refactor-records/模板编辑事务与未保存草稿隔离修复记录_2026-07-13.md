# 模板编辑事务与未保存草稿隔离修复记录

- 日期：2026-07-13
- 范围：模板参数编辑、保存/恢复、详情与模板切换、主面板切换、工作模式切换、程序关闭、Workbench/执行模板同步、外部模板文件冲突
- 状态：已实施并通过相关回归验证

## 1. 修复结论

此前模板详情直接修改 Bridge、Workbench 和执行链共同持有的 `TemplateConfig`。字段修改虽然尚未写入磁盘，却已经成为当前会话中的全局模板；Workbench 接收同一对象后还会清除模板 dirty，导致保存按钮灰掉、恢复基线被污染、未保存样式可能参与执行。

修复后建立三层边界：

```text
磁盘已保存模板
      ↓ 加载/深拷贝
Committed Template ─────→ Bridge / Workbench / 真实执行
      ↓ 深拷贝
Draft Template ─────────→ 模板详情编辑 / 当前编辑区只读预览
```

约束如下：

1. 详情编辑器只接触 `Draft Template`；
2. 草稿变化只在模板面板内部刷新摘要和预览，不发送全局 `template_changed`；
3. 显式保存成功后才生成新的 committed 深拷贝并发布一次；
4. 放弃修改时从 committed 深拷贝重建草稿；
5. Workbench、标题详情和方案面板不再拥有清除模板 dirty 的权限；
6. 真实执行始终读取 Bridge 中的 committed 模板。

核心实现位于 `src/ui/template_edit_session.py` 和 `src/ui/panels/template_panel.py`。

## 2. 交互规则（已修正）

旧实施把所有“离开”都当成事务终点，反而破坏了草稿暂存语义。最终规则是：

- 切换模板参数详情：直接切换，保留当前草稿；
- 切换主面板：直接切换，不保存、不放弃；
- 切换模板或工作模式：按 `mode_id + template_id + source_path` 暂存独立内存草稿，返回时恢复；
- Workbench 绑定和方案切换：不被模板草稿拦截，始终使用 Bridge 中的 committed 模板；
- 显式点击“保存”：写入当前 JSON，成功后才发布到 Bridge/Workbench/执行链；
- 重命名模板：只修改内存草稿和当前显示名称，不再顺带提交其他未保存样式；
- 关闭程序：如仍有草稿，仅此时统一提供“保存全部 / 放弃全部 / 取消”。

内置来源不再被当成强制只读条件。当前模板存在真实 JSON/YAML 路径时，主按钮统一为“保存”并原位写入；无路径时才以同一模板 ID 创建可持久化文件。“创建副本”是独立身份操作，不再替代保存。

## 3. 展示层只读化

修复了仅调用 `set_template()` 就改变模型的路径：

- 正文详情不再因展示而创建 `styles.body`；
- 页眉页脚和目录详情不再因展示而写入默认页码阶段；
- 表格详情只投影兼容的智能层级，不再原地规范化旧值；
- 参考文献详情只投影旧版字体字段，只有真实用户编辑时才执行升级；
- 页面、标题、题注、公式和其他详情继续保持只读同步。

默认值补齐与旧版迁移不得继续放入视图同步函数；视图打开前后模板必须深度相等。

## 4. 保存与冲突保护

保存链保持同目录临时文件加 `os.replace()` 的原子写入。新增源文件版本记录：加载或保存模板时记录路径、大小、纳秒 mtime 和 SHA-256。保存前若发现同一源文件已被外部修改，默认阻止覆盖并要求用户明确确认。

原位保存继续使用当前逻辑模板 ID，不再从文件名反推并改写 ID。多草稿“保存全部”在写盘前完成目标路径去重、草稿缓存碰撞和外部版本预检；所有内容先写入同目录 staging 文件，再统一替换目标。正常运行时任一目标提交失败会恢复本批次原文件，并且不会提前把任何 Session 标为 committed。

版本预检还区分“确实不存在”和“路径存在但不是可读取常规文件”。编辑开始后被外部新建的目标必须确认覆盖；准备完成后再次变化会在批量写入前中止；序列化失败产生的 staging 半成品也会在 finally 阶段清理。

如果编辑中的外部源文件被删除：

- 不再自动切换默认模板；
- 保留当前草稿；
- 明确提示点击“保存”可在原路径重建文件，仍保留外部变化确认。

## 6. 回归验证

新增或更正的核心验收包括：

1. 草稿与 committed 模板不是同一对象；
2. 编辑后模板 dirty 为真，但 Bridge 和 Workbench 值不变；
3. 保存后磁盘、Bridge、Workbench 同时更新并清除 dirty；
4. 详情、面板、模板和工作模式切换不弹出保存决策，返回后草稿仍在；
5. 打开全部模板详情不会改变输入模型；
6. 后台预加载标题、页眉页脚和目录不会制造草稿变化；
7. 外部文件变化时保存被拦截，草稿和外部文件均得到保留；
8. 主面板和工作模式切换不保存草稿；程序关闭尊重保存全部/放弃全部/取消结果；
9. 标题恢复、保存和最终 DOCX 排版链继续有效；
10. 预览投影及整体预览交互没有因事务隔离退化。
11. 原位保存保持逻辑模板 ID；同路径别名不会制造重复草稿或覆盖缓存。
12. 重命名不会写盘；批量保存失败会回滚全部目标并保留全部 dirty Session。
13. 外部新建目标必须确认，准备后再次变化会阻止提交，非文件目标与序列化半成品不会进入落盘链。

最终验证数据记录在《[模板草稿暂存与 JSON 显式保存语义修正记录](模板草稿暂存与JSON显式保存语义修正记录_2026-07-13.md)》，避免继续保留已被新语义取代的旧计数。

## 7. 最终语义

> 样式决定预览，但必须区分草稿样式和已保存样式。草稿只决定当前编辑区预览；已保存样式决定全局模板、Workbench 和真实执行。导航只切换上下文，保存才改写 JSON；预览始终只读，不决定样式，也不承担保存。

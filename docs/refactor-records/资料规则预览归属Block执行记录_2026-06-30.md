# 资料规则预览归属 Block 执行记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经把资料规则的选择、写回、未识别修复收进 `_MaterialRuleSelectorBlock`。但还有一个明显断点：

```text
资料规则操作在 block 里，资料规则预览仍由 _ContentDetail 顶部单独持有。
```

这会导致 block 只像“按钮和输入框集合”，还不像模板管理里的样式 block。模板管理的成熟体验不是只有控件，而是同一对象同时拥有：

```text
参数入口
当前状态
预览结果
诊断定位
```

所以本轮继续把“资料规则校验 / 资料规则名称 / 适用场景族 / 字段预览 / 图片签章 / 附件清单”这个预览摘要下沉到 `_MaterialRuleSelectorBlock`。

## 2. 改动前状态

`_ContentDetail` 原先直接创建：

```text
_schema_validation_summary = SummaryGrid(...)
```

并在两个入口刷新：

```text
set_scene(...)
_on_edited(...)
```

刷新方式是页面层直接调用：

```text
_schema_validation_summary.set_items(_build_material_schema_validation_items(scene))
```

这和上一轮抽出的 `_MaterialRuleSelectorBlock` 边界不一致。页面层仍知道“资料规则预览如何渲染”，block 只知道“资料规则如何编辑”。

## 3. 本轮实现

### 3.1 Block 持有预览 SummaryGrid

`_MaterialRuleSelectorBlock` 新增：

```text
_preview_summary = SummaryGrid(columns=3)
preview_summary
refresh_preview(scene)
```

现在资料规则相关的预览由 block 持有，`_ContentDetail` 只把它加入卡片布局。

### 3.2 `_ContentDetail` 保留兼容别名

为了不打断现有测试和其他调用，仍保留：

```text
_schema_validation_summary
```

但它现在指向：

```text
_material_rule_selector.preview_summary
```

也就是说旧名字还在，真实归属已经变成 selector block。

### 3.3 刷新路径下沉

`_ContentDetail` 不再直接 set_items，而是调用：

```text
_material_rule_selector.refresh_preview(scene)
```

这样页面层不再关心资料规则预览的 SummaryGrid 如何构造和刷新。

## 4. 当前边界

本轮刻意没有把所有输入资料字段都塞进 block。

已经属于 block：

- 资料规则选择；
- 主资料规则；
- 附加资料规则；
- 未识别规则修复；
- 资料规则校验摘要；
- 字段 / 图片 / 附件预览；
- 资料规则相关导航定位。

暂时仍属于 `_ContentDetail`：

- Markdown；
- LaTeX；
- 资料包必需；
- 必填字段输入；
- 资产角色输入；
- 失败策略；
- 水印。

这个边界是有意保守的。必填字段和资产角色会影响资料规则预览，但它们也是输入资料 profile 的 override，不完全等同于资料规则选择器本体。后续如果要继续收拢，应该先设计“资料要求 block”，再决定是否把这些 override 也纳入。

## 5. 与模板管理的一致性收益

这轮后，资料规则开始具备更像模板样式管理的对象结构：

| 模板管理样式对象 | 资料规则对象 |
| --- | --- |
| 样式字段编辑 | 主规则 / 附加规则编辑 |
| 来源与覆盖状态 | 资料规则校验状态 |
| 样式预览 | 字段 / 图片 / 附件预览 |
| 诊断跳转字段 | 资料规则 ID / 必填字段 / 资产角色定位 |
| block 语义 API | `_MaterialRuleSelectorBlock` |

这不代表输入资料页已经优秀，但它已经从“散落表单 + 顶部摘要”推进为“资料规则对象自己带预览”。

## 8. 仍需继续

下一轮更值得继续推进的是“预览内容可读性”，而不是单纯移动代码。

当前预览已经有：

```text
资料规则校验
资料规则
适用场景族
字段预览
图片/签章
附件清单
```

但它仍偏信息密集。后续建议增加一个更像模板管理预览的“首要状态行”：

```text
已识别 2 个资料规则
字段：5 个必填
资产：2 个签章角色
附件：无
```

并把英文 label、raw id、来源证据继续留在 tooltip。这样用户进入输入资料详情时，第一眼看到的是“这组规则会要求什么”，而不是必须逐个读格子。

## 9. 本轮结论

上一轮解决的是：

```text
资料规则操作散落在页面层。
```

本轮解决的是：

```text
资料规则预览散落在页面层。
```

现在资料规则选择器已经同时持有编辑入口、修复动作、预览摘要和导航定位。它还不是最终优秀设计，但已经具备继续独立成文件、继续复用到其他入口的结构基础。

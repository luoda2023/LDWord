# 动态功能导航卡与输出 Word 文案执行记录

日期：2026-06-30

## 1. 本轮目标

上一轮已经把固定导航卡副标题改成人话状态，但动态功能卡和输出详情仍有两类残留：

```text
表格格式·题注编号·图表居中·续表
Markdown修复·空白清洗·结构校验
最终 DOCX
对比 DOCX
```

这些表达都不是错误，但在当前产品语境里仍偏工程或文件格式视角。用户在场景规划页更需要知道“这里启用了吗、会不会生成 Word 文件”，而不是先理解具体模块清单或 DOCX 扩展名。

## 2. 本轮实现

### 2.1 动态功能卡副标题改成状态

动态卡原来直接使用 `group.description`：

```text
表格格式·题注编号·图表居中·续表
页眉·页脚·页码·目录·图表目录
Markdown修复·空白清洗·结构校验
```

现在改为：

```text
已启用 · 3 项设置
已跳过 · 3 项设置
```

具体模块清单仍在对应详情页，不塞进左侧导航卡。

### 2.2 输出详情控件从 DOCX 改为 Word

输出设置详情中的控件标签改为：

```text
最终 Word
对比 Word
```

内部字段仍保持：

```text
final_docx
compare_docx
```

真实文件扩展名和执行产物没有变化，只是用户可见文案更接近日常表达。

## 3. 边界判断

| 层级 | 使用什么表达 | 保留什么内部语义 |
| --- | --- | --- |
| 左侧导航卡 | 已启用 / 已跳过 / N 项设置 | 不展示模块清单 |
| 输出详情控件 | 最终 Word / 对比 Word | 字段名仍为 `final_docx` / `compare_docx` |
| 文件路径与产物 | `.docx` 扩展名 | 真实文件格式不改 |
| 高级证据/报告 | 可出现 DOCX 或内部 id | 用于审计，不进主控件文案 |

## 4. 代码落点

| 文件 | 变更 |
| --- | --- |
| `src/ui/panels/scene_panel.py` | 新增 `_nav_dynamic_group_subtitle(...)`；动态功能卡副标题改成状态；输出控件标签改为 Word |
| `tests/test_scene_panel_architecture.py` | 守住动态卡不再显示模块清单；守住输出表单标签为“最终 Word / 对比 Word” |

## 5. 当前效果

用户扫左侧导航时看到的是：

```text
表格与图表：已启用 · 3 项设置
校验与合规：已跳过 · 3 项设置
```

进入输出设置时看到的是：

```text
最终 Word
对比 Word
```

这和模板管理页的表达更接近：先说对象和状态，再进入详情改参数。

## 6. 后续继续推进

### P0：输入资料详情的 placeholder 仍有 schema 示例

例如：

```text
每行一个 schema，例如 signature_assets_v1
```

后续应改成：

```text
每行一个资料规则，例如签章资料
```

内部 id 可以保留在 tooltip 或高级证据中。

### P1：报告/样本高级证据继续区分“用户说明”和“审计证据”

高级证据区域仍需要保留 DOCX、manifest、fixture 等审计词，但可以进一步分成默认可读摘要和展开后的原始证据。

## 7. 本轮结论

这一轮把左侧动态导航和输出详情控件继续从工程词汇拉回用户任务语言：

- 动态功能卡只表达启用状态。
- 输出控件说 Word，而不是扩展名。
- 内部字段和文件格式保持稳定。

这让场景规划页更像一个可扫描的设置界面，而不是把实现细节散落在每个入口上。

# 输出版本模板说明与模板管理一致性执行记录

日期：2026-06-30

## 本轮结论

输出区的“套用模板”链路已经从一个裸下拉，收敛为和模板管理一致的“可读主文案 + tooltip 技术锚点 + 点击后生成业务对象”的交互模型。

本轮不再继续堆页面说明文字，而是把说明放进版本模板选项自身：主界面只显示“学生版、教师版、资料归档包”等人能理解的版本名；悬停时解释这个模板会新增什么交付版本、打开哪些输出内容、附带哪些内容块规则，并保留 `preset_id` 作为排查和兼容用的技术编号。

## 与模板管理的对齐点

模板管理页已经形成了三个稳定原则：

1. 主界面优先展示业务名，不把内部 ID 放在第一阅读层。
2. 来源、编号、字段路径这类技术锚点可以保留，但应下沉到 tooltip、详情或高级区。
3. 用户点击一个动作前，应能知道它改变什么对象，而不是只看到一个抽象按钮。

输出区之前的问题在于：

- 行标题叫“业务模板”，但实际动作是新增一个交付版本，概念边界偏虚。
- 下拉项只显示版本名，无法判断“套用模板”后会打开最终 Word、对比 Word、资料包，还是会增加内容块删除规则。
- `preset_id` 虽然被保留为数据值，但缺少对应的人话说明，导致用户无法建立“我选了什么”和“系统改了什么”的关系。

本轮调整后：

- 行标题改为“版本模板”，和“版本管理”保持同一对象边界。
- “套用模板”按钮说明为“按所选版本模板新增交付版本”。
- “应用推荐”按钮说明为“按当前场景类型补齐推荐交付版本”。
- 版本模板下拉项增加 tooltip，统一说明：新增交付版本、输出内容、内容块规则、模板编号。

## 链路是否打通

当前链路已经闭合：

1. 用户在“版本模板”里选择“学生版”等业务选项。
2. tooltip 告知套用后会新增哪个交付版本，并列出输出内容和内容块规则。
3. 点击“套用模板”后，系统用内部 `preset_id` 创建 `DeliveryPreset`。
4. 新交付版本写回 `scene.delivery_presets`，并同步为当前默认交付版本。
5. 输出摘要继续展示最终 Word、报告、资料清单、内容块规则等结果。
6. 技术值仍保留在数据层和 tooltip，便于定位，但不污染主阅读层。

这条链路和模板管理的“显示名在前，来源/编号在后”已经保持一致。

## 本轮实现

涉及文件：

- `src/ui/panels/scene_panel.py`
- `tests/test_scene_panel_architecture.py`

主要实现：

- 新增 `_DELIVERY_PRESET_TEMPLATE_ARTIFACTS`，把版本模板会开启的输出内容投影为中文标签。
- 新增 `_delivery_preset_template_artifact_labels()`，统一生成“最终 Word、报告 JSON、报告 Markdown、资料清单、资料包”等输出说明。
- 新增 `_delivery_preset_template_rule_summary()`，复用内容块 selector 的中文显示名，生成“答案：删除块；解析：删除块”这类用户能读懂的规则说明。
- 新增 `_delivery_preset_template_tooltip()`，把“新增交付版本 / 输出内容 / 内容块规则 / 模板编号”组成稳定说明。
- 新增 `_populate_delivery_preset_template_combo()`，替代普通 `_populate_combo()`，让这个下拉拥有专属的业务说明。
- 将输出区行标题从“业务模板”改为“版本模板”。

## 可读性边界

本轮刻意没有把说明写成页面上的大段常驻文本，原因是输出区本身已经承载了版本管理、交付名称、输出开关、命名规则、内容块规则等较多控件。常驻解释文字会继续放大噪音。

新的边界是：

- 主界面：只保留用户完成任务必须看到的词，例如“版本模板”“套用模板”“学生版”。
- tooltip：解释动作影响和内部编号。
- 高级区：放交付编号、目标模板、命名规则、报告策略等低频配置。
- 数据层：继续保留 `preset_id`、selector、action 等稳定字段。

这让界面更接近模板管理页的结构：用户先看到可操作对象，再按需展开来源和技术细节。

## 测试覆盖

新增/更新测试点：

- 输出区必须出现“版本模板”，不能再出现“业务模板”。
- 学生版模板主文本只能显示“学生版”，不能暴露 `student_version`。
- 学生版模板 tooltip 必须包含：
  - “新增交付版本：学生版”
  - “输出内容：最终 Word、报告 JSON、报告 Markdown”
  - “答案：删除块”
  - “解析：删除块”
  - “模板编号：student_version”
- 资料归档包模板 tooltip 必须包含资料清单、资料包、详细报告和 `material_archive` 编号。
- “套用模板”仍能创建学生版、重复学生版和资料归档包交付版本。

## 后续必要优化

仍然值得继续推进的点：

1. 版本模板定义目前仍在 `scene_panel.py` 内部。后续如果模板数量继续增加，应下沉为独立 registry，避免 UI 文件继续承担业务配置职责。
2. “版本模板”下拉已经有说明，但还没有可视化预览差异。后续可以考虑在不增加常驻文本的前提下，提供轻量详情区或右侧摘要，展示套用前后的输出开关差异。
3. “应用推荐”和“套用模板”现在边界更清晰，但推荐规则本身还可以继续结构化，和版本模板走同一套说明投影。
4. 内容块规则的主路径已经人话化，后续可以继续把高级区里的规则编辑器拆成更显式的“选择内容块 + 选择处理方式 + 添加规则”组合，进一步减少手写表达式。

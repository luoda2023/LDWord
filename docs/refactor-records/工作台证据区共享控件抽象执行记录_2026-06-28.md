# 工作台证据区共享控件抽象执行记录

日期：2026-06-28

## 本轮目标

上一轮已经把证据里的“参数路径 / 证据文件 / 输出路径 / 替换来源”投影成了可点击动作，但实现仍然偏工作台私有：按钮和证据文本都写在 `QuickExecutionDetail` 里。

本轮继续推进的目标是把它从“工作台里的一段逻辑”升级成“可被模板管理、场景管理、预检详情共同复用的证据控件模型”。

## 执行结论

已经完成第一层抽象：

- 新增 `EvidenceLineItem`：统一描述一条证据行。
- 新增 `EvidenceLineList`：统一展示结构化证据行。
- 新增 `EvidenceActionBar`：统一展示证据动作按钮。
- 工作台问题详情区已接入这两个共享控件。
- 原来的证据文本仍保留在隐藏 `body_label` 中，确保旧测试、旧读取路径和兼容逻辑不立刻断裂。

这意味着工作台证据区已经从“文本解释 + 私有按钮”进入“结构化证据列表 + 共享动作条”的形态。

## 功能边界

### 共享控件负责

- 证据行的结构化展示。
- 证据动作按钮的生成。
- 动作去重。
- 发出通用动作信号。
- 不理解业务问题类型。
- 不判断跳转到哪个面板。

### 工作台负责

- 从 `WorkbenchIssueItem` 提取证据。
- 把工作台证据行转换为 `EvidenceLineItem`。
- 把 `navigate_parameter` 映射为场景/模板/兜底路由。
- 把 `open_evidence` 等动作映射为本地文件打开。

这个边界比之前更清晰：共享层只做控件，业务层只做语义和路由。

## 与模板管理的一致性推进

模板管理已经有比较稳定的模式：

- 左侧选择对象。
- 中间展示参数摘要。
- 右侧或下方展示预览/动作。
- 控件由共享 UI 提供，不让每个面板私有实现一套。

本轮把工作台证据区往这个模式推进了一步：

- 证据从普通 QLabel 文本变成结构化行。
- 动作从工作台私有按钮变成共享动作条。
- 工作台不再直接拥有证据按钮布局细节。
- 后续模板预检、场景预检可以复用同一套 `EvidenceLineItem` 输入。

## 当前仍然不够好的地方

### 1. 证据行还没有分组

现在是线性证据列表。更优秀的形态应该能按类型分组：

- 参数
- 文件
- 来源
- 说明
- 输出

这样证据很多时不会变成一长串行。

### 2. 动作条还没有接入图标规范

共享动作条目前使用文字按钮，避免共享层反向依赖 `src.ui.icons`。如果要和模板管理的图标按钮完全一致，需要抽一个更底层的共享图标解析入口，不能让 `src.shared.ui` 直接依赖业务 UI 包。

### 3. 行内动作还没有启用

`EvidenceLineList` 已经预留 `show_inline_actions`，但工作台默认关闭，避免重复。未来如果进入更宽的详情页，可以开启行内动作，让每条证据右侧直接有对应操作。

### 4. 证据模型还没有进入适配器层

现在 `EvidenceLineItem` 的转换函数仍在工作台 UI 文件里。下一轮可以把转换前移到 adapter：

- `WorkbenchEvidenceLineProjection`
- `workbench_issue_evidence_lines(issue)`
- `workbench_issue_evidence_actions(issue)`

这样 UI 层只绑定控件，不再维护证据语义。

### 5. 模板预览与证据预览仍是两套模型

模板管理的“样式预览”处理的是格式效果，工作台证据控件处理的是问题证据。两者可以进一步统一到“可解释投影”模型：

- `projection.title`
- `projection.rows`
- `projection.actions`
- `projection.preview`
- `projection.navigation`

这会让模板管理、场景管理、工作台在结构上更一致。

## 后续建议

下一轮最值得做的是把证据语义从 UI 文件继续下沉：

1. 在 `workbench_execution_adapter` 中新增证据投影函数。
2. 让 `QuickExecutionDetail` 只调用 adapter，得到 `EvidenceLineItem` 或中间 projection。
3. 把 `IssueNavigationRegistry` 建起来，集中管理问题类型到面板卡片的路由。
4. 再考虑让模板预检和场景预检接入 `EvidenceLineList / EvidenceActionBar`。

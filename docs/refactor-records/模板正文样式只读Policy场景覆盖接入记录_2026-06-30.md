# 模板正文样式只读 Policy 场景覆盖接入记录

日期：2026-06-30

## 1. 本轮目标

上一轮把 `StyleManagementBlock` 的外层槽位语义从旧 `rules` 补成可巡检的 `policy`。本轮继续把这个语义落到模板管理真实页面。

目标不是一次性做完整“所有场景覆盖总览”，而是先打通一个真实、可验证、用户能理解的最小链路：

```text
当前场景
-> 模板正文样式页
-> 只读 policy 槽
-> 显示当前场景哪些分区使用独立样式，哪些仍跟随模板正文基线
```

这样模板管理不再只像孤立的基线编辑页，而能承认“场景分区会覆盖模板正文样式”这件事。

## 2. 为什么先做当前场景覆盖

审计结果：

| 数据源 | 当前可用性 | 结论 |
| --- | --- | --- |
| `PanelBridge.current_scene()` | 已存在，模板页也已用于筛选兼容模板 | 可直接承接当前场景上下文 |
| 全量场景列表 | `list_scene_descriptors()` 可列描述，但不一定带运行时覆盖状态 | 不适合直接冒充完整覆盖总览 |
| 场景分区样式 | `SceneWorkspace.section_styles` 是权威覆盖状态 | 当前场景覆盖可准确判断 |
| 分区启用状态 | `scene.format_scope.sections` 可判断分区是否启用 | 可控制 policy 行可见性 |

所以本轮选择先做“当前场景覆盖提示”，不做“所有场景覆盖总表”。这是为了避免在模板页展示弱证据。

## 3. 用户体验变化

### 修改前

模板正文样式页只有：

```text
source | scope | editor
```

用户能编辑模板正文基线，但看不到当前场景是否已经在某些分区中脱离模板。

### 修改后

模板正文样式页变成：

```text
source | scope | policy | editor
```

其中 `policy` 是只读的“场景覆盖”：

- 当前场景某分区有独立样式：对应行 checked。
- 当前场景某分区仍跟随模板：对应行 unchecked。
- 当前场景未启用某分区：对应行隐藏或不可作为重点展示。
- toggle 全部禁用，避免用户误以为能在模板页直接修改场景覆盖。
- 当前场景第一个独立样式分区会成为当前行。

## 4. 实现路径

### 4.1 Projection 下沉

新增：

```python
build_template_body_scene_policy_projection(scene)
```

它返回：

```text
StylePolicyProjection(kind="template_body_scene_policy")
```

每个 `STYLE_VARIANTS` 都被转换为一行只读 policy：

| 状态 | 判断 |
| --- | --- |
| checked | `variant.key in scene.section_styles` |
| visible | 当前场景存在，且分区启用或已经覆盖 |
| tooltip | 用普通语言说明“跟随模板 / 使用独立样式 / 未启用” |

### 4.2 模板正文 projection 带上 policy

`build_template_body_style_projection(...)` 新增 `scene=None` 参数，并把 policy 放进 `StyleObjectProjection`：

```python
StyleObjectProjection.from_owner_state(
    ...,
    policy=build_template_body_scene_policy_projection(scene),
)
```

这样模板正文页仍然只消费统一投影，不直接拼覆盖逻辑。

### 4.3 `StyleDetail` 接入只读 policy deck

模板正文样式详情新增：

```python
self._template_policy_deck = StylePolicyControlDeck(..., read_only=True)
```

并传入：

```python
StyleManagementBlock(..., rule_control=self._template_policy_deck)
```

虽然旧参数名仍是 `rule_control`，但上一轮已经为外层补了 `policy` 语义属性，所以该页面会报告：

```text
style_management_slot_plan = source|scope|policy|editor
style_management_has_policy = True
style_management_policy_control_ready = True
```

### 4.4 `TemplatePanel` 传入当前场景

模板面板新增统一同步：

```python
detail.set_scene(self.bridge.current_scene())
```

覆盖以下时机：

- 详情页初次加载。
- 模板刷新时。
- 场景切换时。

这保证模板页看到的只读 policy 与当前场景保持一致。

## 7. 剩余差距

### P0：全量场景覆盖总览仍未完成

当前只展示“当前场景”的覆盖关系。优秀设计里，模板管理还应该能回答：

```text
这个模板被哪些场景使用？
哪些场景覆盖了正文、参考文献、致谢等分区？
点击某个覆盖项能跳到对应场景分区样式。
```

这需要更强的数据源，不应只靠当前 scene。

### P0：只读 policy 行还没有跳转动作

现在 policy 行是只读状态反馈，还没有点击跳转到场景分区样式。后续可以复用上一轮的 `policy_selected`：

```text
Template StyleDetail policy_selected("references_body")
-> emit navigation intent
-> ScenePanel scn_scope/style rules
-> focus scene.section_styles.references_body
```

### P1：文案仍需统一中文短语

只读槽位标题是“场景覆盖”，比旧的 rules/schema 更可读，但最终还应与场景页“独立样式”文案统一：

```text
模板页：场景覆盖
场景页：独立样式
执行前复核：本次使用
```

这三者可以继续用 `StylePolicyProjection.title` 统一管理。

## 8. 本轮结论

模板管理现在开始承认场景覆盖关系：

- 不再只是编辑模板正文基线。
- 有当前场景时，会显示只读 policy 槽。
- 当前场景分区独立样式会被投影到模板页。
- 模板页和场景页开始共用 `StylePolicyControlDeck` 的真实视觉和状态协议。

这一步距离“优秀设计”仍不够，但它让模板管理、场景分区样式、执行前复核的同构链路又往前闭合了一块。

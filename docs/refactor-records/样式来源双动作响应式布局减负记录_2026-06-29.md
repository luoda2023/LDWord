# 样式来源双动作响应式布局减负记录（2026-06-29）

## 1. 本轮继续推进的问题

上一轮已经压缩了模板核对摘要，并让 Workbench 在全部分区跟随模板时隐藏 `调分区`。视觉审计结果变为：

```text
模板概览：50px
Workbench：50px
场景概览：98px
```

场景概览仍然偏高，根因不是文案，而是 `看模板 / 调分区` 两个按钮竖排。场景页确实需要双入口，但双入口不应该天然让首屏多占一倍高度。

## 2. 本轮执行

文件：

- `src/shared/ui/style_source_compact_row.py`

将 `StyleSourceCompactRow` 的动作区从固定竖排改为响应式 `QBoxLayout`：

```text
宽度 >= 760px：横排按钮
宽度 < 760px：竖排按钮
```

这样桌面窗口使用横排降低高度，窄屏仍回到竖排以避免横向滚动。

## 6. 当前判断

这轮把三入口的样式来源行在桌面尺寸下统一压到 50px。更重要的是，窄屏仍然允许按钮竖排，避免为了桌面密度牺牲移动/窄窗稳定性。

剩余风险：

- Qt offscreen 仍不能证明真实 Windows 中文字体。
- 760px 断点需要真实窗口继续验证。
- 如果未来按钮文案变长，横排动作区可能需要更细的宽度计算。

## 7. 下一步建议

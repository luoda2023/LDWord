# 场景概览核对依据入口减负执行记录（2026-06-29）

## 1. 本轮继续推进的问题

场景概览已经完成了几轮第一屏减负：

- `模板与样式 / 分区样式` 合并为 `样式来源`。
- `风险处理 / 人工确认` 合并为 `风险与确认`。
- `执行预览` 从长文本升级为步骤行。

继续审阅后，剩下一个偏工程化的入口：

```text
高级证据
覆盖范围、样本和请求证据。
```

这块对开发、审计、回归验收有价值，但“高级证据”这个词不像用户语言；折叠状态下还常驻一行解释，会继续占第一屏空间。

本轮把它改成：

```text
核对依据
```

并让说明文字只在展开后出现。

## 2. 设计判断

### 2.1 保留能力，不把它放回主流程

`scn_evidence` 仍然存在，路由 ID 不变。它仍然能：

- 展示场景覆盖摘要。
- 生成和查看样本文档。
- 查看请求样本。
- 打开请求样本对应的 DOCX 证据。

本轮只改变用户可见入口名称和折叠态密度，不删除开发核验能力。

### 2.2 名称改为用户能理解的“依据”

旧名称：

```text
高级证据
```

问题是它像内部审计分区。

新名称：

```text
核对依据
```

更接近用户会问的问题：为什么这个场景能这么判断？依据在哪里？

### 2.3 折叠态只留入口

旧折叠态仍展示：

```text
覆盖范围、样本和请求证据。
```

新折叠态只保留标题和 `展开` 按钮；展开后才显示：

```text
查看场景覆盖、样本文档和请求样本。
```

这样第一屏减少一行常驻解释，普通用户不必在主流程里读审计说明。

## 5. 当前限制

1. `核对依据` 仍然在主滚动流里，不是右侧抽屉。
2. 展开后的内容仍偏审计和开发核验，普通用户主流程不应依赖它。
3. 真实桌面截图仍需后续补充，确认折叠态高度、标题宽度和展开后中文换行。

## 6. 当前判断

本轮之后，概览页的主流程更干净：

- 用户先看任务、步骤、关键设置和风险。
- 需要追溯时再展开 `核对依据`。
- 开发核验能力仍保留，但不再用“高级证据”这种内部入口压在第一屏。

这一步继续推进“删除不必要的冗余文本描述”和“边界更清晰”的目标。

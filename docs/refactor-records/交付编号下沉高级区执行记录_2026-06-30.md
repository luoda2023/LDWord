# 交付编号下沉高级区执行记录 2026-06-30

## 本轮结论

输出设置主路径此前仍保留“交付 ID”输入框。虽然它对保存、命名和运行时引用很重要，但它不是普通用户配置交付版本时首先要理解的内容。

这和前几轮形成的规则不一致：

- 主路径显示业务名和业务动作。
- 内部 key、编号、变量和诊断信息下沉到高级区或 tooltip。
- 用户先选择“学生版 / 审阅稿 / 资料包”等业务版本，再在必要时编辑稳定编号。

本轮将“交付 ID”从输出主表单下沉到“高级命名与报告”折叠区，并改名为“交付编号”。

## 改动内容

### 主路径

保留：

- 默认交付
- 交付操作
- 业务模板
- 交付名称
- 最终 Word
- 对比 Word
- 资料清单
- 资料包

不再直接展示：

- 交付 ID

### 高级区

新增/保留：

- 交付编号
- 目标模板
- 模板选项
- 输出目录
- 文件命名
- 命名信息
- 添加内容块
- 内容块规则
- 报告 JSON
- 报告 Markdown

`交付编号` placeholder 改为：

```text
自动生成，可按需修改
```

`review_copy` 这类内部编号示例下沉到 tooltip。

### 导航

从执行问题或修复入口定位到 `preset_id` 时，输出页会自动展开高级区，并高亮“交付编号”字段。

同时将字段显示名从“交付方案 ID”改为“交付编号”，避免导航 tooltip 又把 ID 概念带回主提示。

## 边界保持

本轮没有改变：

- `DeliveryPreset.preset_id`
- `scene.default_delivery_preset_id`
- 新增、复制、删除、重排交付版本逻辑
- 文件命名变量 `{preset_id}`
- 执行侧 payload key

只改变控件归属、显示名、placeholder 和导航展开行为。

## 测试证据

新增/更新测试覆盖：

- 输出表单标签包含“交付编号”，不再包含“交付 ID”。
- `review_copy` 不出现在 placeholder，只保留在 tooltip。
- 导航到 `preset_id` 时自动展开高级区。
- 导航 tooltip 显示“交付编号”，raw `preset_id` 仍保留在控件属性中。

本轮目标：把上一轮剩余的“真实运行时诊断样本 -> navigation intent -> 具体控件高亮”继续往前推进。上一轮已经做到模板页和场景页能处理字段定位，但 Workbench 问题队列还没有把场景字段修复目标稳定建模，导致场景字段链路只能靠手写 intent 验证。

## 1. 本轮发现的问题

上一轮后已有能力：

```text
ScenePanel.handle_navigation_intent()
  -> card_id=scn_scope
  -> field_id=scene.section_styles.references_body.font_cn
  -> _ScopeDetail.focus_navigation_field()
  -> 具体开关/控件高亮
```

但 Workbench 侧 `_open_issue_repair_target()` 只稳定支持：

```text
template_style_field -> TemplatePanel
output_target -> ScenePanel 输出页
field/asset/schema -> AssetsPanel
```

缺少：

```text
scene_scope_field -> ScenePanel 处理范围
scene_style_field -> ScenePanel 样式覆盖
```

这意味着场景面板虽然会接字段，但运行时问题队列还不会把场景字段作为一等修复目标发出来。链路不算真正打通。

## 2. 本轮执行

### 2.1 Workbench 增加场景字段修复路由

修改：
- `src/ui/panels/workbench/panel_v2.py`

新增路由：

```text
scene_scope_field -> panel_id=scene, card_id=scn_scope
scene_style_field -> panel_id=scene, card_id=scn_scope
```

并保留原始字段路径为：

```text
field_id / payload.issue_key
```

代表性字段：

```text
format_scope.sections.references
scene.section_styles.references_body.font_cn
```

### 2.2 修复路由注册表增加场景字段 owner

修改：
- `src/config/scene_repair_routing.py`

新增 route：

```text
route_id: scene_field_repair
owner_layer: scene
repair_target_types:
  - scene_scope_field
  - scene_style_field
issue_categories:
  - scene_scope
  - scene_style
primary_surface:
  ScenePanel processing scope and style override detail
```

这个 route 明确了边界：

```text
模板默认样式问题 -> TemplatePanel
场景处理范围/样式覆盖问题 -> ScenePanel scn_scope
```

避免把场景级覆盖误送到模板默认样式页。

### 2.3 补真实跨面板链路测试

修改：
- `tests/test_scene_repair_routing.py`
- `tests/test_workbench_execution_session_architecture.py`

新增验证：

1. `scene_scope_field` 和 `scene_style_field` 能归入 `scene_field_repair` route。
2. Workbench 对 `scene_style_field` 发出的 intent 是：

```text
panel_id = scene
card_id = scn_scope
issue_id = scene_style_field
field_id = scene.section_styles.references_body.font_cn
return_panel_id = workbench
return_card_id = quick_execute
```

3. Workbench 对 `scene_scope_field` 发出的 intent 是：

```text
panel_id = scene
card_id = scn_scope
issue_id = scene_scope_field
field_id = format_scope.sections.references
```

4. 使用同一个 `PanelBridge` 连接 `WorkbenchPanel` 和 `ScenePanel` 后：

```text
WorkbenchPanel._open_issue_repair_target()
  -> bridge.navigate_to_intent
  -> ScenePanel.handle_navigation_intent()
  -> _ScopeDetail.focus_navigation_field()
```

能实际高亮：

```text
scene.section_styles.references_body.font_cn
  -> references_body 独立样式开关

format_scope.sections.references
  -> references 处理范围复选框
```

## 3. 链路状态

本轮后的链路：

```text
运行时问题队列 item
  -> repair_target_type / repair_target_key
  -> WorkbenchPanel._open_issue_repair_target()
  -> NavigationIntent(panel_id, card_id, field_id)
  -> ScenePanel.handle_navigation_intent()
  -> _ScopeDetail.focus_navigation_field()
  -> ParagraphStyleEditor.widget_for_field() 或 scope checkbox
  -> NavigationHighlighter.highlight()
```

现在场景字段不再只是页面内部能力，而是从 Workbench 修复入口能到达的能力。

## 5. 仍未完成的缺口

### 5.1 运行时 issue item 生成还未批量补样本

本轮打通的是 repair target 到 UI 的链路。还没有批量补齐“哪些运行时诊断会生成 `scene_scope_field` / `scene_style_field` issue item”。

后续应在 execution adapter 或诊断 issue item 生成层补代表性样本，例如：

```text
scene_scope_field:
  format_scope.sections.references

scene_style_field:
  scene.section_styles.references_body.font_cn
  scene.section_styles.*.line_spacing_pt
```

### 5.2 通配 section_styles 的业务落点仍需策略

`scene.section_styles.*.line_spacing_pt` 这类通配字段现在能被 `ParagraphStyleEditor` 归一，但场景页选择哪个分区仍取当前编辑分区。后续需要决定：

```text
通配字段是否默认跳到第一个已覆盖分区？
还是跳到样式覆盖摘要，并提示需要选择分区？
```

### 5.3 样式覆盖仍未导航级拆分

路由目前进入 `scn_scope`，再落到样式覆盖卡片。只要样式覆盖继续藏在处理范围详情里，用户路径仍是：

```text
处理范围 -> 样式覆盖
```

后续如果样式覆盖字段类 issue 增多，应把 `样式覆盖` 升为左侧导航入口。

## 6. 下一步建议

下一轮优先补运行时 issue item 生成层的代表性样本，让 `scene_scope_field` / `scene_style_field` 不只存在于手动路由测试里，而是真正能从诊断报告或执行问题队列产生。

## 1. 本轮已执行

### 1.1 扩展共享 editor 的使用方式

修改：

- `src/shared/ui/paragraph_style_editor.py`

`ParagraphStyleEditor` 新增 `build_layout` 参数：

- `build_layout=True`：editor 自带完整 `TemplateFormStack + template_form_pair_row` 布局，适合场景页直接挂载；
- `build_layout=False`：editor 只创建控件并提供同步/回写逻辑，不自带布局，适合模板页把控件放回既有三张卡片和 `InspectorForm` 中。

这个设计让共享 editor 不强迫所有页面采用同一外壳。它统一的是控件、字段、禁用态和读写逻辑；页面 owner 仍可决定自己的信息架构。

### 1.2 模板正文排版页接入共享 editor

修改：

- `src/ui/panels/template_style_detail.py`

`StyleDetail` 现在：

- 创建 `ParagraphStyleEditor(build_layout=False)`；
- 从 editor 取得 `font_cn`、`font_en`、`size_combo`、`bold_switch`、`italic_switch`、`alignment_combo`、`special_indent`、`left_indent`、`right_indent`、`line_type_combo`、`line_value`、`space_before`、`space_after`；
- 保留原来的三张卡片：文字样式、对齐与缩进、行距与段距；
- 保留原来的 `InspectorForm.add_grid()` 布局；
- 保留摘要卡、保存、恢复、snapshot、dirty state、导航高亮；
- 把 `_sync_from_template()` 委托给 `ParagraphStyleEditor.set_style()`；
- 把 `_on_form_edited()` 委托给 `ParagraphStyleEditor.apply_to_style()`。

也就是说，模板页现在是 owner shell：

```text
TemplateStyleDetail
  -> TemplateSummaryCard / 保存 / 恢复 / snapshot / summary
  -> ParagraphStyleEditor(build_layout=False)
    -> shared controls and StyleConfig read/write
  -> InspectorForm cards keep template page layout
```

### 1.3 场景页与模板页形成同源 editor

当前状态：

```text
TemplateStyleDetail
  -> ParagraphStyleEditor(build_layout=False)
  -> TemplateConfig.styles["body"]

ScenePanel._ScopeDetail
  -> ParagraphStyleEditor(build_layout=True)
  -> SceneWorkspace.section_styles[variant]
```

这实现了上一轮文档中定义的“一个样式编辑器，两个数据 owner”：

- 模板 owner：编辑默认正文格式；
- 场景 owner：编辑本场景分区覆盖；
- editor：共享控件、同步、回写、禁用态和 field map。

### 1.4 更新测试口径

修改：

- `tests/test_template_style_detail.py`

旧测试要求 `template_style_detail.py` 直接出现 `FontCombo/SizeCombo/SpacingInput/IndentInput/SpecialIndentInput`。这会把旧实现锁死。

新测试要求：

- `template_style_detail.py` 不直接构造段落样式底层控件；
- `paragraph_style_editor.py` 负责构造这些共享控件；
- 模板页仍保留 `InspectorForm`、三卡片布局、保存/恢复和摘要行为。

### 1.5 更新审计与修复路由证据

修改：

- `src/config/control_contract_registry.py`
- `src/config/scene_control_runtime_consistency_audit.py`
- `src/config/scene_repair_routing.py`

证据从旧 marker：

```text
template_style_detail.py: _font_cn = FontCombo
template_style_detail.py: _line_value = SpacingInput
template_style_detail.py: _special_indent = SpecialIndentInput
```

迁移为新事实：

```text

```

这样静态契约、运行时一致性审计、Workbench 修复路由都不再要求旧的复制实现存在。

## 4. 仍未完成

### 4.1 场景信息架构还没拆分

`_ScopeDetail` 仍然同时承担：

- 处理范围；
- 分区样式开关；
- 分区样式编辑。

虽然样式 editor 已共享，但信息架构仍应继续拆成：

- `ScopeDetail`：处理哪些区域；
- `StyleOverrideDetail`：哪些区域覆盖模板默认样式。

这一步才会进一步提升用户理解成本和边界清晰度。

### 4.2 场景详情页骨架还没有整体归一

本轮只处理了段落样式 editor。其他场景详情页仍大量使用 `_SimpleFormDetail + Card + SummaryGrid + template_form_row`，还没有系统迁移到类似模板管理的 summary card / `InspectorForm` / detail shell。

### 4.3 release gate 集成项仍未复验

上一轮记录中提到完整：

```text
python -m pytest tests/test_scene_control_runtime_consistency_audit.py -q
```

最后 release gate 集成项长时间无输出。本轮没有重新跑完整 release gate，只跑了前三个审计项并通过。

因此仍不能声明 release gate 集成项已验证通过。

## 5. 下一步建议

1. 拆分 `_ScopeDetail` 为“处理范围”和“样式覆盖”两个清晰板块。
2. 抽一个通用 `ConfigDetailShell` 或 `SceneDetailShell`，把场景详情页逐步迁移到和模板管理一致的详情骨架。
3. 给 `ParagraphStyleEditor` 增加更明确的 field-widget 查询接口，后续让模板页导航高亮和场景页问题定位共享同一套 field map。
4. 单独排查 release gate 集成项耗时或卡住原因。
5. 继续清理 `control_contract_registry` 中偏英文工程化的 `scene_surface/template_surface` 表达，但不要影响审计语义。

## 6. 本轮判断

这轮完成了前面多份规划中最关键的代码事实：模板管理和场景规划不再各自拥有一套段落样式控件实现。

现在的结构更合理：

- `ParagraphStyleEditor` 管“样式怎么编辑”；
- `TemplateStyleDetail` 管“模板正文默认样式怎么保存、恢复和预览”；
- `_ScopeDetail` 管“场景分区覆盖写到哪里”。

下一轮应从控件复用继续推进到信息架构复用：把场景里的“处理范围”和“样式覆盖”拆清楚。

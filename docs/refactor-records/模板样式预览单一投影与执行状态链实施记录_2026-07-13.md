# 模板样式预览单一投影与执行状态链实施记录（2026-07-13）

## 1. 实施结论

本轮已将模板样式预览从“可变模板 + 专用共享外壳 + 旁路方案开关”收敛为一条生产链：

```text
TemplateConfig + 当前 SceneWorkspace
  -> resolve_template_baseline() / resolve_config()
  -> build_module_selection_plan()
  -> build_template_overview_projection()
  -> TemplateOverviewDetail.apply_projection()
  -> TemplateStylePreview.set_projection()
  -> layout + paint
```

预览现在展示的是模板基线或当前方案的有效计划级结果，不再猜测某份输入文档的对象级跳过结果。运行时和预览共用同一个模块依赖裁剪算法。

## 2. 产品与交互结果

- 概览已移除放大按钮、点击激活、悬停卡片、tooltip 和弹窗入口。
- 预览标题区直接显示“模板基线”或“当前方案”，状态原因在正文中可见。
- 页面设置与分节整理是两行独立参与控制，不再用一个聚合开关覆盖两种状态。
- 参与控制使用可见标签、可见状态、标准复选框、Tab/Space 键盘行为和读屏描述。
- 当前方案请求开启但依赖不满足时，开关保持开启，并显示“依赖未满足”；不会把自动裁剪偷偷写回为关闭。
- 当前方案跳过某模块时，对应模板参数编辑器仍可编辑；模板 dirty 与方案 dirty 不混存。
- 没有当前方案时，参与控制完全隐藏，概览稳定显示模板基线。

关键显隐规则已落地：

| 状态 | 预览结果 |
| --- | --- |
| `page_setup` 关闭 | 保留中性白纸；隐藏纸型、页边距、装订线、页眉页脚距离引导 |
| `section_format` 关闭 | 只隐藏分节整理提示，不影响纸张设置 |
| `paragraph_style` 关闭 | 隐藏正文；若编号有效则保留中性标题编号示意 |
| `heading_numbering` 关闭 | 标题与目录保留，但不显示标题编号 |
| `heading_recognition` 关闭 | 标题编号和目录按同一模块计划自动裁剪，并显示依赖原因 |
| `table_format` 关闭 | 表格块消失并回收空间；题注可独立保留 |
| `header_footer` 关闭 | 页眉页脚内容及对应距离引导一起消失 |
| `toc` 关闭 | 目录块消失；模板内不再有第二个目录总开关 |
| `caption` 关闭 | 图题和表题一起消失 |
| 所有可预览模块关闭 | 中性白纸内显示明确空态，不留下空白大洞 |

## 3. 代码收敛

### 3.1 新的唯一语义基础

- `src/pipeline/module_selection.py`：不可变 `ModuleSelectionPlan`、requested/effective/auto-pruned 决策与唯一依赖闭包算法。
- `src/shared/engine/heading_numbering_format.py`：公共标题编号格式化与解析纯函数。
- `src/config/resolver.py`：显式 `resolve_template_baseline()`，不制造假场景。
- CLI、工作台执行、旧工作台入口和资料装配运行时均已切换到 `ModuleSelectionPlan`。
- 旧 `select_enabled_modules()` 已删除。

### 3.2 新预览包与概览协调器

- `template_feature_specs.py`：模板功能身份、详情卡、模块控制和预览块的单一静态注册表。
- `template_preview/model.py`：Qt-free frozen 投影合同。
- `template_preview/sample.py`：标题、正文、表格、目录和题注的共享语义样例。
- `template_preview/projector.py`：`ResolvedConfig + ModuleSelectionPlan -> TemplatePreviewProjection` 纯投影。
- `template_preview/layout.py`：横向比例、compact、第二页、宽屏并排和窄屏堆叠布局。
- `template_preview/widget.py`：只接收投影的非交互 QPainter 组件。
- `template_overview_detail.py`：选择器、参数摘要、可见模式/状态和直接预览外壳。
- `template_participation_controls.py`：逐模块、可见、可访问的当前方案参与控制。
- `template_navigation_context.py`：从单一注册表生成方案到模板的导航文案。

### 3.3 单一状态变化入口

`PanelBridge.update_current_scene_module_switches()` 使用 copy-on-write：

1. 无场景或无语义变化时不发信号；
2. 有变化时复制场景并更新 requested 状态；
3. 标记方案 dirty；
4. 只发一次 `scene_changed`。

`TemplatePanel` 只在初始化、`template_changed` 和 `scene_changed` 时进入 `_refresh_overview_projection()`。dirty-only 信号只更新保存按钮。实测一个模板编辑或一个模块切换都只增加一次投影刷新计数。

投影边界若发生解析异常，会记录异常日志并显示页内安全状态“预览暂不可用；模板参数仍可编辑”，不会让整个模板面板崩溃或把异常细节暴露给用户。

## 4. 配置与运行时清理

- 删除 `TocConfig.enabled`、模板详情“启用目录”控件和 `toc_cfg.enabled` 运行时二次判断。
- TOC 硬依赖改为 `heading_recognition`，标题编号仅作为软顺序；允许无编号标题生成目录。
- 删除场景中的 `table/header_footer/toc/caption/formula_table` 僵尸外观字段及不可达 resolver/migration 分支。
- 内置场景工厂中的表格偏好迁移到显式 `template_overrides`。
- 仓库场景、方案与模板 JSON 已一次性更新；没有留下迁移脚本、feature flag 或双读。
- 标题编号 adapter 绑定模板时不再补写默认方案；默认模板工厂或用户明确选择预设时才建立默认绑定。

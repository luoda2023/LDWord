# 场景概览样式来源合并与双跳转执行记录（2026-06-29）

## 1. 本轮继续推进的问题

前几轮已经把场景里的“分区样式”做成独立页面，并让它和模板管理共享样式管理控件。但概览页仍然残留一个信息架构问题：

```text
模板与样式
分区样式
```

这两行在工程边界上是清楚的，但在用户第一屏里仍然像两个并列功能点。用户真正关心的是“这次文档样式由谁决定”：模板基线是什么，当前场景有没有分区独立样式。

因此本轮把两行合并成一行：

```text
样式来源
```

并保留两个动作：

```text
看模板    调分区
```

这样第一屏少一行，但不会牺牲模板预览和分区样式编辑的入口。

## 2. 设计判断

### 2.1 不是把边界重新混在一起

本轮只合并概览表达，不合并业务页面。

| 层级 | 处理方式 |
| --- | --- |
| 概览页 | 合成一个“样式来源”用户任务 |
| 模板管理 | 仍负责全局模板基线 |
| 分区样式 | 仍负责当前场景的局部独立样式 |
| 导航 | 一行保留两个目标：`tpl_overview` 与 `scn_style_rules` |

这解决的是第一屏可读性，不改变功能边界。

### 2.2 摘要改成来源句

旧表达是两条摘要：

```text
使用“默认格式”；核对页面、正文、标题、表格、页眉页脚、目录、参考文献和题注
全部分区跟随模板
```

新表达合并为：

```text
模板：默认格式，核对页面、正文、标题、表格、页眉页脚、目录、参考文献和题注；分区：全部分区跟随模板
```

用户可以一眼知道：

- 模板基线是谁。
- 要核对模板的哪些样式面。
- 当前分区是否跟随模板。

### 2.3 双按钮不是并排挤压

第一次实现把 `看模板` 和 `调分区` 横向并排，620px 宽度下触发了水平滚动。测试暴露出这个问题后，本轮改成右侧动作列：

```text
看模板
调分区
```

摘要区域保持足够宽度，按钮仍然清楚。

## 5. 当前限制

1. `样式来源` 目前是单行摘要，不是展开式小组。它解决第一屏可读性，但还不是完整的分组控件。
2. `看模板 / 调分区` 仍是文字按钮。后续如果概览行动作继续增多，应考虑菜单化或图标按钮，但当前两个动作保持文字更容易理解。
3. 真实桌面环境仍需要补一轮截图验收，确认中文字体、按钮高度和 620px 以下窄宽度表现。

## 6. 当前结论

这一步把“模板管理”和“分区样式”的关系从两个并排入口，整理成一个用户能理解的来源判断：

```text
样式来源 = 模板基线 + 当前场景分区是否独立
```

功能边界没有混乱，第一屏却更短、更像人话。现在用户不需要先理解两个模块的工程分工，也能知道该看模板还是调分区。

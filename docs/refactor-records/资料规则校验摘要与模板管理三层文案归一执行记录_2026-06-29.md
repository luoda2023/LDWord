# 资料规则校验摘要与模板管理三层文案归一执行记录

日期：2026-06-29

## 本轮结论

上一轮已经把输入资料摘要和输出版本摘要改成“主文案说人话、内部 id 放证据层”。继续深挖后发现，输入资料详情里的“资料规则校验摘要”仍然没有完成同样的分层：它把 `Schema 校验`、`Schema 名称`、`Schema family`、英文 registry label、字段 key、素材 role key、`profile override`、`assets/...` 目录等直接放在主视图中。

这会造成两个体验问题：

1. 用户看不懂：主视图像配置文件审计结果，而不是“当前资料规则是否能用”。
2. 与模板管理不一致：模板管理的摘要控件只展示用户可读结论，技术证据留在 tooltip/回执/审计层；资料规则校验却把三层混在一起。

本轮将资料规则校验摘要也改为同一套三层表达：

- 主显示：资料规则校验、资料规则、适用场景族、字段预览、图片/签章、附件清单。
- 可见 detail：中文规则名和中文字段/角色名，例如“合同方字段资料”“合同编号（必填）”“资质证书（必填，图片 / PDF）”。
- tooltip：保留 `schema_id`、英文 registry label、字段 key、role key、来源、归档目录等技术证据。

## 与模板管理的一致性

本轮完成后，场景详情里的资料规则校验摘要与模板管理摘要控件形成同一套边界：

- 控件层：仍然只是 `SummaryGridItem`，不理解业务。
- 投影层：负责把 id/key/registry label 转译成用户可读名。
- 证据层：tooltip 保存 raw id 和审计上下文。

这和模板管理里的样式摘要、样式差异、样式回执一致：主界面只回答“现在是什么状态、用户该看什么”，不把实现字段直接暴露为说明文本。

## 仍需继续处理

1. 资料规则编辑输入框仍然需要用户输入精确 id，因此 placeholder 里保留了 `contract_parties_v1` 这种示例；后续可以通过更强的下拉/选择器减少手输。
2. 未知资料规则修复按钮 tooltip 仍显示 raw id，这是必要的定位证据，但按钮文案可继续优化成“替换未注册规则”。
3. 执行运行时和工作台里仍可能出现 `schema labels`、`assets/...` 等证据文本；下一步应检查执行报告/资料一致性报告的前台显示层。
4. 证据型卡片仍有 report id / fixture id 的主文案泄露风险，建议继续把 evidence builder 改成“用户结论 + tooltip 技术证据”模式。

# 场景样式覆盖恢复模板动作执行记录

日期：2026-06-28

## 1. 本轮继续推进的问题

上一轮已经新增 `SectionStyleOverrideProjection`，让场景样式覆盖能明确显示：

- 未处理
- 跟随模板
- 已覆盖 0 项
- 已覆盖 N 项

但界面仍有一个交互缺口：用户想放弃当前分区覆盖、回到模板样式时，只能通过关闭分区覆盖开关来完成。这个行为虽然技术上正确，但对用户不够直观。

用户看到“已覆盖 N 项”时，下一步自然需要一个动作：

```text
恢复模板
```

而不是让用户猜“关闭开关就是恢复模板”。

## 2. 设计判断

### 2.1 恢复模板不是重置字段

这轮没有把每个字段逐个改回模板值，而是删除当前分区的场景覆盖：

```text
remove scene.section_styles[variant_key]
```

原因是场景和模板的边界应该保持清晰：

- 模板管理负责默认样式和模板有效分区样式。
- 场景管理只负责是否在当前场景覆盖模板。
- 恢复模板就是撤销当前场景覆盖，而不是复制一份模板值继续保存成覆盖。

这样做还能避免“看起来恢复了模板，但实际上仍然有一份和模板相同的场景覆盖”这种伪恢复状态。

### 2.2 按钮必须跟随当前分区状态

按钮状态由当前分区的投影决定：

- 当前分区跟随模板：按钮禁用。
- 当前分区未处理：按钮禁用。
- 当前分区已覆盖 0 项：按钮启用。
- 当前分区已覆盖 N 项：按钮启用。

这保证按钮含义稳定：只要按钮可点，点击后都会让当前分区重新跟随模板。

## 3. 本轮实现

### 3.1 场景页新增“恢复模板”按钮

文件：`src/ui/panels/scene_panel.py`

在“编辑分区”同一行新增：

```text
恢复模板
```

按钮使用现有 `_apply_template_button_contract(..., "secondary")`，保持与场景页其他操作按钮一致。

### 3.2 新增恢复处理方法

文件：`src/ui/panels/scene_panel.py`

新增：

```python
_on_restore_selected_style_to_template()
```

逻辑：

```text
当前分区存在场景覆盖
  -> disable_section_style_override(scene, variant.key)
  -> 同步当前分区 toggle 为关闭
  -> 刷新 ParagraphStyleEditor
  -> 刷新样式覆盖摘要
  -> 发出 scope_changed
```

### 3.3 程序同步 ToggleSwitch 视觉状态

文件：`src/ui/panels/scene_panel.py`

新增：

```python
_set_variant_toggle_checked(...)
```

原因是 `ToggleSwitch.setChecked()` 只改变 checked 状态，不一定同步滑块位置。场景页在 `set_scene()`、关闭处理范围、恢复模板等程序化路径中都需要稳定同步开关状态和视觉位置。

### 3.4 主题刷新时重新套用按钮样式

文件：`src/ui/panels/scene_panel.py`

`_apply_theme()` 现在会对恢复按钮重新应用现有按钮样式契约，避免主题切换后按钮样式漂移。

## 4. 对用户理解的改进

本轮之后，场景样式覆盖的状态和动作形成闭环：

```text
跟随模板
  -> 开启覆盖
  -> 已覆盖 0 项 / 已覆盖 N 项
  -> 恢复模板
  -> 跟随模板
```

用户不需要理解 `scene.section_styles` 是否存在，也不需要知道关闭 toggle 的内部含义。界面直接给出动作。

这也继续强化前几轮确定的职责边界：

- 模板页：定义默认样式。
- 场景页：覆盖或恢复模板样式。
- 工作台：把问题带到对应设置位置。

## 6. 后续仍可继续推进

### 6.1 覆盖行的开关文案仍可进一步优化

当前行仍是“覆盖分区 + toggle”。后续可以考虑把每个分区行改成更明确的两态：

```text
参考文献    跟随模板 / 覆盖
```

但这会涉及行组件改造，本轮先用“恢复模板”动作补齐关键闭环。

### 6.2 仍缺轻量段落预览

当前用户能知道改了哪些字段，但还不能在场景页直接看到“改后长什么样”。下一步可以继续做：

```text
TemplateConfig + SceneSectionOverride
  -> 轻量段落预览投影
```

并在“样式覆盖”卡片里展示当前分区的一小段预览。

## 7. 结论

本轮把“恢复模板”从隐含在 toggle 里的副作用，提升为用户可见动作。它不是大改 UI，但它让场景覆盖的心智模型更完整：

```text
模板是基准，场景可以覆盖，覆盖可以随时撤销回模板。
```

这比继续增加解释文字更有效，因为用户看到的是可执行动作，而不是额外说明。

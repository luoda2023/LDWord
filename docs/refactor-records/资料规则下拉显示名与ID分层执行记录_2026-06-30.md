# 资料规则下拉显示名与 ID 分层执行记录

日期：2026-06-30

## 1. 本轮目标

资料要求 block 的主控件、占位和 tooltip 来源已经逐步人话化，但资料规则下拉列表仍有一个入口级残留：

```text
合同方字段资料 (contract_parties_v1)
签章资料 (signature_assets_v1)
```

这会把 schema id 放在用户选择动作的第一层。用户真正需要选择的是业务资料规则，不是内部 ID。因此本轮把下拉可见文本改成业务名称，ID 保留在 data 和 tooltip。

## 2. 本轮实现

`_populate_material_schema_combo(...)` 原来向下拉框写入：

```text
{资料规则显示名} ({schema_id})
```

现在改为：

```text
{资料规则显示名}
```

例如：

```text
合同方字段资料
签章资料
```

同时保留：

```text
itemData = schema_id
tooltip = 资料规则 ID / 英文名称 / 适用场景族
```

这样用户第一眼看到的是业务名称，诊断和测试仍能通过 `findData("contract_parties_v1")` 定位真实 ID。

## 3. 边界规则

| 层级 | 显示什么 |
| --- | --- |
| 下拉可见项 | 资料规则业务名称 |
| item data | `schema_id` |
| tooltip | 资料规则 ID、英文名称、适用场景族 |
| 输入框真实值 | 仍可显示 / 输入 `schema_id` |
| 诊断和执行证据 | 仍可使用 `schema_id` |

这不是隐藏内部 ID，而是避免把 ID 放在主选择路径上。

## 4. 代码落点

| 文件 | 变化 |
| --- | --- |
| `src/ui/panels/scene_panel.py` | `_populate_material_schema_combo(...)` 的可见项只显示 `material_schema_display_name(...)`，tooltip 保留 ID 和英文名称 |
| `tests/test_scene_panel_architecture.py` | 守住下拉 itemText 不包含 `contract_parties_v1`，tooltip 仍包含 ID 和英文名称 |

## 6. 仍需继续

这轮只处理了资料规则下拉的可见文本。后续还可以继续检查其他下拉：

- 交付版本下拉是否仍暴露 preset id；
- 变量插入下拉是否把变量名当主文案；
- 目标模板下拉是否把 template id 放在第一层。

如果这些下拉也存在“业务名 + 内部 id”混排，应按同一原则处理：

```text
主路径显示业务名
tooltip / data 保留真实 ID
```

## 7. 本轮结论

资料规则选择入口现在更像用户在选“资料规则”，而不是选 schema id。这个改动很小，但它补上了一个直接可见的割裂点，也和前面“主界面说人话、证据层保留 ID”的边界保持一致。

# 输出目标预检问题队列交付显示名归一执行记录

日期：2026-06-30

## 背景

上一轮《Workbench 最近结果交付显示名与日志链路归一执行记录》把最近结果、产物清单、执行历史日志和快速执行日志接到了交付显示名目录。但文档中仍留下一个明确断点：输出目标预检和问题队列还可能显示 `review 输出文件已存在` 这类 raw preset id。

这个断点比普通日志更影响体验，因为它出现在用户做决策的位置：是否覆盖文件、是否调整输出路径、是否继续执行。主文案如果继续讲 `review`，用户需要自己把技术 ID 翻译成“审阅稿”，交互就会重新变得“不说人话”。

## 本轮目标

把输出目标预检链路改成三层分工：

- 主文案：使用交付显示名，例如“审阅稿：输出文件已存在，将被覆盖”。
- 明细：去掉重复的版本前缀，只保留问题本身，例如“输出文件已存在，将被覆盖”。
- 追踪锚点：保留 raw preset id，例如 `repair_target_key == "review"`、source note 中的“交付版本 ID：review”。

这样用户先看到业务语义，系统仍能准确定位修复目标。

## 实现内容

### 1. Pipeline 源头使用显示名生成预检消息

文件：`src/pipeline/runner.py`

新增 `_output_target_display_label(item)`，优先使用 `OutputTargetPreflightItem.label`，否则回退到 `delivery_preset_display_name(...)`。

影响范围：

- duplicate target message
- target exists message
- target is directory message
- parent not writable message
- path too long / near limit message
- output target preflight tracker 的 `before` 文本

示例变化：

- 之前：`answer_key 输出文件已存在，将被覆盖`
- 现在：`答案版 输出文件已存在，将被覆盖`

### 2. Workbench 适配器兜底旧 payload

文件：`src/ui/adapters/workbench_execution_adapter.py`

`output_target_preflight_issue_items(...)` 现在通过 `_planned_output_preflight_items(...)` 取得四段信息：

- raw label：稳定目标，例如 `review`
- display label：用户显示，例如 `审阅稿`
- detail：去掉 raw/display 前缀的问题明细
- path：输出路径

关键处理：

- 旧 payload 中的 `review 输出文件已存在...` 会被清洗成 `输出文件已存在...`。
- 新 payload 中的 `审阅稿 输出文件已存在...` 也会被清洗成 `输出文件已存在...`。
- issue summary 统一生成 `审阅稿：输出文件已存在...`。
- source notes 增加 `交付版本 ID：review`，避免 raw id 从主文案消失后丢失追踪能力。

### 3. 最近结果产物预检明细同步受益

同一个 `_planned_output_preflight_items(...)` 也服务于 artifact detail：

- 产物卡片 label 已是“审阅稿”。
- detail 现在只显示“输出文件已存在...”，不再显示 `review 输出文件已存在...`。

这避免了“标题人话化、详情又掉回 raw id”的细小割裂。

## 边界说明

本轮没有改 raw key 的存储位置：

- `output_paths["review"]` 不变。
- `issue_id == "output_target.review.warning"` 不变。
- `repair_target_key == "review"` 不变。

这些值是路由和自动修复定位锚点，不能被显示名替换。归一只发生在用户主阅读路径：summary、details、日志、产物预检文案。

## 当前链路状态

交付版本显示名目前已覆盖：

- 场景/模板选择控件
- 模板预览与输出入口
- Workbench 可见交付版本下拉
- 运行时 `{preset_label}` 文件/目录模板
- delivery preset payload 的 raw/display 分层
- 最近结果与产物清单
- 执行历史日志与快速执行日志
- 输出目标预检与问题队列

剩余值得继续推进的是报告 Markdown 的读者态呈现：JSON/manifest 继续保留 raw key 是正确的，但 Markdown 报告面向人阅读，可以显式展示 display label，并把 raw id 降到“版本 ID”或调试信息。

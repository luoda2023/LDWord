# 输出应用推荐预读与版本模板一致性执行记录

日期：2026-06-30

## 本轮结论

上一轮已经把“版本模板 + 套用模板”做成了可理解入口，但旁边的“应用推荐”仍然是黑盒：用户只能看到一个按钮，无法提前知道它会新增哪些交付版本、会不会更新已有版本、默认选中哪个版本。

本轮把“应用推荐”补成可预读动作：按钮 tooltip 会基于当前场景类型生成推荐结果预览，点击前就能看到将新增/更新的版本、默认版本和版本 ID。这样它和“套用模板”保持了同一套边界：主界面短、tooltip 解释影响、数据 ID 留在技术层。

## 原问题

输出区当前有两个自动化入口：

- “套用模板”：选择一个版本模板后新增单个交付版本。
- “应用推荐”：按场景族一次性补齐推荐交付版本、资料规则、预检规则等。

前者经过上一轮已经可以说明“新增交付版本、输出内容、内容块规则、模板编号”。后者仍然只有一句“按当前场景类型补齐推荐交付版本”，这会带来两个体验问题：

1. 操作影响不透明。用户不知道点击后会生成“合同审阅稿、合同签署稿、字段一致性报告”，还是其它版本。
2. 概念边界不一致。同样是输出区的自动化动作，“套用模板”能预读，“应用推荐”却只能盲点。

## 本轮实现

涉及文件：

- `src/ui/panels/scene_panel.py`
- `tests/test_scene_panel_architecture.py`

新增实现：

- `_scene_family_delivery_preview_tooltip(scene)`：用当前场景的深拷贝 dry-run 一次 `apply_planned_scene_family_defaults()`，只读取推荐结果，不改变真实场景。
- `_delivery_preset_preview_label(scene, preset_id)`：从 dry-run 后的版本对象里取业务标签，避免把 `review_copy`、`signing_copy` 直接放到第一阅读层。
- `_compact_delivery_preview_labels()`：控制 tooltip 中的版本列表长度，避免推荐版本过多时说明过长。
- `_sync_preset_action_buttons()` 中动态刷新“应用推荐”按钮 tooltip。

当前 tooltip 结构为：

```text
按当前场景类型补齐推荐交付版本。
场景类型：合同交付
将新增：合同审阅稿、合同签署稿、字段一致性报告
默认版本：合同审阅稿
版本 ID：review_copy, signing_copy, field_consistency_report
```

## 一致性边界

本轮继续沿用模板管理页的三层信息模型：

1. 主界面只显示动作名：“应用推荐”。
2. tooltip 解释动作影响：“将新增/将更新/默认版本”。
3. 技术锚点保留在末尾：“版本 ID”。

这比在按钮旁边追加说明文字更合适。原因是输出区已经有“版本管理、版本模板、交付名称、输出开关、命名信息、内容块规则”等控件，常驻解释文字会增加扫描负担。tooltip 则让解释跟随动作本身，用户需要时才展开。

## 链路复核

当前链路已经更完整：

1. 用户进入输出区。
2. “版本模板”用于新增单个常见交付版本。
3. “应用推荐”用于按场景类型批量补齐交付版本。
4. 两个入口都能在点击前说明会生成什么。
5. 点击后仍走原有 `apply_planned_scene_family_defaults()`，真实业务规则没有被 UI 层重写。
6. 输出摘要继续负责展示当前默认版本和已开启的输出内容。

这说明输出区不再只是“参数堆叠”，而是在逐步形成清晰的动作边界。

## 测试覆盖

新增断言：

- 合同交付场景中，“应用推荐”按钮 tooltip 必须包含“场景类型：合同交付”。
- 点击前必须说明“将新增：合同审阅稿、合同签署稿、字段一致性报告”。
- 点击前必须说明“默认版本：合同审阅稿”。
- 技术编号必须保留在 tooltip 末尾：`review_copy, signing_copy, field_consistency_report`。
- 原有点击后创建推荐交付版本、资料规则和输出摘要的行为保持不变。

## 后续建议

1. “应用推荐”目前预读的是交付版本，后续可以继续扩展为资料规则、预检目标、合规配置的完整预览。
2. 场景族推荐规则仍散落在 `scene_family_application.py` 的各族函数里，后续可以抽出只读 projection API，让 UI 不必通过 dry-run 获取预览。
3. 输出区下一步最值得继续优化的是内容块规则编辑器，把手写 `answer=remove` 进一步收敛成“内容块 + 处理方式 + 添加规则”的组合控件。

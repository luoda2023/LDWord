# 样式控件与模板管理详情主文案归一执行记录

日期：2026-06-29

## 本轮结论

场景规划和模板管理已经有可复用的控件基础：`SummaryGridItem`、`SummaryGrid`、`StyleManagementBlock` 和样式差异/回执投影都可以跨模板管理、场景详情、执行中心复用。当前体验不够好的核心问题不在“缺控件”，而在“投影层没有统一分层”：用户主视图、辅助说明、审计证据混在一起，导致场景详情页仍把 `schema_id`、`preset_id`、字段 key、`preset artifact` 这类实现词直接展示给用户。

本轮将输入资料详情和输出版本详情改为与模板管理一致的三层表达：

1. 主显示：只放用户可读名称，例如“标书资料”“合同方字段资料”“客户版”“披露归档包”。
2. 辅助说明：解释当前选择的业务含义，例如“执行时默认生成”“由当前输出版本决定”。
3. tooltip/证据层：保留原始 `schema_id`、`preset_id`、注册表 label，用于审计、跳转、问题定位。

## 与模板管理的对齐点

模板管理的优秀部分是“组件复用 + 投影转译”：

- 控件层只渲染 `SummaryGridItem`/`StyleManagementBlock`，不理解业务 id。
- 模板或样式相关差异先转换成稳定投影，再交给控件。
- 用户看到的是样式、页面、正文、标题、表格等自然语言；技术字段只在证据、tooltip 或调试链路出现。

场景详情页应保持同一规则：

- 场景管流程、范围、风险策略，不直接解释模板样式细节。
- 模板管样式基线、样式预览和样式差异，不重复发明场景侧样式控件。
- 资料规则管输入字段和素材角色，场景只引用可读资料包名称。
- 输出版本管交付份数、产物、显隐规则，场景只显示“客户版/审阅稿/归档包”等版本语义。

## 本轮发现的断点

1. 输入详情主卡片仍显示 `bid_materials_v1`、`company_name`、`seal` 等内部键。
2. 输出详情主卡片仍显示 `formal_minutes`、`customer_copy`、`policy_collection` 等交付版本 id。
3. 默认产物详情写着 `preset artifact 驱动`，属于实现层措辞。
4. 资料规则注册表已经有字段和素材角色结构，但摘要投影没有统一转译。
5. 部分测试把“主文案必须出现 raw id”当成契约，反过来固化了不友好的界面。

## 当前边界

已经归一：

- 场景概览首屏主文案。
- 输入资料详情主文案。
- 输出版本详情主文案。
- 最近结果/执行中心样式复核块与模板管理的 `StyleManagementBlock` 复用。

仍应继续处理：

- `schema_validation_summary` 仍带有注册表英文 label、`profile override` 等技术证据词；它比主摘要更偏审计，但如果面向普通用户，也应做同样三层化。
- 证据卡片仍显示若干 report id、fixture id、rule id。当前保留原因是它们承担“链路是否打通”的审计证据，但后续可以拆成“用户结论 + 技术证据 tooltip”。
- `SummaryGrid` 目前没有公开 `tooltip_for(key)`，面板级测试只能通过投影对象检查 tooltip。若后续大量依赖 tooltip 契约，可以补一个只读查询方法。
- 样式管理相关 block 已经复用，但场景内“样式来源、样式差异、样式回执”的入口排序仍可以进一步收敛：场景页只做入口和结论，具体查看仍回模板管理/执行回执块。

## 推荐的下一步

1. 继续清理 `schema_validation_summary`：主视图改成“2 个资料规则通过 / 5 个字段 / 2 个图片角色”，英文 registry label 和 `profile override` 下沉 tooltip。
2. 给所有证据型卡片建立统一 `evidence_summary + evidence_tooltip` 投影，避免每个 evidence builder 自己拼接 raw id。
3. 把场景详情中的样式相关入口整理成三块：样式来源、样式差异、执行回执；每块都复用 `StyleManagementBlock` 的同一视觉和状态规范。
4. 在 `SummaryGrid` 上增加 `tooltip_for(key)` 测试辅助，减少控件测试为了查 tooltip 绕回投影层。

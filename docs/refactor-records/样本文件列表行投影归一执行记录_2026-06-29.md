# 样本文件列表行投影归一执行记录

日期：2026-06-29

## 1. 本轮结论

前一轮已经把请求说法列表行统一成 `SceneRequestCellListItemProjection`。继续审计后，样本文件列表还差同一层抽象：

- 场景页直接创建 `QListWidgetItem`。
- 可见文本调用 `scene_sample_fixture_display_name(...)`。
- tooltip 调用 `scene_sample_fixture_tooltip_text(...)`。
- `fixture_id` 手动写入 `Qt.UserRole`。

这虽然已经比早期 raw id 友好，但还不是完整的行投影。请求说法行已经有 `sample_id/text/tooltip`，样本文件行也应有 `fixture_id/text/tooltip`，这样后续抽 `SampleEvidenceBlock` 时，两类列表可以用同一种行模型。

## 2. 已落地调整

### 2.1 新增样本文件列表行 projection

文件：`src/ui/panels/scene_summary_projection.py`

新增：

- `SceneSampleFixtureListItemProjection`
- `scene_sample_fixture_list_item_projection(...)`

投影字段：

| 字段 | 用途 |
| --- | --- |
| `fixture_id` | 内部选择/打开文件路径，不做主文案 |
| `text` | 列表可见文本，例如“合同交付样本 1：正文片段 / 域 / 批注” |
| `tooltip` | 样本编号、资料包、场景族、Word 对象、检查重点、处理方式和边界 |

### 2.2 场景页接入

文件：`src/ui/panels/scene_panel.py`

调整：

- `_refresh_sample_fixture_list()` 改为消费 `scene_sample_fixture_list_item_projection(...)`。
- `QListWidgetItem.text` 来自 projection。
- `Qt.UserRole` 使用 projection 的 `fixture_id`。
- `tooltip` 来自 projection。
- 场景页不再直接调用样本显示名和样本 tooltip 函数。

## 4. 当前边界

已归一：

- 请求说法列表行 projection。
- 样本文件列表行 projection。
- 请求筛选、数量、空态、证据动作状态。
- 样本库、样本文件、样本目录动作状态。

仍需继续：

4. 评估 Workbench 是否也需要样本文件列表，而不仅是请求说法列表。

## 5. 设计判断

这轮是小步，但它让样本区两类列表的投影模型对齐：

```text
样本文件：fixture_id / text / tooltip
请求说法：sample_id / text / tooltip
```

这为后续抽真正的 `SampleEvidenceBlock` 提供了稳定输入。下一步如果重排 UI，就不需要再从两个列表里拆字符串，而是直接消费行 projection。

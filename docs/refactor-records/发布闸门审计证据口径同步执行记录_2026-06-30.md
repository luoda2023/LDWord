# 发布闸门审计证据口径同步执行记录

日期：2026-06-30

## 1. 背景

上一轮深度分析确认：场景规划与模板管理的样式控件已经有较多共享基础，但发布闸门仍按旧源码 marker 判断证据。例如 `scene_control_runtime_consistency_audit` 还在查找：

```text
template_form_row("中文字体"
template_form_row("英文字体"
template_form_row("字号"
```

而当前真实实现已经变成：

```text
style_field_descriptors.py 定义字段标签、控件属性和布局槽位
ParagraphStyleEditor 通过 style_field_layout_rows(...) 生成表单行
StyleControlSurface 通过共享 surface 给模板和场景复用
```

因此本轮目标不是降低发布闸门要求，而是把审计证据口径同步到当前共享抽象，让闸门继续验证真实链路。

## 2. 本轮修复范围

### 2.1 样式控件运行时审计

文件：

- `src/config/scene_control_runtime_consistency_audit.py`

调整点：

- 字体/字号、左右缩进、特殊缩进、行距、段距不再要求 `ParagraphStyleEditor` 内硬编码中文 label。
- 新增/替换为描述符证据：`STYLE_FIELD_LABELS`、`STYLE_FIELD_LAYOUT_SLOTS`、`STYLE_FIELD_CONTROL_CONTRACT_IDS`。
- 模板详情证据从 `ParagraphStyleEditor(` 直连改为 `StyleManagementBlock -> StyleControlSurface -> ParagraphStyleEditor`。
- 缩进、行距、段距的布局证据从旧的 `self._spacing_form.add_grid(...)` 改为 shared surface 和 descriptor 驱动。

## 4. 当前判断

本轮把发布闸门从“追旧源码字符串”推进到“追当前真实抽象”：

- 样式控件审计现在承认描述符驱动布局。
- 交付产物审计现在承认共享 artifact display helper。
- 输出目标和题图事务任务路由现在承认统一 issue navigation projection。
- 资料 schema 修复现在承认路由到场景资料区，而不是旧 Workbench 填充卡。
- 歧义澄清 UI 现在守住人话化文案，不再要求候选路由这类工程词出现在主 UI。

这使得后续继续重排场景页和抽业务 block 时，发布闸门可以跟着真实产品结构走，而不是把已经完成的抽象误判为缺证据。

## 5. 后续建议

下一步应继续做真正的产品结构重排，而不是只修审计：

1. 用 `StyleManagementContentPlan` 强制模板、场景、Workbench 三类样式页暴露同一套槽位。
2. 抽 `DeliveryVersionBlock`，把输出版本的主控件和高级命名/报告/显隐规则分层。
3. 抽 `MaterialRuleSelectorBlock`，把资料规则选择、未识别修复、规则预览从 `_ContentDetail` 中拆出来。
4. 继续清理主路径中的 `schema / preset / contract / payload / route` 等工程词。

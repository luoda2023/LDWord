本轮目标：解决 `scene.section_styles.*.*` 通配字段进入 ScenePanel 后落点不稳定的问题。上一轮已经能从运行时诊断生成 `scene_style_field`，但通配字段仍可能按当前下拉所选分区跳转，这会让用户觉得系统在“随机跳”。

## 1. 本轮发现的问题

当前已有链路：

```text
scene.section_styles.*.line_spacing_pt
  -> scene_style_field
  -> WorkbenchPanel
  -> ScenePanel.scn_scope
  -> _ScopeDetail.focus_navigation_field()
```

但旧逻辑中：

```text
* -> 当前编辑下拉里的分区
```

这有明显问题：

- 如果用户上次停在“附录”，诊断就会跳到附录；
- 但实际已有覆盖的可能是“参考文献”；
- 用户看到的跳转和问题来源不一致，会降低可信度。

## 2. 本轮执行

### 2.1 固化通配字段分区选择策略

修改：
- `src/ui/panels/scene_panel.py`

新增：

```text
_wildcard_style_variant()
```

通配字段现在按以下优先级选分区：

```text
1. 已开启处理范围，且已经开启独立样式覆盖的分区
2. 已开启处理范围的第一个分区
3. 已存在独立样式覆盖的分区
4. 当前编辑下拉所选分区
```

也就是说：

```text
scene.section_styles.*.line_spacing_pt
```

不再直接落到“当前下拉项”，而是优先落到最可能可编辑、最符合问题语义的分区。

### 2.2 保留未开启覆盖时的用户路径

如果通配字段选中的分区还没有开启独立样式，仍遵循上一轮规则：

```text
未开启覆盖 -> 高亮该分区的独立样式开关
已开启覆盖 -> 高亮具体样式控件
```

这让用户看到的链路是：

```text
系统发现某类分区样式问题
  -> 先告诉你要在哪个分区开启覆盖
  -> 开启后再编辑具体字体/行距
```

比直接跳到禁用控件更容易理解。

## 5. 仍未完成的缺口

### 5.1 通配字段仍缺摘要级落点

当前策略会落到一个具体分区。更理想的产品体验可能是：

```text
通配字段 -> 样式覆盖摘要
摘要提示：该问题影响多个分区，请选择要覆盖的分区
```

但这需要样式覆盖摘要支持可聚焦/可操作状态，不只是展示文本。

### 5.2 普通非批量 diagnostics 仍未结构化进入 issue queue

本轮继续沿用 batch/material diagnostics 链路。普通单文档执行的 diagnostics 仍主要作为摘要进入执行结果，不会自动变成可点击 issue item。

### 5.3 样式覆盖仍在 `scn_scope` 内

通配字段现在能稳定落点，但导航路径仍是：

```text
场景配置 -> 处理范围 -> 样式覆盖
```

如果后续样式类 issue 增多，`样式覆盖` 仍应考虑升级为左侧导航入口。

## 6. 下一步建议

下一轮可以在两个方向中选一个：

1. 给样式覆盖摘要增加可聚焦状态，让通配字段先落到摘要，再由用户选择具体分区。
2. 扩展普通非批量 diagnostics，使单文档执行问题也能进入结构化 issue queue。

# 样式 Owner 主提示短状态与只读原因下沉执行记录

日期：2026-06-30

## 1. 本轮目标

前几轮已经完成两件基础工作：

1. 场景分区样式区通过 `SceneStyleRulesBlock` 暴露对象级 API。
2. 未启用独立样式时，字段编辑区可以折叠，并且有 `style_management_editor_collapsed_by_readonly` 语义属性。

本轮继续处理用户最直接能感受到的问题：主界面提示文案仍然偏解释句，例如：

```text
参考文献：跟随模板。开启独立样式后可编辑。
```

这类文案把“对象是谁”“状态是什么”“为什么不能编辑”揉在一行里。对象其实已经由分区选择器、摘要、预览标题表达了，主提示不需要重复对象名。本轮目标是把主提示压成短状态，把详细原因下沉到只读原因属性。

## 2. 本轮代码调整

### 2.1 投影层主提示改为短状态

文件：`src/config/style_variant_semantics.py`

调整 `build_section_style_override_projection(...)` 的 `editor_hint`：

| 状态 | 旧主提示 | 新主提示 |
| --- | --- | --- |
| 跟随模板 | `参考文献：跟随模板。开启独立样式后可编辑。` | `跟随模板 · 开启独立样式后可编辑` |
| 已开启但未改字段 | `参考文献：已开启独立样式，与模板一致。` | `已开启独立样式 · 与模板一致` |
| 已调整字段 | `参考文献：正在编辑，不同：...。` | `正在编辑 · 不同：...` |

状态值、差异详情和预览来源不变。也就是说，信息没有丢，只是主阅读层不再重复分区名和完整解释句。

### 2.2 Owner fallback 也分离主提示与只读原因

文件：`src/shared/ui/style_owner_state.py`

调整 `scene_section_style_owner_state(...)`：

```text
hint = 主界面短状态
readonly_reason = 详细只读原因
```

跟随模板时：

```text
hint: 跟随模板 · 开启独立样式后可编辑
readonly_reason: 参考文献：跟随模板。开启独立样式后可编辑。
```

这样 owner toolbar 展示短状态，`StyleControlSurfaceState.readonly_reason` 仍保留完整原因，后续可用于 tooltip、诊断或审计详情。

## 3. 测试更新

文件：`tests/test_scene_panel_architecture.py`

新增/更新断言：

1. `scene_section_style_override_projection(...)` 跟随模板时，`editor_hint` 必须是短状态。
2. 启用独立样式但字段未变时，`editor_hint` 必须是短状态。
3. `scene_section_style_owner_state(...)` 跟随模板时，`hint` 不应包含 `参考文献：` 前缀。
4. 真实面板中 `_style_editor_hint.text()` 必须等于短状态。
5. `style_surface_readonly_reason` 仍保留完整详细原因。

这组测试锁住了主提示和详细原因的边界。

## 4. 对用户体验的意义

用户之前觉得“不说人话”，很大一部分来自主界面承担了太多解释职责。正确的信息层级应该是：

```text
主提示：现在是什么状态
摘要/预览：当前对象和效果是什么
差异区：改了哪些字段
tooltip/只读原因：为什么现在不能编辑
```

本轮之后，跟随模板状态不再在主提示里重复“参考文献：”。主提示只说：

```text
跟随模板 · 开启独立样式后可编辑
```

这比长句更像一个产品状态，也更适合和模板管理保持同一套语言。

## 5. 后续建议

### P0：继续压缩主界面的长解释

后续可以继续审计这些主界面文案：

```text
先在处理范围中启用「...」
正在编辑 · 不同：...
关闭当前分区的独立样式，重新跟随模板有效样式
全部分区跟随模板
```

原则是：主界面给短结论，详细原因进 tooltip、差异详情、审计报告。

### P1：建立主提示长度守门

可以给 style owner hint 增加静态或单元测试约束：

```text
主提示不重复当前对象名
主提示不超过一行常见长度
主提示不以完整解释句替代状态
```

这会进一步防止文案回到“配置面板说明书”风格。

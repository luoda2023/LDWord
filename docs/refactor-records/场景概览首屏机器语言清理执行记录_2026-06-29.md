# 场景概览首屏机器语言清理执行记录

日期：2026-06-29

## 本轮目标

上一轮已经把最近结果里的样式差异和回执统一进 `StyleManagementBlock(difference|receipt)`。这轮继续处理用户指出的核心体验问题：界面“很不说人话”。

本轮聚焦场景概览首屏的 SummaryGrid。截图中最刺眼的问题包括：

- `custom_basic`
- `quick_formatting`
- `Green/L5`
- `template 13 / scene 37 / material 6 / output 17`
- `custom_basic / manual / 提示`
- `quick_formatting: Quick Word formatting`
- `Bid strategy and certificate truthfulness remain outside core`
- `Original copy / Duplicate copy / Internal review`

这些内容本质上是工程证据、注册表 id 或产品成熟度审计语，而不是用户决策语言。

## 关键判断

首屏 summary tile 应该先回答用户问题：

| 用户问题 | 主界面应回答 |
| --- | --- |
| 这类文档能不能处理 | 适用场景、输入格式、风险策略 |
| 格式控件是不是一致 | 已统一，哪些大类已归一 |
| 参数归属是否清楚 | 模板、场景、资料、输出已分工 |
| 输出是什么 | 最终 Word、审阅稿、正式纪要、正本/副本 |
| 哪些事需要人工确认 | 不判断策略/真实性/法律有效性 |

首屏不应该直接展示：

- registry id
- fixture id
- preset id
- pack id
- owner count ledger
- Green/L5 这种内部成熟度等级
- 英文边界说明

## 剩余边界

本轮只处理“场景概览首屏 SummaryGrid”的主路径。仍未完全处理的区域：

1. 输入资料详情页仍显示 `bid_materials_v1`、`product_assets_v1` 等 schema id。
2. 输出详情页仍显示 `formal_minutes`、`archive_manifest` 等 preset id。
3. 证据卡 detail 仍显示 report id / fixture id，这是审计追溯需要，但后续可改成“可读名 + tooltip 内部 id”。
4. `P1 · 成熟度 L1/L2` 仍偏审计口径，后续可以改成“优先场景 · 正在深化”一类产品语言。

## 本轮结论

这轮把用户最容易看到的 SummaryGrid 从“技术账本”往“产品判断”推进了一步：

- 主界面说人话。
- tooltip 保留审计线索。
- 测试开始守住主界面不再漏出机器词。

下一轮最值得继续的是输出详情页和输入资料详情页：把 preset id / schema id 也做成同样的双层展示。

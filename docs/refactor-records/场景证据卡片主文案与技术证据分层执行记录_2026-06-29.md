# 场景证据卡片主文案与技术证据分层执行记录

日期：2026-06-29

## 本轮结论

前两轮已经把输入/输出摘要、资料规则校验摘要改成“主文案可读、技术 id 下沉”。继续审计后，场景概览里的证据卡片仍然是一个明显断点：它们虽然显示“已打通”，但 detail 中仍直接拼接 `schema_id`、`report_id`、`fixture_id`、`rule_source_id`、`delivery_preset_id`。

这让用户看到的不是“哪些能力已经有证据”，而是“内部注册表和测试样本编号”。它与模板管理的样式摘要不一致：模板管理主视图只给结论，技术证据放在 tooltip/回执/审计层。

本轮将所有场景证据卡片统一为：

- 可见 detail：资料规则中文名、输出版本中文名、报告/样本/规则来源数量、必要通道状态。
- tooltip：保留原始技术证据，包括资料规则 ID、报告 ID、规则来源 ID、样本 ID、输出版本 ID、界面入口 ID、风险域 ID、回执 ID。

## 当前效果

示例：

- 之前：`资料规则：contract_parties_v1 / 报告：contract_field_consistency_report / 样本：contract_delivery_signature_fields_degraded`
- 现在：`资料规则：合同方字段资料 / 签章资料 / 输出版本：字段一致性报告 / 最终 Word / 审阅稿 等 4 个 / 报告 1 项 / 样本 1 个`
- tooltip 保留：`资料规则 ID：contract_parties_v1 / signature_assets_v1 / 报告 ID：contract_field_consistency_report / ...`

这个模式与模板管理的设计一致：主界面回答“用户能理解的状态”，tooltip/证据层回答“工程上如何证明”。

## 仍需继续处理

1. 证据卡片的 tooltip 仍偏长，后续可以做成可展开的“证据明细”小面板，而不是完全依赖 tooltip。
2. `build_scene_sample_fixture_detail_text` 仍然包含样本 ID，这是更偏审计的明细文本；如果直接面向普通用户，还应继续做三层化。
3. `scene_matrix_drilldown` 仍有部分英文 source/drilldown 文案，属于更深的矩阵审计层，下一轮可以继续清理。
4. 工作台执行报告和运行时 material/schema 证据也需要同样审计，避免执行后又把 technical id 带回前台。

# 样式预览真实链路复用与控件边界执行记录

日期：2026-06-29

## 1. 本轮结论

本轮继续围绕“样式、控件规划没有和模板管理保持一致性与高度复用”进行深挖。结论是：

```text
之前已经有共享控件，但真实页面仍有绕开共享结构的入口。
最明显的是模板概览页的页面级样式预览：它直接创建 Card + TemplateStylePreview。
```

这会造成一个产品层问题：

```text
模板正文详情、场景分区样式已经使用 StyleManagementBlock。
模板概览里的样式预览却仍像一张独立普通卡片。
用户会看到相似内容，但代码和语义不是同一套。
```

本轮已把模板概览的页面级预览接入 `StyleManagementBlock` 的命名 `preview_slot`，并新增 `template_overview_preview` 内容计划。这样模板管理内部至少形成了三类清晰边界：

| 页面 | 共享模式 | 内容计划 | 用户心智 |
| --- | --- | --- | --- |
| 模板概览页样式预览 | `template_overview_preview` | `preview` | 看模板整体效果 |
| 模板正文排版详情 | `template_baseline_edit` | `source|scope|editor` | 编辑模板正文基线 |
| 场景分区样式详情 | `scene_section_rules` | `source|scope|rules|difference|editor|preview` | 管理场景对模板的覆盖 |

这一步不是视觉上的大改版，但它把“页面级预览也属于样式管理体系”落到了真实链路。

## 2. 发现的关键断点

### 2.1 共享 block 有槽位，但真实页面未使用

上一轮已经给 `StyleManagementBlock` 增加：

```text
preview_slot
receipt_slot
style_management_content_plan
```

但审计发现真实代码里：

```text
src/ui/panels/template_panel.py
  TemplateOverviewDetail 直接创建 Card 和 TemplateStylePreview

src/ui/panels/workbench/execution_center.py
  ExecutionCenter 直接创建 StyleResultReceiptRow

src/ui/panels/workbench/recent_run_panel.py
  RecentRunPanel 直接创建 StyleResultReceiptRow
```

这说明复用还停在 API 具备能力阶段，没有完全进入页面结构。

### 2.2 内容计划声明和实际控件不一致

`StyleManagementContentPlan` 已经存在 `editor=False` 的模式，例如 `readonly_review`。但之前 `StyleManagementBlock` 无论 content plan 是否包含 `editor`，都会创建并展示 `StyleEditingSection` 的编辑表单。

这会造成两个风险：

1. 只读复核类页面可能被动出现编辑控件。
2. 内容计划成为“文档标签”，而不是实际渲染契约。

本轮已修正为：

```text
content_plan.editor = False
  不把 StyleEditingSection 放入主布局
  隐藏 style_surface
  保留对象属性供测试和后续复核使用
```

这样 `editor=False` 才真正表示“不展示字段编辑区”。

### 2.3 空摘要网格会制造不必要占位

`DetailSummaryCard` 默认会创建 `SummaryGrid`。当 `StyleManagementBlock` 只用于预览槽位时，如果没有摘要项，空网格不应该占据视觉空间。

本轮已让 `DetailSummaryCard` 在没有摘要项时隐藏 `summary_grid`：

```text
无 summary_items：隐藏
有 summary_items：显示
再次置空：隐藏
```

这对删除冗余文本和多余空间很重要。否则“为了复用共享 block”会带来一个空的中间层，反而破坏页面可读性。

## 3. 本轮代码落点

### 3.1 新增模板概览预览模式

文件：

```text
src/shared/ui/style_management_block.py
```

新增模式：

```text
template_overview_preview
```

契约：

```text
owner toolbar：关闭
owner status：关闭
内置段落 preview：关闭
editor：关闭
preview_slot：开启
```

内容计划：

```text
preview
```

设计含义：

```text
模板概览页的样式预览只回答“这个模板整体长什么样”。
它不编辑字段，不解释来源，不重复展示范围，不塞入场景规则。
```

### 3.2 模板概览页接入 preview_slot

文件：

```text
src/ui/panels/template_panel.py
```

原结构：

```text
_preview_card = Card(...)
_preview_card.add_widget(header)
_preview_card.add_widget(desc)
_preview_card.add_widget(TemplateStylePreview)
```

新结构：

```text
_preview_slot = QWidget(...)
_preview_slot 内部放 desc + TemplateStylePreview

_preview_management_block = StyleManagementBlock(
    title="样式预览",
    icon_name="eye",
    mode="template_overview_preview",
    preview_slot=_preview_slot,
)
```

关键变化：

1. 页面级预览仍使用 `TemplateStylePreview`，不把页面预览强行改造成段落预览。
2. 承载结构进入 `StyleManagementBlock`，与模板正文详情和场景分区样式共享内容计划语言。
3. 预览描述仍来自 `StylePresentationEnvelope`，不是散落硬编码文案。

### 3.3 `editor=False` 真正隐藏编辑区

文件：

```text
src/shared/ui/style_management_block.py
```

新增行为：

```text
self._editor_enabled = bool(self._content_plan.editor)

if self._editor_enabled:
    layout.addWidget(self._editing_section)
else:
    self._editing_section.setVisible(False)
    self._editing_section.style_surface.setVisible(False)
```

这样只读或预览类 block 不会出现字段表单。

### 3.4 空摘要网格不再显示

文件：

```text
src/shared/ui/template_summary_card.py
```

新增行为：

```text
DetailSummaryCard 初始化时隐藏 summary_grid
set_summary_items(items) 时按 items 是否为空切换显示
```

这让 `StyleManagementBlock` 可以安全承载“只有预览槽位”的页面，不会产生空白摘要区。

## 4. 与模板管理的一致性提升

### 4.1 统一的是承载语法，不是把所有预览做成同一个控件

这点很重要。

模板概览的 `TemplateStylePreview` 是页面级预览，展示 A4、边距、页眉页脚、标题层级和正文排版在同一张纸上的效果。

场景分区样式的 `StylePreview` 是段落级预览，展示某个分区当前有效样式。

它们不应该合并为同一个 widget。真正需要统一的是外层语法：

```text
StyleManagementBlock
  content_plan
  preview_slot
  receipt_slot
  rule_control
  editor
```

本轮实现的是：

```text
页面级预览和段落级预览保留各自展示能力。
外层统一进入 StyleManagementBlock。
```

### 4.2 文字说明减少，结构说明增强

之前如果为了让用户理解页面，可能会加很多解释：

```text
这是样式预览，用于预览纸张比例、页边距、页眉页脚距离，以及标题层级和正文排版在同一页面中的效果。
```

这种文案会变长，也不一定更易懂。

本轮的方向是让结构替代冗余说明：

```text
卡片标题：样式预览
简短摘要：来自 StylePresentationEnvelope.summary
主体：真实页面预览
```

用户不需要知道内部模式叫 `template_overview_preview`。内部模式只用于保证工程一致性。

## 5. 当前链路状态

### 5.1 已打通

| 链路 | 当前状态 |
| --- | --- |
| 模板正文排版详情 | `StyleManagementBlock(mode="template_baseline_edit")` |
| 场景分区样式详情 | `StyleManagementBlock(mode="scene_section_rules")` |
| 模板概览页面级预览 | `StyleManagementBlock(mode="template_overview_preview", preview_slot=...)` |
| Workbench 执行中心样式回执 | `StyleManagementBlock(mode="execution_receipt_review", receipt_slot=StyleReceiptSlotFrame)` |
| Workbench 最近结果样式回执 | `StyleReceiptSlotFrame` |
| 内容计划属性 | `style_management_content_plan` 等属性可被测试读取 |
| legacy 自由插入 | `management_widgets` 已有守门，不允许业务代码继续使用 |
| 页面级预览摘要 | 继续来自 `StylePresentationEnvelope` |

### 5.2 尚未完全打通

| 链路 | 当前问题 | 建议下一步 |
| --- | --- | --- |
| 差异预览 | 场景详情有差异条，但没有统一回执式摘要 | 设计 `StyleDifferenceReceipt` 或 `StyleDifferenceSummarySlot` |
| 页面级预览与字段编辑联动 | 模板概览预览会刷新，但字段编辑页不在同屏反馈整体页面 | 后续可做“编辑后预览跳转”或侧栏预览 |

最近结果后续已通过 `StyleReceiptSlotFrame` 迁移，避免了 `RecentRunPanel(Card)` 内再嵌完整 `StyleManagementBlock` 的视觉层级问题。

## 8. 后续必要功能

### 8.1 Workbench 回执进入共享槽位

当前执行中心已经接入：

```text
execution_receipt_review = receipt
```

最近结果也已接入：

```text
StyleReceiptSlotFrame
```

后续不再把 Workbench 回执作为 P0 缺口，下一步应转向样式差异摘要。

### 8.2 差异摘要独立为可复用 slot

场景分区样式现在已经有规则、编辑和预览，但“相对模板改了什么”仍散在差异条和字段文案中。建议新增一个可复用的差异摘要组件：

```text
StyleDifferenceReceipt
```

它应该服务三个入口：

1. 场景分区样式详情：编辑时即时看差异。
2. Workbench 执行前：确认将应用哪些覆盖。
3. 执行报告：写入实际使用的样式覆盖。

### 8.3 页面文案继续删减

后续不应继续添加长解释，而应继续按下面原则收敛：

| 类型 | 保留位置 | 页面是否展示 |
| --- | --- | --- |
| 用户决策文案 | 当前页面 | 展示 |
| 内部策略 key | tooltip、报告、debug、测试 | 不直接展示 |
| 链路证据 | md 文档、测试、属性 | 不直接展示 |
| 长说明 | 文档或高级详情 | 默认不展示 |

## 9. 本轮判断

本轮把“模板概览样式预览”从孤立卡片推进到共享样式管理体系，是一条真实链路进展。它解决的是控件规划和模板管理不一致的一个明确断点。

但整体目标还没有结束。下一轮重点应该是：

```text
场景差异摘要形成可复用 slot。
继续删掉用户看不懂的内部策略文字。
```

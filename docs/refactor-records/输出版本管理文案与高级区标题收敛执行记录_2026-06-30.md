# 输出版本管理文案与高级区标题收敛执行记录 2026-06-30

## 本轮结论

上一轮已经把“交付 ID”下沉为高级区的“交付编号”，但输出设置主路径仍有两个不够顺口的点：

- “交付操作”像内部动作组，不像用户正在管理多个输出版本。
- “高级命名与报告”已经不准确，因为高级区现在还包含目标模板、内容块规则和报告开关。

本轮继续收敛输出页文案，使主路径更像“版本管理”，高级区更准确表达“命名、规则与报告”。

## 改动内容

### 主路径版本管理

原文案：

```text
交付操作
新增交付 / 复制当前 / 移除当前
```

新文案：

```text
版本管理
新增版本 / 复制版本 / 移除版本
```

`上移 / 下移` 保持不变，因为它们是清晰的排序动作。

### 业务模板动作

原按钮：

```text
添加模板
应用场景族推荐
```

新按钮：

```text
套用模板
应用推荐
```

原因：

- “添加模板”容易被理解成管理模板库，而这里实际是用业务模板新增交付版本。
- “场景族”属于内部规划概念，主按钮只需要表达“应用推荐”。

### 高级区标题

原标题：

```text
高级命名与报告
```

新标题：

```text
高级命名、规则与报告
```

这样能覆盖当前高级区真实内容：

- 交付编号
- 目标模板
- 输出目录
- 文件命名
- 命名信息
- 添加内容块
- 内容块规则
- 报告 JSON / Markdown

## 边界保持

本轮只改文案，不改变：

- 新增、复制、移除、上移、下移交付版本的逻辑。
- 业务模板生成 `DeliveryPreset` 的逻辑。
- 场景族推荐应用逻辑。
- 高级区折叠/展开行为。
- 按钮样式契约。

## 测试证据

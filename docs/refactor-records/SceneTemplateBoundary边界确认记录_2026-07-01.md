# Scene / Template 边界确认记录

日期：2026-07-01

## 1. 本轮目标

本轮不先改 UI，而是先确认程序边界，避免继续在场景页和模板页之间重复定义同一套文档结构。

用户提出的问题是准确的：

```text
模板里的章节规划已经定义了参考文献、致谢、附录、摘要、目录等结构。
场景里又出现处理范围，并再次列出这些区域。
这会让用户不知道到底谁说了算，也会让程序产生策略冲突。
```

本记录用于固定最终边界：模板、场景、运行时各自负责什么。

## 2. 当前代码事实

### 2.1 模板已经拥有文档结构定义

文件：`src/config/template.py`

`TemplateConfig` 包含：

- `heading_numbering`
- `heading_model`
- `section`
- `styles`
- `toc`
- `caption`
- `reference_style`

其中 `HeadingModelConfig` 已经定义了标题语义和特殊章节识别：

- `level_to_word_style`
- `style_alias_to_level`
- `max_heading_levels`
- `non_numbered_title_texts`
- `non_numbered_prefixes`
- `non_numbered_heading_style_name`
- `non_numbered_heading_style_mode`

这些字段已经能够表达：

- 什么是一级/二级/多级标题
- 哪些标题不编号
- 参考文献、致谢、摘要、目录等如何识别
- 附录/附件/Appendix 等前缀如何处理
- 标题和非编号标题使用什么样式

因此，模板侧已经是“文档结构和格式基线”的自然归属。

### 2.2 场景当前也拥有一套区域开关

文件：`src/config/scene.py`

`SceneWorkspace` 当前包含：

- `format_scope: FormatScopeConfig`
- `available_sections`
- `section_styles`

`FormatScopeConfig.sections` 目前硬编码了：

- `body`
- `references`
- `errata`
- `acknowledgment`
- `appendix`
- `abstract_cn`
- `abstract_en`
- `toc`
- `resume`

这组字段和模板的章节规划存在明显语义重叠。

如果继续把它作为“场景定义的文档章节”，就会形成第二套章节系统。

### 2.3 场景 UI 当前把两个概念混在一起

相关文件：

- `src/ui/panels/scene_scope_sections.py`
- `src/ui/panels/scene_style_override_sections.py`
- `src/ui/panels/scene_summary_projection.py`
- `src/ui/panels/scene_panel.py`

当前 UI 结构中：

- `处理范围` 显示 9 个区域开关。
- `分区样式` 显示区域级样式覆盖。
- `处理范围` 摘要里还提示“分区样式在独立页面设置”。

这会让用户误解为：

```text
场景也在定义章节。
模板也在定义章节。
分区样式又像第三套规则。
```

这不是合理的最终程序形态。

## 3. 最终边界定义

### 3.1 模板是文档结构的唯一来源

模板负责回答：

```text
文档有哪些结构？
这些结构如何识别？
默认格式是什么？
标题和非编号标题如何处理？
目录、参考文献、题注等格式规则是什么？
```

模板拥有：

- 章节/标题识别规则
- 标题编号规则
- 非编号标题规则
- 附录前缀规则
- 区域默认格式
- 页面、表格、页眉页脚、目录、题注、参考文献等格式基线

禁止在场景里新增另一套章节分类体系。

### 3.2 场景只表达任务意图和作用边界

场景负责回答：

```text
这类任务允许处理到什么程度？
使用哪个模板？
是否使用资料包？
是否启用某些处理模块？
是否存在格式例外？
输出什么结果？
```

场景不负责回答：

```text
什么是参考文献？
什么是附录？
什么是摘要？
目录算不算章节？
```

这些问题必须由模板的章节规划和运行时识别结果回答。

### 3.3 运行时负责把模板结构落到当前文档

运行时负责回答：

```text
当前文档实际识别出了哪些区域？
这些区域命中了哪个模板结构？
场景允许处理哪些命中区域？
有哪些高风险对象需要跳过、提醒或阻断？
```

推荐顺序：

```text
模板结构规划
-> 运行时识别当前文档区域
-> 场景作用边界过滤
-> 场景格式例外覆盖
-> 风险预检和执行策略
```

## 4. 现有字段的合理解释

### 4.1 `format_scope.sections`

当前存在，但不能继续被解释为“场景章节定义”。

过渡期合理解释：

```text
format_scope.sections 是历史兼容的处理门禁。
它只能表示“允许/不允许处理某个模板识别出的区域”。
它不能创建区域，也不能定义区域含义。
```

长期建议：

- UI 不直接展示这组硬编码 checkbox。
- 改为高级兼容数据，或迁移为 `application_boundary`。
- 区域标签必须来自模板结构或运行时识别结果，而不是场景硬编码。

### 4.2 `section_styles`

当前存在，合理边界是：

```text
section_styles 是格式例外，不是章节定义。
```

它只能表达：

- 某个模板识别出的区域是否脱离模板默认格式。
- 某个区域的局部格式覆盖。

它不能表达：

- 新增一个章节类型。
- 改变模板对章节的识别规则。
- 决定某个区域是否存在。

### 4.3 `available_sections`

当前存在，但最终不应成为用户可见的结构来源。

合理边界：

```text
available_sections 只能作为旧场景兼容或运行时候选过滤。
用户可见区域清单必须来自模板规划或当前文档识别结果。
```

## 5. UI 命名确认

### 5.1 不推荐继续使用

```text
处理范围
分区样式
范围影响
关闭区域会跳过内容
分区样式在独立页面设置
```

原因：

- “处理范围”容易被理解成章节定义。
- “分区样式”不说明和模板的关系。
- “范围影响”把处理门禁和格式例外混在一起。

### 5.2 推荐命名

场景概览中：

```text
资料包
套用模板
作用边界
格式例外
```

详情页中：

```text
作用边界
格式例外
```

推荐说明文案：

```text
章节识别来自当前模板；这里仅设置本场景允许处理到哪里。
```

格式例外说明：

```text
默认跟随模板；只有需要局部不同格式时才添加例外。
```

## 6. 合理的最终程序形态

### 6.1 场景概览

推荐显示：

```text
当前场景
  自定义

场景策略
  资料包：未开启
  套用模板：默认格式
  作用边界：跟随模板默认
  格式例外：无
```

其中：

- `套用模板` 指向模板。
- `作用边界` 不列出硬编码章节。
- `格式例外` 只显示是否有覆盖。

### 6.2 作用边界详情

推荐控件：

```text
作用边界
章节识别来自当前模板；这里仅设置本场景允许处理到哪里。

[跟随模板默认]
[仅正文]
[全文]
[执行前确认]
```

如果需要显示区域列表，只能作为只读预览：

```text
模板可识别区域：正文、参考文献、附录...
当前文档命中区域：正文、参考文献...
```

不能在这里重新定义这些区域。

### 6.3 格式例外详情

推荐控件：

```text
格式例外
默认全部跟随模板；只有需要局部不同格式时才添加例外。

当前：无格式例外
```

有例外时：

```text
参考文献：独立格式
附录：独立格式
```

这些例外必须绑定到模板识别出的结构，不得创建新结构。

## 7. 后续改造守门规则

后续代码改动必须遵守：

1. 不在场景 UI 中新增章节定义入口。
2. 不把 `format_scope.sections` 作为用户可见的章节规划来源。
3. 不让 `section_styles` 决定区域是否存在。
4. 模板结构优先于场景边界。
5. 场景只能过滤、约束、覆盖，不能重新定义文档结构。
6. 所有“正文、参考文献、附录、摘要、目录”等用户可见区域名称，最终必须来自模板规划或运行时识别投影。
7. 如果当前代码必须保留旧字段，应明确标注为兼容层，不作为新 UI 的主模型。

## 8. 最终确认

最终合理程序不是：

```text
模板定义章节规划。
场景再定义一套处理区域。
分区样式再绑定这套区域。
```

最终合理程序应是：

```text
模板定义结构和默认格式。
场景定义任务边界和格式例外。
运行时根据模板识别文档区域，再按场景边界执行。
```

当前程序已经具备一部分底层能力，但 UI 和字段命名仍有历史重叠。

因此结论是：

```text
现状不是最终合理形态。
以上边界是后续改造应确认的合理程序边界。
```

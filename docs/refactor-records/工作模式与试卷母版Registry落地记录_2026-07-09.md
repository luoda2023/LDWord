# 工作模式与试卷母版 Registry 落地记录

日期：2026-07-09

## 1. 本轮目标

按《工作模式与母版管理配置分层规划》和《试卷链路基准验收与母版视角补充》继续落地，优先执行低风险阶段：

- Phase E1：新增 `WorkModeSpec(exam)` 与工作模式 registry。
- Phase E2：新增 `MasterSpec`，先包装现有试卷母版，不迁移旧文件。
- Phase 2：`PanelBridge` 增加工作模式状态，但不改旧 scene/template 链路。
- Phase 3：标题栏增加工作模式下拉，只同步工作模式状态。
- Phase 3 后半：标题栏模式切换默认 scene/template，并增加 dirty 防护。
- Phase E3：新增试卷 mode-scoped manifest，只作为母版展示和契约增强。
- Phase E4：试卷运行时报告增加母版追溯证据。
- 公文版母版基线：新增内置 GB/T 9704 通用 DOCX 母版壳、母版 manifest 和文种 profile registry。
- Phase 6A：新增 registry-backed 母版管理页面，独立于 `TemplatePanel`。
- Phase 6B：接入试卷母版生命周期最小闭环。
- Phase 6C：抽取可复用母版 preflight 服务，并让 UI 与运行时 evidence 共用。
- Phase 6D：新增试卷母版样张视觉验收服务和 manifest。

本轮不做：

- 不改 `SceneWorkspace` 的语义。
- 不改 `TemplateConfig` 的语义。
- 初始阶段不改 resolver / pipeline；后续仅对 `official` pipeline 增加资料信号触发的公文母版装配 runtime，不改 resolver。
- 不移动 `exam_masters/`。
- 不在 dirty scene/template 存在时自动丢弃用户改动。
- 不把 manifest 作为试卷母版唯一事实源。
- 不改变学生卷 / 答案速查的输出路径和生成行为。
- 初始阶段不把公文内置母版接入现有 `official` runtime / pipeline；后续已完成后端 pipeline 低风险接入，并在母版页补入最小前台装配动作；完整公文装配页仍未完成。
- 不把母版管理页面替换成现有模板参数面板。
- 不把试卷母版页的导入、重命名、删除能力推广到公文、论文、标书。

## 2. 新增模块

### 2.1 `src/config/work_mode.py`

新增 `WorkModeSpec`，用于描述产品顶层工作模式。

当前内置模式：

- `custom`：通用版，保留现有默认行为。
- `exam`：试卷版。
- `thesis`：论文版。
- `bidding`：标书版。
- `official`：公文版。
- `technical`：技术文档版。
- `report`：报告版。

关键 API：

- `list_work_modes()`
- `get_work_mode(mode_id)`
- `default_work_mode()`
- `work_mode_for_scene_id(scene_id)`

设计边界：

- 工作模式只决定产品入口、默认 scene/template、可见母版域和资料 schema。
- 工作模式不替代 `SceneWorkspace`。
- 工作模式不替代 `TemplateConfig`。
- 默认工作模式仍为 `custom`，避免改变现有启动行为。

### 2.2 `src/config/master_library.py`

新增 `MasterSpec` 与 `PlaceholderContract`，并先对试卷母版做只读包装。

关键 API：

- `list_masters(mode_id, ...)`
- `get_master(master_id, mode_id=None, ...)`
- `default_master(mode_id, ...)`
- `list_exam_masters(...)`

当前只实现 `exam` 模式：

- `default_exam` 被包装为 `MasterSpec(mode_id="exam")`。
- `docx_path` 仍指向 `exam_masters/builtin/default_exam_v20.docx`。
- 用户母版继续通过现有 `ExamPaperConfig.custom_blank_styles` 和 `sync_user_exam_blank_master_files()` 识别。
- 手动放入用户目录的有效母版会被包装成 `source_type="discovered"`。

其他模式暂时返回空集合，直到它们有明确母版契约。

## 6. 标题栏工作模式下拉

`src/ui/title_bar.py` 新增 `titlebar_work_mode_combo`：

- 显示 `WorkModeSpec.label`，例如“通用版”“试卷版”“论文版”“标书版”“公文版”。
- 主窗口通过 `TitleBar(self, self._container, self.bridge)` 传入同一个 `PanelBridge`。
- `PanelBridge.work_mode_changed` 会同步标题栏下拉。
- 用户在标题栏选择模式时，会调用 `bridge.set_current_work_mode(mode_id)`。

当前边界：

- 标题栏切换工作模式会加载该模式的默认 scene/template。
- 如果当前 scene/template 是 dirty，会弹出“保存并切换 / 放弃更改 / 取消”的确认分支。
- 选择“保存并切换”时复用 `save_scene_to_library()` / `save_template_to_library()` 保存当前配置，保存成功后继续切换。
- 选择“放弃更改”时直接继续切换，并由目标模式默认配置清除 dirty 状态。
- 选择“取消”或保存失败时回退到原工作模式，不加载新 scene/template。
- 切换成功时会正常触发 `scene_changed` / `template_changed`，保持旧面板同步链路。

新增 `tests/test_title_bar_work_mode.py`，覆盖：

- Bridge 切换到 `exam` 后，标题栏显示“试卷版”。
- 标题栏选择 `official` 后，Bridge 当前工作模式变为 `official`。
- 单独实例化标题栏时，模式选择不会触发旧 scene/template 信号。
- 主窗口中标题栏选择 `official` 后，会加载 `official` scene 和 `official_gbt` builtin template。
- dirty scene/template 存在时，取消会回退到原模式，且不触发旧 scene/template 信号。
- dirty scene/template 存在时，放弃更改会继续切换并清除 dirty 状态。
- dirty scene/template 存在时，保存成功会先保存当前配置再继续切换。
- dirty scene/template 存在时，保存失败会回退到原模式并保留 dirty 状态。

## 7. 工作模式默认配置加载

`src/ui/main_window.py` 新增工作模式切换处理：

- 监听 `bridge.work_mode_changed`。
- 根据 `WorkModeSpec.default_scene_id` 加载默认 scene。
- 根据 `WorkModeSpec.default_template_id` 加载默认 template。
- 对 scene 绑定工作模式默认 template，确保如 `official -> official_gbt` 这种模式级默认模板不会被旧 library 归一逻辑压回 `default`。
- 成功后清除 scene/template dirty 状态。
- 失败时记录 warning 并回退到上一个工作模式。
- dirty 保存失败时不会吞掉用户修改，仍留在原工作模式并保留 dirty 状态。

当前 `official_gbt`、`bid_engineering` 等模板仍然不写入 `templates/` 目录，加载时走 `load_template_from_library()` 的 builtin fallback；这符合“不迁移旧模板文件”的边界。

## 11. 母版管理入口与试卷生命周期最小闭环

新增：

```text
src/ui/panels/masters_panel.py
tests/test_masters_panel.py
```

`MastersPanel` 当前定位为 registry-backed 母版入口：

- 从 `PanelBridge.current_work_mode_id()` 读取当前工作模式。
- 通过 `list_masters(mode_id)` 展示当前模式母版。
- `exam` 模式展示 `default_exam` 和对应 DOCX / manifest / 占位符契约。
- `exam` 模式会读取当前 scene 的 `ExamPaperConfig`，因此用户副本会进入母版列表。
- `official` 模式展示 `official_gbt_standard`，并明确标注为内置母版、DOCX 可用、runtime 装配尚未接入。
- `custom`、`thesis`、`bidding` 等未落地契约的模式显示空状态。

试卷模式已接入低风险生命周期动作：

- 设为当前：更新当前 scene 的 `exam_paper.blank_style_id`，并标记 scene dirty。
- 创建副本：调用现有 `create_exam_blank_master_copy()`，复制 DOCX 到用户母版目录，并把副本设为当前母版。
- 导入 DOCX：调用现有 `import_exam_blank_master_docx()`，复制外部 Word 文件到用户母版目录，并把导入件设为当前母版。
- 重命名：只允许 `user` / `imported` 试卷母版改名，不允许内置母版改名。
- 删除：只允许 `user` / `imported` 试卷母版删除，且仅删除位于用户母版目录内的文件；内置和手动发现母版不在这里删除。
- 打开 DOCX：打开当前母版对应的 Word 文件。
- 打开母版文件夹：打开 `exam_masters/user` 或测试替换后的用户母版目录。
- 生成样张：调用 `verify_exam_master_sample_visual()`，输出到 `output/exam_master_samples`，不混入母版本体目录。
- 占位符 preflight：当前展示 DOCX 可读性和必需占位符是否存在，后续再扩展成完整视觉验收。

导航接入：

- `src/ui/panel_registry.py` 新增 `PanelSpec(id="masters", title="母版管理", icon="layers")`。
- 新入口放在 `scene` 和 `template` 之间。
- `src/ui/icons/catalog.py` 新增 `SIDEBAR_ICONS["masters"] = "layers"`。
- `src/config/work_mode.py` 的默认 `visible_panels` 纳入 `masters`。

关键边界：

- `TemplatePanel` 保持原入口和原创建逻辑。
- `ScenePanel` 保持原入口和试卷装配卡片。
- 母版页面只在用户明确点击“设为当前”或“创建副本”时修改 `ExamPaperConfig.blank_style_id`。
- 母版页面不迁移 `exam_masters/` 和 `templates/`。
- 母版页面不把公文内置母版伪装成完整前台公文装配页；当前只提供文种选择、示例资料套用、当前资料生成样张和 preflight 状态。
- 公文、论文、标书暂不显示这些试卷专属动作。
- 导入、重命名、删除仅在试卷模式启用，且按母版来源限制权限。

新增测试覆盖：

- `masters` 被注册在 `scene` 与 `template` 之间。
- `create_panel("masters")` 返回 `MastersPanel`。
- `create_panel("template")` 仍返回 `TemplatePanel`。
- 通用版显示“还没有登记母版契约”的空状态。
- 切到试卷版后显示 `default_exam`、`af_title`、`af_questions` 和 DOCX 可用。
- 切到公文版后显示 `official_gbt_standard`、`内置母版`、`DOCX 可用` 和公文占位符契约。
- 创建试卷母版副本会写入临时用户母版目录、更新当前 scene、标记 dirty，并刷新出用户母版行。
- 设为当前会更新 `blank_style_id` 并标记 scene dirty。
- 生成试卷样张会写入生成物目录 `output/exam_master_samples`。
- 打开 DOCX 和打开母版文件夹使用正确路径。
- 导入试卷母版会复制临时外部 DOCX 到用户母版目录、更新当前 scene 并刷新列表。
- 重命名只修改当前 scene 中的用户母版记录。
- 删除只移除用户副本/导入件，并把当前母版回退到 `default_exam`。
- preflight 对默认试卷母版显示“通过”。

## 13. 试卷样张视觉验收服务

新增：

```text

```

该服务提供：

- `verify_exam_master_sample_visual(style_id, output_dir, config=None, attempt_render=True)`
- `ExamMasterVisualVerificationResult`
- `png_has_content(path)`

当前验收链路：

```text
试卷母版
  -> 生成样张 DOCX
  -> 写入 visual manifest
  -> 如果有 LibreOffice/Word COM：尝试 DOCX -> PDF
  -> 如果有 pdftoppm：尝试 PDF -> PNG
  -> PNG 做非空像素检查
```

manifest 记录：

- `sample_docx_path`
- `pdf_path`
- `png_paths`
- `renderer`
- `status`
- `issues`

状态边界：

- `visual_png_ok`：PDF/PNG 已生成，PNG 非空。
- `png_blank`：PNG 已生成但疑似空白。
- `renderer_unavailable`：没有可用 DOCX->PDF 渲染器。
- `pdf_render_failed` / `png_render_failed`：渲染链路失败。
- `docx_only`：显式跳过渲染，只生成 DOCX。

当前机器环境检查结果：

- `pdftoppm` 可用。
- `pywin32` 可用。
- 未直接发现 `WINWORD.EXE` 或 LibreOffice 命令。

因此这一步完成的是“视觉验收服务和证据 manifest”，而不是声称任意机器上都能固定产出 PDF/PNG。真实 PDF/PNG 产出依赖用户机器安装 Word 或 LibreOffice；不可用时 manifest 会明确记录降级状态。

`MastersPanel` 的“生成样张”按钮已改为调用该服务，并根据结果提示：

- 已生成样张和 PNG 预览。
- 已生成 DOCX，但视觉渲染器不可用。
- PNG 疑似空白。
- PDF/PNG 渲染失败状态。

新增测试覆盖：

- `attempt_render=False` 时写入 `docx_only` manifest。
- 渲染器不可用时写入 `renderer_unavailable` manifest。
- fake renderer + fake PNG 路径返回 `visual_png_ok`。
- 空白 PNG 会被 `png_has_content()` 拒绝。

# 附件包准备工作台落地记录

日期：2026-07-13

## 目标

将附件文件夹中大量 Token 的核对与填写，从附件卡片内逐行跳转，收敛为一个完整的双栏准备工作台。附件卡片只保留静态摘要和单一入口；字段值、时间方案、图片绑定仍由各自唯一的数据模型负责，不在附件内部复制第二份值或状态。

## 最终交互

- 附件卡片展示“文件数、Token 数、引用数、待准备数”，使用位置仅作静态信息，不悬浮、不点击。
- 点击“准备与检查”打开窗口级模态工作台。
- 左栏只按“字段填写、时间方案、源文件检查、生成检查”四个阶段导航；右栏是唯一处理区，不再重复 Token 概览。
- 直接字段按当前数据展示完整 Token 和行内输入；默认只看待填写项，多数据通过带缺项计数的选择器切换。
- 时间 Token 中已有数据表列的日期仍归直接字段；只有未创建且可计算的日期 Token 进入统一时间方案。
- 同一套时间方案一次应用到“本次生成”已勾选数据，不要求逐项目重复配置。
- “保存草稿”允许未就绪退出；“检查并完成”只在所有项目均可解析且源文件可读时完成。

## 状态与所有权

工作台不持有独立业务状态机，只投影以下事实：

| 对象 | 唯一事实来源 | 工作台职责 |
| --- | --- | --- |
| 字段是否存在 | `EntityProfile.declared_field_keys` | 区分“已创建但为空”和“尚未创建” |
| 文本/直接日期 | `EntityProfile.fields`、`field_aliases` | 按每条数据自己的字段键批量编辑并显示覆盖率 |
| 字段来源 | `EntityProfile.field_sources` | 只记录导入等来源，不再充当字段存在性标志 |
| 计算日期 | `EntityProfile.timeline_plans` | 编辑一套方案并同步到全部项目 |
| 图片 | 图片 Token 绑定及图片资料角色 | 显示是否已映射、是否已选择，不复制图片值 |
| 附件源文件 | `AttachmentBinding` 与扫描报告 | 展示 Token、引用位置和不可读文件 |
| 就绪状态 | 准备报告的纯计算结果 | 只读显示，不另行保存 |

结构“已映射”和数据“可生成”严格分开：例如图片 Token 已绑定到 `logo` 但尚未选择图片时，属于已映射、未就绪；空白 Excel 列属于已创建、待填写；完全不存在的字段属于未创建。

## 生成链路

1. 绑定附件文件夹后只扫描一次 DOCX Token，并聚合文件数和引用数。
2. 卡片和工作台使用同一份“本次生成”勾选范围，并将扫描结果分别投影到其中每个 `EntityProfile`。
3. 工作台的编辑写回 Profile 的字段或时间方案；附件包不保存附件专用副本。
4. 批量共享上下文只携带本次附件绑定；字段别名和时间方案由每个 Profile 自己携带，避免当前编辑项污染其他数据。
5. 每个项目生成前继续使用现有预检；未解析 Token 或不可读文件会阻止“检查并完成”。

## 真实 ISO 样本验证

样本：`tests/TEST-1/py版 优选/ISO一键生成`。

- 18 条项目数据
- 6 个 Word 模板
- 41 个唯一 Token
- 114 处引用
- 30 个直接字段列
- 11 个待统一配置的时间 Token

这 41 个 Token 不再形成 41 次独立跳转，而是收敛为直接字段批量编辑与一个统一时间方案。空白 Excel 表头会作为已声明字段保留，因此能区分“字段存在但没值”和“字段尚未创建”。

## 关键实现

- `src/services/material_attachments/requirements.py`：Token 扫描和逐 Profile 类型化投影，统一状态、下一动作与资料所有者。
- `src/services/material_attachments/preparation.py`：无 UI 状态的准备报告聚合，不保存第二套状态机。
- `src/services/material_attachments/timeline_preparation.py`：附件时间方案所有权、冲突检查和跨 Profile 原子应用。
- `src/shared/ui/workspace_dialog.py`：复用统一无边框窗口能力的工作台语义外壳。
- `src/ui/panels/assets/attachment_preparation_dialog.py`：准备会话、四阶段路由和提交边界。
- `src/ui/panels/assets/attachment_preparation_views.py`：阶段页面与稳定键行组件。
- `src/ui/panels/assets/attachment_preparation_style.py`：工作台主题投影，不承接业务逻辑。
- `src/ui/panels/assets/attachment_preparation_session.py`：隔离草稿、字段写入、导入策略和报告刷新事务。
- `src/ui/panels/assets/attachment_preparation_presenter.py`：统一勾选范围、草稿回写与选择保持。
- `src/ui/panels/assets/attachment_preparation_summary.py`：只读静态摘要与唯一入口，不暴露逐行任务 API。
- `src/ui/panels/assets/batch_import.py`：保留空白导入列的声明信息。
- `src/ui/panels/assets/batch_output_presenter.py`：批量生成上下文携带附件绑定和时间方案。

## 回归边界

覆盖直接时间字段与计算节点区分、空白 Excel 列保留、逐 Profile 别名字段写入、逐 Profile 图片就绪、资料所有权冲突、勾选范围与弹窗一致、未勾选项不被提交、主时间方案与附件时间方案隔离、导入不继承无关资料域、共享附件绑定优先级、真实 ISO 数量级，以及独立附件与附件文件夹原有绑定/导出/生成链路。

## 2026-07-13 收口修复

本轮针对审阅中发现的重复所有权和范围漂移完成以下修正：

1. 卡片、弹窗、批量生成统一以勾选数据为范围；没有勾选项时不再默认为当前项或全部项。
2. 聚合需求不再保存会被后一个 Profile 覆盖的单一 `resource_key`，而是每条 Profile 保存自己的映射键；不同别名可以在同一列正确写回。
3. 图片值由每条 Profile 自己的图片资料解析，不再从当前编辑项生成一份全局图片状态。
4. `@time` 仅表达值类型；普通日期缺失时创建字段，只有 `节点_...`、`时间节点1-1` 这类明确节点契约进入时间方案。
5. 附件时间方案使用 `attachment_workbench_equal` 所有权标记。主时间编辑器忽略并原样保留该方案；若普通时间方案已经占用同一输出字段，工作台明确报冲突而不覆盖。
6. 准备工作台导入表格时只继承附件处理所需的别名、相关图片角色、附件自有时间方案和当前附件绑定；不再复制内容资料、无关图片角色等整套 Profile 域。
7. 字段声明、字段值、字段来源分为三个事实：`declared_field_keys`、`fields`、`field_sources`。工作台创建空字段不会伪造为“导入来源”。
8. 删除旧逐行摘要组件及其 `row_count/requirement` 等死 API；卡片只接收同一份类型化准备报告。

## 2026-07-13 视觉与任务流二次收敛

首次工作台仍把 41 个 Token 同时放进左侧“准备事项”和右侧“准备概览”，虽然数据正确，但形成了重复导航、只读表格和不明确的左右关系。本轮只重构视图与交互编排，`AttachmentPreparationSession`、类型化需求投影和生成链不变。

最终结构收敛为四个阶段：

1. `字段填写`：右侧一次展示当前数据需要处理的字段；默认只看待填写项，可切换数据记录并直接在行内编辑。下拉数据项显示各自剩余缺项，避免用户逐条试探。
2. `时间方案`：所有计算型时间 Token 合并为一套“开始字段 + 结束字段 → 比例节点”规则，一次应用到本次生成范围。
3. `源文件检查`：只显示不可读文件、图片资料缺失、所有权冲突或错误 Token 等不能在前两阶段直接解决的问题。
4. `生成检查`：只汇总 Token 对应数、可生成数据数、输出文件数和替换位置，并按前三个阶段列出阻断原因。

交互和视觉约束如下：

- 左侧只保留四张阶段导航卡，不再出现单个 Token、审计分组或第二份概览清单。
- 窗口复用项目统一的无边框、圆角、可拖动和屏幕自适应外壳，不使用操作系统原生 Qt 标题栏。
- 字段和时间节点不再使用 `QTableWidget` 的原生选择态与委托编辑器，改用稳定键保留的行组件和项目内联输入控件。
- Token 始终完整展示，例如 `{{@text:项目名称}}`；字段页只把业务状态简化为“待填写/已填写”，底层仍保留 missing、empty、partial 等唯一状态事实。
- `6文件·12处` 只作静态文本，无点击、Tooltip 或悬浮详情。
- 当前 Profile 已提供数据，因此头部显示“当前 N 条数据”；只有用户主动导入后才显示数据表文件名，不再出现“尚未导入数据表”与页脚已有数据互相矛盾。
- 绑定成功和工作台保存成功由附件卡片的持久摘要确认，不再弹出会覆盖模态窗口的成功 Toast；预检失败等异常警告仍保留。
- 字段筛选、阶段计数、最终阻断项都直接从同一个 `AttachmentPreparationReport` 派生，没有新增 UI 状态机或附件专用字段副本。

新增的共享边界为 `src/shared/ui/workspace_dialog.py`，它只复用已有预览外壳的窗口能力，不复制标题栏实现；附件行控件集中在 `attachment_preparation_views.py`，对话框只负责会话编排、阶段路由和提交。

专项 Qt 回归为 `22 passed`。附件 intake、Token 扫描、替换、真实 ISO 样本、资料面板与批量上下文扩大回归为 `183 passed, 1 skipped`；唯一跳过项仍是当前 Windows 账户没有符号链接能力。扩大组合中的 3 个既有 helper 架构断言仍因旧归档、批量导入和映射对话框方法已删除而失败，本轮没有补回废弃接口。相关生产代码通过 `compileall`。

## 2026-07-13 用户审阅后的任务流收敛

用户审阅指出窗口默认宽度过大、内外层资料命名和图标不一致，并且独立“生成检查”页混合结构映射、数据就绪与静态产量，无法形成清晰的下一动作。最终继续收敛如下：

1. 默认窗口由 `1360×840` 调整为 `1100×760`，仍保留 `980×640` 最小尺寸和自由放大能力；左栏收窄为 236px。
2. 左栏和右侧页面统一使用外层资料域名称：`字段资料`、`时间计划`；图标统一为外层的 `type`、`chart-no-axes-gantt`。阶段编号从卡片标题移除，避免窄栏中标题和状态徽标互相挤压。
3. 独立“生成检查”阶段删除。其“重新检查”原本只刷新同一份 `AttachmentPreparationReport`，不执行文件试生成或额外校验，因此不再保留容易误解的操作表面。
4. 底部状态实时显示“可生成数据数、字段资料缺项、时间计划缺项、源文件问题”；不再并列展示语义不同的“Token 已对应”和“Token 已就绪”。
5. 未完成时主按钮定位到第一个真实阻断阶段；用户已在该阶段时按钮显示“请先完成”并禁用。全部数据就绪后按钮直接变为“完成准备”，不再强制经过已通过的源文件页或只读结果页。
6. 当前附件专项扩大回归为 `59 passed, 1 skipped`；跳过项仍为当前 Windows 账户不支持符号链接。真实 ISO 样本按 `1100×760` 渲染后，三张导航卡最小宽度均小于可用宽度，字段行在 786px 内容宽度下无横向溢出。

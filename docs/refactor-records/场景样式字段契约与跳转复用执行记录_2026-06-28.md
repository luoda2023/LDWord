本轮目标：继续把“场景样式覆盖”和“模板正文排版”的一致性从控件外观推进到字段契约。上一轮已经做到两边共用 `ParagraphStyleEditor`，但字段定位、修复跳转和高亮逻辑仍有 owner 各自维护的残留，这会让后续诊断问题很难稳定落到同一个控件。

## 1. 本轮发现的问题

### 1.1 控件复用了，但字段映射没有完全复用

上一轮之后：

```text
模板正文排版 -> ParagraphStyleEditor
场景样式覆盖 -> ParagraphStyleEditor
```

这解决了“字体、字号、缩进、行距控件长得不一样”的问题。

但模板页的 `StyleDetail.focus_navigation_field()` 仍自己维护一张 `body.* -> widget` 映射。共享编辑器内部也有类似逻辑。也就是说：

```text
控件实例：共享
字段定位：重复
```

这不是优秀设计。字段定位一旦重复，后续会出现三个风险：

1. 新增字段别名时只改了一处，模板页和场景页行为分叉。
2. 执行诊断报告中的字段路径可能能定位模板页，却不能定位场景页。
3. 用户看到的是同一个控件，但问题跳转行为不一致，会觉得系统“不说人话”。

### 1.2 场景样式覆盖没有字段级跳转

`ScenePanel._focus_navigation_field()` 已经支持把导航意图交给详情页，但 `_ScopeDetail` 之前没有 `focus_navigation_field()`。

结果是：即使诊断里有 `scene.section_styles.references_body.font_cn` 这种明确路径，场景页也只能到“处理范围 / 样式覆盖”这个大区域，不能进一步落到“参考文献独立样式”的开关或字体控件。

### 1.3 未开启覆盖时不能直接跳禁用控件

场景样式覆盖有一个关键产品边界：

```text
默认跟随模板
开启独立样式后才允许编辑
```

如果问题定位直接跳到禁用的字体控件，用户会困惑：为什么跳到这里却不能改。正确做法应该是：

```text
未开启覆盖 -> 定位到对应分区开关
已开启覆盖 -> 定位到具体样式控件
```

这比再写一段长说明更有效。

## 2. 本轮执行

### 2.1 共享编辑器接管字段契约

修改：
- `src/shared/ui/paragraph_style_editor.py`

新增：
- `STYLE_FIELD_WIDGET_ATTRS`
- `STYLE_FIELD_ALIASES`
- `canonical_paragraph_style_field_id(field_id)`
- `ParagraphStyleEditor.widget_for_field(field_id)`

现在共享编辑器能识别这些路径：

```text
body.font_name
template.styles.body.font_en
scene.section_styles.references_body.size_pt
section_styles.*.special_indent_value
body.space_after_unit
```

并归一到稳定字段：

```text
font_cn
font_en
size_pt
special_indent
space_after
```

归一规则属于共享编辑器，不再属于模板 owner 或场景 owner。

### 2.2 模板正文页删除重复字段映射

修改：
- `src/ui/panels/template_style_detail.py`

`StyleDetail.focus_navigation_field()` 不再维护局部 `mapping: dict[str, QWidget]`，改为：

```text
self._paragraph_style_editor.widget_for_field(target)
```

模板页现在只负责：
- 当前模板数据如何读写；
- 定位后如何高亮；
- 保存、恢复和摘要。

共享编辑器负责：
- 字段名如何归一；
- 字段落到哪个控件。

### 2.3 场景样式覆盖增加字段级跳转

修改：
- `src/ui/panels/scene_panel.py`

`_ScopeDetail` 新增：
- `focus_navigation_field(field_id)`
- `_style_navigation_target(field_id)`
- `_scope_zone_for_field(field_id)`
- `_highlight_navigation_widget(widget, label)`

现在支持：

```text
section_styles.references_body.font_cn
scene.section_styles.references_body.font_cn
references_body.font_cn
section_style.font_cn
format_scope.sections.references
```

行为规则：

```text
字段指向某个分区样式
  -> 先切到该分区
  -> 如果没有开启独立样式，定位到分区开关
  -> 如果已经开启独立样式，定位到具体控件

字段指向处理范围
  -> 定位到对应区域复选框
```

这让用户看到的链路更像一句人话：

```text
这次问题在“参考文献字体”。
但参考文献现在跟随模板，所以先打开“参考文献独立样式”。
打开后再改字体。
```

## 3. 一致性边界

本轮后的责任分布：

| 层级 | 责任 |
| --- | --- |
| `ParagraphStyleEditor` | 段落样式字段归一、字段到控件、样式读写控件 |
| 模板正文页 | 管模板默认正文样式、保存恢复、模板摘要 |
| 场景样式覆盖页 | 管是否覆盖模板、分区选择、当前场景覆盖样式 |
| 诊断/修复路由 | 只需要提供字段路径，不需要知道具体控件类 |

这比“每个页面自己写一张字段表”更接近可维护的设计。


结果：

```text

```

新增/收紧的测试覆盖：
- 共享编辑器能归一模板字段、场景字段、通配场景字段和具体样式字段；
- 模板正文页必须通过 `widget_for_field(target)` 定位字段；
- 模板正文页不允许重新出现局部 `mapping: dict[str, QWidget]`；
- 场景样式覆盖在未开启覆盖时定位到分区开关；
- 场景样式覆盖在开启覆盖后定位到具体字体控件；
- 处理范围字段能定位到对应区域复选框。

## 5. 仍未完成的缺口

### 5.1 高亮逻辑还没有共享

目前 `StyleDetail`、`_SceneSimpleDetail`、`_ScopeDetail` 都有相似的 `_highlight_navigation_widget()`。这不是最终形态。

后续应抽成共享 helper，例如：

```text
src/shared/ui/navigation_highlight.py
```

让模板页、场景页、输出页使用同一套高亮样式和 tooltip 规则。

### 5.2 场景页仍是同页双卡，不是导航级拆分

`处理范围` 和 `样式覆盖` 已经在 `_ScopeDetail` 内拆开，但左侧导航仍只有 `处理范围` 一个入口。后续是否要升级为：

```text
处理范围
样式覆盖
```

需要结合整体场景信息架构再判断。当前实现先保证边界清楚，不强行扩导航。

### 5.3 诊断报告到字段路径的全链路还要继续验

本轮验证的是页面级字段定位能力。还没有完整验证：

```text
运行时诊断 -> navigation intent -> ScenePanel -> _ScopeDetail -> ParagraphStyleEditor
```

后续要用真实诊断样本或现有 routing 测试继续打通。

### 5.4 文案还能继续减

本轮减少的是“需要解释的跳转断点”，不是大规模文案删除。场景样式覆盖里仍有若干提示文本，例如：

```text
当前跟随正文
开启独立样式后可编辑
正在编辑某分区的场景独立样式
```

这些暂时保留，因为它们是状态反馈，不是冗余说明。后续可以结合视觉回归再判断是否压缩成状态 chip。

## 6. 下一步建议

优先级从高到低：

1. 抽取共享导航高亮 helper，继续减少模板页和场景页的行为重复。
2. 用真实 navigation intent 样本验证运行时诊断能否落到 `section_styles.*.*` 字段。
3. 判断 `样式覆盖` 是否需要升级成左侧导航入口，而不是继续挂在 `处理范围` 下。
4. 做一次运行截图检查，确认“未开启覆盖 -> 开关高亮”和“已开启覆盖 -> 控件高亮”在视觉上足够明显。

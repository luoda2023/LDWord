# Workbench 首页最终设计方案 V3

- 日期：2026-03-31
- 状态：Final Draft

## 1. 核心设计理念

### 1.1 动态卡片系统

左侧不是固定的 6 个卡片，而是：
- **第一张固定卡片**："快速执行" - 完整工作流
- **第二张固定卡片**："配置管理" - 配置的保存/加载/管理
- **动态卡片**：根据"快速执行"中开启的高级功能，动态显示对应的配置卡片

### 1.2 开关即卡片

当用户在"快速执行"中开启某个高级功能（如"标题编号"）时：
- 左侧自动出现"标题编号"配置卡片
- 关闭该功能时，对应卡片消失
- 这样左侧卡片数量是动态的（2-7 张）

## 3. "快速执行"卡片详细设计

### 3.1 右侧详情区布局（垂直流式）

采用从上到下的流式布局，用户按顺序完成配置：

```
┌─────────────────────────────────────┐
│ 1. 输入文档                          │
├─────────────────────────────────────┤
│ 2. 场景模板                          │
├─────────────────────────────────────┤
│ 3. 高级功能（可展开/折叠）            │
├─────────────────────────────────────┤
│ 4. 输出文档                          │
├─────────────────────────────────────┤
│ 5. 执行控制                          │
├─────────────────────────────────────┤
│ 6. 执行反馈（执行时出现）             │
└─────────────────────────────────────┘
```

### 3.2 区域 1：输入文档

**内容：**
- 文档选择器（支持拖拽、浏览、最近文档下拉）
- 当前文档信息卡片：
  - 文件名
  - 文件路径（可点击打开目录）
  - 文件大小
  - 最后修改时间
- 文档校验状态（✓ 格式正确 / ⚠ 警告 / ✗ 错误）

**交互：**
- 拖拽文件到选择器区域
- 点击"浏览"按钮选择文件
- 点击"最近文档"下拉快速选择

### 3.3 区域 2：场景模板

**内容：**
- 场景模板下拉选择器
- 当前模板说明卡片：
  - 模板名称
  - 模板描述（1-2 句话）
  - 启用的模块列表（折叠显示，点击展开）
- Strict Mode 开关（独立一行）

**交互：**
- 下拉选择模板
- 点击"查看模块"展开/折叠模块列表
- 切换 Strict Mode

### 3.4 区域 3：高级功能

**内容：**
- 区域标题："高级功能"+ 展开/折叠图标
- 默认折叠，点击展开后显示：
  - ☐ 标题编号 [配置] 按钮
  - ☐ 内容填充 [配置] 按钮
  - ☐ 模块控制 [配置] 按钮
  - ☐ 输出设置 [配置] 按钮
  - ☐ 执行历史 [查看] 按钮

**交互：**
- 勾选某个功能时：
  1. 左侧立即出现对应的配置卡片
  2. [配置] 按钮变为可点击状态
- 点击 [配置] 按钮：
  1. 自动切换到左侧对应的卡片
  2. 右侧显示该功能的详细配置
- 取消勾选时：
  1. 左侧对应卡片消失
  2. 该功能的配置被禁用（但保留配置值）

### 3.5 区域 4：输出文档

**内容：**
- 输出目录选择器
- 输出文件名预览（自动生成，可编辑）
- 输出格式选项（如果支持多种格式）
- 覆盖策略：
  - ○ 覆盖已有文件
  - ○ 自动重命名
  - ○ 每次询问

**交互：**
- 点击"选择目录"浏览文件夹
- 直接编辑输出文件名
- 选择覆盖策略

### 3.6 区域 5：执行控制

**内容：**
- 大号"开始执行"按钮（主色调，突出显示）
- 按钮下方显示就绪状态：
  - ✓ 所有配置就绪
  - ⚠ 警告：XXX（仍可执行）
  - ✗ 错误：XXX（无法执行，按钮禁用）

**交互：**
- 点击"开始执行"：
  1. 按钮变为"执行中..."（禁用状态）
  2. 下方出现"执行反馈"区域
  3. 开始执行任务

### 3.7 区域 6：执行反馈（执行时动态出现）

**内容分为三个子区域：**

#### 6.1 实时进度条
- 总体进度百分比（0-100%）
- 当前执行的模块名称
- 预计剩余时间（可选）

#### 6.2 模块状态列表
```
┌─────────────────────────────────┐
│ ⏳ 标题编号处理    等待中        │
│ ▶ 内容填充        执行中 45%    │
│ ✓ 格式标准化      已完成        │
│ ✗ 图片处理        失败          │
└─────────────────────────────────┘
```
- 每个模块一行
- 状态图标：⏳等待 / ▶执行中 / ✓完成 / ✗失败
- 点击某个模块可展开查看该模块的详细日志

#### 6.3 日志流（可折叠）
- 实时滚动显示执行日志
- 支持日志级别筛选（全部/错误/警告/信息）
- 支持复制日志
- 支持导出日志到文件

**执行完成后：**
- 进度条变为 100%，显示"执行完成"
- 显示总耗时
- 显示结果摘要：
  - ✓ 成功处理 XX 项
  - ⚠ 警告 XX 项
  - ✗ 错误 XX 项
- 显示操作按钮：
  - [打开输出文件]
  - [打开输出目录]
  - [查看完整报告]

## 6. 完整交互流程

### 6.1 新用户首次使用流程

1. 打开首页，默认选中"快速执行"卡片
2. 左侧只有 2 张卡片："快速执行" + "配置管理"
3. 拖拽或选择输入文档
4. 选择场景模板
5. （可选）展开高级功能，勾选需要的功能
6. 确认输出路径
7. 点击"开始执行"
8. 查看执行反馈（进度条 + 模块状态 + 日志流）
9. 执行完成，打开输出文件

### 6.2 高级用户配置流程

1. 在"快速执行"中展开高级功能
2. 勾选"标题编号"
3. 左侧立即出现"标题编号"卡片
4. 点击"标题编号"卡片或点击 [配置] 按钮
5. 右侧切换到标题编号的详细配置
6. 完成配置后，点击左侧"快速执行"返回
7. 继续其他配置或直接执行

### 6.3 配置保存与复用流程

1. 完成所有配置后，点击左侧"配置管理"卡片
2. 输入配置名称和描述
3. 点击 [保存] 按钮
4. 下次使用时，在"配置管理"中点击 [加载] 按钮
5. 所有配置自动恢复（包括高级功能的开关和详细配置）

## 7. 关键技术点

### 7.1 动态卡片管理

**状态管理：**
```python
class WorkbenchState:
    enabled_features: Set[str]  # {'heading_numbering', 'quick_fill', ...}

    def enable_feature(self, feature: str):
        self.enabled_features.add(feature)
        # 触发左侧卡片列表更新

    def disable_feature(self, feature: str):
        self.enabled_features.remove(feature)
        # 触发左侧卡片列表更新
```

**卡片顺序：**
- 固定卡片始终在前："快速执行" → "配置管理"
- 动态卡片按开启顺序排列
- 或者按预定义的优先级排列

### 7.2 配置序列化

**配置结构：**
```json
{
  "name": "我的配置",
  "description": "用于技术文档的标准配置",
  "created_at": "2026-03-31T10:00:00Z",
  "input_document": "/path/to/doc.docx",
  "scene_template": "technical_doc",
  "strict_mode": true,
  "enabled_features": ["heading_numbering", "quick_fill"],
  "feature_configs": {
    "heading_numbering": {
      "scheme": "1.1.1",
      "depth": 3,
      "link_to_toc": true
    },
    "quick_fill": {
      "data_source": "/path/to/data.xlsx",
      "mappings": [...]
    }
  },
  "output": {
    "directory": "/path/to/output",
    "filename_template": "{date}_{template}_{original}",
    "overwrite_strategy": "rename"
  }
}
```

### 7.3 状态同步

**开关联动：**
- "快速执行"中的勾选框 ↔ 左侧卡片的出现/消失
- "快速执行"中的勾选框 ↔ 各功能卡片中的启用开关
- 三者保持同步，任一处修改都会同步到其他地方

**使用信号/事件机制：**

    def on_log_message(self, level: str, message: str):
        # 追加到日志流

## 11. 最终设计的核心优势

### 11.1 降低认知负担

- 新用户只需要关注 2 张卡片："快速执行" + "配置管理"
- 左侧卡片数量随需求动态变化，不会一开始就展示 6-7 张卡片
- 高级功能按需出现，不使用就不可见

### 11.2 提高操作效率

- 80% 的操作在"快速执行"一张卡片内完成
- 垂直流式布局符合自然的操作顺序
- 配置管理独立，方便快速保存和复用

### 11.3 保持灵活性

- 高级用户可以随时开启需要的功能
- 每个功能都有独立的配置空间
- 配置可以保存和复用，支持多种使用场景

### 11.4 清晰的反馈

- 执行过程中的三重反馈（进度条 + 模块状态 + 日志流）
- 实时更新，用户随时了解执行状态
- 执行完成后的结果摘要和快捷操作

## 12. 关键设计决策

### 12.1 为什么采用动态卡片？

**问题：** 固定 6-7 张卡片会让新用户感到困惑

**方案：** 动态卡片系统
- 默认只显示 2 张核心卡片
- 开启功能时才出现对应卡片
- 关闭功能时卡片消失

**优势：** 界面简洁，按需扩展

### 12.2 为什么配置管理独立成卡片？

**问题：** 配置管理放在快速执行内会让该卡片过于臃肿

**方案：** 独立的"配置管理"卡片
- 专注于配置的保存、加载、管理
- 与执行流程分离，职责清晰

**优势：** 功能聚焦，易于使用

### 12.3 为什么执行反馈放在快速执行内？

**问题：** 旧设计的底部固定区域占用空间，且与当前操作脱节

**方案：** 执行反馈作为快速执行的一部分
- 执行时动态出现
- 与执行按钮在同一上下文

**优势：** 上下文连贯，空间利用更合理

## 13. 总结

**最终设计的核心理念：**

> **简洁的默认 + 强大的扩展 + 清晰的反馈**

- **简洁的默认：** 2 张固定卡片，新用户零学习成本
- **强大的扩展：** 动态卡片系统，高级用户按需配置
- **清晰的反馈：** 三重执行反馈，实时了解任务状态

这个设计完全符合你的期望：
- ✓ 第一张卡片包含完整工作流
- ✓ 高级功能通过开关控制，开启后出现独立配置卡片
- ✓ 垂直流式布局，操作顺序清晰
- ✓ 配置管理独立，方便保存和复用
- ✓ 执行反馈丰富（进度条 + 模块状态 + 日志流）
